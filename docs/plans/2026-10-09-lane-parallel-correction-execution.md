# D-567 Fleet 병렬 보정 검증 실행 계획 (2026-10-09)

**상태:** 실행 중. ADR은 Proposed이고 주행 보정은 제품 제어에 연결되지 않았다. 입력 결과가 없으면 단계 판정은 HOLD다.

## 확인할 가설

| 가설 | 반증할 사례 | 측정값 |
|---|---|---|
| H1: 링 진입 방향은 Fleet 지도 접선과 축에서 동기화한 위치로 계산하면 상대 `turn_deg`보다 정확하다 | SW는 좋아지고 NE는 악화, 늦은 자세·다른 `map_id`, odom epoch 교체 | 첫 호 시작 방향 − 독립 GT 접선, 첫 0.1 m·전체 `|Δr|`, STOP |
| H2: 한쪽 바닥 경계와 Fleet 호를 함께 쓰면 오추종 없이 drift를 줄인다 | spoke·벽·현·사람/상자 가림, 경계 ID 교체 | 승인 바닥선 대비 차체 여유, 잘못된 보정 수, HOLD, 연속 miss |
| H3: 계측한 오차·지연·정지 거리의 여유만큼만 진행하면 두 선 소실에서 멈출 수 있다 | 지연·중복·역순 프레임, Rosy Cam 소실, 오돔 reset, 최대 속도에서 정지 | 마지막 유효 증거부터 이동, 실제 정지 추가 이동, 경계 침범·접촉 0 |

## 실행 순서와 판정

1. **현행 한 바퀴(D-557).** 모델 PC의 격리된 ROS domain/Gazebo partition/workspace에서 `map_v2_fleet_real`, `camera_lane_mode: keep`, 배포 `line_follow.yaml`을 덮지 않은 D-520 한 바퀴를 실행한다. 기록에는 코드 SHA, map SHA, profile, start pose, 시드, CORE/Fleet 포트, 각 호의 실제 자세·명령·IR·LiDAR·HOLD를 넣는다. 우선 기존 [lap SIM 4](../validation/lane-trip-lap-sim4-2026-10-09/result.md)와 비교한다. 모델 PC 연결이 없으면 기존 로그 재계산만 오프라인 증거로 남기고 새 SIM 성공이라고 쓰지 않는다.
2. **후보 계산을 기록에서 분리.** 지도 자세, CORE 오돔, 영상·바닥 경계의 원본 시각과 출처를 저장한다. `map_id`·epoch·시간 정합이 확인되지 않는 샘플은 `unknown`이다. 같은 Rosy Cam 유래 지도 자세와 바닥선의 오차를 독립 확률처럼 합치지 않는다. 보정 후보의 횡·방향 오차, 상한, 거절 이유, 계산 지연을 기록하되 움직임은 현행 D-520이 맡는다.
3. **폐루프 Gazebo.** SW·NE 각각 최소 4회와 한 바퀴 12회에서 baseline/지도 자세 후보/지도+승인 바닥선 후보를 같은 시작으로 비교한다. 한쪽 선 소실, 양쪽 가림, 벽·spoke·현, 0.1/0.25/0.5 s 지연, 중복·역순, 지도 ID 교체, odom reset을 주입한다. 데이터 선택과 이득 조정에 쓴 run은 확인 run에서 제외한다. 독립 GT에서 차체 sweep의 경계 침범·물체 접촉 0, 통과 불가 구간 전 STOP, 허용된 구간의 완주를 합격 목표로 한다. 최대 호 `|Δr|`, 진입 방향·연속 miss, 잘못된 경계의 양의 조향 승인, STOP 원인·정지 거리·도착률은 진단값으로 모두 기록한다. 차로 폭·차체 폭·오차·정지 거리를 대조하기 전 `|Δr|` 0.05/0.03 m를 단독 합격 문턱으로 쓰지 않는다. 실패 run을 삭제하지 않는다.
4. **두 로봇 read-only 현장 계측.** Fleet roster와 CORE TLS 신원으로 두 로봇 ID를 확정한다. `9dfk`와 `8kcn` 각각에서 accepted `wheel_odometry`·`camera_profile`·`lidar_mount`의 기록 digest, 실행 중 override·센서 파라미터·release를 대조한다. 그 로봇의 지도·바닥선 투영, odom 대 독립 위치, 카펫 회전 응답, 최대 지연, 차체 충돌 형상과 부착물, 정지 후 추가 이동을 따로 측정한다. 바퀴 보정 차이를 물리 차체 반경 차이로 대입하지 않는다. 영상·Fleet·CORE 샘플은 같은 timestamp라고 추정하지 않고 요청 구간과 실제 sensor stamp를 보존한다. 원본은 현장 비공개 저장소, 공개 기록에는 SHA와 수치 범위만 둔다. 현장 운영자와 독립 정지 수단이 확인되지 않으면 움직이지 않는다.
5. **장치 단계.** D-520 체크리스트와 사람 검수 시험 계획을 두 로봇마다 별도로 적용한다. 첫 움직임은 현행 주행과 병렬 shadow 계산만 허용한다. 매 시도는 출발/정지 위치, 속도·거리·시간, 운영자·E-Stop, 하나의 실패 시 즉시 HOLD를 미리 기록한다. 그 자료로 ADR의 오차 상한과 실제 정지 여유가 충족될 때에만 CORE 내부 보정 입력을 켜는 별도 변경·Safety-Review·서명 배포를 진행한다. DEVICE 통과와 FIELD 일상 주행 수용은 따로 판정한다.

## 현재 진행·차단 항목

- 기존 ROS-SIM 원시 기록에서 NE +15.497…+16.273° 진입 오차와 첫 25 mm crossing 0.1104–0.1281 m를 재계산했다. 이는 후보 설계 입력이며 새 알고리즘 통과 증거가 아니다.
- 모델 PC 전용 `rosy_d567_ws`에서 현행 코드 SHA를 대조·빌드한 D-557 [한 바퀴 기준 run](../validation/lane-parallel-correction-baseline-2026-10-09/result.md)이 `arrived`로 끝났다. SIM 충돌 상자 외접 원과 도색선 중심 사이 최소 대리 여유 −35.1 mm이므로 차체 경계 수용은 아직 미판정이다. 실제 충돌 형상과 허용 도색선 범위, 오차·정지 여유를 검증해야 다음 단계로 간다.
- 기존 현장 기록상 대상은 `rosy_26` (`rosy-pinky-9dfk`)와 `rosy_60` (`rosy-pinky-8kcn`)이다. 이는 2026-10-09 [장치 읽기 기록](../validation/pinky-lcd-runtime-2026-10-09/result.md)의 식별자이며, 현재 연결·현장 안전 정지 담당자 존재를 증명하지 않는다. 두 로봇의 현 시점 Fleet/CORE 읽기, 안전 정지 담당자, 실측 위치·정지 거리를 확인해야 4·5항을 판정할 수 있다. 설정 파일의 `site_floor_map_id`나 Fleet `LOCALIZED`만으로 완료 처리하지 않는다.

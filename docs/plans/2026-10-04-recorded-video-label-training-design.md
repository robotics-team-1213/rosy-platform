# 기존 주행 영상의 라벨 보완과 모델 비교

사용자가 촬영된 영상에 벽·신호등·다른 장애물이 포함돼 있다고 확인했고, 그 영상을
활용해 라벨과 학습을 개선하도록 요청했다. 기존 라벨을 덮어쓰지 않고 검수된 새 버전을 만든다.

## 현재 확인된 준비 상태

2026-10-04 로컬 검토 묶음은 5개 영상 출처에서 추린 76프레임이다.
학습 제안 44 / 검증 제안 32이며 촬영 그룹을 양쪽에 섞지 않았다.
기존 고정 평가용 2세션은 포함되지 않는다. 76장과 객체 검토용 4장의 이미지 SHA를 재검증했다.
원본 MP4 전체의 SHA를 이번에 다시 검사한 것은 아니다.

76프레임 모두 검수 대기이며, 4프레임의 객체 박스 7개도 사람 검수 대기이다.
신호등 2 / 로봇 2 / 사람 발 3이고 신호등 상태는 둘 다 unknown이다.
이는 준비 초안이며 새 클래스 학습 완료나 정답 데이터 수용 근거가 아니다.

## 라벨 구성

| 대상 | 표현 | 검수 기준 |
|---|---|---|
| 바닥, 차선, 벽, 주행 가능 영역, 정지선 | 픽셀 마스크 | 보이는 경계만 표시하고 미확인 픽셀은 ignore_index=255로 남긴다. wall role은 wall을 유지한다. |
| 신호등 | 객체 박스 + state 속성 | red/yellow/green/off/unknown을 구분하되 실제 밝은 등판이 식별될 때만 색을 확정한다. |
| 다른 로봇 | 객체 박스 | 본체와 가림 상태를 표시한다. 작은 원거리 실루엣의 클래스는 검수한다. |
| 사람/사람 발 | 객체 박스 | 발만 보이면 person_feet로 기록하며 보이지 않는 전신 박스를 추정하지 않는다. |
| 기타 장애물 | 객체 박스 + 종류/가림 메모 | 영상에서 관측된 물체를 목록화한 뒤 필요한 세부 클래스를 결정한다. 모든 미확인 물체를 같은 정답으로 강제하지 않는다. |

기존 segmentation manifest의 닫힌 role 집합에 객체·신호 색 role을 임의로 추가하지 않는다.
현재 lane 모델을 확장하는 접근과 별도 객체 모델을 함께 쓰는 접근을 비교했으며,
첫 실험은 **기존 마스크 보완 + 별도 객체/신호 상태 학습**으로 한다.
공유 encoder/multi-head 모델은 같은 평가에서 이점이 확인된 뒤 검토한다.
위 state 속성은 라벨 설계안이며 운영 API/주행 권한을 새로 정의하지 않는다.

## 데이터 보완 순서

1. 76프레임의 마스크 경계, 누락 객체, 프레임 전체 검수 상태를 정리한다.
   부분 박스만 있는 장면을 음성 샘플로 쓰지 않는다. assistant 초안은 정답으로 자동 승격하지 않는다.
2. 원본 영상에서 물체 출현 전·근접·통과 후, 신호 상태 변화, 가림·역광·흔들림 장면을 추가 추출한다.
   서로 거의 같은 연속 프레임을 과하게 늘리지 않는다. 원본 SHA/프레임 번호/촬영 그룹을 보존한다.
3. 기존 영상의 분할 조각과 같은 날 연관 촬영은 같은 그룹으로 묶는다.
   그룹 단위 train/val/test를 고정하고, 객체가 없는 평가 그룹에는 해당 클래스 성능을 N/A로 표시한다.
   신호 상태별 독립 평가 영상이 부족하면 추가 촬영을 요구하며 검증 프레임으로 학습하지 않는다.
4. 검수 완료 여부와 클래스별 장면 수를 먼저 집계한다. 통과한 이미지/라벨만 immutable dataset으로 내보낸다.
5. 동일 데이터/분할/입력 크기로 현재 lane 모델, 작은 segmentation 후보,
   작은 객체 후보를 비교한다. 정확도와 대상 장치 지연을 함께 보고한다.

## 평가와 실행 단계

Segmentation은 클래스별 IoU와 기존 차선 성능 저하를 검사한다.
객체는 클래스별 precision/recall/AP와 거리·가림별 미검출을 확인하고,
신호 상태는 unknown을 포함한 혼동행렬 및 red→green 오판을 별도로 보고한다.
표본이 없는 클래스는 성능을 추정하지 않는다. 새 객체 수용 기준은 학습 전에 별도로 고정한다.
기존 intake gate와 126프레임 고정 평가 세트는 유지하며, 평가 결과를 보고 기준을 낮추지 않는다.

영상 인식과 주행 정책 학습은 별도의 증거가 필요하다. 벽·신호등 라벨만으로
정지/회피 행동의 정답을 만들지 않는다. 행동 학습에는 관측 시각에 맞는 실제 조작 기록,
운전자 의도와 성공/실패 판정, 독립 과제 평가가 추가로 필요하다.
현재 기록된 cmd_vel을 모두 숙련자 정답이라고 가정하지 않는다.

검수 → 데이터 빌드 → 학습 → 고정 평가 → 녹화 replay → shadow 순으로 진행한다.
shadow 관측은 자동 주행 활성화나 물리 수용이 아니다. 최종 명령 writer는 기존 CORE/owner를 유지한다.

다음 실행: 추가 장면 추출·라벨 검수·클래스별 독립 평가 보강 후 dataset 빌드.
미완료: 사람 검수, 새 객체/신호 모델 학습 및 품질 평가, 모델 PC 전체 job, 장치 shadow와 현장 수용.
기존 외부 lane 학습 코드는 provenance/immutable dataset/intake 경로에 연결하되,
객체 박스가 기존 segmentation trainer의 지원 형식이라고 가정하지 않는다.

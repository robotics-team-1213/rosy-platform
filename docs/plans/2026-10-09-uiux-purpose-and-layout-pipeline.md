# ROSY 작업 목적·레이아웃 평가 파이프라인

**기준:** D-543, D-280, D-153. Fleet의 구조 구현 순서는 [D-540 실행 계획](2026-10-09-fleet-console-v2.md)을 따른다. **현재 단계:** SOURCE 진단. 상용 수준 목표는 화면별 작업 완료와 제품 전체 G1/G2/G3·현장 수용을 모두 확인할 때까지 HOLD다.

## 화면을 만들기 전에 쓰는 작업 카드

| 칸 | 반드시 답할 내용 |
|---|---|
| 역할과 시작 | 누가, 어떤 상태에서 이 화면을 열고 무엇을 알고 오는가? |
| 한 문장 목적 | 이 화면에서만 답할 질문과 완료할 작업은 무엇인가? |
| 첫 화면 | 상태·근거·다음 안전한 동작 중 무엇을 가장 먼저 보아야 하는가? |
| 데이터·권한 | 값의 출처·나이, 읽기/쓰기 주체, 거부 시 안내는 무엇인가? |
| 공간 | 주 시각 자료·행동·보조 정보가 각각 얼마의 주의를 요구하며 왜 그 크기인가? |
| 인계 | 어느 결과를 들고 어디로 가는가? 입력은 보존되는가? 어떻게 돌아오는가? |
| 종료 | 성공/실패/중단을 무엇으로 확인하고 다음 행동은 무엇인가? |

## 품질 평가표

각 항목을 **0** 없음/오해 유발, **1** 일부 존재하나 추측 필요, **2** 대부분 명료하나 한 상태·폭·역할에서 막힘, **3** 선언된 상태·폭·역할에서 관찰로 입증으로 채점한다. 평가자는 근거 위치 또는 캡처를 적고, 확인하지 못한 항목은 `?`로 둔다. 합계는 우선순위 도구일 뿐 GO가 아니다.

| 축 | 3점일 때 관찰할 것 |
|---|---|
| 목적과 역할 | 첫 화면만 보고 이 작업의 대상과 이유를 말할 수 있다. |
| 상태와 증거 | 현재 값·출처·나이·미확인이 판단에 필요한 곳에 보인다. |
| 정보 위계와 공간 | 안전·주 판단·주 동작이 먼저 보이고 지도·목록·빈 칸은 필요만큼 차지한다. |
| 이동과 인계 | 링크의 목적·대상·보존되는 맥락·복귀 길을 예측할 수 있다. |
| 조작과 권한 | 할 수 있는 동작, 막힌 이유, 확인·완료가 서로 구분된다. |
| 용어와 설정 범위 | 라벨만으로 소유자와 효과를 알고 같은 개념은 같은 이름이다. |
| 상태별 복구 | 빈/지연/끊김/거부/오류/안전 정지에서 다음 안전한 행동을 찾는다. |
| 접근성과 적합성 | 선언 폭에서 읽기·키보드·터치·초점·스크롤 순서가 작업 순서를 따른다. |

**판정:** 24점 중 20점 이상은 개선 후보의 사용성 목표이며, 한 축이라도 1점 이하면 구조 재설계 대상이다. 안전·권한·증거 정직성에 0점 또는 미검증 `?`가 있으면 점수와 무관하게 HOLD다. UI/UX GO는 D-153 G1/G2/G3를 별도로 모두 충족해야 한다. 실제 사용자·DEVICE·FIELD 수용도 별도다.

## 반복 실행 순서

1. **범위 고정:** 활성 화면 목록을 `shared/web/surfaces.yaml`과 실제 경로로 대조한다. 하위 작업도 각각 작업 카드를 채우고 기존 ADR의 권한·안전 경계를 확인한다.
2. **SOURCE 진단:** 작업 카드와 8축 평가표에 화면 코드·ADR 근거를 적는다. 결함을 역할·구조·문구·상태·공간으로 재현 가능하게 기술하고 가장 큰 작업 실패 하나를 선택한다.
3. **한 흐름 개선:** 시작→판단→행동→결과→복귀를 화면과 코드에 반영한다. 공유 토큰·컴포넌트와 기존 문법을 사용하며 새 권한/API는 별도 계약으로 처리한다.
4. **로컬 검증:** G1 검사, 대표 작업의 브라우저 캡처를 선언 폭과 정상·빈·지연·끊김·거부·SAFE_STOP에서 찍어 G2 행렬을 채운다. G3는 D-153의 여덟 항에 코드/캡처 근거를 붙인다. 실제 사람에게 화면의 목적, 다음 동작, 복귀 경로를 설명 없이 수행하게 하고 막힌 곳을 기록한다.
5. **승격:** 해당 후보 SHA, 테스트·캡처·사용자 작업 결과, 설치 이미지·현장 readback을 별도 칸으로 남긴다. 실패하면 2단계로 돌아간다. 한 화면의 통과를 다른 화면이나 현장 수용으로 확대하지 않는다.

**우선순위:** D-540의 공통 머리와 Cell→예외 큐 인계에 이 평가표를 적용 → 관제/설치/지도 작업 전환 → 전체 활성 화면으로 확대. 각 단계의 완료는 새 디자인 문장이 아니라 실제 화면 변경과 D-153 증거로 판정한다.

# 지도–실제 대조와 초안 보정 설계

Date: 2026-11-10
Status: Implemented (`feat/map-reality-check`) — 관제 지도 화면의 「지도–실제 대조」 패널과 Fleet 서버 API

## 1. 목표와 배경

관제가 보여 주는 사이트 지도가 **실제로 로봇이 달린 곳**과 같은지 판정하고, 전체 지도가 한꺼번에
어긋나 있으면 초안을 한 번의 강체 변환으로 그 주행 위에 올린다.

- 판정 대상은 차로(선)와 구역(제외 구역·횡단보도)이다. "이 차로를 아무도 안 달렸다",
  "이 구역에 로봇이 들어갔다", "차로는 맞는데 프레임이 밀렸다"를 구분해 말한다.
- 보정은 **초안에만** 쓴다. 활성 지도는 운영자가 초안을 검토하고 활성화할 때까지 그대로다.
  지도 편집은 로봇 명령을 내리지 않는다.
- 근거는 Fleet이 이미 들고 있는 사실만 쓴다. 새 장치·새 수집 경로를 만들지 않는다.

## 2. 근거 (reality) 범위

| 근거 | 이번 범위 | 이유 |
|---|---|---|
| D-594 경로 이력 `PathStore` | **사용** | Fleet이 스스로 기록한 map 프레임 점이다. 서버 안에 있고, 창(`last_s`)으로 자를 수 있고, 로봇별로 고를 수 있다 |
| 천장 카메라 관측(sighting) | 범위 밖 | 가져오기가 브라우저 쪽이고, 카메라가 없는 현장(2026-10-31 점검)에서 판정이 멈춘다. 경로 이력이 같은 사실을 이미 담는다 |
| SLAM 점유 지도 (`tools/calibration/slam_map_align.py`) | 범위 밖 | 오프라인 도구다. 서버 요청 경로에 넣으려면 지도 파일 적재·정합 비용·실패 모드를 새로 정해야 한다 |
| 주행 가르치기(D-494 6) 선 | 범위 밖(같은 계열) | 확정한 선은 초안 차로가 된다. 확정 전 비교는 경로 이력과 중복이다 |

기본 창은 6 h(한 교대), 최대 24 h(D-594 보관 한도)다. 창 안에 주행이 없으면 `no_evidence`이고
아무것도 주장하지 않는다.

## 3. 판정 규칙 (`fleet/map_reality.py`, 순수)

차로 중심선을 0.25 m 간격으로 샘플해 가장 가까운 주행 점과의 거리를 잰다.

- **허용 오차 0.15 m** — D-455 sighting `max_jump_m` 과 같은 값이다. "차로 위에 있다"가
  카메라 sighting 과 여기서 같은 뜻이 된다. 조절 손잡이를 만들지 않는다.
- 차로 상태: 샘플의 절반 이상이 0.15 m 안 → `matched`; 0.5 m 안쪽 샘플의 중앙값이 0.15 m 초과
  → `offset`(차로는 있는데 밀렸다); 나머지 → `uncovered`(아무도 안 달린 차로).
- 구역: 제외 구역 안에 든 주행 점 수(`entered`/`clear`), 횡단보도(`used`/`unused`).
  점 3개 미만인 제외 구역은 면적으로 판정하지 않는다.
- 지도 밖 주행: 어떤 차로에서도 0.5 m 넘게 떨어진 점의 수와 비율(`off_lane`).

### 3.1 전체 어긋남 판정 (강체 정합)

ICP(6회, 최근접 짝 게이트 0.5 m)로 `yaw + 평행이동` 하나를 찾는다. 채택 조건을 모두 만족해야 한다.

- 짝 20개 이상, 차로 샘플의 30 % 이상이 짝지어짐 — 지도와 주행이 같은 차로여야 한다.
- 정합 뒤 중앙 거리가 정합 전의 절반 이하.
- 변화가 `0.05 m`/`0.3°` 보다 크고, 한 사이트 프레임으로 납득되는 `5 m`/`30°` 이하.

채택되지 않으면 이유 문자열을 남기고(`fit.reason`) 보정하지 않는다. 지도에 없는 차로를 로봇이
달렸다면 그 점은 짝이 되지 않아 지도 전체를 끌고 가지 않는다.

### 3.2 판정 사다리 (verdict)

1. `mismatch` — 로봇이 제외 구역을 지났다. 구역이나 주행 중 하나가 틀렸다. 사람이 본다.
2. `offset` — 강체 보정이 채택됐다. 차로는 있는데 프레임이 밀렸다.
3. `unmapped` — 차로 절반 초과가 안 달렸다. 지도에 없는 길이거나 지도가 낡았다.
4. `match` / `partial` — 전부 맞음 / 일부만 맞음.
5. `no_evidence` — 창에 주행이 없다.

`offset` 을 `unmapped` 보다 먼저 본다. 한 방향으로 밀린 지도는 "안 달린 차로"처럼 보이기 때문이다.

## 4. API (`fleet/server/sitemap/site_map_routes.py`)

| 경로 | 권한 | 하는 일 |
|---|---|---|
| `GET /api/fleet/site-map/reality-check?last_s=&robot_id=` | 읽기 | 활성 지도(없으면 초안)를 경로 이력과 대조해 `rosy.site_map_reality/1` 보고서를 돌려준다. 쓰기 없음 |
| `POST /api/fleet/site-map/reality-check/apply` | 이름 있는 운영자 | 초안에만 강체 변환을 적용해 새 초안 리비전을 만든다 |

`apply` 본문은 `expected_revision`, `last_s`, `robot_id` 뿐이다. **변환은 브라우저가 보내지 않고
서버가 같은 근거 창으로 다시 계산한다.** 거절은 409 `SITE_MAP_NO_DRAFT`(초안 없음),
`SITE_MAP_DRAFT_CHANGED`(다른 운영자가 먼저 저장), `SITE_MAP_NO_CORRECTION`(채택된 보정 없음,
이유 문자열 포함), 422 `SITE_MAP_INVALID`(변환 결과가 스키마 검증 실패 — 횡단보도 차로 결합이
정확한 0 비교라 반올림 뒤 깨질 수 있다)다. 성공하면 `site_map_events` 에 `reality_corrected`
(이전·새 리비전, fit, 판정, 근거 수)를 남긴다.

활성 지도는 어떤 경로로도 바뀌지 않는다. 보정 뒤 운영자는 기존 초안 편집·활성화 절차를 그대로 쓴다.

## 5. 화면 (`applications/fleet/web/sitemap/site-map-reality.js`)

「지도 만들기」 흐름의 초안 편집 다음에 「지도–실제 대조」 절을 둔다. 창·로봇을 고르고
「대조」 를 누르면 판정·차로 표·구역 표·보정 제안을 보여 주고, 채택된 보정이 있을 때만
「초안에 적용」 버튼이 산다. 적용은 서버가 다시 계산하므로 화면은 변환값을 만들지 않는다.

# 현장 관제 접속·좌표 확인 흐름

사용자가 UI/UX 리팩터링과 커밋·머지·검증 후보 배포를 승인했다. 기존 지도 중심
배치와 DESIGN.md 토큰을 유지하고, 관제 접속에서 시작점 저장까지 다음 행동을
화면에서 찾을 수 있도록 정리한다. 외부 디자인 참조 대신 현재 관제 화면과 제품
디자인 계약을 기준으로 삼는다.

## 범위와 선택

문구만 바꾸면 준비 순서가 드러나지 않고, 전체 화면 교체는 현장 운영자의 기존
조작 위치를 바꾼다. 기존 배치에 준비 안내를 더하고 인증·보정 상태를 바로잡는다.

- 접속 → 카메라·지도 보정 → X/Y 좌표 확인 → 시작점 설정 순서를 표시한다.
- 인증 전에는 지도·로봇·발행·시작점 상태가 조회 중인 것처럼 남지 않는다.
- 접속 안내에서 키보드로 토큰 입력란에 바로 이동할 수 있다.
- 승인된 보정이 없는 경우 설치·보정 화면에서 해야 할 일을 안내한다.
- 인증 상실 시 이전 지도·좌표·시작점과 목표 선택을 지우고 재접속을 안내한다.
- PC와 모바일에서 가로 넘침 없이 안내·지도·조작을 읽고 사용할 수 있다.

API·역할·안전 조건·주행 명령은 변경하지 않는다. 시작점은 표시 기준이며 로봇
위치확정이나 주행 허가가 아니다. 보정 저장과 배경 학습은 기존 승인 절차를 따른다.

## 구현과 검증

정적 HTML/CSS와 기존 console/map/start-point 뷰에서 상태를 표현한다. 새 런타임
의존성과 새 API는 만들지 않는다. 실제 Chromium으로 인증 해제·복구, 보정 없음,
키보드 포커스와 모바일 레이아웃을 검증하고 기존 시작점 저장 시나리오도 확인한다.
관련 pytest 결과는 known_failures와 비교한다. main 통합 뒤 CI와 서명 후보 검증을
통과한 동일 커밋을 배포하고 현장 HTTPS 화면을 읽어 확인한다. 호스트·브라우저·배포
검증과 실제 로봇 좌표 오차 검증은 구분해 기록한다.

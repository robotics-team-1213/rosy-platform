# 관제 운영자용 관제 AI 에이전트 설계안

상태: 2026-10-20 사용자 구현 요청에 따라 첫 조회 전용 버전을 구현했다. 실제 모델 승인·운영 활성화·한국어 음성 수용과 장치 실행 연결은 별도이며 아직 완료되지 않았다.

현재 소스는 Console 패널, 출처가 분리된 웹 대화, 영속 중복 방지, 근거에 따른 상태 응답, 독립 승인 broker, 선택적 로컬 음성 입출력을 제공한다. 실행 요청은 기존 작업 화면으로 안내한다. 일반 CHAT도 고정 안내문으로 표시하여 모델 자유 문장이 물리 상태나 완료 사실로 노출되지 않게 했다. 아래 중 장치 실행 연결은 후속 단계 설계다.

다음 작업은 [구현 계획](2026-10-20-operator-ai-plan.md)을 검토하고 1단계 텍스트 대화부터 구현하는 것이다. 실제 장비 접근·배포·이동은 이 문서 작성 범위에 포함하지 않는다.

## 목적과 완료 기준

운영자가 관제 화면에서 음성 또는 텍스트로 질문하고 실제 관제 상태에 근거한 답을 받는다. 후속 대화를 이어가고, 작업 요청은 기존 Fleet 실행 소유자에게 연결하며, 완료 여부는 실행 기록으로 확인한다.

- “전체 상태 알려줘”에는 조회 시각과 근거가 있는 상태 요약을 표시한다.
- “2번은 왜 멈췄어?”에는 확인된 사건과 모르는 원인을 구분한다.
- “그 로봇을 입구로 보내줘”에서 대상이 불명확하면 되묻고 실행하지 않는다.
- 작업의 접수·실행 중·완료·실패·확인 불가를 구별한다. 모델 문장으로 완료를 확정하지 않는다.

## 현재 구현과 재사용 범위

2026-10-20 로컬 main `8d8921ac0e` 기준으로 소스를 확인했다. 로컬 main은 원격과 분기되어 있어 구현 시작 시 대상 기준을 다시 확인한다. 소스 존재를 배포·활성화·현장 수용의 증거로 사용하지 않는다.

| 확인한 위치 | 현재 역할 | 계획 |
|---|---|---|
| `operations/site_ui/console/` | Fleet가 제공하는 정적 ES module 관제 UI | 대화 패널 추가 |
| `operations/site_ui/console/work/channel-request-view.js` | 기존 대화 요청 검토 화면 | 실행·검토 상세 연결 재사용 |
| `operations/decision/src/rosy/decision/conversation/codec.py` | 모델 입력·답변·후속 문맥 검증 | 의미 계약 재사용, 웹 입력 식별은 별도 설계 |
| `operations/fleet/fleet/server/channel/conversation/` | 선택적으로 구성하는 대화 작업·모델 호출 | 검증·호출·결과 처리 재사용 |
| `operations/fleet/fleet/server/channel/execution/` | 기존 대화 요청과 실행·결과 연결 | 3단계 연결 대상 |
| `deploy/site/install_conversation_broker.py` | 승인 증거를 요구하는 broker 설치 도구 | 새 LLM 서버 대신 기존 배포 경로 검토 |

기존 채널 접수는 Discord guild/channel/author와 운영자 매핑을 검증한다. 웹 세션을 가짜 Discord 사용자나 채널로 변환하지 않는다. Console 입력은 인증된 Fleet principal을 출처로 기록하고, 채널별 인증 어댑터 뒤에서 의미 검증과 작업 처리를 공유한다. Discord의 기존 동작과 소유권 검증은 보존한다.

관련 기준은 [D-728](../adr/D-728-natural-language-channel-operations.md), [API reference](../reference/ROSY%20API%20%26%20Protocol%20Reference.md), [플랫폼 소유 영역](../../tools/harness/platform_parts.yaml)이다. D-728은 명확한 일반 요청에 일괄적인 추가 확인 클릭을 요구하지 않는다. 위험 작업·독립 승인·기존 admission은 해당 실행 소유자의 기준을 따른다.

## 기능과 책임

운영자가 보는 기능은 아래 여섯 가지다. 기능 수와 서버 수를 일치시키지 않는다. 모두 기존 Fleet와 Console에 설치하고, 모델·음성 연산만 승인된 AI PC 경로를 사용한다.

| 기능 | 첫 버전 동작 | 추가 시점과 조건 |
|---|---|---|
| 상황 조회 | 전체/선택 로봇의 온라인·모드·정지 상태를 시각·근거와 함께 설명 | 새로운 항목은 원래 데이터 소유자의 읽기 권한을 연결한 뒤 제공 |
| 사건 설명 | 허용된 사건·작업 기록에서 확인한 정지 사유를 설명. 기록 없으면 원인 미확인 | 원인 추측을 확정 사실로 기록하지 않음 |
| 후속 대화 | “그 로봇”, “그 장소”를 현재 선택·최근 대화와 대조. 여러 후보면 되묻기 | 장기 기억·사용자 간 대화 합치기는 제외 |
| 작업 요청 | 조회 전용 배포에서는 기존 작업 화면 안내 | 실행 연결 단계에서 기존 owner에 요청하고 실제 상태 표시 |
| 결과 알림 | 요청에 연결된 작업 상태를 대화에서 확인 | “도착하면 알려줘”를 지원하는 실행 연결 단계에서 기존 결과·알림 경로 사용 |
| 음성 | 눌러서 녹음 → 인식문 수정 → 전송, 선택적 읽어주기 | 텍스트 대화 수용 후 추가. 상시 청취는 제외 |

질문에 답하려고 임의로 조치하거나 작업 실패를 모델이 스스로 복구하지 않는다. 복구 요청도 허용된 작업 요청으로 취급한다. “응답 중단”, “녹음 취소”, “로봇 작업 취소”는 다른 행동으로 표시하고 처리한다. 응답 생성을 중단해도 이미 수용된 로봇 작업이 취소되었다고 표시하지 않는다.

### 모듈 인터페이스와 상태 소유자

아래 이름은 내부 설계안이며 공개 API 필드가 아니다. `runtime.py`는 의존성·worker 시작과 종료만 연결하고 기능별 정책을 쌓지 않는다. 별도 파일이 실제 책임을 갖지 않으면 만들지 않는다.

| 모듈 | 소유하는 책임과 상태 | 작은 인터페이스 | 의존 대상 |
|---|---|---|---|
| Console `assistant/panel.js` | 입력 초안, 선택 표시, 펼침·접힘, 요청 표시 | `createAssistantPanel({scope, call, el})` | Fleet 공개 계약과 공통 UI 수명 관리 |
| Console `assistant/voice.js` | 녹음·재생 자원, 취소와 정리 | 녹음 결과를 인식문으로 전달; 최종 답변 읽기/중단 | 마이크·오디오와 Fleet 음성 계약 |
| Fleet `assistant/routes.py` | HTTP 인증·입력 검증·오류 매핑 | 접수·자기 대화 조회·요청 조회 | 기존 auth와 대화 처리 모듈 |
| Fleet `assistant/service.py` | 요청 접수→문맥 구성→모델 검증→결과 저장의 순서 | `submit(principal, message)` / `read(principal, request_id)` | journal, context, 검증된 provider |
| Fleet `assistant/journal.py` | 대화·요청·모델 시도·결과의 영속 전이와 중복 방지 | 접수, 시도 예약, 종료, 자기 범위 조회 | 기존 Fleet DB/transaction. 장치 작업 상태는 소유하지 않음 |
| Fleet `assistant/context.py` | 사용자가 읽을 수 있는 상태·사건·작업·선택의 제한된 읽기 결과 | `build_context(principal, selection)` | 기존 Fleet/World/사건/작업 읽기 소유자 |
| 기존 Decision conversation + broker provider | 의미 계약·제안 검증, 승인 모델 호출 | 제한된 입력 → 검증된 답변/명확화/작업 후보 | journal·UI·장치 명령에 의존하지 않음 |
| 기존 Fleet 실행 연결 | 후보 수용·중복 실행 방지·작업 결속·실제 결과 조회 | 검증된 요청 → 기존 작업 참조/상태 | 기존 실행 원장·Task/Mission/Cell/CORE |

대화 처리는 `service.py`의 작은 인터페이스 뒤에 묶는다. routes·UI가 모델 호출 순서나 DB 테이블을 알 필요가 없게 한다. 반대로 사건·작업의 권한 규칙을 assistant에 복사하지 않고 원래 읽기 소유자의 인터페이스를 호출한다. 서버가 자기 HTTP API를 다시 호출하는 우회도 추가하지 않는다.

`context.py`는 첫 버전에 상황 조회·사건 설명에 필요한 읽기만 명시적으로 연결한다. 기존 `model_tool_catalog.py`에는 `get_fleet_state`, `get_incident_status`, `get_mission_status`가 있으나 그 존재만으로 웹 사용자에게 도구 권한을 부여하지 않는다. 현재 문맥에 결속된 읽기만 연결하고, 새 도구에는 기존 effect class·allowlist·권한·시험을 함께 등록한다. 플러그인 로더나 범용 자율 도구 루프는 추가하지 않는다.

### 재사용 전에 풀어야 하는 결합

다음은 소스로 확인한 제약이다. 기존 구현을 그대로 복사해 두 번째 대화 엔진을 만드는 방식은 선택하지 않는다.

| 근거 | 유지보수·기능 영향 | 설계 결정과 검증 |
|---|---|---|
| `codec.py:81`의 입력과 `:42`의 이력에 Discord author/guild/channel이 필수. `jobs.py:26`은 같은 필드로 이력을 조회 | 웹 세션을 직접 넣을 수 없고 가짜 식별자는 권한·이력 검증의 의미를 바꿈 | 출처가 명시된 웹 대화 계약을 새 버전으로 정의. 공통 의미 검증을 재사용하되 기존 v1 decoder·원장은 유지. 웹↔Discord 문맥 혼합 거부 시험 |
| `conversation/runtime.py:66`은 채널 journal·reply_outbox가 있어야 시작 | 웹만 쓰는 관제가 Discord 설정에 의존할 수 있음 | 채널 접수/회신 설치와 공통 대화 처리를 분리. Console 단독·Discord 단독·동시 구성 시험 |
| `execution/runtime.py:10`은 단일 `channel_admission`과 선택 문맥 callback을 설치 | 웹 worker를 하나 더 설치하면 충돌하거나 기존 실행 결속을 덮어쓸 수 있음 | 실행 소유자 하나에 출처별 검증 입력을 연결. 두 번째 실행 원장·worker·callback 교체 금지. 동시 설치와 중복 실행 시험 |
| `codec.py:123`의 상태 문맥은 로봇 온라인/모드/estop/line_state·지도·작업 종류 목록 중심 | 상세 사건·작업 진행·배터리 등이 들어 있다고 가정하면 답변 근거가 없음 | 권한 있는 읽기에서 필요한 근거를 별도 구성. 없는 항목은 모른다고 답하며 모델 입력 확장 시 새 승인·평가 증거 확보 |
| `codec.py:98`, `jobs.py:26`은 최대 최근 4개·120초·같은 environment hash의 이력을 사용 | 로봇 상태가 변하면 이전 맥락이 사라질 수 있어 지속적 대화 기억으로 간주할 수 없음 | 모델 대화 이력, UI의 명시적 선택, 실행 owner가 수용한 문맥을 구별. 갱신 시 각각 재검증하고 오래된 근거·불명확한 대명사는 되묻기 |

공통 처리의 소스 위치 변경은 ADR와 매니페스트·설치 시험을 먼저 확정한 뒤 별도 변경으로 수행한다. 모델 입력·스키마·출처 정책이 바뀌면 기존 D-728 모델 승인 증거를 그대로 적용하지 않는다. 기존 프로토콜은 유지하고 Console용 계약의 독립 승인 여부를 확인한다.

### 상태·취소·관측

대화 요청 상태와 실행 상태를 별도 필드로 표시한다. `ANSWERED`는 답변이 생겼다는 뜻이며 로봇 작업 완료가 아니다. 실행 상태는 연결된 owner의 원래 값을 보존하고 UI에서만 이해하기 쉬운 문구로 표시한다. 일회성 읽어주기 종료도 작업 상태를 바꾸지 않는다.

대화·요청·모델 시도·실행 작업 식별자를 연결해 접수, 문맥 조회, 모델 호출, 검증, 실행 수용, 결과 반영 중 어디에서 보류됐는지 추적한다. 로그에는 단계·시간·이유 코드·모델 버전·근거 참조를 남기고 키·원음·전체 대화를 일반 로그에 복제하지 않는다. 새로운 추적 서버나 별도 대시보드는 만들지 않는다.

모델 호출의 단절·타임아웃·UNKNOWN을 provider 내부에서 숨겨 재시도하지 않는다. 웹 조회 재시도는 새 작업 접수가 아니며, 사용자가 같은 식별자를 다른 본문으로 전송하면 충돌로 거부한다. 결과 알림은 기존 결과 회신/알림 경로를 사용하고 재전송 식별자로 중복 표시를 방지한다.

### 변경이 도달해야 하는 범위

| 변경 예 | 정상적인 수정 범위 | 함께 바뀌면 구조를 재검토할 곳 |
|---|---|---|
| LLM 모델·전송 방식 교체 | 기존 provider·승인 설정·계약 적합성/모델 평가 | UI, 음성 녹음, 장치 실행 코드 |
| “배터리 알려줘” 추가 | context 읽기·허용 출력 계약·평가 사례 | routes별 조건 분기, UI 질문별 분기, 실행 worker |
| 새 작업 종류 추가 | 기존 작업 owner·허용 의미/도구 계약·결속 시험 | 음성 모듈, 별도 assistant 실행 원장 |
| STT 교체 | 음성 adapter·배포 핀·음성 수용 시험 | 대화 원장, 작업 수용 규칙 |
| 패널 위치 변경 | panel·배치 CSS·브라우저 시험 | 모델 provider, journal, 사건 읽기 권한 |

유지보수 완료 기준은 기능 수보다 이 표의 변경 범위와 권한·중복 방지 회귀를 만족하는 것이다. 불필요한 인터페이스를 미리 만들지 않고 실제 웹/Discord 두 출처와 음성/텍스트 두 입력에 필요한 구분만 둔다.

| 구분 | 제안 위치와 책임 |

| 화면 | 기존 `/console` 오른쪽에 접을 수 있는 “관제 AI” 패널. 지도·비상정지를 가리지 않는다. 작은 화면에서는 전환해서 보는 전체 폭 패널 |
| UI 소스 | `operations/site_ui/console/assistant/`. 별도 웹 앱·Node 서버를 만들지 않는다 |
| 웹 대화 접수·원장 | `operations/fleet/fleet/server/assistant/`. 현장 PC의 기존 Fleet 프로세스에 설치 |
| 의미 해석 계약 | `operations/decision/src/rosy/decision/conversation/operator.py`. 웹 조회용 계약이며 기존 Discord codec은 유지 |
| LLM 추론 | 기존 승인된 AI PC broker 경로. 모델 PC는 평가·승격 증거를 담당하고 Fleet 원장을 쓰지 않는다 |
| 음성 | 첫 adapter는 관제 브라우저의 로컬 한국어 인식·재생. 지원되지 않으면 텍스트 유지. AI PC STT는 대상 브라우저 수용 실패 시 별도 검증·추가 |
| 실제 실행 | 기존 Fleet Task/Mission/Cell/formation owner와 로봇 CORE. AI PC·브라우저가 직접 ROS나 장치에 명령하지 않는다 |

별도 대화 웹 앱, 기존 Console 패널, Discord 전용 유지 중 Console 패널을 선택한다. 운영자가 지도와 작업을 보면서 질문할 수 있고 기존 인증·정적 배포를 재사용하기 때문이다.

## 입력과 응답

첫 배포는 텍스트 입력, 대화 내역, 처리 상태, 근거 링크, 선택한 로봇·장소 표시를 제공한다. 화면의 현재 선택은 사용자 입력의 단서이며 권한이나 실행 승인을 대신하지 않는다. 대화 문맥은 현장·principal·대화별로 격리한다. 로그아웃·계정 전환 시 화면을 비우고 이전 계정 요청의 늦은 응답을 버린다.

서버는 요청을 영속 접수한 후 기존 처리 주기에서 모델을 호출하고 UI는 요청 상태를 조회한다. 동일 요청 식별자의 재전송은 같은 결과를 반환한다. 호출 결과가 UNKNOWN이면 모델 호출이나 실행을 자동 재생하지 않는다. 근거가 오래되거나 권한·지도·모델 승인 정보가 바뀌면 다시 확인하거나 보류한다.

새 API는 구현 전 ADR/API 예약 절차로 확정한다. 요청 신원은 세션에서 얻고 본문의 principal을 신뢰하지 않는다. 경로·envelope를 API reference와 `contracts/foundation/core_common/protocol/schemas.py`에 함께 등록한 뒤 클라이언트를 연결한다. 새 API를 이미 존재하는 계약처럼 취급하지 않는다.

## 음성

눌러서 녹음하고 중지하면 STT 결과를 편집 가능한 입력란에 표시한다. 최종 전송은 텍스트와 같은 경로를 사용한다. 중간 인식 결과로 명령하지 않는다. 상시 청취·호출어는 제외한다.

첫 adapter는 브라우저가 로컬 한국어 인식과 설치된 언어 팩을 지원할 때만 시작한다. 30초·최종 인식문 2000자로 제한하며 원음을 서버로 보내거나 저장하지 않는다. 언어 팩 준비는 운영자가 단추를 눌렀을 때만 시도하고 클라우드 인식으로 대체하지 않는다. [Microsoft 공식 문서](https://learn.microsoft.com/en-us/microsoft-edge/web-platform/speech-recognition-api)는 한국어 로컬 인식과 브라우저/개발 채널 조건을 설명한다. 모든 운영 브라우저에서 동작한다고 간주하지 않고 실제 기능과 언어 팩의 가용성을 확인한다.

실제 관제 PC의 한국어·로봇명·장소명·소음 수용 시험은 아직 수행하지 않았다. 대상 브라우저에서 로컬 한국어 인식을 지원하지 않거나 품질이 기준에 못 미치면 AI PC STT를 별도 구현한다. 그때 모델·승인·음성 길이·본문 크기·디코딩 시간·동시 처리 한도를 계약에 먼저 확정한다. 지금의 소스 회귀 통과로 음성 품질 수용을 표시하지 않는다.

TTS는 브라우저의 로컬 한국어 음성만 사용한다. 음성이 없거나 재생이 거절되면 텍스트 응답을 유지하고 이유를 표시한다. 읽어주기는 사용자가 누르며 언제든 중단할 수 있다. 녹음 시작 전 재생을 중지해 AI 음성이 다시 입력되지 않게 한다. 실시간 음성 대화와 전용 TTS 모델은 첫 버전에서 제외한다.

## 실행과 실패

1단계와 2단계는 조회 전용이다. 이동·작업 요청에는 아직 실행을 지원하지 않음을 명시하고 기존 작업 화면으로 안내한다. 조용히 실행한 것처럼 답하지 않는다.

3단계는 이름 있는 운영자의 요청만 기존 실행 경로에 연결한다. 동일 요청의 중복 실행 방지, 현재 권한·지도·정지 세대·자원·원장 결속을 보존한다. 수동 비상정지는 항상 기존 경로를 사용한다. “그만”처럼 의미가 불명확한 대화를 비상정지 기능의 대체 수단으로 사용하지 않는다.

모델 미설정·승인 만료·서비스 단절 시 AI 기능의 준비 안 됨/보류 상태와 근거를 표시한다. 마이크 거부·STT 실패·TTS 미지원은 텍스트 경로로 복귀한다. 인증 만료와 네트워크 단절을 다른 상태로 표시하고, 실행 여부가 불명확한 요청은 다시 보내서 해결하지 않는다.

## 검증과 제외 범위

완료 증거는 실제 모델 연결 상태, 원격 자동 시험, 한국어 음성 수용, 허용된 현장 작업 결과를 구분해 기록한다. 가짜 모델을 쓰는 UI 시험은 실제 모델 품질 증거가 아니다.

현장 사람↔로봇 대화, 로봇 마이크·스피커, 상시 청취, 모델 학습, 임의 도구 실행, 새로운 로봇 제어 경로는 제외한다. 공급자·모델 변경과 음성 엔진 확정은 준비 시험 결과를 기준으로 하며 이 초안에서 승인하지 않는다.

# Cell 문서 편집 확장

사용자의 계속 처리 요청에 따라 D-450 G1의 입력 흐름을 보완한다. 기존 Console·문서 revision·canonical compiler를 유지한다. 장치 TCP 관측이나 티칭 수락을 문서 저장으로 대체하지 않는다.

## 설계

기존 박스·home 입력 옆에 레시피 이름·작업 방향·공급 스테이션, 팔레트 ID/프레임/치수/허용 적재량, 층 패턴/대칭/슬립시트 여부를 편집하는 폼을 제공한다. 층과 팔레트는 명시적으로 추가·삭제한다. 슬립시트 설정을 제거해도 층의 요구 조건을 자동으로 지우지 않으며 canonical compiler가 불일치를 거절한다.

셀에는 프레임의 세 XYZ 티칭점, 프레임 판정 한계, 스테이션의 프레임/XYZ/yaw 편집을 제공한다. 길이는 m, yaw는 rad, 프레임 각도 한계는 deg로 표시한다. 기존에 승인·측정한 문서를 입력하는 기능이며 로봇을 움직이거나 측정값을 만들어 내지 않는다.

모든 변경은 JSON 문서와 동일한 한 초안을 고치고 이전 미리보기를 무효화한다. 저장 CAS와 작업 제안의 해시 검사는 그대로 사용한다. 네트워크 처리 중 동적 입력·추가·삭제도 잠그며 수정 전 응답은 기존 edit epoch로 거절한다. 새 REST 경로나 실행 writer는 만들지 않는다.

## 구현과 검증

1. 실제 Chromium에서 구조 편집·저장·재접속·재계산과 잘못된 층 적재의 거절을 먼저 실패로 확인한다.
2. 별도 Console 자산 모듈에 폼을 구성하고 allowlist에 등록한다. 기존 문서 저장·컴파일·승인 로직은 재사용한다.
3. 변경 후 브라우저 회귀, Cell API/store/job 회귀와 모바일 overflow를 확인한다.
4. 독립 검토와 관련 계약 검사를 통과한 범위만 커밋·로컬 main에 머지한다.

## 수용 경계

이 변경은 G1 초안 편집 증거다. D-404의 장치 티칭 프록시·fresh TCP capture·원자적 운전석 상호 배제와 owner 수락/readback은 별도 구현·검증이 필요하다. G2 전체 적재 및 G3 슬립시트 장치 수용을 완료로 표시하지 않는다.

# 카메라 추종 판단 표시 개선

사용자 범위: 차선·경로 추종과 주변 객체 표시. 현재 도로 미리보기의 청록색 선은
도로 페인트의 전체 무게중심 오차를 표시했으며 실제 추종기의 경로나 목표점이 아니었다.
같은 화면에서 무엇을 봤고 어떤 목표를 골랐는지 구별한다.

## 표시와 근거

- `line/keep_debug`: 초록 왼쪽 경계, 파랑 오른쪽 경계, 주황 제외 후보와 이유,
  자홍 목표점·점선 목표 방향, 전략·오차·신뢰도. `image_size`와 `ground`는
  내부 진단 묶음의 추가 정보이며 외부 API를 신설하지 않는다.
- `line/observation`: keep 이외 카메라 모드에서는 동일 프레임 CAMERA_LINE의
  방향·오차·신뢰도만 표시한다. 공간 목표점이 없으면 만들지 않는다.
- `camera/observation`: 기존 분할 검출기의 영역 박스. F는 foreground, D는 dark,
  번호는 해당 프레임 안의 영역 번호다. NEAR는 검출기의 near_path 근거이다.
  사람·로봇 클래스, 지속 추적 ID, 객체 속도는 제공하지 않는다. 거리 `m`이
  없으면 `unranged`. 최대 48 박스 중 3개만 글자를 붙여 화면 가림을 제한한다.
- `perception/road_state`: 기존 D-384 추정기의 상태로 별도 ROAD SHADOW 평면도에
  0.33 m 이내 차선 중심과 경계를 표시한다. 모델은
  `y = -d - x*phi + kappa*x*x/2`. TRACK/COAST/SLOW만 표시하고 STOP·보정 의심·
  잘못된 수치는 숨긴다. 노드가 실행되지 않으면 `PRED unavailable`이다.
  이는 도로 형상의 추정이며 최종 모터 명령 궤적이나 객체 이동 예측이 아니다.
- 도로 PAINT 무게중심은 작은 청록 점으로 표시한다. STOP/CROSSWALK는 기존
  검출 결과에 신뢰도와 거리 유무를 표시하고 신호 상태는 LIGHT로 이름 붙인다.

## 연결 및 실패 상태

기존 `camera/preview/compressed`와 CORE의 인증된 JPEG 경로를 그대로 사용한다.
영상 메타데이터는 `follow-road-v2`. 각 근거는 8개 프레임을 보관하고 촬영 시각이
1 us 이내로 일치하는 것만 합친다. 최신 프레임의 콜백이 처리 중이면 0.5 s 이내의
최근 완료 프레임을 선택한다. 다른 시각의 객체·추종 결과는 합치지 않는다.
타이머는 기존 최대 2 fps/640 px/JPEG 바이트 제한을 유지한다.
보정 변경과 카메라 시각 역행은 프레임·근거 캐시를 비운다.

근거 부재는 unavailable이며 안전·모터 정지 명령을 뜻하지 않는다.
HOLD/FOLLOW는 추종 관측 상태이고 CORE의 최종 주행 허가를 보증하지 않는다.
UI는 제어 경로를 바꾸지 않으며 감지 입력에는 오버레이 영상을 재사용하지 않는다.

## 검증

모듈 크기 판단: control 전체 크기는 40,547행 기준에서 40,803행으로 증가했다.
추가 표시 로직은 ROS-free `perception/follow_preview.py`에 분리했고 ROS 구독은 기존
observer에 둔다. 새 프로세스·writer·감지 의존성을 만들지 않으며 기존 P1a의
sensing/safety 분리 대상과 함께 이동한다. 따라서 기존 `split` 판단을 유지하고
현재 크기를 기록한다. 크기 허용 여유나 실패 목록은 변경하지 않는다.

순수 시험: 촬영 시각 조인·지연 콜백·유한 캐시·잘못된 수치·HOLD 목표 숨김,
카메라 모드의 방향 표시, 경계/영역 렌더링, 기존 도로 모델 식과 STOP 억제.
기존 녹화 영상의 재생 결과를 변경 전후로 렌더링한다. 재생의 NOMINAL 지면 모델은
실기 보정이 아니며 실제 객체 거리로 내보내지 않는다. 추정기가 STOP인 녹화 구간은
예측을 숨기는 것이 올바른 결과다. ROS 그래프 실행·설치·현장 수용은 별도 검증이다.

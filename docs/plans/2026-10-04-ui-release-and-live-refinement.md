# 웹 UI 배포와 전체 화면 순차 개선

사용자 지시: 남은 커밋을 반영·배포하고 전체 화면을 순서대로 점검한다.
결정 근거: D-439 공용 작업 디자인, D-225 서명 로봇 릴리스, D-301/D-441 사이트 후보 검증,
D-427/D-430 경로 이전·안전 소유권. 이 계획은 실제 실행 증거를 대신하지 않는다.

1. 원격 main의 경로 이전과 로컬 UI 개선을 원격 기준의 통합 worktree에서 합친다.
   공유 main의 역사·다른 세션 파일을 보존하고 force-push하지 않는다.
2. 이동된 Pilot Android의 자산·공용 Cam 빌드 입력과 registry를 실제 위치에 맞춘다.
   두 부모의 신호 감독·판단기·영상 증거·정지·IDLE 예약 소유권을 독립 검토한다.
3. 실제 원격 CI 실패를 재현하고 호환 동작·빌드 제외 범위를 고친다. 단언·skip·예산으로
   실패를 숨기지 않는다. 영향 검사·quick·생성 기록과 CI를 구별한다.
4. 정식 서명 로봇 릴리스와 사이트 후보를 만들어 기존 Pinky·관제 PC에 적용한다.
   Lenovo Pilot·S21 Cam은 기존 자격과 설정을 유지하는 앱 업데이트로 설치한다.
   장비가 응답하지 않으면 발견/기존 접속 경로를 확인하고 다른 장비로 대체하지 않는다.
5. 실제 동작과 화면을 로봇 진입 → 운용/카메라 → 준비/설치/정비 → Fleet → 게임/도구
   순서로 읽기 전용 점검한다. 이동·비상 정지 해제나 허가되지 않은 운용으로 검사하지 않는다.
6. 각 화면의 원인·수정·유지 이유·검증·미확인 사항을 D-439 검증 기록에 추가한다.
   desktop/mobile 점검 한 묶음과 수정 후 한 묶음으로 확인하고 불필요한 반복 polish를 피한다.

7. 실물 수용 후 dashboard 패키지의 10148줄을 담당 화면별로 다시 검토한다.
   D-447 상태 구독 store는 하나의 transport 담당으로 유지한다. 남은 재사용 자산을
   기존 shared/web 담당으로 모을 수 있는지 실제 소비 경로로 판단하고,
   역할별 원본 경계와 installed-resource 계약을 기록한다. 새 ROS 실행 프로세스나
   중복 소켓을 만들지 않으며 파일 상한·패키지 +150 허용치를 유지한다.

8. Pilot 화면별 responsive CSS를 기존 로비·연결·운용 담당에 맞춰 분리한다.
   좁은 화면의 44px 조작 면적 수정은 유지한다. asset loading 순서, 공용 토큰,
   installed-resource와 Android APK 자산 일치를 검증한 뒤 분리하며 파일 상한을 바꾸지 않는다.

현재: 통합 소스의 독립 검토, migration/구조 110 PASS와 나머지 quick 370 PASS/2 SKIP를 확인했다.
기존 인증서가 동일한 Pilot·Cam APK를 무선 ADB `install -r`로 업데이트했다.
원격 CI와 서명된 로봇/관제 후보 배포, 순차 실물 화면 수용은 진행 중이다.
상세 결과는 `docs/validation/ui-release-integration-2026-10-04/README.md`에 기록한다.

## Cam 실기 화면 후속 정리

실제 송출 화면에서 IPv4·IPv6 주소와 세부 통계가 영상 및 운영 동작을 밀어내는 것을 확인했다.
기본 화면은 수신 대상·송출 상태·온도·마커 안내·초당 프레임·촬영 유지/종료 동작을 보여준다.
주소·렌즈·비트레이트·요청 품질은 명시적인 '연결·송출 정보 보기'로 펼친다. 접어도
오류·발열 경고·렌즈 변경 실패·프레임 누락 안내는 보인다. 송출·설정·인증 정책은 유지한다.
검증은 기존 JVM suite와 APK 빌드 후 실제 폰에서 접힘/펼침 및 촬영 유지 여부를 확인한다.

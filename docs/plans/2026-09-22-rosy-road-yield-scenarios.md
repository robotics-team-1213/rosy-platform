# rosy_road 도로 회로 — 점유 우선권 양보 시나리오

- 날짜: 2026-09-22
- 상태: SOURCE — 월드/맵 생성 완료, S1~S6 은 기존 코드로, S7(선착)은
  `traffic.py` ETA + `console.py` 대기 풀기 순서로 구현되어 시험 통과
  (`test_server_priority.py`, fleet 372 passed). Gazebo 실측 증거는 미수집.
- 배경: 260919 MAP FILE.STL 을 1:1 Gazebo 월드(`rosy_road.world`)와 nav2 정답 맵
  (`rosy_road.yaml`)으로 변환했다. 도면이 도로 회로(방 + 로터리 + S 커브)라서,
  도로 교통 규칙에 대응하는 양보 시나리오의 베이스가 된다.

## 1. 맵 개요 (월드 좌표, 단위 m)

월드 원점은 도면 좌하다. 사이트 2.81 x 1.27 m. 생성: `stl_to_world.py`,
`world_to_map.py --resolution 0.02 --seed 0.48,0.64`.

| 요소 | 위치/크기 | 역할 |
|---|---|---|
| 좌측 방 | 내부 x 0.24~0.71, y 0.24~1.05 (0.47 x 0.81) | 대피/회차/대기. 유일한 넓은 공간 |
| 방 문(서쪽 개방부) | x≈0.73, y 0.50~0.80, 폭 ~0.44 m | 방과 링 접근부 사이 1차선 병목 |
| 로터리 | 중심 (1.07, 0.642), 섬 반경 ~0.15, 순환 차로 반경 ~0.25 | 교차로. 점유 우선권의 무대 |
| 로터리 진입부 | 서(0.85, 0.64) / 북(1.07, 0.95) / 남(1.07, 0.35) / 동(1.35, 0.64) + 사선 | 진입 양보 판정 지점 |
| 상단 통로 | y≈1.16, x 0.6~1.3 | 일방통행 링크 |
| 하단 통로 | y≈0.14, x 0.6~1.3 | 일방통행 링크 |
| 좌측 통로 | x≈0.14, y 0.05~1.22 | 방 주변 회랑 |
| S 커브 + 우측 루프 | x 1.4~2.8 | 시야 없는 추종 구간 |

차로 폭은 도면 그대로 0.10~0.20 m 다. pinky 풋프린트 반폭 0.06 m — 한 대는
"약간의 여유"로 지나가고(2026-09-22 사용자 실험), 두 대는 어디서도 못 지나간다.
그래서 이 맵의 교통은 전부 **일방통행 + 양보**다.

## 2. 교통 규칙 (도로 -> fleet 대응)

| 도로 규칙 | fleet 규칙 | 구현 상태 |
|---|---|---|
| 본선 주행 차량 우선 — 세우지 않는다 | claim + NAVIGATING 로봇 선점 금지 | 있음 (`traffic.py`, 콘솔) |
| 로터리 순환 차량 우선, 진입 차량 양보 | 경로 충돌 시 신규 미션 대기 | 있음 (`ROUTE_CONFLICT`) |
| 교차로 먼저 도달한 차 우선 (선착) | 충돌 지점 ETA 비교 | **없음 — S7, traffic.py 확장** |
| 동시 도착은 결정적 타이브레이크 | robot_id 정렬 (기존) | 있음 |
| 막다른 길 맞바꾸기 | `bays` 벽감 양보 | 있음 |
| 대피소 | 좌측 방 (`_make_room`) | 있음 |
| 신호등 | ROSY-SIGNAL-001 — 표시 장치일 뿐 인터록 아님 | 있음, 철학 유지 |
| 구급차 우선(미션 클래스) | 계약 변경 필요 — API Ref 사이클 | 안 함 |

## 3. 시나리오

공통 관측면: fleet console snapshot(`queued.reason`, `yielding`, `goal`),
core 이벤트(`nav.started` / `nav.canceled` / `nav.completed` 타임라인),
가제보 ground truth 최소 거리. 합격 기준: 별도 표기 없으면 60 s 안에 두 미션 모두
`ARRIVED`, 교착 시 화면이 거짓 약속(자동 출발 문구)을 남기지 않을 것.

### S1 로터리 진입 양보 (핵심, 기존 코드로 통과해야 한다)

- 배치: A 스폰(방) -> 목표 링 동쪽(1.35, 0.64). B 스폰(하단 통로) -> 목표 링 서쪽
  (0.85, 0.64). A 를 먼저 내리고 링에 진입시킨 뒤 B 를 내린다.
- 기대: B 의 경로가 A 의 순환 경로와 겹쳐 `ROUTE_CONFLICT` 로 대기. A 가 링을 빠져
  나가면(claim 해제) B 가 재하달된다.
- 관측: A 주행 중 B 의 목표가 취소되었는가(로봇을 세우지 않고 미션만 대기했는가).

### S2 로터리 안 맞마주침 (기존 코드)

- 배치: A 는 링 서쪽에서 동쪽 목표, B 는 링 동쪽에서 서쪽 목표 — 순환 방향이 서로
  반대. 링 차로는 1차선이라 둘 다 못 지나간다.
- 기대: 먼저 내린 미션이 claim 을 쥔다. 늦은 미션은 대기하고, 대기만으로 풀리지
  않으면(서 있는 로봇이 길을 막은 형국) 입구 쪽으로 베이 양보(`YIELDING`).
- 관측: 양보자가 입구 쪽인가(링 한가운데가 아니라), 양보 후 원 목표로 복귀하는가.

### S3 상단 통로 맞마주침 — 자리가 없으면 없다고 말한다 (기존 코드)

- 배치: 상단 통로 양 끝에서 서로의 자리로 맞바꾸기. 통로 폭 0.15 m, 벽감 없음.
- 기대: 둘째 미션은 `NO_YIELD_SPACE` — 화면은 "물러나면 출발합니다"가 아니라 사람을
  부른다. 운영자가 한 대를 치우면 남은 미션이 저절로 나간다.
- 근거: 폭 1 m 방 실측(2x1 m 맞바꾸기 실패)의 재현이다. 이 맵은 그 방보다 좁다.

### S4 방 = 대피소 (기존 코드)

- 배치: A 가 하단 통로를 달리는 중, B 의 목표를 A 의 목표 자리로 내린다.
- 기대: B 는 대기하고, 길을 막은 서 있는 로봇이 없으면 그대로. 서 있으면
  `_make_room` 이 방으로 피한다 — 방 문(0.44 m)은 1차선이라 피하는 동안 A 의
  경로가 문을 겹치면 A 가 먼저다.
- 관측: 양보 배치가 방 안인가(통로 한가운데가 아니라), `BAY_SLACK_M` 만큼 깊이
  들어갔는가.

### S5 문 병목 교차 (기존 코드)

- 배치: A 는 방 안에서 밖으로, B 는 밖에서 방 안으로 — 동시에.
- 기대: 문은 1차선이다. 하나의 미션만 나가고 나머지는 `ROUTE_CONFLICT` 대기.
  두 대가 문 안에서 만나면(이미 늦은 상태) 베이는 방이므로 B(밖) 가 양보한다.

### S6 3대 순환 스트레스 (기존 코드)

- 배치: 3대를 방, 상단 통로, 하단 통로에 두고 링을 공유하는 목표를 연속 내린다.
- 기대: 우선순위가 mission 순서 + robot_id 로 결정적 — 같은 배치면 매번 같은 대가
  양보한다. 대기 최장 시간을 기록해 기아 한계선을 본다.
- 관측: 대기 행렬이 풀리는가(순환하면 반드시 풀린다), 화면의 대기 사유가 실제와
  일치하는가.

### S7 교차 입구 선착 — ETA 점유 우선권 (구현: 대기 풀기 순서)

- 배치: 블로커 뒤에서 두 미션이 대기 중 — rosy_01 은 공유 충돌 지점까지 멀리,
  rosy_02 는 바로 앞. 블로커가 지나가 두 미션이 같은 스냅샷에서 풀린다.
- 동작(2026-09-22 구현): `_run_traffic` 이 대기자를 풀 때 robot_id 순 대신
  `traffic.remaining_distance`(경로 따라 충돌 지점까지 남은 거리)가 짧은 미션부터
  내려보낸다. 경로/좌표를 모르면 무한대로 밀리고, 동점이면 robot_id — 결정적이다.
- 상한선(변경 없음): 점유 클레임(달리는 로봇)은 선착과 무관하게 이긴다. ETA 가
  바꾸는 것은 **대기자들 사이의 순서**뿐이다. 달리는 로봇을 세우는 데 쓰지 않는다.
- 구현 위치: `traffic.py` `closest_points` / `remaining_distance`(순수 기하),
  `console.py` `_release_order`. 시험 `test_server_priority.py`.
- 계약 변경 없음: 우선권은 점유 상태에서만 온다. 미션 우선순위 클래스(구급차)는
  별도 — `goal()` 계약 확장이고 API Ref 사이클부터 도는 별도 작업이다.

### S8 전체 정지/취소 복귀 (회귀)

## 5. 남은 과정 / 알려진 이슈

1. **차로 폭 vs nav2 footprint (QA 수치 확정)**: `nav2_params.yaml` 는 footprint
   폴리곤 `[[±0.06, ±0.06]]` + `footprint_padding: 0.03` — **실효 폭 0.18 m** 다.
   rosy_road 차로는 0.10~0.20 m 라서, 0.18 m 이상 차로(링 차로, 넓은 S 커브)만
   주행 가능하고 0.10~0.15 m 급(상하 통로, 좌측 통로)은 플래너가 거절한다. 선택지:
   (a) 이 월드 한정 `footprint_padding: 0.01` 로 0.14 m 까지 낮추거나, (b) 맵을
   `stl_to_world.py --scale 1.3` 로 재생성해 차로를 0.13~0.26 m 로 키우거나,
   (c) 좁은 구간은 보행 전용으로 남긴다. `worlds.yaml` 의 `inflation_radius: 0.05`
   는 (a) 전제로 잡아 두었다.
2. **외곽 프레임 "누수"의 정체**: free 가 프레임 밖으로 새어 나간 게 아니라
   **프레임 이중선 사이 슬리버**(x 0.01~0.05 m 대역 152 셀)가 free 로 잡힌 것이다.
   inflation 이 흡수해 항법 영향 없음 — 다음 정비 때 `stl_to_world.py` 에 래스터
   closing 을 넣어 지운다.
3. **벽 관절 핀홀**: 이중선 벽의 활선 사이 틈. costmap inflation 이 흡수한다 —
   맵을 SLAM 정합성 비교에 쓸 때만 문제가 된다.
4. **표시 제거 판정**: 슬롯/rung 사각형 여덟 개와 로터리 입구 X자, 문 사다리는 바닥
   표시로 뺐다(사용자 결정). 실물에 이것들이 벽/언덕으로 있다면 `MARK_ZONES` 와
   `MARK_MAX_EXTENT_MM` 를 되돌려야 한다.
5. **Gazebo 실측**(S1~S8 필드 증거): Windows 호스트는 런치 불가 — Linux/Pi 에서
   `gz_multi.launch.py world_name:=rosy_road.world robots:=2` 로 위 시나리오를
   돌리고 이벤트 타임라인과 최소 거리를 logs.md 에 남긴다.

# 스테이션 정밀 접안과 자동 충전 운영 설계

상태: 사용자 설계 승인(2026-10-16, "그럼 그걸 목표와 설계에 반영하고 진행하도록 해볼래?"). 승인 범위는 자동 충전 운영, 배터리 상태에 따른 복귀·재투입, 스테이션 이동 후 위치 재확인·복귀다. 구현·배포·실기 검증 완료를 뜻하지 않는다. 실행 순서와 구체 계약은 [구현 계획](2026-10-16-station-charge-lifecycle.md)으로 연결한다.

기준 소스: `436d52a55`. 첫 범위: 스테이션 1개, 이동 로봇 1대. 이후 다중 로봇에서도 스테이션 예약과 장치 소유권을 유지할 수 있게 한다.

## 목표와 완료의 의미

사용자가 요구한 흐름은 작업 중 배터리를 감시하고, 필요한 시점에 충전 스테이션으로 복귀하고, 정밀 접안·충전·완료 확인을 거친 뒤 작업에 다시 투입되는 자동 운영이다. 스케줄은 주기적으로 재평가하고 배터리 변화·작업 완료·충전 상태 변화에도 즉시 재평가한다.

전체 목표를 다음 다섯 부분으로 검증한다. 일부 부분의 성공으로 전체를 완료 처리하지 않는다.

1. 스테이션 카메라의 유효한 상대 위치 관측으로 기존 로봇 내부 접안 제어기를 구동한다.
2. 위치 공차, 실제 정지 관측, 물리 착좌 신호가 모두 확인된 뒤 충전 상태를 인정한다.
3. 배터리 잔량·건강도·작업 비용·귀환 비용을 근거로 복귀와 재투입을 결정한다.
4. 충전 완료 후 출발 조건을 재검사하고 이안 완료를 확인한 뒤 새 작업을 배정한다. 재시작·중복·통신 끊김에도 이전 작업을 무조건 재실행하지 않는다.
5. 스테이션 위치가 바뀌면 이전 좌표를 무효화하고, 관제·로봇이 같은 지도와 위치 버전으로 새 복귀 위치·방향을 확인한다. 새 위치의 접근 가능성과 귀환 에너지 여유를 확인한 뒤 복귀·정밀 접안한다.

## 선택한 접근과 대안

권고는 기존 로봇 내부 접안 제어기를 유지하고, 스테이션 관측 어댑터와 Fleet 충전 운영 정책을 연결하는 것이다. Fleet은 언제 복귀·출발할지 결정하고, CORE는 각 동작의 수락·정지·최종 속도 출력을 소유한다. 충전기의 전기적 충전 종단과 접점 개폐는 충전기/스테이션 장치가 맡는다.

대안인 고정 잔량 임계만의 복귀는 초기 보수적 운용에 사용할 수 있지만 작업 비용과 열화를 반영하지 못한다. Fleet에서 카메라를 보며 직접 속도를 계속 보내는 대안은 기존 CORE 제어·정지 경계를 우회하므로 채택하지 않는다. 기존 Nav2 도킹 전체 교체는 이번 목적에 필요하지 않다.

## 관측과 정밀 접안

스테이션 관측은 대상 robot/station, 촬영 시각, 순번, 세션, 교정 revision, 좌표계, 상대 위치·방향, 관측 유효성과 오차 근거를 결속한다. 기존 표시용 sighting의 quality=null을 제어 품질로 승격하지 않는다. 카메라 장착과 로봇 마커 장착 오프셋을 함께 교정하고 스테이션 작업 기준 좌표에 연결한다.

좌표 변환은 카메라/스테이션 좌표에서 측정한 로봇 포즈로부터 기존 검출기 경계가 요구하는 base_link 기준 목표 상대 포즈를 계산한다. 스테이션 목표 착좌 위치와 마커 위치는 별도 오프셋이다. 검출 시각의 odom과 결속하고 이후 odom 증분으로 보정하며, 서로 다른 시계의 값을 직접 빼지 않는다. 출처·대상·순번·세션·revision 불일치, 미래 시각과 만료 관측은 거절한다.

로봇은 접근 허용 범위와 속도 한도 안에서 기존 제어기를 실행한다. 관측 유실 시 유실을 인지한 로컬 제어 틱에서 정지 출력을 요구한다. 자동 복구·재착좌는 거리·횟수·시간 예산 안에서만 가능하고, 예산 소진은 HOLD와 사유를 남긴다. 기존 습관적 크리프는 새 스테이션 프로필에서 별도 검증 없이 허용하지 않는다.

착좌 판정은 위치 공차 안의 최신 관측, 측정 속도가 정지 범위 안인 연속 관측, 디바운스된 리밋스위치 또는 동등한 물리 착좌 근거를 함께 요구한다. 명령 0 또는 DOCKED 문자열만으로 실제 정지를 확정하지 않는다. 접점 통전은 MCU의 기존 부하 인터록을 유지한다.

## 스테이션 이동과 관제·로봇 좌표 합의

사용자 추가 요구(2026-10-16): 충전 스테이션 위치가 바뀌어도 관제와 로봇이 새 좌표를 산출·공유해 복귀해야 한다. 스테이션 식별자와 설치 위치는 분리한다. 같은 충전기가 이동하면 station ID는 유지하고 위치 버전만 올린다. 다른 충전기로 바뀐 경우 위치가 같아도 같은 장치로 취급하지 않는다.

**위치를 알아낼 수 있는 관측부터 구별한다.** 스테이션에 붙은 카메라로 로봇만 보는 경우 로봇과 스테이션 사이의 상대 위치는 알 수 있지만 새 지도상 절대 위치는 그 관측 하나로 정해지지 않는다. 다음 세 방법으로 지도 기준을 확보한다.

1. 고정 현장 카메라가 식별 마커를 가진 스테이션을 관측한다. 승인된 현장 교정과 스테이션 마커→목표 착좌 오프셋으로 새 지도 포즈를 산출한다. 기존 로봇 sighting에 station ID를 끼워 넣지 않고 별도 대상 계약을 정의한다.
2. 새 위치의 스테이션 또는 로봇 카메라가 지도 기준 마커를 관측하거나, 지도 위치가 유효한 로봇과 상대 포즈를 함께 관측한다. 2차원 변환을 합성해 계산하되 관측 시각과 지도/odom 세대, 마커 장착 오프셋의 불확실성을 함께 전파한다. 로봇 지도 위치 자체를 같은 스테이션 관측에서 만든 경우 이를 독립 근거로 중복 사용하지 않는다.
3. 자동 관측 범위 밖이면 설치 절차로 새 지도 위치와 접근 구간을 확인한다. 사람이 숫자를 입력하거나 기존 teach API를 호출했다는 사실만으로 자동 복귀 가능 상태가 되지 않는다. teach-by-docking은 현재 로봇 자리의 기록이며 이동한 충전기의 자동 발견이 아니다.

카메라도 스테이션과 함께 움직였다면 기존 카메라→지도 교정은 재사용하지 않는다. 카메라→스테이션 장착 변환은 장착이 유지된 경우에만 유효하다. 회전 이동도 위치 변경이다. 지도 ID가 같더라도 지도 revision이 다르면 기존 좌표와 섞지 않는다.

**위치의 권위는 관제의 검증된 설치 기록 하나에 둔다.** 로봇·카메라는 관측 후보를 보내고 Fleet이 출처·대상·시간·좌표계·오차와 반복 일관성을 확인해 위치 버전을 발행한다. 지도 포즈를 단순 평균하거나, 메시지 수신 순서가 늦다는 이유로 최신 위치로 채택하지 않는다. 로봇은 그 버전과 지도/프레임을 수락했는지 회신하고, CORE가 사용할 수 있는 좌표 변환과 접근 실행기가 있을 때만 복귀를 수락한다. D-758은 Proposed이며 이 설계에서 이미 구현된 공통 지도 기준이라고 가정하지 않는다.

설치 기록은 station ID, map ID와 revision, 위치·방향, 위치 버전, 측정 시각·출처·교정 revision, 오차 근거, 유효 상태, 안전한 진입·후진 구간을 결속한다. 기존 도크 포즈는 목표 착좌 위치이고 진입 위치는 기종 오프셋으로 별도 산출한다. 새 위치가 기존 차로 그래프 밖이면 차로 종점에서 스테이션까지 검증된 연결 구간을 마련해야 하며 임의 공간 주행으로 대체하지 않는다. 위치 버전·교정 revision·충전 세션 ID는 서로 다른 식별자다.

제안 상태 흐름은 `위치 유효 → 이동 의심/이전 위치 무효 → 새 위치 후보 → 관측·접근 검증 → 새 버전 확정 → 로봇 수락 → 복귀 가능`이다. 장치 이동 신고, 유효한 지도 관측의 지속적인 변화 또는 기준 마커 변화로 재검증한다. 검출 잡음 하나로 변경을 확정하지 않는다. 관측 사각지대의 이동을 자동으로 감지한다고 보장하지 않으며, 관측 유효기간과 복귀 시 재확인으로 오래된 좌표의 무조건 사용을 막는다.

복귀·접안 명령은 위치 버전에 결속한다. 이동 의심 또는 새 버전 발행 시 이전 버전의 예약·계획은 실행 불가로 표시하고, 진행 중인 로봇에 취소/정지를 요청한다. 로봇 로컬 유효기간과 관측 유실 정지는 관제 취소 메시지가 끊겨도 유효하다. 정지·이전 시도 종료를 확인하기 전 새 목표로 덮어쓰지 않는다. 이미 시작된 DockingManager가 도크 포즈를 캐시할 수 있으므로 데이터베이스 한 행의 수정으로 실행 중 목표가 바뀐다고 가정하지 않는다.

새 위치 확정 후 Fleet은 경로와 충전 접근 비용을 다시 계산한다. 늘어난 귀환 거리와 탐색 비용 때문에 배터리 여유가 부족하면 안전 정지·운영자 지원으로 전환한다. 위치가 불명일 때 마지막 좌표로 반복 주행하거나 무제한 탐색하지 않는다. 자동 재탐색은 승인된 영역·시간·에너지 예산 안에서만 한다. 로봇이 충전 중인 스테이션을 옮기는 경우 일반 재탐색으로 처리하지 않고 접촉 상실·움직임·충전 이상을 처리해 자동 이안과 재투입을 막는다.

충전 복귀는 `검증된 새 진입 위치까지 이동 → 스테이션 ID·위치 버전 재확인 → 상대 위치 폐루프 접근 → 착좌·충전 확인`으로 수행한다. 관제·로봇 좌표 수락 ACK는 위치의 실측 정확도나 실제 접안 성공을 증명하지 않는다.

## 충전 운영 상태와 소유권

아래 이름은 설계 내부 의미이며 기존 공개 enum/API를 이미 확장했다는 뜻이 아니다.

`작업 가능 → 복귀 예약 → 작업 안전 종료/보류 → 복귀 → 접안 → 충전 확인 → 충전 중 → 충전 완료 대기 → 출발 검사 → 이안 → 작업 가능`

모든 단계에서 고장·증거 불명·취소는 사유가 있는 HOLD로 이어진다. 저전압 긴급 대응은 일반 스케줄보다 우선하고 기존 로컬 정지·셧다운 경로를 약화하지 않는다. 수동 조작과 E-stop이 자동 출발보다 우선한다.

Fleet은 robot과 station 자원을 원자적으로 예약하고 충전 세션 ID와 각 동작 attempt를 저장한다. 작업 배정과 충전 복귀가 동시에 로봇을 잡지 못하게 기존 admission/claim에 통합한다. 로컬 저배터리 복귀가 이미 시작됐으면 Fleet은 관측·대조하고 두 번째 복귀를 제출하지 않는다. Fleet이 없어도 CORE의 저배터리 보호는 유효하다.

충전 중 로봇은 일반 배정 대상에서 빠진다. 충전 완료는 즉시 출발 명령이 아니다. 작업이 없으면 충전기 규칙에 따라 안전하게 대기하고, 승인된 작업이 있으면 출발 검사를 거쳐 자동 이안한다. 대기 중 재충전은 히스테리시스로 처리해 출발·복귀가 반복되지 않게 한다.

## 배터리 정보와 복귀 스케줄

잔량(SOC 추정), 용량 열화(SOH), 데이터 신뢰도, 고장 상태를 별도 사실로 취급한다. 건강도 수치는 배터리 ID·측정 시각·측정 방법·정격/실측 용량·유효 조건·revision에 결속한다. 미측정값을 100% 또는 건강함으로 채우지 않는다. 전압 하나, 충전 횟수 하나로 실측 SOH를 만들어내지 않는다.

측정 가능한 구성에서는 팩 전류·전압·온도 또는 검증된 BMS/fuel gauge 값을 받아 유효 용량과 부하별 소모를 추정한다. 도크 전류는 로봇 부하와 충전 손실을 분리하지 않으면 팩 유효 용량의 직접 측정이 아니다. BMS/gauge가 없는 현재 구성은 건강도 미측정으로 유지하고 승인된 보수적 운행 프로필을 사용한다. 이 프로필과 작업 비용 근거도 없으면 자동 작업 배정을 거절한다. 전체 건강도 적응 운영의 장치 수용에는 실제 계측이 필요하다.

새 작업 수락 조건은 같은 단위로 환산한 보수적 사용 가능 에너지가 `작업 에너지 + 스테이션 귀환 에너지 + 대기·접안·재시도 에너지 + 예비 에너지`를 충족하는 것이다. 예측 비용은 실측으로 검증된 경로/작업/적재 프로필과 불확실성 상한을 사용한다. 계측이 부족한 초기 구성은 승인된 최대 작업·귀환 시간과 잔량 임계로 제한하며 예측값을 실측으로 표시하지 않는다.

복귀 판단은 주기 재평가와 배터리 경보·작업 경계·경로 변경·스테이션 상태 변경 이벤트에 반응한다. 동작 도중 재평가는 임의 중단을 뜻하지 않는다. 안전하게 끝낼 수 있는 현재 작업 단위와 귀환 여유가 있으면 그 경계에서 복귀하고, 부족하면 로컬 보호 정책으로 전환한다. 작업의 재개 지점은 저장하고 성공이 불명인 동작은 자동 반복하지 않는다.

스테이션 이동 또는 위치 유효성 변경도 스케줄 재평가 이벤트다. 기존 위치로 계산한 귀환 비용과 재투입 에너지 예산을 폐기한다. 스테이션이 아직 검증 중이면 새 작업 수락 조건에 사용 가능한 충전 목적지가 없다는 사실을 반영한다.

열화 또는 높은 소모가 관측되면 작업 허용 범위를 줄이고 더 이른 복귀와 큰 예비량을 적용한다. 고장과 계측 범위 밖 온도는 유지보수 HOLD로 처리한다. 특정 SOH·온도·충전 상한 수치를 제조사 사양과 측정 없이 기본값으로 정하지 않는다.

## 충전 완료와 재투입

물리 만충은 충전기/BMS의 정상 종단 근거와 유효한 팩 상태로 확인한다. 단순 전류 없음은 접촉 불량·충전기 고장·종단을 구분하지 못하므로 완료로 간주하지 않는다. 현재 전압 전략의 CHARGED_HOLD 이벤트만으로 자동 재투입하지 않는다. 과거 peak 전압 대신 최신 팩 표본을 요구한다.

기준 소스에서 `ChargingConfirmation.update()`는 도크가 charging=false를 보고하면 `reset()`으로 peak_v도 지운다. `_tick_docked()`는 그 뒤 `_check_full()`을 호출하고, 이 함수는 peak_v를 만충 전략에 전달한다. 따라서 현재 기본 경로를 읽은 것만으로 정상 전류 종단에서 만충 이벤트가 보장된다고 볼 수 없다. 구현 검증은 실제 호출 순서로 정상 종단을 재현하고, 충전 중 확인 창과 충전 세션 완료 근거의 수명을 분리해야 한다. 과거 충전 세션의 만충 근거는 다음 세션에 재사용하지 않는다.

| 입력 변화 | 반드시 확인할 결과 |
|---|---|
| 착좌 유지, 정상 충전 뒤 정상 종단, 최신 팩 표본 정상 | 충전 중 확인은 해제돼도 해당 세션의 충전 완료 근거는 판정 가능. 작업이 있을 때만 출발 검사 |
| 착좌 유지, charging=false, 종단 이유 없음 또는 fault | 완료로 승격하지 않고 사유가 있는 대기/HOLD. 자동 이안 없음 |
| 팩 전압만 높음, 접촉 이탈 또는 팩 표본 만료 | 충전 완료·재투입 불가 |
| 이전 세션 완료 이벤트가 재접안 뒤 도착 | 현재 세션 상태와 출발 허가에 영향 없음 |
| 정상 만충 뒤 작업 없음, 시간이 지나 재충전 시작 | 작업 가능으로 자동 전환하지 않고 같은 예약 아래 대기/재충전 상태를 대조 |

정책상 목표 충전량 도달과 물리 만충은 별도 사실이다. 우선 정상 종단까지 충전하는 프로필을 사용하고, 부분 충전 후 투입은 사용자가 승인한 충전기 제어·배터리 운영 프로필이 있을 때만 연다. 소프트웨어 스케줄은 충전기의 전기적 종단을 대체하지 않는다.

출발 검사는 최신 배터리/도크 상태, 다음 작업과 귀환 에너지 예산, 고장/정지 latch, 로봇·스테이션 소유권, 통신, 후진 공간과 출발 경로를 확인한다. 자동 출발은 이미 승인된 운영 정책과 작업 범위 안에서 수행한다. 충전 접점의 안전한 분리 순서는 장치 프로필에 검증하고, 계측되지 않은 맹목적 후진으로 DEVICE를 통과시키지 않는다.

작업 가능 전환은 이안 완료·접점 이탈·출발 위치/경로 확인 이후에만 한다. 이전 작업 자동 재개는 저장된 재개 지점과 기존 실행기의 재개 계약이 있는 경우에 한한다. 그 외에는 기존 작업을 HOLD로 두고 승인된 새 작업을 선택한다.

## 장애와 재시작

Fleet 재시작은 저장된 충전 세션과 실제 CORE·도크 상태를 먼저 대조한다. 요청을 다시 보내는 것으로 복구하지 않는다. CORE 재시작으로 boot/odom 세대가 바뀌면 이전 접안·정지 증거를 폐기한다. 완료 이벤트가 중복 또는 지연 도착해도 같은 attempt를 한 번만 처리한다.

충전 중 통신이 끊기면 스테이션의 로컬 전기 인터록은 계속 동작하고 로봇은 자동 이안하지 않는다. 충전 확인을 잃으면 기존 로컬 배터리 보호를 재개한다. 접안 접근 중 끊김, 고착 스위치, 접촉했으나 무전류, 충전 종단 불명, 예약 경쟁, 출발 경로 막힘은 서로 다른 사유로 기록한다.

## 검증과 완료 기준

| 단계 | 필수 증거 |
|---|---|
| 계약/순수 로직 | 좌표·단위·시계 검증, 대상/교정/attempt 불일치 거절, 계측 결측과 stale, 비용 예산과 열화 프로필, 히스테리시스, 중복 이벤트와 재시작, 저배터리 로컬 우선권 |
| 통합 | 카메라 producer→검증→CORE 접안, 착좌/정지→충전 확인, 완료→출발 검사→이안→작업 배정의 실제 호출 경로. 출발 불가 조건에서 모터 명령 없음 |
| 원격 시뮬레이션 | 1대/1스테이션에서 작업→예측 복귀→접안→충전 모사→이안→다음 작업을 연속 3회. 각 상태의 관측 유실·통신 끊김·재시작 주입. 합성 SOH/충전은 합성으로 기록 |
| 실기 벤치 | 실측 교정·위치/방향 오차·정지 판정·접점 인터록·팩/도크 계측·정상 충전 종단·출발 공간 검증 |
| 현장 | 실제 작업·적재 조건에서 반복 사이클과 낮은 배터리/열화 조건의 복귀 여유 확인. 충전 시간·대기·접안 성공률·복귀 잔량·재투입 실패 기록 |

스테이션 이동에는 다음 반례를 별도 검증한다.

- 같은 지도의 병진 이동·방향 회전 후 새 버전 수락과 왕복 충전 흐름을 확인한다. 스테이션과 함께 움직인 카메라의 오래된 지도 교정으로는 복귀를 허용하지 않는다.
- 복귀 중·최종 접근 중 위치 변경 시 이전 시도의 정지/종료 확인 전 새 목표가 나가지 않아야 한다. 기존 좌표를 가진 로봇과 재시작한 로봇은 새 버전 수락 전 실행하지 않는다.
- 다른 지도/revision, 잘못된 station ID, 지연·역순·중복 관측과 새 위치를 사칭한 단일 이상값을 거절한다. 관제 단절 중 로컬 명령/관측 만료를 확인한다.
- 고정 카메라 사각지대·스테이션 전원 끊김·기준 마커 미검출·접근 통로 막힘은 위치 미확정 또는 접근 불가로 표시한다. 자동으로 이전 좌표로 되돌리지 않는다.
- 경로가 길어져 귀환 예비량이 부족한 경우 새 작업·재탐색을 막고 지원 요청을 기록한다. 충전 중 스테이션 이동은 자동 출발로 이어지지 않아야 한다.
- 실기는 독립 측정한 새 착좌 위치·방향과 관제 기록·로봇 사용 버전을 비교한다. 위치 교환 ACK나 시뮬레이션 좌표 일치만으로 실기 정밀도 수용을 주장하지 않는다.

시뮬레이션의 초기 접안 비교 기준은 기존 주차 시험의 위치 20 mm/방향 5°로 두며, 실기 요구 공차는 접점·가이드의 허용 오차와 측정 불확실성을 포함해 더 엄격하게 정한다. 이 시뮬레이션 수치는 실기 공차의 승인이 아니다.

실기 활성화 전 장치 프로필에 반드시 기입할 항목은 배터리/충전기 식별과 사양, 설치 센서, 목표 착좌 공차, 관측/정지/착좌 신선도·연속 확인 시간, 접근/후진 한도, 작업·귀환 비용, 예비량과 복귀/재투입 임계다. 빠진 프로필은 실행 시 거절한다. 임의 숫자로 채워 수용하지 않는다.

시험은 저장소 규칙에 따라 원격 pytest와 원격 시뮬레이션으로 수행한다. SOURCE·SIM 성공으로 실기 capability를 켜지 않는다. 전체 목표 완료에는 실제 계측 기반 건강도 운영과 장치·현장 증거가 필요하며, 현장 접근이 없으면 미완료 항목을 유지한다.

## 구현 전 계약 작업

운영 조합은 기존 Fleet app의 명시적 `charge_runtime_factory`로 구성한다. factory에는 실제 TripRunner·지도 원장·작업 서비스·station ingress·로봇 클라이언트 provider를 전달하고, 반환한 runtime이 같은 객체와 충전 원장을 사용하는지 검사한다. 기본값은 비활성이며 원본 시각을 보존하는 배터리·에너지 예산·관측 scope 어댑터를 별도로 설치해야 한다. 서버 시작·종료와 lease 손실은 같은 runtime을 통하며 새 명령 제출을 닫는다.

주기 평가는 기존 순수 에너지 정책을 사용한다. 입력에는 robot/boot/battery, station/map/pose revision, 승인한 예산 source/epoch/cost revision과 원본 유효 시간이 필요하다. 새 작업의 최종 admission은 durable task ID·robot·type·전체 request의 SHA256을 예산의 `work_task_id`·`work_request_digest`와 대조한다. 로봇 단위 주기 판단은 복귀 우선권을 결정하며 특정 작업의 에너지 충족 증거를 대신하지 않는다. 작업 요청이 바뀌거나 예산이 만료되면 수락하지 않는다.

정지용 메모리는 전송 전에 저장한 정확한 session·correlation·operation만 보관하며 재승인이나 재전송에 사용하지 않는다. DB 장애와 coroutine 취소에도 해당 정지를 시도하고 HOLD 저장 실패는 보고한다. 재시작·site stop에서는 기존 트랜잭션 안에서 충전 robot/station claim을 UNKNOWN으로 유지한다. 물리적 정지·이안 확인 전에는 예약 해제나 재가동 가능으로 판정하지 않는다.

충전이 위치 근거의 최초 유효기간을 넘길 때는 새 전역 관측을 같은 버전으로 CORE에 동기화한다. ACK는 현재 시각으로 계속 응답할 수 있으므로 ACK 만료만 기다리지 않고 실제 return/dock owner 조회 때도 원래 target lease를 대조한다. 갱신은 원래 binding이 살아 있는 동안 같은 session/target의 새로운 capture만 허용한다. 위치·접근 포즈·지도·출처·교정 변경은 같은 버전 갱신으로 처리하지 않는다. I/O 이후에도 target과 측정 권한의 원래 수명을 검사하며 feed·native 실행·착좌·충전 완료의 수명을 연장하지 않는다. 전역 관측이 끊겨 이미 만료됐다면 HOLD/reconcile을 유지한다.

이 설계는 사용자 승인과 D-772에 따라 실행 중이다. SRS·API reference·공유 schema·producer/consumer 시험을 같은 변경에서 갱신한다. API v1.254의 이안 허가/실측 Receipt와 시작·갱신·완료 경로는 명시적 로컬 프로필·물리 facts를 요구한다. 미설치 피드는 비어 있으며 실기 활성화는 여전히 실측 프로필·장치 수용을 요구한다. Fleet의 선택 작업·에너지 예산 결속, 실제 Receipt 기반 claim 해제와 작업 재투입, 전체 3회 cycle은 별도 미완료 기준이다.

기존 코드 경계에 맞춰 관측 변환·충전 증거·로컬 접안·Fleet 스케줄·세션 복구를 분리해 구현 계획을 작성한다. 다른 진행 중 브랜치의 power policy/claim 변경은 착지 시 대조하고 중복 소유자를 만들지 않는다.

2026-10-16 구현 보강: 지도 좌표 재발견에는 스테이션과 독립된 고정 지도 카메라를 사용한다. 스테이션에 부착된 별도 카메라는 로봇 마커의 상대 접안만 측정한다. 지도 카메라는 매 영상에서 등록된 네 고정 landmark의 rectified pixel quad를 대조하며 스테이션 표식 전체가 그 coverage 안에 있을 때만 위치 후보를 보낸다. 표식 누락·카메라 이동·불량 숫자/기하는 후보를 만들지 않는다. 바닥 표식을 station-marker 높이의 H로 투영하지 않으며 설치 변경은 재측정·승인·교정 revision 갱신이 필요하다. Fleet이 접근 경로·연속 관측·위치 버전을 검증하고, CORE는 이전 세션의 목표로 이동을 계속하지 않는다. 현재 합성 검증과 미완료 설치/실기 기준은 구현 계획 Task 13에 기록한다.

## 관련 결정과 자료

충전 runtime의 작업 인계는 기존 TaskService의 정확한 완료/native 자원 해제·CORE 수동 인계를 사용한다. 인계 ACK 뒤에도 원본 정책·Task/dispatch·claim을 다시 검사하고, Console의 같은 goal/route/목표 lease projection만 동시 새 명령·보류·대형·클라이언트 변경이 없을 때 정리한다. 새 전송과 정지 세대가 이 정리와 경합하면 projection을 유지한다. IDLE ACK 뒤 정리가 보류됐어도 다음 평가가 절차를 건너뛰지 않으며, 물리 정지·Task DB claim 해제는 기존 owner가 계속 소유한다.

설치 실행은 D-774의 `station-vision` 명령으로 기존 수신기·source-only publisher·상대/지도 worker를 조립한다. source별 렌즈·마커 교정의 source/epoch/revision과 실제 영상 크기·회전을 대조한다. 설치된 측정 source만 실행 수명 동안 기존 demand를 요청하고, 소비 task 종료 시 연결·자격 HTTP client를 닫는다. 일반 preview/추적의 대기 규칙과 CORE/Fleet 권한은 유지하며 전체 현장 lifespan 수용은 별도다.

- [D-350 도크 단계](../adr/D-350-dock-hardware-phase-tiers.md): 자동 충전은 계측 도크를 기준으로 하고 기존 Phase 1 징후와 구분한다.
- [D-369 제어와 정지 증거](../adr/D-369-control-authority-and-stop-evidence.md): ACK·정지 명령·실제 정지는 다른 사실이다.
- [D-763 작업 단계](../adr/D-763-fleet-work-kinds-composed-steps.md): 기존 실행 owner·원장·claim 경계를 유지한다.
- [TI battery fuel gauges](https://www.ti.com/product-category/battery-management-ics/battery-fuel-gauges/overview.html): 용량·부하·온도 등을 고려하는 계측 근거 참고. 특정 부품 선정이나 현재 로봇의 SOH 측정 증거는 아니다.

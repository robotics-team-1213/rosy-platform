# Fleet 평면 지도 편집기 설계안

상태: 2026-10-21 사용자 승인. 구현 계획 작성의 기준이며, 제품 구현·API 변경·현장 적용을 완료했다는 기록이 아니다.

## 목적과 확인된 요구

현장 운영자가 설계 도면을 가져오거나 빈 지도에서 시작해 도로·목적지·구역을 직접 그리고 수정한다. 같은 구성을 템플릿으로 복사하고, 이후 제공되는 지도도 앱 소스나 이미지를 다시 배포하지 않고 등록할 수 있어야 한다.

사용자는 입력 자료로 STL·CAD 설계 파일을, 편집 범위로 평면 지도에서 도로·목적지·구역을 편집하는 방식을 선택했다. 좌표 이동과 군집 주행도 적용된 지도를 기준으로 사용할 수 있어야 한다. 실제 파일 형식·크기는 아직 제공되지 않았다.

첫 지원 입력은 STL로 잡는다. 다른 CAD 형식은 해당 형식의 실제 파일과 변환 정확도를 확인한 뒤 지원 목록에 추가한다. 모든 CAD 확장자를 처음부터 읽는다고 약속하지 않는다.

## 기존 기능과 선택한 접근

| 접근 | 영향과 판단 |
|---|---|
| 기존 지도 편집·초안·프로필에 도면 가져오기와 직접 편집을 연결 | 권장. 운영 지도 저장소와 revision·활성화 검사를 재사용한다. |
| 브라우저에 별도 CAD 편집기를 도입 | 원본 설계 수정까지 범위가 커지고 운영 도로·목적지와 별도 모델이 생긴다. 이번 범위에는 필요하지 않다. |
| 외부 변환 후 지도 JSON만 가져오기 | 기존 JSON 가져오기를 계속 지원할 수 있으나, 운영자가 Fleet 안에서 직접 그리고 수정하려는 요구를 충족하지 못한다. |

현재 `site-map.js`에는 빈 지도, 프로필 복사, `rosy.site_map/1` JSON 가져오기와 초안 저장·활성화가 있다. `site-map-survey.js`와 `shared/site-map-edit.js`에는 요소 추가·수정·삭제가 있다. 이를 확장하며 별도 지도 원장을 만들지 않는다.

기존 STL 변환기 `middleware/perception/map/map_v2_fleet/scripts/stl_scene.py`와 `integrations/simulation/gazebo/scripts/stl_to_world.py`에는 특정 코스의 축·단위·형상 가정이 있다. 기존 측정 지도와 생성 자산은 보존하고, 이 가정을 새 입력에 자동 적용하지 않는다.

## 운영자 흐름

1. **시작:** 빈 지도, 설계 파일 가져오기, 기존 템플릿 복사 중 하나를 선택한다.
2. **도면 맞춤:** 투영 평면, 단위, 축척, 원점과 방향을 확인한다. 알려진 두 점 사이 거리로 크기를 확인하고 미리보기에서 좌우·상하 방향을 확인한다.
3. **직접 편집:** 도로, 목적지, 구역을 추가하고 선택·이동·꼭짓점 수정·삭제한다. 잘못된 조작은 실행 취소·다시 실행으로 되돌린다.
4. **저장:** 초안으로 저장하거나 템플릿으로 복사한다. 저장은 운영 지도 교체와 구분한다.
5. **검증·적용:** 좌표·연결·구역·revision과 현재 작업 상태를 확인하고 명시적으로 활성화한다. 거절되면 이유를 표시하고 기존 운영 지도를 유지한다.

파일 변환 실패는 현재 지도와 편집 중인 초안을 덮어쓰지 않는다. 저장 충돌이 발생하면 다른 사용자의 revision을 덮어쓰지 않고 비교·다시 불러오기를 안내한다. 저장하지 않은 변경이 있으면 페이지 이탈과 도면 교체 전에 확인한다.

## 편집 화면과 도구

공용 ROSY 셸·토큰·타이포그래피·버튼·필드를 사용한다. 왼쪽은 선택·그리기 도구와 레이어, 가운데는 확대·축소·이동 가능한 평면 캔버스, 오른쪽은 선택 항목 속성이다. 작은 화면에서는 도구·속성을 접어 같은 지도와 편집 상태를 유지한다.

| 대상 | 직접 조작 | 속성 |
|---|---|---|
| 도로 | 선분·연속점 추가, 꼭짓점 이동, 끝점 연결, 삭제 | 이름, 연결 목적지, 방향, 기존 계약이 허용하는 주행 방식·속도 제한 |
| 목적지 | 점 추가·이동, 방향 수정, 삭제 | 이름, 기존 장소 종류, 위치·방향 |
| 구역 | 다각형 그리기, 꼭짓점 추가·이동·삭제 | 이름, 기존 시설·금지 영역 계약이 허용하는 종류 |

숫자 좌표 입력을 함께 제공해 마우스 정밀도에 의존하지 않는다. 선택·완료·취소·실행 취소는 키보드로도 조작할 수 있어야 한다. 편집 모드와 이동 요청 모드를 화면에 분명히 표시한다. 편집 클릭·드래그·저장·템플릿 복사는 로봇 명령을 보내지 않는다.

## 데이터와 책임

| 대상 | 책임과 보존 내용 |
|---|---|
| 원본 설계 자료 | 원본 bytes·해시·파일 형식을 보존한다. 운영자가 수정한 도로 정보와 분리한다. |
| 변환된 도면 참조 | 원본 해시, 변환기 버전, 선택 평면·단위·축척·원점·방향을 연결한다. 도면은 편집 배경이며 자동으로 운행 가능한 도로가 되지 않는다. |
| 편집 초안 | 기존 Fleet 지도 모델과 저장소가 도로·장소·시설·금지 영역 및 revision을 소유한다. 실행 취소 이력은 현재 편집 세션의 변경을 되돌린다. 저장 후 재접속하면 저장된 revision에서 시작한다. |
| 템플릿 | 기존 프로필을 재사용한다. 복사본은 독립된 지도 식별자를 갖고 원본 템플릿을 변경하지 않는다. 현장 교정·활성화 증거는 복사하지 않는다. |
| 활성 운영 지도 | Fleet가 명시적으로 검토·활성화한 불변 버전이다. 카메라·로봇·경로 표시가 어떤 지도 버전을 사용하는지 표시한다. |

큰 원본 파일과 변환 결과를 기존 작은 지도 JSON에 넣지 않는다. 파일 보관·가져오기 경계는 Fleet의 현재 인증·권한과 연결하고, 경로 접근·파일 형식·크기·복잡도·변환 시간 제한을 서버에서 검사해야 한다. 임의 로컬 경로나 외부 URL을 그대로 읽는 기능은 제공하지 않는다. 이 경계의 API·저장 형식은 구현 전 ADR·API 계약에서 확정한다. 이 설계안은 새 REST 경로나 필드명을 정의하지 않는다.

변환 후 편집 좌표는 기존 지도 좌표계로 정규화한다. 비유한 값, 범위를 벗어난 좌표, 잘못된 도로 연결과 유효하지 않은 다각형은 기존 모델 검증과 가져오기 검증에서 거절한다. 도면이나 변환이 바뀌면 기존 교정이 계속 유효하다고 간주하지 않는다. 새 도면의 좌표 정합성을 확인하기 전에는 기존 로봇 위치 앵커와 운행 근거를 재사용하지 않는다.

## 이동·군집 주행과 연결

좌표 이동은 **로봇 선택 → 활성 지도에서 좌표·목적지 선택 → 경로·준비 상태 확인 → 명시적 요청 → 진행·결과 표시** 순서다. 편집 초안의 임의 좌표를 곧바로 운행 목표로 보내지 않는다.

군집 주행은 기존 대형 기능을 사용해 **리더·참여 로봇·대형·간격 선택 → 준비 상태 확인 → 활성 지도에서 리더 목적지 선택 → 명시적 요청**으로 연결한다. 편집기 안에 별도 군집 제어기를 만들지 않는다.

Fleet가 명령 접수·권한·충돌을 검증하고 CORE가 장치 안전과 최종 이동·정지를 소유한다. World는 현재 위치 투영을 제공한다. 지도 변경은 D-655의 진행 중 trip·대형·teach 차단과 revision 검사를 유지한다. 기존 비상 정지와 주의 큐는 편집·실행 화면에서도 접근 가능해야 한다.

## 구현 전 계약 정리와 검증 기준

기존 D-655·D-488·D-635의 저장·조사·프로필 경계를 먼저 대조한다. 도면 자산과 좌표 변환 근거에 필요한 확장은 ADR 번호를 도구로 예약하고 API reference·스키마·소비자를 함께 변경한다. 문서만으로 기존 계약이 바뀐 것으로 취급하지 않는다.

완료 여부는 다음 증거로 판단한다.

- 서로 다른 축·단위·원점을 가진 STL fixture에서 같은 실측 기준 거리를 복원한다. 잘못된 파일·형상·변환 설정은 기존 지도 손실 없이 거절한다.
- 실제 Chromium에서 도면 가져오기, 빈 지도, 템플릿 복사 각각으로 도로·목적지·구역을 그리고 꼭짓점 수정·삭제·실행 취소·재실행·저장·재접속한다.
- 원본·템플릿·활성 지도는 초안 편집 중 바뀌지 않는다. 충돌 revision, 권한 부족, 진행 중 작업으로 인한 활성화 거절을 확인한다.
- 편집 과정에서 로봇 명령 요청이 발생하지 않는다. 실행 모드의 명시적 요청만 기존 Fleet admission으로 전달되는지 검증한다.
- 변환 도면을 바꿨을 때 이전 교정 근거를 자동 재사용하지 않는다. 실제 도면·현장 기준점에 대한 정확도와 실물 좌표 이동·군집 주행은 별도 현장 수용으로 남긴다.

첫 구현 계획은 STL 가져오기와 평면 편집·저장·활성화까지로 작성한다. 실제 좌표 이동·군집 운행 수용은 같은 지도 버전과 교정 근거를 사용해 후속 검증한다. 3D 메시 자체 편집, 자동 도로 의미 추출, 모든 CAD 형식 지원, 여러 사용자의 실시간 동시 편집은 첫 범위에 넣지 않는다.

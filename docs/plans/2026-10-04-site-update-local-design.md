# 사이트 자동 업데이트의 로컬 변경 안전성

사용자가 요청한 D-441 후속 개선. D-427 소스 이동과 D-430 구동 권한을 변경하지 않는다.

서명된 이미지만 설치하는 현재 구조를 유지한다. 로컬 변경을 무조건 덮어쓰는 방법은 현장 작업을 잃을 수 있고, 모든 수동 설치를 영구 거부하는 방법은 정상 운영 복구를 막는다. 서명과 실제 실행 상태를 검증한 수동 설치만 기록에 반영하고, 명시적 보류 및 배포 설정 불일치는 자동 전환을 막는 방법을 채택한다.

- 전환 journal 복구는 보류보다 먼저 수행한다. 보류는 다운로드, 새 전환, prune을 막으며 재개는 잠금 안에서 명시적으로 수행한다.
- 실제 현재 커밋과 기록이 다르면 서명·실행 이미지 검증 후 installed를 실제 값으로 맞춘다. 이전 rollback 기록을 추측하지 않는다. 다음 자동 전환의 previous는 실제 검증한 현재 설치다.
- Compose 설정 hash와 실행 컨테이너의 hash, 읽기 전용 루트 및 비특권 상태를 비교한다. 루트 관리자가 Docker label을 위조하는 공격에 대한 방어는 아니다.
- 자동 서명은 정확한 main 커밋의 ci.yml 최신 실행과 ci-result 성공이 필요하다. 미완료·실패·API 오류는 재시도 가능한 보류이며 manifest 영구 거부로 기록하지 않는다.
- 선택적 HTTPS 기능 검사로 Fleet state와 Vision source 목록의 응답 구조 및 현장 지정 ID를 검증한다. 자격 증명은 별도 호스트 파일에서만 읽고 출력하지 않는다. 검사 실패는 전환 롤백을 유발한다. 카메라 실제 프레임과 로봇 실기 인수는 별도 증거로 구분한다.

안전성 시험은 격리된 파일·Docker/systemd/HTTP 포트와 Linux에서 수행한다. 운영 서버에 고의 장애나 구동 명령을 보내지 않는다. 기존 키·enrollment·현장 데이터는 보존한다.

## Concrete supported profile

Existing localization backend only, nonrolling global map frame exactly map, resolved robot base/odom/scan frames, map source topic exactly the resolved approved topic. Full grid <=4,194,304 cells, positive finite resolution/dimensions, original time integers, exact finite planar axis-aligned origin (q.z=0, q.x=q.y=0, q.w=+/-1), raw occupancy [-1,100]. No static timestamp TTL. Canonical ROSY-GRID-v1 digest exactly matches Python including signed zero, float32 resolution promoted to double, signed int8 bytes; header/load time remain separate.

AMCL and static consumers accept ONE immutable original full identity (digest+all metadata+header/load time) per instance. Exact repeats are no-op, not new adoption. Different input, including raw A/B that convert to the same AMCL three-state cells, retires the instance BEFORE native processing. Reloading a changed map requires actual stop and fresh native instances/context; it does not resume old parents. Station movement within the same map remains supported through approved station-pose/transform revision reconciliation. This restriction does not redefine whole-goal success.

For global StaticLayer require enabled=true, rolling=false, use_maximum=false, subscribe_to_updates=false, map_subscribe_transient_local=true, footprint_clearing_enabled=false. No incremental subscription is constructed. Initial conversion params (unknown cost, trinary, threshold, frames/resolution/map topic) must be validated and fingerprinted. Runtime parameter writes are frozen using pre-set callbacks, rejecting the WHOLE mixed transaction before inherited callbacks can partially mutate. Do not replace the effective parameter vector with an acceptable subset. AMCL's base dynamic map_topic handler must never execute after freeze. Internal pose-save parameter writes may fail under this profile; no map admission depends on them.

Footprint topic changes do not change StaticLayer cells when footprint clearing is disabled. They are NOT proof of accepted robot geometry. The map readback claims map-conversion config only, not planner/footprint/measurement correctness. Geometry/calibration and other native safety inputs still require existing separate profile/admission checks before operational factory activation. A native test verifies footprint notification cannot change the retained original static buffer under this profile.

Initial verified AMCL profile is STANDALONE (one AMCL per process). NEW_UNIFORM_SAMPLING uses a static free-space vector shared across AmclNode instances; an ordinary AMCL in the same component process could bypass an instance's map lock. Verified use_composition=True is explicitly rejected until this shared-state hazard is solved. Ordinary existing standalone/composable launches stay available unchanged. This is a discovered SDK constraint, not an assertion that composition works. Whole user's one-mobile goal does not require composition.

## Wire and CORE lifetime (finite sampled evidence, NOT an atomic snapshot)

Reserve actual ADR/API as required before writing new IDL/public contract. Candidate typed read-only service in existing interfaces package: fixed 16-byte challenge; response echoes it and supplies contract/build/config IDs, native role and resolved node, random per-instance16-byte ID, uint64 generation, active/adopted status/reason, full original digest/frame/dimensions/resolution/origin/header/load time. Bound all string sizes at producer AND consumer. Native status carries no motion permission and no new cmd_vel publisher. UUID creation failure closes, never uses a zero ID. Service names are candidate amcl/map_adoption and global_costmap/static_layer/map_adoption resolved by actual node namespace and plugin name; verify genuine graph in tests.

CORE original source object and immutable MapObservation object identity are captured BEFORE issuing two queries. Exact repeats produce a new source object snapshot, so `is` comparison rejects even A->same-A delivery during a query. Capture current fence/parent too; late callbacks can stop/discard only the captured parent. Existing source/lifecycle callbacks already stop that parent.

Proposed initial software timing profile: poll every .25s; each query/set must finish within .25s of its FIRST before-monotonic bracket; successful evidence expires at that first before+.5s, never reply receipt+.5. Each role has a fresh one-use nonce, issued only by bridge ROS clients; fail duplicates/wrong providers/role/namespace/build/config/instance/generation/original source, missing replies, clock fault, source/lifecycle supersession, inactive or mismatch. Native generations/instances cannot regress or ABA into a new execution. No network call or RMW wait on final writer.

Independent responses are NOT a simultaneous snapshot and NOT a native stability lease. Immutable input ensures a still-valid native instance cannot silently adopt B between responses. Cleanup/reset/instance loss can still occur after its response. Therefore admit only finite sampled adoption evidence, with separate lifecycle/readiness checks and supported stale-detection/STOP bound. Never label it "currently active together". Missing/negative/late readback requests STOP of exact captured parent, then expires its cached evidence even if callback processing stops. Final fence checks immutable cached proof deadline/source/context NONBLOCKING on every autonomous selection AND final writer boundary; timeout commits software STOP, never resumes on a new successful poll. No new source lock in 50Hz writer. Install required native-map slot CLOSED uniquely before first cycle; ordinary default factory remains unchanged.

Explicit parent rule: the complete native tuple (both consumer instance IDs, both adoption generations, exact original CORE map object/identity and config/build IDs) is frozen when a parent is admitted. ANY observed tuple change, including a HIGHER generation after native reset->same-map reapplication completed entirely between polls, consumes that exact parent. A new positive readback cannot overwrite its tuple. An evidence GAP/expiry also consumes it; later same-tuple success cannot revive it. Fresh parent requires existing measured-stop handoff and fresh context/energy. Poll success may replace finite sampled time evidence ONLY for the exact frozen tuple, while the previous evidence is STILL unexpired. It cannot renew parent Budget/deadline. Selection retains its own evidence deadline so a newer successful poll cannot extend an old selected writer receipt. Required regressions: actual resetLayers/reset+same-map full reapply between polls; unchanged tuple returned after previous proof expires; new positive poll during a stalled old selected write; no-map-callback native loss. All must refuse/consume old authority without reassigning STOP to a replacement.

The .5s evidence lifetime + <=.02s nominal writer period is only a software profile target, NOT measured physical stop. Accepted runtime scheduling ceiling, downstream/watchdog delay and measured braking tail must be part of the existing Limits/profile and whole-window return/energy budget before DEVICE admission. Physical delay unknown => closed. This explicitly covers AMCL retiring after its reply but before the static reply, or native mutation with NO new CORE map callback: no false simultaneous claim, bounded stale evidence, exact parent eventually STOP independently of service callbacks. Tests must show this finite deadline at final writer, not only a polling manager check.

CORE integration owned paths: existing navigation MapEvidence owner remains raw observation only; native-adoption owner under Drive behaviors/navigation retains readback state; CORE bridge sibling handles ROS conversion/query brackets; CORE drive/execution installs source once, validates required map proof at native admission, Fence applies cached expiry at selection/final boundary. Add resolving safety module/anchor entries for Python. Dedicated native folder under existing navigation package registered as safety ROOT concern (supports C++ without fake Python anchors).

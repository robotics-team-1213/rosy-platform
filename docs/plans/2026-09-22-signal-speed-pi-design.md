# 신호등 속도 평면 설계 — 라즈베리파이에서 가능하게

- **Status:** Draft — **운영자 검토 중(미결정)**. Pi 사용 여부·속도 계층·감속 루프

  확정판으로 갱신한다. 코드 쪽 소스 추상화(cv/file/picamera2)는 결정과 무관하게

  **ADR D-166 (Accepted)** — 자동 감속 상향 조건 포함.

## 1. 목표 — 학교존 개념의 실구현 경로

이 제품의 컨셉(신호등 + 단속 카메라)이 하는 일은 "속도를 늦추는 것"이다. 로봇
사이트에서 그대로 옮기면:

```
로봇 과속 → (측정) → (판정) → 로봇 감속 + 신호등 적색
              Pi        Fleet      로봇·신호등
```

역할은 이미 잡혀 있다(관측 설계 §6): **측정은 Pi, 판정은 Fleet, 표시는 신호등,
달리는 것은 로봇.** 이 문서는 "측정"을 라즈베리파이에서 가능하게 하는 구조를 잡는다.

## 2. 왜 라즈베리파이인가 — 이미 반은 준비돼 있다

관측 서비스(`signal/observer/observer.py`)는 **순수 Python + OpenCV**로, 프레임
소스만 추상화돼 있다:

| 소스 | 어디서 | 상태 |
|---|---|---|
| `{"type": "cv"}` | Windows/관제 PC + USB 웹캠 | **구현·시험 완료** — 벤치 1단계 |
| `{"type": "file"}` | 어디서나 — 기록 프레임 재생 | **구현·시험 완료** — 회귀 세트용 |
| `{"type": "picamera2"}` | **라즈베리파이 + Pi 카메라** | 구현(느린 import 가드) — Pi 에서 실측 필요 |

즉 Pi 배치는 새 코드가 아니라 **같은 서비스의 다른 소스**다. "Windows 벤치에서
통과한 판정 로직이 Pi 현장에서도 똑같이 돈다"가 이 구조의 약속이고, 그 동등성을
AC-24 로 검증한다.

## 3. 배치 구조

```
[Pi + Pi 카메라]  ── GET /observed, /speed (읽기 전용) ──▶ Fleet 콘솔(판정)
  systemd 상시 기동                                            │
  측정만 한다, 명령 경로 없다                                   ▼
                                              신호등 컨트롤러(표시) + 로봇(감속)
```

- Pi 는 **사이트 관측 장비**다 — 신호등 컨트롤러와 같은 신뢰 등급: 측정만 하고
  명령 경로가 없다. Pi 가 뚫려도 얻는 것은 엉뚱한 속도 숫자뿐이고, Fleet 의
  오도메트리 교차 검증이 그 숫자를 걸러낸다.
- 전원·네트워크: 유선 LAN 우선(측정 장비는 무선보다 정합), 무선이면 AC-05 RSSI 기준
  동일 적용. systemd unit 으로 상시 기동(watchdog 포함).

## 4. 하드웨어 옵션

| 구성 | 적합 | 비고 |
|---|---|---|
| Pi Zero 2 W + 카메라 모듈 | 저가·저전력, 640×480 OpenCV 분류는 충분 | 속도 계측(트래킹)까지 하면 여유 낮음 — 측정 주기 5 fps 로 제한 |
| **Pi 4/5 + 카메라 모듈 (권장)** | 관측+속도 동시, 여유 | DIN/인클로저 수납 용이 |
| Pi + USB 웹캠 | 벤치 이관 최소 (cv 소스 그대로) | Pi 카메라보다 저조도 약함 |

## 5. 속도 계층 — 누가 무엇을 말하는가

| 층 | 출처 | 성격 |
|---|---|---|
| 1차 | **로봇 오도메트리** — Fleet 가 이미 모으는 pose 차분 | 상시·무설비. 다만 바퀴 미끄럼에 무방비 |
| 2차 | **Pi 카메라 트래킹** — 알려진 거리의 기준선 2개(또는 ArUco) 통과 시간 | 오도메트리의 독립 검증자. 조명·가림에 민감 |
| 판정 | **Fleet** — 두 출처가 모일 때만 과속 확정 | 한 출처가 말한 속도만으로 로봇을 감속시키지 않는다(독의 2-소스 원칙과 동일) |

- 계측 API 초안: `GET /speed` → `{ "tracks": [{"track_id": "r1", "speed_mps": 0.42,
  "ts": ..., "confidence": 0.88}] }` — 읽기 전용. 구현은 관측 동등성(AC-24) 통과 후.
- 캘리브레이션: 프레임 안에 알려진 거리(기준선 2개)를 두고 px→m 스케일을 고정한다.
  캘리브레이션 값은 설정 파일(커밋 가능 — 비밀 아님), 현장마다 다시 잰다.

## 6. "속도를 늦춘다" 루프 (Fleet 소유)

```
Pi 측정 + 오도메트리 → Fleet 과속 판정(정책) → ① 신호등 적색 표시
                                              → ② 로봇 감속 (공식 경로 없음 — 계약 개정 과제)
```

- ① 은 이미 구현된 scatter 로 충분하다 — `all_red`/적색 표시는 표시 장치의 몫.
- ② 의 로봇 감속 메커니즘 — **API Ref 확인 완료(2026-09-22): 공식 자율 감속 경로는
  없다.** 후보 3개를 계약·코드에서 기각했다:
  1. `PUT /api/v1/safety/limits`(SAF-004, Admin)은 `manual_linear`/`manual_angular`
     만 받는다 — **manual 스코프 상한만** 바꾸고 자율 주행(`scope="nav"` 클리핑,
     `command/manager.py`)에는 영향이 없으며, 값은 오버레이에 **영구 저장**된다
     (일시 감속이 아님).
  2. SRS SAF-004의 "Fleet Velocity Limit"(`fleet_linear`)은 설정
     (`rosy_default.yaml`)에만 있고 **API 필드가 없다**(`LimitsRequest` 미포함).
  3. nav 를 포함한 전 스코프를 낮추는 유일한 API 는 `POST /swarm/follow` 의
     `max_speed`(`session_linear`, `clip()` 이 모든 스코프에 `min()` 적용)인데
     **추종 세션 전용**이고 세션 종료 시 해제된다 — 과속 반응 경로로 쓰면 의미가
     어긋난다.
- 따라서 이 루프의 ② 는 v1 에서 "신호등 적색 + 운영자 개입"까지만 보장하고,
  **자동 감속은 로봇 계약 개정(일시 상한 경로 신설) 과제**가 확정됐다.
  **여기서 임의 REST 경로를 만들지 않는다**(저장소 규칙).
- 그래서 **v1 의 반응은 기록 전용이다(D-166)** — 과속 확정 이벤트는 기록·표시까지,
  로봇 감속은 (1) 계약 경로 확인(**2026-09-22: "없음"으로 확인 — 앞으로의 선행
  조건은 계약 개정**) + (2) AC-25 통과 뒤에 재결정한다.

## 7. 수용 기준 — 2026-09-22 수용 계획 §3 "속도·Pi 관측 (E2 → E3)" 로 승격 완료

아래 표가 원본이다. 수용 계획 쪽이 판정의 기록 위치다 — 여기서 숫자를 바꾸면
거기도 같이 바꾼다(양쪽 불일치는 문서-vs-코드 갈라짐과 같은 종류의 실패다).

| AC | 클레임 | 방법 | 합격 |
|---|---|---|---|
| AC-24 | Pi 관측 동등성 | 같은 장면을 Windows(cv)와 Pi(picamera2)에서 관측 → 판정 일치 | 50회 상태 전환 일치 ≥ 49 |
| AC-25 | 속도 계측 정확도 | 고정 카메라 ROI 2개(d = 1.0 m, 30 fps)로 알려진 속도의 대상(카트/로봇) 3속도 × 5회 | 1.5 m/s 까지 실제 속도 대비 오차 ±10% 이내 |
| AC-26 | Pi 상시성 | 24 h 가동 | 프로세스 재시작 0회(수동 제외), 재시작 후 자기 복귀 |

## 8. 열린 질문

1. Pi 대수·설치 위치(속도 계측은 구간당 1대, 관측은 신호기당 1대 — 합칠지 분리할지)
2. 과속 판정 정책(임계값, 측정 구간 길이, 2-소스 불일치 시 처리)
3. 로봇 감속 메커니즘 — **확인 완료(2026-09-22): 공식 경로 없음 → §6.** 자동 감속은
   로봇 계약 개정 과제로 넘어갔고, 이 질문은 닫혔다(재개 조건: 계약에 일시 상한
   경로가 실제로 생긴 뒤)
4. Pi 전원(USB/POE 헤더)과 인클로저

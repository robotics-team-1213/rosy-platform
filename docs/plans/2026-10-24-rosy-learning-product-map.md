# Rosy Learning 제품 지도: 무엇을 하는 센터인가

**상태:** [D-857](../adr/D-857-rosy-learning-product-definition.md)로 결정됨(2026-10-24). 현재 코드·문서·배포 기록을 조사해 묶은 기준안이며, 결정은 §9와 D-857이다. 이 문서는 코드·배포·권한을 바꾸지 않는다.
**근거:** 앱 화면 조사(`learning/curation/perception/review_app.py`, `review_app_web/`, `*_web.py`), 파이프라인 조사(`learning/`, `deploy/model_pc/`, `deploy/ai_pc/`), 의도 문서(PRODUCT.md, CONCEPTS.md, D-458·D-459·D-461·D-475·D-516·D-527·D-545·D-745·D-755·D-792·D-793·D-840), 배포 기록(`docs/solutions/deployment/learning-center-upgrade-needs-the-identical-unit-first-2026-10-23.md`, D-530 unit 목록).

## 1. 한 줄 정의

**Rosy Learning은 로봇이 겪은 일을 사람이 확인한 정답으로 바꾸고, 그 정답으로 만든 모델 후보가 실제로 나아졌다는 증거를 쌓아 승인권자에게 넘기는 모델 PC의 학습 센터다.**

로봇을 움직이지 않는다. 모델을 배포하지 않는다. "학습이 끝났다", "평가를 통과했다"는 실행 권한이 아니다(D-745, D-793).

## 2. 누가 무엇을 하러 오는가

| 사용자 | 하러 오는 일 | 지금 가능한가 |
| --- | --- | --- |
| 검수자 | 사진·영상·구간에 사람 정답을 단다(객체·픽셀·OMX 구간·VLM 질문) | 객체·픽셀은 됨. OMX 구간은 부분, VLM은 브랜치(D-853 Proposed) |
| 학습 담당 | 승인된 자료로 학습을 돌리고 결과·실패 이유를 본다 | 인식(Pinky 차로)만 화면에서 시작·중지·재시도. 나머지는 CLI |
| 평가·승인 담당 | 후보 모델이 기준선보다 나은지 독립 평가셋으로 보고, 승격 기록을 남긴다 | 화면 없음. 인식 intake 게이트만 자동, 나머지 수동 |
| 관리자 | 계정·권한·외부 자료(HF)·저장 공간을 관리한다 | 협업 모드에서만. 가져온 HF 자료가 검수로 이어지지 않음 |

PRODUCT.md는 사용자를 "학습 검수자" 하나로 적는다. 위 넷으로 넓히는 것이 첫 결정이다(§8 결정 1).

## 3. 하나의 학습 루프

모든 도메인은 같은 일곱 단계를 지난다. Learning은 각 단계의 **상태와 다음 할 일**을 보여주고, 사람의 판단이 필요한 단계(정답, 승격)를 직접 받는다. 무거운 실행은 기존 소유 모듈을 부른다(CONCEPTS.md: "does not hold its own training logic").

```text
① 수집 → ② 정답 → ③ 데이터셋 → ④ 학습 → ⑤ 평가 → ⑥ 승격 기록 → (⑦ 배포·현장: Learning 밖)
   ↑                                                                    │
   └──────────────── 현장 실패·판단 기록이 다음 수집이 된다 ─────────────────┘
```

| 단계 | Learning에서 하는 일 | 사람이 하는가 | 소유 모듈(실행) |
| --- | --- | --- | --- |
| ① 수집 | 들어온 자료 확인, 지문 검증, 등록 | 등록 승인 | `curation/*`(fetch, intake, collection_pipeline), Rosy Cam, OMX 수집 |
| ② 정답 | 객체·픽셀·구간·질문 정답 달기, 평가 정답은 별도 state(D-475) | **예** | `review_store`, `review_masks`, `omx_web`, `vlm_judge` |
| ③ 데이터셋 | 승인된 정답만 봉인해 데이터셋으로 | 시작 버튼 | `review_bridge`, `review_pipeline`, `lerobot_export` |
| ④ 학습 | 실행·중지·재시도, 진행·로그 | 시작 버튼 | `learning_cycle`/`train_job`, `native_cycle`, `m1_job`, Isaac `run_control` |
| ⑤ 평가 | 독립 평가셋 결과, 기준선 대비, 실패 사례 | 결과 확인 | `registry/perception/intake`, `m1_eval`, `vlm_judge` 평가, `decision_replay` |
| ⑥ 승격 기록 | 증거를 묶어 후보로 등록, 승인 요청 | **예**(승인은 Fleet·사람) | `registry/policy`, `registry/perception/store`, Fleet `policy_governance` |
| ⑦ 배포 | Learning 밖. 서명 릴리스·shadow·현장 승인 | 예 | `deliver`, `slot_cli`, AI PC 고정 버전, Fleet |

## 6. 목표 메뉴: 루프의 단계 = 메뉴

메뉴를 §3 단계에 맞춰 다섯 개로 정리한다. 도메인(Pinky 차로·OMX·VLM…)은 메뉴가 아니라 **각 메뉴 안의 필터**다.

| 메뉴 | 들어가는 것(지금 화면) | 첫 화면에서 보이는 것 |
| --- | --- | --- |
| **홈** | 지금 `/learning`의 단계 표시를 도메인별로 확장 | 도메인마다 루프 7칸의 상태와 막힌 칸, 다음 할 일 하나 |
| **자료** | `/catalog`, HF 가져오기(`/accounts`의 가져오기 부분), 카메라 맞춤, OMX 수집 intake | 새로 들어온 자료, 검증 실패, 「검수로 보내기」 |
| **정답** | 객체, 픽셀, OMX 구간, VLM 질문, 평가 정답(D-475 별도 state) | 종류별 남은 수, 내 차례, 승인 대기 |
| **학습** | 인식 학습 실행·중지, OMX `native_cycle`, 월드 모델, SIM 실험 | 실행 중·실패·완료, 어떤 데이터셋 지문으로 돌았는지 |
| **평가·승격** | intake 결과, VLM 평가, decision replay, SIM 판정, 레지스트리 후보 | 후보 vs 기준선, 실패 사례, 「승격 요청」(승인은 Fleet·사람) |

계정·저장 공간은 상단 설정으로 옮긴다. 「작업」과 「학습·결과」의 중복은 홈과 학습으로 나눠 없앤다.

## 7. 필요한 기능 (우선순위)

### P0 — 루프 한 바퀴를 끝까지 (도메인 둘)

`2026-10-19` 평가와 같은 결론: **팔 과제 하나와 주행 코스 하나**를 한 계보로 끝까지 돌린다.

1. **정답이 쌓이게 한다.** Pinky 차로 승인 마스크 0건, VLM 정답 0건이 지금 가장 큰 막힘이다. 검수 인원·분량 계획이 필요하다(결정 4).
2. **OMX 구간 → 데이터셋 자동 연결.** `/learning/omx`에 저장된 구간을 `native_segments`가 DB에서 직접 읽게 한다. JSON 내려받기·CLI 수동 전달을 없앤다.
3. **홈의 단계 표시를 도메인별로.** `learning_pipeline.project()`가 픽셀만 세는 것을 도메인 목록(차로·객체·OMX·VLM)으로 넓힌다. 각 도메인은 「다음 할 일」 하나만 낸다.

### P1 — 끊긴 연결 잇기

4. HF 가져오기 → 정답 대기열 등록(협업 모드에서도).
5. 카메라 맞춤 결과 → OMX 수집 intake가 직접 읽기.
6. SIM 결과 → 학습·평가 화면에 연결.
7. 「승인 자료 준비」를 데이터셋 단계 하나로 합치기(객체·픽셀·홈 세 곳 → 한 곳).
8. VLM 정답 → 질문별 보정·기준값(T5)과 결정 비교(T6)를 평가 화면에서.

### P2 — 평가·승격을 화면으로

9. 후보 vs 기준선 비교 화면(독립 평가셋, 실패 사례 보기).
10. 승격 요청: 증거 묶음 → registry 후보 → Fleet 승인 요청. 승인·배포는 Learning 밖(D-793).
11. 레지스트리 통합 보기: perception store, policy registry, reasoning registry를 한 목록으로(읽기 전용).

### P3 — 운영 정리

12. **센터를 하나로.** 아래 §8 결정 2.
13. AI PC Learning(D-840, Fleet `/console/learning/ai` 503) 설치.

## 9. 결정 (D-857, 2026-10-24)

1. **사용자와 범위:** 네 역할로 넓힌다. 범위는 수집 → 승격 기록까지의 루프다.
2. **센터 하나:** 8768. 8774·8769는 자료를 옮긴 뒤 퇴역, 8786은 미리보기, 8773·8775·8770은 소유자 확인.
3. **VLM 판단:** 별도 평가 state(8790), 임시 정답 허용. 들어가는 문은 센터의 「평가·승격」.
4. **정답:** 사람이 달거나, 모델 합의·토론으로 임시 정답을 만든다. 승격 평가는 확정(사람) 정답만. 사람 확인은 사진 종류당 평가셋 30장, 의견 갈림·점검 보기당 50장 상한, 점검 주 10건.
5. **메뉴:** 홈 / 자료 / 정답 / 학습 / 평가·승격, 도메인은 필터.
6. **Proposed ADR:** 대체 0건. D-449·D-792·D-834·D-853에 개정 메모. D-475·D-514·D-793은 전제로 유지.

# 독립·상하위 관제 후속 목표

**기준:** [D-850](../adr/D-850-composable-control-units.md). 구조 목표는 Accepted이며 이 문서는 후속 설계·검증의 순서를 정한다. 완료 표시는 산출물과 검증 근거가 있을 때만 한다. 아래 최초 계획과 현재 구현·수용 현황을 구분한다.

**목표:** 관제 단위가 독립 운영하고, 하위 관제를 포함하며, 상위에는 하나의 서브 관제로 참여할 수 있게 한다. PC 배치는 논리 책임과 별도로 정한다.

**상세화:** [최종 목표와 상세 설계](2026-10-23-composable-control-design.md)에 G1–G5의 기본안과 P0–P5 실행·수용 기준을 기록했다. [D-851](../adr/D-851-control-unit-delegation-and-recovery.md)은 세부 계약의 Proposed 설계다. 독립 검토를 마쳤으며, 설계 기록·병합과 세부 결정 승인·기능 수용은 구분한다. 아래 체크박스는 승인·구현·수용 근거 없이 닫지 않는다.

## 2026-10-25 소프트웨어 구현 현황과 남은 수용

### 새 구현 목표: 관제 정보를 실제로 모으는 통합관제

사용자의 추가 구현 지시에 따라 기존 유한 navigation 위임을 넘어 [D-862](../adr/D-862-integrated-control-information-and-stop-requests.md)를 적용한다. 문서 등록·기존 회귀 통과와 새 기능 완료를 구분하고 아래 항목을 실제 source/증거로 닫는다.

- [x] **I1 공유 계약:** D-862/API v1.313을 등록하고 strict/bounded 회귀·독립 검토 후 commit `7a3d0dc892`로 로컬 main에 반영했다. FULL27호출의 G1 timing LOAD-FLAKY 격리 통과와 원래 실패는 구분한다.
- [x] **I2 정보 수집:** SharedGather·직접 소유 SQL·활성 지도와 R/A/B/A1 수집·신선도·부분 단절·권한/개인정보 거절을 구현했다. source `aaaf7ed3f2`의 실제 backend HTTP·SQLite·TLS 집중 회귀는 NEW0이다. 최종 병합은 I6에서 확인한다.
- [ ] **I3 통합 화면:** 관제별 연결/상태/작업, 소유 관제·map ID/version을 표시하는 지도, 단위별 정지 요청/결과/복구 정보를 실제 API와 연결한다. 근거 없는 좌표 융합이나 물리 정지 완료 표시를 하지 않는다.
- [x] **I4 정지 요청:** immutable identity/fence·같은 transaction latch·활성 send/미확인 rearm guard·기명 로컬 재시운전 처분과 중복/DB/재시작 경합을 구현·회귀했다. backend source `aaaf7ed3f2`와 CORE 연계 source `10fc372212`는 각각 NEW0이며 소스 독립 검토를 받았다. 기존 로컬 긴급 정지는 보존하고 물리 정지는 UNVERIFIED다.
- [ ] **I5 TLS·배치:** 명시 peer CA와 opt-in 설정/token/CA mount를 연결하고 실제 TCP/TLS·배치 계약을 검증한다. 부모 정보 공유와 정지 수신 권한은 각각 기본false로 명시 허용한다.
- [ ] **I6 소프트웨어 수용:** 실제 생산자→수집→화면 및 정지 요청→기존 owner→관제별 결과의 source SHA 원격 회귀·Chromium·독립 계약/안전 검토를 남기고 커밋·로컬 main 병합한다. 실물·현장 수용은 아래 N1–N3과 분리한다.

선행 구조 정리는 schema1170→569줄의 기존 모델 소유 분리이며 FULL23호출·통합892 PASS/6 SKIP·NEW0으로 로컬 main에 반영했다. 이 작업을 I1–I6 전체 구현 완료로 세지 않는다.

runtime source는 `feat/integrated-control-runtime`에서 최종 수용 중이다. 실제 sample/browser가 viewer 읽기 잠금과 정지 응답/overview 세대 차이를 찾아 수정했고, source `bbffbf8577`의 UI·실제 sample Chromium 재검증은 NEW0이다. 실제 Fleet backend와의 무가로채기 browser smoke, HTTP 증거 등록·배치 계약·공식 최종 착지 게이트가 남아 있다. 실제 PC 배포·장치 수용은 N1–N3으로 유지한다.

**최종 목표:** 각 관제가 자기 자원·원장·운영자와 실행 책임을 가지고 독립 운영하며, 동일한 관제가 하위 관제를 포함하거나 상위 통합관제에 참여할 수 있게 한다. 각 PC의 배치와 네트워크 연결은 이 논리 책임에 맞추고, 상위의 요청 접수가 하위 승인이나 장치 실행 권한으로 바뀌지 않게 한다.

| 범위 | 현재 상태·근거 | 남은 수용 |
|---|---|---|
| G1 관제 구성·경계 | D-850와 [D-855](../adr/D-855-control-unit-wire-and-scoped-cancel.md)의 첫 유한 navigation 범위 구현. 독립·부모/자식·3수준, 직접 자원 소유·순환 거절 | 실제 현장·자원 배정 확정 |
| G2–G4 위임·권한·복구 | D-855 범위의 영속 identity, 대상 관제 기명 승인, 원래 실행의 조건부 취소, 단절·재시작 회귀 완료 | D-851 전체는 Proposed 유지. 다른 작업 종류·실물 정지·현장 복구 수용은 별도 |
| G5 구현·PC 배치 | 기존 Fleet/CORE/UI 경로 연결 완료. [관제 역할·네트워크 구성](../deployment/control-units.md)에 논리 역할과 호스트·인접 통신 경계를 명시 | 실제 PC별 주소·인증서·방화벽·기동 설정 확정 및 연결 확인 |
| G6 소프트웨어 종단 | 구현 commit `d154853fc894711dffd080f610e7ad41e09af189`, [동결된 공식 검증·병합 기록](../validation/control-unit-pipeline-2026-10-24b/result.md). UI·샘플·HTTP 증거는 연결된 선행 기록 참조 | 실제 PC 간 LAN/TLS, 설치·배포, 장치 운행과 현장 수용 미확인 |

이번 후속 작업은 역할표·네트워크 호출 방향·방향별 자격·기동 및 확인 절차를 실제 코드와 다시 대조하고 누락을 보완한다. 이 문서 갱신·검증·커밋·로컬 main 병합까지가 작업 종료 기준이다. 실제 연결 확인 없이 아래 현장 목표를 완료 표시하지 않는다.

- [ ] **N1 실제 배치 확정:** PC별 unit ID·직접 자원·부모/자식·독립 DB·기명 운영자와 승인된 private 설정 소유자를 정한다. 통합관제에 로봇 직접 소유가 있으면 동일한 로컬 승인·CORE 경로를 사용한다.
- [ ] **N2 PC 간 연결 수용:** 각 직계 연결 양방향의 DNS·TLS 신뢰·방화벽·방향별 service 인증과 범위 거절을 실제 PC에서 확인하고 증거를 남긴다. 기본 site Compose 기동만으로 중첩 관제가 활성화되었다고 판단하지 않는다.
- [ ] **N3 장애·복구 현장 수용:** 승인 전 조상 단절, 이미 승인된 작업, 재연결·재시작, 원래 작업 취소와 실제 장치 정지 증거를 분리해 확인한다. 래치 해제·재무장·자동 재배정은 연결 복구로 실행하지 않는다.

N1–N3의 실행은 실제 설치·장치 작업 승인과 현장 조건이 있을 때 진행한다. 이번 소프트웨어·문서 작업으로 현장 수용을 대신하지 않는다.

## 최초 진행 순서와 완료 기준 (2026-10-23 설계 기준선)

다음 체크박스는 당시 전체 설계·현장 수용의 기준선이다. 현재 완료 범위는 위 현황표가 우선하며 D-855 첫 구현으로 전체 항목을 일괄 완료 처리하지 않는다.

- [ ] **G1 — 첫 적용 범위와 관제 경계 결정.** 현장 내 공정·셀 또는 다중 현장 중 첫 범위를 정한다. 관제 식별·등록·관할 자원·부모 관계·순환 방지·지원 깊이를 설계하고 구성 예시를 남긴다. 완료 기준은 독립 A, 상위 아래 A·B, 자체 하위를 가진 A의 상위 참여를 모순 없이 설명하고 잘못된 포함 관계의 거절 기준을 정한 것이다.
- [ ] **G2 — 상태 정본과 업무 위임 계약 결정.** G1을 입력으로 상위 업무와 하위 작업의 대응, 각 상태의 쓰기 소유자·조회 출처·완료 증거를 정한다. 접수와 실행 완료를 구별하고 거절·취소·재시도·중복 요청·상위 교체 시 경합을 명시한다. 완료 기준은 정상·중복·응답 유실·취소 경합의 순서별 상태 전이와 소유자를 설명할 수 있는 것이다.
- [ ] **G3 — 권한과 정지 경계 결정.** G1·G2의 범위별 인증·위임 권한·사람 확인과 정지 요청의 전파·응답·실패 처리를 정한다. 완료 기준은 서브 등록이 구동 권한을 만들지 않고 상위 요청이 CORE·OMX owner의 검증을 우회하지 않으며, 무권한·범위 밖 요청·권한 회수 중 요청의 처분이 정해진 것이다. 안전·계약 경로는 해당 저장소의 독립 검토를 거친다.
- [ ] **G4 — 단절·재연결 정책 결정.** G2·G3를 입력으로 상위 단절 중 기존 작업·신규 요청의 허용 범위, 장치 연결 단절, 재연결 후 상태 대조·충돌 처리·늦은 응답 처분을 정한다. 완료 기준은 중복 실행 없이 상태를 맞추는 근거가 있고 링크 복구가 래치 정지 해제나 자동 권한 승격을 뜻하지 않는 것이다. 기존 단절 정책을 변경하려면 소유 계약을 별도로 개정한다.
- [ ] **G5 — 최소 구현 범위와 PC 배치 결정.** G1–G4 승인 후 현재 서비스·API·원장을 재사용할 부분과 필요한 최소 변경을 실제 호출 경로로 조사한다. 관제 서비스와 화면, 현장 조정, 모델·추론, 장치 실행을 호스트별로 배치하고 자원·네트워크 조건을 적는다. 완료 기준은 소유 파일·생산자·소비자·공개 계약·회귀 시험이 지정된 구현 계획이다. 역할마다 별도 PC나 새 서비스를 강제하지 않는다.
- [ ] **G6 — 구현과 단계별 수용.** G5의 구현 계획에 따라 변경한다. 독립·상하위 업무 흐름과 무권한·중복·거절·취소·단절·재연결을 검증한다. 중첩 구성은 G1에서 승인한 깊이까지 확인한다. 완료 기준은 커밋 SHA에 묶인 원격 회귀와 종단 증거이며 실물·현장 수용은 별도로 기록한다. 소프트웨어 시험만으로 장치 수용을 완료 표시하지 않는다.

## 소유 기준과 변경 위치

설계 시 아래 정본과 실제 호출 경로를 먼저 확인한다. 폴더 위치만으로 실행 권한이나 배치를 추정하지 않는다.

| 대상 | 현재 확인할 위치 | 후속 산출물 |
|---|---|---|
| 용어·구조 목표 | `CONCEPTS.md`, D-850 | 용어가 확정되면 용어집을 갱신하고 구조 결정은 ADR에 기록 |
| 작업·원장·조정 | `operations/fleet/`, `operations/site_execution/`, D-435 | G2의 상태·위임 설계, 소유 경로별 구현 계획 |
| 관측·상태 출처 | `operations/world/`, D-435 | 실행 결과와 관측을 구분한 출처·정합성 설계 |
| 관제 화면·접점 | `applications/fleet/`, 공개 API reference | 상하위 범위·상태를 표시하는 소비자 설계 |
| 장치·안전 | `middleware/core/`, OMX owner의 현행 계약, D-430 | 권한·정지·단절 검토와 소유자별 수용 근거 |
| 호스트 배치 | `deploy/`, D-434·D-516 | 실제 설치 구성과 자원·통신 조건 |

미결 계약을 API 필드나 실행 모드로 먼저 구현하지 않는다. accepted ADR의 기록은 보존하고 결정이 바뀌면 저장소 ADR 절차를 따른다. 구현 단계에서는 소유 경로의 AGENTS와 SRS·API reference를 읽고 영향을 받는 호출자·시험·설정·설치 경로를 함께 다룬다.

## 검증과 보고

문서 단계는 harness 생성·lint와 저장소의 문서 계약 시험으로 확인한다. 구현 단계의 시험 선택은 변경된 경로와 공식 affected selector에 따른다. pytest는 커밋된 SHA를 공식 원격 runner로 실행하고 모든 결과를 known failures와 비교한다. 안전·권한 검토, 실제 UI 종단, 장치 동작, 현장 수용은 각각 증거를 남긴다.

G1–G4는 설계 산출물의 승인, G5는 실행 가능한 구현 계획, G6은 기능·장치 수용의 증거로 닫는다. 이 목표 목록을 기록·병합한 사실만으로 어느 항목도 완료 처리하지 않는다.

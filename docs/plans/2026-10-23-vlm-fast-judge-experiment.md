# VLM 빠른 판단 실험 계획

**설계:** [2026-10-23-vlm-fast-judge-design.md](2026-10-23-vlm-fast-judge-design.md)
**위치:** 모델 PC, 오프라인 재생만. 노트북·AI PC 운영 경로·로봇은 쓰지 않는다. `operations/situation`의 운영 코드는 이 계획에서 바꾸지 않는다.
**시작 전:** [시험 저장소 운영 규칙](../../../rosy-ops/docs/lab-host-storage.md)대로 `df -h ~/rosy-test`를 확인한다.

## 목표

같은 케이스·같은 모델(Qwen3-VL-8B)에서 현행 방식과 「전처리 + 닫힌 질문 + 확률 읽기」를 비교한다. 결과는 방향 판단용이며 D-610 켜는 관문이나 승격 증거가 아니다.

## 과제

| # | 할 일 | 끝난 기준 |
| --- | --- | --- |
| T0 | 재생 세트 목록: D-607 막힘 39건(`X:\DevTemp\steer-review\deadlock\`), 9dfk·8kcn 횡단보도, 2026-10-09–10 현장 기록에서 천장·전면 두 장과 상황이 모두 있는 케이스를 고른다 | 케이스 JSONL과 빠진 케이스·사유 목록 |
| T1 | 사람 정답: 케이스마다 설계의 질문 6개 사실 + 사람이 고른 결정 | 정답 JSONL, 판정 애매 케이스 표시 |
| T2 | 기준선: 현행 `Vlm.judge` 경로를 같은 케이스로 재생 | 결정·`inference_s`·실패 사유 기록 |
| T3 | 전처리: 신선도·화질·crop·고정 크기·사실 카드. 해상도 2–3개를 비교한다 | 전처리 결과와 거절 사유 분포 |
| T4 | 질문 점수: transformers로 사진 prefix 1회 + 질문 suffix마다 선택지 토큰 확률. prefix 재사용 유무를 둘 다 잰다 | 질문별 확률, 단계별 지연 |
| T5 | 보정·기준: 교차 검증(케이스가 적으므로 leave-one-out)으로 질문별 temperature와 기준값 | 질문별 보정 전·후 오차, 기권율 |
| T6 | 결정 표 적용 후 사람 결정과 비교 | 결정 일치율, 위험 답 수, 기권율 |
| T7 | Qwen3.5-4B·9B로 T4–T6 반복. GPU 메모리가 맞으면 JEV-27B-VL 기준선 | 모델별 같은 표 |
| A0 | 로봇암 재생 세트: 사람 `outcome`이 있는 OMX 실물 녹화에서 top·wrist 두 장이 있는 집기 전·VERIFY_HOLD·VERIFY_RELEASE 시점 프레임을 뽑는다 | 케이스 JSONL, 판단 지점별 개수 |
| A1 | 로봇암 사람 정답: 설계의 로봇암 질문 6개 사실 | 정답 JSONL |
| A2 | T3–T7 하네스를 로봇암 질문으로 반복(top ROI는 고정 설정) | 질문별 확률·지연·보정 |
| A3 | 센서 판정과 결합한 성공 규칙 적용 후 사람 `outcome`과 비교 | 거짓 성공 수, 놓친 성공 수, 기권율 |
| T8 | 결과 기록: `docs/validation/vlm-fast-judge-<날짜>/result.md`, 원본 로그 해시 | 기록과 다음 결정 제안 |

## 판정

| 항목 | 기준 | 출처 |
| --- | --- | --- |
| 위험한 움직이는 답 | 0건 | D-610 |
| 사람 결정과 일치 | ≥ 0.7, 그리고 기준선 이상 | D-610 |
| 질문별 균형 정확도 | 묶음별로 보고. 기준선 대비 하락 묶음은 따로 표시 | 이 계획 |
| 지연 p95(모델 PC GPU, 판단 1건 전체) | ≤ 1 s 목표. 현행 켜기 기준은 ≤ 6 s | 이 계획 / D-492 |
| 기권율 | 보고만 한다. 기권은 analyzer 제안 유지 | 이 계획 |
| 로봇암 거짓 성공 | 0건(센서 + 이미지 결합 규칙 기준) | 이 계획 |
| 로봇암 놓친 성공 | 보고만 한다. 놓친 성공은 HOLD라 안전하지만 작업이 멈춘다 | 이 계획 |

39건 규모에서는 지연·방향만 믿는다. 질문별 정확도 차이가 몇 건 차이면 결론 내지 않고 사진 보관 결정(설계 「열린 결정」 1)으로 넘긴다.

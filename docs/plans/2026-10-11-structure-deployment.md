# 구조 정리 배포 실행 계획

사용자 요청: D-637 구조 이동과 설명 정리를 실제 배포와 설치 버전 확인까지 완료한다.

## 범위와 완료 조건

- 공유 main에 착지한 구조 변경의 정확한 SHA를 발행한다. 해당 SHA의 전체 CI와 서명 후보 빌드가 통과해야 한다.
- 현재 배포 인벤토리의 Pinky 두 대는 기존 네이티브 전체 payload 경로를 사용한다. 파일 이동 때문에 delta 배포는 사용하지 않는다. 설정·교정·장치 신원·지도·모델 슬롯은 보존한다.
- Site Fleet, Console, Vision, proxy는 기존 서명 후보와 자동 업데이트 경로를 사용한다. 컨테이너 이미지 SHA, 서비스 상태, 인증된 장치 목록과 API를 적용 전후 비교한다.
- 모델 PC의 실제 학습·리뷰 소비자와 AI PC의 상황 서비스는 설치된 실행 경로를 조사한다. 변경이 닿는 실행 소스만 기존 서명 코드·버전별 리뷰 배포 절차로 갱신한다. 학습 데이터와 검수 DB, 모델 가중치는 교체하지 않는다.
- 장치마다 설치 manifest/source revision과 실제 프로세스 실행 경로, 준비 상태를 직접 읽는다. 건강 상태만으로 버전 적용을 판정하지 않는다.
- 기존 보류·작업·교정·안전 게이트를 우회하지 않는다. 주행 명령과 E-stop 해제, 신규 모델 활성화, 실주행 수용은 이 배포의 완료 조건에 포함하지 않는다.

## 실행 순서

1. 예약된 자동 배포 작업, 현재 릴리스, 보류, 실제 소비자, 도달 가능 여부를 읽는다. 사설 주소·토큰·로그는 X: 세션에만 둔다.
2. 필요한 배포 소비자 수정이 있으면 자체 worktree에서 수정·커밋하고 원격 관련 시험과 known-failures 비교, lint 후 main에 착지한다.
3. 생성 문서 및 pre-push 게이트를 통과한 main SHA를 push한다. 동일 SHA의 CI 및 site/native 후보 빌드를 추적한다. 기존 RobotCD의 원자적 번호 예약과 롤아웃을 중복 실행하지 않는다.
4. CI 통과 후 서명과 ABI 확인을 완료한다. 기존 등록 canary 적용과 실제 실행 버전·준비 상태 확인 뒤 나머지 장치에 적용한다. Site와 모델 코드도 각자의 서명·유휴·기능 확인 게이트를 따른다.
5. 컨테이너/프로세스의 실제 SHA, API readback, 보존된 인벤토리·데이터 계보, 되돌림 경로와 미확인 항목을 배포 결과에 기록한다.

## 실패와 되돌림

각 설치기의 기존 자동 되돌림을 유지한다. 도달 불가, 서명·ABI·CI 실패, 작업 중 보류는 미배포로 기록하고 원인을 해소한 뒤 같은 검증 경로로 재시도한다. 서명 릴리스 ID를 재사용하지 않는다. 동료의 배포 보류를 해제하거나 공유 checkout의 변경을 정리하지 않는다.

## 진행

- 계획 수립 완료. 배포 전 인벤토리와 설치 경로 확인 중.
- 초기 확인: Site와 모델/AI PC는 SSH로 도달한다. 로봇 두 대는 현재 등록된 Site 경유 LAN 주소에서 도달하지 않는다. 이전 자동 로봇 롤아웃은 철회 상태다. 실제 주소와 원인을 추가 확인한다.
- 소스/문서 검증과 로컬 main 착지는 완료된 이전 단계다. 원격 CI, 서명 릴리스 적용, 장치 버전 확인은 별도 증거로 기록한다.

# Rosy Cam 사진 저장·저조도 촬영 검토안

상태: 사용자 승인 후 송출 사진 저장·공유와 시간 제한 자동 조명을 구현했다. 아래 최초 검토 내용은 후속 고해상도 촬영·보정의 경계를 포함한다. 자동 조명은 이번 사용자 요청에 따라 기본 활성화하며, 자동 렌즈 변경은 하지 않는다. 전체 장치·현장 판정은 별도다.

## 이번 구현 범위 (2026-10-04)

- 현재 송출 JPEG의 소유한 복사본을 앱 내부에 저장한다. 최대 2 MiB, 인코딩 후 3초 이내 프레임만 허용하고 저장 시 화면 회전을 적용한다. 메타데이터의 `encoded_monotonic_ms`는 센서 촬영 시각이 아니라 JPEG 인코딩 후 단조 시각이다. 최근 사진 20장과 대응 JSON을 유지하며, 공유는 사용자가 누르는 Android 공유 창과 photos 전용 FileProvider 권한으로 한다.
- 실제 바인딩된 렌즈의 `hasFlashUnit()`과 실제 `TorchState`를 사용한다. Y 평면 평균 밝기 28 이하가 2초 이어지면 조명을 켠다. 자체 조명으로 밝아진 프레임 때문에 깜박이지 않도록 점등을 유지하되 최대 30초 후 독립 타이머로 끄고 10초 쉬며, 이후 새 저조도 관측이 필요하다. 온도 43°C 이상 또는 Android thermal status 3 이상이면 차단한다.
- 송출 종료·렌즈 재연결·오류 때 조명을 끈다. 끄기 요청 실패나 3초 동안 실제 꺼짐이 확인되지 않으면 카메라 바인딩과 송출 세션을 종료한다. 화면 자동 절전 중에도 서비스가 밝기·조명 제어를 계속한다.
- `dumpsys activity service`의 읽기 전용 진단은 송출·조명·사진 상태의 boolean만 내보낸다. 주소·자격정보·파일명·사진은 출력하지 않고 다른 앱이 호출하는 촬영/조명 receiver나 임의 wire 필드를 추가하지 않는다.
- 기본 후면 렌즈 선택은 조명을 지원하는 렌즈를 사용하려는 운용자 조작이다. 초광각 미지원 표시를 유지하며, 렌즈를 바꾸면 시야와 기존 설치 보정을 다시 확인해야 한다.
- 별도 ImageCapture 고해상도 사진, Night/Low Light Boost, 노출 보정, Fleet 촬영 명령 API와 물리적 방향 회전은 후속 범위다. 현재 사진은 송출 해상도의 snapshot이며, 단순 저조도 감지는 렌즈 가림과 어둠을 구별하지 않는다. 조명으로 개선되지 않는 장면은 렌즈와 조명 배치를 확인한다.

## 사용자 요구와 확인한 상태

- 영상 송출 중 원하는 시점의 사진을 저장하고 공유한다. 어두울 때도 촬영할 수 있도록 필요에 따라 플래시나 조명을 사용한다. 화면 자동 절전과 관제 PC 원격 깨우기는 유지한다.
- 2026-10-04 S21의 실제 수신 JPEG 1280×720을 가져왔다. 서로 다른 두 프레임의 seq가 증가했고 age는 227–366 ms였다. 사진은 거의 검다. 통신 성공과 장면을 식별할 수 있는 사진은 별도로 판정한다. 어두운 장면인지 렌즈가 가려졌는지는 사진만으로 확정하지 않는다.
- 현재 앱은 CameraX Preview + ImageAnalysis를 서비스 수명주기에 연결해 JPEG를 송출한다. ImageCapture와 torch 제어는 없다. CameraX 버전은 1.4.0이다.
- 실제 camera service 조회에서 송출 카메라 id 2의 flash.info.available은 FALSE, 기본 후면 id 0은 TRUE였다. 기기 모델만 보고 모든 렌즈에서 플래시가 된다고 가정하면 안 된다. 이 조회는 조명 점등이나 촬영 성공의 증거가 아니다.
- "돌려서"는 플래시 사용과 실제 방향 변경 중 의미를 확인하는 중이다. 방향 변경은 별도 요구로 두며, 회전 거치대·모터를 확인하지 않은 휴대폰을 소프트웨어만으로 물리적으로 돌릴 수 있다고 약속하지 않는다.

## 권장 단계

1. **현재 화면 사진 저장:** 인증된 Vision의 현재 JPEG를 저장한다. 촬영 시각·seq·frame age·해상도·렌즈를 함께 남긴다. 오래된 프레임이나 미수신은 저장 성공으로 표시하지 않는다. 이 단계는 송출 해상도의 사진이며 고해상도 정지 사진으로 표시하지 않는다.
2. **별도 사진 촬영:** CameraX ImageCapture로 JPEG를 저장하고 촬영 완료·실패를 표시한다. 플래시는 꺼짐/자동/켜짐을 선택한다. 실제 바인딩 렌즈의 hasFlashUnit()으로 지원 여부를 판단한다. 플래시 없는 초광각에서는 미지원으로 표시하고 기본 후면으로 바꿔 찍는 선택을 안내한다. 자동으로 렌즈를 바꾸거나 기존 카메라 설치 보정값을 재사용하지 않는다.
3. **송출 저조도 대응:** 프레임 밝기와 촬영 상태를 확인해 저조도 안내를 내고 지원되는 보정 옵션을 제시한다. 연속 영상의 LED 조명(torch)은 정지 사진 플래시와 따로 제어한다. 기본은 꺼짐이며 사용자가 켠 시간 제한 조명 또는 명시적으로 선택한 자동 정책만 허용한다. 활성 상태·자동 꺼짐을 표시한다.

ImageCapture가 Preview + ImageAnalysis와 동시 바인딩되는지 실제 렌즈별로 검사한다. 실패하면 기존 송출 조합으로 복구하고 사진 촬영 미지원으로 표시한다. 사진 촬영을 위해 다른 카메라 앱을 실행하거나 스트림을 몰래 중단하지 않는다.

## 저조도 정책과 실패 처리

- 자동 노출/노출 보정, 지원되는 Low Light Boost를 먼저 검토한다. 현재 CameraX 버전과 실제 렌즈 지원을 확인한 뒤 사용할 API를 결정한다. Android 버전만으로 S21 지원을 주장하지 않는다. Night 확장은 별도 정지 사진 모드이며 연속 송출과 동시에 된다고 가정하지 않는다.
- 밝기 검출에는 단일 프레임 대신 지속 시간과 히스테리시스를 사용한다. 역광·포화·렌즈 가림 가능성을 안내하고, 영상이 검다는 이유만으로 무조건 LED를 켜지 않는다. 임계값은 정상·저조도·가림 실기 사진으로 정한다.
- torch와 boost의 동시 사용 가능 여부를 확인한다. 보정이나 LED를 켠 후 개선 여부를 측정하고, 개선되지 않으면 반복 점등 대신 부족한 조명/가림 안내를 낸다.
- 조명은 시간 상한·재점등 간격을 두고 기존 발열 상태를 반영한다. 세션 중지·렌즈 교체·오류·온도 제한 시 끄고 실제 꺼짐을 확인한다. 재시작은 꺼짐으로 시작한다.
- 휴대폰 조명이 닿지 않는 먼 영역은 조명 배치 개선이 필요할 수 있다. 방향을 바꾸면 고정 카메라의 설치 보정과 관측 영역을 다시 확인한다. 로봇 주행으로 카메라를 돌리는 동작은 포함하지 않는다.

## 관제 PC 조작과 공유

- 관제 PC에 현재 사진 저장과 별도 촬영 요청, 조명 상태 확인/시간 제한 점등을 제공한다. 기존 화면 깨우기 명령과 구분한다. 명령 전달만으로 촬영·점등 성공을 표시하지 않고 장치 완료 응답과 실제 이미지 수신을 확인한다.
- 영상 저장은 기존 인증된 Vision/Fleet 경로를 이용한다. 진단용 서버 비밀키로 임의 토큰을 발급하는 방식을 제품 기능으로 만들지 않는다. Rosy Cam의 기존 wire config에 조명 필드를 임의 추가하지 않는다. 원격 명령이 필요하면 권한·요청 식별자·만료·완료 응답을 정의하고 API/프로토콜 계약을 함께 반영한다.
- 정상 페어링한 PC의 ADB로 조작하는 경우 실제 serial/model 확인을 유지하고 다른 앱이 임의 호출할 수 있는 공개 촬영·조명 진입점을 만들지 않는다.
- 원본 JPEG와 시각·렌즈·조명 사용 여부를 공유한다. 밝게 보정한 사본은 원본과 구분하고, 원본을 덮어쓰지 않는다. 사진·실제 주소·토큰·장치별 상세 증거는 공개 저장소에 커밋하지 않는다. 보존 기간과 저장 공간 초과 처리를 구현 때 정한다.

## 실기 수용 조건

화면 절전 상태에서 사진 저장, 중복 촬영 요청, 미수신/오래된 프레임, 기본 후면/초광각의 지원 차이, 저조도/정상 조명/역광/가림, LED 시간 제한·중지·발열·렌즈 교체 시 꺼짐을 검사한다. 사진 촬영 전후 실제 JPEG의 seq 증가와 freshness로 송출 유지·복구를 확인한다. 장치 지원 조회나 JVM 시험만으로 저조도 촬영 성공을 주장하지 않는다.

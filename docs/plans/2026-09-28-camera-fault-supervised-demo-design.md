# 전면 카메라 고장 시 관제 지원 시연 설계

- 날짜: 2026-09-28
- 상태: [D-313](../adr/D-313-supervised-camera-fault-demo.md) 구조 결정의 설계 근거. 코드 활성화, 장치 설치, 바닥 주행 승인이 아니다.
- 관련 계약: CORE SRS SAF-001/SAF-002/NAV-001/NAV-007, Fleet SRS HITL, D-2, D-143, D-257, D-268, D-295

## 목표와 결정

전면 카메라가 없거나 운전 중 고장 나도, **관제 PC가 현장 전체를 천장 카메라 영상으로 보면서**, 시연 작업의 종류와 살아 있는 센서에 따라 정지·작업 보류·제한된 복구를 지시할 수 있게 한다. 첫 고장 반응은 항상 현재 명령을 0으로 만들고 기존 목표를 취소하거나 보류하는 것이다. 이후 새 작업은 그 작업에 필요한 센서와 장치 수용 기록을 다시 확인한 뒤에만 시작한다. 예전 카메라 프레임이나 기존 목표를 자동 재개하지 않는다.

최종 `cmd_vel`과 로컬 정지 책임은 CORE에 남긴다. Fleet은 상태를 모으고 작업 의도를 전달한다. 천장 카메라의 **원본 영상은 관제 PC에서 실시간으로 보여주고**, 같은 프레임에서 산출한 sighting은 위치 표시·대조에 사용한다. sighting은 로봇 위치 추정이나 충돌 회피 입력으로 승격하지 않는다(D-257). Fleet의 명령·상태 API가 영상 바이트 또는 ROS `cmd_vel`을 중계하지 않는다.

## 관제 PC의 전체 시야

현장 카메라(초기에는 천장에 고정한 폰)가 현장 PC의 `overhead`/Vision 수신기로 JPEG를 보낸다. **영상 보기 경로**는 Vision 서비스의 최신 프레임을 인증된 관제 브라우저에 제공한다. Fleet 콘솔은 별도 HTTPS 미디어 경로를 화면에 배치하되 Fleet 서버 프로세스에 영상 바이트를 통과시키지 않는다. **좌표 경로**는 같은 수신 프레임을 ArUco/보정 처리해 Fleet `sightings`에 좌표·시각·품질만 보낸다. 이로써 관제사는 영상 전체와 지도 위 자기 pose/외부 pose를 함께 본다. 현재 저장소는 폰→Vision→sighting 경로와 Fleet 지도/작업 화면을 가지고 있지만, 인증된 **Vision→관제 브라우저 라이브 영상 경로와 통합 화면은 아직 구현되지 않았다.** 이 설계는 D-257의 'Fleet은 영상을 다루지 않는다'는 경계 안에서 관제 PC 영상 요구를 추가하는 제안이며, API/권한/대역 계약은 구현 전에 별도로 확정한다.

영상 화면에는 카메라 이름, 현재 프레임 캡처 시각과 지연, 보이는 구역, 로봇 ID/위치, 가려진 구역을 명시한다. 마지막 프레임을 살아 있는 영상처럼 고정 표시하지 않는다. 프레임이 오래되거나 카메라·네트워크가 끊기면 영상에 `STALE`/`OFFLINE`을 덮고 해당 구역의 관제 지원 이동을 보류한다. 카메라 하나로 현장을 모두 볼 수 없으면 구역별 카메라를 추가하고 각 카메라의 시야·좌표 보정·시간 동기를 확인한다. 화면상 전체 시야는 관제사가 작업을 지시할 근거이며, 로봇 가까운 장애물·바닥 낙하의 최종 판단은 계속 로컬 센서가 맡는다.

## 센서가 실제로 맡는 일

| 입력 | 허용하는 판단 | 대신할 수 없는 것 |
| --- | --- | --- |
| 바닥 3채널 IR 반사율 | 보정된 흑·백 값으로 흰 선 추종(`IR_LINE`); 별도 보정에 따른 낙하 감지 | 일반 공간의 장애물 거리, 지도상 위치, 영상 표지 인식 |
| LiDAR + 근접/초음파 | 측정 범위 안의 장애물·여유 거리와 로컬 정지 | 바닥 낙하, 카메라만 읽는 표지나 정지선 |
| 오도메트리 + IMU + 지도/TF | 로봇 위치 추정과 경로 진행 증거 | 근접 장애물의 독립 감지 |
| 천장 카메라 영상 + 관제 PC | 현장 전체 또는 명시된 카메라 시야의 실시간 관찰, 로봇의 외부 위치·방향 대조, 작업자 개입 판단 | 카메라에 가려진 영역과 Pinky의 신선한 로컬 충돌·낙하 감지 또는 물리 정지 확인 |

IR 선 추종은 **현장에 흰 선이 있고**, 각 로봇의 IR 검정/흰색 끝점이 측정돼 `ir_calibration_enabled`가 참인 경우에만 선택한다. 선이 없는 바닥에서 IR만으로 목적지까지 이동하는 기능은 만들지 않는다. 카메라 차선·시각 표지·정지선·집기·카메라 도킹에 의존하는 임무는 카메라 장애 동안 보류한다.

## 상태와 작업 선택

상태는 `NORMAL`, `CAMERA_HOLD`, `DEGRADED_READY`, `DEGRADED_RUNNING`, `RECOVERY_HOLD`로 표현한다. 단일 원인 코드와 캡처 시각을 상태·감사 기록에 남긴다.

| 조건 | 판정과 관제 동작 |
| --- | --- |
| 카메라 preview만 고장, 실제 관측은 fresh | 영상 표시 장애로 알린다. 운전 정책의 카메라 의존 여부를 별도로 확인한다. |
| 운전에 쓰는 카메라 관측이 stale/invalid/없음 | `CAMERA_HOLD`: 기존 차선 명령·목표를 폐기하고 0 명령 및 로봇 속도 readback을 요청한다. 정지 확인 전 새 작업을 받지 않는다. |
| LiDAR·낙하 IR·오도메트리·TF·지도/위치 추정과 정지 경로가 fresh, 해당 실기 수용도 완료 | `DEGRADED_READY`: 관제사가 카메라 비의존 Nav2 목표를 짧은 구간 단위로 요청할 수 있다. CORE가 다시 적격성을 판정한다. |
| 보정된 IR 선, LiDAR·낙하 감지·정지 경로가 fresh, IR 선 추종 실기 수용도 완료 | `DEGRADED_READY`: 관제사가 `IR_LINE`을 선택할 수 있다. 선택 직후 대기하고 **새 IR 관측**이 들어와야 출발한다. |
| Navigation이 없지만 Teleop과 정지 경로가 별도로 수용됨 | 현장 입회 아래 짧고 저속인 수동 복구만 허용한다. 네트워크/조작 입력 상실 시 기존 500 ms watchdog으로 정지한다. 천장 관측은 작업자 확인용이다. |
| 위 조건 중 하나라도 실패·불명확하거나 외부 관측과 로봇 pose가 크게 다름 | `RECOVERY_HOLD`: 원격 이동을 거부하고 현장 회수 또는 센서 수리로 전환한다. |

관제 PC의 `goal`, `IR_LINE`, `teleop` 요청은 서로 다른 작업으로 다룬다. 로봇별 한 작업만 소유하고, 모드 변경 전에 기존 명령과 관측 generation을 폐기한다. E-stop과 로컬 안전 판단은 모든 관제 명령보다 우선한다. Fleet의 `QUEUED`/CORE의 `ACCEPTED`는 로봇 이동·완료·물리 정지의 증거가 아니다.

## 실패와 복귀 규칙

1. 카메라 끊김을 확인한 즉시 0 명령과 작업 중지 결과를 요구한다. 0 명령 전송만 성공하거나 속도 readback이 없으면 상태를 `RECOVERY_HOLD`로 둔다.
2. 대체 센서의 관측 시각, 출처, 보정 revision, 필수 토픽 및 map ID를 확인한다. stale 값, 마커 누락, 카메라/로봇 위치 불일치, IR 선 상실, LiDAR·낙하 센서·TF 실패 시 다시 정지한다.
3. 관제사는 카메라 없는 시연 작업을 **새로** 선택한다. 이전 카메라 기반 작업은 자동 변환하거나 재개하지 않는다. 바닥 IR과 `IR_LINE`은 현재 코드의 배타적 소스 선택·fresh 관측·loss latch를 재사용한다.
4. 카메라가 돌아와도 자동으로 기존 모드/임무로 되돌리지 않는다. 장치 진단과 작업자 재선택 후 fresh 관측으로 시작한다.

## 현재 구현 상태와 실행 순서

- 이미 있음: CORE `IR_LINE`/`CAMERA_LINE` 배타 선택, 소실·stale 시 0 명령, 3 s loss latch, Teleop watchdog, Fleet goal/정지 요청, Fleet sighting 수신 API.
- 아직 없음: Fleet sighting을 쓰는 완성된 관제 대조 화면, 카메라 고장 상태와 대체 작업 적격성을 한곳에서 결정하는 브로커, 해당 결정의 CORE readback 결합, 실기에서 수용된 IR 선 추종/무카메라 Nav2 경로.
- 현재 기본 설정은 `ir_calibration_enabled: false`이며, 최근 네이티브 Pinky 기록은 `motor` 모드·Navigation 꺼짐·G4/G5 HOLD다. 설정값을 임의로 켜거나 승인 기록을 만들지 않는다.

### 구현 단계

1. CORE에서 카메라 **장치 고장**, preview 고장, 카메라 기반 작업의 관측 상실을 구분해 표시한다. 카메라 의존 작업 중 관측 상실은 기존 명령을 취소하고 HOLD/0 속도 및 정지 결과를 기록한다. 고장 주입·복귀·오래된 프레임 시험을 먼저 만든다.
2. Vision 서비스의 최신 프레임을 별도 인증·속도 제한이 있는 관제 영상 경로로 노출하고 Fleet 화면에 표시한다. 영상과 sighting의 `source_id`·캡처 시각을 묶어 같은 장면인지 보여준다. 가려진 구역·끊긴 영상은 현장 전체가 보인다고 표시하지 않는다. Fleet 서버의 영상 중계 금지 계약은 유지한다.
3. ROS import 없는 적격성 판정기를 둔다. 입력은 작업 종류, 장치 capability/readiness, 필수 센서 신선도·보정·위치·맵, E-stop/정지 readback, 관제 카메라의 신선도·시야, 외부 sighting 상태다. 출력은 허용 가능한 작업과 구체적인 차단 이유다. 관제 UI는 이 출력만 표시하고 직접 우회하지 않는다.
4. Fleet은 작업자에게 `정지 유지`, `IR 선 시연`, `짧은 Nav2 목표`, `입회 수동 회수` 중 적격한 작업만 요청하도록 한다. 요청/수락/실행/완료/정지 readback을 별도로 표시한다. 천장 sighting과 로봇 pose의 불일치는 경고와 작업 보류에만 쓴다.
5. 합성 고장 주입 → ROS-SIM 단일 최종 publisher·watchdog·센서 stale → ARM64 설치/readback → 바퀴를 든 G4 → 제한된 바닥 시연 순서로 승격한다. 영상 지연·시야 누락·IR 끝점·낙하/장애물 정지·네트워크 단절·실제 제동 거리·독립 정지를 실기에서 측정한다.

시연 경로는 우선 **흰 선이 있는 짧은 구간의 `IR_LINE`**을 택한다. Nav2 목표 시연은 G4/G5와 localization/지도 수용 뒤에만 추가한다. 흰 선과 지도 모두 준비되지 않았다면 관제 화면 관찰과 정지 시연까지가 현재 가능한 범위다. 파일별 구현·시험·롤백은 [실행 계획](2026-09-28-camera-fault-supervised-demo.md)에 기록한다.

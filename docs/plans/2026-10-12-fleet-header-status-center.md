# Fleet 상태 센터와 단일 테마

기준은 PRODUCT의 Operate 모드, D-641의 의미 아이콘·단계별 상세, D-668의 역할 분리다. 첫 헤더는 기술 검사를 통과했지만 사용자 검토에서 의미의 혼재로 거절됐다. `impeccable` layout/operate와 `frontend-design`을 적용해 묶음의 이유를 먼저 정한다.

```text
넓음  [제품·현장]          [연결 수 · 알림 수 · 개발]    [테마]    [비상 정지]
좁음  [제품·현장]                                             [비상 정지]
      [연결 수 · 알림 수 · 개발]                               [테마]
```

| 영역 | 이유 | 표시·행동 |
| --- | --- | --- |
| 제품·현장 | 지금 관리하는 곳의 식별 | 브랜드와 현장명. 기존 홈 목적지 유지 |
| 상태 센터 | 관제를 쓸 수 있는 현재 조건을 한곳에서 확인 | 연결고리+비율, 종+미확인 수, 활성 개발 경고를 한 48px 조작 안에 표시. 열기는 읽음이 아님 |
| 테마 | 개인 표시 선호이며 관제 상태와 독립 | 달·해·모니터 하나. 한 클릭 순환, 현재와 다음 선호를 툴팁으로 설명 |
| 비상 정지 | 즉시 위험 조작이며 다른 기능과 독립 | 기존 팔각형·동사·위험색·48px·권한 규칙 유지 |

내부 값에 배지 테두리나 새 클릭 영역을 추가하지 않는다. 짧은 필수 값·위험·개발 경고는 남기고 반복 행동 명칭은 공용 아이콘·툴팁으로 제공한다. 계정·권한·개발 조건·메시지 이동은 기존 펼침 영역에 둔다. 그룹 사이 간격은 내부 간격보다 넓다.

1. 공용 inline 태그와 styleguide 견본, 네 문서 동일 헤더, 요약 컨트롤러를 함께 갱신한다.
2. 기존 호출자·픽스처를 맞추고 권한 예외·읽음·접속 실패를 보존한다.
3. 원격 Chromium으로 네 문서와 넓음/좁음·두 테마·접속 상태를 한 회차에 측정하고 캡처를 직접 평가한다. 의미·구조 평가와 기계 검사를 구별한다. 필요한 수정은 묶어서 하고 한 번의 확인 회차로 마감한다.
4. 공식 원격 착지 검사·NEW 비교·푸시·CI·서명 설치·실제 화면 readback을 수행한다. 실제 장치 동작과 UX 사용자 수용은 별도다.

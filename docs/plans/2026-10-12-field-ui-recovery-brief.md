# 현장 운용·오류 복구 중심 UI 목표와 평가

사용자는 전체 활성 UI의 본문·작업 흐름 개선, main 착지·push·배포 검증을 요청했고, 추가 스킬 평가의 우선순위를 **현장 운용·오류 복구**로 선택했다. 이 문서는 기존 PRODUCT.md·DESIGN.md·D-153·D-641의 방향을 구체화한다.

## 우리가 만들고 싶은 경험

현장 사용자는 문제가 생겼을 때 **어느 대상인가 → 무엇을 확인했나 → 왜 막혔나 → 지금 무엇을 할 수 있나 → 처리 결과가 실제로 반영됐나**를 순서대로 이해하고 작업을 끝낸다. 모르는 상태는 미확인으로 남기고 요청 접수와 실제 완료를 구분한다.

| 역할 | 끝내야 하는 일 | 화면이 제공할 판단 근거 |
|---|---|---|
| Fleet 운영자 | 현재 개입 대상을 고르고 원인에 맞게 대응한 뒤 상태를 다시 확인 | 현장/대상, 현재 사건 단계, 통신 신선도, 가능한 조작과 거절 이유, CORE 결과 |
| Robot/Pilot 운용자 | 정확한 로봇에 접속하고 운전 가능 여부를 확인하며 실패에서 복구 | 대상 정체성, 접속/권한, 신선한 상태, 비상 정지, 재시도 또는 정비로 가는 길 |
| 설치·정비 담당자 | 실패한 설치 단계와 필요한 선행 조건을 확인하고 같은 단계에서 재검증 | 단계, 장치와 자료 출처, 실패 이유, 기존 입력, 재확인 결과 |
| Cell 운영자 | 문서를 준비해 결과를 검토하고 허용되는 작업만 제안 | 저장/초안 구분, 서비스 구성 여부, 계획과 작업 ID, 승인/장치 동작/목표 확인 구분 |
| 학습 검수자 | 현재 자료와 초안을 검토하고 명시적으로 저장·승인 | 원본/초안/승인, 검수 상태, 변경 결과, 복구 가능한 입력 |
| Cam·LCD·경기 사용자 | 해당 매체의 송출·판독·경기 작업을 수행 | 매체별 정체성, 현재 상태와 근거, 기존 조작과 요청/결과 |

헤더는 정체성·연결/권한·전역 보조 조작·안전을 맡는다. 본문은 현재 작업과 주된 예외, 맥락 영역은 원인과 결과, 상세 공개는 진단을 맡는다. 모든 화면에 같은 목록과 조작을 반복하지 않는다. 기존 의미 아이콘 탐색과 접근성 이름은 D-641의 사용자 결정에 따라 유지한다.

## 수용 기준

- 선언된 좁은 화면에서도 현재 대상·주된 예외·다음 행동과 비상 정지 접근이 유지된다.
- 연결 실패와 인증 거절, 오래된 값과 현재 값, 요청과 완료를 혼동하지 않는다.
- 복구는 기존 입력을 보존하고 현재 상태를 먼저 조회한다. 응답을 잃은 쓰기 명령을 자동으로 재전송하지 않는다.
- 오류 문구가 내부 HTTP 코드만 보여 주지 않고 확인할 대상과 다음 행동을 설명한다.
- G1 원격 회귀, G2 선언 상태/화면 폭, CI, 서명 릴리스와 설치 SHA, 실제 설치 화면, G3 사람 작업 검토를 별도로 기록한다. 확인하지 않은 실물 매체는 GO로 표시하지 않는다.

## 스킬 평가

`impeccable`의 context·audit·clarify와 `frontend-ui-engineering`의 접근성·오류 상태·공용 부품 원칙을 사용했다. 설계 목표는 인터뷰 답변과 기존 제품 계약에서 정했으며 새로운 미적 방향이나 장식 효과를 도입하지 않았다. 아래 점수는 Fleet의 소스와 이번 화면 캡처에 한정한 기술 평가이며 제품 전체 또는 실물 수용 점수가 아니다.

| 평가 축 | 0–4 점수 | 근거와 한계 |
|---|---|---|
| 접근성 | 3 | 이름·키보드 설명·공용 focus·정지 규격 회귀가 있다. 실물 보조 기술 전체 검증은 미확인이다. |
| 성능 | 2 | 기존 정적 모듈과 부품을 재사용하며 의존성을 추가하지 않는다. 설치본 성능 trace·장기 폴링 부하는 이번 평가에서 측정하지 않았다. |
| 반응형 | 3 | 네 Fleet 문서와 작은 Robot/Pilot/Learning 캡처·넘침 회귀를 확인했다. 실물 터치·확대 판독은 미확인이다. |
| 테마 | 4 | 닫힌 토큰과 기존 화면별 테마 계약을 유지하고 관련 원격 계약 검사가 통과했다. |
| 구현 일관성 | 3 | 역할별 업무 영역과 공용 머리/조작을 재사용한다. 이번 추가 발견은 공용 오류 메시지의 복구 안내 부족이다. |
| 합계 | **15/20** | 기계·소스 근거에서 양호하며 실제 장치/사용자 작업 검증이 남는다. |

### 결정적 검사와 실제 판단

`impeccable detect --json operations/ui/console`은 12건을 출력했다: side-tab 5, broken-image 3, flat-type-hierarchy 2, em-dash-overuse 2. 실제 화면 경로의 `/common`·`/console/assets`를 소스 디렉터리 아래로 해석해 stylesheet를 읽지 못했으므로 색/서체 판정은 불완전하다. 동적 영상의 초기 hidden 이미지와 이후 src 할당, D-641의 의도된 탐색, 기존 원격 글자 규격과 본문 문맥을 확인했다. 이 출력만으로 계약된 UI를 교체하지 않았다. 원시 출력은 공용 임시 증거 세션 `evidence/impeccable-console.json`에 보존한다.

### 추가 개선

**P1: 관제 응답 실패에 복구 행동이 없다.** `shared/web/fleet-client.js`가 일반 서버 실패를 `HTTP 503`, 네트워크 실패를 `Failed to fetch`로 그대로 넘겨 Cell 등에서 사용자가 다음 행동을 판단하기 어려웠다. 공용 요청 어댑터에서 서버/연결 확인 불가와 현재 상태 재조회 안내를 제공하도록 고쳤다. 네 문서와 개발 접속·비밀번호 접속 호출자는 기존 어댑터를 그대로 사용한다. 서버의 세부 메시지·코드·status, 예외 객체, 취소와 인증 처리, 쓰기 비재전송을 보존한다.

추가 Node 회귀는 변경 전 3 FAIL을 재현했고, 변경 후 요청 계약과 함께 33 PASS를 확인했다. Cell 저장 실패 브라우저 회귀는 실제 표시가 내부 코드 대신 재조회 안내를 제공하는지 검사한다. 통합 회귀·착지·push·CI·배포 결과는 검증 기록에 뒤이어 연결한다.

# 차선 모델 실패에서 주행 재검증까지의 개선 파이프라인

2026-10-09. 적용 범위: [첫 링 맵 폐루프 비교](../validation/lane-model-closed-loop-2026-10-09/result.md)의 다음 반복. 이 문서는 실행 순서이며 모델·보정 후보의 조향 승격을 승인하지 않는다. 주행 목표와 권한은 [D-567](../adr/D-567-fleet-plan-parallel-lane-correction.md), 원본·라벨 출처와 세션 분리는 [D-379](../adr/D-379-learning-data-pipeline-auto-labels-local-store.md), 평가 정답은 [D-475](../adr/D-475-human-reviewed-fixed-eval-truth.md)를 따른다.

## 이번 결과가 가리키는 개선 단위

- PIDNet·U-Net·v13-drivable은 서쪽 직선에서 멈춰 링 호 표본이 없다. U-Net의 `none` 연속 163프레임은 카메라 시각 42.0–62.25초, v13의 192프레임은 41.25–65.125초다. 시작 시점의 Gazebo 참값은 각각 약 `(-1.242,-0.456)`, `(-1.250,-0.452)` m이다. 두 실행은 비슷한 *위치*에서 경계가 사라진 후보 사건이다. 실행별 시뮬레이션 시각이 다르므로 시각끼리 대조하지 않는다. PIDNet에는 짧은 소실과 재검출이 반복된다. 원본 영상·마스크를 아직 대조하지 않았으므로 테이프 소실, 벽·spoke 오인, 잘못된 좌우 선택 중 원인은 미확정이다.
- `strategy=none` 총수는 실패율이 아니다. 모드가 꺼진 시작 구간, 정상 코너 전환, 정지 뒤 프레임도 포함한다. 집계는 **주행 명령이 유효한 동일 경로 구간**으로 자르고, `paint_source_used=learned`와 모델 리비전 일치 여부를 분리한다. v11의 완주에는 fallback 62프레임이 섞였다.
- `arrived`인 threshold·v11도 보수적 원형 대리 여유가 각각 −21.4 mm, −41.3 mm까지 내려갔다. 완주율만 최적화하면 경계 위험을 가린다. v13의 drivable 클래스는 이번 폐루프 조향에 쓰이지 않았으므로 그 결과로 drivable 주행 성능을 평가하지 않는다.

## 한 번의 개선 반복

| 1. 사건 묶음 | `rec/keep.jsonl`의 `strategy`, 좌우 경계, `paint_source_used`, 모델 리비전을 `log.jsonl`의 `sim_t`, GT·odom, CORE 명령·정지 사유와 맞춘다. 같은 시각의 `frames.npz` 원본과 추론 마스크를 붙인다. 첫 지속 소실의 앞뒤, 재출현, fallback 전환, 재선택·정지 순간을 모두 포함한다. | 실행·모델·지도·카메라 보정·원본 해시와 프레임 시각이 결속된 검토 후보. 시간 정합이 불명확하면 원인 분석에서 제외하고 `unknown`으로 남긴다. |
| 2. 원인 검수 | 사람은 원본에서 동일 물리 경계의 ID, 실제 가림/영상 밖/도색 소실/벽·spoke 오인/좌우 전환을 판정한다. 모델 마스크와 지도·LiDAR 투영은 **후보**로만 보여 준다. 실패 위치가 같다는 이유로 모델 문제라고 단정하지 않는다. | 프레임별 근거와 검수 revision. 승인된 경계가 없는 구간은 `unknown`; 보이지 않는 선을 정답 도색 화소로 채우지 않는다. D-475의 평가 세션은 학습 입력보다 먼저 예약한다. |
| 3. 분기 | 물리 선이 보이는데 마스크가 끊기면 인식 오류, 마스크는 맞는데 `keep_debug`가 사라지면 투영·선 선택 오류, 경계가 실제로 없으면 시간·지도·odom의 유효 범위와 정지 판단을 검토한다. CORE `obstacle_ahead`는 LiDAR/IR 근거도 함께 본다. | 사건마다 하나의 주원인과 반증 가능한 재현 조건. 서로 다른 원인을 한 학습 배치에 섞지 않는다. |

D-475 가져오기 연습의 207장은 모두 `pending`이고 승인 정답이 0건이므로 현재 사람 정답 기반 점수는 `HOLD`다. |

### 두 개의 판정 루프를 분리한다

1. **동일 영상 진단:** 다섯 폐루프 실행은 경로가 갈라진 뒤 서로 다른 프레임을 보았다. 따라서 각 원본 프레임을 모든 모델에 다시 통과시키고 같은 카메라 보정·전처리·시각에서 마스크와 `keep_debug`를 비교한다. SIM의 독립 경계 정답을 주입한 진단 실행에서도 멈추면 모델 학습보다 선 선택·지도·CORE 이유를 먼저 조사한다. 이 정답 주입은 원인 구별용이며 제품 입력이나 승인된 사람 평가 정답이 아니다.
2. **차체 경계 판정:** 기존 `audit_track_footprint.py`는 벽 충돌 형상과 표본 자세 사이의 간격을 계산하며 `continuous_collision_proof=false`를 명시한다. D-422 장애물 sweep도 도색된 차로 안쪽 유지의 정답은 아니다. 기존 threshold·v11 로그부터 독립 GT 자세의 **회전된 차체 다각형 전체**를 지도에서 승인된 좌·우 주행 경계와 대조한다. 표본 사이의 최대 이동, 자세·지도·경계 오차 상한, 정지 명령 후 추가 이동을 더해 연속 구간의 최소 여유를 계산한다. 도색 중심선과 실제 넘지 말아야 할 경계, 허용 도색 점유 폭을 같은 값으로 취급하지 않는다. 경계 위치나 오차 상한이 없으면 `unknown`이고 안전 통과가 아니다.

이 두 루프를 먼저 돌리면 모델이 보이는 선을 놓치는 문제와, 모델이 맞아도 경로·차체가 차로를 벗어나는 문제를 따로 고칠 수 있다. 특히 threshold·v11의 완주를 차체 경계 검사 전에 성공 학습 사례로 사용하지 않는다.

## 우선 실행 순서

1. 먼저 기존 threshold·v11의 GT와 충돌 형상으로 차로 경계 여유를 재계산한다. 동시에 첫 영상 검토 묶음은 U-Net·v13의 비슷한 서쪽 소실 위치와 PIDNet의 반복 소실로 한정한다. 카메라 원본은 모델 PC에 남아 있고, 로그 묶음은 첫 결과 문서에 있다. 원본·마스크·CORE 이유를 한 타임라인으로 내보내 사람이 `visible / occluded / absent / wrong-object / unknown`을 판정할 수 있게 한다.
2. 그 검수로 **인식 vs 선 선택 vs 실제 부재**를 나눈다. 승인 결과가 없는 동안은 새 모델 학습이나 보정 조향의 승격 기준을 만들지 않는다. 검수자를 아직 확보하지 못하면 후보와 `unknown`만 기록하고 기존 안전 정지를 유지한다.
3. 한 가지 수정으로 동일 실패 구간을 다시 실행하고, 반복 폐루프에서 완주와 차체 경계를 **동시에** 검증한다. 이 단계가 통과한 뒤에만 AI PC 실시간 폐루프 지연, Pi 배포 예산, 로봇별 장치 검증을 진행한다. 모델 PC CPU 폐루프 결과를 AI PC 실시간 성능으로 대체하지 않는다.

현재 상태: 1단계의 로그·위치 후보만 확인, 원본 영상·마스크의 사람 판정과 실제 차체 sweep은 미완료. 따라서 학습 가설과 주행 후보 모두 HOLD다.

## 1. 왜 v1 계약이 이 제품과 맞지 않는가

v1 은 "릴레이 접점이 색별 램프 회로를 직접 닫는다"는 가정 위에 서 있다 — 그래서
`POST /command {mode, lamps}` 로 상태를 **직접 지정**할 수 있었다. 실물은 다르다:

1. **버튼은 펄스다.** 접점이 할 수 있는 것은 "누른다"뿐. `lamps: {green: true}` 를
   지시할 방법이 없고, 버튼 한 번이 모드를 다음 칸으로 넘길 뿐이다.
2. **램프 상태는 개방 루프다.** 장치는 자기가 누른 횟수는 알지만, 제품의 전원이
   사람 손으로 켜지거나 건전지가 교체되면 현재 모드를 모른다. v1 의 `lamps` 는
   "보고"가 아니라 **추정**이 된다.
3. **페일세이프 강제가 흔들린다.** v1 의 핵심("신뢰할 수 없으면 적색 점멸")은
   상태를 직접 쓸 수 있을 때만 성립한다. 모드 사이클 제품에서 점멸 패턴이 사이클에
   없으면 적색 점멸 자체를 만들 수 없다.

이 세 가지를 숨기지 않고 계약에 쓰는 것이 v2 의 요지다.

## 2. v2 명령 모델 — 펄스 프리미티브

```json
{ "seq": 21, "mode": "pulse", "presses": 2, "hold_ms": 120, "gap_ms": 350 }
```

- `presses` — 접점을 몇 번 닫을지. `hold_ms` 누름 길이, `gap_ms` 사이 간격
  (B0 가 제품별 값 확정: 숏클릭/롱프레스 구분, 최소 간격).
- 장치는 `presses_since_boot` 카운트와 `assumed_mode`(사이클 지도 B0 기준 추정)를
  `/status` 에 보고한다. 필드명이 v1 의 `mode`·`lamps` 에서
  `assumed_mode`·`sensed_lamps`(옵션) 로 바뀐다 — **"추정"과 "측정"을 필드 이름부터
  구별한다.**
- 사이클 지도(예: 꺼짐→적→황→녹→꺼짐)는 B0 가 확정하고 NVS 에 두지 않는다 — 펌웨어
  상수로, 계약 문서에 기록한다(제품 교체 시 계약 개정).

### 2.1 색 이름과 의미 — 색을 필드 이름으로 박지 않는다 (2026-09-22)

렌즈가 초록인지 청록인지는 렌더링과 실물에서 다르게 보일 수 있다(토이 LED는 전압에
따라서도 색이 달라 보인다 — "파랑이다/초록이다" 논쟁을 우리가 직접 겪었다). 그래서
v2 에서는:

- 램프 필드는 **위치 기반**(`left`/`mid`/`right` + `beacon` + `camera_light`) —
  색 이름을 필드 이름으로 박지 않는다.
- 장치는 보이는 대로 **색을 보고**한다(`sensed: ["red", "orange", "teal-green"]` —
  F1 센서가 읽은 값).
- **의미(stop/caution/go)는 사이클 지도가 정의한다**: 지도의 각 칸에 운영자가
  이름을 붙인다(예: 적 단독 = `stop`, 초록·청록 단독 = `go`). 계약은 색의 의미를
  모른다 — 알 필요도 없다. 의미는 운영자의 지도 기입이므로 제품이 바뀌어도 계약
  구조는 그대로다.
- 카메라 프롭: **속도 확인(단속 카메라) 컨셉 전용이다 — 관측 센서 마운트로 재활용하지
  않는다**(2026-09-22 운영자 지시). 카메라 라이트가 있으면 사이클 관찰 대상에
  포함할 뿐이다.

## 3. 상태 재구성 + 명령 의미론 — v2 가 대답해야 할 두 가지

v1 에서 `POST /command` 가 곧 상태였다(멱등 set). v2 의 `pulse` 는 **비멱등 상대
명령**이다 — 같은 `{presses: 2}` 를 두 번 보내면 네 번 누르게 된다. 재전송 하나가
현장을 어긋나게 하므로, 계약에 다음 두 가지를 명시한다.

### 3.1 명령 의미론 — 펄스는 비멱등, 멱등성은 Fleet 이 복구한다

- **장치:** 펄스는 **수용한 `seq` 마다 한 번만** 실행한다(단조 seq 검사가 재전송
  중복을 막는다). 수용과 실행 사이에 전원이 나가면 실행했는지 모른다 — 모른다는
  사실을 보고에 남긴다(숨기지 않는다).
- **Fleet:** 운영자 의도를 **목표 상태 `set(목표)` 로 저장**하고, 현재 `assumed_mode`
  부터 목표까지 필요한 `presses` 를 계산해 보낸다. 명령이 끊겨 재시도해도 멱등하다 —
  목표에 이미 도달했으면 보낼 것이 없다.
- **완료 확인은 상태로:** 펄스를 다시 치지 않는다. `/status` 의 `assumed_mode` 가
  목표와 같으면 끝. 관측(F-EXT)이 있으면 실측으로 교차 확인한다.

### 3.2 상태 재구성 — 강등 사다리와 desync fault

`assumed_mode` 는 추정이다. 신뢰 등급을 계약에 박아 화면과 판정이 같은 말을 쓰게
한다:

| 등급 | 근거 | 언제 |
|---|---|---|
| **CONFIRMED** | 확인 지연 예산 T 안의 `/status` 재확인, 또는 F1/F-EXT 실측 일치 | 직후 확인 성공 |
| **ASSUMED** | 펄스 카운트로 계산(실행 가정) | 명령 후 미확인 구간 |
| **UNKNOWN** | 재동기화 실패, 전원 리셋, **지도에서 후보 0개** | 모르는 것은 모른다고 |

- **후보 0개 = desync fault** — 사이클 지도에서 갈 곳이 없으면 조용히 순환하지 않고
  fault 로 보고한다.
- **확인 지연 예산 T = 5 초(제안):** 관측 폴링(1 Hz + debounce 2 ≈ 2–3 s)이 T 안에
  들어와야 한다. T 를 넘기면 CONFIRMED → ASSUMED 강등 — observer v0.3 의
  `frozen`/`age_s` 가 이 예산의 측정값이다.
- **강등은 화면에서 보인다** — UNKNOWN 을 CONFIRMED 로 그리지 않는다.

## 4. 피드백 등급 — 결정할 것 (이 문서의 유일한 질문)

| 옵션 | 구성 | 할 수 있게 되는 것 | 못 하는 것 |
|---|---|---|---|
| **F0** 피드백 없음 | 접점만 | 펄스 명령 | 상태는 순수 추정. 제품 상태가 어긋나면(건전지 교체, 손버튼) 영구 불일치 |
| **F1** 광 센서 | 렌즈 방향 **RGB 색 센서(TCS34725 류) 1개**, 별도 소형 마운트 — **카메라 프롭은 속도 확인 전용이라 건드리지 않는다**(2026-09-22 운영자 지시) | `/status` 가 **실측** 램프 색(`sensed`) 보고. 추정↔실측 어긋남을 faults 로 — 독의 "추정이 아니라 측정" 철학 적용 | 강제 소등 불가 |
| **F-EXT** 외부 카메라 관측 | 제품을 개조하지 않고 **바깥 카메라가 신호등을 본다** — `signal/observer/` 호스트 서비스(OpenCV 고전 분할 v1, YOLO는 선택 v2). 별도 설계: `2026-09-22-signal-observer-vision-design.md` | 비침습으로 "명령↔실측" 교차 검증(S-11 해소). 컨트롤러 내부 센서가 필요 없어진다 | 관측 카메라가 신호등을 계속 봐야 한다(설치 조건). F2 없으면 강제 소등 불가 |
| **F2** 전원 스위치 | 건전지 라인 직렬 MOSFET(릴레이 아님 — 코일 상시 전류가 건전지를 먹는다) | **강제 소등** = 신뢰 상실의 물리적 표시. 전원 사이클 = 상태 재동기화(카운트 리셋) | 램프가 꺼진 것과 고장난 것의 구별은 여전히 불가(F1 없으면) |

**권장: F1 + F2.** 조합하면 닫힌 고리가 완성된다 — 센서가 실측하고, 어긋나면 계산해
누르고, 불확실하면 강제 소등한다. 부품은 LDR 3개 + MOSFET + 저항 몇 개 수준이다.
v1 페일세이프는 이렇게 재정의된다:

- 관제 침묵/재부팅 → **알려진 위치로 눌러 적색 유지**(카운트가 살아 있을 때)
- 상태 불확실(카운트 상실, 센서 불일치 지속) → **F2 강제 소등** — "보여 주는 것이
  없다"는 것 자체가 신뢰 상실의 표시다. v1 의 적색 점멸이 이 자리를 대신한다.

## 6. 컨트롤러 전원 (확정 권고)

건전지 교체식 제품이므로 **컨트롤러는 별도 전원(USB 보조배터리)** — 제품 건전지를
갈아 끼우는 순간이 사이클 카운트 리셋 순간이므로, 두 전원이 서로를 모르게 분리한다.
런타임은 AC-20 이 실측으로 강제한다.

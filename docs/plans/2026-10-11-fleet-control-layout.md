# Fleet 관제 레이아웃과 조작 규칙

근거: [D-629](../adr/D-629-control-sizing-and-console-hierarchy.md), [DESIGN.md](../../DESIGN.md). 목적은 현장 파악 → 상태 확인 → 필요한 대응 → 근거 검토다. 모든 값을 크게 보여주는 화면이 아니라 다음 행동을 찾는 화면으로 만든다.

## 화면 구조

```text
┌─ Rosy Fleet · 현장 이름 ── 접속·연결·알림 ────── 비상 정지 ─┐
│ 관제 / 설치·보정 / 현장 지도 / Cell                         │
├──────────────────────────────────┬─────────────────────────┤
│ 현장 지도 · 지도 조작             │ 지금 필요한 개입        │
│                                  ├─────────────────────────┤
│ 지도·현재 관측                    │ 상태 / 알림 / 기록 / 도구│
│                                  ├─────────────────────────┤
│ 넓은 화면 왼쪽 2/3                │ 선택한 목적의 내용       │
│                                  │ 오른쪽 1/3, 한 레일 스크롤│
│ 범례·관측 상태                    │                         │
└──────────────────────────────────┴─────────────────────────┘
```

현재 개입은 탭 바깥에 있다. 지도는 오른쪽 탭 전환으로 바뀌지 않는다. 좁은 화면은 개입 → 지도 → 같은 탭 순서이고, DOM·탭 이동 순서도 이와 일치한다.

이 와이어프레임을 이번 구현의 고정 기준으로 사용한다. 새 화면 배치를 만들 때는 이 문서의 목적·영역·순서부터 수정하고 코드로 옮긴다.

## 배치와 규격의 이유

공통 머리의 `알림`은 오른쪽 알림 탭의 진입점이다. 최근 관제 메시지와 현재 개입 요약을 확인하고, 개입 링크로 항상 보이는 큐에 복귀한다. 읽음 표시와 실제 처리 상태는 구분한다. `기록·근거`에는 상세 사건 검토를, `운영 도구`에는 설정을 남긴다. 강제 팝업이나 별도 명령 버튼을 만들지 않는다.

| 구분 | 규칙 | 이유 |
|---|---|---|
| 전역 조작 | 접속·연결·비상 정지는 머리, 화면 목적은 그 아래 문서 탐색 | 어디서든 대상 현장과 접속 상태를 확인하고 멈춘다. |
| 현재 개입 | 오른쪽 맨 위, 실제 원인·가능한 답·거절 이유를 같은 자리에서 확인 | 운영자가 다음 행동을 찾기 위해 기록을 뒤질 필요가 없다. |
| 로봇 상태 | 기본 탭, 등록 로봇과 현재 관측을 확인 | 가장 빈번한 현장 확인을 처음부터 보여준다. |
| 기록·근거 | 사건·조치·검토와 이벤트 기록, 시각은 제목과 분리 | 과거 증거가 현재 위험처럼 보이지 않고 문제를 재검토할 수 있다. |
| 운영 도구 | 대형·신호·연동을 별도 탭에 유지 | 설정·집단 조작이 감시 업무와 경쟁하지 않는다. |
| 제목 | 주 지도 20px, 우측 하위 제목 16px, 같은 역할은 같은 굵기 | 주 영역·하위 묶음의 계층을 크기로 읽는다. |
| 본문·버튼 | 본문 16px, 일반 버튼 라벨 14px, 버튼 높이 최소 48px·좌우 12px | 읽을 내용과 누를 대상을 구분하고 같은 조작은 같은 손 감각을 갖는다. |
| 보조 정보 | 라벨 14px, 시각·출처 등 12px, 보조 역할 색 | 필요한 근거를 남기되 현재 값·행동과 경쟁하지 않는다. |
| 위험 조작 | 같은 48px·14px·좌우 12px, 위험 채움·아이콘·보이는 동사 | 크기를 통일하고 색상과 명확한 문구로 즉시 개입을 찾는다. |
| 간격 | 4·8·12·16·24·32px 기존 토큰, 관련 항목은 가까이·묶음은 떨어뜨림 | 경계선과 카드의 반복보다 가까움으로 관계를 읽는다. |

## 검증과 완료 기준

기존 모듈·API·인증·CORE 실행 권한은 유지한다. 비상 정지를 포함한 버튼 다섯 종류의 실제 높이·글자·여백 일치, 필드 48px, 긴 사유 줄바꿈을 원격 브라우저로 확인한다. 관제는 기본 탭·키보드 이동·숨겨진 내용 접근·현재 개입의 상시 노출·지도 크기 유지·기록 검토 저장·내보내기를 확인한다. 데스크톱 1366×768·1920×1080, 모바일 390×844·320×568을 두 테마로 묶어서 비교한다. 소스 렌더·설치 서버·로봇 장치·현장 주행 증거는 구분한다.

## 실행 순서

1. 공용 토큰·부품으로 색상, 글자, 버튼과 간격을 구현한다. 화면 CSS는 이 역할 토큰을 소비하고 같은 값을 화면마다 새로 적지 않는다.
2. 위 와이어프레임을 기존 DOM·인증·명령 소유자에 적용한다. 알림 조회·읽음·최근 로그는 `inbox.js`, 데이터 조회와 명령 전달은 기존 관제 셸이 맡는다.
3. 실패 로그의 노드·원인·시험 SHA를 기록한다. 이동된 경로는 현재 Git 구조로 맞추고, 기존 main 실패와 새 회귀를 같은 노드로 대조한다. 시험의 크기·넘침·키보드·안전 요구를 낮추지 않는다.
4. 관련 브라우저 시험과 통합 검사를 끝내고 커밋·main 머지를 완료한다. 푸시·CI·설치본·실물 증거는 각각 기록한다. 새 레이아웃 제안은 이 완료 후 별도 변경으로 다룬다.

# 스테이션 운영 정책과 복구 보완안 R1

상태: 계획 검토용. 기준 소스 `ee0153823ab8b4b464cb2ceb33929af71da642ac`. [실기 결합 R2](2026-10-17-station-hardware-integration-design.md)의 G1–G6을 구체화한다. 기존 책임·전체 목표·시뮬레이터 제외·현장 확인 연기·실행 승인 범위를 유지한다. 새 wire field·enum·기능이 이미 구현됐다는 뜻이 아니다.

## 1. 먼저 확정할 판단 경계

| 쟁점 | 선정안 | 비교와 이유 |
|---|---|---|
| 자동 운영의 최소 측정 | 원본 사용 가능 Wh 하한·온도·pack/capacity revision과 유효한 SOH 근거를 요구 | 기존 순수 정책의 SOH 결측 허용·보수적 시간 경로를 삭제할 필요는 없지만 이번 건강도 자동 운영의 완료 근거로 사용할 수 없음 |
| 충전 종료와 출발 | 장치 정상 종료, 선택 작업의 수행 가능성, 출발 interlock을 별도 판정 | SOC 목표 도달만으로 충전기를 종료하거나 Base를 움직이지 않음 |
| 충전 목표 | 최초 범위는 현재 세션의 정상 종료 후 재투입 | 작업 마감에 맞춘 부분 충전은 vendor의 정상 중단/분리 계약·계측이 확보된 후 별도 설계. 이번 구현에서 임의 조기 이안하지 않음 |
| 재시작 | 기존 원장과 실제 owner를 대조하는 복구를 우선 | 명령을 재전송하는 복구는 전송 결과 불명 상태에서 중복 동작을 일으킬 수 있음 |
| 위치 재합의 | 현재 설치 기록 하나와 출처 있는 새 후보, 이전 실행 종료 후 새 revision | 두 좌표의 평균·마지막 도착 메시지 채택은 출처·세대·오차를 해결하지 못함 |

실제 정책은 `operations/site_execution/src/rosy/execution/site/charge_policy.py`, 프로필은 `contracts/foundation/core_common/protocol/station_charging.py`에 있다. 현재 SOH 결측을 일괄 거절하지 않으며 보수적 시간 경로가 존재한다. `ChargePolicyAdmission`은 승인 source·원본 수명·예산/작업 digest를 검증하고, `ChargeDeparture`는 선택 작업과 출발 중 재검사를 수행한다. 새 설계는 이 경로에 명시적 운영 capability 검사를 추가하는 작업이며 다른 운용 프로필을 조용히 변경하지 않는다. CORE의 필수 원본 에너지 제한을 Fleet의 시간 기준 판단으로 우회할 수 없다.

## 2. 배터리 건강도와 복귀 결정

SOC는 현재 잔량, SOH는 승인된 용량/건강도 추정의 품질·수명, 사용 가능 Wh 하한은 이번 운행 예산의 근거로 구분한다. SOH가 없는 장치를 정상 건강도로 채우지 않는다. 장치가 SOH를 제공하지 않으면 승인된 실측 용량 교정이 SOH 근거를 생성할 수 있는지 장비 단계에서 판단하며, 온라인 추정기를 이번 범위에서 새로 만들지 않는다. 팩 교체·교정 변경은 새 identity/revision으로 재수용한다.

동일한 기준 시점으로 소비를 반영한 에너지 하한과, 선택 작업·최악 귀환·대기·접안/재시도·정지 tail·reserve를 비교한다. 각 비용 항의 단위·구간과 중복 여부를 프로필에 기록한다. SOH로 이미 보정된 Wh에 SOH 비율을 또 곱하지 않는다. Wh 산정 원본 시점 이후 소비와 CORE의 전체 실행 창 계산은 실기 결합 R2의 계약을 유지한다.

판정 우선순위는 다음과 같다.

1. E-stop·장치 fault·온도/전기적 위험은 기존 로컬 보호와 maintenance HOLD가 우선한다.
2. 필수 계측·SOH·경로·station 근거 결측은 새 작업/자동 출발을 닫는다. 진행 중 실행은 기존 근거의 수명과 제한을 적용하고 만료/철회 시 정지한다.
3. 귀환 예산 자체가 부족하면 무리한 복귀를 제출하지 않고 승인 영역 내 정지·지원 절차로 전환한다.
4. 귀환은 가능하나 새 작업 후 귀환이 불가능하거나 복귀 SOC 조건이면 복귀를 우선한다. 현재 작업의 안전 종료점까지 필요한 시간·에너지도 예약한다. 종료점을 기다릴 여유가 없으면 기존 취소/정지 경로를 사용한다.
5. 충전 완료 후에도 선택된 작업과 현재 귀환 예산이 모두 충족할 때만 재투입한다. 대기 작업이 없으면 정상 충전 완료 대기를 유지한다.

`return_soc < redeploy_soc`인 기존 히스테리시스를 유지한다. 복귀 결정을 durable attempt로 확정한 뒤 작은 값 상승만으로 작업 상태로 되돌리지 않는다. 고장 해제·새 계측은 새 평가의 필요조건이며 기존 HOLD 해제 권한이나 소모한 parent를 복원하지 않는다. 장기 SOH/온도 추세는 정비 권고에 사용하되 새 capacity revision과 수용 없이 운행 한계를 자동 상향하지 않는다.

## 3. 충전과 전기적 분리

| 구간 | 확인할 사실 | 결측/실패 처리 |
|---|---|---|
| 착좌 후 | 실제 접점·정지·부하 interlock, 올바른 충전기/팩 연결 | 암 인계·충전 인정·자동 이안 차단 |
| 충전 시작 | vendor가 정의한 활성 상태와 유효한 전류/팩 반응 | 시작 제한 시간 초과 시 사유 있는 HOLD, 무제한 재착좌 금지 |
| 충전 중 | 원본 전류/온도/팩 fault·접점·세션 근거 | 승인된 vendor 보호/중단 절차, 작업 및 출발 차단 |
| 정상 종료 | 현재 세션의 정상 charger/BMS 종료, 신선한 팩 근거 | timeout·통신 단절·fault 종료를 만충으로 취급하지 않음 |
| 이안 전 | 정상 종료·전기적 분리 가능 상태·arm 영역 인계·새 에너지 승인 | 기존 owner가 순서 보장, 미확정이면 HOLD |

충전 전류가 작다는 사실 하나를 완료로 해석하지 않는다. 충전 시작·무진행·최대 체류 시간의 정의와 측정 간격은 vendor 사양 및 G1 profile로 결정한다. 단순 통신 timeout은 전류 차단을 증명하지 않는다. 출력 정지 명령·장치 ACK·실제 전기 상태를 각각 기록한다. 충전기 명령이 필요한 경우 CORE가 소유하는 제한된 세션 동작으로 계약하고 Fleet은 원시 relay/API를 직접 호출하지 않는다. 독립 reader가 출력 권한까지 얻지 않도록 읽기 포트와 동작 포트를 구분한다.

## 4. 위치 변경과 재합의의 진행 보장

스테이션 위치 변경 시 기존 실행/예약 무효화와 정지 요청을 먼저 기록한다. 실제 정지·이전 실행 종료를 확인한 뒤 독립 지도 기준의 후보를 검증한다. 후보에는 map/pose/교정 revision·원본 시각·오차·접근/후진 구간이 필요하다. 후보 관측만으로 현재 설치 기록을 덮어쓰지 않는다.

Fleet이 검증한 설치 기록을 발행해도 로봇의 수락과 새 native map 근거·접근 가능성·귀환 에너지 확인 전에는 실행 가능 상태가 아니다. ACK 유실은 정확한 revision을 조회해 대조하며 옛 명령을 재전송하지 않는다. Fleet 재시작·동시 후보·늦은 ACK에서는 기존 원장의 revision 비교/조건부 갱신을 사용해 한 현재 기록만 확정한다. 충돌하는 후보는 순서를 강제로 정하지 않고 재관측 대기로 남긴다.

카메라와 스테이션이 함께 움직였고 독립 지도 기준을 볼 수 없으면 상대 접안 관측만으로 새 절대 좌표를 산출할 수 없다. 마지막 위치로 탐색을 시작하지 않는다. 설치 재측정 또는 승인 영역/에너지 내 제한된 관측 절차가 필요하다. 자동 발견을 보장하는 제품 요구와 현재 관측 범위를 구분해 표시한다.

## 5. 복구·기한·증거 계약

| 중단 지점 | 복구의 첫 행동 | 재개를 허용하는 근거 |
|---|---|---|
| 전송 직후 응답 유실 | 저장된 정확한 session/attempt/operation으로 owner 조회 | 실제 상태·원장·동작 identity 일치. PREPARED 재전송 금지 |
| 충전 중 Fleet 단절 | CORE/장치의 로컬 보호 유지, 자동 출발 차단 | 현재 세션의 착좌·충전·owner 대조와 정상 복구 절차 |
| CORE/충전기 재시작 | 새 boot/epoch로 이전 근거 거절, 자원은 UNKNOWN 유지 | 실제 정지/접점·전기 상태와 기존 작업 종료 확인 |
| 이안 중 정지/예약 상실 | 기존 Base 실행 정지와 OMX 신규 admission 차단 유지 | 영역 점유와 실제 정지 대조 뒤 기존 owner의 명시적 조정 |
| DB/기록 저장 실패 | 이미 알고 있는 exact 실행의 제한된 정지 시도, 새 제출 차단 | 저장 복구 및 실제 상태 대조. 예약 timeout만으로 점유 해제 금지 |

모든 시간 제한은 목적을 명시한다. 센서 신선도는 원본 시계/sequence, 행위 deadline은 로컬 trusted clock, durable lease는 기존 원장 계약을 따른다. 다른 시계의 수치를 직접 비교하지 않는다. 원격 BMS I/O가 제어 타이머를 막지 않도록 bounded queue/timeout·역압을 설계하며 overflow는 오래된 입력 삭제로 신선도를 꾸미지 않고 결측/고장을 알린다. CPU 부하로 갱신이 늦어진 경우에도 만료는 유지한다.

제어에 필요한 실제 bounded 로그·저장 지연과 관측 기록의 보존 기간을 분리한다. 정상 상태·원본 입력/판정·요청/수락·실측 종료를 session/attempt/boot/pack/map revision으로 대조할 수 있어야 한다. 저장/전송 상태를 성공으로 위장하지 않는다. 기록 용량·지연 한계와 원장 정리 정책도 G1 운영 기간/G2·G3 capacity 수용 항목이다.

## 6. 추가 구현 단위와 수용 기준

| 작업 | 기존 책임/대상 | 수용 사례 |
|---|---|---|
| P1 지원 계약 | profile/schema, Fleet admission, CORE readback | SOH 결측·팩 교체·교정 변경 시 건강도 자동 운영 거절, 다른 프로필 동작 구분 |
| P2 비용/반복 방지 | 기존 policy/budget/runtime | 원본 age·동일 비용 이중 공제·경계값·SOC 흔들림·안전 종료점 비용·복귀 후 값 상승 검증 |
| P3 전기 시퀀스 | CORE station owner, 실제 charger/BMS 포트 | 오래된 완료/0A/fault/시작 timeout·분리 미확정에서 다음 단계 차단, 실제 원본 확인 |
| P4 좌표 합의 | 기존 station 설치 원장·CORE 수락 | 두 후보 경합·회전 이동·새 지도·늦은 ACK·발행 직후 재시작·관측 사각지대 |
| P5 복구/부하 | 기존 durable intent와 owner·reader lifecycle | 전송 전후 crash·DB 장애·느린 I/O·queue overflow·이안 중 예약 상실에서 중복 동작/자동 재개 없음 |

P1–P5는 실기 결합 R2의 G2–G4에 포함해 수행하고 G5–G6에서 실제 장치로 대조한다. 승인 숫자가 없는 필드에 임의 기본값을 넣어 활성화하지 않는다. 필수 확인값은 장치 모델/배선·정상/고장 종료 정의·전기 분리 순서·카메라 교정/공차·안전 정지/작업 종료 시간·에너지 오차/비용·운영 기간이다. 이전에 연기된 현장 확인을 다시 요구하는 승인 절차로 만들지 않는다.

대안인 SOC 고정 주기·충전 완료 즉시 출발은 설명과 구현이 쉽지만 작업 비용·열화·동작 소유권을 보장하지 못한다. 선택안은 현재 원장/정책을 보강하므로 계약과 부하 시험이 늘지만 새 스케줄러나 명령 owner를 만들지 않는다. 다중 로봇 큐 최적화·부분 충전·온라인 SOH 학습은 이번 1대/1스테이션 수용을 대신하지 않으며 별도 확장이다.

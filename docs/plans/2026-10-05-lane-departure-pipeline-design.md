# 직선 차선 이탈을 재현하고 개선하는 처리 파이프라인

**상태:** Proposed. 원인 조사 및 설계 초안이며, 수정 완료·모델 승격·주행 수용 기록이 아니다.

## 관측과 한계

사용자는 실제 주행에서 직선의 흰 경계선을 넘어갔고, 이후 로봇을 정지했다고 확인했다. 현장 실패로 취급한다. 이탈 당시의 영상, 인식 결과, 최종 명령, 실제 움직임을 시간으로 연결한 완전한 기록은 확보하지 못했다. 마지막 장시간 시험은 SSH 응답을 받지 못했고 종료 결과 파일도 생성하지 못했다. 통신 실패만으로 재부팅이나 모델 장애를 단정하지 않는다. 사용자 정지 확인과 장치의 최신 정지 readback은 서로 다른 증거다.

앞서 적용한 카메라 높이·pitch는 체커보드 기반 추정이다. 공유 초점거리·왜곡 가정과 추정 판 두께를 포함하며, 실제 차선 주행 정확도를 보장하지 않는다. 적용 기록은 `docs/validation/camera-board-applied-2026-10-05/result.md`에 있다.

현재 소스에서 확인한 사실:

- `middleware/perception/control/sensing/perception/lane_keep.py`: 기본 차로 반폭은 0.0925m다. 양쪽 경계가 있으면 중심선을 추정하고, 한쪽만 있으면 경계를 반폭만큼 안쪽으로 옮긴 목표를 사용한다. 경계 추적과 좌우 분류도 목표 선택에 영향을 준다.
- 같은 코드의 confidence 0.9/0.6은 양쪽/한쪽 경계 전략의 상수다. 물리적 차선 유지 확률로 해석하면 안 된다.
- `middleware/perception/control/line_observer_node.py`: keep 모드는 선택한 paint mask를 기하 처리한다. `paint_source_used`, 경계, 목표점 등의 debug 정보가 있다. learned paint 경로와 별도 shadow inference는 구분해야 한다. 이탈 당시 사용한 경로는 동기화된 runtime 증거로 확정해야 한다.
- `middleware/core/services/core_features/line_follow/manager.py`: 관측 error에 조향 gain을 적용하고 confidence·곡률·한도로 속도를 조절한다. 인식 성공 상태만으로 로봇 외곽이 차로 안에 있는지 증명하지 않는다.

## 선택할 접근

**권고: 동기화 기록 → 실패 재현 → 원인별 수정 → 모델 및 제어 평가를 함께 수행한다.** 기존 D-465 자동 라벨링, D-462 검토, D-464 데이터셋을 재사용한다. 첫 결과물은 새로운 모델보다 이탈을 설명할 수 있는 재생 사례다.

기하와 gain만 조정하면 비교 비용은 작지만 경계 오인식을 놓칠 수 있다. 분할 모델만 교체하면 흰 선 인식은 개선될 수 있지만 잘못된 폭·좌우 분류·조향 지연은 남을 수 있다. 결합 접근에서는 기록과 재생을 먼저 만들고 실제로 실패한 단계만 수정한다.

## 처리 순서와 소유

1. **로봇에서 지속 기록.** 원본 영상과 source timestamp, keep debug의 경계·좌우·선택 전략·목표점, 실제 paint source/model revision, 카메라 보정 revision, CORE 결정과 최종 명령, odometry, scan/IR freshness를 연결한다. timestamp의 시계 영역과 수신 시각을 보존한다. 로봇 내부에 제한된 용량으로 순환 기록하고 주기적으로 flush한다. SSH 종료 시 stdout만 받아 저장하는 방식의 증거 손실을 해결한다. 녹화 자체가 제어 지연을 늘리지 않는지도 측정한다.
2. **실패 구간 우선 추출.** 사용자 이탈 표시, 경계 교체, 좌우 분류 변화, 목표점 급변, 관측 소실, 조향 포화, 명령과 odometry 불일치, 통신 단절 전후를 검토 대상으로 묶는다. 이 지표들은 후보 선정용이다. 모델 confidence나 추정 목표점으로 실제 이탈 정답을 자동 확정하지 않는다.
3. **모델 PC 자동 초안과 검토.** D-465의 기존 기하·분할 prelabel을 사용한다. 바닥의 흰 경계와 벽·반사·가로선을 구분하고 가림·시야 밖은 불확실 영역으로 남긴다. D-462에서 원본과 revision을 검토한 뒤 D-464의 승인 데이터셋으로 만든다. 실제 로봇 궤적이 차선을 넘었으므로 그 궤적을 바닥/차로 정답으로 그대로 사용하지 않는다. OpenRouter는 선택적인 장면 분류·검토 우선순위 보조다. 실시간 조향은 로봇의 perception과 CORE가 담당한다.
4. **재생 비교로 원인을 분리.** 같은 원본과 보정으로 threshold/denoise/learned paint를 비교한다. 별도로 검토된 경계 마스크를 넣어 기하 목표와 조향을 비교한다. 정답 마스크에서도 목표가 틀리면 폭·투영·좌우 분류를 조사한다. 목표는 맞고 명령이 틀리면 조향 부호·gain·포화를 조사한다. 명령은 맞고 움직임이 틀리면 시간 지연·구동 응답·odometry를 조사한다. 영상 재생은 제어 계산을 검증하지만 차량 운동의 폐루프 효과는 시뮬레이션이나 별도 현장 검증이 필요하다.
5. **필요한 수정만 검증.** 폭은 확인된 두 경계로 자동 추정하되 한쪽만 보일 때 폭의 불확실성과 관측 나이를 유지하는 방안을 검토한다. 카메라 자동 보정은 잔차와 독립 영상에서의 투영 오차를 확인한다. 수동 보정 모드를 기본 경로로 요구하지 않는다. 제어 개선 후보는 횡오차·방향오차와 실제 응답을 함께 사용하는 방식이다. 차체 외곽의 경계 여유와 지연 중 이동량을 계산할 수 있는지 확인한 뒤, 여유가 부족할 때 감속/정지하는 조건을 설계한다. 새 외부 API나 프로토콜은 이 초안에서 확정하지 않는다. 최종 명령 발행 권한은 CORE에 유지한다.

## 조사할 가설

| 가설 | 구분할 증거 |
|---|---|
| 벽·반사·가로선을 차선으로 선택 | 같은 프레임의 원본, 검토 마스크, 선택 경계와 paint source |
| 단일 경계의 폭 또는 좌우 분류가 잘못됨 | 확인된 실제 차로 폭, 경계 좌표, 추적 side, 목표점의 시간 변화 |
| 카메라 투영에 체계적 편차가 있음 | 보정 revision과 독립 지면 점/양쪽 경계의 투영 오차 |
| 조향 부호·gain·포화 또는 지연 문제 | 정답 목표, CORE 명령, 최종 명령, 실제 yaw/횡이동의 동기화 기록 |

모든 가설은 미확정이다. 기록을 확보하기 전 gain이나 confidence threshold를 반복 변경해 원인을 숨기지 않는다.

## 평가와 진행 조건

train/eval은 인접 프레임 대신 촬영 세션과 capture component 단위로 분리한다. 동일 보정·장면이 train과 eval로 새지 않도록 묶음도 확인한다. D-464의 고정 eval 전체 제외 계약을 유지한다.

픽셀 IoU 외에 얇은 경계 누락/오인식, 지면 경계 오차, 목표 중심 오차, 조향 방향 일치, end-to-end 지연, 관측 소실 회복을 측정한다. 폐루프에서는 로봇 차체 외곽 기준 최소 경계 여유, 이탈 횟수와 지속 시간, 횡오차와 방향오차, 포화 시간을 기록한다. 카메라와 odometry만으로 차선 이탈 정답을 독립 확정할 수 없으면 외부 관측과 현장 확인을 사용한다.

첫 재시험은 이번 직선 실패 조건을 재현하는 사례로 한다. 조건·거리·속도와 합격 기준을 실행 전에 고정하며, 관측된 흰 경계선 침범은 실패로 판정한다. 이후 조명·편측 경계·가림·곡선으로 확대한다. 수치 기준은 차로 폭·차체 폭·측정 불확실성·응답 지연을 확인한 뒤 정한다. host 테스트, 모델 replay, shadow 실행, 실제 차선 유지 결과를 각각 보고한다.

## 다음 실행 단위

- perception/CORE: 기존 debug와 최종 명령을 시간으로 연결하는 로봇 내 기록 경로 및 읽기 전용 회수.
- learning: 실패 구간 intake와 D-462 검토 연결, 승인 마스크로 기하 재생 비교.
- control: 재생 결과가 지목한 원인의 최소 수정과 폐루프 검증 계획.

이 초안에서는 추가 주행, 모델 학습/승격, runtime 변경, 안전 조건 제거를 실행하지 않았다. 이번 실패의 해결 및 FIELD 수용은 미완료다.

# Rosy Account 공통 프로필 연결

기존 D-757 구현과 프로필·운영 감사에서 남은 연결을 완료한다. 계정 정본은 기존 Fleet 원장,
편집 화면은 `/console/profile`로 유지한다. 프로필 표시 실패를 권한 허용으로 처리하지 않는다.

1. 현재 access token에 결속된 userinfo, 공통 Python receiver, CORE/Games/학습 session을 연결한다.
2. Fleet 프로필에 역할과 실제 자원별 권한을 구분해 표시한다. Robot/Pilot/학습/Games에서
   동일 표시 이름과 내 계정 진입점을 제공한다. 기존 입력·작업은 새 탭 진입으로 보존한다.
3. Cam/Pilot 네이티브도 같은 userinfo 계약과 브라우저 프로필 진입을 사용한다.
   프로필 통신은 정지·장치 명령 경로와 분리하며 계정 전환 후 이전 이름을 버린다.
4. 유효/정지/회수/타 계정/장애, 프로필 저장 후 앱 재조회, 좁은 화면·키보드,
   정확한 grant 표시를 원격 API·Chromium과 native 빌드로 확인한다.
5. 배포·TLS·client 등록·실계정 이관 준비를 확인하고 가능한 운영 연결을 진행한다.
   관리 권한·인증서·접속 장치가 없는 항목은 구체적 증거를 남긴다. 키/계정 원문은 공개 문서에 넣지 않는다.

구현·원격 시험·native·local main·CI·배포·실사용 수용을 각각 기록한다.
사용자는 구현과 커밋·로컬 병합을 승인했다. 원격 push는 이번 요청으로 추정하지 않는다.

## 운영 재확인

2026-10-14 읽기 전용 확인에서 현장 Fleet은 이전 이미지이며 Account 설정·마운트가 없다.
현재 공통 HTTPS 후보는 발견했지만 신뢰 인증서와 443 listener가 없고, 보호된 설정을
설치할 비대화형 관리자 권한도 없다. 기존 계정·DB를 보존한 서명 배포가 필요하다.
실제 주소·사용자·키·인증서 원문은 공개 문서에 남기지 않는다.

학습 서버는 loopback만 검사하면 누락된다. tailnet 주소에서 다음 다섯 운영 단위를 확인했다.

| 운영 단위 | 전환 시 보존할 경계 |
|---|---|
| dataset review | 별도 데이터셋 서버와 기존 데이터 경로 |
| edge review | 현재 편집 서비스와 프로젝트 매핑 |
| v12 review | 고정된 이전 소스와 데이터 계보 |
| v13 evaluation | 고정 평가 릴리스와 모델·데이터 계보 |
| v13 review | 현재 curation 코드와 소유자 매핑 |

다섯 서비스 모두 Account session 경로가 404였다. 유지할 대화형 서비스마다 현재 adapter와
HTTPS receiver를 적용해야 하며, 서로 다른 데이터셋을 하나의 일반 인스턴스로 대체하지 않는다.
TensorBoard는 별도 인증 진입점이 필요한 보조 조회 서비스다. 통합 adapter가 있다고 간주하지 않는다.
현재 로봇 등록 목록과 연결된 Android 기기는 다시 확인하지 못했다.

운영 수용 순서는 서명된 후보 → 관리자 HTTPS·키·Android app-link 구성 → 기존 원장 보존 활성화
→ 각 서비스·프로젝트·로봇 매핑 → 실제 계정 로그인·프로필 저장/재조회·권한 변경/회수·로그아웃이다.
이 단계와 최악 지연 조건의 native 회수 시간 측정은 소스·격리 시험 통과로 대신하지 않는다.

## 구현과 검증 기록

- 중앙 `userinfo`는 활성 access token·계정·세션 family·revision을 확인한다. CORE/Games/Learning은
  같은 계정에 결속된 표시 이름과 고정 프로필 URL을 전달한다. 이름은 자격이나 권한으로 쓰지 않는다.
- Robot/Pilot/Games/Learning은 중앙 프로필을 표시하고 편집 화면으로 연결한다. Fleet은 역할과
  실제 자원별 grant를 구분한다. 오류·로그아웃·계정 변경 후 이전 이름/권한을 다시 표시하지 않는다.
- Cam/Pilot은 같은 프로필을 사용하며 정지 경로는 프로필 통신을 기다리지 않는다. Pilot에서 외부
  프로필로 이동하기 전 기존 세션 종료 절차를 따른다. APK 설치와 실제 app-link 수용은 별도다.
- `176415123` 원격 API·자산·구조 회귀: 584 passed, 204 skipped, NEW 0.
  skip에는 opt-in 브라우저가 포함되므로 아래 실제 브라우저 기록과 구분한다.
- Node 50개 통과: 표시 값·URL·계정 결속·늦은 응답·로그아웃·Learning 주기 갱신과 기존 전송 회귀.
- 실제 HTTPS Robot→Pilot 브라우저에서 중앙 이름 수정/재조회, 프로필 새 탭, 조회 장애의 이전 이름 제거,
  로그아웃을 확인했다. Games도 이름 갱신·로그아웃·권한 회수를 확인했다. Fleet 40개는 프로필·grant를 포함한다.
- Learning의 실제 HTTPS 서버·브라우저·서명 검증·암호화 SQLite 시험은 로그인→이름 갱신→장애/복구
  →로그아웃 후 이전 쿠키 거부를 확인했다. 중앙 Authority 통신만 시험 대역이며 운영 인수 증거가 아니다.
- 독립 backend/web/native 검토를 수행했다. Native 빌드 결과는 아래와 같고,
  로컬 착지는 `tools/land.py`의 원격 회귀·known-failures·lint 결과와 Git 이력으로 확인한다.

통합 `7d59815e4` 브라우저 묶음은 79개 통과, 기존 Games 시험의 `expect` import 누락 1개 실패였다.
제품 동작 변경 없이 `641b69c65`에서 해당 import를 복구하고 그 시험을 원격 재실행해 통과했다.
같은 `641b69c65`의 관리자·Learning 실제 브라우저 묶음 5개도 통과, NEW 0이다.
각 기록의 범위가 다르므로 하나의 SHA에서 모든 시험을 실행했다고 합산하지 않는다.

Pilot 시험용 공개 설정 APK는 `fc1b3bdc3`의 JVM 106개 통과·1개 skip과 빌드 성공을 확인했다.
APK 안의 `account-profile.js`는 소스와 바이트 단위로 같으며, service worker는 통합 캐시 버전이다.
공유 native `AccountSession.kt`도 최종 소스와 동일함을 확인했다.
issuer·client·resource·callback은 비운영 시험 설정이다. 운영 로그인이나 기기 app-link 성공을 뜻하지 않는다.
Cam도 최종 `fc1b3bdc3` 기준 JVM 440개 통과·skip 없음, APK 빌드 성공을 확인했다.

마지막 검토에서 Python 프로필 조회의 중복 세션 재검증/갱신을 제거했다. 이미 저장된 서명 토큰과
계정·family 결속, 만료, 응답 후 원장 변경 검사를 유지하고 userinfo가 현재 활성 상태를 확인한다.
선택적인 userinfo 통신만 소켓 타임아웃 1초를 사용하며 기존 인증 통신은 3초다.
이는 중복 지연을 줄이는 변경이며 DNS·DB·전체 요청 시간이나 native 30초 회수를 실측했다는 뜻이 아니다.

운영 서버는 변경하지 않았다. CI·서명 배포·실기기·실계정 수용은 미완료다.

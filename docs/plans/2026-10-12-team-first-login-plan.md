# 팀원 계정 발급과 첫 로그인 변경 구현 계획

사용자 지시와 [D-686](../adr/D-686-fleet-first-login-password-change.md)에 따른다. 명단·자격은 private 현장 기록에서만 다룬다. 구현은 기존 `uiux/header-all-surfaces`의 계정 작업을 잇고 공유 main의 미커밋을 보존한다.

1. **기존 UI 착지 발견 수정:** disabled 이유, 새 로그인 설치 자산 closure, 문서의 비밀 탐지 오검출을 실제 계약에 맞춘다. Fleet 크기 판정은 현재 소스·새 인증 범위·독립 검토로 재판정하고 예산을 무작정 늘리지 않는다. 지도 충돌 후 재접속은 입력을 보존하므로 기록 후 명시적 새로고침을 안내하고 최신 서버 초안 readback을 검사한다.
2. **서버:** 기존 PasswordSessions/authorize에 초기 쿠키 제한, 같은 출처 change-password, 기존 SQLite의 source-bound 변경 해시, 세션 회전·캐시 무효화·재시작/경쟁 처리. 새 계정 API/권한/의존성은 추가하지 않는다. 해당 모듈·API reference·D-519 호출자를 점검한다.
3. **화면:** 전용 로그인에서 첫 변경 입력/확인/제약·오류·결과 확인 후 업무 복귀. 첫 변경 미완료 계정을 운용자로 표시하거나 보호된 행동을 활성화하지 않는다. 폼 실제 라벨·키보드·중복 제출·비밀 초기화와 Map/Cell 초안 보존을 검증한다.
4. **회귀와 독립 검토:** 서버 RED→GREEN은 적정 자원 원격 PC만 사용한다. Node·로그·설치 자산·실제 Chromium·CSRF·권한 거절·DB 장애·재시작·경쟁을 검증하고 known_failures와 비교한다. 구현과 명세/품질 검토를 구분한다.
5. **착지·출하:** 사용자가 이미 승인한 main 착지/push를 기존 도구로 수행한다. 해당 SHA CI, 서명 릴리스, 설치 SHA·자산·로그인 화면을 확인한다. 실패한 묶음을 합산하여 통과로 표시하지 않는다.
6. **실제 발급:** 설치 서버의 네 팀 명단만 사람 로그인으로 발급/읽기 확인한다. 초기 비밀번호=ID와 필수 변경 여부를 검증하되 팀원 대신 최종 비밀번호를 정하지 않는다. 서비스 토큰은 보존하고 비밀/메일을 공개 문서·로그·메시지로 전달하지 않는다. 실제 팀원 변경·실물 장치 수용은 당사자 증거가 없으면 미확인으로 남긴다.

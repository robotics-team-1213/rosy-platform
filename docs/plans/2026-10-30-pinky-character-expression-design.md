# Pinky 캐릭터 표현 — 방향성 눈인사와 졸린 대기

기준 결정: [D-922](../adr/D-922-pinky-calm-curious-character-expression.md). 작성일: 2026-10-30.

## 확정한 범위와 기본값

사용자가 선택한 것은 상황별 자동 반응과 표정·후면 LED 연동, 차분하고 호기심 많은 동료라는 성격, 사람이 있는 방향으로 먼저 보내는 눈인사, 긴 일반 대기의 졸린 휴식이다. 이 문서는 선택을 구현 가능한 범위와 검증 조건으로 풀어 쓴다. 코드 구현·실물 수용 기록은 아니다.

사용자가 남은 질문의 해결을 위임하여 아래 기본값을 설계 결정으로 채택했다. 여러 사람 처리·재인사·휴식·시선·어휘·LED의 제품 선택은 닫혔다. 실제 장치에서의 색·방향·밝기·움직임 확인과 감지·렌더링 연결은 검증·구현 작업으로 남는다. 사용자가 각 수치를 직접 선택한 것으로 기록하지 않는다.

## 성격은 같은 경험의 전후에 이어진다

기본 성격은 반응의 강도와 속도를 정한다. 현재 상태·관심은 주행, 유효한 새 대상, 일반 대기 등 지금 표현할 대상을 정한다. 직전 경험의 짧은 맥락은 같은 관측의 반복 여부와 대기 지속, 차단 해제 직후인지를 구분한다. 사람 신원 식별·사람별 장기 기억·대화 시스템은 추가하지 않는다.

| 장면 | 표현 목표 | 복귀 근거 |
|---|---|---|
| 주행 | 집중한 눈, 절제된 시선, 알아볼 수 있는 LED 리듬 | 검증된 이동·정지·모드 변화 |
| 새 대상 발견 | 작은 놀람 후 관심 | 사건 만료 또는 높은 우선순위 상태 |
| 사람이 다가옴 | 해당 방향으로 시선 이동 후 먼저 눈인사 | 짧은 반응 종료 후 현재 작업 |
| 사람이 옆으로 이동 | 화면 안에서 부드러운 방향 추종 | 최신 관측, 관측 소실 시 중립 |
| 정상 정지 | 차분히 쉬는 태도 | 새 작업 또는 유효한 사건 |
| 장애물 차단 | 주의·상황 확인·기다림 | 실제 차단 해제 |
| 경로 실패 | 곤란함과 명확한 실패 표시 | 실패 해제·새 상태 |
| 긴 일반 대기 | 졸린 듯 편안히 쉼 | 사람 관측·작업 시작·우선 표시 |
| 목적지 도착 | 작은 만족 후 일반 대기 | 실제 성공 근거 |
| 비상 정지·고장 | 기존 안전·고장 표시 우선 | 실제 해제 상태 |

졸린 휴식은 장애물 차단·실패·비상 정지·관측 누락에 적용하지 않는다. 차단이 길어졌다는 이유만으로 편안한 잠으로 바꾸지 않는다. 화면의 휴식은 실제 절전 진입이나 센서 정지를 요청하지 않는다.

## 눈인사는 방향에 맞고 반복을 억제한다

사용자가 선택한 범위는 방향성 있는 화면 눈인사다. 눈웃음과 눈꺼풀의 작은 변화로 표현할 수 있으며, 실제 깜빡임은 D-504의 금지와 충돌하므로 이번에 채택하지 않는다. 몸체 회전·주행 방향 변경·사람 추종은 추가하지 않는다.

관측의 종류·방향·시각·신뢰도 검증은 기존 경로에서 재사용한다. 지원되는 방향 정보가 없으면 표정만으로 사람 위치를 꾸미지 않는다. 새로운 관측인지 판정할 식별자가 있으면 재사용하고, 없으면 검증된 종류의 등장·소실 전환으로 제한한다. 스트림 복구 첫 스냅샷을 새 인사의 근거로 바로 재생하지 않는다.

관측이 오래되거나 사라지면 시선을 중립으로 복귀한다. 사람의 눈맞춤·의도·감정은 추론한 사실로 표시하지 않는다. 아래 선택·유지 규칙으로 매 프레임 다른 사람에게 시선이 튀는 전환을 방지한다.

## 여러 사람에게 관심을 나누는 규칙

기존 검증과 알려진 모델 revision을 통과한 `person` 중 신뢰도 0.5 이상, 기존 0.3초 신선도 안의 관측만 쓴다. 상자 좌표는 정규화된 좌상단 `x,y`와 크기 `w,h`이며 중심은 `x+w/2,y+h/2`다. 기존 `Detection.track_id`는 선택적 값이다. 모델 revision·스트림 세대·추적 ID를 함께 보며 신원으로 해석하지 않는다.

모든 후보가 서로 다른 추적 ID를 가지면 현재 대상을 우선 유지한다. 새 선택은 화면 중앙과의 수평 거리, 신뢰도 내림차순, 추적 ID 오름차순이다. 현재 대상을 최소 3초 유지하고 이후 미인사 대상에게 같은 순서로 관심을 나눈다. 새 인사는 전역 5초 간격을 지킨다. 모두 인사했으면 다른 사람에게 연속으로 시선을 돌리지 않고 현재 대상을 잠깐 유지한 뒤 작업·중립으로 돌아간다. 대상이 최신 관측에서 사라지면 인사를 즉시 중단하고, 최소 유지 시간이 끝나지 않았더라도 소실된 방향을 추적하지 않는다.

ID가 빠지거나 중복되면 그 관측은 무리 단위로 처리한다. 사람 상자 중심의 신뢰도 가중 평균을 바라보고, 무리의 등장에 한 번 인사한다. 무리가 계속 보이는 동안 개별 사람의 추가·재등장을 추측하지 않는다. 추적 가능 여부가 바뀌면 새 기준 스냅샷을 잡고 전환 자체를 새 사람 등장으로 세지 않는다.

## 인사·휴식·시선의 시간과 범위

| 항목 | 채택한 기본값 | 이유와 경계 |
|---|---|---|
| 등장 확인 | 최신의 연속 관측 0.5초, 서로 다른 seq 최소 2개 | 단일 프레임 오검출 억제. 관측 사이 신선도 0.3초를 넘기면 확인 누적 초기화 |
| 인사 유지 | 일반 대기 1.5초, 주행 0.6초 | 짧게 인사하고 현재 작업으로 복귀. 조종·도킹 등 작업 중에도 0.6초 상한 |
| 전체 새 반응 간격 | 5초 | 발견·인사가 겹쳐도 연속 과잉 반응을 막음. 안전 표시는 이 간격과 무관하게 즉시 선점 |
| 같은 대상 재인사 | 최신·연속 관측으로 확인된 부재 10초 및 직전 인사 후 60초, 둘 다 충족 | 계속 보이는 사람에게 반복하지 않음. 무리 모드에서는 무리 전체 부재 기준 |
| 관심 대상 최소 유지 | 3초 | 관측 소실·카드·안전 선점에는 즉시 해제. 인사 뒤 짧은 관심은 남은 유지 시간 안에서 일반 대기에만 허용 |
| 졸린 휴식 진입 | 일반 대기 300초 | 현재 IDLE 기준 유지. 작업·유효한 새 사람 등장·우선 상태 진입 시 초기화 |
| 휴식 전환 | 눈꺼풀 변화 1초, 느린 움직임 8초 주기 | 완전한 눈 감기·깜빡임 없이 쉼을 표현. 실제 전원 상태를 변경하지 않음 |
| 시선 이동 | 320×240에서 수평 ±6 px, 수직 0 px, 이동 0.4초 | 현재 자산의 자발적 시선 오프셋을 대체하여 합산 초과 방지 |
| 방향 계산 | 입력의 비반전 영상에서 중심 x를 로봇 좌우로 해석해 수평 범위에 선형 대응 | 카메라·LCD 좌우 변환은 소유 렌더러에서 한 번 적용하고 실제 좌우 수용으로 확인 |
| 관측 소실 | 현재 방향 반응 즉시 취소, 중립으로 0.4초 복귀 | 오래된 관측으로 사람 위치를 계속 표시하지 않음 |

유효한 연속 빈 관측과 추적 대상의 연속 부재만 10초 재인사 조건에 누적한다. 패킷 손실·오래됨·모델 변경·seq 역행은 부재가 아니다. 이 경우 부재 누적을 버리고 현재 반응을 취소한다. 스트림 복구 첫 관측의 대상은 이미 보이는 기준 집합으로 삼아 인사를 재생하지 않는다. 최초 기동에서는 안정된 0.5초 관측 뒤 한 번 인사할 수 있다.

10초 부재 뒤 돌아왔어도 직전 인사 후 60초가 안 지났으면 그 재등장 반응은 폐기한다. 계속 보이는 동안 60초가 지나도 인사하지 않는다. 다음 재인사에는 다시 10초 이상 유효한 부재와 새 재등장이 필요하다. 전역 5초 간격에 걸린 새 등장도 반응을 예약하지 않고 버린다. 여러 사람이 처음부터 함께 있을 때는 현재 유효하게 보이는 미인사 후보를 3초 유지·5초 간격에 맞춰 고르는 것을 허용하지만, 이미 버린 재등장 반응이나 안전 선점 중의 관측을 미인사 후보로 되살리지 않는다.

안전·고장·차단·필수 카드가 반응을 선점하면 반응을 폐기한다. 선점이 끝나도 현재 보이는 사람에게 밀린 인사를 하지 않고 새 기준을 잡는다. 현재 세대에서 보이는 추적 대상의 인사 여부는 계속 유지하고, 마지막 유효 관측 후 60초가 지난 대상만 기억에서 제거한다. 기억에는 64개 상한을 둔다. 상한을 넘으면 임의로 잘라 재인사를 일으키지 않고 무리 모드로 낮춘다. 사람별 장기 기억은 만들지 않는다.

## 표정 어휘와 후면 LED 기본값

첫 버전은 기존 `hello/basic/angry/bored/fun/happy/interest/sad` 8종만 쓴다. 일반 대기는 basic, 사람·대상 관심은 interest, 작은 눈웃음 인사는 happy, 졸린 휴식은 bored 형태를 활용한다. 도착의 만족도 happy를 쓰되 실제 성공 근거에만 연결한다. 나머지 모드 매핑·상황 카드는 기존 계약을 유지하며, 차단·실패의 bored가 졸린 일반 휴식으로 해석되지 않도록 카드·상위 상태 표시가 우선한다. 미사용 angry를 새 분노 동작으로 연결하지 않는다.

아래 RGB는 `set_led`의 채널 값이다. 물리 밝기 퍼센트가 아니며 `set_brightness` 전역 설정은 바꾸지 않는다. 기본 RGB에 같은 배율을 곱해 반올림하고 범위를 제한한다. 호흡은 끊어지는 점멸 대신 부드러운 사인 곡선으로 0.4~1.0배, 휴식은 0.25~1.0배 사이에서 움직인다. 기존 5 Hz 적용 예산을 유지한다.

| 상황 | 기본 RGB·채널 상한 | 리듬 |
|---|---|---|
| 일반 대기·일반 정지 | (12,4,10), 최대 12 | 고정 |
| 주행 | (0,24,24), 최대 24 | 4초 호흡 |
| 수동 조작 | (20,20,20), 최대 20 | 4초 호흡 |
| 도킹 | (24,0,20), 최대 24 | 4초 호흡 |
| 발견·눈인사 | 현재 상태의 같은 색, 최대 36 | 기본 밝기에서 0.4초 상승·유지·0.4초 복귀. 0.6초 반응은 상승·복귀 각 0.3초, 유지 없음 |
| 차단·기다림 | (24,14,0), 최대 24 | 2초 호흡. 해제 근거가 있을 때만 종료 |
| 졸린 일반 휴식 | (8,3,7), 최대 8 | 8초 호흡 |
| 안전 정지·실패·경보·필수 정보 | 기존 표시 | 위 감정 효과 전부 중단. 경보의 어두운 구간도 양보 |

인사·발견의 증폭 배율은 해당 상태 RGB의 채널 최대값이 36이 되도록 정하되, 원래 RGB가 모두 0이면 강조하지 않는다. 실제 LED가 없거나 서비스가 준비되지 않으면 표현 경로만 재시도하며 주행·안전 경로를 바꾸지 않는다. 실물에서 과도하게 밝거나 색 구분이 어려우면 이 설계 기본값을 근거와 함께 조정한다.

## 얼굴과 LED는 한 판단을 다르게 표현한다

얼굴은 관심과 태도의 세부, LED는 뒤에서도 알아볼 수 있는 상태와 리듬을 맡는다. ROS-free 공통 판단 결과를 기존 데이터 형태에 맞춰 전달하며 별도 이벤트 프레임워크는 도입하지 않는다.

의미 우선순위는 안전 정지·고장 > 차단·경로 실패 > 발견·인사 > 작업 > 일반 대기다. 실제 적용에서는 단일 LCD 소유자의 상황 카드·CORE 누락·필수 정보·절전 계약과 후면 LED의 기존 배터리 경보 우선권을 유지한다. 경보의 어두운 점멸 구간도 감정 효과가 차지하지 않는다.

단조 시계로 일시 반응을 만료하고 안전 상태에 진입하면 즉시 폐기한다. 모드가 바뀐 뒤 끝나지 않은 인사를 재생하지 않는다. 주행 중 눈인사 뒤에는 현재 작업에 집중하는 표현으로 돌아간다. 서비스가 늦게 뜨거나 재시작되면 현재 의도가 적용되는지 검증한다.

| 후면 RGB | `middleware/core/services/core_features/power/battery.py`, `middleware/drivers/pinky_led` | 경보·정보 표시·감정 효과 중재, 재연결 적용 |
| 얼굴 | `middleware/robot_ui/face/{make_faces.py,emotion}` | 단일 소유자·어휘·자산·시선 렌더·설치·재생 예산 |

위치는 소스 조사 기준이며 writer 권한이나 배포 closure를 새로 정하지 않는다. D-380의 상태 램프와 후면 RGB를 같은 출력으로 취급하지 않는다. 표현은 최종 `cmd_vel`을 만들거나 기존 정지 판단을 바꾸지 않는다.

## 선택하지 않은 방식

자산 종류만 늘리는 방식은 상태 전후의 연속성과 반복 반응을 해결하기 어렵다. 자유 감정 생성·성격 설정 화면은 이번 요구보다 크다. 기존 구조 안의 공통 표현 정책과 제한된 짧은 맥락을 사용한다. 기존 8종·320×240·깜빡임 금지·전력 예산은 현재 계약으로 남으며, 바꿀 필요가 있으면 관련 계약과 시험을 함께 검토한다.

## 후속 구현의 완료 기준

1. 정책: 정상 정지·차단·실패·일반 대기 구분, 안전 선점, 사건 만료, 대기 초기화, 반복 인사 억제, 오래되거나 잘못된 관측 배제.
2. 관측: 사람 종류·방향의 producer부터 화면까지 실제 연결을 추적하고 미지원·소실·재연결을 검증한다. 주행은 모드 이름만으로 추측하지 않는다.
3. 출력: 서비스와 face-inputs가 같은 의도를 표현하고 LED 경보의 밝은 구간·어두운 구간 모두 감정 효과보다 우선한다. 서비스 복구 후 현재 의도를 적용한다.
4. 자산: 어휘·생성·설치·허용 목록·소비자가 일치하고 320×240·재생 예산을 지킨다. 새 시선·표정의 형태와 움직임을 렌더로 확인한다.
5. 원격 시험: 저장소 공식 원격 pytest와 known-failure 비교로 해당 커밋을 검증한다. 로컬 노트북 pytest로 대체하지 않는다.
6. 실물: LCD의 실제 시선 방향·거리·각도·조도와 뒤 LED의 위치·밝기·색·전환을 별도 확인한다. 정지 카드·절전·CORE 누락·배터리 경보와의 공존을 확인한다.

## 기록과 후속 단계

기획 토론·사용자 선택은 팀 Confluence에서 이어 기록하고, 실행 계약·ADR·코드 검증은 소유 저장소에 남긴다. 내부 사이트 주소와 대화 원본·작업 공간의 임시 슬롯 메타데이터는 공개 ADR에 복제하지 않는다. 이번 문서 변경은 새 API·표정 이름·실물 동작을 배포하지 않는다.

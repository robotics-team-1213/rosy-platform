# Fleet 목표·대형 주행 지원

사용자 범위는 사이트 Fleet 서비스, 실제 로봇 주행, 목표 주행과 대형 주행이다.
기존 CORE 목표 API와 리더·팔로워 API를 사용한다. 최종 cmd_vel 발행자는 CORE다.

## 구현

- Fleet는 인증된 CAP-001을 읽어 로봇 상태 행의 capabilities로 표시한다.
  표시 캐시는 5초다. 조회 실패는 null이며 온라인 상태 증거를 지우지 않는다.
- 목표 전송·양보 지점 전송 전에 navigation.goal_navigation을 새로 확인한다.
  대형 계획은 리더 swarm.lead, 팔로워 swarm.follow를 확인한 뒤 릴레이를 연다.
  알 수 없거나 true가 아니면 동작 요청을 보내지 않는다. CORE의 최종 판정은 유지한다.
- 콘솔은 미지원 기능의 버튼을 비활성화하고 이유를 표시한다.
  기존 서버에 필드가 없으면 기존 UI를 유지한다. 새 서버의 null은 확인 불가다.
- 기능 조회 중 로봇 클라이언트 교체·대형 편입·중단이 생기는 경합도 거절한다.

## 현장 증거와 남은 순서

두 장치의 설치 런타임은 motor이고 수동 주행만 광고한다. 각각 짧은 저속
수동 명령을 실행했고 엔코더 이동 및 마지막 IDLE·속도 0을 읽었다.
첫 장치의 브라우저 기준 정지 관측 지연은 약 1.61초, 두 번째는 약 0.33초다.
이는 물리 정지 시간의 독립 측정이나 G4 합격 증거가 아니다.

점유 지도와 신뢰 가능한 공통 좌표 위치가 없고 장치의 navigation 서비스가
비활성이다. 목표·대형 주행은 실행하지 않았다. 천장 카메라 수신은 위치 수용을
대신하지 않는다. dispatch 재개, E-Stop 해제, 승인 파일 생성은 하지 않았다.

실제 활성화는 기존 commissioning 계약 순서로 진행한다.

1. 릴리스·장치에 결합된 모터 사전점검과 G4 원시 시험 기록을 확보한다.
   첫 장치 정지 지연을 다시 측정해 원인을 해소한다. 빈 승인 파일로 통과시키지 않는다.
2. 정식 승인 도구로 검증한 뒤 navigation 런타임과 SLAM·점유 지도·위치를 준비한다.
3. 한 대의 짧은 목표·취소·정지 readback을 확인한다.
4. 두 장치의 공통 map/frame, 신선한 pose/reference 스트림, 팔로워 이탈 정지를
   확인한 뒤 저속 대형 시험과 현장 관찰 결과를 기록한다.

호스트 테스트는 소스 회귀 증거다. 새 사이트 이미지 배포, 장치 기능 활성화,
실제 목표·대형 주행, 독립 현장 수용은 별도이며 아직 완료하지 않았다.

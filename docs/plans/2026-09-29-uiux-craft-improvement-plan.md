# UI/UX 크래프트 개선 계획 — D-280 후속 전 표면 회차 (Impeccable 렌즈)

**Goal:** 여섯 활성 표면을 D-280 순서(운용 웹 → Fleet → 게임 → 얼굴·장치 신호 → 문서)로
돌면서, 남은 D-153 게이트 마감(G3 사람 평가·상태 행렬·readback 표현)과 크래프트
심화(위계·밀도·문구·온기)를 한 회차씩 함께 닫는다.

**Architecture:** D-280은 제품 성격을, concept 16과 D-153은 법과 평가 방법을 소유한다.
이 계획은 각 표면에 Impeccable 크래프트 패스(critique → 표면별 특화 패스 → polish)를
얹고, 검증은 유한하게 묶는다 — 배치 검증 1회, 수정 1배치, 확인 1회, 그러면 정지한다.
열린 결말의 폴리시 루프는 돈을 태우고 마감 핸드오프가 잘하는 일을 대신하는 실패다.
새 토큰·부품·문법이 필요하면 그 자리에서 ADR을 쓴다(사용자 승인 2026-09-29).

**Tech Stack:** 현행 정적 웹(`src/hmi/web` 토큰·부품, `src/hmi/dashboard` 셸·패널,
Fleet `fleet/server/web`, 게임 `games/web`), PIL 얼굴 렌더러, pytest·Playwright,
`impeccable detect` 기계 검사, `docs/validation/` 회차 기록.

**Status:** 실행 계획. 표면별 완료와 게이트 변화는 각 모듈 `progress.md`와 회차
폴더가 소유한다.

---

## 원칙 (이 계획의 법)

1. **계약이 크래프트보다 먼저다.** D-220(정지), D-202/D-214(대비), 닫힌 토큰 집합,
   4문법, D-218(확인 문법) 위반은 "더 예뻐진" 결과로 상쇄되지 않는다. G1 빨간 표면은
   즉시 HOLD다.
2. **다듬음은 보존하고, 재디자인은 대체한다.** 각 패스는 현행 정체성·문구·동작을
   유지하는 다듬음이다. 표면의 시각 세계를 갈아엎는 안은 이 계획의 범위가 아니고
   별도 설계 문서로 간다.
3. **검증은 유한하다.** 표면당 배치 검증 1회(데스크톱+모바일 함께) → 수정 1배치 →
   확인 최대 1회. 그 후 다음 표면으로 간다.
4. **LOCAL은 DEVICE/FIELD가 아니다.** 이 계획의 어떤 캡처도 실물 수용으로 승격하지
   않는다(D-91, D-153.3).

## P1 — 역할 운용 웹 (`/console` `/setup` `/device`)

**표면 질문:** 지금 움직여도 되는가?

**현재 blocker** (`STATUS.md` dashboard): /device host-system, /console
mode/teleop/line-follow/docking/map 최신 변경의 브라우저 회귀·신흘 관리자 캡처 부재로
SOURCE/LOCAL HOLD.

| 패스 | 내용 | 반영 파일 |
|---|---|---|
| critique | 1366×768·390×844 전체 셸 스크린샷을 8항 G3 시트로 읽기. 정보 위계(상태→근거→조작), 카메라/지도/조작 3영역 배분, 문구 밀도 | `surface.html`, `shell/`, `panels/console/*`, `panels/host/*` |
| layout | 감지·관측·조작 밀도 재점검. 같은 외곽선 카드 남발로 위계가 무너진 구간 정리(Law 2) | `shell/shell.css`, `styles.css` |
| clarify | 증거·접수·완료 문구 통일 점검 — "접수됨"과 "완료"가 다른 말로 읽히는지 | `panels/host/*`, `triage.js` |
| harden | 첫 기동·권한 거부·SAFE_STOP·지연·연결 끊김 셀의 회복 동선. 비활성 조작의 이유가 그 사용자 권한으로 도달 가능한지 | `panels/*`, role manifest |
| polish | 배치 검증 후 남은 미세 결함만. E-stop 상단 고정·44px 대상 유지 | — |

**게이트:** dashboard 브라우저 전체 회귀, 역할 G2 60셀 재생성(오버플로·페이지오류 0),
G1 전 suites. **사람 G3:** 운용자·설치자 각 1인 이상 8항 시트(§G3 참조).

## P2 — Fleet (`/console`)

**표면 질문:** 어느 로봇에 주의가 필요한가?

**현재 blocker:** 실물 페어링·E-STOP/목표 readback 없음, 사람 G3 미수행. LOCAL
브라우저·서버 시험은 초록이다.

| 패스 | 내용 |
|---|---|
| critique | 8상태×3뷰포트 현행 셀을 예외 우선 원칙으로 재독회. 정상 로봇이 중립색인지, 예외가 첫 시야에 들어오는지 |
| distill | "정상은 안 보임" 심화 — 전체 보기 토글·로스터 요약·대기열에서 정상 정보가 차지하는 면적 재조정. 지도·카메라·개입 3열 배분 재점검 |
| harden | 지연 나이·연결 상실·권한 거부 문구가 로봇 장애와 Fleet 장애로 구분되는지(이전 회차 수정의 회귀 방어) |
| adapt | 320·390px 재확인. 상단 전체 정지·상태 태그가 화면 안에 있는지 |

**게이트:** Fleet 계약 시험, 브라우저 24셀 재생성, G1. **사람 G3:** 사이트 관제자
관점 8항. 실물 로봇 readback은 이 회차가 올리지 않는다.

## 가로 작업 (모든 표면에 적용)

### G3 사람 평가 프로토콄 (최대 blocker)

D-153 G3 8항은 사람 판정을 요구하지만 프로토콜이 없었다. 이 계획이 첫 프로토콄을
정한다:

- 표면별 8항 시트(정직·증거 상태·색·위계·불가역·어휘·표면 질문·표면 문법)에
  판정자가 **근거 셀(캡처) 또는 코드 위치를 지적**하고 한 줄 판단을 쓴다.
- 판정자: 해당 표면 청중 2인(예: 운용자+설치자). 에이전트 사전 독회는 회차 준비일
  뿐 사람 판정을 대신하지 않는다(D-153 회차 기록의 실태와 같은 선).
- 기록: `docs/validation/uiux-surfaces-<date>/g3-<surface>.md`. 위반 0이어야 표면
  GO 후보가 된다.

### G2 보존형 증거

X:\DevTemp 일회성 캡처는 지워지면 회차가 빈약해진다. 각 표면 회차 종료 시
`matrix.json`과 대표 셀 PNG를 `docs/validation/uiux-surfaces-<date>/`에 보존한다.
D-153.4(보존형 G2)의 실행 규칙이고, 필요 시 회차에서 별도 ADR로 고정한다.

### 기계 검사 편입

`impeccable detect --json <변경 파일>`을 G1 회차에 편입한다(게임 회차에서 이미
사용례 있음). 경고는 정적 오판 여부를 근거와 함께 기록하고 무시를 남긴다.

### 온기 예산 (ADR 후보 A-2)

"따뜻함은 작은 곳에"의 실행 가능 문장: 따뜻함은 색 예산이 아니라 짧은 배려 문구·
장미색 표식 범위(D-277)로 유지한다. P1 크래프트 회차에서 빈 상태·대기 문구에 온기
문장이 필요하면 그 회차에서 ADR로 문구 계약을 제안한다. 운용 화면에 새 따뜻한
색을 추가하는 안은 기각 우선이다.

## 순서와 완료 기준

| 단계 | 표면 | 시작 조건 | 회차 산출 |
|---|---|---|---|
| 1 | P1 역할 웹 | 없음(즉시) | 크래프트 패스 + 브라우저 회귀 초록 + G2 60셀 재생성 + G3 시트(사람) |
| 2 | P2 Fleet | P1 완료 | 패스 + 계약·브라우저 초록 + 24셀 재생성 + G3 시트 |
| 3 | P3 게임 | P2 완료 | 패스 + 시험 초록 + 13셀 재생성 + G3 시트 |
| 4 | P4 얼굴 | Pi 벤치 가용 | 패스 + PIL 초록 + 실물 사진 BENCH + (필요 시) A-1 ADR |
| 5 | P5 문서 | P1–P3 확정 후 | 교정 + docs SOURCE 유지 |
| 6 | 총평 | 전 단계 후 | D-153 표면별 판정 갱신(LOCAL 범위), 잔여 DEVICE/FIELD blocker 명시 |

**완료 기준:** 각 표면이 (a) 크래프트 패스 1회, (b) 유한 검증 통과, (c) G1/G2 현행
셀 통과, (d) 사람 G3 시트 1회 이상을 갖추고, 위반이 0이다. 제품 전체 D-153 판정은
이 계획이 LOCAL 범위에서만 갱신하고, 장치·현장 게이트는 각각 실물 증거가 도착할 때
별도로 올린다. 어느 표면의 LOCAL 성공도 실물 수용으로 합치지 않는다.

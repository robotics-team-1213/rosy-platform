# 일정 시간 연속 점등으로 로봇 식별

사용자 결정: 점멸 대신 일정 시간 조명을 켜고, 신원을 잃으면 주기적으로 다시 식별한다.

기존 CORE 요청·rosy-face 램프 소유 경로를 쓴다. 새 API나 의존성은 없다. 기존 3초 제한 안에서 처음 1초는 꺼짐 기준이고 다음 2초는 연속 점등이다. 긴 점등을 위한 시간 제한 확장과 별도 설정은 추가하지 않는다. 고장·E-Stop·주의 표시의 거절과 선점은 그대로다.

Vision은 여러 익명 로봇 중 끊기지 않은 한 트랙의 꺼짐→1초 이상 연속 켜짐→꺼짐을 확인한다. 여러 트랙이 같은 증거를 보이면 거절한다. 정적 파랑·짧은 반짝임·트랙 가림은 확정하지 않는다. 이전 로봇의 점멸과 단일 blob 정색 폴백은 호환한다. 완전한 파랑 전환 증거는 이전 예상 자리 밖에서도 이름을 되찾을 수 있지만, 불완전 정색과 주황의 예상 자리 제한은 유지한다.

미확인 로봇은 익명 blob이 보이면 30초 주기로 재요청한다. 한 source의 파랑 요청은 하나뿐이므로 두 대는 순서대로 처리한다. 마커를 한 번도 못 봤거나 들려 옮겨진 로봇도 포함한다. 확인된 트랙·진행 중 요청·신선하지 않은 상태·E-Stop·주의 표시는 건너뛴다.

LED 좌표는 이름·차로 관찰·표시용이다. 추종 주행용 지도 기준점과 방향을 자동으로 확정하지 않는다(D-472 부록 3). 로봇 payload와 Fleet/Vision 모두 적용한 뒤 실제 천장 영상에서 두 대 식별, 재식별 주기, 겹침 거절을 검증해야 한다. 코드 테스트는 현장 수용을 대신하지 않는다.

기존 [운영 구조](2026-10-20-operator-ai-operations.md)의 후속 작업이다. 실행 위치와 보호 설치 절차는 [운영 안내](../../operations/fleet/docs/operator-assistant.md)가 소유한다. 아래 표는 실제 수용 순서와 남길 증거를 정한다. 새 자연어 실행 권한이나 모델 승격을 부여하지 않는다.

- 현장 이미지의 source commit 태그는 `rosy-site-fleet:cadbfde749be868239f4cd1899c7ad5a2414cf29`이며 Fleet·Vision·프록시가 healthy다. 이미지 태그만으로 전체 실행 바이트 일치를 증명하지 않는다.

## 명령 전처리 후속 설계 — 검토안, 미구현

이 절은 초기 검토 이력이다. 설계 정본은 [D-831 관제 자연어 전처리·명령 후보 검증·토큰 예산](../adr/D-831-operator-command-preprocessing.md)이며, 후속 구현·변경은 ADR의 책임과 수용 기준을 따른다.

사용자 추가 요구는 자연어를 명확한 명령 후보로 바꾸고 토큰을 줄이는 과정이다. 현재 구현의 분류·보호 계약은 유지하며, 아래 변경은 별도 구현·평가 후 승격한다. 형태소 분석기가 LLM 토크나이저를 대신하거나 토큰 감소를 보장하지는 않는다.

### 현재 코드가 하는 일

- `OperatorInput`은 원문 2,000자, 이력 최대 4턴, 사실 최대 64개와 ko/en locale을 제한한다. Fleet은 선택 로봇으로 사실을 좁히고 5초 신선도·권한·응답 후 사실 변화를 확인한다.
- broker는 한 번의 호출, context 8192, 생성 최대 1024와 닫힌 출력 schema를 사용한다. 프롬프트가 부정·인용·가정·불명확한 대상의 분류 규칙을 제시한다.
- 공개 응답은 서버가 검증한 사실로 만든다. CONTROL은 실행 허가가 아니며 좌표 접수는 별도 API에서 `core_common.intent.interpret`와 기존 Task 경로를 사용한다.
- 전용 표기 정규화·형태소 분석·로봇/장소 별칭 해소·자연어 인자 추출·입력 토큰 사전 계산은 없다. 2,000자/65,536바이트 제한을 토큰 예산으로 간주하지 않는다.

### 제안 경계와 처리 순서

1. **입력 보존 — Fleet:** 원문, locale, 요청 ID와 인증 신원을 보존한다. STT 원문과 운영자가 편집해 전송한 문장을 구분한다. 입력에서 사용자 신원·권한을 추출하지 않는다.
2. **표기 정리 — Decision:** 별도 정규화 사본에 NFC·제한된 공백 처리를 적용한다. 부정 어미·조사·인용·숫자 부호·단위와 정확한 식별자는 보존한다. 불용어 삭제나 공격적인 오타 교정으로 의미를 바꾸지 않는다. 정규화 버전을 입력 hash·평가 profile에 결속한다.
3. **대상 해소 — Fleet의 카탈로그 + Decision 해석:** 등록된 로봇·장소 ID와 승인된 별칭만 사용한다. 별칭 충돌, 미등록 이름, 불명확한 지시어는 재질문한다. 근사 일치는 제안만 하고 장치를 자동 선택하지 않는다. 형태소 분석은 필요 시 이름/조사 경계 후보를 돕는 보조 수단이며 실행 승인 근거가 아니다.
4. **명령 후보 — Decision:** 언어 표현을 기존 intent의 동작·대상·목적지·수치/단위로 매핑한다. 현재 Console 출력 schema에는 인자가 없으므로 LLM이 이미 구조화된 이동 명령을 만드는 것으로 설명하지 않는다. 추가 계약이 필요하면 ADR/API 예약·동일 SHA 평가를 먼저 한다. 기존 계약을 복제한 새 실행 DSL은 만들지 않는다.
5. **검증 — Fleet:** 후보의 필수 인자·타입·유한 수치·등록 대상·부정/인용/가정 문맥을 검사한다. 여러 명령·자기 수정·조건문은 첫 단계에서 단일 명령으로 재확인한다. 모델 confidence는 권한이나 수용을 대체하지 않는다.
6. **사람 확인과 접수 — Fleet → CORE:** 대상·동작·인자를 보여주고 명시적 확인을 받는다. 확인 이후에도 현재 권한·카탈로그 버전·관측·승인 만료를 재검사한다. 기존 Task 멱등성·CORE 최종 권한·비상정지 경로를 사용한다.

Console과 Discord는 채널별 인증·원장·응답을 유지하고 공통 의미 해석만 기존 Decision 모듈에 둔다. 두 채널의 신원이나 대화 이력을 섞지 않는다.

### 토큰을 줄이는 순서

- 먼저 실제 `prompt_eval_count`·`eval_count`·지연을 같은 ko/en 사례로 측정한다. 현재 broker는 이 수치를 검사하지만 관제용 사용량 기록은 아직 제공하지 않는다.
- 정형 버튼·기존 구조화 API는 LLM 호출 없이 처리한다. 자연어를 임의 정규식에 맞춰 실행하는 빠른 경로는 추가하지 않는다.
- 선택 대상의 필요한 사실과 관련된 최근 대화만 전달한다. 권한·신선도·사실 근거를 버리는 요약은 하지 않는다. 카탈로그가 너무 크면 조용히 잘라 실행하지 말고 대상을 재질문한다.
- 고정 정책과 대상 카탈로그는 버전/hash로 관리한다. 캐시가 도입되더라도 요청별 인증과 최신 사실·실행 결과를 공유 캐시로 대체하지 않는다.
- 원문이 현재 JSON과 `LATEST USER MESSAGE`에 중복되는 것은 읽기 쉬운 원문을 추가해 실제 ko/en 분류 문제를 해결한 경로다. 중복을 없애려면 같은 독립 suite에서 의미·거절 정확도와 토큰/지연을 비교해야 한다. 절감률을 미리 주장하지 않는다.
- 동작 후보를 확정할 수 없으면 한 번에 부족한 인자만 질문한다. 자동 다중 호출·자동 재시도로 UNKNOWN이나 기존 호출 예산을 우회하지 않는다.

전처리 변경의 수용 사례에는 `보내`, `보내지 마`, `보내지 말라는 뜻이야`, `A 말고 B 상태`, `A를 보내고 B는 보내지 마`, 인용·가정·혼합 언어·잘못 인식한 ID·음수 좌표·단위 변환·별칭 충돌·권한 철회를 포함한다. 같은 입력의 전/후 후보, 거절·재질문, 토큰·지연을 비교하고 의미가 달라진 절감을 채택하지 않는다.

ROSY를 항만 중심으로 가져간다면
2026-10-20 · 현재 저장소 문서와 항만 공식 사례를 바탕으로 한 초기 제안

제 의견은 항만에 집중하는 방향을 검토할 만하다는 것입니다. 우리가 가진 관측·작업 조정·장비 실행·학습의 연결 구조를 활용할 수 있습니다. 다만 첫 제품은 한 운영 주체의 한 구역에서 반복되는 업무 하나로 정하는 편이 좋겠습니다. 현재로서는 ‘제한 구역 순찰·점검 → 이상 증거 확보 → 담당자 확인 → 조치 완료 기록’을 첫 후보로 추천합니다. 실제 고객과 현장 접근 조건이 확인되면 이 우선순위는 바뀔 수 있습니다.

1. 먼저 ‘항만의 누구에게 무엇을 제공하는가’를 정해야 합니다

항만공사 시설 담당자, 터미널 운영사, 물류창고 운영사, 정비업체는 구매 목적과 권한이 다릅니다. 첫 고객은 현장 출입을 허용하고, 반복 업무의 기록을 제공하며, 도입 성과를 평가할 수 있는 담당 조직이어야 합니다.

첫 미팅에서는 다음 네 가지를 확인하면 됩니다.
- 사람이 매일 반복하는 점검 또는 이동 업무는 무엇인가?
- 그중 시간을 많이 쓰거나 위험에 노출되는 구간은 어디인가?
- 로봇·카메라를 설치하고 운용할 권한은 누가 갖는가?
- 어떤 결과를 얼마만큼 개선하면 실제 운영비를 지불할 의사가 있는가?

‘AI 관제 플랫폼’보다 ‘정해진 점검을 빠짐없이 수행하고, 이상이 생겼을 때 위치·사진·시각과 처리 이력을 제공한다’처럼 구매할 결과로 설명하는 편이 좋겠습니다.

2. 첫 업무 후보의 우선순위

첫 후보: 제한 구역 반복 점검
정해진 지점을 순회하며 시설 상태를 촬영하고 담당자가 확인할 증거를 남깁니다. 탐지 대상은 현장에서 실제로 중요한 시각적 이상 한두 가지로 한정합니다. 현재 정상 상태, 과거 기록과의 차이, 확인 필요 상태를 구분하고 근거가 부족하면 판단을 보류합니다. 로봇 이동이 어렵다면 기존 카메라와 작업자 촬영으로 동일한 업무 흐름을 먼저 검증할 수 있습니다.

두 번째 후보: 항만 배후 창고의 정해진 구간 소형 물품 이송
물류창고 파트너와 반복 이송 물량이 이미 확보되어 있다면 이쪽을 먼저 해도 됩니다. 물품 인수·인계, 목적지 점유, 통행 우선순위, 중단·재개를 함께 검증해야 합니다. 현재 팔레타이징과 로봇 미션 구조의 경험을 활용할 여지가 있으나 현장 적합성은 별도 확인이 필요합니다.

후속 후보: 컨테이너 야드 이송과 대형 하역장비 협업
장비 제어 권한, 기존 운영 시스템 연동, 혼재 교통, 안전 검증의 범위가 큽니다. 장비사·운영사와 구체적인 실증 계약이 확보될 때 범위를 정하는 것이 좋겠습니다. 이미 그런 파트너가 있다면 위 우선순위보다 파트너의 실제 문제를 우선해야 합니다.

이 순위는 시장 규모나 수익성을 검증한 결론이 아니라, 현재 구조에서 첫 실증을 완결하기 쉬운 순서에 대한 판단입니다.

3. 현재 구조는 이렇게 활용하면 됩니다

현재 기준은 middleware / operations / learning의 세 파트입니다. 항만을 지원하기 위해 새 최상위 플랫폼을 만들기보다 기존 책임에 필요한 현장 정보를 추가하는 것이 적절합니다.

World: 지금 현장에 대해 무엇을 아는가
현재는 관측·운영자 pin·odom을 통한 현재 상태 projection이 구현 범위입니다. 항만 적용에서는 구역, 설비, 점검 지점, 관측 시각과 출처를 연결할 필요가 있습니다. 이 항만 정보 모델은 추가 설계 대상입니다. 오래된 관측을 현재 정상으로 표시하면 안 됩니다. 행동에 따른 미래 예측은 현재 구현된 기능으로 취급하지 않습니다.

Processes: 어떤 업무를 완료해야 하는가
‘점검 지점 이동 → 관측 → 결과 확인 → 필요 시 담당자 통보 → 완료 확인’ 같은 현장 절차를 표현합니다. 업무 완료는 명령 전송 성공과 구분해야 합니다. 실행 시점에 실제 결과를 누가 확인하고 기록할지도 정해야 합니다.

Fleet: 여러 로봇과 자원을 어떻게 배정하고 조정하는가
현재 원장·수용·배차 책임을 활용합니다. 항만 업무가 요구할 경우 통로·점검 지점·충전 위치 같은 자원의 점유와 해제를 표현합니다. 외부 시스템의 작업 취소나 재전송이 중복 실행을 만들지 않도록 연동 경계를 정해야 합니다.

Decision: 어떤 대응 후보를 제안할 것인가
관측과 제약을 근거로 재관측, 대기, 다른 지점 점검, 사람 확인 요청 등의 후보를 제시합니다. 실행 승인과 장치 제어 권한은 기존 소유자에 둡니다. 공통 상황평가의 최종 소유권은 D-647에서 Proposed이므로, 그것을 확정된 구조로 전제하지 않습니다.

Middleware와 장비 통합: 각 장비에서 어떻게 실행하는가
현재 Base 최종 명령 경로는 CORE가 소유하고, OMX는 별도 joint/action owner를 유지합니다. 항만용 장비를 도입할 때도 해당 장비의 제어기·정지 권한을 명시해야 합니다. 소프트웨어 연결 가능성과 현장 안전 적합성은 각각 검증해야 합니다.

Learning: 어떤 실패를 다음 버전에서 줄일 것인가
점검 영상, 운용자 확인, 개입 이유와 실행 결과를 기존 수집·검수·학습·평가 흐름에 연결합니다. 현장에서 얻은 데이터를 독립 평가에도 남겨 두고, 새 모델은 평가와 배포 관문을 거쳐 적용합니다.

4. 항만에 맞춰 특히 보강할 것

첫째, 공간과 시간입니다. 위치뿐 아니라 진입 금지 구역, 이용 가능한 시간, 관측 유효기간, 위치 불확실성을 업무 조건으로 표현해야 합니다. 통신이 끊기거나 위치 근거가 부족할 때의 정지·대기·복구 정책도 장비와 구역별로 정해야 합니다.

둘째, 외부 시스템과의 책임 경계입니다. 첫 고객이 쓰는 터미널 운영 시스템(TOS), 창고 시스템 또는 정비 시스템 중 필요한 하나부터 연결합니다. 외부 작업 ID, 상태 변경, 취소, 재시도, 완료 근거를 합의하고 누가 최종 기록을 소유하는지 정합니다. 현장 시스템의 교체를 전제로 삼지 않습니다.

셋째, 실제 환경과 장비입니다. 야외라면 우천·염분·조명·노면·통신·대형 차량 혼재가 요구조건에 어떻게 반영되는지 조사해야 합니다. Pinky에서 검증한 구조와 소프트웨어를 재사용할 수 있어도, 항만용 차체와 센서의 적합성은 새로 확인해야 합니다.

넷째, 사건 처리입니다. 이상 탐지 이후 누가 확인하고 조치하며 닫는지까지 업무에 포함해야 합니다. 작업자가 받아들일 수 있는 오탐 수준과 개입 부담이 제품 가치에 직접 영향을 줍니다.

5. 첫 실증은 이렇게 구성하겠습니다

단계 A: 고객 한 곳, 구역 하나, 점검 업무 하나를 정합니다. 기존 수행 시간·빈도·개입·보고 기록을 수집합니다. 로봇이 실제로 필요한지 고정 카메라나 기존 절차 개선과 비교합니다.

단계 B: 판단을 기록하되 운영에는 개입하지 않는 관찰 운용을 합니다. 담당자의 판정과 비교하고 놓친 이상, 불필요한 경보, 관측 불가 상황을 모읍니다.

단계 C: 허용 구역에서 장비 한 대로 전체 업무를 수행합니다. 통신 단절, 경로 차단, 낮은 배터리, 위치 신뢰도 저하, 사람 개입 후 재개를 검증합니다. 현장에 없는 조건을 시뮬레이션 통과만으로 수용하지 않습니다.

단계 D: 사람이 하던 기준선과 비교합니다. 점검 완료율, 누락·오탐, 점검당 소요 시간, 사람 개입 시간, 이상 발견부터 확인까지의 시간, 유지보수 비용을 봅니다. 합격 수치는 고객과 사전에 합의합니다. 결과가 좋으면 지점과 장비 수를 늘리고, 다음 업무로 확장합니다.

조직도 이 실증을 중심으로 묶는 편이 좋겠습니다. 현장 담당자는 접근 권한·절차·합격 기준을, 플랫폼 담당자는 상태·작업·연동을, 로봇 담당자는 장비·이동·정지·복구를, 인지·학습 담당자는 증거·판정·평가를 책임집니다. 작은 팀에서는 겸임하되 책임은 분명히 둡니다.

6. 지금 할 수 있는 주장과 남은 불확실성

현재 구조는 항만 업무를 붙일 수 있는 책임 구분을 제공합니다. 저장소 STATUS.md에는 여러 모듈의 장치·현장 검증이 HOLD/PARKED로 남아 있으며, 항목마다 검증 날짜도 다릅니다. 따라서 이 문서는 항만 현장 투입 가능성이나 현재 장비 상태를 증명하지 않습니다.

로테르담항의 공식 자료는 센서·데이터를 활용한 자산 점검과 지상·수상·수중·공중 무인 시스템의 점검·정비 적용 사례를 설명합니다. 이는 항만 점검이라는 적용 분야의 근거입니다. 우리 제품의 경쟁력, 국내 고객의 구매 의사, ROI를 입증하는 자료는 아닙니다.

제가 먼저 선택할 다음 행동은 ‘실증 가능한 항만 운영 주체를 찾아 반복 점검 업무 하나의 현재 절차와 비용을 함께 확인하는 것’입니다. 그 결과를 바탕으로 필요한 World 정보, 작업 절차, 장비와 연동 범위를 정하면 됩니다.

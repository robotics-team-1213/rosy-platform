## D-477 현장 LAN 밖 팀 협업 접속은 Tailscale tailnet으로 연다 — 전송 계층만 추가하고 SSH·콘솔 권한은 그대로

**Status:** Accepted (2026-10-06, 사용자 결정: 4명 팀 협업 원격 접속·비상업 확인·개발 기기 1대 우선; 구현·DEVICE/FIELD 별도).

잇는 결정:
- D-418: 로봇 SSH 세 갈(화면 코드 등록·임시 비밀번호·팀 키). VPN을 "범위 밖, 별도로 붙을 수 있다"로 남겨 둔 자리가 이 ADR이다.
- D-452: LAN 밖 대상은 승인 directory와 정상 DNS/VPN 주소로 찾는다.
- D-434: site PC와 model PC 역할 분리. 두 PC는 이미 한 tailnet으로 이어져 있다(검증 기록의 별칭 `rosy-site-pc-ts`).
- D-276: site 콘솔 per-principal 계정·역할. D-193: LCD 일회용 로그인 코드.
- D-154: 공용 이미지 + SD 개인화. D-412: 로봇 자동 업데이트. D-226: 공개 저장소 배치 규칙.

### Context

- 팀은 4명이고 현장 LAN 밖에서도 함께 작업해야 한다. 사용자가 팀 규모 4명, 비상업 용도, 개발 기기 1대부터를 확인했다(2026-10-06).
- model PC·site PC는 이미 한 tailnet 위에서 쓰인다. 로봇은 현장 사설망 안에서만 접근할 수 있다.
- 주소 드리프트는 실손해였다. 2026-10-01 사이트 대역 재번호 때 IP로 고정한 `known_hosts`가 깨졌고(D-373, D-370), D-452는 주소 대신 신원으로 대상을 찾도록 방향을 정했다.
- D-418의 세 갈은 모두 "로봇에 도달할 수 있다"를 전제한다. 임시 비밀번호 drop-in은 RFC1918(10/8, 172.16/12, 192.168/16)만 매치한다. Tailscale의 CGNAT 100.64.0.0/10은 RFC1918이 아니어서 tailnet 위에서는 이 길이 조용히 적용되지 않는다.
- 관제 콘솔은 신뢰된 LAN의 HTTPS(8443)만 받는다. 포트 포워딩으로 인터넷에 노출하지 않는다(`docs/deployment/raspberry-pi-wifi-image.md`).

### Decision

**1. 기존 tailnet을 팀 망으로 승격한다.**
- 이미 site PC·model PC가 붙어 있는 tailnet에 팀원 4명을 각자 계정으로 초대한다. Personal 플랜(무료, 사용 6명 한계, 비상업 한정)을 쓴다. 4명에 예비 2명 자리가 남는다.
- 로봇이 늘어도 사용자 수는 세지 않는다. 로봇·site PC는 사람 계정이 아니라 태그로 등록한다(2).
- 상업 전환은 tailnet을 다시 만들지 않고 플랜만 올린다. 전환 트리거는 Risks R2에 둔다.

**2. 로봇과 site PC는 tagged resource로 등록한다.**
- 태그(예: `tag:rosy-robot`, `tag:rosy-site-pc`)로 소유한다. 개인 계정 소유 기기가 아니므로 담당자 계정 변동과 무관하다.
- tailscaled는 로봇 이미지에 들어가고(D-154 개인화 단계에서 join), join용 auth key는 D-226에 따라 gitignored `private/`에 둔다. 공개 문서에는 자리표시자만 쓴다. 새 secret 종류이므로 ignore 규칙·추적 템플릿·배치 테스트를 같은 변경에 넣는다.
- tailnet ACL은 기본 전체 허용을 그대로 두지 않고, 팀원→기기·site 방향만 열고 기기→팀원 기기 방향은 막는다.

**3. tailnet은 전송 계층으로만 쓴다. SSH 권한 체계는 D-418 그대로다.**
- Tailscale SSH(대리 sshd)는 끈 채로 둔다. 로그인은 기존 plain sshd와 D-418 화면 코드 등록(`dev:<이름>` 라벨·만료·회수), 팀 키 묶음을 그대로 쓴다.
- 이유: Tailscale SSH는 `authorized_keys`·`expiry-time`·라벨 체계를 우회하고, 실제 운용에서 추가 인증 때문에 대기한 관측이 있다(2026-10-04 모델 배달 시도 기록, `docs/validation/`).
- `rosy` 계정의 `NOPASSWD sudo`(D-418 §4)도 그대로다. tailnet 안팎 할 없이 SSH 접속은 root다.

**4. 임시 비밀번호(D-418 §2)는 현장 LAN 전용으로 유지한다.**
- Match 대역에 CGNAT 100.64.0.0/10을 추가하지 않는다. tailnet 안에서는 키 경로(등록·팀 키)만 쓴다.
- 키 없는 접속 표면이 tailnet 전체로 넓어지는 것을 막는다. 현장에서 급할 때의 보험 길은 RFC1918에서만 작동한다.

**5. 관제 콘솔 원격 접속은 site 방화벽의 인터페이스 허용에 `tailscale0`을 추가한다.**
- 콘솔 권한·TLS·per-user 계정은 D-276 그대로다. 브라우저만 있으면 되는 팀원은 SSH 없이 여기서 작업한다.
- 포트 포워딩·공인 노출은 하지 않는다. 신뢰된 LAN 원칙을 tailnet 인터페이스로 확장할 뿐이다.

**6. LAN 밖 주소는 MagicDNS 이름으로 식별한다.**
- D-452의 "다른 망은 승인 directory와 정상 DNS/VPN 주소" 자리에 MagicDNS 이름이 들어간다. IP 고정으로 인한 주소 드리프트 실패 클래스가 사라진다.
- 실제 tailnet 이름·주소는 `private/`에 두고 공개 문서에는 자리표시자를 쓴다(D-226).

**7. 도입 순서는 개발 기기 1대부터다.**
- (1) 로봇 이미지·개인화에 tailscaled 추가 → (2) 개발 기기 1대 join → (3) 자동 업데이트(D-412) 뒤에도 유닛이 살아 있는지, `rosy-network`·host-agent와 충돌이 없는지 확인 → (4) site 방화벽 `tailscale0` 추가와 팀원 초대 → (5) 검증 뒤 전 기기 확대.
- 기기 쌍둥이(twin)로 join·이름 해석 흐름을 먼저 확인할 수 있다.
- 이 ADR은 결정 기록이며 구현 커밋·장치 검증·현장 수용과 분리된다.

### Alternatives

- **site PC에 subnet router만 두고 로봇은 직접 가입하지 않음.** 현장 망 밖(개발 실·집)에서 로봇에 닿지 못하고 기기별 접근 제어도 어렵다. 기각.
- **Tailscale SSH 켜기.** D-418 체계를 우회하고 운용 관측(추가 인증 대기)도 나쁘다. 기각.
- **임시 비밀번호 Match에 CGNAT 추가.** 키 없는 root 접속 표면이 tailnet 전체로 넓어진다. 기각.
- **SSH 사이트 CA.** D-418이 "로봇과 사람이 늘면" 후속으로 둔 길이다. 4명에는 과하다. 유지(후속).
- **인터넷 직접 노출(포트 포워딩).** 기존 배포 문서가 이미 금지한다. 기각.

### Consequences

- 팀원 4명이 현장 밖에서 콘솔(브라우저)과 SSH(키 보유자만)를 함께 쓸 수 있다. 콘솔은 설치가 필요 없다.
- 로봇 이미지에 새 systemd 유닛(tailscaled)과 의존성이 들어간다. 이미지 빌드·자동 업데이트 payload에 반영해야 한다.
- tailnet 계정 초대·해지가 새 운영 책무가 된다. 팀원 해지는 SSH 키 라벨 회수(D-418)와 함께 본다.
- Tailscale은 외부 서비스다. 제어 서버 장애 시 기존 direct 연결은 유지되지만 새 연결 수립이 느려질 수 있다. 현장 LAN 안의 기존 경로(mDNS·사설망)는 그대로 살아 있으므로 tailnet은 보완 경로다.

### Risks

- **R1. tailnet 계정 유출.** 도달성만 생긴다. SSH는 여전히 D-418 키가, 콘솔은 D-276 계정이 각각 필요한 2단계 구조 그대로다.
- **R2. 플랜 조건 변화(비상업 한정).** Rosy가 상업으로 전환되면 Standard로 올린다. tailnet 재구성 없이 승격된다. 이것이 전환 트리거다.
- **R3. 로봇 이미지 안정성.** 새 데몬의 부팅·메모리·자동 업데이트 충돌. 개발 기기 1대 선행 검증으로 완화한다.
- **R4. auth key 노출.** D-226 배치 규칙과 배치 테스트로 저장소 노출을 막는다.

### Validation

- TWIN: tailscaled join, 태그 부여, MagicDNS 이름 해석.
- HOST: 등록 도구가 tailnet 주소로 동작(`known_hosts` 고정 유지), site 방화벽 `tailscale0` 규칙, 문서 배치 테스트.
- DEVICE: 개발 기기 1대에서 tailnet SSH·콘솔, 자동 업데이트·재부팅 뒤에도 재가입 없이 연결.
- FIELD: 현장 수용은 별도.

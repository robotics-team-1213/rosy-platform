## D-933 공급암 S 셀은 면마다 그린 지도 대신 카메라 모델 하나와 인쇄 마커로 좌표를 잡는다

**Status:** Proposed (2026-10-30). 설계만 정한다. 구현, 인쇄물 부착, 실물 정확도 수용은 별도다.

### Context

위 카메라 픽셀을 팔 좌표로 바꾸는 지금 방법은 면마다 따로 맞춘 affine 지도다(`cell_calibration.fit`).

- 점은 집게 표시 약 11개로 모은다(`cell_pipeline.coarse_map`, `cell_calibrate.remap`).
- 높이는 핀홀 시차 근사(`cal.parallax`, `cameras.top.height_m`, `center_px`)로 넣는다.
- 오차는 평균 6.3 mm, 최대 13.6 mm다(leave-one-out). 손가락 여유 16 mm 안에 이 오차와 팔 처짐, 높이 시차가 함께 들어가야 한다.
- 카메라나 면, 핑키가 움직이면 그 면의 지도를 다시 만들어야 한다. 2026-10-28에는 카메라가 7도, 20~45 px 돌아 지도가 무효가 됐다. 10-29~30에는 핑키가 45 px 움직여 놓을 자리가 로봇 몸체 위에 떨어졌다.

사용자 요구(2026-10-30)는 이렇다. 좌표가 움직여도, 다른 곳에서도, 지금 처리한 것들이 문제없이 되어야 한다. 깊이나 좌표 체계를 미리 그려 두고, 점을 찍는 보정을 쓴다.

이미 있는 것:

- `cell_checkerboard.py`: 내부 파라미터 `calibrateCamera`, ChArUco 판과 검출, `solvePnP`, `pixel_to_plane`(왜곡을 펴고 광선과 `z = surface_z`의 교점). 아직 쓰는 곳이 없다.
- `cell_surface.py`: 면 높이를 터치로 잰다.
- `cell_marks.py`: 그리퍼 ArUco 검출.
- `cell_site_track.py`: 이미지 특징으로 움직인 핑키를 따라간다.
- Fleet Cell 화면의 "보정 인쇄물": 실제 크기 벡터 PDF.

관련 ADR: D-633(실측 카메라 보정), D-775(보정의 승인·저장·적용·무효화는 목적별 기존 소유자), D-457(마커 우선, 마커 없는 대안), D-794(top은 작업대 고정, front는 손목), D-904(공급암 S 파이프라인), D-911(작업 범위 게이트), D-931(동작 전 판정).

### Decision

1. **고정 카메라마다 카메라 모델 하나**: 내부 파라미터 `K`와 왜곡 계수, 팔 베이스 기준 자세 `T_base_cam`.
   - 내부 파라미터는 ChArUco 한 장으로 한 번 잰다.
     - A4, 7×10칸, 칸 20 mm, 마커 15 mm, `DICT_4X4_50` ID 0~34
     - 판을 20~40도 기울여 화면 구석까지 25~30장
     - 왜곡은 k1, k2, p1, p2(k3 고정)
     - 합격 기준은 재투영 RMS 0.5 px 이하
   - 해상도나 초점이 바뀌면 다시 잰다. 노출은 기하에 영향이 없다.
2. **카메라와 팔 사이**:
   - 팔 베이스 판에 고정 마커 2개를 붙이고 매 실행 `solvePnP`로 `T_base_cam`을 구한다.
   - 처음 설치와 검증에는 그리퍼 상면 마커(20 mm, ID 0)를 정기구학 점 12~15개(높이 섞음)에서 찍는다.
   - 5자유도 팔의 `calibrateHandEye`는 회전 다양성이 부족해 쓰지 않는다.
3. **높이는 이미지가 아니라 터치로 잰다**: 650 mm에서 1 mm 높이 차이는 0.15 % 배율 차이뿐이다. 면 높이는 `cell_surface`(현장 코드의 `touch_survey` 포함)로 재고, 픽셀은 그 높이의 평면과 만나는 광선으로 바꾼다.
4. **움직이는 면과 로봇은 마커 묶음으로 매번 다시 찾는다**:
   - 바닥/보드, 컨베이어, 핑키 트레이에 25 mm 마커(ID 35~48)를 면마다 3~4개 붙인다. 서로 150 mm 이상 떨어뜨리고 한 줄에 두지 않는다.
   - 모서리를 모두 묶어 `solvePnP`로 면 자세를 푼다. 마커 하나로는 기울기가 흔들리고 평면 뒤집힘이 생긴다.
   - 마커가 안 보이면 지금의 특징 추적(`cell_site_track`)으로 물러나고, 그것도 안 되면 거부한다.
   - 마커 이름, ID, 면 위 위치는 데이터로 둔다.
5. **이음매는 하나**: `cell_observe.predicted_pixel`과 `to_arm`의 서명을 그대로 둔다. 보정 파일에 카메라 기록이 있으면 안에서 모델(`project`, `pixel_to_plane`)을 쓴다. `pixel_fn`을 쓰는 곳(`cell_finger_room`, `cell_place_fit`, `cell_site_track`)은 바꾸지 않는다. 면 지도 생성기(`coarse_map`, `remap`, `pivot_calibrate`)는 모델과의 잔차 검사로 바꾸거나 은퇴한다.
6. **소유와 무효화는 D-775를 따른다**:
   - 카메라 모델은 `cell_calibration` 파일의 카메라 기록으로 저장한다.
   - `cell_preflight`의 카메라 이동 검사가 기준을 넘으면 무효로 보고, 베이스 마커로 자세만 다시 푼다.
7. **인쇄물은 ROSY에서 낸다**: Fleet Cell 화면 "보정 인쇄물"에 ChArUco 판과 면 마커 묶음 PDF를 더한다. 생성기는 이미 `DICT_4X4_50` 비트표를 가진다. 오검출이 보이면 AprilTag 36h11(30 mm 이상)로 옮긴다.

### Consequences

- 카메라, 핑키, 면이 움직여도 지도를 다시 그리지 않는다. 마커로 다시 풀거나 거부한다.
- 같은 인쇄물과 같은 리비전(D-932)이면 다른 셀에서도 같은 절차로 좌표가 선다.
- 사람이 할 일: ChArUco와 면 마커를 무광지에 100 %로 인쇄하고, 50 mm 막대를 자로 확인하고, 단단한 판에 붙여 놓는다. 그리퍼 마커를 붙인다. ChArUco 판을 기울여 들어 준다.
- 위험:
  - 낮은 해밍거리 사전의 오검출
  - 기울이지 않은 촬영으로 초점거리 퇴화
  - 판의 휨
  - 팔 백래시(수 mm)가 베이스 자세 검증의 하한
- 정확도 목표(면 위 평균 3 mm 이하)는 실측으로 수용한다. 지금 지도(6.3/13.6 mm)보다 나빠지면 채택하지 않는다.
- 근거 자료: `Rosy/docs/research/2026-10-30-arm-s-grid-markers.md`(방식 비교, OpenCV 4.12 API 확인, 1.1 px/mm 합성 검출 20/20).

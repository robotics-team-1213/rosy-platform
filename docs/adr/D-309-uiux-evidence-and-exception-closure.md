## D-309 UI/UX의 프론트·백엔드 책임과 시간·예외·안전 증거를 분리한다

**Status:** Accepted (2026-09-27, 실행 기준). D-153의 네이티브 확인 셀 증거 방법과 색 판정을 아래 범위에서 명확히 한다. 화면별 GO나 장치 수용을 선언하지 않는다.

잇는 결정: [D-153](D-153-ui-ux.md) · [D-218](D-218-web-dialogs-name-the-action.md) · [D-253](D-253-game-board-and-diagnostic-freeze.md) · [D-280](D-280-calm-intelligence-product-design-philosophy.md) · [D-306](D-306-surface-ownership-and-uiux-closure.md). 근거 회차: [2026-09-27 UI/UX](../validation/uiux-surfaces-2026-09-27/README.md).

**Context:** D-306 회차는 Fleet 팔로워의 낮은 송신 빈도를 `지연`이라 부르지만 마지막 송신 후 나이를 제공하지 않고, 게임 보드는 HTTP 200의 마지막 프레임이 언제 생성됐는지 알 수 없다. Fleet 기본 로스터는 정상 로봇도 모두 펼쳐 concept 16 §7.3의 예외 우선 문법에 어긋난다. `/setup`·`/device`는 `SAFE_STOP` 입력이 와도 그 이유와 다음 행동을 표시하지 않는다. D-153의 G2는 불가역 확인의 캡처를 요구하지만 D-218은 확인창을 브라우저/OS가 소유하는 네이티브 `window.confirm`으로 고정했다. 로컬 Playwright 페이지 PNG에 OS 대화상자는 들어오지 않는다. D-153의 따뜻한 색 법칙과 D-280이 허용한 게임 공의 초점색도 적용 범위를 구분해야 한다. 이 불일치와 누락을 화면만 꾸며 덮으면 근거 없는 `fresh`와 장치 정지 완료를 만들게 된다.

현재 경로 대조: CORE는 `/api/v1/ui/surfaces/{surface}`의 역할·capability로 패널 매니페스트를 만들고 API에서 권한과 안전을 집행한다. `src/hmi/dashboard/shell`은 그 매니페스트의 슬롯·포커스·상태를 표시한다. Fleet 서버는 `/api/fleet/formation`과 목표·정지 API를 소유하지만 `map-view.js`가 릴레이 `Hz`와 나이로 지연을 직접 판정한다. 게임 호스트는 `/overlay.json`의 경기 데이터를 만들지만 보드는 응답의 신선도를 판단할 근거가 없다. 이 두 화면은 concept 16 §5의 **증거 판정은 서버, 클라이언트는 표시** 원칙과 아직 맞지 않는다.

**책임 표:**

| 경계 | 백엔드/호스트가 확정 | 프론트/렌더러가 소유 | 넘지 않는 선 |
|---|---|---|---|
| CORE 역할 화면 | 인증·역할·capability·패널 매니페스트, 값별 `evidence`와 임계, `SAFE_STOP`, 명령 허용/거부와 readback | `/console`·`/setup`·`/device`의 정보 순서, 폼·포커스, 상태/사유/결과 문구, 선제적 비활성 | 숨긴 버튼은 보안 집행이 아니고 POST 접수는 장치 적용 완료가 아니다 |
| Fleet 관제 | 로봇 상태 gather, 릴레이 계측·증거 판정, 사이트 권한, 목표/취소/정지 수용·결과 | 예외 우선 정렬·접힘, 지도·목록 연결, 키보드 목표 선택과 확인, 서버 판정/나이 표시 | UI는 `Hz`에서 지연을 재판정하거나 정지 요청을 물리 정지로 부르지 않는다 |
| 게임 호스트 보드 | 경기 상태·점수·관측 출처, 마지막 보드 갱신 시각과 신선도, `/stop` 접수 | 피치·점수·유실·지연의 가시화, Space/버튼 입력, 실패 후 포커스와 재시도 | HTTP 200을 양쪽 로봇의 물리 정지로 해석하지 않는다 |
| 얼굴 LCD | CORE/부팅 서비스가 상태와 만료 시간을 제공 | `src/hmi/face`가 320×240 의도·주의·위험을 그려 카드 만료 후 의도로 복귀 | PIL/호스트 PNG는 Pi 폰트·실물 판독을 증명하지 않는다 |
| 공통 UI | API·계약의 정본이 아니다 | `src/hmi/web`은 토큰·버튼·증거 accessor만 공유, 각 표면은 배치와 문구를 소유 | 공통 카드 레이아웃으로 표면 질문을 덮지 않는다 |

**Decision:**

**구조 재점검 결과:** CORE의 `ui_manifest.py`는 역할·capability·inventory로 화면 구성을 정하고, `navigation.py`는 operator 권한·capability·실행 모드를 검사한다. Fleet의 `app.py`는 사이트 인증과 작업 대기열 디스패치를 소유한다. 화면의 버튼 비활성화는 이 서버 검사를 대신할 수 없다. 실제 코드에서 Fleet 디스패처는 `safety.estop`이 없는 상태를 `not ...get("estop")`으로 가용하다고 판단했다. 사이트 서버는 `estop is False`가 명시된 로봇만 작업을 배정해야 한다. CORE의 독립적인 이동 명령 검사는 그대로 유지하고, Fleet의 가용성 판단과 CORE의 최종 명령 허용을 각각 검증한다.

**경계 검사 순서:** (1) CORE/Fleet가 신원·권한·capability·안전·증거 시각을 판정한다. (2) 프론트엔드는 판정 결과와 이유를 표시하고 입력·초점·접근성을 담당한다. (3) 명령 접수, 실행 ACK, 상태 readback, 물리 결과는 서로 다른 단계로 기록한다. 공용 UI 컴포넌트는 토큰·상태 표시 패턴을 공유하되 정책을 재계산하지 않는다.

1. **나이와 판정은 Fleet 서버가 소유한다.** 릴레이는 팔로워별 마지막 *송신 완료* 후 경과 시간 `follower_last_tx_age_s`(초, 송신 기록이 없으면 `null`)를 `RelayStats`에 더한다. Fleet 서버는 기존 리더 수신 나이·오류, 팔로워 연결·송신 Hz·마지막 송신 나이와 임계값을 이용해 로봇별 `stream_evidence` (`fresh`/`delayed`/`disconnected`/`unavailable`, `age_s`, `reason`, `stale_after_s`)를 `/api/fleet/formation`에 내보낸다. 이 판정은 Fleet 릴레이의 송수신 근거이며 팔로워의 수신·실행·물리 추종 readback이 아니다. `map-view.js`의 임계·상태 재판정은 제거하고 서버 판정과 나이만 표시한다. 나이가 없으면 `송신 시각 없음`이라 말한다. 끊김·오류는 지연보다 우선한다.
2. **게임 보드 신선도는 호스트가 확정한다.** 호스트는 실제 경기 틱의 마지막 보드 갱신 시각을 UTC `generated_at`으로 찍고 같은 페이로드를 재전송할 때 갱신하지 않는다. `/overlay.json` 응답은 호스트 시계로 계산한 `age_s`, `stale_after_s`, `evidence`를 함께 보낸다. 브라우저는 `evidence=delayed`면 `지연 · 마지막 생성 N초 전`, 시각/판정이 없으면 `시각 정보 없음`으로 표시하고 자체 임계값으로 `fresh`를 만들지 않는다. HTTP 실패는 별도 화면 전송 오류이며 per-value `disconnected`와 혼동하지 않는다. 경기 `hold`와 CORE SAFE_STOP도 다른 상태다. 생성 시각은 천장 카메라의 노출 시각이나 로봇 실행 증거가 아니다.
3. **Fleet 기본 목록은 개입할 로봇부터 보여준다.** 오프라인, 오류, 안전 미확인·E-STOP, 대기/양보, 릴레이 지연·끊김, 선택된 목표 로봇은 기본 예외 목록에 남긴다. 정상 로봇은 기본 목록에서 접되 `전체 로봇 보기`로 언제든 열 수 있고 키보드로 로봇을 고른 뒤 목표를 지정할 수 있다. 접힌 정상 수와 전체 수를 문장으로 표시한다. 예외가 없어도 빈 화면 대신 `개입할 로봇 없음`과 전체 목록 진입을 남긴다. 지도에는 모든 로봇을 표시하고, 전체 목록에서 선택한 로봇은 목록을 다시 접어도 대상·좌표·확인을 볼 수 있게 남긴다. 정상 카드의 경보색 경계는 없애고, 지도 내 로봇 식별색과 작은 ROSY 브랜드색은 경보와 별개의 데이터/브랜드 색으로만 유지한다.
4. **경기 공 색과 위험색을 분리한다.** D-280이 지정한 공의 따뜻한 초점색은 경기장 안의 단일 데이터 표식 예외다. 홈/원정 이름·점수의 따뜻한 장식색은 없애고 텍스트·위치로 구분한다. 유실·정지 실패의 위험색과 공 색은 같은 의미로 읽히지 않게 형태/라벨을 함께 쓴다. 이 결정을 D-153 G3 색 항목의 해당 표면 해석으로 기록한다.
5. **절차 화면은 안전 정지를 명시한다.** `/setup`과 `/device`는 현재 CORE `mode=SAFE_STOP`을 읽으면 상단 절차 상태 영역에 `안전 정지`와 관측 근거·다음 행동을 표시한다. 로봇 운동을 시작하는 조작은 기존 capability·서버 권한 외에 안전 정지 중에도 비활성 사유를 제공한다. 네트워크 조회, 로그, 정비 읽기와 상단 E-stop 접근은 유지한다. `SAFE_STOP`이 사라졌다는 UI 변화만으로 물리 정지 해제나 재출발을 주장하지 않는다.
6. **네이티브 확인의 G2 증거는 이벤트 기록이다.** D-153의 `window.confirm` 셀은 D-218이 소유한 OS 크롬의 픽셀 PNG 대신, 호출 버튼과 대상이 보이는 페이지 캡처, 브라우저 dialog 이벤트의 정확한 문구, 취소 시 API 0회, 승인 시 단일 요청·서버 응답의 재현 가능한 기록으로 채운다. 확인창 자체의 OS별 외형은 제품 UI 판정 대상이 아니다. 버튼의 위험 시각 범주·키보드 진입·복귀는 페이지에서 평가한다. 이 규칙은 커스텀 확인창 신설 허가가 아니다.
7. **승격은 표면별이다.** 각 소유 표면의 G1, 선언한 G2 셀, G3 8항 위반 0을 다시 판정한다. LOCAL 합격은 화면 경로 증거일 뿐이다. LCD의 Pi 글꼴·거리/각도/조도·카드 만료, 로봇/게임 정지 및 Fleet 목표의 물리 readback, 사이트 운영 판단은 BENCH/DEVICE/FIELD 회차가 올 때까지 HOLD다. 레거시 sensing 진단은 D-253/D-266에 따라 PARKED다.

**Alternatives:** UI에서 `Hz`를 나이로 추정하면 마지막 송신 시각과 주기를 혼동한다. 모든 로봇을 기본 목록에 계속 두면 예외 우선 질문을 풀지 못한다. 전체 목록을 제거하면 정상 로봇의 수동 목표 지정이 사라진다. 네이티브 확인을 커스텀 모달로 바꾸면 D-218의 브라우저 접근성 계약을 되돌린다. LOCAL 캡처로 실물 LCD·정지를 GO로 올리는 안은 D-153의 증거 계층을 깨뜨린다.

**Consequences / rollback:** Fleet 릴레이 상태의 추가 필드는 과거 소비자가 무시할 수 있는 부가 읽기값이지만, 필드가 없는 이전 서버는 `시각 없음`으로 표시한다. 게임 페이로드의 생성 시각도 과거 fixture에서 없을 수 있으며 화면은 fail closed 한다. 예외 목록의 접힘은 탐색 동작을 바꾸므로 1920/390/320px과 키보드·포커스·목표 확인을 다시 찍는다. 단계별 코드 커밋은 Fleet 계측/목록, 게임, 역할 화면 단위로 되돌린다. 문서 기준을 되돌릴 때는 이 ADR을 고쳐 지우지 않고 새 ADR로 대체한다.

**Validation:** [D-309 실행 계획](../plans/2026-09-27-uiux-evidence-exception-closure.md)의 실패 재현→수정→LOCAL 회귀→표면 카드 갱신 순서. API·증거 필드가 바뀌는 단계는 해당 서버 시험과 클라이언트 브라우저 시험을 함께 실행하고, 코드 없이 결정만 쓴 단계는 GO로 세지 않는다.

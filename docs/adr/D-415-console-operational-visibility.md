## D-415 관제 콘솔 운용 가시성 — 로그 뷰어·진단 패널·빈 상태 안내

**Status:** Accepted (2026-10-02, 사용자 지시 — "로그도 볼 수 있게, 디버그에 대해서도 생각할 수 있게").

이은 결정: [D-280](D-280-calm-intelligence-product-design-philosophy.md) · [D-410](D-410-console-operate-and-install-documents.md) · [D-414](D-414-console-direct-action-and-discovery-cards.md).

### Context

2026-10-02 회차 계측: 운용 문서의 `#log`가 21px(1줄)로 사실상 안 보이고, 신호등 패널이
제목만 40px로 죽은 공간이며, 디버그·진단 정보를 볼 패널이 아예 없다. 사용자 지시:
"로그나 이런것도 볼 수 있게 하고 디버그에 대한 부분도 생각할 수 있게 개선해라."

### Decision — 네 단계

1. **로그 뷰어** — `#log`가 스캔 대상이 되는 패널이다:
   - 기본 높이 8줄(`min-height`), 펼치면 24줄(`details` 토글)
   - "지우기" 버튼(quiet, 실제 지움)
   - 수준 색: `good`/`bad` 클래스가 이미 있으니 그대로 쓴다
   - 상한 40줄 → 120줄(LOG_MAX)

2. **진단 패널** — 운용 문서 ops 블록 맨 아래 접힌 `<details id="console-diagnostics">`
   "진단":
   - 상태 갱신 주기(마지막 성공 시각, 현재 상태)
   - 로봇별 마지막 오류(robot.error가 있으면 표시)
   - 발견 검색기 상태(운용 문서에서도 보임)
   - 관제 API 응답 상태(어떤 경로가 404/503인지 — poll-gate 상태)

3. **신호등 빈 상태** — 카드가 0일 때 "설정된 신호등이 없습니다" 한 줄(ui-empty 규칙).

4. **카메라 프리뷰** — 운용 문서의 카메라 구역이 "인증 대기"로 공허하지 않게:
   - 프레임 영역에 마지막 영상 시각 표시
   - 인증 안 됐으면 로그인 안내 문장으로 바로 연결

### 실행 순서

1 → 2 → 3 → 4. 각 단계마다 브라우저 검증 + 계측 시험.

### Alternatives

- **별도 디버그 표면(/console/debug)**: 운용자가 디버깅 중에도 운용 화면을 떠나고 싶지
  않다. 접힌 details로 같은 문서에 둔다. 거절.
- **로그를 WebSocket 스트림으로**: 아직 백엔드에 로그 스트림 엔드포인트가 없다.
  v1은 폴링이 만드는 클라이언트측 이벤트만 보여준다. 백엔드 로그는 다음 회차.

### Consequences

운용자가 "왜 안 되지?"라고 물을 때 같은 화면에서 답을 찾을 수 있다. 로그가 안 보여서
놓치는 이벤트가 사라진다. 진단 패널은 기본 접혀 있어 정상 운용의 조용함을 해치지 않는다.

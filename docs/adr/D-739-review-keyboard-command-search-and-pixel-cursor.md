# D-739 검수 앱의 기능 검색과 원본 좌표 커서는 모든 화면의 키보드 작업을 연결한다

**Status:** Accepted (2026-10-13, 사용자 요청: 단축키로 모든 기능이 동작하도록 한다. 구현·호스트/브라우저 확인·운영 적용·사람 라벨 수용은 별도다).

### Context

D-538의 승인·클래스·사진 이동 단축키는 유지하지만, 초안 비교·부분 보완·재검수·자료 준비·입력/접힌 기록에는 공통 키보드 진입점이 없다. 픽셀의 점·브러시·다각형은 포인터에 의존한다. 모든 버튼에 암기할 단일 키를 추가하면 클래스 키나 텍스트 입력과 충돌한다.

### Decision

1. **기능 검색:** 객체·픽셀·작업 목록·자료 등록에서 `Ctrl+K`/`Meta+K`로 현재 화면의 버튼·링크·입력·접힌 항목·캔버스를 검색한다. 방향키와 Enter로 선택하고 Esc로 닫는다. 검색창에 포커스를 두고 닫으면 기존 포커스를 복원한다. 기존 공용 `openLiveDialog`와 `ui-*`, 토큰을 사용한다.
2. **실제 조작을 재사용:** 선택은 기존 요소를 클릭하거나 입력에 포커스를 준다. 필드의 원래 change/검증, 버튼의 disabled/이유, 교체/삭제 확인, 충돌·원본 준비·승인 조건을 우회하지 않는다. 닫힌 details의 입력은 해당 항목을 열고 포커스를 준다. 열어 둔 동안 대상이 사라지거나 비활성화되면 실행하지 않는다.
3. **자주 쓰는 키:** D-538의 기존 키는 유지한다. `Ctrl+S`는 픽셀 초안 저장, `R`은 최신 내용, `U`는 해당 검수의 재검수, `E`는 승인 자료 준비, 객체 `Insert`는 좌표 박스 추가로 연결한다. 드물거나 확인을 요구하는 동작은 기능 검색을 사용한다. 키 이름/비활성 이유를 검색 결과와 안내에 보여 준다. 텍스트·숫자·select·IME 조합 중에는 작업 키를 실행하지 않는다. 명시적인 기능 검색 키만 입력 중에도 열 수 있다.
4. **원본 픽셀 좌표:** 캔버스에 포커스가 있을 때 `Alt+방향키`로 원본 이미지 기준 한 픽셀, `Alt+Shift+방향키`로 열 픽셀 이동한다. 현재 `(x,y)`와 원본 크기를 보여 준다. Space는 점/다각형 꼭짓점을 추가하며 브러시는 Space를 누른 동안 이동하고 놓을 때 한 획의 초안으로 끝낸다. Esc는 진행 중 획/선택을 취소한다. 기존 Enter 적용·Ctrl+Z 되돌리기·초안 저장을 재사용한다. 이동 모드에서는 Alt+방향키가 보기만 이동하고 칠하지 않는다. 기존 맨 방향키는 사진 이동이다.
5. **데이터 경계:** 좌표 커서/십자선은 표시이며 마스크나 AI 입력이 아니다. 점 32개·다각형 128개·브러시 2048점과 반지름/클래스/원본 범위 검증을 포인터와 공유한다. 좌표 이동·검색·도구 전환 자체는 라벨이나 승인 revision을 바꾸지 않는다. 객체 좌표 수정과 픽셀 저장 방식·독립 승인·255 규칙은 유지한다.
6. **AI 보조:** 기능 검색은 기존 초안 미리보기·255 보완·AI 의견의 표시를 연결할 뿐 새 추론/학습/승격/로봇 권한을 만들지 않는다. 구현 범위와 의미/현재성 제한, 후속 제안은 [AI 검수 보조 조사](../../learning/curation/perception/docs/ai-review-assistance.md)에 분리한다. 실제 원본을 외부 모델로 전송하지 않는다.

### Verification

- 네 화면의 검색 열기·IME/입력·닫기/포커스·링크/필드/접힌 항목 실행.
- 비활성 승인·로딩/충돌·사라진 대상·기존 확인 취소를 우회하지 않음.
- 키보드 점/영역/브러시의 원본 좌표, 경계/확대, 적용·저장·되돌리기·진행 획 취소와 포인터 회귀.
- 실제 사진 독립 복사본에서 데스크톱/좁은 화면과 한글 입력을 확인한다. 호스트/브라우저 성공은 운영 설치·실물 터치·정답 품질·학습 수용을 대신하지 않는다.

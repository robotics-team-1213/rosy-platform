# D-641 운용 화면의 다섯 영역·의미 아이콘·단계별 근거 공개

**Status:** Accepted (2026-10-11)

### Context

D-629와 D-639는 관제 위계와 공용 규격을 정의했다. 그러나 실제 사건 화면은 요약, 과거 관측, AI 참고, 실행 결과, JSON을 한곳에 펼쳐 읽기 부담을 만든다. 개발 연결 배지와 문서 탐색도 업무 영역을 차지한다. 사용자는 2026-10-11 화면을 제시하며 글자를 전부 노출하는 대신 의미 아이콘과 헤더·좌우 사이드바·푸터의 역할을 먼저 설계하고 ADR에 기록하도록 요구했다.

### Decision

1. 운용 웹 화면은 다섯 영역을 구분한다. **헤더**는 제품·사이트 정체성과 전역 알림·접속·비상정지, **좌측 탐색**은 앱/문서 이동, **중앙**은 현재 업무와 주 조작, **우측 맥락**은 현재 상태·개입·결과, **푸터**는 보조 운영정보와 진단 경로를 소유한다. D-540의 현재 시각은 푸터로 옮길 수 있으나 시계를 수신 신선도나 정상 통신 증거로 표시하지 않는다. 고정 푸터로 영상이나 작은 화면의 조작을 가리지 않는다. 모든 역할에 같은 로봇 목록을 복제하지 않는다.
2. Fleet 네 문서는 공통 shell을 쓴다. 관제 중앙은 지도·영상, 오른쪽은 현재 개입과 알림/기록/운영 도구다. Install은 중앙의 설치 단계와 해당 결과, Site-map은 활성/초안·경로·운행, Cell은 준비/컴파일/제안/진행을 유지한다. 문서 내부 작업 단계는 좌측 전역 문서 탐색과 별개다. 좁은 화면은 탐색을 가로 줄로 재배치하고 맥락을 흐름 안에 둔다. 현재 개입의 모바일 우선 노출과 비상정지 접근을 유지한다.
3. 의미 아이콘은 공용 `actionIcon`의 닫힌 이름과 공용 SVG 기하를 사용한다. `fleet`=관제 연결망, `map`=접힌 지도, `install`=장비 설치, `cell`=작업 구역, `notification`=알림 종, `history`=시간 기록, `tools`=운영 설정, `refresh`=다시 조회, `download`=내보내기, `connect`=접속 연결고리다. 기존 아이콘은 재사용하고 실제 견본에서 뜻과 상태를 먼저 확인한다. 화면마다 다른 그림으로 같은 동작을 표현하지 않는다.
4. 전역 탐색·맥락 탭·접속·알림·새로고침·확대·내보내기의 반복 조작은 공용 아이콘을 기본으로 하며 같은 뜻의 글자를 상시 중복하지 않는다. 이름은 접근성 트리와 hover/키보드 focus의 공용 설명에 남긴다. 알림 개수처럼 달라지는 상태 값은 보이는 숫자로 유지한다. SVG는 장식으로 `aria-hidden`이다. 페이지 링크는 `aria-current`, 탭은 `aria-selected`, 토글은 `aria-pressed`로 상태를 표현한다. 색만으로 선택을 표시하지 않는다. 비상정지는 동일한 48/14/12 규격과 보이는 동사를 유지한다. 판단·위험·거절·실행 결과는 필수 문구를 숨기지 않는다.
5. 개발 연결 모드는 기존 D-473의 노출 요구를 유지하는 짧은 전역 경고 표지로 표현한다. 접근성 이름과 설명은 개발 연결의 권한 효과를 명확히 알린다. 장문 정책·토큰·빌드 식별자는 접속/진단을 열었을 때 보여준다. 개발 모드를 정상 운영 상태처럼 보이게 만들지 않는다.
6. 사건은 **한 줄 요약·현재 단계·다음 조치**를 먼저 보여준다. 사건 이력은 기본적으로 접혀 있으며 과거 기록과 현재 개입을 구분한다. 펼친 사건에는 AI 판단, Fleet 결정/전달, CORE 수락/거절/처리 결과를 짧은 역할 행으로 제시한다. 관측 시각·신선도·영상 보존 여부와 사람 검토 상태는 근거 영역에서 확인한다. 원시 필드·JSON·내부 식별자는 별도 진단 disclosure를 열어 확인하며 일반 첫 화면에는 노출하지 않는다.
7. 정보 축약은 증거를 없애지 않는다. AI 제안과 실행 완료, Fleet 전달과 CORE 수락, 읽음과 검토 완료, 과거 영상과 현재 관측을 구분한다. 모르는 값은 미확인으로 남긴다. 검토 저장·내보내기·기존 API·credential·CORE 최종 권한을 유지하며 새 메시지 broker나 권한 경로를 만들지 않는다.
8. 표면은 위치만 소유하고 공용 토큰·버튼·disclosure·아이콘·설명 부품을 덧칠하지 않는다. CSP의 외부 자산/클래스 규칙을 지킨다. 1920×1080, 1366×768, 390×844, 320×568의 실제 네 문서에서 레이아웃·선택 상태·tooltip·키보드·경고·정지 접근·과거/현재 구분을 검증한다. ADR 수용과 소스·원격 시험·CI·서명 설치·실물 수용은 각각 기록한다.

9. 정보 밀도는 글자를 작은 크기로 줄여 확보하지 않는다. 관련 조작을 같은 업무 영역에 묶고, 위치·아이콘·선택 표시·상태의 순서로 문맥을 제공한다. 처음 사용하는 사람도 현재 위치와 다음 조작을 알아볼 수 있도록 생소하거나 위험한 조작에는 짧은 이름을 남긴다. 보충 설명은 공용 tooltip으로 제공하며 마우스 hover와 키보드 focus 모두에서 열리고 Escape로 닫힌다. 조작을 활성화하면 해당 설명을 닫아 다음 조작을 가리지 않으며, focus가 유지된 동안 같은 설명을 바로 다시 열지 않는다. 필수 상태·위험·실패 이유를 tooltip 안에만 넣지 않는다. 모바일에서는 hover 없이도 이름과 조작 맥락을 확인할 수 있어야 한다.

### Consequences

사건 패널의 표시·검토·내보내기는 `operations/ui/console/incident-view.js`가 소유한다. 기존 D-362의 분리 의무를 적용하며 `console.js`의 인증·폴링·명령 권한과 공용 조작 규격은 유지한다. 내부 자산 등록과 설치본 검사도 함께 갱신한다.

기존 토큰과 ES module, static allowlist, 메시지 조회·검토 저장 경로를 재사용한다. 글자가 적다는 것만으로 개선을 선언하지 않으며, 운용자가 현재 상태를 알아보고 다음 업무로 이동할 수 있어야 한다. Pilot 영상/입력과 로봇 검수 등 다른 매체의 고유 작업은 각 역할 계약을 유지한다.

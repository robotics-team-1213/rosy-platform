## D-623 최신 영상과 지도 방향을 함께 보여 주는 복구 문맥

**날짜:** 2026-10-10
**상태:** 구현 — 이동 권한 변경 없음

### 결정

사용자는 Fleet이 지도 방향과 AI 판단으로 복구를 이끌고, 프론트가 전달·CORE 수락·안전 정지 결과를 보여 주며, 카메라 차선 경계가 실제로 변한 경우에만 새 판단을 하도록 요청했다.

1. 지도 방향 재평가는 기존 D-607 `stuck_heading.reassess`를 쓴다. 같은 지도 버전, 신뢰 자세, 촬영/odom 기준, 신선도를 통과한 `heading_review`만 AI case 문맥과 Fleet 막힘 행에 전달한다. 이 값은 회전 허가가 아니다. 실패하면 원인을 표시하고 이전 방향을 재사용하지 않는다.
2. 지도 영상 변환 캐시는 DOM 이미지 객체가 아니라 프레임 전달 객체를 기준으로 갱신한다. 같은 프레임에서 지도만 다시 그리면 캐시를 쓴다. 새 프레임은 새로 변환한다. 영상 다운로드·decode에 걸린 시간도 신선도에서 차감한다.
3. 기존 막힘 증거 API의 기본 동작(사건별 최초 영상 보관)은 유지한다. `live=true`는 현재 RAW front 프레임을 매 요청마다 읽는다. CORE 촬영 시각 또는 보고된 나이·sequence를 유지하고 3초 초과, 미확인 시각, 사건 종료는 표시하지 않는다. 프론트는 2초마다 새 영상을 읽고 3초를 넘기면 지운다. 최초 사건 사진을 현재 위치처럼 표시하지 않는다. 사용자 요청에 따라 D-136 T1/D-577 8의 사건별 한 장 제한을 이 열린 막힘 API의 인증된 단일 JPEG 조회에 한해서 개정한다. 일반 영상 relay/stream 경로는 추가하지 않는다.
4. 프론트는 AI 제안과 별도로 Fleet이 실제 보낸 명령, CORE 수락/거절/응답 불명, 수신 후 동작 상태를 보여 준다. `accepted`는 복구 성공이 아니다.
5. 차선 경계 변화는 새 JPEG·confidence·보정 jitter와 다르다. 기존 D-468 `Corridor.matches`가 자세를 같은 좌표로 옮겨 경계 두 지점을 비교한다(거리 0.015 m, 방향 0.12 rad 기준). CORE는 신선한 ready 기하의 서로 다른 촬영 시각 3개에서 같은 새 경계를 연속 확인한 경우에만 문의용 revision을 올린다. 중복 시각·기하 미확인·epoch/geometry 변경은 변화로 세지 않는다. 현재 `LineStuckStatus.inquiry.lane_boundary {state:unknown|baseline|confirming|confirmed, revision, epoch, source_stamp_ns, geometry_id?, reason?}`를 Fleet이 열린 사건의 최초 문의보다 우선한다. AI 서버는 사건별 처음 한 번 맥락을 확인하고, 이후에는 `confirmed` revision이 바뀐 경우에만 다시 VLM에 문의한다. 기존 장치처럼 경계 상태가 없는 경우에는 같은 사건의 VLM 재문의가 없다. 확인 불가 상태는 사람/CORE 규칙으로 남으며 자동 이동 허가가 아니다. D-595 필드 보정의 고정 quad는 별개이며 차선 변화 신호로 쓰지 않는다.
6. 계속 같은 자리에 있는 복구는 D-610 결과 창과 시도·시간 상한, D-607 `REALIGN` 계약을 따른다. CORE가 현재 센서로 시작 전/진행 중 정지한다. 임의 반복 회전, 안전 정지 후 자동 재무장, 충전 중 이동을 추가하지 않는다. Fleet REALIGN 실행 경로와 장치 수용은 별도 미완료로 표시한다.
7. 모델/전송 실패는 같은 경계 revision에서 최대 3회 재시도한다. 소유자 비활성은 시도를 소비하지 않는다. 성공적으로 전송한 제안만 revision을 소비하고, 실패 3회 이후에는 새 확정 경계까지 VLM 문의를 억제한다. 기존 Fleet 규칙·사람 전달·정지는 계속 동작한다.

### 검증

같은 `<img>`에 새 sequence를 넣은 지도 배경 갱신, 같은 프레임 캐시 재사용, decode 중 만료, 현재 영상 재요청과 사건 사진 보존, 사건 교체/종료 중 응답 폐기, 방향 정보의 API/AI/UI 전달을 원격 테스트한다. D-468 경계 비교와 D-595 고정 quad 시험도 재검증한다. 실제 브라우저·장치 주행 수용은 별도 증거다.

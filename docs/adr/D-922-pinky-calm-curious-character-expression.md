## D-922 Pinky는 차분하고 호기심 많은 동료로 표현하고 방향성 눈인사와 졸린 대기를 연결한다

**Status:** Accepted (2026-10-30, 사용자 성격·상호작용 선택 및 정식 ADR 기록 지시). 표현 경험과 책임 경계에 대한 결정이다. 제품 코드 구현·배포·장치·현장 수용 완료를 뜻하지 않는다.

### Context

현재 CORE는 모드별 기본 표정을 고르고 내비게이션 차단·실패에는 bored를 사용한다. IDLE 300초 후에도 bored가 나온다. 후면 RGB LED는 배터리 경보와 정보 표시를 우선한다. 이 구조만으로는 대상 발견, 정상 정지, 차단, 휴식의 전후 맥락을 일관되게 표현하기 어렵다.

사용자는 상황별 자동 반응과 표정·후면 LED 연동을 선택하고, 하나의 인격체 관점에서 더 토론하기를 요청했다. 이어 「차분하고 호기심 많은 동료」, 사람이 있는 방향을 따라 먼저 보내는 눈인사, 긴 대기에는 「졸린 듯 쉬기」를 선택했다. 무작위 표정 교체보다 관심과 직전 경험이 이어지는 표현으로 구체화한다. 개인별 신원·장기 기억이나 자율적인 신체 추종의 요구로 해석하지 않는다.

### Decision

1. **기본 성격은 차분하고 호기심 많은 동료다.** 작은 관심과 절제된 놀람, 작업 중 집중, 안전한 긴 대기의 편안한 휴식으로 표현한다. 성격을 고르는 새 운용 모드·설정 화면은 이번 범위에 넣지 않는다.
2. **사람을 향해 먼저 눈인사한다.** 유효하고 최신인 관측이 사람의 존재와 방향을 제공할 때 화면의 시선을 해당 방향으로 부드럽게 옮기고 눈인사를 표현한다. 관측이 사라지거나 오래되면 중립으로 돌아간다. 같은 지속 관측에 인사를 반복하지 않는다. 이 결정은 화면 표현이며 몸체 회전·주행 방향 변경·사람 추종 권한을 추가하지 않는다.
3. **긴 일반 대기는 졸린 듯 쉰다.** 눈꺼풀이 내려가고 움직임이 잦아드는 표현을 설계한다. 실제 전원·절전·센서 가동 상태와는 별개다. 차단·고장·비상 정지·관측 누락은 일반 휴식으로 표시하지 않는다. 사람이 관측되거나 작업이 시작되면 해당 상태의 표현으로 돌아가는 것을 설계 목표로 둔다.
4. **현재 상태와 짧은 맥락에서 얼굴·LED 의도를 함께 고른다.** 의미 우선순위는 안전 정지·고장 > 차단·경로 실패 > 짧은 발견·인사 반응 > 현재 작업 > 일반 대기다. 단조 시계에 따른 만료와 관측 등장·소실로 반복 반응을 억제한다. 실제 성공 근거 없이 도착·완료·해결을 표현하지 않는다.
5. **기존 표시·제어 권한이 우선한다.** 안전 카드·CORE 누락·필수 정보·전력·깨움 계약과 배터리 LED 경보의 우선권을 유지한다. 경보의 어두운 점멸 구간에도 감정 색을 섞지 않는다. 표현 정책은 속도·정지 명령을 발행하지 않는다.
6. **기존 모듈에서 확장한다.** ROS-free 표현 정책은 CORE 소유 경로, 관측·시간·서비스 전달은 bridge, 그림과 시선 렌더링은 얼굴 패키지, 후면 RGB 적용은 기존 LED 서비스에 둔다. 새 최상위 파트·별도 감정 서버·두 번째 LCD/LED writer는 만들지 않는다.

### Alternatives

- **종류만 늘리기:** 같은 관측의 반복 놀람, 차단과 휴식의 혼동, 얼굴과 LED의 다른 판단을 남긴다.
- **자유 감정 생성·성격 설정·장기 사람 기억:** 현재 요구를 넘고 감지 사실·표시 우선순위를 검증하기 어렵다.
- **사람 쪽으로 몸체를 돌리기:** 화면 눈인사 요구에 물리 동작 권한을 추가하므로 이 결정에서 채택하지 않는다.

### Consequences

실제 producer가 제공하는 사람 종류·방향·신선도와 정지 이유·운동 관측을 먼저 추적해야 한다. 정보가 부족하면 지원 범위를 명시하고 추측 표현을 하지 않는다. 여러 사람의 관심 순서, 재인사 간격, 긴 대기 진입 시간, 시선 이동량, LED 색·밝기·주기는 미정이다. 1.5초 반응·5초 재반응 간격 등 토론 수치는 확정 계약이 아니다.

정책·bridge·렌더러에 같은 판단을 중복 구현하지 않는다. 새 표정이나 hand-over 필드가 필요하면 허용 목록·생성기·설치·소비자·시험을 한 변경 단위에서 맞추고 기존 계약과의 이행을 기록한다. 단순 표정 확장으로 안전 또는 움직임을 바꾸지 않는다.

### Validation / transition

이번 변경은 문서다. 상세 범위와 후속 수용 기준은 [설계 문서](../plans/2026-10-30-pinky-character-expression-design.md)에 둔다. ADR 본문·색인 일치, 링크·하네스 및 문서 계약을 검증한다. 실제 감지·정책·표정·LED 구현과 원격 회귀, 실물 LCD·후면 LED 수용은 후속 작업이다. Accepted를 구현 또는 장치 GO로 해석하지 않는다.

### 추가 결정 — 미결 세부의 기본값 (2026-10-30)

사용자는 남은 질문의 해결을 위임했다. 앞선 Consequences의 미정 항목은 아래 기본값과 연결된 설계 문서로 닫는다. 이는 사용자가 수치 하나하나를 직접 선택했다는 기록이 아니라, 위임에 따라 정한 설계 결정이다. 원래 성격·표시 권한·안전 경계는 유지한다. 실물 확인 결과에 따른 값 변경은 이유와 근거를 기록한다.

1. **관심 대상을 안정적으로 고른다.** 모든 유효한 사람 관측에 서로 다른 추적 ID가 있으면 현재 대상을 유지하고, 새 선택은 화면 중앙에 가까운 순서, 신뢰도 높은 순서, 작은 추적 ID 순서로 정한다. 최소 3초 동안 대상을 유지하되 관측 소실·안전 선점에는 즉시 해제한다. 한 사람을 계속 보고 있을 때는 인사를 반복하지 않는다. 미인사 대상이 있으면 유지 시간과 전역 반응 간격 뒤 같은 순서로 관심을 나눈다. 영상 크기로 실제 거리를 추정하지 않는다.
2. **추적 ID가 부족하면 무리 단위로 반응한다.** 인위적인 사람 ID나 새 추적기를 만들지 않고 유효한 사람 상자 중심의 신뢰도 가중 평균을 바라본다. 이 경우 무리가 계속 보이면 추가 사람의 진입·재등장을 개별 인사로 판정하지 않는다.
3. **인사는 1.5초, 주행 중에는 0.6초로 제한한다.** 새로운 사람은 0.5초 동안 연속된 최신 관측으로 확인한다. 전역 새 반응 간격은 5초다. 같은 대상은 유효한 관측에서 10초 이상 부재가 확인되고 직전 인사 후 60초가 지난 경우에만 재인사 대상이 된다. 60초 전에 돌아오면 그 재등장 반응을 폐기하고, 계속 보이는 동안 시간이 찼다고 뒤늦게 인사하지 않는다. 다음 재인사는 다시 10초 이상 부재가 확인된 새 재등장에서만 판정한다. 스트림 손실을 부재로 계산하지 않는다. 안전 선점·관측 복구 시 반응을 대기열에 쌓거나 재생하지 않는다.
4. **휴식은 기존 300초 일반 대기 후 시작한다.** 작업 시작·유효한 사람 등장에 휴식에서 빠져나오고, 일반 대기로 돌아온 때부터 다시 센다. 전원 절전·카드 표시 우선권은 그대로다. 안전·차단·실패·관측 누락은 졸린 휴식의 진입 조건이 아니다.
5. **시선은 수평 ±6 px 안에서 0.4초에 걸쳐 움직인다.** 320×240 기준이며 수직 오프셋은 0이다. 기존 자산의 자발적 시선 이동에 더하지 않고 대체한다. 관측이 오래되면 방향 추종을 종료하고 중립으로 복귀한다. 첫 버전은 기존 8종 이름을 유지하고 깜빡임을 넣지 않는다.
6. **후면 LED는 RGB 채널 배율로 낮게 표현한다.** 전역 밝기 서비스를 바꾸지 않는다. 일반 감정 효과는 채널 최대 24/255, 인사 강조는 최대 36/255, 휴식은 최대 8/255로 제한한다. 기본 색·리듬은 설계 표에 정하고, 기존 배터리 경보·정보 표시·안전 표시가 있으면 감정 효과를 전부 양보한다. 물리 밝기와 색 판독은 별도 수용 대상이다.

사람 관측은 기존 검증과 알려진 모델 revision, `person` 신뢰도 0.5 이상, 기존 0.3초 신선도 상한을 재사용한다. 새 API·wire 필드를 이번 문서 변경으로 도입하지 않는다. 감지와 방향성 렌더링의 실제 연결은 미지원 여부까지 확인할 후속 구현 작업이며, 미결된 제품 선택과 구분한다.

# D-926 운용 화면의 읽는 순서·깊이·말의 규칙

**Status:** Accepted (2026-10-30, 사용자 결정). D-641 4항의 "맥락 탭은 아이콘 단독" 부분을 대체한다. 토큰 값·테마·조작 크기(D-629)·정지 계약(D-220)·장미색 범위(D-277)는 그대로다. 화면별 적용은 단계별로 나눠 착지하며, 각 단계의 원격 시험·캡처·사용자 검토는 따로 기록한다.

### Problem

2026-10-30 Fleet 샘플 서버를 운영자로 접속해 1366×768·390×844로 찍은 화면에서 다음이 확인됐다(캡처 목록과 16개 관찰은 작업 공간 계획 `2026-10-30-ui-hierarchy-foundation.md`).

- 토큰은 지켜진다(표면 CSS 원시 색 15개, 글자 크기는 전부 토큰). 그런데 화면은 정돈되어 보이지 않는다.
- 하위 탐색이 있는 지도·Cell 화면이 모든 하위 화면을 한 페이지에 이어 붙인다(지도 3,541px). 탐색이 이동이 아니라 장식이다.
- 앱 바 아래에 소속 없는 둘째 줄이 있고, 학습 정책 승인 화면은 앱 바가 아예 다르다.
- 관제 오른쪽 탭 넷이 아이콘 단독이고 그중 종은 앱 바 알림과 같은 그림이다. 사용자가 둘을 구분하지 못한다.
- 글자 역할 사용이 label 109·micro 32·body 20·title 15회다. 거의 모든 글이 굵은 라벨이라 제목·본문·보조가 갈리지 않는다.
- 운용 화면에 `owner HOLD`, `rig revision`, `receipt SHA-256`, `D-793`, `undefined`가 나온다.

기존 ADR은 값(색·크기·간격)과 자리 치수를 닫았지만, 한 화면에서 무엇이 먼저인지, 한 번에 몇 가지 일을 보이는지, 사용자가 몇 단계 안에 있는지, 어떤 말을 숨기는지는 정하지 않았다.

### Decision

1. **읽는 순서 다섯 층.** 모든 운용 화면은 안전 → 지금 상태 → 할 일 → 근거 → 진단 순서로만 보인다. 흰 채움 주 동작은 화면당 하나다. 위험 채움은 사용자가 지금 할 일이 있는 위험에만 쓰고 원인과 다음 행동을 같은 줄에 쓴다. 진단 층(내부 코드·리비전·해시·ADR 번호)은 기본으로 숨긴다. `undefined`·`null`은 화면 글자가 될 수 없다.
2. **깊이 다섯 단계.** 0 앱(앱 바) · 1 영역(탐색 레일) · 2 화면(하위 탐색 + 본문) · 3 대상(오른쪽 칸 또는 상세 화면) · 4 확인·진단(대화상자·진단 접힘). 깊이마다 자리·면·나가는 법이 하나다. 한 단계 깊어지면 면이 한 단계 솟는다(카드 속 카드 금지). 깊이 2 이상은 경로 줄로 `영역 / 화면 / 대상`을 보인다. 깊이 수는 폭과 무관하다.
3. **하위 탐색은 이동이다.** 하위 탐색을 누르면 본문에 그 화면 하나만 보인다. 한 목록에 다른 층을 섞지 않는다. 모양은 공용 부품 하나다.
4. **접힘은 한 겹, 깊이 4에만.** `details` 안에 `details`를 두지 않는다. 화면의 주된 일을 접어 두지 않는다. 접힘이 셋 이상 필요하면 하위 화면으로 나눈다.
5. **앱 바는 한 줄.** 앱 바 아래에 소속 없는 줄을 두지 않는다. 모든 Fleet 문서는 같은 앱 바와 레일을 쓴다.
6. **본문 탭은 아이콘과 이름을 함께 보인다.** D-641 4항의 맥락 탭 아이콘 단독을 대체한다. 앱 바의 알림·계정 단추만 아이콘 단독 예외이며, 같은 그림을 본문 탭에 다시 쓰지 않는다. 탐색 레일은 D-741대로 아이콘 아래 이름이다.
7. **말의 층.** 화면에서 쓰는 글자 역할은 화면 제목(`--text-title`), 구획 제목, 본문(`--text-body`), 보조(`--text-micro`) 넷이다. `--text-label`은 입력 이름과 칩에만 쓴다. 안내 문장은 구획당 한 문장이고 같은 말은 화면에 한 번만 쓴다. 운용자 말을 쓰고, 바꿀 말이 없는 내부 용어는 진단 층으로 보낸다.
8. **부품 모양 하나씩.** 목록은 공용 목록 행(이름·상태 칩·보조 한 줄·동작)이며 브라우저 기본 점 목록을 쓰지 않는다. 상태 칩은 한 모양에 색만 다르다. 막힌 버튼의 사유는 버튼 아래 한 줄이다. 빈 상태는 한 줄과 다음 동작이다. 파일 입력은 `createFilePicker`다. 칸을 넘는 행은 버그다.

### Verification and recovery

단계마다 같은 페이지를 1366×768·390×844로 다시 찍어 다음을 기록한다: 화면 목적과 상태가 3초 안에 읽히는가, 흰 채움이 하나인가, 위험 옆에 할 일이 있는가, 내부 용어·`undefined`가 보이는가, 하위 탐색이 본문을 바꾸는가, 390에서 본문이 첫 화면 안에서 시작하는가, 칸 넘침이 있는가. 기계로 확인할 수 있는 항목(탭 이름 보임, `undefined` 문자열, 칸 넘침)은 브라우저 시험으로 지킨다. 화면 적용은 단계별 브랜치이므로 한 단계를 되돌려도 앞 단계와 토큰은 영향받지 않는다.

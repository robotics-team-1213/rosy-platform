## D-950 도킹 진입 방향은 후면(후진)이다 — 짐칸 USB 코를 충전소 깔때기에 후진으로 꽂는다

**Status:** Accepted (2026-11-01, 사용자 결정; 방향만 정한다. 구현·Gazebo·실물 수용과 아래 후속 항목은 별도다)

잇는 결정:

- [D-941](D-941-track-platoon-hold-points-charge-bays.md): 261026 트랙 주차장 충전 칸의 후진 진입 운용(Proposed). 이 ADR은 같은 방향을 플랫폼 도킹 전체의 기본 방향으로 올리고, 하드웨어(짐칸 USB 코·충전소 깔때기)를 근거로 적는다.
- [D-349](D-349-dock-auto-charge-code-readiness.md)·[D-350](D-350-dock-hardware-phase-tiers.md): 정면 포고핀·자석 도크의 코드 준비와 단계. 관계는 아래 표.
- [D-200](D-200-docking-owns-the-docking-mode.md): 도킹은 DOCKING 모드와 전용 슬롯을 쥔다.
- 설계 정본: Confluence SP 15368305 「2026-11-01 3D 자료 — Pinky 짐칸 · 후진 USB 충전소」(v11).

### Context

`docs/plans/2026-09-02-docking-station-design.md`의 「Docking direction is forward」는 IR 배열과 초음파가 `+X`를 보므로 정면 진입이 정렬 센서를 도크 쪽으로 둔다고 적었고, 후진 진입에는 로봇에 없는 센서가 필요하다고 했다. 사용자가 이 방향을 바꾸기로 정했다(2026-11-01).

제안 설계(위 Confluence)는 다음이다. 근거가 되는 숫자는 설계 값이며 실측이 아니다.

- Pinky 뒤 위판 나사 2개에 3D 출력 짐칸을 건다. 컨테이너를 로봇 폭 방향으로 눕힌 가로 3칸이고 차체 뒤로 38.5 mm(1줄) 나온다.
- 짐칸 뒷면 코 안에 USB-C 암 단자를 코 끝과 면을 맞춰 두고 뒤 고정판이 받친다. 충전소 기둥(전기차 충전기 모양)의 USB 카트리지는 뒤 덮개가 케이블을 물고, 스펀지로 플러그를 0.6 mm 앞에 둔다. 로봇 코가 밀면 플러그가 끝까지 꽂힌다.
- 충전소 옆벽 깔때기가 차체를 좌우 ±2 cm에서 ±3 mm로 모으고, 받침 홈이 마지막 4 mm에서 ±1.5 mm로 맞춘다.
- 전원은 USB 5 V다. 2S 팩(8.4 V) 충전은 로봇 쪽 2S 충전 모듈이 맡는다. Pinky 충전 입력은 확인하지 못했다.

현재 코드에서 후진은 언도킹과 재시도 백오프에만 쓰인다. `database.py:45` `undock_distance_m = 0.35`(오도메트리 전용 후진), `manager.py:291-296`·`manager.py:595`(언도킹 거리·속도), `parking_phases.py:293-295`와 `parking.py:159-165` `reverse_twist`(후진 조향, 속도 `reverse_speed = 0.05`, `parking.py:134`). 후진으로 도크에 들어가는 접근 단계는 없다.

### Decision

1. **진입 방향은 후면이다.** 기본 도킹 방향을 후진 진입으로 정한다. 정면 진입 절은 이력으로 남기고 위 설계 문서에 이 ADR 참조를 단다.
2. **충전 판정은 D-350 Phase 1과 같다.** 팩 전압 상승 1소스이고 도크 계측이 없다. deep 셧다운(D-27)은 억제하지 않는다. 전압 상승만으로 D-27 충전 확인을 켜지 않는다는 D-941 §6도 그대로다.
3. **후진 진입의 위치 근거는 후보를 둔다.** 아래 셋은 모두 이 ADR에서 채택하지 않는다. 어느 것이 되는지는 실물 시험 뒤 후속 결정이다.

| 후보 | 내용 | 상태 |
|---|---|---|
| 정면 카메라로 정렬선 | 칸 바닥 분홍선을 앞 카메라로 보며 후진한다. D-941 §5가 이미 같은 방식을 칸 운용으로 제안했다 | 후속 확인 |
| 도크 DB 자세로 오도메트리 후진 | 도크 DB(`docking/database.py`)에 등록한 자세로 간다. 회전 3°가 25 cm에서 1.3 cm가 되므로(D-941) 단독 근거로 약하다 | 후속 확인 |
| 멈춤 판정 | 후진 명령 중 바퀴 정지 + 팩 전압 상승으로 삽입 완료를 본다 | 후속 확인 |

4. **도킹 모드의 장애물 정지는 후속으로 남긴다.** LiDAR 정면 정지(`core.yaml:12-22`, 스캔 180° 중심 ±20°, 정지 0.20 m·재개 0.28 m)는 차선 추종 쪽 설정이고(`middleware/core/gateway/core/drive/line_follow.py`), 후진 방향에는 후방 정지 근거가 코드에 없다. 충전 기둥이 LiDAR 높이에 걸릴 수 있으나, 도킹 단계에서 어떤 정지·면제를 쓸지는 정하지 않는다. 다만 D-200의 계약(도킹 슬롯은 `Mode.DOCKING`에서만 바퀴에 닿고, e-stop·EMERGENCY에서는 입력을 버린다, Decision 1·4)은 바꾸지 않는다. 후진 접근도 같은 슬롯과 모드 이음새를 써야 하며, 접근 단계의 장애물 면제(`manager.py:495-498`, 코스트맵 면제)와의 관계는 후속 결정에서 정한다.
5. **회전 반경 변화는 여기서 정하지 않는다.** 짐칸을 달면 제자리 회전 반경이 `body_rotation_radius_m = 0.08257`(`core.yaml:28`)에서 USB 코 끝까지 약 134 mm(1줄 짐칸)로 커진다. D-397은 이 값을 올리면 안전 봉투를 다시 정하는 별도 결정이 필요하다고 못박았다(D-397 `robot_radius` 항, 정지 거리 바닥과 좁은 통로 여유). 따라서 짐칸을 단 로봇의 footprint·회전 반경·정지 거리는 **D-397 안전 봉투를 바꾸는 후속 결정**이다. 이 ADR은 기하 값을 바꾸지 않는다. D-941의 칸 폭 18–19 cm 제약(칸 안 회전 불가)도 134 mm 반경(지름 268 mm)이면 통로 회전 공간 검토가 더 필요하다.
6. **정면 포고핀 도크와의 관계는 다음과 같이 읽는다.**

| 구분 | 내용 |
|---|---|
| 사실 | D-349·D-350은 정면 자석·포고핀 도크와 그 단계를 정한다. 후면 USB 코 경로는 접점·전원(USB 5 V + 로봇 쪽 2S 모듈)이 달라 D-350의 도크 하드웨어와 같은 부품이 아니다 |
| 이 ADR의 결정 | 기본 진입 방향만 후면으로 정한다. 충전 판정은 D-350 Phase 1과 같은 1소스를 쓴다 |
| 추론 | 후면 경로가 자리 잡으면 정면 포고핀 도크는 쓰이지 않을 수 있다. 사용자가 말하지 않았으므로 대체인지 병존인지는 정하지 않는다 |
| 팀 확인 필요 | 포고핀 하드웨어 경로(D-349·D-350)를 유지·보류·폐기할지, 그리고 D-349의 `docking.supported`·펌웨어 계약(ROSY-DOCK-001)이 후면 경로에서 무엇이 되는지 |

### 관계

| 기존 결정 | 관계 |
|---|---|
| 2026-09-02 도킹 설계 「Docking direction is forward」 | 방향을 바꾼다. 본문은 이력으로 남긴다 |
| D-200 | 모드·슬롯 계약은 유지한다. 후진 접근의 정지·면제는 후속 |
| D-349·D-350 | 정면 포고핀 경로. 대체·병존은 팀 확인 필요. Phase 1의 판정·D-27 정책은 이어받는다 |
| D-351 | 재시도 분류(도달 실패 대 접점 후 전류 없음)는 계측이 없어 후면 경로에 그대로 옮기지 못한다. 전압 1소스에서의 분류는 후속 |
| D-397 | 기하 NOMINAL은 바꾸지 않는다. 짐칸 반경은 안전 봉투 변경 후속 |
| D-941 | 같은 방향의 트랙 운용 제안. 짐칸 돌출이 D-941은 약 50 mm, 설계 정본은 38.5 mm로 달라 한쪽을 맞춰야 한다(팀 확인 필요) |

### Consequences

- 방향 결정만 효력이 있다. 코드·`capabilities.yaml`(`docking.supported: false`)·펌웨어는 바뀌지 않는다.
- 후속 결정 목록: 후진 위치 근거 채택, 도킹 모드 장애물 정지·면제, D-397 안전 봉투(짐칸 반경), 포고핀 경로의 처우, 전압 1소스 재시도 분류, Pinky 충전 입력 확인, 짐칸 돌출량 정본 값.
- Accepted는 구현이나 실물 수용을 뜻하지 않는다. 후진 정렬 조향과 안전 경로를 건드리는 변경은 독립 리뷰와 `Safety-Review:`가 필요하다(D-430 §5).

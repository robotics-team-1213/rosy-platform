## D-467 병합된 작업트리는 증거를 확인한 뒤 종료하고, X: 임시 공간은 출처별로 정리한다

**Status:** Accepted (2026-10-05, 사용자 작업트리 정리·X: 용량 확보·교훈 ADR 기록 지시). 저장소 작업 절차에만 적용한다. 제품 런타임, 현장 장치, 배포 승인은 바꾸지 않는다.

### Context

D-372는 병합되고 깨끗한 작업트리의 제거와 남의 미커밋 작업 보존을 정했다. 실제 정리에서는 같은 이름의 오래된 폴더라도 상태가 달랐다. 일부는 `main`에 병합된 깨끗한 Git 작업트리였고, 일부는 수천 파일이 스테이징된 미완성 작업, 현재 경로로 이전되기 전 초안, 생성된 `.lock`, 또는 다른 세션의 진행 중 작업이었다. 수정 시각과 폴더 이름만으로 소유권이나 삭제 가능 여부를 판단할 수 없었다.

2026-10-05 점검에서 병합·청결·잠금·프로세스 조건을 다시 확인한 F: 작업트리 35개는 정상 `git worktree remove`로 종료했다. X:에는 원본 증거·릴리스 이미지·학습 입력과 일회성 다운로드가 함께 있었다. 중앙 목록이 없어 열리지 않는 `gh-artifact.*.zip` 네 개(합계 약 4.95 GB)를 찾았지만 자동 승인 검토가 삭제를 거부해 그대로 두었다. 파일 이름이 임시처럼 보이거나 사용자가 일반 정리를 승인했다는 사실만으로 검토 거부를 우회할 수 없다. X: 여유 용량은 실제 삭제 전후의 드라이브 값으로만 보고해야 한다.

### Decision

1. **작업트리 종료는 현재 상태로 판정한다.** 제거 직전에 등록된 정확한 경로가 저장소의 `.worktrees/<짧은 이름>` 아래인지 절대 경로로 확인한다. `git status --porcelain`에 추적·스테이징·미추적 변경이 없어야 하고, 해당 `HEAD`가 현재 `main`의 조상이어야 한다. Git 잠금과 사용 중인 프로세스를 확인한다. 하나라도 불명확하면 보존하고 소유자/후속 작업으로 남긴다. 오래된 수정 시각은 후보 선정에만 쓴다.
2. **등록된 작업트리는 Git으로 종료한다.** 조건을 만족할 때 `git worktree remove`를 `--force` 없이 실행하고 등록 해제와 폴더 부재를 확인한다. 브랜치 참조는 그 브랜치가 완전히 병합되고 후속 작업에 쓰이지 않는 것을 별도로 확인한 뒤 `git branch -d`로 정리한다. `git worktree prune`이나 폴더 재귀 삭제로 미등록·사용 중 작업을 한꺼번에 처리하지 않는다. D-372의 남의 WIP 보존 규칙을 유지한다.
3. **F:와 X:의 소유를 분리한다.** 제품 소스와 일반 Git 작업트리는 저장소와 그 `.worktrees/`에만 둔다. Orca가 X:에 만든 작업트리는 그 위치에서 관리하며 F:로 옮기지 않는다. 스크래치·로그·검증 찌꺼기는 X:에 둔다. 원본 영상, 학습 입력, 릴리스 payload, 기기 증거, 자격 자료를 폴더 이름이나 나이만으로 일회성 파일로 분류하지 않는다.
4. **X: 삭제는 파일 단위의 증거와 용량 readback을 요구한다.** 정확한 경로와 유형·크기·무결성·참조·프로세스 사용을 확인하고, 작업 대상이 X:의 의도한 경계 안에 있는지 절대 경로로 검사한다. 재생성 가능한 다운로드와 캐시를 우선 검토한다. 삭제 전후 `Get-PSDrive X`로 실제 회수한 바이트를 기록한다. 자동 승인 검토가 거부하면 같은 삭제를 다른 명령으로 재시도하지 않고 파일을 보존하며 거부 사유와 미확보 용량을 보고한다.
5. **공유 상태는 매번 다시 읽는다.** 다른 세션의 커밋·작업이 계속 들어오므로 오래된 목록을 삭제 허가로 쓰지 않는다. 각 제거·병합·푸시 직전에 `main`, 작업트리 상태, 등록 목록을 다시 확인한다. 미커밋 초안을 단지 작업트리를 비우기 위해 커밋하거나 제품 `main`에 섞지 않는다.

### Alternatives

- 수정 시각이나 이름만으로 오래된 폴더를 일괄 재귀 삭제: 진행 중 WIP와 고유 증거를 잃을 수 있어 거절한다.
- 모든 미커밋 파일을 먼저 일괄 커밋·병합: 현재 계약과 맞지 않는 이전 경로 초안, 생성 파일, 다른 세션의 작업이 제품 이력에 들어가므로 거절한다.
- 공간이 부족해도 아무것도 정리하지 않음: 검증된 병합·청결 작업트리는 안전하게 종료할 수 있으므로 채택하지 않는다.

### Consequences and validation

정리 결과는 제거한 정확한 작업트리 목록, 보존한 이유, Git 등록 수, X: 삭제 전후 여유 바이트로 구분해 보고한다. F: 작업트리 삭제를 X: 여유 공간 증가로 계산하지 않는다. 저장소 문서 검사는 ADR 본문·ADR Log 일치와 `rosy_harness.py lint`, 관련 문서 계약 시험으로 한다. 이 ADR의 Accepted 상태는 정리 절차의 채택을 뜻하며 X:의 거부된 파일 삭제나 현장·장치 수용을 뜻하지 않는다.

## D-893 관제 단위와 호스트 배치를 분리하고 부하에 따라 합치거나 나눈다

**Status:** Accepted (2026-10-27, 사용자에게 위임받은 설계 결정). 수용 범위는 논리 역할과 배치 선택 원칙이다. 새 실행 경로·자동 승인·실시간 제어의 원격 이전·배포·DEVICE/FIELD 수용을 허용하거나 완료한 결정이 아니다.

### Context

암 한 대에 컴퓨터 한두 대, 암 여러 대에 공유 컴퓨터 한 대, Pinky의 내장 라즈베리파이와 외부 컴퓨터, 별도 통합관제 컴퓨터가 함께 참여할 수 있어야 한다. 사용자는 이를 하나의 시스템으로 관리하면서 연산 부하와 장치 연결 조건에 따라 실행 위치를 나누기를 요구했다.

D-850은 독립·중첩 관제의 논리 역할을 정했고 D-855·D-862는 제한된 위임·정보 집계·정지 요청을 구체화했다. 이번 결정은 그 관제 단위와 물리 호스트의 배치 관계를 정한다. 모든 컴퓨터를 Fleet 서버로 부르거나 장비 수로 관제·컴퓨터 수를 고정하면 보조 연산에도 원장과 실행 권한을 불필요하게 늘리게 된다.

### Alternatives

| 대안 | 이점 | 판단 |
|---|---|---|
| 통합 PC 한 대에 모든 실행 고정 | 설치와 데이터 관리가 단순하다. | 장치 연결 거리·GPU 경합·호스트 장애의 영향이 커진다. 가능한 배치지만 필수 구조로 고정하지 않는다. |
| 장비·컴퓨터마다 Fleet 한 개 고정 | 담당 위치를 설명하기 쉽다. | 계산만 보조하는 PC에도 원장이 생기고 같은 셀의 두 암을 불필요하게 나눈다. 채택하지 않는다. |
| 논리 역할을 유지하고 호스트 배치를 선택 | 작은 현장의 통합과 장비별 분산을 같은 책임 모델로 표현한다. | 배치별 통신·자원 경합·복구 검증이 필요하지만 사용자 요구와 기존 관제 경계에 맞으므로 채택한다. |

PC를 추가할 때마다 관제 단위를 나누는 방식은 과도한 분산을 만들고, 모든 실행을 중앙으로 모으는 방식은 장치 가까이에 있어야 하는 제어 경계를 약하게 한다. 작업 조정 범위가 달라질 때 관제를 나누고, 계산·연결·장애 격리만 달라질 때는 실행 호스트를 나눈다.

### Decision

1. **관제 단위·장치 실행자·보조 연산·호스트를 구분한다.** 관제 단위는 자기 범위의 작업 조정과 원장을 소유한다. 장치 실행자는 상태·권한·안전 조건을 재검사하고 최종 동작을 소유한다. 보조 연산은 허용된 영상 처리·고정 모델 추론·계획 후보 계산을 맡으며 PC가 따로 있다는 이유로 원장·구동 권한을 얻지 않는다. 호스트는 이 인스턴스를 실행하는 물리 컴퓨터이며 장치·관제 수와 일대일 관계를 강제하지 않는다. 기존 CONCEPTS와 identity를 재사용하고 새 공개 ID 필드는 만들지 않는다.

2. **한 관제 단위가 여러 호스트의 실행자를 이용할 수 있다.** 암 제어와 영상 추론을 다른 PC에 두어도 작업 조정 범위가 같으면 관제 단위를 추가할 필요가 없다. 보조 PC 추가를 위해 Fleet 서비스·원장을 복제하지 않는다. 같은 관제 원장의 다중 호스트 active-active 쓰기, 자동 이전·자동 승격은 이번 결정에 포함하지 않는다. 기존 수용된 실행 경로만 사용하며 새 원격 연산 연결은 계약과 수용 증거가 필요하다.

3. **한 호스트에 여러 역할이나 관제 인스턴스를 함께 둘 수 있다.** 동거하는 인스턴스의 원장·설정·포트·서비스 자격과 장치 할당을 격리하고 기존 인증·admission을 유지한다. 독립 운영·승인·원장이 필요한 장비군은 별도 관제 단위 후보로 둔다. CPU/GPU 부족만으로 관제 단위를 추가하지 않는다. 프로세스 격리는 전원·OS·USB·GPU 장애의 물리 격리를 증명하지 않는다.

4. **통합관제는 담당 하위 관제의 공개 경로로 업무를 조정한다.** 하위의 장치 자격을 복사해 직접 명령하거나 하위 원장을 덮어쓰지 않는다. 접수·승인·실행·완료·결과 불명과 각 하위의 신선도를 구별한다. 현재 D-855 navigation 위임의 하위 named operator 승인·기존 admission을 자동 승인이나 팔·임의 장치 위임으로 확대하지 않는다. 통합 화면은 관제·장비·호스트 관계를 보여줄 수 있지만 하나의 화면이 단일 원장이나 공통 지도 좌표계를 뜻하지 않는다.

5. **배치는 부하와 장치 연결·장애 범위를 근거로 선택한다.** 아래는 후보이며 새 배치의 지원 완료를 주장하지 않는다.

| 구성 | 배치 방향 | 수용 조건 |
|---|---|---|
| 암 1대 + PC 1대 | 장치 실행·현장 관제·인식을 함께 둘 수 있다. | 동시 부하에서 제어 주기·관측 신선도·정지 응답을 만족한다. |
| 암 1대 + PC 2대 | 연결 호스트는 장치 실행, 보조 호스트는 무거운 인식·추론을 맡는다. | 원격 결과의 장치·요청·시각·버전을 검증하고 만료된 결과를 거절한다. |
| 암 2대 + PC 1대 | 두 장치 실행 인스턴스와 셀 관제를 함께 둘 수 있다. | UART·카메라·설정 격리, 각 암의 정지·복구와 동시 부하를 검증한다. |
| 암별 제어 PC + 통합 PC | 장치 실행을 유지하고 업무 범위에 맞게 셀·하위 관제를 묶는다. | 제어 PC 수로 관제 수를 결정하지 않고 공유 물체·공간의 승인 owner를 정한다. |
| Pinky + 내장 라즈베리파이 | CORE와 지연 민감한 주행·안전 경로는 로봇에 유지한다. 추가 역할 동거는 자원 검증으로 판단한다. | 내장 PC 존재만으로 Fleet 설치를 요구하거나 자동 허용하지 않는다. |
| 외부 GPU PC 공유 | 여러 장비의 허용된 인식·추론 요청을 처리할 수 있다. | 큐 지연·자원 상한·요청 구분·모델 버전·단절 처리를 검증한다. |

두 암이 같은 물체를 처리하면 한 셀의 조정 범위로 묶는 것을 우선 검토하되 각 장치의 최종 실행자는 유지한다. 다장치 실시간 동기 동작과 이동 베이스 위 팔의 복합 실행은 별도 수용을 요구한다. 모델 PC 학습·평가와 AI PC 고정 추론의 기존 호스트 역할은 유지한다.

6. **호스트 변경은 정본 owner를 보존하는 계획된 전환으로 한다.** 작업과 발행을 멈추고 진행 중 요청·결과 불명을 조정한 뒤 원장·설정·모델·보정 버전을 확인한다. 이전 인스턴스의 실행 권한을 회수하고 새 위치의 단일 owner·현재 세대·장치 상태를 검증한 뒤 기존 재무장 절차를 따른다. DB 복사나 주소 변경만으로 완료된 이전이라고 하지 않는다. 단절·재연결은 자동 독립 전환·재실행·정지 해제의 근거가 아니며, 진행 중 동작의 계속·중단과 신규 작업 허용은 각 장치·작업의 기존 계약을 따른다. 장치 안전은 통합 PC 연결 유지에 의존하지 않는다.

### Consequences and validation

장비가 늘어도 필요한 계산 자원을 추가할 수 있고 작은 현장은 통합 배치를 유지할 수 있다. 대신 각 배치의 정본 owner와 공유 호스트 장애 범위를 운영 기록에 남겨야 한다. 실제 배치를 활성화하기 전에 다음을 검증한다. 수치 기준은 해당 장치·기능 계약을 따르고 새 조건이면 시험 전에 정한다.

- 장치·관제·실행 인스턴스·호스트의 대응과 정본 owner, 중복 장치 할당 거절.
- 최대 동시 부하에서 제어 주기·큐 지연·프레임 손실·네트워크 신선도·메모리·CPU/GPU 사용량.
- 통합·보조 연산·장치 호스트의 단절·재시작·응답 유실에서 기존 정지 경로, 중복 실행 차단, 결과 불명 보존, 늦은 명령·결과 거절.
- 공유 호스트 두 암의 장치 혼선 방지와 한 암의 정지·복구가 다른 암에 미치는 영향.
- 통합 화면이 하위 원장·신선도·정지 결과를 보존하고 하위 승인을 우회하지 않는지 확인.

## D-823 OMX Leader를 통한 자동 운용 중 수동 개입·복구·자동 복귀

**Status:** Proposed (2026-10-20). 활용 방향과 제어권 경계의 제안이다. 구현 완료, 새 API·RobotMode, 장치 capability 활성화, 실물 동작 또는 DEVICE/FIELD 수용을 뜻하지 않는다.

## Context

자동 적층·회수 중 파지·접근·배치가 예상과 달라지면 사람이 Leader로 조작해 복구하고 자동 작업으로 돌아갈 수 있어야 한다. Leader의 주목적을 교시·학습 데이터 수집으로만 두면 이 운용 요구가 빠진다. 개입 기록의 학습 활용은 부가 기능이다.

D-299는 Leader를 운영 로컬 제어기에 들어오는 입력 후보로 두고, LeRobot의 직접 시리얼 개발·기록 모드와 구분한다. D-369는 Fleet의 업무 제어, 장치 로컬 최종 명령자, driver, 물리 정지, 독립 goal verifier의 책임을 분리한다. 이번 제안은 그 경계 안에서 자동 입력과 사람 입력 사이의 제어권 전환을 구체화한다.

문제는 Leader 연결 여부보다 전환 순간이다. 이전 자동 목표가 늦게 실행되거나, 현재 팔과 다른 Leader 자세가 한 번에 전달되거나, 그리퍼 값이 달라 물체를 놓거나, 수동 복구 후 오래된 작업 상태로 자동 재개할 수 있다. 두 팔이 같은 물체를 잡고 있으면 한 팔의 이동이 상대 팔에 내부 힘을 만들 수 있다.

## Proposed decision

### 1. Leader는 운용 중 사람이 개입하는 입력 장치다

자동 운용 → 개입 요청 → 자동 입력 차단·취소·실제 상태 확인 → Leader 입력 기준 설정 → 제한된 수동 복구 → 상태 재관측·작업 정합·재계획 → 작업자의 명시적 요청에 따른 자동 복귀를 목표로 한다.

‘즉시’는 개입 요청을 정상 자동 작업보다 우선 처리한다는 요구다. 특정 시간 이내 물리 전환을 보장하거나, 다른 Leader 절대 자세를 그대로 전달한다는 뜻이 아니다. 요청·명령 차단·정지 확인·수동 입력 허용 시각과 실제 지연을 각각 측정한다.

Leader 조작은 제조사가 공식 제공한다. 제조사 예제에서 teleop과 추론 모드를 분리하는 것은 조작 금지의 근거가 아니다. 다만 기본 teleop launch의 초기 자세 이동·새 Follower 연결을 운용 중 takeover로 그대로 사용하지 않는다.

### 2. 최종 명령자는 유지하고 입력 제어권만 전환한다

수용된 OMX 로컬 owner가 Follower driver/시리얼 버스를 계속 독점한다. Leader 어댑터는 입력을 읽어 owner에 전달하며 Follower 포트를 별도로 열지 않는다. owner 내부 중재기는 자동 입력과 Leader 입력 중 하나만 허용한다. 여러 프로세스가 번갈아 직접 쓰는 방식이나 동시 writer는 채택하지 않는다.

Fleet은 관련 작업·자원 claim·dispatch와 durable 업무 상태를 소유한다. 로컬 owner는 개입 우선순위, 실제 실행 취소·중재, 관절·속도·작업공간 제한과 software stop을 집행한다. Leader가 Fleet 원장·admission·base 명령 권한을 얻지 않는다. Pinky 최종 base 명령은 CORE에 남는다. 보호 정지는 정상 개입보다 우선하며, Leader 연결·enable·복귀 요청이 stop latch·rearm 권한을 대신하지 않는다.

아래 상태명과 mode/epoch는 **설계용 개념**이다. 기존 RobotMode나 구현된 wire 필드가 아니다. 외부 API·IPC·schema가 필요하면 D-18의 계약·producer/consumer 변경을 별도 범위로 설계한다.

| 상태 | 허용 동작 | 전이 조건 |
|---|---|---|
| AUTO | 승인된 자동 입력 | 개입 요청을 우선 처리하고 새 자동 입력 차단 |
| TAKEOVER_PENDING | 새 자동·수동 이동 금지, 취소·정지 요청 | 기존 실행 취소, 큐·오래된 권한 무효화, 실제 팔 상태 확인 |
| ALIGNING | Leader 읽기·상태 표시, 수동 이동 금지 | 대상 identity·단위·freshness·입력 기준점·파지 상태 확인 |
| MANUAL | enable을 유지하는 동안 제한된 수동 입력 | enable 해제 시 다음 목표 차단·정지 확인·입력 기준 재설정. 복귀 요청 시 RECONCILING |
| RECONCILING | 자동·수동 이동 금지, 상태 재관측 | 작업·화물·지지·슬롯 정합과 재계획 및 승인 조건 확인 |
| SAFE_STOP | 기존 보호 정지·장애 처리 | 기존 복구 권한과 조건 적용. 자동 해제·재개 없음 |

개입 시 제어 세대를 변경해 과거 자동 목표·완료 이벤트·수동 샘플을 거부할 계약을 둔다. 취소 ACK나 소프트웨어 큐 삭제만으로 하드웨어 정지를 확정하지 않는다. 상태가 불명확하거나 취소·관측이 시간 내 확인되지 않으면 수동 입력을 열지 않는다. 현재 하위 실행이 선점 가능한지는 구현 전 실제 producer→consumer→driver 경로에서 확인한다.

### 3. 전환은 자세와 파지를 연속적으로 유지해야 한다

첫 구현 후보는 실제 Follower 현재 자세와 Leader 기준 자세를 읽고, 이후 Leader의 상대 관절 변화량을 검증된 매핑으로 전달하는 방식이다. 첫 목표가 현재 팔 자세와 연속이어야 한다. 입력 기준을 바꾸는 clutch는 입력 비활성·정지 확인 후 수행한다. 관절 한계에서 목표를 계속 누적하지 않는다.

Leader 샘플을 기존 명령 경로의 연속 스트림으로 직접 전달하지 않는다. D-496 결정 4의 제한 목표 하나씩 실행·이전 목표 종결 확인·100 ms 스트림 금지와 동시 명령 금지를 유지한다. 상대 입력은 그 제약 안의 제한 목표 후보로 검토하며, 연속 로컬 teleop이 필요하면 제어 계약·관련 ADR 변경과 검증을 별도로 제안한다. 이 Proposed ADR만으로 현행 제한을 해제하지 않는다.

관절·속도·가속도·샘플당 변화·신선도·작업공간 제한을 적용한다. L/F 기하 차이와 5관절 IK 때문에 같은 관절값이 같은 Cartesian 경로를 뜻하지 않는다. 상대 매핑도 충돌 회피나 안전의 증거가 아니며 조작성을 검증해 채택한다.

그리퍼는 별도 enable과 해제 조건을 가진다. 전환 시 Leader 그리퍼 값으로 기존 파지 명령을 덮지 않는다. 보유·지지 확인 없이 물체를 해제하지 않는다. Leader 단절·stale·타깃 변경·enable 해제·임대 단절에서는 다음 목표를 차단하고 실제 정지 상태를 확인한다. 연결 복구만으로 재개하지 않는다.

### 4. 양팔 개입은 작업 격리와 물리 지지를 함께 다룬다

한 팔의 개입이 관련 협응 작업 전체를 격리하도록 Fleet 업무 상태와 로컬 실행 상태를 결속한다. 상대 팔과 운반 장치의 공유 구역 진입을 막는다. 양팔 정지 요청 발행이 동기 정지나 하중 유지의 증거는 아니다. 작업 담당 팔과 물리 지지주체를 구분한다.

초기 범위는 한 Leader·한 Follower의 비접촉 및 받침 지지 복구다. 다른 팔이 비접촉 퇴피 상태이거나 별도 검증된 지지를 유지할 때만 제한된 조작을 허용한다. 양팔이 같은 강체를 잡은 상태에서 한쪽을 고정하고 다른 쪽을 임의 이동하는 동작은 초기 범위에서 보류한다. 양팔 동시 수동 조작은 두 Leader 입력, 공통 제어권·관측·부분 실패 처리·접촉력/컴플라이언스·하중 경로를 별도로 검증해야 한다.

공중 인계는 수신 보유 확인 전 제공 팔 해제 금지, 받침 인계는 안착 확인 후 제공 팔 해제·퇴피라는 물리 조건을 유지한다. 사람의 조작·HOLD·그리퍼 닫힘은 물체 지지의 독립 증거를 대신하지 않는다.

### 5. 복귀는 새 관측과 계획으로 시작한다

작업자의 명시적 복귀 요청 뒤 물체 ID·그립·슬롯·적층·적재·상대 팔 상태를 재관측한다. Fleet이 미완료 작업·자원과 정합하고 기존 승인·grant 조건을 적용한 새 계획만 실행한다. 오래된 궤적을 이어 실행하거나 불명 결과를 완료로 기록하지 않는다. 정합 실패는 자동 복귀나 자동 수동 enable로 처리하지 않는다.

사람이 복구한 결과는 무인 성공과 구분한다. 개입 지연·상태 전이·팔/작업 identity·실제 관측·전달 목표·거부 근거·개입 전후 상태를 기록한다. 기록 장애가 개입 차단이나 오래된 명령 전달을 유발하지 않도록 제어와 분리한다. 학습·DAgger·공동 정책은 개입 기능의 선행 조건이나 완료 기준이 아니다.

## Consequences

운영자는 학습 시스템에 의존하지 않고 제한된 복구 조작을 요청할 수 있다. 대신 자동 목표의 선점·취소, 오래된 이벤트 무효화, 입력 연속성, 협응 작업 격리와 업무 정합을 구현해야 한다. Leader 연결만으로 얻는 기능이 아니다. 자동 복구율과 사람 개입 복구율은 별도 지표가 된다.

본 ADR은 Proposed이며 기존 Accepted 결정을 대체하지 않는다. 실제 포트·주소·계정·현장 배치는 공개 ADR에 적지 않는다. 장비 연결·실물 조작 권한을 새로 부여하지 않는다.

## Validation / implementation gates

모든 동작 시험은 **NOT RUN**이다. 구체 API와 허용 수치는 구현 전 별도 계약·측정으로 정한다.

1. 현재 자동 입력→local owner→controller/driver 경로와 grant·임대·cancel·stop·readback을 추적한다. 선점 불가 구간을 먼저 확인한다.
2. 모의 시험으로 전 상태 전이·단일 writer·과거 목표/완료 이벤트 거부·보호 래치 우선·부분 전환 실패를 검증한다.
3. 자세·그리퍼 불일치, stale/단절, enable 해제, 타깃 변경, 취소 지연, 양팔 한쪽 실패에서 급동작·해제·자동 재개가 없음을 검증한다.
4. 기존 실물 정지·profile·속도·단일 owner 준비 조건 이후 한 팔 비접촉 저속으로 요청→차단→정지 확인→입력 허용 지연과 최대 자세 변화를 측정한다. 허용치는 작업 여유·속도·정지 실측에 근거해 시험 전에 고정한다.
5. 낮은 받침의 한 물체 복구와 재관측·원장 정합·새 계획 복귀를 검증한다. 전체 시도·실패·안전 중단·사람 개입을 분모와 함께 기록한다.
6. 독립 팔/받침 지지부터 양팔 작업 격리·부분 실패를 검증한다. 동일 강체 공동 접촉은 별도 제어·센서·하중 경로 증거 전에는 확대하지 않는다.

## D-460 운전석 임대는 만들지 않는다 — 조종 소유권은 지금의 어휘로 유지한다

**Status:** Proposed (2026-10-04, 사용자 승인 후 "계속" 대기열. D-343 §2.4(운전석 임대 계약)의 채택·거절 판정이다. 이 ADR이 거절이면 D-343 2.4는 닫히고 관전·양보 요청은 좌석 임대 없이 정의된다. 구조를 바꾸는 ADR이므로 D-427·D-429·D-430과의 관계는 아래 표.)

| 관련 | 관계 |
|---|---|
| D-427 (소스 이동) | 관계 없음 — 새 최상위 폴더를 만들지 않는다. 기존 경로만 쓴다 |
| D-429 (다섯 관심사·포트) | 관계 없음 — Motion Intent·DeviceControlPort를 열지 않는다 |
| D-430 (안전 분리) | 구현이 없어 safety 경로를 건드리지 않는다. 채택이었다면 safety 경로 변경이라 trailer가 필요했을 것이다 |

## 배경

- D-343 2.4(2026-09-29 초안, 미승인)는 `POST /api/v1/teleop/seat` 임대 발급과 `409 SEAT_TAKEN`을 제안했다 — "한 로봇을 여러 조종 화면이 동시에 잡을 수 있다"는 태블릿 실측(52개 탭)의 해법으로.
- 그러나 D-411 A(녹화 수호자, Accepted)는 "CORE has no Pilot seat"을 못박았다 — 소유권은 (a) 링크(토큰의 열린 `/ws/state`)와 (b) 다른 토큰의 수락된 teleop으로 판단한다(`seat_changed`). 보정 lease(D-321)가 세 번째 어휘다.
- teleop은 마지막 수락 우선(last-wins)이다. 새 임대 임대자 개념은 CommandManager의 소유권 판정을 바꾸고, 녹화 수호자의 `seat_changed` 정의와 어긋난다.

## 결정

1. **`POST /api/v1/teleop/seat` 계약을 만들지 않는다.** 조종 소유권은 지금의 세 어휘(링크·수락 teleop·보정 lease)로 유지한다. 이유는 셋이다: (a) D-411 A와 정면 충돌하는 계약을 같은 저장소에 두지 않는다, (b) 임대 만료 타이머(2 s 제안)는 watchdog(SAF-002, 500 ms)과 어휘가 겹쳐 두 시계가 한 현상을 따로 판단한다, (c) 한 자리 보장은 임대자보다 **아는 것의 표시**가 먼저다 — 누가 운전 중인지 로비가 말하면 된다.
2. **대신 D-343 §2.1의 방 목록이 운전 중 표시를 싣는다.** 방 행에 `driver` 필드를 둔다: `{present: bool, label?: string}` — 누가 운전 중인지는 **라벨만**(역할·만료 같은 자격 식별은 싣지 않는다, D-193). 소스는 그 기기의 공개 상태 요약에 이미 있는 활동 증거(teleop 수락 흔적)이며, 새 측정·새 저장을 만들지 않는다.
3. **거절 본문은 그대로 둔다.** 다른 토큰의 teleop이 현재 조종 중일 때 새 teleop의 응답은 바뀌지 않는다(계약 변경 없음). 관전(영상·상태만)과 "양보 요청"은 운전자 라벨을 보고 사람의 말로 해결한다 — 자동 양보 큐는 범위 밖이다.

## 결과

- 새 API 경로 없음, 새 스키마 없음, CommandManager·녹화 수호자 변경 없음. D-18 API 주기가 열리지 않는다.
- D-343 2.4는 이 ADR로 닫힌다(초안의 임대 계약 부분). §2.1 방 목록 설계는 `driver` 필드 추가로 이어진다.
- 한 자리 보장의 강제력은 없다 — 강제력이 필요해지면 그때 새 ADR이 임대 계약을 다시 연다(거절의 재검토 조건을 문장으로 남긴다).

## 검증

- 이 ADR: ADR Log 행 + harness lint.
- `driver` 필드가 방 목록에 붙을 때: 공개 정보만(라벨 외 식별자 금지) 시험이 핀한다.

# D-840 하나의 Learning 프로젝트에서 여러 로봇과 실행 호스트를 연결한다

**Status:** Accepted for implementation (2026-10-22, 사용자 지시). 범용 로봇 지원·운영 배포 수용은 별도다.

2026-10-22 구현 구체화: 기존 검수 DB의 불변 학습 대상·과제·자료 결속을 사용한다. 호스트는
과제 정의가 아닌 실행의 속성이고, 같은 프로젝트 사이의 명시적 메타데이터 전달로 과제 identity를
보존한다. 입력 프로필과 참여 로봇/device/component/role의 순서를 검증하고 run·평가·다운로드에
같은 snapshot을 남긴다. 역사 자료는 명시 사후 연결로 표시한다. 등록 자체는 장치 연결 증거가 아니다.
로컬 HTTP 계약과 준비 조건은 [학습 앱 문서](../../learning/curation/perception/docs/review-app.md)에 둔다.

## Context

사용자는 기존 Learning 프로젝트 하나를 Model·AI PC에서 함께 사용하며 여러 종류·여러 개체의
로봇을 학습하는 러닝센터를 요구했다. OMX 팔과 ACT/HIL-SERL은 첫 학습 대상이다. Fleet의
Docker 배포 경로로 들어가야 하며, 개발용 터널과 별도 후보 구동은 제품 배포가 아니다.

## Decision

러닝센터의 최상위 단위는 로봇 종류나 PC별 앱이 아닌 기존 중앙 Account의 Learning 프로젝트다.
Fleet 작업 탐색은 기존 이미지 안의 Learning 진입을 제공하고 승인된 보호 HTTPS 원본의
`/learning`으로 이동한다. 특정 팔 화면을 전체 센터의 홈으로 고정하지 않는다. 로그인·프로젝트
권한·사용자 HF 연결은 기존 중앙 Account와 Learning 소유권을 유지한다. 새 프로젝트로 권한을
복사하거나 Model의 개인 연결 비밀을 AI에 복제하지 않는다.

| 구분 | 의미 |
|---|---|
| 로봇 종류·모델 revision | 관측·행동 정의와 실행 어댑터의 호환 범위 |
| 로봇 개체·구성 요소 | 기존 robot/device identity와 팔·센서·실행 owner 참조. 팔 ID를 로봇 전체 ID로 바꾸지 않는다. |
| 학습 참여 그룹 | 한 과제를 수행할 한 개 이상의 개체/구성 요소와 역할·순서·좌표/시간 기준 |
| 학습 과제 | 목표·성공/실패·초기화와 참여 그룹, 입력/행동 서명, 자료·평가 범위 |
| 학습 방법 | 명시된 자료/보상과 서명을 지원하는 알고리즘 및 어댑터 |
| 실행 호스트 | 같은 프로젝트 작업을 수행하는 Model/AI 계산 자원. 새 로봇 종류나 프로젝트가 아니다. |

사용자는 로봇·과제를 먼저 정하고 호환되는 자료·학습 방법·실행 호스트를 선택한다.
시범 수집, 검수, 학습, 독립 평가와 다음 실험은 같은 과제 identity로 이어져야 한다.
여러 개체를 따로 학습하는 경우와 협동 정책으로 학습하는 경우를 구분한다. 서로 다른
관측/행동 서명을 가진 로봇 자료를 자동으로 합치거나 같은 정책으로 실행하지 않는다.
장치 최종 writer·권한·제어 전환·관측 신선도·중단은 해당 실행 owner에서 검증한다.

기존 인식 학습·Pinky 원본/행동 연구·OMX 팔·SIM 경로를 센터 안에서 구분한다. D-832의
팔 그룹 프로필은 OMX 어댑터 계약이며 범용 로봇 등록 계약이 아니다. 범용 참여 그룹·어댑터
호환성과 실행 계약은 위 구분에 따라 단계적으로 구현한다. 화면 문구만 바꿔 모든 로봇의
실물 강화학습이 가능하다고 표시하지 않는다. 미지원은 필요한 어댑터/자료/실행 연결을 안내한다.

운영 이미지는 실제 배포에 쓰이는 공개 원본과 서명 후보 절차를 기준으로 만든다. 별도 개발
줄기의 무관한 재구조화·미게시 이력을 통째로 배포하지 않는다. 코드 holder 경로가 다르면
해당 서명 원본의 manifest·Docker COPY·설치 자원 identity에 맞춰 필요한 변경만 이식한다.

| 기존 결정 | 유지할 관계 |
|---|---|
| D-427 | 학습·검수·평가·artifact 소유권을 유지한다. 소스 폴더만으로 실행 호스트를 추정하지 않는다. |
| D-429 | 기존 계약/어댑터 의존 방향을 유지하며 Fleet 원장에 학습기가 직접 쓰지 않는다. |
| D-430 | CORE/Base 및 독립 OMX 최종 writer를 유지한다. 등록·학습 완료는 장치 실행 수용이 아니다. |
| D-757 | 중앙 identity·프로젝트 권한과 사용자 연결 소유권을 보존한다. |
| D-832 | OMX 다중 팔·다중 카메라 ACT/HIL-SERL은 센터의 구체 어댑터 경로로 계속 구현한다. |

## Consequences

Fleet 이미지의 일반 센터 진입, 동일 프로젝트 바인딩의 Model/AI 운영 원본, 명시적인
지원 범위와 호환성 검증을 함께 확인해야 한다. 이미지/서비스 건강만으로 학습 사용 가능을
판정하지 않는다. 실제 사용자 인증/HF 동의·개별 로봇/협동 과제 성공은 독립 수용 증거가 필요하다.

## 구현 전 경계 보충 (2026-10-22)

이번 사용자가 요청한 AI PC 학습은 실험실 오프라인 학습이다. D-516의 운영 고정 추론 역할과
별도 OS 사용자·서비스·가상환경·코드/자료/모델 출력 경로로 격리하고 운영 추론의 승인 모델·
설정·자격과 Fleet/장치 권한을 공유하지 않는다. GPU 학습은 같은 GPU의 운영 추론 사용 중에
대기하며 운영 서비스를 임의 중단하지 않는다. 운영 모델로의 전달은 기존 평가·승격 절차를
유지한다. 실제 호스트 분리와 자원 확인 수단은 배포 전에 확인해야 하며 아직 수용되지 않았다.

Model/AI는 같은 기존 중앙 project_id를 확인하고 호스트별 client/callback·상태·center 원장을
유지한다. 공유 자료는 봉인된 데이터·검수 버전·모델의 revision/hash와 과제/입력 provenance로
한정하고 수신 검증한다. 개인 HF 토큰·세션·쓰기 가능한 DB를 복제하지 않는다. 현재 호스트별
Center 사이의 자동 목록/작업 동기화는 없으며, 실제 기존 프로젝트·운영 서비스 매핑은 확인 전이다.

D-446 서명 코드 후보는 설치된 controller와 Python 환경을 갱신하지 않는다. D-545 보호 서비스에
연결하는 trusted installer/controller는 별도 검토한 고정 revision으로 설치·원복 가능하게 준비하고,
서명 소스와 실제 서비스 인자·학습 환경의 지문을 함께 확인한다. Fleet 이미지는 기존 signed site
경로로 검증·전환하며 원격 Learning 설정·유닛·controller의 복구는 별도로 확인한다. 설치 순서와
수용 조건은 [운영 진입 배포 계획](../plans/2026-10-22-fleet-learning-entry-deployment.md)에 둔다.

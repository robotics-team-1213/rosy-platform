## D-416 관제 콘솔 디버그 강화 — 로스터 카드 마지막 응답·대형 모니터링 모드·카메라 플레이스홀더

**Status:** Accepted (2026-10-02, 사용자 지시 — "이어서 해줄래").

이은 결정: [D-280](D-280-calm-intelligence-product-design-philosophy.md) · [D-414](D-414-console-direct-action-and-discovery-cards.md) · [D-415](D-415-console-operational-visibility.md).

### Context

D-415 진단 패널이 전체 상태를 보여주지만, 개별 로봇 카드에는 디버그 정보가 없다 —
오프라인 로봇이 그냥 "—" 네 칸으로 죽어 있다. 대형 폼이 운행 중에도 6개 입력 필드를
펼쳐 놓아 모니터링보다 설정이 앞선다. 카메라 프리뷰가 선택 전에 빈 칸이다.

### Decision — 세 단계

1. **로스터 카드 마지막 응답** — 오프라인 로봇의 카드 하단에 `마지막 응답: N초 전`
   또는 `응답 없음`을 보인다. 온라인 로봇은 생략(정상은 조용하다, D-280).
   근거: 사용자가 "언제부터 안 됐지?"에 바로 답할 수 있어야 한다.

2. **대형 모니터링 모드** — 대형이 RUNNING/HOLDING일 때 폼을 접고 상태 요약
   (모양·간격·리더·멤버 수) + "해제" 버튼만 보인다. 폼은 IDLE일 때만 펼친다.

3. **카메라 플레이스홀더** — 소스가 선택되지 않았을 때 프레임 영역에 카메라 아이콘과
   "카메라를 선택하세요" 문장을 둔다(인증 안내는 D-415에서 이미 처리).

### Alternatives

- **WebSocket 이벤트 스트림**: 백엔드에 아직 로그 스트림 엔드포인트가 없다. 다음 회차.
- **로스터 카드에 전체 상태 덤프**: 너무 크다. 마지막 응답 하나면 디버깅 첫 단계로 족하다.

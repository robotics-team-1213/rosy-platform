## D-517 여러 로봇이 같은 차로망을 동시에 달린다 — 로봇마다 trip 하나, Fleet 블록 통행권, 로봇 우선 해결과 Fleet 판단

**Status:** Proposed (2026-10-08, 사용자 요청: "2대를 동시에 돌게 할거고 이에 대한 규칙도 세워야겠지 … 군집, 수십 대도 가능하도록". 안전 경로 변경이라 사용자 수락과 Safety-Review 전에는 구현하지 않는다.)

### Context

시연에서 두 대가 파란 출발 자리 두 곳(D-513)에서 같은 방향으로 고리를 계속 돈다. 다음은 수십 대 군집이다. 2026-10-08 코드와 ADR을 다시 읽은 결과는 다음과 같다.

- **trip은 사이트 전체에 한 대다.** `trip_runner.py`는 진행 중 trip 하나(`_live`)와 잠금 하나를 두고, 두 번째 출발을 `TRIP_BUSY`로 거절한다. D-494는 여러 대 동시 trip을 "교통 층 ADR"로 미뤘고 이유는 적지 않았다.
- **한 바퀴 뒤 계속 도는 방법이 없다.** trip은 마지막 장소에 닿으면 끝난다. 차선 주행만 켜 두는 방법도 안 된다. 회전 교차로 입구의 갈림은 trip이 주는 교차로 지시(D-495, D-507)로만 지난다.
- **로봇이 먼저 풀고 Fleet에 묻는 길은 있지만 trip에는 꺼져 있다.**
  - CORE는 앞 물체에서 몸체 기준으로 선다(D-422, `line_follow/manager.py`). 5 s 뒤 `nav.line_obstacle_hold`를 내고, 막힘(D-407)을 콘솔에 묻는다. 앞 물체가 로봇인지는 모른다.
  - Fleet 해결기(D-438, `stuck_resolver.py`)는 규칙 R1 `peer_ahead`(앞 로봇이면 기다림)와 D-451 `room_hold`를 가진다. 그러나 `--stuck-resolver`로만 켜지고, trip 로봇은 건너뛴다(D-494 14항, `stuck_resolver_loop.py`). 모델 단계는 아직 없다.
  - D-451은 한 방향 고리에서 같은 방향 두 대를 둘 다 PROCEED로 두고, 간격은 로봇이 직접 선다고 정했다.
- **통행권 저장소는 있지만 호출하는 곳이 없다.** `traffic_reservations.py`(D-426 상태 FREE→RESERVED→OCCUPIED→RELEASING)는 시험만 부른다. D-474 구역 허가의 CORE 쪽(`road_behaviour`)도 연결되지 않았다. trip 재계획에 쓰는 `blocked`도 늘 비어 있다.
- **같은 방향 간격을 몸체 정지에만 맡기면 trip이 끝난다.** 앞 로봇 뒤에서 20 s 동안 0.05 m 미만으로 움직이면 trip은 정체(`stall`)로 끝나고 차선 주행을 끈다(`trip_ports.py`).
- **Fleet 루프는 한 대 기준이다.** 0.5 s마다 로봇 상태를 REST로 강제로 새로 읽고, 호출마다 1.5 s 한도를 둔다. 여러 대를 차례로 돌리면 주기를 지킬 수 없다.
- **출발 자리는 장소 id로 목적지가 될 수 없다.** 출발 자리는 차로 중간에 있어 그래프의 끝점이 아니다. 장소 id를 목적지로 주면 `TRIP_NO_ROUTE`다. 좌표로 주면 경로가 나온다. 2026-10-08 시연 지도(`map_v2_fleet`, `east`·`west` 일방)에서 출발-북 → 출발-남은 east → ring_n → west, 출발-남 → 출발-북은 west → ring_s → east다.

### Decision

**원칙.** 안전은 로봇이 혼자 지킨다. 순서와 간격은 Fleet이 정한다. Fleet이 정하지 못하면 로봇은 서 있고, Fleet 해결기가 규칙 → 사람 순서로 푼다. Fleet이 멈추거나 링크가 끊겨도 로봇은 받은 통행권 끝에서 선다. 그래서 더 위험해지지 않는다.

1. **로봇마다 trip 하나.** `TRIP_BUSY`는 "그 로봇에 진행 중 trip이 있음"으로 바뀐다. 사이트 전체 제한은 없앤다. trip 상태(계획, 구간, 교차로 지시, 정체 시계)는 로봇별로 둔다. 운영자 정지는 지금처럼 그 로봇의 trip을 끝낸다. 전체 정지(`cancel_all`)는 모든 trip을 끝낸다.

2. **반복 운행(lap).** `POST /trip`이 `repeat: true`와 경유지 순환 `via`를 받는다. 마지막 목적지에 닿으면 같은 순환의 다음 바퀴를 현재 자세에서 다시 계획하고, 운영자 확인 없이 이어 간다. 지도 버전이 바뀌거나 통행권 문제로 재계획이 실패하면 그 자리에서 서고 해결기(5항)로 넘긴다. 시연은 출발-북 ↔ 출발-남 두 장소의 순환이다.
   - **출발 자리를 목적지로.** 장소가 어떤 차로의 끝점도 아니면, 그 장소 id는 좌표와 `yaw`(`arrive_yaw`)를 준 목적지로 계획한다(D-489 6항의 좌표 붙이기). 차로 폭의 두 배 안에 붙일 차로가 없으면 지금처럼 거절한다.

3. **Fleet 블록 통행권(moving block).** 활성 지도의 모든 차로를 블록으로 나눈다. 블록 하나에는 로봇 한 대만 들어간다.
   - **블록 길이**는 사람이 고르는 숫자가 아니다. 로봇 몸체 길이, D-500 정지 거리(반응 + 감속, 그 차로의 속도 상한 기준), D-422 여유, 위치 불확실성 두 배를 더한 값의 최솟값보다 짧지 않게 Fleet이 계산한다. 차로가 그보다 짧으면 차로 하나가 블록 하나다. 시연 지도에서는 약 0.35 m(Pinky 0.118 m + 정지 0.12 m + 불확실성 2×0.05 m)다. 고리 7.6 m는 블록 약 20개가 된다.
   - **구역(D-474)은 블록 묶음이다.** 회전 교차로처럼 갈림과 합류가 있는 곳은 구역 하나로 묶고 수용 대수를 둔다(기본 1). 구역 안의 블록은 따로 주지 않는다.
   - **점유는 사실로 정한다.** 로봇의 지도 자세(`MapPose`)를 그 로봇 계획 위에 붙이고, 몸체 앞뒤 끝과 불확실성이 걸치는 블록을 모두 점유로 본다. 자세가 `LOCALIZED`가 아니면 마지막 점유를 UNKNOWN으로 두고 풀지 않는다. 그동안 이웃 블록도 주지 않는다(D-426 3항).
   - **요청과 허가.** trip 로봇은 계획을 따라 앞의 블록을 요청한다. 허가는 요청 시각 순서다. 구역 안에 이미 있는 로봇의 다음 블록이 먼저다(회전 교차로 우선). 한 번에 허가하는 앞 블록 수는 정지 거리를 덮는 만큼이다. 시연 속도에서는 1~2개다.
   - **고리 수용 한도.** 한 방향 고리에 올라갈 수 있는 trip 로봇 수는 "그 고리의 블록 수 − 구역 수용의 합 − 1" 이하다. 넘치면 출발을 `TRIP_LOOP_FULL`로 거절한다. 블록이 하나라도 비어 있으면 한 방향 고리에서 순환 대기가 생기지 않는다.
   - **일반 그래프의 교착.** 고리가 아닌 망에서는 매 주기 "누가 누구의 블록을 기다리는가" 그래프를 만들고, 순환이 있으면 해결기(5항)로 넘긴다. 계산은 로봇 수에 비례한다.

4. **로봇은 통행권 끝에서 선다(CORE 새 계약).** Fleet은 속도를 지시하지 않는다(D-18). 대신 trip 로봇에 **통행권**을 보낸다.
   - 형식: `{authority_id, leg_id, until_m, expires_at}`. `until_m`은 현재 trip 구간을 따라 허가된 마지막 블록의 끝까지의 거리다.
   - CORE는 그 지점 앞, 몸체 기준 정지 거리에서 선다. 통행권을 늘리면 다시 간다.
   - **만료하면 선다.** `expires_at`(발급 뒤 2 s) 안에 새 통행권이 없으면 CORE는 그 자리에서 선다. 이것이 Fleet 정지·링크 단절의 기본 안전이다. 감시 타이머(300 ms)와는 별개다.
   - 몸체 정지(D-422), IR 가드(D-491), E-stop은 통행권보다 먼저다. 통행권이 있어도 앞이 막히면 선다.
   - 통행권을 기다리며 서 있는 것은 정체가 아니다. 정체 시계는 통행권 안에서 움직이지 못할 때만 돈다.
   - 이 계약은 CORE 안전 경로 변경이라 API Reference, 공유 schema, Safety-Review를 거친다.

5. **막히면 로봇 → Fleet 해결기 → 사람.** D-494 14항을 고친다. 해결기는 trip 로봇도 다루고, 다음 중 하나면 그 로봇을 넘겨받는다.
   - CORE 막힘 이벤트(D-407).
   - 통행권 안에서 정체가 이어짐(앞에 다른 로봇이 없는데 못 감).
   - 교착 그래프의 순환.
   - 점유 UNKNOWN이 이어짐.
   - 시도 순서는 이렇다. (a) 앞에 로봇이 있으면 기다림(R1). (b) 막힌 차로를 `blocked`로 넘겨 다른 길 재계획(D-490, 지금은 비어 있는 입력을 연결). (c) 현장 근거가 있을 때만 짧게 후진(D-507 6항). (d) 사람. 시간 예산과 감사 기록은 D-438을 따른다. 모델 단계(D-492)는 그 ADR이 수락되면 (c)와 (d) 사이에 들어간다.

6. **Fleet 루프는 수십 대를 견딘다.**
   - 모든 trip 로봇의 판단은 한 주기(0.5 s)에 함께 한다. 로봇별 호출은 동시에 보내고 로봇마다 한도를 둔다.
   - 한 로봇의 지연이 다른 로봇의 주기를 막지 않는다. 늦은 로봇은 통행권을 늘려 받지 못해 스스로 선다.
   - 자세는 Rosy Cam 지도 자세를 먼저 쓰고, 로봇 REST 강제 읽기는 로봇당 1 Hz 이하로 줄인다.
   - 목표 규모는 로봇 30대, 지도 차로 200개, 주기 안 판단 시간 100 ms 이하다. 시험으로 잰다.

7. **단계와 수용.**
   - **M0 (순수 계산):** 블록 분할, 점유 판정, 허가 순서, 고리 수용 한도, 교착 그래프. 단위 시험으로 무작위 N대(최대 50대) 고리·격자를 돌려 블록 하나에 두 대가 들어가는 순간 0, 고리 순환 대기 0을 확인한다.
   - **M1 (Fleet):** 로봇별 trip, 반복 운행, 출발 자리 목적지, 해결기 연결. 가짜 로봇으로 2대·10대·30대 주기 시간을 잰다.
   - **M2 (CORE 통행권):** Safety-Review. 만료 정지, Fleet 정지, 링크 단절, 통행권과 몸체 정지 경합을 시험한다.
   - **SIM:** 모델 PC나 관제 PC의 Gazebo(이 노트북 금지)에서 `map_v2_fleet` 시연 고리 2대 30분 연속 주행. 접촉 0, 블록 중복 0, 사람 개입 0을 확인한다. 이어서 6대로 같은 시험을 한다.
   - **DEVICE/FIELD:** 2대 실물. 현장 지도(D-513 시연 지도)에서 10바퀴. 사람이 옆에 있고 E-stop을 쥔 채 한다.

### Alternatives

| 대안 | 판단 |
|---|---|
| 간격을 로봇 몸체 정지에만 맡김(D-451 그대로) | 두 대는 부딪치지 않지만 뒤차의 trip이 정체로 끝난다. 교차로 합류 순서도 없다. 기각 |
| Fleet이 속도를 직접 조절 | D-18 위반. CORE만 최종 명령을 낸다. 기각 |
| 시간 기반 경로 예약(시공간 A*) | 수십 대에서 처리량은 좋지만 실물 속도 편차에 약하고 재계획이 잦다. 블록으로 시작하고 처리량이 모자라면 다시 본다 |
| 바닥 표시로만 구역 판단(D-474 그대로) | 고리 전체에 표시를 그릴 수 없다. 구역 입구는 D-474 바닥 표시를 쓸 수 있고, 블록은 지도 자세를 쓴다 |
| Open-RMF 같은 외부 교통 관리 | 규모에는 유리하지만 지금 계약·인증과 따로 논다. 별도 ADR |

### Consequences

- 두 대 시연과 수십 대 군집이 같은 규칙을 쓴다. 다른 점은 블록 수와 고리 수용 한도뿐이다.
- 실물 동시 주행에는 Rosy Cam 지도 자세가 필수다. 위치가 확정되지 않은 로봇은 trip을 시작하지 못하고, 확정이 끊기면 선다.
- 시연 지도는 고리 차로를 일방으로 둔다(`east`, `west`). 양방 차로는 블록 허가가 마주 오는 두 로봇에게 같은 블록을 주지 않으므로 안전하다. 다만 가운데에서 서로 기다리면 교착이므로 해결기로 넘어간다.
- 고치는 결정 표: D-494 1항·14항(trip 한 대, 해결기 제외)은 이 ADR의 1·5항으로 바뀐다. D-451의 "같은 방향 간격은 로봇이"는 trip 로봇에는 3항 블록이 대신한다. D-474 구역은 3항 구역의 한 종류다.

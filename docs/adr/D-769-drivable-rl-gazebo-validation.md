## D-769 기존 drivable 검수 자료를 활용한 강화학습과 Gazebo Fleet 검증

**Status:** Accepted (2026-10-16, 사용자 방향 합의 및 ADR 기록 요청)

방향과 검증 순서를 승인한 결정이다. 구현·새 학습·정책 승격·배포·실물 수용을 뜻하지 않는다.

### Context

사용자는 이미 검수한 `drivable` 영역을 주행에 활용하려고 이 작업을 시작했다.
`wall` 클래스를 추가하는 일로 목표를 바꾸지 않고, 기존 영역 인식에서 주행·강화학습·Gazebo 검증까지 연결한다.

- [검수 자료 확인](../validation/drivable-reviewed-desktop-2026-10-11.md):
  `v13-drivable-human-20261010` 2,769장(train 2,167 / val 358 / test 244),
  모든 frame의 human_edit/done 및 image/mask 5,538개 hash 확인 기록이 있다.
  의미는 로봇에서 선을 넘지 않고 연결되는 바닥이다. 전체 도로면 정답으로 재해석하지 않는다.
  원본 영상 그룹이 split 사이에 겹쳐 독립 최종 평가 자료로 쓸 수 없다.
- [Gazebo 인계](../plans/2026-10-15-lane-regulation-sim-handoff.md):
  m30(drivable)과 m31(lane_marking, floor gate를 끈 진단)은 한 바퀴 안에 차로를 놓쳤다.
  m29의 15바퀴와 m36의 신호 포함 14바퀴는 대체 인식 실행이며 학습 인식 성공이 아니다.
  당시 `model-v1`이 위 검수 자료의 어느 학습 산출물에 해당하는지는 먼저 대조해야 한다.
- 기존 `drivable_target`은 연결 영역과 분기를 처리하고 `boundary_paint`로 기존 추종기에 연결한다.
  영역 인식 실패, 영역 가공·목표 생성 실패, 제어·실행 거절을 분리해야 한다.
  현재 floor gate는 lane_marking 경로에 wall 역할을 요구하지만 drivable 경로는
  drivable 역할로 시작할 수 있다. lane_marking 대체 경로의 wall 조건까지 없어지는 것은 아니다.
- [Isaac 진단](../validation/isaac-map-rl-2026-10-11/result.md)의 위치·지도 기반 완주는
  카메라 drivable 주행이나 실제 Fleet 연결의 완주가 아니다. 기존 Q-learning은 재사용 후보이지
  Gazebo에 연결된 학습 실행기로 간주하지 않는다.

### Decision

#### 1. 기존 drivable 자료와 모델의 계보부터 연결한다

첫 작업은 원본 dataset·검수 mask·classes·학습 run·export 모델·실행 pointer의 버전과 hash 대조다.
현재 모델이 검수분을 반영했는지 확인하기 전에 전체 재라벨링이나 wall 추가 학습부터 하지 않는다.
기존 이미지·mask·split·모델을 덮어쓰지 않고, 새 산출물은 별도 revision으로 남긴다.

D-659·D-663·D-665의 도로면/현재 구역/선택 경로 구분을 유지한다. 기존 자료에 semantic을
소급 부여하거나 `road_surface/1` 모델을 기존 조향 슬롯에 넣지 않는다. 구형 자료는 원래 의미의
기준선·개발 자료로 활용하며, 새 의미 선언·운영 전달은 해당 계약의 검수·출처 조건을 따로 충족한다.
이 ADR은 기존 shadow·delivery·POLICY admission 제한을 해제하지 않는다.

#### 2. 영역 인식과 주행 연결을 단계별로 진단한다

목표 흐름은 다음과 같다. 이는 책임 구분이며 새 API나 필드 선언이 아니다.

`camera -> drivable observation -> robot-connected region -> Fleet route direction -> Drive candidate -> CORE safety/final command`

Perception은 가시 영역과 불확실성을, World는 검증된 현재 자세·시각·보정/좌표 관계를,
Drive는 영역 안의 주행 후보를 담당한다. Fleet은 경로·통행권·교통 조정을 소유하고 CORE만
최종 명령을 발행한다. 학습 정책이나 지도 안내가 관측되지 않은 바닥을 관측 사실로 만들지 않는다.

고정 영상에서 RGB, 원시 drivable mask, 연결 영역, 분기 선택, 변환된 경계, 목표점,
후보 명령, 최종 명령과 거절 이유를 같은 시각으로 대조한다. 입력 resize/crop(기존 패키지의
320x240, rows 112..239), 카메라 보정, pixel→ground→map 좌표와 freshness를 확인한다.
미예측 crop 영역은 정상 배경이나 안전 영역으로 채우지 않는다.

기존 drivable_target/boundary_paint/추종기를 먼저 재사용한다. 영역은 맞는데 경계 변환이나
분기 선택에서 실패하는 것이 확인되면 그 공유 경로를 고친다. Fleet의 지정 방향과 후처리의
기본 우측 선택이 충돌하는지도 검사한다. 새 직접 영역 추종기는 필요가 입증된 뒤 별도 계약으로 정한다.

wall은 drivable 사용의 일괄 선행 조건으로 두지 않는다. 필요한 경로의 floor gate와 실제
LiDAR·몸체·경계 안전 검사는 유지한다. gate를 끈 m31은 진단 기록이며 운영 대안이 아니다.
영역의 hole filling·틈 메우기를 장애물 부재의 증거로 쓰지 않는다.

#### 3. 인식 모델을 고정한 뒤 제한된 주행 조절을 학습한다

초기 학습은 기존 주행기의 제한된 조향 보정으로 시작한다. 인식 모델과 주행 정책을 동시에
변경하지 않는다. Q-learning 등 기존 구현의 재사용 가능성을 먼저 확인하며 새 알고리즘이나
속도 행동 확장을 이번 결정의 필수 범위로 삼지 않는다.

정책 입력 후보는 현재 영역 형상·경계 여유·목표 방향·속도·관측 신뢰도다. 실제 구현 전에
관측 schema, action 범위, 보상·종료·시간 단위를 고정한다. 평가 중 정책은 갱신하지 않는다.
시뮬레이터 정답 자세·충돌 상태는 보상/독립 평가에 쓸 수 있지만 카메라 정책의 관측에 몰래 넣지 않는다.

보상은 지정 경로 진행·영역 내 유지·조향 안정성을 비교하도록 설계한다. 경계 이탈·충돌·
유효 목표 상실을 별도 기록하고, 인식/센서 오류와 정책 행동에 귀속할 수 있는 실패를 구분한다.
신호·횡단보도·Fleet 통행권의 정상 대기를 진행 부족이나 실패 벌점으로 처리하지 않는다.
무효 관측을 학습 state로 채우지 않으며 실제 적용된 행동과 transition을 결속한다.
CORE의 거절·정지·E-stop·watchdog·권한/관측 만료를 보상으로 우회할 수 없다.

#### 4. Gazebo를 기준 환경으로 학습 실행과 Fleet 평가를 연결한다

Gazebo의 기존 센서·CORE·Fleet 실행 경로를 재사용한다. 학습 실행기는 episode 시작,
정지 확인 후 reset, identity/epoch 격리, 관측·실제 적용 행동·보상, 종료·정리 기록을 연결해야 한다.
Isaac 실행기를 그대로 복제하거나 CORE 옆에 최종 명령 publisher를 만들지 않는다.
모델 PC의 learning 영역이 학습·정책 산출물을 소유하며 실행기와 Gazebo adapter의 상세 연결은
D-427 소유권에 맞춰 구현한다. 기존 원격 자원·예약 절차를 사용하고 노트북에서 실행하지 않는다.

같은 지도 계보(`map_v2_fleet` / `260919 MAP FILE.STL`), variant, 초기 자세·seed,
센서/보정·안전 설정·시간 한도에서 다음 세 조건을 분리해 비교한다.

| 조건 | 목적 |
|---|---|
| 대체 인식 + 기존 주행 | 기존 Fleet/CORE 기준선의 회귀 확인 |
| 고정 drivable 모델 + 기존 주행 | 인식·영역 연결의 성능 확인 |
| 같은 drivable 모델 + 학습 후 고정 정책 | 강화학습의 추가 효과 확인 |

각 frame의 실제 인식 출처와 fallback 사유를 기록한다. 대체 인식으로 달린 구간을 학습 인식의
성공으로 세지 않는다. 순수 drivable 비교에서는 fallback 발생을 별도 실패/보류로 판정한다.
train/eval의 source·seed·episode를 분리하고 실패 실행도 분모에서 빼지 않는다.

#### 5. 짧은 구간부터 독립 반복과 두 대 Fleet까지 검증한다

순서는 직선 → 굽이 → 유한 한 바퀴 → 새 초기화 반복 → 신호·횡단보도 → 두 대 Fleet다.
각 단계의 거리·시간·반복 수·허용 오차·성능 기준은 실행 전에 고정하며 결과를 본 뒤 완화하지 않는다.
첫 목표는 drivable 모델로 한 바퀴를 안정적으로 실행하고 같은 모델에서 강화학습의 추가 효과를
입증하는 것이다. 목표 상실률·경계 이탈·충돌·조향 변동·진행/완주율·정상 대기·정지·회복을 함께 본다.

Fleet의 arrived 이벤트만으로 완료하지 않는다. 실제 목표 위치·정지, lease 해제·CORE OFF와
최종 zero, 정리 결과를 함께 확인한다. map variant와 시나리오별 결과를 분리하고 다른 지도·
두 대 전체 코스·실물 수용으로 확대하지 않는다. 학습 정책이 기준선보다 낫지 않으면 채택하지 않는다.

#### 6. 재학습은 확인된 인식 실패를 보충한다

같은 영상의 단계별 재생에서 모델 자체의 실패가 확인되면 기존 검수분을 보존하면서
Gazebo의 굽이·바닥·횡단보도 등 부족한 장면을 추가 검수한다. 안전 조건이나 지도 형상을
학습 성공을 위해 바꾸지 않는다. 실제 카펫과 SIM 성능은 별도 집계해 기존 실물 성능의 회귀도 확인한다.
독립 최종 시험은 학습에서 제외하도록 예약한 원본 영상/실행 단위와 검수 정답을 사용한다.
기존 2,769장의 이미지 중복 없음만으로 독립성을 주장하지 않는다.

### Consequences

기존 drivable 검수 투자를 유지하면서 데이터/모델 연결, 인식, 영역 변환, 제어의 실패를
각각 확인할 수 있다. 성공한 대체 인식 주행을 학습 정책의 성과로 혼동하지 않는다.
새 학습 전에도 고정 영상 재생과 모델 계보 확인으로 다음 수정 범위를 좁힐 수 있다.

아직 필요한 것은 실제 모델 대조, 단계별 실패 재현, Gazebo 학습 lifecycle 연결,
독립 평가 구성과 정책 개선·완주 증거다. 이 기록 자체는 그 작업들의 완료 증거가 아니다.
실물 활성화·배포·정책 승격과 main 착지·push는 이번 ADR 작성 범위에 포함하지 않는다.

## D-468 차선 이탈은 로컬 복귀·재탐색을 먼저 소진하고 Fleet에 요청한다

**Status:** Accepted (2026-10-05, 사용자 ADR 결정·목표·구현 지시; SOURCE/DEVICE/FIELD 수용 별도)

### Context

사용자가 직선에서 흰 선을 넘어가는 실제 이탈을 보고했다. D-407은 장애물 또는 차선 소실을 처리하지만, 선이 계속 보이는 차선 침범을 감지하지 않는다. `lane_visible`만으로 복구를 종료하면 차로 밖에서도 재개할 수 있다. 기존 `ForwardTrail`은 명령 적분이며 실제 주행 경로가 아니다. 당시의 전체 odometry·영상 동기 기록이 없으므로 원인을 확정하거나 이전 위치를 재구성했다고 말할 수 없다.

사용자 추가 결정: 멈추고 Fleet에 묻는 것을 정상 복구 경로로 삼지 않는다. 로봇이 센서와 기록으로 해결을 먼저 시도하고 Fleet은 최후 수단이다. 안전 증거가 없으면 이동 출력은 영이지만 인식·위치 추정·복구 가능성 평가는 계속한다.

### Decision

1. **소유권:** perception은 원본 영상 시각에 묶인 지면 차선 경계와 품질을 제공한다. CORE line-follow는 실제 odometry 경로, 차체 침범 판정, 복구 상태와 제한된 명령 제안을 소유한다. 최종 출력은 기존 CommandManager 한 곳이다. 모델 PC는 실패 기록 검수·평가·학습을 담당하며 실시간 최종 명령을 발행하지 않는다.
2. **차선 침범:** 차체 footprint와 선택된 경계의 부호 있는 여유 및 예측 여유를 검사한다. 선의 가시성과 차로 내부 여부는 별개다. 완전한 양쪽 경계, 신선한 자세, 일관된 geometry에서 정상 차로 checkpoint를 만든다. 단일 경계는 그쪽 침범 증거가 될 수 있지만 전체 차로 안전을 증명하지 못한다. NOMINAL 투영을 보정 완료로 승격하지 않는다.
3. **실제 경로:** 원본 odom frame·timestamp·수신 시간과 SE(2) 자세를 저장한다. frame 변경, 시각 역행, 큰 위치 점프, stale pose이면 기존 경로를 무효화한다. 명령 적분을 실제 이동 거리로 대체하지 않는다. 처음 이탈한 순간 정상 checkpoint와 경계를 고정한다.
4. **로컬 폴백 순서:** `departure_stop`에서 이동을 감속/중단하고 (a) 현재 경계로 차로 방향·복귀 후보를 재추정, (b) 마지막 정상 경로가 있으면 충돌 검사한 짧은 구간을 실제 자세 피드백으로 역추적, (c) 기록이 없거나 역추적이 불가능하면 현재 센서로 빈 공간과 차로 후보를 재탐색, (d) 검증된 빈 공간에서만 제한된 회전/저속 정렬, (e) 차로 내부와 방향을 여러 연속 프레임으로 검증한 뒤 재개한다. 실패한 후보는 반복하지 않고 다음 후보/방법으로 넘어간다. 주행 공간을 입증할 수 없으면 정지 상태에서 인식·재위치 추정을 계속한다.
5. **복구 성공:** 같은 저장 차로의 경계 위치·방향과 차체 여유를 확인한다. 선이 보임만으로 성공하지 않는다. 저장 차로가 없으면 새 차로 후보를 명시적으로 검증하며 '이전 차로 복귀'라고 보고하지 않는다. 인접 평행 차로가 구별되지 않으면 성공 판정을 보류한다.
6. **제한:** 각 이동 후보는 거리·각도·시간·시도 횟수로 제한하고, 실제 자세로 진행을 확인한다. 전후방 및 회전 footprint의 신선한 장애물 증거, 바닥/낙하 위험 판단, E-stop, 제어 권한, live 속도 상한을 유지한다. 근거가 없는 reverse·spin·forward를 폴백으로 넣지 않는다. 센서가 복구되면 새 증거로 재평가하되 같은 무진척 동작을 무한 반복하지 않는다.
7. **Fleet 최후:** 로컬 방법별 거절/실패 원인과 사용한 증거를 남긴 후에만 기존 stuck 사건으로 Fleet 지원을 요청한다. Fleet 단절은 로컬 복구 시작을 막지 않는다. 사람의 진행 버튼을 각 로컬 단계의 필수 조건으로 만들지 않되 기존 유효한 운전 권한을 위조하거나 갱신 실패를 무시하지 않는다. D-407의 console-first 정책은 이 차선 이탈 경로에서만 supersede하며 다른 stuck/YIELD 계약은 보존한다.
8. **증거와 배포:** 침범/폴백 원인, 실제 자세, 선택/거절 경계, 적용 명령을 원본 영상 시각으로 보존한다. source 시험, 합성 폐루프, signed release 설치/readback, 실제 복구를 따로 보고한다. 구현되지 않은 폴백은 지원 가능하다고 표시하지 않는다. 실제 시험은 정상 checkpoint가 있는 이탈과 checkpoint 없는 시작을 모두 포함한다.

### Consequences

매니저 선택 조건은 기존 `recovery_local_enabled`를 사용한다. CAMERA_LINE의 typed containment와 차체 geometry가 있는 경우 D-468 판단이 일반 추종과 D-407보다 먼저 적용된다. 기존 관측·IR_LINE·이미 진행 중인 별도 stuck/YIELD 계약은 보존한다. 복구 후보는 원래 generation/evidence_revision으로 같은 CommandManager 경로에 제출되며, 실제 자세 변경·무효화와 제출 직전 이동 공간 판정 철회는 오래된 후보를 거부한다.

이동 근거 공급자는 원본 센서의 유효 기간·교정 출처·바닥과 실제 후보 swept path를 확인해야 한다. `(0, 0)`에 대한 참도 바닥 증거의 신선함을 요구한다. 미연결 공급자, 예외, 참이 아닌 응답은 이동 허가가 아니다. 현재 소스 연결과 실제 공급자의 런타임 연결·장치 수용을 구분한다. 공개 모드·명령·stuck 필드는 추가하지 않는다.

현재 이탈 위치에 정상 경로 기록이 없으면 바로 '원래 자리로 돌아가기'를 보장하지 않는다. 그 경우에도 현재 센서로 후보 탐색을 수행한다. 차선이 보이는 이탈과 차로가 없는 상태를 구별하는 추가 계약·검증이 필요하다. Accepted는 구현/설치/실주행 통과를 의미하지 않는다. 실행 순서와 남은 증거는 `docs/plans/2026-10-05-lane-return.md`에 기록한다.

## D-273 OMX 팔 제어와 작업 카메라 스트림은 고정 작업대에서 단계별로 결합한다

**Status:** Accepted (2026-09-26, implementation order only). 이 결정은 OMX 드라이버 구현, 영상 연결, 팔 동작 또는 DEVICE/FIELD 수용을 뜻하지 않는다.

**Context:** [OMX-AI ROS 2·카메라 검토 보고서](../reference/OMX_AI_ROS2_Camera_Report_2026-09-26.md)는 책상 고정형 OMX-AI, 상부 RGB, 경량 손목 RGB와 규칙 기반 집기 기준선 뒤의 ACT 실험을 제안한다. 현재 `omx_adapter`는 비활성 모델 중립 프로필과 `ros2_control` 계약만 검증하며 실제 드라이버·시리얼 포트·관절 상태 발행이 없다. `src/products/omx/config/omx.disabled.yaml`도 모델과 드라이버가 비어 있다. Pinky의 `camera/front`는 이동 로봇 관측용이고, D-152의 CORE 화면은 저주기 최신 JPEG 미리보기만 허용한다. D-55의 이동 조작 capability는 실물 모델·장착·하중·보정·복구 시험 전까지 비활성이다. 사용자가 요청한 첫 구현 목표는 **OMX 팔 조작과 카메라 스트림 연결을 함께 완성하는 것**이다.

**Decision:**

1. **첫 대상은 독립 고정 작업대다.** OMX-F 팔로워와 OMX-L 리더를 포함한 실제 구입 모델·리비전, 전원, 포트, 관절 순서·단위·그리퍼 표현을 실물과 제조사 자료로 확정한다. Pinky 탑재와 주행 중 조작은 이 단계에 넣지 않는다. 기존 로봇의 최종 `cmd_vel`은 CORE만 발행한다(D-38, D-55).
2. **제어 기준선을 영상보다 먼저 닫는다.** 선정된 공식 드라이버/제어 스택의 태그·커밋·의존성·RMW·장치 점유 방식을 고정한다. ROSY OS의 CycloneDDS 결정(D-117)과 벤더 스택의 통신 방식이 다르면 단순히 토픽이 통할 것으로 가정하지 않는다. 동일하게 검증한 RMW 구성이 없으면 명시적 제한 어댑터/브리지 계약을 별도 결정하고 시험할 때까지 통합을 HOLD한다. `omx_adapter`에서 검증된 관절 피드백과 trajectory 계약으로 연결하되, 가짜 `joint_states`나 가짜 hardware plugin으로 진입 조건을 채우지 않는다. ROS 제어와 native LeRobot이 같은 직렬 장치를 동시에 소유하지 않는다.
3. **팔 명령은 단일 권한과 정지 상태를 갖는다.** 리더 teleop, MoveIt/규칙 기반 작업, 향후 학습 정책은 한 순간에 하나만 관절 명령을 낸다. 명령마다 작업 ID·모드·기준 상태·보정 revision을 확인하고 유효하지 않거나 오래된 관절 상태, 제한 밖 목표, 충돌 미검증 경로를 거부한다. 연결 상실·worker 중단·재부팅 후에는 재연결만으로 이전 명령을 재실행하지 않고 HOLD에서 사람의 재확인을 요구한다. 소프트웨어 정지, 토크 해제, 전원 차단의 실제 물체 낙하/팔 처짐은 별도로 측정한다.
4. **상부 RGB 스트림을 먼저 연결한다.** OMX 작업 카메라는 Pinky의 `camera/front` 및 사이트 천장 카메라와 다른 source/frame/profile을 사용한다. 지속 식별되는 USB 장치에서 원본 프레임과 같은 촬영 시각의 `CameraInfo`를 로컬 인식·기록 경로에 제공한다. 해상도·FPS·노출·초점·조명·프레임 유실·지연을 프로필/계측값으로 기록하고, 유한한 최신 프레임 큐와 stale 거부를 둔다. 렌즈, 작업대 평면, 카메라→팔, TCP 보정을 revision으로 묶고 별도 3×3 기준점에서 좌표 오차를 검증한다. 카메라가 보인다는 사실만으로 집기 좌표가 유효하다고 보지 않는다.
5. **화면용 미리보기와 제어용 영상은 분리한다.** 제어 PC의 로컬 원본 스트림은 인식·동기화·데이터 수집에 사용한다. CORE 대시보드에 표시할 경우 D-152의 최대 2 FPS·640 px·최신 1장·인증/lease 상한을 지킨다. 고속 브라우저 스트림이나 원격 팔 조작은 이 결정으로 열지 않는다. 필요해지면 미디어 전송, 사용자 권한, 지연, stop 경로를 별도 ADR과 API 계약으로 승인한다. Fleet·사이트 서버에는 원본 영상이나 로봇 DDS를 중계하지 않는다(D-118, D-269).
6. **규칙 기반 집기 경로를 먼저 만든다.** 가벼운 부품 한 종류와 지정된 시작 구역·트레이를 고정한다. `검출 → 좌표 유효성 확인 → 접근 → 파지 → 이송 → 놓기 → 결과 확인` 각 단계의 관절/영상 시각과 실패 이유를 남긴다. 카메라 중단, 좌표계/보정 불일치, 그리퍼 상태 불명확, USB 분리, 정지 실패는 명령 중단과 HOLD로 처리한다. 결과 불명확 시 자동 집기 재시도는 하지 않는다.
7. **손목 RGB와 학습은 기준선 이후에 붙인다.** 상부 카메라·규칙 기반 집기의 장치 시험이 통과하면 손목 카메라의 브래킷·케이블·가반하중을 자세별로 측정하고 새 보정 revision을 만든다. 리더 시범과 영상·관절·명령을 동기화해 먼저 10개 에피소드의 정합을 검사한 뒤 수집을 확대한다. ACT는 별도 훈련/평가 경로에서 규칙 기반 기준선과 비교한다. 모델 출력도 3항의 단일 권한·한계·정지 검증을 통과해야 하며, 학습 성공이 팔 안전 수용을 대신하지 않는다.

**Implementation order and gates:**

| 순서 | 작업 | 다음 단계 진입 조건 |
|---|---|---|
| P0 | 실물 OMX 모델·호스트·드라이버·RMW·정지 수단 결정 | 버전/장치/포트 소유권 기록; 통신 경계와 수동 정지 절차 검토 |
| P1 | 저속·무하중 관절 제어와 피드백 | 단일 명령 소유, 한계/통신 상실/재시작 시험, 실물 상태 readback |
| P2 | 상부 RGB와 보정·TF·작업면 | 지속 장치 식별, 연속 30분 스트림·재부팅 시험, 별도 3×3 오차 측정 |
| P3 | 고정 좌표와 규칙 기반 집기 | 분리된 30회 중 27회 성공을 초기 실증 목표로 측정하고 모든 실패/정지/개입 기록; 수치는 생산 신뢰도 증거가 아님 |
| P4 | 경량 손목 RGB와 시범 기록 | 추가 질량·간섭·보정 통과, 10개 파일럿의 영상·관절·명령 정합과 세션 분리 |
| P5 | ACT 비교 및 선택적 확장 | 새 시작 조건의 성공률·주기·개입률·지연을 P3와 비교; 깊이/Pinky 연계는 병목과 별도 게이트가 있을 때만 |

**Consequences:** OMX 관련 구현은 `src/devices/omx/adapter`의 장치 경계와 `src/products/omx`의 설정 경계를 유지한다(D-232). 새 외부 팔 명령/API, 미디어 endpoint, capability 선언, 이미지의 `vision`/`omx` slice 활성화는 이 ADR만으로 승인되지 않는다. 필요한 각 계약은 API Reference와 공유 schema를 같은 변경에서 갱신하고(D-18), 해당 장치/릴리스 게이트를 통과한 뒤 노출한다. 현행 비활성 프로필과 CORE 화면 제한은 그때까지 유지한다.

**Validation / Transition:** P0/P1의 계약과 fault 시험은 SOURCE/LOCAL, 실제 ROS graph·시뮬 관절 경로는 ROS-SIM, 잠긴 버전의 설치 산출물은 ARTIFACT로 각각 기록한다. 실제 OMX·카메라·제어 PC의 영상 품질, 지연, 보정 오차, 하중, stop/전원 상실 후 거동과 집기 결과는 DEVICE에서 계측한다. Pinky 정지/도킹과 고정 OMX의 연계는 별도 FIELD 수용이다. P0–P4의 물리 증거가 없으면 `omx` capability와 이동 조작을 활성화하지 않는다. 보고서의 6–8주 일정은 장비 도착 뒤 실험 순서이며 납기나 안전 보증이 아니다.

## D-1028 Robot 운용 콘솔 좁은 화면의 읽기 순서: 머리, 운전 모드, 카메라, 지도

**Status:** Accepted (2026-11-14)

### 배경

사용자가 ROSY UI 콘셉트([2026-11-14-rosy-ui-concept.md](../superpowers/plans/2026-11-14-rosy-ui-concept.md))와 화면별 읽는 순서 명세([2026-11-14-rosy-ui-screen-specs.md](../superpowers/plans/2026-11-14-rosy-ui-screen-specs.md))를 승인했고 후속으로 "나머지 ui ux 도 더 개선하고"라고 했다. 명세 6절의 390 순서는 머리, 띠, 운전 모드, 카메라, 지도, 접힌 진단이다.

지금 순서(지도 → 조작 → 감지)는 [2026-10-08 운용 지도·경로 화면 검토](../validation/uiux-robot-navigation-stage-2026-10-08/result.md)의 "모바일에서 지도는 첫 관측 영역"과 그 후속 "보이는 순서와 키보드 순서 일치"가 정했다. 번호가 있는 ADR은 아니고 시험 네 곳이 그 순서를 지킨다(`test_role_g2_browser.py`, `test_surface_layout_browser.py`, `test_surface_viewport_budget_browser.py`).

### 결정

1. 64rem 미만 `/console`의 슬롯 순서를 **banner(머리·띠) → act(운전 모드·수동 운전) → sense(카메라) → observe(지도)** 로 바꾼다. 2026-10-08 검토의 모바일 지도 우선 순서만 대체한다. 넓은 화면의 감지 → 관측 → 조작 3열과 지도 첫 화면 규칙 이외의 항목(지도 무대·레이어 버튼 순서, 지도 ID 정합성)은 그대로다.
2. 보이는 순서와 키보드 순서는 같다. `shell.js`의 `syncSlotOrder`가 DOM 순서를 정하고 `shell.css`의 격자 영역이 같은 순서를 쓴다. 폭이 바뀌어도 패널을 다시 mount하지 않고 초점을 되돌려 놓는다(기존 계약).
3. 비상 정지는 머리(`#shell-estop`)에 있고 모든 폭에서 맨 앞이며 늘 활성이다. 이 결정은 정지 경로를 바꾸지 않는다. 수동 운전은 계속 `act` 슬롯 안에 있어 지도보다 앞이고, 영상 피드백인 카메라가 바로 뒤에 온다.
4. 시험 기준: 좁은 화면에서 운전 모드가 첫 화면에 보이고 `act < sense < observe` 순서다. 지도 캔버스의 첫 화면 위치(`canvasTop < 700`)는 더 이상 기준이 아니다. 지도 오류 상태판과 재시도, 지도 ID 불일치 문구 시험은 그대로다.

### 검토

패널(Claude, opencode glm-5.3, agy) 중 opencode는 "콘솔 수동 운전은 저속 넛지이고 피드백은 지도 위 위치"라는 이유로 지도 우선 유지를 주장했다. 기각 이유: 넛지의 피드백인 카메라가 조작 바로 아래에 오고, 지도는 한 화면 아래에서 곧바로 이어지며, 명세와 사용자 승인이 머리 → 운전 모드 → 카메라 → 지도다. 모터 상태 접힘 진단 재구성은 별도 과제다.

이 결정은 실물 장치·현장 조명·제품 전체 UI/UX 수용을 선언하지 않는다.

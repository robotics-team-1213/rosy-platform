## D-514 객체·픽셀 검수는 서로 다른 클래스 계약을 쓰고, 물체 종류와 통로 점유 판단을 분리한다

**Status:** Proposed (2026-10-08, 사용자 요청에 따른 검수 기준 초안; 클래스셋 전환·학습·로봇 배포 미승인).

관련 결정: [D-423](D-423-camera-object-range-detection-and-model-slots.md), [D-459](D-459-pinky-persistent-label-review-application.md), [D-462](D-462-incremental-pinky-pixel-review-and-current-decisions.md), [D-464](D-464-pinky-indexed-review-dataset-build.md), [D-485](D-485-review-app-class-sets.md).

### Context

같은 사진에서도 객체 검수는 **개별 물체의 박스와 종류**, 픽셀 검수는 **영상 각 픽셀의 표면/영역**을 결정한다. 두 검수는 독립 revision·승인이다(D-462). D-485는 작업 공간당 객체 클래스셋 하나와 픽셀 클래스셋 하나를 불변으로 묶지만, 현장 판단 기준까지 정하지는 않았다.

현재 로봇 `object_det` 계약은 `robot, obstacle_box, cone, traffic_light, sign, person_feet` 여섯 종류다(D-423). 별도 검수용 `object_review_obstacle_v1.yaml`은 일곱째 `obstacle`을 “주행 경로를 막는 미분류 물체”로 정의한다. 이 이름에는 물체의 종류와 사진 속 위치 판단이 섞여 있다. 더구나 `vision_review_drafts.py`의 2차 질의는 **모든** 박스를 바닥 위 통로 차단 물체로 제한해, 바닥에 있지 않은 `traffic_light`·`sign`의 초안 누락을 만들 수 있다. 실제 v12 초안에서도 벽의 파란 표시를 물체로 잡은 오검출이 있었다. 모델의 두 번 일치, 빈 박스, 이미지 한 장의 위치 추정만으로 정답·통로 안전성·사람 승인을 증명할 수 없다.

### Decision

1. **작업별로 클래스의 질문을 고정한다.** 객체 클래스는 “보이는 독립된 물리적 실체가 무엇인가”에 답한다. 픽셀 클래스는 “이 좌표가 어떤 표면/영역인가”에 답한다. 동일 사진에서 객체 박스와 픽셀 영역이 겹쳐도 모순이 아니다. 예를 들어 바닥 위 상자는 `obstacle_box` 박스이고 상자에 가린 바닥 픽셀은 추정해 채우지 않는다. 객체 승인으로 픽셀 승인 또는 그 반대 승인을 만들지 않는다.
2. **위험·위치·상태는 클래스명이 아니다.** 통로 안/밖, 이동성, 바닥 접점, 가림, 거리, 신호 색은 해당 물체의 별도 관찰 또는 판단 근거다. 현재 검수 export가 그 속성을 담지 못하면 클래스명에 우겨 넣지 않고 검수 메모/보류로 남긴다. `traffic_light.signal_state`처럼 기존 계약이 있는 필드만 쓴다. 위험/정지 결론은 카메라 클래스에서 내리지 않는다(D-423).
3. **현재 7클래스 `obstacle`은 기존 작업 공간의 의미를 유지한다.** 이미 묶인 클래스셋은 이름과 순서로 SHA가 정해지므로(D-485), `obstacle`의 뜻을 “모든 미분류 물체”로 바꾸면 SHA는 같아도 라벨 의미가 달라진다. 기존 승인·초안은 재해석하지 않는다. 다음 검수 클래스셋에서는 `other_object`처럼 새 이름을 써서 “종류를 더 구체화할 수 없는, 영상에서 분리되는 물리적 물체”를 표현한다. 통로 점유는 그 선택 조건이 아니다. 새 이름·순서·작업 공간을 먼저 고정하고, 기존 데이터의 재라벨 여부는 이미지별 사람 검수로 결정한다. `other_object`를 D-423 로봇 6클래스에 자동 추가하지 않는다.
4. **판별 불가를 정답 클래스로 만들지 않는다.** 독립 물체가 아닌 벽·그림자·도색·반사·바닥 무늬에는 박스를 만들지 않는다. 물체 존재는 보이나 종류를 알 수 있으면 새 검수셋의 `other_object` 후보로 두고 사람이 확인한다. 존재 자체·경계·가림 뒤 부분이 불확실하면 임의의 박스/픽셀 정답을 만들지 않고 해당 작업을 pending으로 둔다. 픽셀의 미확인 값 255는 `ignore_index`이지 클래스가 아니다. `crosswalk`/`speed_bump`의 role `ignore`는 클래스 인덱스가 있는 출력 채널이라는 뜻이며 255와 다르다.
5. **LLM 초안은 클래스별 질문으로 검증한다.** 공통 조건은 보이는 실체와 타이트한 박스다. 바닥 접점·통로 점유는 `obstacle_box`, `cone`, 일반 물체 등의 상황 근거로 물을 수 있지만 `traffic_light`·`sign`·사람의 보이는 발에 일괄 강제하지 않는다. 2차 모델 일치는 초안 필터일 뿐 승인 근거가 아니다. 근거가 빈약하거나 두 질의가 다르면 사람의 대기열로 보내고, 답을 비워둔 경우도 사진 전체 확인 후에만 음성 라벨로 승인한다.
6. **소비 경계를 드러낸다.** 객체 내보내기는 객체 클래스셋의 task·순서·SHA와 승인 revision을 보존한다. 픽셀 내보내기는 `classes.yaml` 원본 SHA·인덱스·role·255 규칙을 보존한다. 객체 7클래스 자료는 D-423 6클래스 모델 학습·서명·배포 입력으로 자동 통과시키지 않는다. 새 모델 계약은 별도 ADR·평가·매니페스트 변경 후에만 가능하다. 픽셀 `background`는 “보이지 않는 바닥을 추정해 칠함”이 아니며, 비어 있는 배경/가림/확인 불가를 구별해 검수한다.

### 검수 시나리오와 다음 행동

| 사진에서 확인한 사실 | 객체 박스 | 픽셀 마스크 | 검수자 행동 |
|---|---|---|---|
| 파란 벽 표시, 그림자, 반사 | 없음 | 보이는 표면만 해당 클래스; 경계 불명은 255 | LLM 박스 삭제, 두 작업을 따로 확인 |
| 통로 안 상자·콘 | 해당 물체 종류 | 물체 뒤 바닥을 추정하지 않음 | 경계 수정, 통로 여부는 별도 판단 |
| 통로 밖 상자·콘 | 같은 물체 종류 | 보이는 픽셀만 | 위치 때문에 박스 종류를 바꾸거나 지우지 않음 |
| 고정 벽·난간·기둥 | 기본적으로 물체 박스 없음 | 해당 셋에 `wall`이 있으면 벽; 없으면 검증된 표면/255 | 독립 물체인지 불명확하면 pending |
| 표지판·신호등이 바닥에 닿지 않음 | 보이는 `sign`·`traffic_light` | 가려진 부분을 추정하지 않음 | 2차 LLM의 바닥 조건 때문에 버리지 않음 |
| 사람의 발만 보임, 다른 로봇 일부가 보임 | 식별 가능한 보이는 부분만 `person_feet`·`robot` 후보 | 가림 뒤 픽셀은 255 | 보이지 않는 전체 몸체/차체로 박스 확장 금지 |
| 종류가 불명확한 독립 물체 | 새 셋의 `other_object` 후보; 기존 셋은 기존 `obstacle` 규칙 | 보이는 표면만 | 새/기존 작업 공간의 클래스셋을 확인하고 사람 검수 |
| 차선·횡단보도·과속방지턱·주행 가능 바닥 | 일반적으로 물체 박스 없음 | 연결된 픽셀 클래스셋의 이름·role대로 | 다른 픽셀 셋의 클래스명/인덱스를 이식하지 않음 |
| 물체가 없거나 사진이 심하게 가림 | 사진 전체 확인 후 빈 객체 승인 가능; 불명확하면 pending | 확인 가능한 픽셀만, 나머지 255/pending | 빈 LLM 응답을 자동 승인하지 않음 |

### 적용 순서와 검증

1. 모델 PC의 다음 초안 생성에서 먼저 2차 질의의 일괄 “바닥 위 통로 차단” 조건을 클래스별 조건으로 고친다. 벽 표시, 통로 밖 물체, 매달린 표지판, 부분 가림, 빈 사진을 회귀 장면으로 확인한다. 기존 초안·승인 데이터는 덮어쓰지 않는다.
2. 검수 화면에 현재 **객체/픽셀 작업**, 클래스셋 이름·SHA, 각 클래스의 포함/제외 사례, 255와 role `ignore` 차이를 표시한다. 화면에서 고른 클래스는 현재 작업의 셋만 사용한다. 새 클래스셋은 새 `--state`에서 시작하고, old→new 자동 변환은 하지 않는다.
3. 실제 이미지로 클래스별 오검출·누락과 사람 수정 건수를 기록하고, 객체·픽셀 각각 승인/대기/제외, 내보내기 SHA, 최신 revision 검사를 확인한다. 별도 데이터 출처·평가 분리·trainer admission(D-464) 없이는 학습 자격을 주장하지 않는다. 호스트/브라우저 확인은 모델 PC 실행·장치/현장 수용과 별개다.

### Alternatives

- 기존 `obstacle`을 위치와 무관하게 재정의: 동일 SHA의 기존 라벨 의미가 달라져 기각.
- 통로 안/밖·움직임·가림의 모든 조합을 클래스로 증식: 데이터가 희박해지고 객체 종류와 판단을 섞으므로 기각.
- 객체와 픽셀에 공통 클래스 목록 하나를 강제: 박스와 면의 질문·인덱스·승인이 달라 기각.

### Consequences

이 ADR은 검수 의미와 후속 구현 순서를 제안한다. 현재 작업 공간, v12 초안, D-423 manifest, D-485 binding 및 D-464 학습 admission은 이 문서만으로 바뀌지 않는다. 새 검수 클래스셋·모델 PC 재생성·화면 반영·실제 승인/학습은 각각 구현과 증거가 필요하다.

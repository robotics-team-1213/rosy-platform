## D-590 Pilot Android의 두 로봇 공용 조이스틱

**Status:** Accepted (2026-10-10, 사용자 요청; SOURCE·DEVICE와 FIELD 수용은 별도)

### 배경

D-582는 한 태블릿에 두 독립 WebView를 붙여 각 로봇을 따로 조종한다. 운영자는 로봇 목록에서 두 대를 선택해 **조이스틱 하나**로 같은 속도·회전 명령을 보내려 한다. 앞으로의 leader/follower는 두 로봇의 위치와 간격을 제어하는 다른 기능이다(D-20·D-60·D-559).

### 결정

1. 로봇 목록에 `2대 함께 조종`을 둔다. 첫 번째와 두 번째 로봇을 각각 선택·인증한다. 같은 `robot_id`를 두 번 쓰지 않는다. 두 카메라와 하나의 공용 조이스틱을 별도 Android 화면에 표시한다. D-582의 독립 화면은 기존 진입 경로로 유지한다.
2. 앱은 두 CORE의 `system/capabilities`에서 `teleop`·`base_velocity` 상한을, `safety/state`에서 현재 수동 상한을 읽는다. 둘 중 작은 선속도·각속도를 공통 상한으로 사용한다. 상한이 없거나 0이면 무장하지 않는다. 두 카메라의 최근 프레임도 요구한다. 운영자가 `두 로봇 수동 조종 시작`을 누르면 각 CORE에 `MANUAL`을 요청하고 둘 다 성공한 뒤에만 조이스틱을 무장한다.
3. 손가락이 닿아 있는 동안 공통 `{linear, angular}`를 두 로봇의 독립 인증 연결에 병렬로 전송한다. 가속은 점진적으로 올리고 손을 떼면 즉시 0으로 내린다. 카메라가 낡거나 한 로봇의 명령·연결·승인이 실패하면 함께 무장을 해제하고 두 로봇에 0을 요청한다. 앱 종료·화면 꺼짐·목록 복귀에도 두 프록시가 각 CORE에 0을 보낸다. 닿지 않는 로봇의 최종 정지는 CORE teleop watchdog(SAF-002)에 맡긴다.
4. 같은 명령은 같은 **경로·간격**을 보장하지 않는다. 화면에서 leader/follower가 준비 중임을 분명히 보인다. 이 진입점은 `swarm/follow`를 호출하지 않고 대형·오프셋·자취 추종의 권한을 주장하지 않는다.

### 검증 경계

- SOURCE: 두 독립 CORE가 같은 명령을 받고, 무장·해제·한쪽 거절·연결 실패에서 두 정지 요청이 발생하는지 확인한다.
- DEVICE: 실제 태블릿에 두 카메라, 단일 조이스틱, 로봇 ID가 보이는지 촬영한다. 비영(非零) 명령은 보내지 않고 정지 경로를 확인한다.
- FIELD: 두 로봇의 안전 공간에서 동시 주행·손 떼기·한쪽 단절·물리 정지를 별도 측정한다. SOURCE와 DEVICE만으로 동시 주행을 수용하지 않는다.

**관련:** D-2, D-20, D-60, D-193, D-323, D-343, D-411, D-460, D-559, D-582, SAF-002.

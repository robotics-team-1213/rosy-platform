## D-278 역할별 표면은 작업 흐름으로 구분하고 색은 의미를 지킨다

**Status:** Accepted (2026-09-26). 화면 구조는 기존 역할 계약을 따른다. UI 보완은 CORE 로컬 브라우저에서 검토했다.

잇는 결정: D-263 메뉴 책임과 확장 · D-265 기반 화면 · D-270 표면별 역할 게이팅 · D-277 ROSY 브랜드 색 토큰.

**Context:**

기반 화면은 역할별 작업 질문으로 나뉘어 있다. `/console`은 지금 로봇을 운용·관찰하는 곳이고, `/setup`은 작업 전 준비, `/device`는 설치·정비다. 실제 권한 매니페스트도 viewer는 console, operator는 console/setup, administrator는 세 화면을 연다. 메뉴의 역할 구분은 맞지만, 지도의 위치·주행 목표 선택은 viewer에게 조작 가능한 것처럼 보였고 모바일에서는 지도 레이어 버튼이 세로로 쌓였다. 이와 함께 ROSY 장미색 팔레트가 브랜드와 상태를 혼동시키지 않는지 다시 확인한다.

**검토 기준:** 작업 적합도, 권한 경계의 명료성, 기능 찾기, 인지 부하, 안전 접근성, 소유·변경 비용. 각 항목은 1(낮음)부터 5(높음)까지 같은 가중치로 평가한다.

| 대안 | 작업 적합 | 권한 명료 | 발견성 | 인지 부하 | 안전 접근 | 소유 비용 | 합계 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 한 화면에서 역할별로 컨트롤을 숨김 | 2 | 2 | 3 | 2 | 4 | 3 | 16 |
| 공통 셸 아래 작업별 표면을 역할에 따라 제공 | 5 | 5 | 5 | 4 | 5 | 5 | 29 |
| 역할마다 별도 웹 앱을 운영 | 4 | 5 | 4 | 5 | 4 | 1 | 23 |

**Decision:**

1. 작업별 기반 화면과 공통 셸을 유지한다. Viewer는 운용 상태·지도·카메라를 보고, Operator는 여기에 운전·수동 운전·도킹·차선 조작과 작업 준비를 더한다. Administrator는 설치·정비와 장치·네트워크·보안 및 관리자 전용 등록 기능에 들어간다. 새 메뉴는 사용자 질문과 URL·권한·표면 소유가 확인될 때만 추가한다.
2. 조작 화면은 존재를 숨기지 않고 사용할 수 없는 이유를 함께 보여준다(D-270 B). 지도 초기 위치·주행 목표 선택은 Operator 이상과 실제 Navigation 지원이 함께 확인될 때만 활성화한다. 그 외에는 native disabled 상태, `aria-describedby` 설명, 화면 내 이유를 제공한다. 지도 캔버스 클릭·키보드 확정도 같은 권한·지원 조건을 다시 확인한다. API가 최종 권한 판단자다.
3. Setup·Device는 절차 화면이므로 역할 밖 패널과 화면 경로를 감춘다(D-270 A). 관리 전용 도크 등록과 장치 정비는 operator 준비 흐름에 끼워 넣지 않는다.
4. 공통 셸은 ROSY 워드마크, 역할, 현재 표면, 비상 정지를 소유한다. 비상 정지는 모든 역할에서 같은 위치에 두며 실행 응답은 물리적 정지 증거로 말하지 않는다.
5. D-277 팔레트의 의미를 유지한다. Rose는 브랜드 표식과 현재 메뉴에만 쓰고, 위험은 빨강, 주의는 호박색, 포커스·데이터는 파랑, 일상 조작은 중립색으로 둔다. 역할별로 색상을 바꾸지 않는다. 지도 다중 선택은 주요 명령의 밝은 면과 구분되는 중립 상승면으로 표현한다.
6. 모바일에서는 비상 정지 문구를 한 줄로 유지하고 세 지도 레이어를 가로 그룹으로 배치한다. 모든 컨트롤은 기존 44px 최소 대상 크기를 유지한다.

**Alternatives:**

- 기존 `/dashboard` 한 장에 권한별 컨트롤을 더 숨기는 방법은 화면 질문이 다시 섞이고 매니페스트·URL·소유 경계가 생기지 않아 제외했다.
- 역할마다 앱을 복제하면 현재보다 짧은 동선은 만들 수 있지만 로그인·안전 셸·테스트가 중복되어 메뉴 확장 비용이 커진다.
- 브랜드 장미색을 모든 버튼 또는 상태에 확대하는 방법은 비상·주의·데이터 의미를 덮으므로 제외했다.

**Consequences:**

표면과 역할 매니페스트가 메뉴의 기준이다. 패널 추가는 상단 메뉴를 자동으로 늘리지 않는다. UI가 역할·capability 경계를 설명해도 API 권한 검사를 대신하지 않는다. 색은 역할 대신 브랜드·상태·포커스·데이터의 구분에 사용한다.

**Validation:**

- 실제 `CoreServices.build()`와 FastAPI를 띄운 CORE 로컬 서버에서 viewer/operator/administrator를 각각 검토했다. Viewer는 console만, operator는 console/setup, administrator는 console/setup/device가 표시됐다. operator setup에 관리자 전용 패널이 나타나지 않았고 administrator만 `setup.dock_admin`과 device 패널을 봤다.
- Viewer 지도 조작은 두 역할 버튼 모두 비활성·사유 연결, operator 화면은 실행 가능한 경우에만 활성이다. 시험 프로필에서는 Navigation이 미제공이라 operator 지도 조작도 비활성이고, 그 이유를 표시한다.
- 1440px 및 390px에서 수평 넘침이 없고 E-stop은 유지된다. Rose 대비는 ground 9.39:1, wash 8.72:1, muted 본문은 ground 6.55:1이다. E-stop foreground/background는 5.31:1이다.
- `src/hmi/dashboard/test`, `src/hmi/web/test/test_palette_gates.py`, `src/runtime/api_web/test/test_surface_manifest_api.py`, `test_ui_manifest.py`, `test_ui_route.py`를 실행한다. 이 CORE-only 브라우저 검토는 map response 미제공과 host-agent 미연결 상태를 포함하며 ROS-SIM/장치/현장 수용을 뜻하지 않는다.

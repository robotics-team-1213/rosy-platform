# D-681: 교체 가능한 판정 모델과 모델 주도 사건 종결

- Status: Accepted
- Date: 2026-10-12
- Related: D-527, D-640, D-652, D-657, D-672, D-679

## Context

최종 목표는 로봇 월드와 현장의 다양한 문제를 모델들이 빠르게 판단·해결하고 경험으로 개선하는 것이다. 사람이 매 판단을 승인하는 운영은 목표에 맞지 않는다. 모델이 응답한 확률 자체를 실측 정확도 또는 실행 권한으로 취급하는 운영도 목표를 만족하지 못한다. Qwen·GLM뿐 아니라 Jev·Laya 등 후속 판정 모델도 교체 가능해야 한다.

## Decision

### 책임과 배치

Fleet은 사건 식별·관측 근거·판단 기준·현재 상태·durable 원장·처리 파이프라인을 소유한다. Decision은 공통 판정 계약, 응답 검증, 모델 간 비교와 다음 단계 선택을 소유한다. AI PC는 운영 추론과 격리된 제공자 실행을 담당한다. Model PC는 독립 평가·확률 보정·개선 후보의 비교를 담당한다. CORE와 기존 장치 실행 소유자는 최종 안전 검사와 명령 발행을 유지한다. 모델의 상황 추론은 월드 모델의 근거를 소비하지만 Fleet 사건 원장과 실행 권한을 대체하지 않는다.

### 처리 루프와 사람 인수

`관측 → 미개입/개입 판단 → 기본 모델 → 불일치 재평가 → 제한된 다음 단계 → 현재 상태 재검사 → 기존 허용 경로에서 처리 → 결과 관측 → 종결/추가 관측 → 실패 피드백`을 기본 루프로 한다. 정상 상태는 미개입으로 종결하며 불필요한 호출·명령을 만들지 않는다. 근거 부족이면 허용된 관측 수집을 먼저 시도한다. Qwen과 Fleet 또는 모델들 사이의 불일치는 같은 사건의 근거로 재평가한다. 재평가 합의만으로 성공·안전을 기록하지 않는다.

사람은 허용된 모델·관측·처리 예산을 소진했거나, 지원하는 처리 방향이 없거나, 최종 결과를 확인할 수 없는 사건을 인수한다. 위험·권한 거절 상태에서는 처리 명령을 중단하지만 허용된 원인 조사와 근거 수집은 계속할 수 있다. 인수에는 사건·시도·판단 차이·현재 위험·필요한 최종 검토를 함께 보낸다. Discord·Slack·Telegram은 같은 인수/outbox 계약의 전달 어댑터이며 전송 성공과 사람 인수를 구분한다. Discord 실제 설정은 담당 세션이 수행한다.

D-679의 최초 GLM 연결 시험은 여전히 합성 1건·1회·출력 1,024 토큰·30초·무재시도이며 검토 완료 HOLD다. 운영 자동 처리는 아래 독립 평가와 기존 실행 admission을 충족한 별도의 승인 프로파일로 도입한다. 연결 시험의 HOLD를 영구적으로 모든 사건에 요구하지 않는다.

### 공통 JSON 판정 계약

다음 버전의 판정에는 아래 정보를 담는다. 구현 시 버전된 schema와 CLI·로컬·HTTP 어댑터의 conformance 시험을 함께 추가하며 기존 D-640 응답 형식은 유지한다.

| 항목 | 의미와 검증 |
|---|---|
| schema_version / profile_revision | 판정 형식과 정확한 실행 모델·프롬프트 revision |
| subject_id / case_id / generation / input_hash | Fleet의 동일 사건·관측·판단 기준에 묶인 식별자 |
| verdict | 미개입·추가 관측·처리 후보·기권 중 하나 |
| alternatives | 허용된 처리 방향별 확률; 유한한 0..1, 중복 없음, 합계 1 |
| evidence_ids / missing_evidence | 기존 근거의 참조와 아직 확보하지 못한 근거; 근거 생성 금지 |
| objections | 위험·근거 부족·판정 충돌; 높은 확률로 위험 이의를 지우지 않음 |
| next_step | 공통 catalog의 허용 단계와 필요한 근거; 임의 명령·코드 금지 |
| success_check | 어떤 현재 관측으로 성공/실패를 확인할지; 모델의 자기 선언만으로 종결 금지 |

모델이 보고한 확률, 보정된 신뢰도, 현재 안전 상태, 실제 결과를 별도로 기록한다. calibration revision은 평가 서비스/승인 프로파일에서 부여하며 모델이 자기 응답으로 지정하지 않는다. malformed·다른 사건·알 수 없는 모델 revision·NaN·근거 조작은 거부한다.

### 초기 자동 처리 기준

자동 처리는 기존 catalog의 승인된 효과와 실행 경로에 한정한다. 읽기·관측 수집은 해당 읽기 권한과 사건/시간/자원 한도를 확인한다. 물리 처리는 현재 사건·관측·정책·사람 점유·E-stop·장치 권한을 기존 admission에서 다시 검사한다. 안전 실패를 확률이나 다른 모델의 찬성으로 무시하지 않는다.

초기 운영 프로파일의 후보 기준은 **보정된 선택 신뢰도 ≥ 0.95, 두 최상위 대안의 확률 차이 ≥ 0.20, 미해결 위험 이의 0건**으로 둔다. 해당 모델 revision과 문제 유형의 독립 검수 세트에서 정확도 하한과 보정 성능이 확인돼야 한다. 이 수치는 초기 설계 기준이며 현재 모델 성능을 입증한 수치가 아니다. 팀의 정답 검수 후 정확도·지연·평가 표본 기준을 확정하며 calibration 없는 모델은 물리 자동 처리에 승격하지 않는다.

관측 부족·위험 누락·다른 사건에 조치·정상 상태의 불필요 명령은 수용 세트에서 0건이어야 한다. 결과 확인 실패는 성공률 분모에서 제외하지 않는다. 시간·비용·호출·관측·조치 시도 한도는 승인 프로파일에 고정하고, 재시작/모델 교체로 초기화하지 않는다. 운영 재시도는 새 관측과 기존 원장으로 관리하며 결과 불명인 명령을 재발행하지 않는다.

### 모델 교체와 개선

모델 역할은 `primary`·`reviewer`·`evaluator`로 나눈다. 역할별 프로파일이 제공자 종류, 정확한 모델 ID/revision, 어댑터, 지원 schema·도메인·입력 형태, 출력·시간·비용 한계와 calibration revision을 지정한다. 기존 공통 `profile_id`와 제공자 호출 경계를 재사용한다. Fleet의 사건 처리 코드에 Qwen·GLM·Jev·Laya 분기를 추가하지 않는다.

어댑터가 JSON 판정 계약을 만족하면 같은 역할에 교체할 수 있다. 텍스트/영상 지원이 다른 모델을 무조건 상호 대체하지 않는다. 부적합한 schema·능력·보정·격리 상태면 해당 역할 admission을 거부한다. 교체는 새로운 프로파일 revision으로 다음 사건부터 적용하며 진행 중인 사건에는 원래 revision을 고정한다. 알 수 없는 비용·접속 설정으로 자동 fallback하지 않는다.

종결 실패와 사람 최종 검토는 사건 원장에 원인·수정·결과로 연결한다. 모델 오류와 지도·보정·현장 연결·장치 오류를 분리해 해당 소유자에게 보낸다. 재생 비교는 규칙/기본 모델/재평가를 같은 독립 사건 세트에서 평가한다. 학습 세트와 독립 평가 세트를 분리하며 위험 회귀 또는 과거 문제 성능 저하 시 승격하지 않는다. 운영 모델을 자체 학습 결과로 즉시 교체하지 않는다.

## Consequences

자동 처리율, 사람 인수율, 불필요 개입률, 위험 누락, 판정 일치율, 실제 종결률, 재발률, 지연과 비용을 함께 측정한다. 사람 인수율 감소만으로 개선을 승인하지 않는다. 현재 수용된 호스트·CLI·가짜 전송 시험과 실제 제공자·독립 품질·장치/현장 수용을 별도 증거로 유지한다.

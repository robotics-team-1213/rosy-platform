## D-522 개발 환경 원격 이동은 사용자 지시로 진행하며 반복 승인 대신 장치 증거를 확인한다

**Status:** Accepted (2026-10-08, 사용자 지시). 운용 권한 결정이며 구현, 장치 이동, G4/G5 수용을 뜻하지 않는다.

### Context

사용자는 ROSY Web으로 두 Pinky를 조종하고 이동 구역을 처리하도록 반복 지시했다.
Rosy Cam 원격 입회와 별도 현장 담당자 없는 진행은 D-521에서 허용했다.
2026-10-08 사용자는 개발 환경에서 다시 승인받느라 멈추지 말고 진행하도록
지시했고, 이를 ADR로 기록해 달라고 했다. D-314는 이미 수동 운전의 반복
확인란을 없앴다. D-512는 에이전트의 실기 시험과 카메라 사전 점검을 제안했다.

현장 조회에서 두 로봇의 CORE는 `motor`, `IDLE`, 속도 0, E-Stop 해제 상태였다.
각 LiDAR와 전면 영상 및 머리 위 Rosy Cam 영상은 수신됐다. 그러나 머리 위
영상의 어느 몸체가 어느 `robot_id`인지 물리적으로 확정하지 못했고, 한
몸체의 뒤쪽 여유는 약 0.065 m였다. 식별 램프 API의 명령 수락은 실제 영상의
램프 식별로 이어지지 않았다. 현재 설치된 사이트 Fleet Web은 인증·tether
API가 소스 계약보다 오래돼 사용자의 전체 Web 조종 목표를 아직 충족하지 않는다.

### Decision

1. 사용자의 이번 지시는 개발 시험에서 에이전트가 ROSY Web/CORE의 정상
   권한 경로로 원격 수동 이동을 수행할 권한이다. 동작마다 사람에게 재승인을
   요청하거나 별도 현장 담당자·물리 전원 차단자를 요구하지 않는다(D-314,
   D-512, D-521). `강제 모드`는 반복 승인 절차를 건너뛰라는 운용 지시로
   기록한다. 로봇의 `ROSY_DEPLOYMENT`·연결 모드·인증/TLS·E-Stop·CORE의
   속도/감시/정지 제한을 무력화하는 설정값이나 API 권한으로 해석하지 않는다.
2. 첫 이동 전에 호스트/boot ID와 영상 속 물리 몸체를 연결하고, 계획한 이동
   방향의 몸체 여유와 바퀴·경로의 케이블, 다른 로봇·사람을 최신 머리 위
   영상·전면 영상·LiDAR로 확인한다. 확인된 시험 구역 안에서 한 대씩
   D-314의 수동 시험 한도(선속도 0.03 m/s, 각속도 0.10 rad/s, 한 시험
   누적 이동 0.10 m)로 시작한다. 후진처럼 몸체 여유가 부족한 방향은
   선택하지 않는다. 영상이 끊기거나 신원·구역이 불명확하면 그 명령은
   보내지 않고 정지 상태를 읽는다. 이 중단은 추가 사용자 승인을
   요청하라는 뜻이 아니라 현장 근거를 보완하라는 뜻이다.
3. 각 이동은 정상 인증된 CORE 경로로 보내고, 요청 수락만이 아니라 속도·모드
   읽기와 다음 영상으로 결과를 확인한다. 버튼 해제·연결 상실 시 0 명령과
   감시 정지를 유지한다. `MANUAL` 경로의 장애물 정지 범위가 자율 주행의
   D-422와 같다고 가정하지 않으며, 이동 전 몸체 간격을 따로 판정한다.
   임시 장치 설정을 바꾸었다면 D-512의 원상복구 규칙을 적용한다.
4. 이 결정은 실물 G4 원시 계측·봉인, G5 지도·정지 증거, 장치에 설치된
   Fleet Web의 인증/권한 검증을 생략하지 않는다. 소스 계약, 사이트 설치
   버전, 명령 수락, 물리 이동을 각각 별도 증거로 기록한다. 현재 미확정
   로봇 신원과 설치 버전은 완료가 아니라 남은 작업이다.

### Consequences and verification

로봇 신원을 확정하기 전에는 속도 명령을 보내지 않는다. 현장 상태를 다시
확인해 조건이 맞으면 동일한 사용자 지시 아래 추가 승인 없이 작은 단일
이동부터 수행한다. 첫 장치 회차에서 robot ID/몸체 대응, 카메라 프레임
시각, 방향별 LiDAR 간격, 명령/정지 응답, 최종 속도 0을 기록한다.

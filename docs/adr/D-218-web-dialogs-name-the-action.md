## D-218 확인 문법의 졸업 — 네이티브 confirm 이 공유 컴포넌트다

**Status:** Accepted (2026-09-25)

**Context:** D-92 제5항은 네 가지(불가역 확인·Fleet 예외 행·좁은 콘솔·얼굴
의도)를 "두 번째 표면이 로직을 필요로 할 때까지 설계하지 않는다"고 남겼다.
2026-09-25 기준 불가역 확인의 트리거는 오래 성립돼 있다 — 실측: 콘솔
app.js 9곳, settings.js 11곳, map.js 1곳, Fleet console.js 1곳(전체 정지),
모두 `window.confirm` 이고 모두 거부 경로가 브라우저 시험으로 고정돼 있다
(Fleet 전체 정지·콘솔 모드 전환·교통 정책 적용).

같은 계측에서 위반 하나를 적발했다(**F-20**): Fleet HITL 큐의 "조종
(WebRTC)" 버튼이 `kind="irreversible"` 모의 버튼으로 `alert("(Mock)")`을
띄웠다 — 서버에 없는 능력을 활성 불가역 버튼으로 그린 것은 Law 0 위반이고,
경보 큐 안의 거짓 조작은 최악의 자리다.

**Decision:**

1. **확인 문법은 네이티브 `window.confirm` 으로 졸업한다.** "공유 컴포넌트"의
   자리를 브라우저가 이미 채운다 — 모달 접근성·포커스 함정·키보드 탈출을
   우리가 다시 만들 이유가 없고 CSP 아래에서도 문제없다. 커스텀 확인
   다이얼로그(표면별 크롬)는 만들지 않는다. Law 3의 시각 범주는 확인
   다이얼로그가 아니라 **호출 버튼**(크기·채움)이 나른다.
2. **어휘 계약.** 세상을 바꾸는 조작은 호출 앞에서 confirm 을 지나며, 거부는
   API 호출 0회로 끝난다(브라우저 시험이 고정). 확인 문장은 청중의 평문으로
   결과를 묻는다("~할까요? / ~했습니까?").
3. **alert/prompt 금지.** 모의 안내도 확인 아닌 길도 없다. F-20 수정:
   HITL 행은 로봇을 이름으로 부르고 진짜 개입 경로(그 로봇의 화면)를
   말하는 텍스트로만 알린다.
4. **계기: 대화 상자 계약 시험.** `test/test_web_dialog_contract.py` —
   (a) 세 웹 표면의 JS 에 alert/prompt 부재(합성어 제외, `window.alert`
   포함 — 첫 룩어하인드가 마침표를 면책해 침입 경로가 된 것을 변이 증명이
   붙잡았다), (b) `window.confirm` 은 고정 파일·횟수표와 일치(새 확인은
   표를 고치는 커밋과 함께 온다 — 그 커밋이 리뷰의 자리), (c) 확인 문장의
   물음 형태. 변이 증명 완료.

**Alternatives:** 공유 headless 확인 흐름 + 표면별 모달 크롬을 뽑는 안
(D-130.2 문자 그대로) — 공유할 로직이 이미 네이티티브 한 줄이라 뽑을 것이
없고, 모달 크롬은 접근성을 우리가 다시 증명해야 하는 비용만 만든다.
커스텀 `ui-confirm` 공유 컴포넌트 안 — 같은 비용에 CSP·스타일 가드가 복잡해진다.

**Consequences:** 새 확인이 필요하면 PINNED_CONFIRMS 표를 고치는 커밋이
함께 온다(표가 곧 인벤토리). Law 3 시각 범주는 버튼이 나르므로 확인
다이얼로그의 생김새는 브라우저/OS의 몫으로 남는다. 게임 보드는 확인 없는
표면이다(정지는 즉시 실행 + 스페이스) — 합류 시 이 표에 등장한다.

**Validation / Transition:** 구현 커밋에서 F-20 수정 + 계약 시험 + 변이
증명(alert 주입 → 적색 → 원복 → 녹색).

**References:** concept 16 §3 Law 0·Law 3·§4, D-72, D-92(제5항), D-101,
D-130.2, D-153(회차 1 F-11), D-194, D-201~D-214 회차.

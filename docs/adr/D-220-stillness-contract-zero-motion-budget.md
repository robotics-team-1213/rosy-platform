## D-220 정지 계약 — 움직임 예산은 0이다

**Status:** Accepted (2026-09-25)

**Context:** 공예 계약 셋(D-201 적합, D-202/D-214 대비, D-203 척급)이 프레임·
색·크기를 닫았고 움직임만 열려 있었다. 철학적 직관("계기판은 뛰지 않는다")을
계약으로 만들기 전에, 이 저장소의 방식대로 먼저 측정했다(2026-09-25,
Playwright 계산 스타일 센서스): 콘솔 운용·점검 양 뷰의 보이는 전 요소에서
`transition` 이 0s 가 아니거나 `animation-name` 이 none 이 아닌 요소는
**0개**. Fleet·게임 시트에도 전이·애니메이션 규칙이 없다(소스 점검).

즉 현재의 관행은 이미 완전 정지다 — 등장 애니메이션도, 상태 전이 페이드도,
숫자 롤도 없다. 이 ADR 는 그 관행을 우연에서 계약으로 옮긴다.

**Decision:**

1. **움직임 예산은 0이다.** 웹 표면의 어떤 요소도 등장·퇴장·전이 애니메이션을
   가지지 않는다. 상태 변화는 점프 컷으로 렌더된다 — 값이 바뀌는 순간이
   곧 화면이 말하는 순간이며, 그 사이를 채우는 보간은 없는 값을 있는 것처럼
   보이게 하는 유일한 수단이다(증거 상태의 적, Law 0 정신).
2. **예외는 ADR 로만.** 어떤 표면이 움직임을 필요로 하면(예: 얼굴의 의도
   화살표가 LCD 에서 움직여야 한다면) 그 예외는 이 ADR 의 amendment 로
   기록되고 예산을 명시한다(무엇이·왜·얼마나). `prefers-reduced-motion`
   블록은 이미 있는 예외의 자리지 예외를 만드는 면허가 아니다.
3. **계기: 움직임 센서스.** 브라우저 시험에서 보이는 전 요소의 계산
   `transition-duration` 이 0s(또는 property none)이고 `animation-name` 이
   none 임을 단언한다. 콘솔(양 뷰)에 붙였다 — 시트가 하나뿐인 다른 표면은
   소스 게이트(전이 규칙 부재)로 같은 성질을 지킨다. 변이 증명 완료.

**Alternatives:** 상태 전이에 짧은 페이드를 허용하는 안(150ms 상한) —
"사라지는 값"과 "나타나는 값" 사이에 중간 상태를 그려 증거를 흐린다.
요소별 화이트리스트를 두는 안 — 예외 목록은 D-92 제5항이 경고한 것과 같은
숨은 결함의 창고다.

**Consequences:** 새 컴포넌트가 hover 트랜지션을 자연스레 붙이는 일을
게이트가 막는다 — 색·테두리 변화는 즉시 일어난다. 캔버스(지도·경기 필드)의
다시 그리기는 애니메이션이 아니라 관측이므로 대상이 아니다. 게임 보드의
공은 관측 대상이지 UI 요소가 아니다.

**Validation / Transition:** 구현 커밋에서 센서스 게이트 추가 + 변이 증명
(전이 규칙 주입 → 적색 → 원복 → 녹색).

**References:** concept 16 §3·§5(증거 상태)·§7, D-72, D-82, D-153, D-201~D-214
공예 계약, `prefers-reduced-motion` 블록(styles.css).

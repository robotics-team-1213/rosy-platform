## D-624 색상 역할과 지켜지는 디자인 법칙

**날짜:** 2026-10-11
**상태:** 구현

### 결정

사용자는 제품 전체 디자인 철학을 문서로 정의하고 색상 토큰부터 세세히 나누어 계속 지키도록 요청했다. D-280의 차분한 지능, D-359의 단일 토큰 출처와 테마 계약을 유지한다.

1. `shared/web/tokens.css`를 단일 진입점으로 유지한다. 원시 팔레트, 파생 색, 사용 목적의 역할, 컴포넌트 토큰을 구분한다. 사본·새 의존성·새 테마를 추가하지 않는다.
2. 반복되는 기본 바탕·들어간 면·본문·보조 글·위험 채움 위 글·세 단계 경계에 역할 8개를 추가한다. 기존 팔레트·파생 값의 별칭이므로 dark/light의 값과 대비를 유지한다. 데이터 Canvas/JS, status/series/brand 색은 기존 의미 집합을 유지한다.
3. 공용 부품, 로봇 웹, Pilot, Fleet, 게임, 학습 검수 웹의 해당 CSS 선언을 역할로 옮긴다. 대응 역할이 있는 직접 색 선언의 팔레트 참조는 시험이 거절한다. 혼합식·지도 래스터·브랜드·native 생성은 기존 계약을 따른다.
4. `DESIGN.md`에 역할 선택표와 필수 법칙을 두고 공용·표면 작업 지침에서 연결한다. 예외는 ADR 및 surface registry로 기록한다. 원시 색 금지·역할 우선·테마 대비·native parity는 기존 시험을 확장해 강제한다.
5. 디자인 수용은 D-153의 G1/G2/G3이며 소스 규칙과 실제 장치/현장 수용을 구분한다. 팔레트 값 보존은 실물 수용을 대신하지 않는다.

### 검증

역할 별칭의 두 테마 해석, 전체 등록 CSS의 직접 팔레트 참조 차단, 기존 대비·범위·parity 회귀를 원격 실행한다. 실제 Fleet의 dark/light, desktop/mobile을 한 번에 비교하고 변경값·넘침·화면 오류를 기록한다.

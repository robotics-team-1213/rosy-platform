## D-892 Fleet 모바일 관제의 로봇 상태·작업 우선 배치

**Status:** Accepted (2026-10-27)

### 배경

사용자는 로그인부터 주요 화면을 평가한 뒤 코드 개선·커밋·머지를 요청했다. 좁은 관제 화면에서는 큰 지도 뒤에 로봇 선택과 상태가 놓여 첫 화면에서 작업 대상과 확인할 문제를 찾기 어려웠다.

### 결정

1. D-629 §4의 좁은 화면 순서를 **현재 개입 → 관제 상세 탭 → 지도**로 대체한다. 상세 탭의 기본은 로봇·작업이며 사용자가 고른 탭은 유지한다. 비상 정지는 기존 위치와 권한 계약을 유지한다.
2. 로봇을 선택하기 전에는 등록 로봇의 연결·안전 요약을 보여준다. 선택한 뒤에는 그 로봇의 상태·작업 영역을 일반 목록보다 앞에 둔다.
3. CSS의 보이는 순서와 반응형 DOM 이동 순서를 함께 맞춘다. 화면 폭을 바꿔도 같은 노드·입력값·선택한 탭·포커스를 보존한다.
4. D-629의 넓은 화면 2:1 배치, 48px 조작 규격과 나머지 결정은 유지한다. 인증·승인·장치 명령·상태의 의미를 바꾸지 않는다.

### 결과와 검증

전화에서는 로봇 상태와 다음 조작을 먼저 찾을 수 있고, 지도는 그 아래에서 스크롤로 접근한다. 지도 전체를 첫 화면에 넣는 이전 우선순위는 유지하지 않는다.

`test/test_fleet_ui_review_browser.py`는 320/390 폭과 두 테마에서 선택 전·후 배치를 확인한다. `test/test_fleet_console_browser.py`는 실제 DOM 순서와 폭 변경 중 노드·입력·포커스 보존을 확인한다. 교통 화면 시험은 지도 그리기와 스크롤 접근, 첫 화면 비상 정지와 가로 넘침을 계속 검사한다.

이 결정은 실물 장치·현장 조명·제품 전체 UI/UX 수용을 선언하지 않는다.

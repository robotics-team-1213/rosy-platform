## D-355 도크·외부 장비 구현은 자재부터 통합까지 단계별 게이트로 진행한다

**Status:** Accepted (2026-09-30, 실행 순서와 완료 조건 확정; 단계별 작업은 구현 플랜 참조).

### Context

D-349~D-354는 도킹 소프트웨어의 준비 상태, 하드웨어 단계, 재시도, 외부 장비 공통 계약, 변경 봉합점, mDNS 발견을 각각 결정했다. 이 결정들을 실제 장비 작업으로 옮길 때는 자재 조달, 벤치 시험, 로봇 실기, 기능 활성화, 시스템 통합 사이의 선행 조건이 분명해야 한다. 자재가 없거나 물리 인수가 끝나지 않은 상태에서 capability를 켜면 소프트웨어 준비 상태가 실물 준비 상태로 오인될 수 있다.

### Decision

도크·외부 장비 작업은 다음 다섯 단계로 관리한다.

1. **자재 조달:** 구성품과 수량을 확정하고, 조립에 필요한 자재가 준비됐는지 확인한다.
2. **벤치 검증:** 도크와 신호등을 각각 독립된 벤치 경로에서 검증한다. 계획의 Phase B와 Phase E는 같은 단계 안의 별도 장비 게이트다.
3. **로봇 실기 검증:** 계측, 커미셔닝, G4 방향·정지 시험을 수행한다. 벤치 작업과 병행할 수 있지만, 필요한 실측 결과가 없으면 의존 작업을 통과 처리하지 않는다.
4. **기능 활성화:** 도크 벤치 게이트가 완료된 뒤 capability를 전환하고 자동 충전 및 충전 완료 동작을 확인한다.
5. **통합:** 도크·신호등 상호작용, Fleet 상태 표시, 도킹 완료 이벤트에 따른 미션 동작을 검증한다. 관련 벤치 게이트가 모두 완료되어야 한다.

각 작업에는 선행 조건, 통과 기준, 증거를 기록한다. 단계가 끝나지 않았거나 증거가 불충분하면 다음 단계의 capability 활성화나 통합 완료로 승격하지 않는다. 실행 항목과 세부 게이트는 [D-349~D-354 도크·외부 장비 구현 플랜](../plans/2026-09-30-dock-device-implementation-plan.md)을 따른다.

### Consequences

소프트웨어 준비, 벤치 동작, 로봇 실기, 활성화, 통합의 상태를 구분해 보고할 수 있다. 도크와 신호등 벤치는 독립적으로 진행할 수 있고, 로봇 실기 준비도 병행할 수 있다. 실물 조립이나 검증이 끝나지 않은 기능은 활성 상태로 간주하지 않는다.

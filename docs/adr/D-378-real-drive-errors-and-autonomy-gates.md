## D-378 실물 로봇은 실물 녹화로 통과한 로직으로만 스스로 간다 — 주행 오류를 기록하고, 차선·정지선·신호는 재생 → 그림자 → 누르는 동안 순서로 들인다

**Status:** Accepted (2026-09-30). 오류 기록과 도입 순서 결정. 실물 설정·배포 변경은 단계마다 사용자 승인.

### Context

2026-09-29~30 실물 rosy-pinky-8kcn(release 2026.09.27-010 + 현장 핫픽스)에서 다음 오류가 났다.
사용자 지적: "로직에 따라 처리하기로 했는데 왜 다 나가는지 봐야 한다."

| # | 날짜 | 오류 | 원인(확인됨) |
|---|---|---|---|
| E1 | 09-29 | 차선 자동(누르는 동안)이 흰 선을 밟고 넘음 | 실물은 `camera_lane_mode: line`(밝은 화소 무게중심 = 선 추종기). main 의 `keep`(D-364)·IR 감시·경로 물체 정지(D-344)는 **실물에 없다**. |
| E2 | 09-30 | Claude 의 PC 수동 운전이 좌회전을 넘겨 둘레 벽을 향함(yaw 94°) — 접촉 없음, 정지 | 오도메트리로 시간만 맞춘 개루프 호(0.03 m/s·0.1 rad/s × 16 s). 호 도중 인식 피드백이 없었다. 직진 구간은 카메라 확인 후 진행해 문제 없음. |
| E3 | 09-30 | 42 분 녹화 세션에 주행이 0 (오도메트리 0.01 m) — 4.2 GB 삭제 | 운전 주체(사용자 태블릿)와 시작 신호가 맞춰지지 않았다. |
| E4 | 09-30 | 기록기 정지가 안 됨 | 비대화형 셸의 백그라운드 작업은 SIGINT 를 무시; `pkill -f` 가 자기 셸도 맞춤. SIGTERM + 실행 경로로 시작하는 패턴으로 고침(PC 스크립트). |

실물 녹화 재생(세션 `20260930T124745Z`, 282 s, 선택 프레임 148장, 원본 `camera/front` 320×240)으로 잰 값:

- **차선**: 사람이 곧게 몬 직진 구간(오도메트리 y≈0, yaw≈0, 36 프레임)에서 정답 조향 ≈ 0.
  - `line`(실물 현재): 평균 오차 **+0.30**, |오차| 0.30 — 직진인데 계속 오른쪽(벽 밑 테이프 쪽)으로 조향(gain 0.8 → −0.24 rad/s). E1 의 직접 원인.
  - `between`: −0.003 / 0.013. `keep`(main): −0.024 / 0.074, 비가시 1.
  - 전체 148 프레임 목표-선 위 비율: line 0.253, between 0.170, keep 0.164, keep v2(`feat/lane-keep-v2`) 0.149·튐 0.007.
- **도로 표시·신호**(`road.py`, 실물 설정 그대로): 정지선(신뢰 ≥ 0.5) 29 %, 횡단보도 23 %, 신호 **GREEN 72 %** — 이 경로에는 신호등이 없다(벽 쪽 초록 물체를 신호로 읽음). 정지선은 형태·위치 검사 없이 가장 낮은 가로 밝은 띠다(2026-09-24 재생에서도 89.5 % 오검출).
- **교통 정책**: 실물·기본 모두 `traffic_policy.mode: DISABLED` — 지금 실물은 신호·정지선에서 서지 않는다. 켜도 실물은 지면 모델(homography)이 없어 거리 = 없음 → 정지선이 보이면 `stop_distance_unavailable` 로 늘 HOLD. 측정 신호(D-337) 경로는 폴링 0.5 s 대 신선도 0.4 s·`age_s` 소급으로 늘 낡을 가능성(코드 읽기, 미실행). 횡단보도는 판정에 쓰이지 않는다. Nav2 명령은 교통 게이트를 거치지 않는다.

### Decision

1. **실물이 스스로 가는 것은 실물 녹화로 통과한 로직뿐이다.** 새 인식·정책은 아래 사다리를 한 칸씩 오른다.
   - **R0 재생**: 실물 녹화(D-356 세션, 원본 `camera/front`)를 `tools/lane_replay.py` 등으로 돌려 관문을 통과한다.
   - **R1 그림자**: 실물에서 새 로직이 관측만 내고(차선은 별도 관측·비교 기록, 교통은 `MONITOR_ONLY`) 사람이 운전한다. 사람 조향과 로직 판단의 차이를 세션마다 남긴다.
   - **R2 누르는 동안**: D-344 보조 자율(진행 버튼·hold lease·L1 이상, D-342)로만 로직이 운전한다.
   - **R3 이후**(연속 주행·무인)는 별도 ADR.
2. **차선 관문(R0)**: 사람이 몬 구간에서 평균 |조향 오차| ≤ 0.08, 목표-선 위 비율이 `line` 보다 낮음, 튐 ≤ 0.02, 비가시는 실제로 선이 안 보이는 프레임에만. 첫 세션 기준 `keep`(main·v2)은 직진 관문을 통과, 교차로·곡선 구간은 사람 운전 세션이 더 모인 뒤 판정한다. 통과하면 실물 `camera_lane_mode` 를 `line` → `keep`(NOMINAL 지면, D-364 §3)으로 바꾸는 반영을 사용자 승인으로 한다.
3. **교통(정지선·신호·횡단보도)은 `DISABLED` 유지**, 다음 순서로 들인다.
   1) 정지선 검출을 형태(두께·폭)·위치·시간 추적으로 바꾸고, 실물 녹화에 사람이 단 라벨로 정밀도·재현율을 잰다(목표: 오검출 ≤ 5 %).
   2) 신호: 로봇 카메라로 램프를 볼지, 천장 관측기(D-337)를 쓸지 정한다. 카메라 신호는 램프 모양·ROI 검사로 고치고, 신호등 없는 녹화에서 GREEN 오검출 ≤ 1 %. 관측기 신선도 예산 버그를 먼저 고친다.
   3) 실물 homography 교정(또는 NOMINAL 지면의 교통 사용 결정)으로 정지선 거리.
   4) 실물 트랙 `map_id`/`scene_revision` 작성.
   5) 실물 `MONITOR_ONLY`(R1) → 멈춤 거리 실측 → `ENFORCED`(R2).
   횡단보도 양보와 Nav2 명령 교통 게이트는 그 뒤 별도 결정.
4. **데이터 수집은 사람 운전이 기본**이다. 세션마다 운전 주체·시작 신호를 먼저 맞춘다(E3). Claude 의 스크립트 운전은 카메라로 확인한 **짧은 직진**과 제자리 회전만 하고, 시간으로 맞춘 곡선 주행은 하지 않는다(E2). 곡선·교차로는 사람이 몰거나, R2 이상의 로직이 몬다.
5. **오류는 이 ADR 의 표에 덧붙인다.** 실물 주행 중 차선 이탈·벽 접근·예상과 다른 정지/출발은 날짜·세션·원인과 함께 적는다. 녹화 세션은 증거로 보존한다(D-356 형식, 공개 저장소 밖).

### Alternatives

- **가제보로 먼저 다듬고 실물에 올린다.** 사용자 결정으로 실물 우선. 가제보(D-364 §5)는 보조 벤치로만 남긴다.
- **교통 정책을 지금 ENFORCED 로 켠다.** 거부. 실물에서 신호 오검출 72 %·지면 없음이라 늘 서거나 잘못 간다.

### Consequences

- 실물 반영(keep 전환, 교통 모드)은 증거와 승인 없이는 없다. 대신 실물 녹화가 계속 필요하다.
- 첫 실물 세션은 직진·정지선·횡단보도·좌곡선·벽 근접을 담았고, 그림자 비교(R1)를 위해 관측 기록 도구가 필요하다.

## D-265 기반 화면은 패널 수와 무관하게 남는다 — 메뉴·정지 진입 계약

**Status:** Accepted (2026-09-26). 구현·브라우저·실기 수용은 별도다.

잇는 결정: D-77(운용자 콘솔), D-193(인증), D-204(역할별 화면·패널 조립, 별도 브랜치),
D-243(`hmi` 화면 소유), D-263(메뉴 확장 원칙). 실행 계획:
[2026-09-26-role-menu-rollout.md](../plans/2026-09-26-role-menu-rollout.md).

**Context:** D-263은 상단 메뉴를 화면 메타데이터에서 만들고, 제공하지 않는 기능은
표시하지 않도록 정했다. D-204 S1 브랜치의 `ui_manifest.py`는 보이는 패널이 하나라도
있는 화면만 `surfaces`에 넣는다. 따라서 CAP-001이 모두 빠지거나 해당 역할의 패널이
아직 없는 동안에는 역할상 허용된 `/console`도 메뉴에서 사라진다. E-Stop은 셸에
있지만, 화면 진입 경로가 패널 존재에 묶이면 사용자가 그 셸을 찾기 어렵다.
또한 CORE SRS WEB-002의 13개 이름은 현재 평면 메뉴 요구로 읽히므로 D-263의
세 화면과 어떻게 양립하는지 명시해야 한다.

**Decision:**

1. **기반 화면의 존재와 패널의 존재는 다른 판정이다.** `/console`, `/setup`,
   `/device`는 고정된 CORE 기반 화면이다. `whoami` 역할이 각각 Viewer, Operator,
   Administrator 이상이면 패널이 0개여도 화면 전환기에 남는다. CAP-001과
   inventory는 그 안에 조립되는 패널을 결정한다. 빈 화면은 비어 있는 이유를
   보여 주며, 사라지거나 `정상`으로 표시하지 않는다. 향후 선택형 화면을 만들
   경우에는 D-263의 독립 화면 조건과 별도 ADR로 노출 정책을 정한다.

2. **E-Stop 진입은 패널/매니페스트 성공에 의존하지 않는다.** 세 기반 화면은
   동일한 셸 위치에 정지 버튼을 렌더한다. 이미 인증된 브라우저에서 패널 import,
   매니페스트 갱신, 일반 상태 폴링이 실패해도 정지 API 요청은 별도로 시도할 수
   있어야 한다. 요청 실패는 실패로 알린다. HTTP 수락은 명령 접수 증거이며
   물리적 정지 증거는 아니다. 미인증 사용자의 정지 권한을 새로 만들지 않는다.

3. **탐색과 직접 접근은 같은 역할 규칙을 쓴다.** 역할이 낮으면 메뉴에서 화면을
   제외하고 매니페스트 직접 요청은 403이다. 미인증 요청은 401, 없는 화면은 404다.
   페이지 HTML이 정적 응답 200이어도 셸은 401/403/404를 각각 안내하고 보호된
   패널을 조립하지 않는다. `whoami`가 실패했을 때 관리자 화면을 추측해 노출하지
   않는다. 매니페스트의 일시적 오류에서는 이미 검증된 메뉴/패널을 유지하거나
   첫 로드라면 빈 상태를 보이며, E-Stop 경로는 독립적으로 유지한다.

4. **WEB-002의 기존 이름은 도달 가능한 정보/작업 항목이다.** Dashboard·Control·
   Navigation·Map·Sensors는 운용, Waypoints는 작업 준비, Devices·Events·
   Diagnostics·Network·ROS·System·Settings는 장치·정비에 배치한다. 이 표는
   상단 메뉴 13개를 요구하지 않는다. 화면 이관 시 동작 단위의 상세 위치는
   역할과 API 권한에 맞게 정한다(예: 도크 등록은 `/setup` 안의 Admin 동작).

**Alternatives:** 패널이 없는 화면을 메뉴에서 숨기면 첫 기능 개발 중 빈 화면은
피할 수 있지만, capability 차이와 권한 차이가 뒤섞이고 정지 진입도 패널 목록에
의존한다. 빈 운용 화면에 가짜 기본 패널을 추가하는 방법은 거짓 상태를 만들고
패널 계약을 왜곡한다. 현재 화면 메타데이터만으로 역할별 기반 메뉴를 생성한다.

**Consequences:** D-204 브랜치의 `open_surfaces = {panel.surface for panel in visible}`
동작은 병합 전에 기반 화면의 역할 필터로 바꿔야 한다. `src/runtime/api_web`은
레지스트리와 역할 판정을, `src/hmi/dashboard`는 셸/화면을 소유한다(D-243).
새 메뉴 서비스나 capability 기반 화면 ID 생성은 없다.

**Validation:** Viewer/Operator/Administrator × 패널 0개/일부/전체의 매니페스트
화면 목록과 401/403/404를 테스트한다. 브라우저에서 빈 `/console`, 매니페스트
오류, 패널 import 오류 동안 메뉴와 E-Stop 진입을 확인한다. API 요청의 접수와
실제 구동계 정지는 별도 증거로 기록한다.

## D-986 항법 승인은 측정이 같으면 새 릴리스로 이어지고, 로그인한 운영자가 API로 끝낸다

**Status:** Accepted (2026-11-07, 사용자 지시: "항법을 재승인하는 절차도 누구나 다 로그인이 되어있다면 바로 할 수 있도록 구조화", "api나 기타로도 처리 가능", 권한은 Rosy Account와 연결). 1항(승계)과 2항(API·카드)을 구현했다. 장치 수용은 어느 쪽도 아직 없다.

잇는 결정: [D-311](D-311-native-g4-evidence-gates-navigation.md), [D-314](D-314-measured-g4-and-direct-teleop.md), [D-321](D-321-attended-calibration-g4-mapping.md), [D-985](D-985-pinky-always-self-updates-to-latest-payload.md).

**Context:** D-985로 기체가 새 릴리스를 스스로 받는다. 승인은 측정한 릴리스에 묶여 있어 릴리스마다 무효가 된다. 재승인은 기체를 움직인 G4 시험 5회의 원본을 검증하는 절차인데, 번들 생성기가 저장소에 없고 승인 뒤 항법을 켜는 제품 경로도 없다. 11-03·11-05 승인은 임시 스크립트와 SSH로 했고, 11-05 원본은 실제 한도를 0.02/0.07로 낮춘 채 요청값을 0.03/0.10으로 적었다.

**Decision:**

1. **서명된 모터·정지 파일이 같으면 승인을 이어받는다.** 승인 때 지문을 표식에 저장한다. 지문은 릴리스의 서명된 `SHA256SUMS`에서 제외 목록 밖 파일의 해시를 모아 만든다. `mapping_approval.py check`는 기동마다 읽기 전용으로 현재 릴리스의 지문과 비교하므로 표식을 고쳐 쓰지 않고, 롤백에도 그대로 맞다. 다음이면 이어받지 않고 다시 측정한다.
   - 지문이 다르거나 읽을 수 없다. 지문 없이 봉인된 옛 표식이다.
   - 표식의 릴리스가 번들과 다르다. 다른 기체다.
   - 봉인된 원본의 해시·속도·방향·정지 지연 검증은 이어받을 때도 매번 다시 한다.

   **제외 목록은 기본 포함이다.** 목록에 없는 파일은 지문에 들어가므로 새 패키지는 검토 전까지 재측정을 요구한다. 제외: 릴리스 신원 파일, 빌드 러너 목록, 문서, 헤더, `sllidar_ros2` 바이너리(같은 입력에서 바이트가 달랐고 모터를 명령하지 않음), Pinky 유닛이 띄우지 않는 패키지(Fleet·Vision·Cell·시뮬레이션·게임·OMX). 모터 경로가 이 패키지를 import하거나 유닛이 띄우면 시험이 실패한다. 웹 UI는 버튼 해제가 측정한 정지의 일부이므로 포함한다. 릴리스가 담지 않는 nav2·deb·시스템 Python은 이미지 쪽에 있으므로 이미지 신원(`/etc/rosy/os-factory-release.json`)도 지문에 넣어, OS가 바뀌면 다시 측정한다.

2. **승인은 REST API가 주인이고 카드는 그 위의 화면이다.** 도구와 에이전트도 같은 API를 호출한다.
   - 권한은 `require_role("operator")`다. Account 로그인은 `robot.operate`로, 기존 토큰은 역할로 판정한다. 승인자는 `auth.principal_ref`로 남긴다. 공용 개발 토큰(`shared_dev`)은 거절한다.
   - 시험은 사람이 버튼을 쥐는 동안만 움직인다. 시작 전에 LiDAR로 진행 방향 여유를 확인하고 부족하거나 스캔이 없거나 오래되면 거절한다. 요청값은 실제로 보낸 값을 적는다. 측정 속도도 한도 안에 있어야 하므로 시험 속도는 0.02 m/s, 0.07 rad/s로 한도보다 낮게 둔다.
   - 몸 바로 옆은 LiDAR로 증명할 수 없다. 최소 거리(C1 약 0.15 m) 안과 자기 몸 가림 구간의 점은 버려지기 때문이다. 시험은 보이는 점의 여유를 확인하고, 안 보이는 구간은 사람이 눈이나 카메라로 확인했다는 표시를 요구한다. 앞쪽도 몸 끝에서 약 9 cm가 이 구간이다. 표시가 없으면 거절한다.
   - 명령 끊김 시험은 멈춤 명령을 보내지 않는다. 명령이 끊긴 뒤 CORE의 teleop watchdog이 세우는지를 잰다.
   - 봉인에 성공하면 hardware 모드로 돌아간다. 항법 시작은 별도 호출이다.
   - 측정은 충전 중이거나 배터리 상태를 모르면 시작하지 않는다.
   - 측정 상태는 시간이 제한된다. 갱신 hold(4시간)보다 먼저 3시간 30분에 끝나고, 재부팅해도 이어지지 않는다. 부팅마다 뜨는 Host Agent가 1분마다 확인해 이전 모드로 되돌린다. 복원에 실패하면 hold를 유지하고 10분 뒤 다시 시도한다.
   - 시험 기록은 `/begin`이 본 릴리스와 지문에 묶이고, 달라지면 봉인 때 버린다. 다른 사람의 갱신 hold가 있으면 측정을 시작하지 않고, 이 절차가 건 hold만 지운다.
   - 권한이 필요한 봉인과 모드 전환은 Host Agent의 좁은 새 명령으로만 한다. 다른 Host Agent 명령의 administrator 요구는 바꾸지 않는다.
   - 속도·이동·정지 한도(0.03 m/s, 0.10 rad/s, 10 cm, 0.65 s)는 바꾸지 않는다.

**Consequences:**

- 릴리스마다 재측정하지 않아도 된다. b8xy의 실제 릴리스에서 소스가 다른 004·005는 지문이 같았고, 코드가 많이 바뀐 10/29와는 달랐다.
- 승계는 파일이 같다는 증명이지 실물이 그대로라는 증명이 아니다. 모터·바퀴·배선을 바꾸면 시험을 다시 해야 하며 이는 사람 판단으로 남는다. 설정(`/etc/rosy`)은 지문에 들어가지 않는다.
- 지금 b8xy·geg6의 승인에는 지문이 없어 한 번은 측정해야 한다. y8xs에는 승인이 없다.
- 웹 UI만 바꾼 릴리스도 재측정을 요구한다. 해제 경로만 남기고 UI를 제외하는 것은 후속 검토다.

**기각:** 측정 없는 승인(승인의 내용이 사라진다), 빌드 때 지문 파일 생성(서명된 `SHA256SUMS`로 충분하다), 제외 목록 대신 포함 목록(새 패키지가 조용히 빠진다), 승계 때 표식 다시 쓰기(쓰기 권한이 늘고 롤백 때 어긋난다).

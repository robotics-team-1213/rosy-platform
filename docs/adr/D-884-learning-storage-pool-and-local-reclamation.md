# D-884: Learning 저장 대상 풀과 검증된 로컬 자료 회수

**Status:** Accepted (2026-10-26, 사용자 설계 승인 및 구현 지시; 운영 활성화·실제 HF/Isaac 수용은 별도)

## 문제

로컬 디스크의 여유가 부족하고 Isaac Sim 학습 자료가 증가한다. 기존 저장 현황은 원격 quota 추정치 하나만 비교하며 예약하지 않는다. HF 왕복 전송은 원본·payload·readback을 함께 보유할 수 있어 로컬 공간을 추가로 사용한다.

## 결정

기존 계정 연결과 등록된 저장 root 위에 프로젝트별 저장 대상 풀과 영속 전송 작업을 둔다. 용량 소유자는 HF 저장소 namespace(user/org)이며 같은 소유자의 토큰·저장소는 quota 하나를 공유한다. 유효한 측정값에서 원격 여유분과 다른 예약·아직 반영되지 않은 commit bytes를 차감한 뒤 새 작업을 배정한다. quota 만료나 권한 부족은 사유를 표시하고 배정하지 않는다.

작업은 요청자·프로젝트·connection generation·repo·고정 commit·파일 SHA-256에 묶인다. 토큰은 기존 암호화 저장소에만 두고 요청별로 주입한다. 배정 뒤 결과가 불확실한 업로드는 hold로 남기고 원본과 예약을 보존한다. commit이 확인된 작업은 같은 revision의 읽기 검증만 재개한다. 진행 중 다운로드의 계정을 자동 교체하지 않는다(D-755).

등록 root의 완료된 자료 묶음은 `rosy.storage-source/1` manifest에 파일 집합·크기·SHA와 출처를 명시한다. manifest의 완료 표시는 파일 보관 범위이며 모델 성공·시뮬레이션 성공·실물 수용의 증거가 아니다. Isaac 자료는 run ID·seed·source revision을 보존하고 profile의 파일 종류를 제한한다. USD asset 참조 closure를 검증하지 않은 묶음과 Isaac 설치 폴더 전체는 받지 않는다.

업로드는 검증된 source 파일을 읽어 전송하고 고정 revision을 메모리 chunk로 읽어 다시 해시한다. 전체 payload/readback을 추가로 디스크에 만들지 않는다. 실제 전송 뒤 source도 다시 확인한다. 별도 기존 `hub_sync.py` CLI와 LeRobot 검증 계약은 유지한다.

로컬 회수는 원격 전체 SHA 검증, 현재 연결 권한과 고정 revision 재확인, 로컬 정확한 파일 집합·해시·디렉터리 identity 일치, 활성 사용·고정 보관 없음이 모두 필요하다. cache 외의 원본은 관리자가 해당 root에 `reclaimable: true`를 설정하고 사람이 작업 ID로 명시적으로 확인한 경우에만 회수한다. 정책 기반 회수는 관리 cache만 대상으로 하며 기본값은 비활성이다. 검수 DB·라벨·보정·임의의 폴더는 대상이 아니다.

전송·회수·복원은 프로세스 종료 시 운영체제가 해제하는 파일 잠금으로 직렬화하고 소비자는 같은 잠금의 공유 lease를 잡는다. 원장 상태만으로 살아 있는 worker의 소유권을 빼앗지 않는다. 회수는 격리된 이름으로 rename한 뒤 삭제하고 재시작 시 남은 파일만 검사한다. 복원은 새 partial 디렉터리에 고정 revision을 내려받아 검증한 뒤 원자적으로 게시한다. 로컬 부족·중단·권한 철회는 부분 자료를 학습 입력으로 노출하지 않는다.

원격 단일 사본은 독립 백업을 대체하지 않는다. 무료 용량의 지속 제공을 제품이 보장하지 않으며 quota를 늘리기 위해 자료를 자동 공개하지 않는다. 실제 계정 연결·업로드·운영 삭제·배포는 별도 운영 수용 기록에 남긴다.

## 소유권과 기존 결정

|---|---|

| D-429 | 외부 HF I/O와 로컬 자료 수명은 학습 경계에 둔다. Fleet/World/Decision의 현재 소유권을 바꾸지 않는다. |

## 검증

동일 조직의 중복 연결, 동시 예약, quota 갱신/만료, 권한·generation 철회, commit 후 429와 불확실한 결과, 원본 교체·추가 파일·symlink, 활성 lease·pin, 회수/복원 중 재시작과 ENOSPC를 원격 회귀로 확인한다. UI/API 권한·CSRF·반응형 회귀와 실제 배포 소스 포함을 별도로 확인한다. host 시험은 실제 HF 저장 성공이나 Isaac 생성 실행·실물 수용을 증명하지 않는다.

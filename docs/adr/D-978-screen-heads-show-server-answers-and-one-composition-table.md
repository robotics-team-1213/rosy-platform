## D-978 화면 머리(노선·수치 띠)는 서버 응답만 보이고, 화면별 적용은 「조합 어휘」 표 한 곳에서 관리한다

**Status:** Accepted (2026-11-04, 사용자 지시: "각 앱의 UI/UX 구조와 기타 부분이 규칙에 의해 한 곳에서 관리되도록" → "이어서 해줄래").

잇는 결정: [D-975](D-975-line-map-stage-track-and-app-lines.md)(노선) · [D-976](D-976-palette-from-product-scales-and-dense-tool-targets.md)(팔레트·도구 밀도) · [D-260](D-260-robot-shows-its-state-by-sound-light-screen-and-summary.md)(로봇 상태는 CORE 규칙표) · [D-945](D-945-cross-surface-layout-canon.md)(뼈대 자리) · [D-329](D-329-surface-registry-and-visual-baseline.md)(표면 레지스트리)

### Context

- 색·글자·부품·표면 목록·뼈대는 `tokens.css`·공용 시트·`surfaces.yaml`·D-945 시험으로 한 곳에서 관리된다. 화면 안 배치와 노선·수치 띠의 적용은 화면마다 코드에만 있었고, 화면 지도(2026-11-04, 작업 공간 기록)는 저장소 밖이었다.
- 노선·수치 띠를 Fleet 설치·정책·Cell에 붙이면서 "화면이 새 판정을 만들지 않는다"를 지켰지만, 그 규칙은 로그와 화면별 시험에만 있었다. Robot 대시보드에는 같은 이유로 노선을 넣지 않았다(D-260 5).

### Decision

1. **화면 머리는 서버 응답만 보인다.** 노선 역의 완료와 수치 띠의 값은 화면이 이미 받는 응답(또는 응답이 채운 요소)에서만 온다. 읽지 못한 근거는 완료로 그리지 않는다. 노선·띠 모듈은 쓰기 요청(POST·PUT·PATCH·DELETE)을 보내지 않는다. 근거가 없는 단계는 역으로 만들지 않고 화면 지도에 "서버 근거 필요"로 남긴다.
2. **「조합 어휘」 표가 화면별 적용의 정본이다.** `DESIGN.md` 표의 노선(`.ui-stage-track`)·수치 띠(`.ui-readout[data-form="strip"]`) 두 줄은 "지금 쓰는 곳"을 HTML 경로로 적는다. 표와 실제로 그 부품을 쓰는 페이지가 다르면 `test_content_vocabulary.py`가 실패한다. 화면에 부품을 붙이거나 떼는 커밋은 같은 커밋에서 표를 고친다.
3. **쓰기 금지는 시험이 본다.** `*-line.js` 노선 모듈과 수치 띠 계산 함수가 있는 모듈은 같은 시험이 쓰기 요청 문자열을 거절한다.

### Consequences

- 새 화면이 노선·띠를 쓰면 표 한 줄을 고쳐야 하므로 적용 현황이 저장소 한 곳에 남는다. 화면 지도 페이지는 이 표와 캡처를 보여 주는 보조물이다.
- 세 칸 배치(`.ui-stage-grid`)는 아직 생산 화면이 쓰지 않는다. 첫 적용 화면이 생기면 같은 방식으로 표에 경로를 적고 시험 대상에 더한다.

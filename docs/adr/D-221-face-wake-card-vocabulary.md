## D-221 얼굴 웨이크 카드의 어휘 — 라벨은 기계 약어로 남는다

**Status:** Accepted (2026-09-25)

**Context:** F-07(회차 1, 2026-09-21)은 로봇 얼굴 웨이크 카드의 라벨이 영문
약어(MODE·NAV·HEALTH)인데 청중은 행인이라는 어휘 긴장을 "소유자 결정"으로
남겼고, 입력은 BENCH 1.5m 가독 실측이었다. 2026-09-25 저장소 안에서 잴 수
있는 사실이 셋 생겼다:

1. **폰트 의존의 실체.** 제품 이미지(네이티브 Ubuntu Server 24.04 arm64)와
   개발 컨테이너 모두 어떤 CJK 폰트 패키지도 설치하지 않는다. 렌더러의
   폰트 후보는 DejaVu 두 경로뿐(한글 글리프 없음). 한글 라벨은 이미지에
   폰트를 싣는 배포 의존 — 몇 MB의 이미지 예산과 새로운 검증 경로를
   만든다.
2. **값은 서버 enum 이다.** 행(MODE/NAV/HEALTH)의 값은 IDLE·NAVIGATING·
   E-STOP·ASSIST REQ — 서버 어휘다. 라벨만 한국어로 바꾸면(모드: IDLE)
   한 카드 안에 두 어휘가 섞이고, 행인은 여전히 값을 못 읽는다.
3. **문법이 이미 답한다.** concept 16 §7.4: 얼굴은 "텍스트를 읽지 않고"
   1.5m·0.5초에 읽히는 표면이다. 행인의 채널은 원래 글자가 아니라 형태와
   색이다 — 배터리 봉(채움+색), 위험 칩(D-202 얼굴 번역), 만료-복귀(§5).
   그 채널들은 이미 갖춰져 있고 게이트가 지킨다.

**Decision:**

1. **라벨은 기계 약어로 남는다.** 웨이크 카드의 행 라벨(MODE·NAV·HEALTH)은
   로봇 어휘의 약어 그대로다. 행인을 위한 얼굴의 약속은 글자가 아니라
   형태·색·만료이고, 그 약속은 이미 계약이다(배터리 채움·위험 칩·hold_s).
   라벨 번역은 값을 번역하지 않는 한 행인에게 아무것도 주지 않고, 값을
   번역하는 것은 서버 어휘(운용자 콘솔·이벤트와 공유)를 바꾸는 별도의
   결정이다.
2. **폰트 의존을 만들지 않는다.** 렌더러의 폰트 후보는 DejaVu 둘로
   고정이다. CJK 폰트 경로가 후보에 들어오는 것은 이미지가 그 폰트를
   싣는 ADR 와 같은 커밋에서만 일어날 수 있다.
3. **BENCH 질문의 재정의.** F-07 의 남은 질문은 "라벨을 무엇으로 할까"가
   아니라 "비문자 채널(봉·칩·%)이 1.5m 에서 0.5초에 읽히는가"다. 실물
   LCD 사진이 답한다(회차 bench-checklist).

**Alternatives:** 한글 라벨 + 이미지 폰트 적재 — 행인 채널이 글자가 아니므로
이득이 없고 배포 의존만 생긴다(사실 1). 아이콘화 — 14px 아이콘은 희귀
독자에게 약어보다 학습 비용이 크다. 값의 한국어화 — 서버 enum 을 얼굴만
번역하면 표면 어휘가 갈라진다(Law 4 는 표면별 어휘를 허용하지만 enum 은
운용자와 공유하는 계약 어휘다).

**Consequences:** 웨이크 카드의 라벨 표는 고정된다(MODE·NAV·HEALTH) —
변경은 이 ADR 의 amendment 다. 얼굴에 한국어가 필요해지는 날(예: 안내
문안 추가)은 폰트 적재 ADR 이 선행한다. 부팅 카드의 슬롯(BOOTING·READY
등)도 같은 결정에 묶인다 — 설치자 청중에게 영문 스테이지명은 평문이다
(Law 4).

**Validation / Transition:** 구현 커밋에서 라벨 표·폰트 후보 고정 계약
시험 추가 + 변이 증명(라벨 교체 → 적색).

**References:** concept 16 §3 Law 4·§5·§7.4, D-72, D-75, D-82, D-153(회차 1
F-07), D-190, D-202(얼굴 번역), D-219.

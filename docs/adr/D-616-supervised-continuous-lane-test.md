## D-616 개발용 연속 차선추종 시험은 CORE hold lease를 유지하며 정지 상태도 계속 관찰한다

## Status

Accepted (2026-10-10, 사용자 요청: 시간마다 시험을 끝내지 말고 관제에서 보며 계속 시험). SOURCE·원격 시험·실물 실행 증거는 별도 기록한다.

## Context

D-614의 v2는 두 로봇에서 실제 CAMERA_LINE과 횡단보도 접근 정지를 실행했다. 기존 시험 도구는 최대 시간, 3초 무이동, lane_departure 등의 사유로 모드를 OFF로 바꿔 현장 관찰을 끊었다. 사용자는 안전장치를 보수적으로 유지하며 테스트/개발 모드로 계속 관찰하고 수정하기를 요청했다.

## Decision

1. 기존 `tools/capture/edge_drive.py drive --continuous-test`를 사용한다. 기본 drive 동작은 유지한다. 이 옵션에서는 최대 시간·무이동·CORE HOLD 사유로 시험 세션을 끝내지 않고 상태와 녹화를 계속 관찰한다.
2. 기존 인증 operator와 CAMERA_LINE `hold_s: 1.0`, `/line-follow/hold`를 그대로 사용한다. D-378 R2의 현장 감독과 즉시 정지 수단을 전제로, 사용자가 명시적으로 시작한 개발 시험의 **전경 연결 세션**이 진행 입력을 유지한다. 데몬, 부팅 자동 시작, 접속을 잃어도 살아 있는 분리 프로세스로 실행하지 않는다.
3. CORE의 body/IR/센서 freshness/E-Stop/횡단보도·막힘 판단은 그대로다. 도구는 안전 판단을 바꾸거나 stuck 승인·E-Stop 해제·자동 재무장을 보내지 않는다. 연속 관찰은 연속 바퀴 명령이나 강제 탈출을 의미하지 않는다.
4. Ctrl+C, 터미널 종료, 관제 OFF, 상태 읽기 실패, hold 거절이면 세션을 끝낸다. finally OFF와 녹화 종료를 수행한다. 갑작스러운 프로세스/연결 손실은 기존 1초 hold 만료로 정지한다. `--rearm`은 연속 시험에서 무시한다.
5. 테스트 모드는 정식 모델 intake 승인·전체 코스 합격·현장 구동 결함 해결을 대신하지 않는다. 8kcn의 명령/odom 회전 불일치는 기존 증거와 함께 결함으로 유지한다.

## Scope / Verification

새 CORE 필드, 인증 개발 모드 전환, 모델 또는 runtime build는 필요 없다. 기존 캡처 도구 옵션·관련 시험만 바꾼다. 합성 시험은 시간 예산을 넘겨 HOLD를 관찰하는지, OFF/lease/연결 손실/인터럽트 뒤 OFF·녹화 종료와 재무장 없음이 성립하는지 검사한다. 실물은 유지 신호가 끊긴 뒤 정지하고 관제 OFF로 종료되는지 따로 확인한다.

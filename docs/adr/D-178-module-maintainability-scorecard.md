## D-178 모듈의 병렬 작업 가능성은 평가표로 측정한다 — 5개 판정 축(M1–M5), 컷 게이트, 기준선

**Status:** Accepted (2026-09-23). 1차 회차(20개 패키지 실측)가 이 표를 채우고,
2차 회차(`control`·`core_features`·`navigation`·`gz_sim` 내부 모듈 분해)가 갱신을 마쳐
착지 조건을 충족 — 선기록 후 실측으로 승격하는 D-162/D-167 패턴.

**Context:** "여러 명이 미들웨어를 동시에 고친다"는 목표를 재는 표가 없다. D-167은
**미들웨어 목표**(단일 관문·Local-First·단일 최종 명령…)를 8개 축 G-1~G-8로 GO/HOLD
판정하지만, 축 단위라서 "이 패키지를 두 사람이 동시에 건드려도 충돌하지 않는가"를 재지
않는다. D-168은 **기계가 검사하는 구조 규칙**(선언 필수·도메인 방향표·자기
시험·600/10k 예산)을 시험으로 고정했지만 규칙은 합격/불합격만 말하고 **얼마나
위험한가, 어디부터 고치는가**는 말하지 않는다. 2026-09-23 1차 실측(20개 패키지)에서
세 가지가 표에 잡혔다: (a) 시험 소유가 패키지 소유와 어긋난 4곳(`core_features`,
`core_events`, `web_common`, `navigation` — 자기 `test/` 0), (b) **인바운드 결합**
(`core/test` 74개 파일이 최소 6개 패키지의 검증을 겸함)은 패키지 fan-out 표에 안
보이는 것, (c) fan-out 0인 패키지(`gz_sim`)가 launch·이미지 경유로만 묶이는 것. 한 장에
앉히는 표가 없어 개선 순위가 논쟁이었다.

**Decision:**

1. **축은 다섯 개고 공식은 합산이다 (M1–M5).** G-숫자(D-167 목표 축)와 충돌하지 않도록
   모듈 축은 **M**으로 부른다.

   | 축 | 명칭 | 판정 질문 | 가중치 |
   |---|---|---|---|
   | M1 | 독립 작업성 | 한 명이 **이 모듈만으로** 구현 → 단독 시험 → 검증까지 끝낼 수 있는가 (외부 모듈 소스 트리나 외부 시험실에 발이 묶이지 않는가) | 25 |
   | M2 | 역할 명확성 | 패키지명·디렉터리·`AGENTS.md`가 실제 책임과 일치하는가, 단일 책임인가, 크기 예산(파일 600행 / 패키지 10k행) 안에 있는가 | 25 |
   | M3 | 동시 유지보수성 | 두 사람이 동시에 고쳐도 충돌이 나지 않는가 — (a) 시험이 자기 패키지에 있는가, (b) fan-out·전파 반경이 작은가, (c) 경계를 코드로 고정한 게이트가 있는가 | 20 |
   | M4 | 공용 모듈 관리 | 공통 코드가 공용 모듈로만 수렴하는가(복제 없음), 도메인 방향표를 지키는가, 공용을 커지지 못하게 하는 예산·계약 게이트가 있는가 | 15 |
   | M5 | 결합 강도·정합 | `package.xml` 선언이 실제 import/launch와 일치하는가, 순환·역방향 결합이 없는가, 결합 유형이 데이터/스탬프 수준인가 | 15 |

   `총점 = Σ(축 점수 × 가중치) ÷ 5` (각 축 1~5점, 최대 100, 가중치 합 100).

   | 점수 | M1 독립 작업성 | M2 역할 명확성 | M3 동시 유지보수성 | M4 공용 관리 | M5 결합 정합 |
   |---|---|---|---|---|---|
   | 5 | 자기 시험 보유 + 코드 fan-out 0 + 외부 소스 불필요 | 책임 문서 고정 + 예산 준수 | 자기 시험 소유 + fan-out ≤1 + 경계 게이트 존재 | 도메인 공용 계약 수렴 + fan-out 0 + 오염 게이트 있음 | 선언=실제, 순환 0, 데이터/스탬프 결합만 |
   | 3 | 시험이 외부 패키지 시험실에 있거나, 런타임이 외부 소스 트리 필요 | 한 패키지 안에 복수 책임 공존 (or 예산 초과 + split 판정 기록) | 시험 홈 공유로 충돌 가능 / fan-out 2 / 전파 반경 ≥3 | 방향표 예외 기록, 부분 복제, 공용 적용 범위 어긋남 | 미선언·과잉선언 1~2건, 기록된 역방향 1건 |
   | 1 | 미선언 코드 결합으로 단독 검증 불가 | 책임 불명확 + 예산 초과 무기록 | fan-out ≥3 + 시험 미소유 | 공용 자리에 복제, 또는 공용이 상위를 의존 | 순환, 내용(구현) 결합, 게이트 부재 |

2. **합산은 쓰되 컷 게이트로 한 축이 다른 축에 눌리지 못한다.** D-167이 0–100 합산을
   버린 이유는 **안전 축**(G-3 단일 최종 명령, G-8 관제 이완 안전)이 높은 점수에
   상쇄될 수 있기 때문이다. M축은 **안전 축을 담지 않는다** — 안전은 D-167 G-3/G-8과
   D-168 기계 시험이 그대로 소유한다. 그래서 상쇄 사유는 여기 성립하지 않고, 대신 같은
   원칙을 축 단위 하한선으로 건다.

   - **M5 ≤ 2 또는 M3 ≤ 2 → 등급 상한 B**
   - **M2 ≤ 2 → 등급 상한 C**
   - **S는 M3 ≥ 4 이고 M5 ≥ 4 필수** — 병렬 작업 표면과 결합 정합이 완전해야만 최고 등급
   - 점수 구간과 게이트는 **더 낮은 쪽이 이긴다**

   | 구간 | 등급 | 의미 (여러 명이 일할 때) |
   |---|---|---|
   | 90–100 | S | 즉시 병렬 개발 가능 — 현상 유지 |
   | 75–89 | A | 양호 — 계약 시험만 유지, 소규모 정리 |
   | 60–74 | B | 한 축이 명확히 약함 — 개선 계획 필요 |
   | 45–59 | C | 병렬 작업 시 충돌/깨짐 리스크 — 우선 개선 |
   | 0–44 | D | 구조적 재설계 대상 |

3. **M1은 코드 결합만, M3은 시험 소유·전파·게이트만 본다.** "시험이 남의 패키지에
   있다"는 한 현상을 두 축에서 함께 깎으면 이중 감점이라, 시험 소유·전파 반경·게이트
   존재는 **M3에서만** 채점하고 M1은 구현을 갈라놓는 외부 코드 소스·fan-out만 본다.
   시험 소유 판정은 D-73 `functional` 목록과 D-168 P2(d) `KNOWN_WITHOUT_OWN_TESTS`
   예외 목록을 **소비만** 하고 새 예외를 만들지 않는다.

4. **aarch64 전용 패키지는 보정하지 않는다 — 기기 전용 ※만 단다.** `imu_bno055`,
   `lamp_control`, `sensor_adc`도 같은 기준으로 채점한다. ※는 "낮은 점수의 원인이
   결합이 아니라 테스트 전략(aarch64에서만 도는 시험)일 수 있다"는 독해 지시이며,
   점수를 올려주는 보정 장치를 만들지 않는 것이 이 항목의 핵심이다.

5. **판정 단위는 1차 패키지, 2차 C/B 모듈의 내부 모듈이다.** 1차는 저장소의 ROS
   패키지 20개(2026-09-24: +`pinky_pro` 잠정, D-196) — **집합 동일성**: 새 패키지가 생기면 기준선에 없어 시험이 붉다. 2차는
   **`apps/control`, `core/core_features`, `navigation/navigation`, `sim/gz_sim`
   4개**만 내부 모듈/파크 단위로 분해해 병렬 작업 충돌 지점을 뽑는다 (판정 단위를
   표면으로 고정하는 D-153 패턴).

6. **재평가 트리거는 게이트가 이미 붉게 만드는 순간이다.** 다음 중 하나면 재채점:
   D-168 `KNOWN_*` 예외 목록 변동(집합 동일성이라 추가·제거 모두 적색),
   `SIZE_VERDICTS` 판정 변경, 패키지 신설·삭제, D-171 control 분리 단계 완료, 시험 소유
   이전(`functional` 목록 변동).

7. **회차 문서도 정본 저장소에 둔다.** 채점표와 선행 결합 보고는
   `docs/assessments/module-coupling-scorecard.md`와
   `docs/assessments/module-coupling-report.md`다. 부모 폴더에 두던 사본은
   여기로 들였다. ADR은 기준과 기준선만 소유한다. 채점의 **산출
   규칙**(가중치 합 100, 총점 재계산, 등급 구간, 컷 게이트, 패키지 집합 동일성)은
   `test/test_module_scorecard.py`가 이 표를 재계산해 검사한다. **점수 값 자체는 회차
   입력이라 시험이 고정하지 않는다** — 주관 채점은 회차 문서가 소유하고 시험은 규칙만
   본다.

점수를 재확인 — **변동 없음**(`control` 57 · `core_features` 59 · `navigation` 57 ·
`gz_sim` 71). 정정 3건 반영: (a) `core_features` 비고 "5.5k 예산 초과"는 잘못된
표기였다(패키지 예산 10k에 실제 5,583행 → 예산 내; M2=3은 "13개 기능 공존" 앵커로
유지), (b) `control` 600행 파일 4건 → **5건**(SIZE_VERDICTS와 일치: split 2·accept 3),
(c) `core_features` 외부 시험 소유 28 → **29개**(core/test, 그 외 2곳 — 시험이 3곳에
분산). 충돌 지점(단일 조립 파일·외부 시험실·fan-in 핫스팟)은 회차 문서 §8.5에 있다.

**Alternatives:**

- **D-167 표에 모듈 축 5개를 추가하는 안** — 목표 축(G)과 모듈 축(M)이 한 표에 섞이면
  판정 단위가 흐려지고 D-167의 착지 조건(첫 회차가 G표를 채우면 Accepted)이 흐려진다.
  별건으로 분리한다.
- **점수를 D-168 시험으로 강제하는 안** — 주관 채점을 집합 동일성으로 검사하면 점수와
  시험을 같이 고치는 위증이 쉬워진다. 시험은 산출 규칙만 검사한다(Decision 7).
- **합산 없이 GO/HOLD만 쓰는 안** — 패키지 20개에 GO/HOLD는 분별력이 없다(전부 HOLD
  아니면 전부 GO). 등급 + 컷 게이트가 분리도와 하한선을 동시에 준다.
- **점수 없이 순위만 매기는 안** — 기준선이 없으면 매 회차 재논쟁이다.

**Consequences:**

- C/B 4개의 개선이 "권고"가 아니라 **기준선 회귀 방지**가 된다: D-168 예외 목록 축소 =
  M1/M3 상승, 미사용 선언 제거 = M5 상승이 그대로 점수로 보인다. D-168·D-73과 같은
  방향으로 조인된다.
- `core_features`(59, C)·`control`(57, C)·`navigation`(57, C)이 개선 순위 상단에 고정된다
  — D-171 control 분리 순서와 같은 방향을 가리키는 **독립 증거**.
- 기준선 갱신은 회차 문서 없이 이뤄지지 않는다(Decision 7): ADR 표 = 스냅샷,
  채점표 = 근거.
- 기기 전용 ※는 감점을 유지한 채 원인만 분리한다 — 보정 없음.

**Validation / Transition:**

- `python -m pytest test/test_module_scorecard.py -q` — 가중치 합, 총점 재계산, 등급
  구간, 컷 게이트, 패키지 집합 동일성을 기준선 표에 대해 검사.
- 변이 증명: 기준선의 한 점수를 바꾸면 총점·등급·게이트 검사가 함께 붉다 → 복구 후 초록
  (2026-09-23 실시).
- 하부 증거: `python -m pytest test/test_module_structure.py -q` 11 passed = M2/M4/M5의
  기계 검사 부분.
- **착지 조건 충족 → Accepted (2026-09-23)**: 2차 회차 완료(회차 문서 §8 — 내부 모듈
  분해·충돌 지점 도출) + 기준선 갱신(점수 변동 없음, 정정 3건 반영) → Status 승격.

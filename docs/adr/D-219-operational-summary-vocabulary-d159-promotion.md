## D-219 운용 요약 어휘의 실행 계약 — D-159 승격

**Status:** Accepted (2026-09-25)

**Context:** D-159(운용 요약 가시성 — 관리는 예외로, Law 0)는 "요약 어휘와
양 표면 동작에 실행 계약이 생길 때까지 Proposed"로 남아 있었다. 2026-09-25
점검 결과 조건의 절반은 이미 성립돼 있고 절반은 없었다:

- 콘솔(운용자): 분류 머리(triage)의 어휘는 `test_triage_contract.py` 가
  선언적 표로 지킨다 — CATEGORY_ORDER(hazard > blocked > mission >
  accuracy > observation), 머리 하나만 색, hazard/blocked 은 채움, 정상은
  머리 없음, 순수 파생(스스로 fetch 하지 않음).
- Fleet(관제자): 주의/최우선 개입 큐에 **실행 계약이 없었다** — 회차가
  쌓이는 동안 아무도 큐 규칙을 고정하지 않았다.

**Decision:**

1. **D-159 를 Accepted 로 승격한다** — 아래 계약이 양 표면을 채운다.
2. **요약 어휘(닫힌 집합).**
   - 콘솔: 머리 하나(범주·제목·설명) + 맥락(최대 셋, 무색) + 영웅띠의
     MODE·SAFETY. 정상은 머리도 색도 없다.
   - Fleet: 최우선 개입 큐(HITL — 로봇 이름 + 진짜 경로 안내)와 주의 큐
     (성능 저하 목록), 연결 약알(pill). 정상 로봇은 큐에 없다.
3. **Fleet 큐 계약(신설).** `src/site/fleet/test/test_console_queues_contract.py`
   — HITL 은 이름으로·정직한 경로로(Law 0, F-20 모의 버튼 금지), 성능 저하는
   주의 큐로, 빈 큐는 hidden 속성으로 사라진다(CSP), 큐 패널은 grid 영역
   고정(D-201). 변이 증명 완료(모의 버튼 복귀 → 적색).
4. **서버 판단 유지.** 요약은 스냅숏에서 파생된다 — 표면이 스스로 판단하지
   않는다(G4, D-72 S3/S4 와 같은 결).

**Alternatives:** 승격을 계속 미루는 안 — 콘솔 쪽 계약이 2026-09-21 부터
존재했고 없는 쪽(Fleet)을 발견하고도 방치하면 "Proposed"가 문서가 된다.
콘솔과 Fleet 의 요약을 하나의 공유 컴포넌트로 통합하는 안 — D-92/D-129 가
시각 컴포넌트 공유를 명시적으로 기각한 자리다(표면이 닮는 것이 결함).

**Consequences:** 새 요약 범주(콘솔 범주·Fleet 큐 종류)는 각 표를 고치는
커밋과 함께 온다. D-159 의 원문은 승격 배지만 얻고 다시 쓰지 않는다.
로봇 얼굴의 웨이크 카드는 이 ADR 의 표면이 아니다(만료-복귀 모델,
concept 16 §5).

**Validation / Transition:** 구현 커밋에서 (1) Fleet 큐 계약 시험 신설 +
변이 증명, (2) D-159 상태 승격, (3) ADR 로그 등록.

**References:** D-72, D-82, D-92, D-129, D-153, D-159, D-201, D-214,
D-218(F-20), concept 16 §3 Law 0·§5·§7.1·§7.3.

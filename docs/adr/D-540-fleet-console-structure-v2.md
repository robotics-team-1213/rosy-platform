## D-540 Rosy Fleet 콘솔 구조 v2 — 동작마다 한 자리, 로봇 카드가 그 로봇의 유일한 동작 자리, 움직이는 경로는 이름 있는 운영자

**Status:** Proposed (2026-10-09, 사용자 결정 세 가지: ① 운행 시작·취소·반복을 관제 로봇 카드로, ② 모든 움직임 경로에 이름 있는 운영자, ③ CORE trip 소유는 별도 ADR [D-541](D-541-core-fleet-trip-lease.md)). 화면 구조, 문구 규칙, Fleet 경로 권한만 정한다. 구현은 `docs/plans/2026-10-09-fleet-console-v2.md`의 브랜치 순서로 하나씩 한다.

### Context

2026-10-09 읽기 전용 감사 두 건(local main `59f8427c1`, API v1.154)이 네 문서(관제 · 설치·보정 · 현장 지도 · Cell)를 1440×900, 1024×768, 390×844에서 실제 Chromium으로 찍고 기능·경로를 표로 맞췄다. 원본은 `X:\DevTemp\fleet-ui-audit\audit.md`, `features.md`, 캡처 24장, `metrics.txt`다.

- **가장 급한 결정이 가장 안 보인다.** 막힘 판단 버튼 5개(`#stuck-panel`)가 큐 패널(`max-height: min(20dvh, 12rem)`) 안 스크롤 아래에 있다. 1440×900에서 제목만 보인다. 큐·로봇 목록·페이지 세 곳이 따로 스크롤한다. 1440×900 관제 문서 높이는 1299px다.
- **같은 일이 여러 곳에 있다.** 멈춤·취소가 다섯 곳에 다섯 꼴(비상 정지, 전체 주행 취소, 카드 `취소`, 현장 지도 `운행 취소` 빨간 채움, Cell `작업 취소`)이다. 운행 시작·취소는 현장 지도 문서에만 있고, 그 문서의 지도에는 로봇이 그려지지 않는다. 카메라 영상은 네 곳, 카메라 연결 승인 패널은 둘이다.
- **머리가 두 갈래다.** 관제·설치는 `#console-token`·`#user-role`·시계·연결 수·테마, 현장 지도·Cell은 `#session`·`#credential`만 있다. 현장 지도 E-stop은 접속 전 `disabled`, Cell은 아니다. "운영자"와 "operator", "운용자"가 섞인다.
- **원시 enum이 보인다.** `LINE_FOLLOW`, `CELL_APP_UNCONFIGURED`, `Vision 응답 503`, "선택된 line-follow가 CORE motion을 소유합니다". DESIGN.md "운용자 말"과 어긋난다.
- **설치 작업이 운영 화면에 있다.** 시작점 저장·삭제와 배경 다시 학습이 관제 지도 아래에 있다(D-410은 설치·보정 몫).
- **움직임 권한이 고르지 않다.** trip 시작·지도 가르치기·가상 신호는 이름 있는 운영자(`require_named_operator`)인데, 목표(`/goal`), 차선 주행(`/line-follow`), 차로 경로(`/route`), 대형(`/formation/*`), 막힘 결정(MANUAL·BACK_AND_RETRY 포함), 물리 신호 명령, 시작점 쓰기는 공유 토큰 `site-console`으로도 된다.
- **반쯤 지은 기능.** 배터리 잔량·CORE `motion_reason`은 로봇이 주는데 쓰지 않는다. 보정 lease 보유자와 현재 운전자를 Fleet이 모른다(trip은 409 `CALIBRATION_ACTIVE`만 받는다). D-524 호스트 제어, D-512 tether 쓰기, D-463 `/route`는 화면이 없다. D-438 사람 단계는 영상 없이 답한다. D-395 `needs_human` 배지에 동작이 없다.

### Decision

#### 1. 원칙: 보는 곳 하나, 누르는 곳 하나

로봇에 닿는 동작마다 운영 중의 자리는 하나다. 설정·보정은 운영 문서에서 뺀다. 문서 넷과 탭 줄(D-501), 웹 경로, 서빙 프로세스(D-518)는 그대로다.

| 동작 | 유일한 자리 | 지금 |
|---|---|---|
| 비상 정지(전체, 래치) | 공통 머리 `#estop` | 네 문서 머리, 꼴이 둘 |
| 이 로봇 정지 = 운행·목표 취소 | 로봇 카드 `운행 취소` | 카드 `취소` + 현장 지도 `운행 취소` + 큐 `중단` |
| 전부 취소(래치 없음) | 로봇 목록 머리 `전체 주행 취소` | 같음 |
| 목표 지정 | 로봇 카드 `목표 지정` 또는 지도 찍기(카드 선택 뒤) | 같음 |
| 운행 시작·반복 | 로봇 카드 `운행…` | 현장 지도 `운행` 칸 |
| 대열(리더–팔로워) | 대형 블록 `대형·대열` | 현장 지도 `대열 리더` |
| 막힘 결정 | 예외 큐 항목 펼침 | 큐 아래 `#stuck-panel` |
| 재계획 확인(`바뀐 경로로 계속`) | 예외 큐 항목 펼침 | 현장 지도 `운행` 칸 |
| Cell 작업 승인·취소 | 예외 큐 항목 펼침(승인), 로봇 카드 한 줄(진행) | Cell 5단계 |
| 위치 확인 필요(D-395) | 예외 큐 항목 펼침 | 배지만 |
| LED로 찾기, 새 주소로 옮기기 | 로봇 카드 | 같음 |
| 신호 명령 | 신호 블록 | 같음 |
| 지도 편집·가르치기·화면 방향·경로 미리보기 | 현장 지도 | 같음 |
| 카메라 보정·시작점·배경 다시 학습 | 설치·보정 `카메라 설치·보정` | 시작점·배경은 관제 지도 아래 |
| 로봇 등록·카메라 연결 승인·호스트 서비스 | 설치·보정 | 승인 패널 둘, 호스트 화면 없음 |

이 표가 "한 자리" 시험의 기준이다. 같은 경로를 부르는 버튼이 두 문서에 있으면 시험이 실패한다(7항).

#### 2. 공통 머리(네 문서)

- 네 문서가 같은 모듈 하나(`web/shared/`)로 같은 머리를 그린다. 구성: 브랜드·사이트 이름, 접속(세션 하나), 역할, 테마(설정 접힘 안), 연결 수, 시계, `#estop`. 문서별 부제는 탭 줄이 대신하므로 없앤다.
- **세션 하나.** 접속 상태는 `GET /api/fleet/auth/session` 하나로 정한다(D-519 5항). id는 관제 쪽(`#console-token`, `#user-role`, `#password-login`)으로 통일하고 `#session`·`#credential`은 없앤다. 토큰 입력은 D-519 6항대로 "토큰으로 접속" 접힘 안이다. 역할 글은 "운영자"·"보기 전용"이고 영어 역할 이름은 `title`에만 둔다. 개발 세션은 `개발 연결 모드` 배지 하나로 말하고 principal id(`development-…`)는 `title`에만 둔다.
- **비상 정지 규칙.** 모든 문서·모든 폭에서 같은 크기(넓은 단 305×80; 좁은 단은 지금 119×80·136×79·136×58로 갈린 것을 한 크기로), 같은 문구, 첫 화면 오른쪽 위다. 숨기거나 접지 않는다. 접속이 없을 때만 `disabled reason="접속이 필요합니다"`이고(요청이 401이 되므로), 네 문서가 같은 규칙이다. 확인 대화상자 위에서도 눌린다(DESIGN.md 확인 대화상자 절).
- 머리 높이는 넓은 단 한 줄, 1024×768에서 두 줄 이하, 390에서 화면 높이 20% 이하(D-359)다.

#### 3. 관제 `/console`

- **배치(64rem 이상).** 지도 3 : 레일 2(D-493). **문서는 스크롤하지 않는다.** 지도 열은 머리 아래 높이를 채우고, **레일 하나만 스크롤한다.** 큐와 로봇 목록은 자기 높이 상한과 자체 스크롤을 갖지 않는다. 레일 순서는 D-493 그대로: 예외 큐 → 로봇 → 관제 카메라 썸네일 → 대형·신호·기록.
- **지도 칸 아래.** 범례 한 줄과 `관제 범위 안내` 접힘 하나만 남는다. 시작점 도구와 `배경 다시 학습`은 설치·보정으로 간다(5항). D-536 로봇 상황 층은 그대로다.
- **예외 큐 항목은 그 자리에서 결정으로 펼친다.** 항목 하나를 누르면(또는 최우선 항목이 하나뿐이면 처음부터) 행 아래에 그 결정이 열린다. `#stuck-panel`은 별도 패널이 아니게 된다. 펼침 종류:
  - 막힘 판단(D-407/D-438): 사실 줄(앞·뒤·회전 여유, 시도, 멈춘 시간) + 증거(8항 해결기 영상) + 결정 5개(대기 / 재개… / 후진 후 재시도… / 수동 / 중단).
  - 재계획 확인(D-494 5항, D-517 5항): 바뀐 경로 요약 + `바뀐 경로로 계속` / `운행 취소`.
  - Cell 승인(D-503, D-450): 작업 요약(제안 결과에서 받은 셀·작업 id, 손 입력 없음) + `실행 승인` / `보류`.
  - 위치 확인 필요(D-395): 후보와 `이 자리로 확정…` / `LED로 찾기`.
  - D-536 안내(warn·crit): 안내 글과 목표 좌표, 동작이 있으면 그 버튼(G2).
  - 한 번에 한 항목만 펼친다. 큐는 D-493 1항 규칙(`attentionItems`)과 순서를 그대로 쓴다. 로봇 이름은 무리 머리에서 한 번만 쓴다(행 안 반복 없음).
- **로봇 카드는 그 로봇의 유일한 동작 자리다.**
  - 동작: `목표 지정`, `운행…`(출발 자리·목적지 고르기 → `운행 시작` / `반복 운행 시작`, 고리 정원 "고리 2/3대"), `운행 취소`(지금 카드 `취소` = 목표 취소와 현장 지도 `운행 취소`를 합친다: trip이 있으면 trip 취소, 없으면 목표·차선 주행 취소), `LED로 찾기`, `새 주소로 옮기기…`. 막힘·재계획·위치 결정은 카드에 두지 않고 큐 항목으로 보낸다(카드는 "판단 요청 · 큐에서 결정" 한 줄과 그 항목으로 가는 링크).
  - **기본 접힘 규칙(결정).** 정상 로봇은 한 줄로 접힌다: 이름 · 운행 한 줄(D-517 10항) · 배터리 잔량. 예외(`attentionItems` 비어 있지 않음)가 있거나 지도·큐에서 고른 로봇은 펼친다. 다음은 `attentionItems`에 없더라도 **반드시 펼친다**: 오프라인(연결 끊김·상태 없음), 비상 정지 래치 걸림, 안전 결함(CORE 안전 상태가 정상 아님), 보정 진행 중(보정 lease 있음). 사용자가 접어도 이 넷이 이어지는 동안은 다시 펼친다. 펼친 카드는 사용자가 접을 수 있고, 예외가 새로 생기면 다시 펼친다. 지금의 `전체 로봇 보기 · 정상 N대` 토글은 없앤다. 정상 로봇도 목록에서 사라지지 않는다.
  - 카드 줄 내용: 운영 모드 문구(원시 enum은 `title`), 운행 한 줄, 위치·방향, 배터리 잔량, 안전, CORE `motion_reason`(8항), 보정 lease 보유자·현재 운전자(8항), payload 버전(읽기 전용, 8항), Cell 작업 진행 한 줄.
- **로봇 목록 머리.** `전체 주행 취소`(quiet)와 발행 띠(`대기 작업 재허가`)는 머리 줄에 있고, 1024에서 레일 폭이 모자라면 머리 아래 줄로 접는다(버튼 글자는 한 줄).
- **대형 블록은 `대형·대열`이다.** D-20 대형(무장 / 대형 변경 / 재개 / 해제)과 D-517 M3 대열(리더와 팔로워 고르기 → `POST /trip`의 `convoy`)을 한 블록에 둔다. 비활성 사유는 블록 한 줄로 모으고 버튼마다 `위 사유`(DESIGN.md "한 원인은 한 번 말한다")다.
- **관제 경로(D-499).** 레일 머리 블록에서 빼서 머리의 연결 태그 옆 링크 태그로 둔다. 문제가 있을 때만 레일 큐에 행으로 나온다.

#### 4. 현장 지도 `/console/site-map`

- 남는 것: 지도, 활성·초안 선택, 화면 방향(`view_turn_deg`), 초안 편집, 지도 가르치기, `경로 미리보기`(표시 전용), 평면 영상 도구.
- **로봇 위치를 그린다.** D-536 `GET /api/fleet/guide`를 읽어 몸체 원·방향·불확실성 고리를 SVG에 그린다(관제와 같은 상황 기록, 같은 색 토큰). 운행 중인 로봇에는 trip 경로와 다음 장소를 읽기 전용으로 겹친다.
- **운행 칸을 없앤다.** 출발 자리·대열 리더·고리 정원·`운행 시작`·`반복 운행 시작`·`바뀐 경로로 계속`·`운행 취소`가 빠진다. 그 자리에 "이 지도로 운행 중: rosy_01 · 3바퀴째 — 관제에서 조작" 읽기 줄 하나와 관제 탭 링크가 남는다. 첫 화면의 위험 채움은 비상 정지 하나가 된다.
- `site-map.css`의 전역 `input, select, label, a` 재칠은 없애고 `ui-field`와 공용 파일 입력을 쓴다.

#### 5. 설치·보정 `/console/install`

- 작업 선택 구조(D-439/D-466)는 그대로다.
- **`카메라 설치·보정` 작업이 받는 것:** 시작점(D-513) 선택·저장·삭제, `배경 다시 학습`. 시작점 쓰기는 이름 있는 운영자다(9항).
- **카메라 연결 승인은 패널 하나다.** D-456(상대 화면 승인)이 기본이고, D-341 코드 입력은 같은 작업 안의 "코드로 연결" 접힘이다. 숨겨진 두 번째 패널은 없앤다.
- **호스트 서비스(D-524)는 작업 하나로 들어온다.** D-524가 수락되면 `호스트 서비스` 작업(목록·재시작·재부팅 예약, 이름 있는 운영자)을 더한다. D-524가 기각되면 `/api/fleet/hosts*` 경로를 지운다. 둘 중 무엇이든 "서버만 있고 화면 없음"으로 두지 않는다.
- 관제 카메라 미리보기는 공용 `vision-view` 하나이고 상태 문구는 6항의 한 출처에서 온다. 중복 id(`#vision-heading`)는 문서마다 하나다.

#### 6. 문구와 버튼 종류

- **운영자 글은 한 출처다.** 화면에 보이는 상태·모드·오류 문구는 `shared/web/core_ui_logic.js`의 `enumLabel()` 표에서 온다(DESIGN.md "운용자 말"). Fleet 전용 값(trip 상태, `TRIP_*`·`CELL_APP_*` 코드, 연결 이유, 영상 상태)도 같은 파일의 표에 더한다. 원시 enum·코드·HTTP 상태는 `title`·`data-*`·진단 접힘에만 둔다. 모르는 값은 지금처럼 받은 그대로 보인다. 영상 상태 문구는 셋("영상 연결 불가", "인증 대기", "영상 대기")이 문서마다 갈리지 않게 표 하나에서 나온다.
- **역할 낱말은 "운영자"다.** D-501을 Fleet 웹에서 문서·시험까지 맞춘다: DESIGN.md의 Fleet 쪽 예시 `reason="운용자 권한이 필요합니다"`는 Fleet 화면에서 "운영자 권한이 필요합니다"다. 로봇 대시보드 쪽 "운용자" 어휘는 이 ADR 범위 밖이다(D-501 범위 그대로).
- **비활성 사유는 한 번.** 버튼 안 `<small data-reason>`과 `title` 툴팁을 같이 쓰지 않는다. 같은 원인이 여러 버튼을 막으면 묶음 한 줄 + `위 사유`.
- **멈춤·취소의 버튼 종류(DESIGN.md:368과 D-493 4항의 충돌 해소).**

| 버튼 | 종류 | 확인 |
|---|---|---|
| 비상 정지 `#estop` | `irreversible` | 없음 |
| 전체 주행 취소 `#cancel-all` | `quiet` | 없음 |
| 로봇 카드 `운행 취소` | `quiet` | 없음 |
| 큐 펼침 `중단`(막힘 ABORT) | `quiet` | 없음 |
| Cell `작업 취소`(Cell 문서 원장) | `quiet` `작업 취소…` | `confirmIrreversible`(D-371, 장치를 멈추지 않는다고 대상 문장에 씀) |

  관제·현장 지도·Cell 어느 첫 화면에서도 위험 채움은 비상 정지 하나다. 멈추는 동작은 확인 없이 바로 나간다(멈춤은 안전 쪽이다). DESIGN.md "비상 정지" 절의 `primary`를 `quiet`로 고친다.

#### 9. 움직이는 경로는 이름 있는 운영자, 멈춤은 열려 있다

- **이름 있는 운영자(`require_named_operator`)로 바꾸는 Fleet 경로:** `POST /robots/{id}/goal`, `/robots/{id}/line-follow`, `/robots/{id}/route`(지우기 전까지), `/formation/{start,reform,resume}`, `/robots/{id}/line-stuck/decision`의 움직이는 답(RESUME·BACK_AND_RETRY·MANUAL·YIELD), `/signals/{id}/command`, `/start-points` 쓰기, `/api/fleet/do`, `/robots/{id}/identify`(LED, 장치를 움직이지 않지만 현장 장치 명령이라 같게 둔다). 이미 이름 있는 경로(trip, teach, site-map, traffic signals, hosts)는 그대로다.
  - 막힘 결정 경로는 **값으로 권한을 나눈다**: 움직이는 답만 이름을 요구하고 WAIT·ABORT는 열려 있다. CORE `POST /line-follow/stuck/decision`이 이미 같은 값으로 나눈다(`line_follow.py`, 움직이는 답만 보정 lease 검사). Fleet 경로는 본문 `decision`을 먼저 보고 움직이는 값일 때만 `require_named_operator`를 적용한다. API Reference 행에 이 나눔을 적는다.
- **열린 채로 남는 멈춤(`require_operator`, 이름 없어도 됨):** `POST /api/fleet/estop`, `/cancel-all`, `/robots/{id}/cancel`, `/trips/{id}/cancel`, `/tasks/{id}/cancel`, `/formation/stop`(해제만 하는 경로, `console_routes.py` "해제는 거절하지 않는다"), 막힘 WAIT·ABORT, `/robots/{id}/line-stuck/claim`(사람이 맡기만 하고 움직이지 않음). 공유 토큰으로 접속한 화면에서도 멈출 수 있다.
- 거절은 403 `OPERATOR_IDENTITY_REQUIRED`(지금 코드)다. 화면은 그 버튼을 `reason="이름 있는 운영자 로그인이 필요합니다"`로 잠그고 머리 로그인으로 안내한다. 감사 기록의 actor는 principal 이름이다(`site-console` 아님).
- Fleet 안의 기계 행위자(막힘 해결기 루프, trip 루프)는 HTTP 경로를 거치지 않으므로 바뀌지 않는다. 그 행위는 trip을 시작한 운영자 이름을 감사 기록에 함께 남긴다.
- **현장 이행(운영 메모).** 이 변경이 배포되는 순간 `site-users.yaml`이 없거나 로그인 줄이 없는 현장은 목표·차선 주행·대형·막힘 결정을 공유 토큰으로 보낼 수 없다(멈춤은 된다). 배포 전에 현장 관리자가 한다.
  1. 관제 PC에서 `python -m fleet.server.site_users hash-password`로 해시를 만든다(D-519 1항).
  2. `site-users.yaml`에 운영자마다 `login`·`password_scrypt`·`role: operator` 줄을 넣는다. 공유 토큰 항목은 기계·보기용으로 남겨도 된다.
  3. Fleet을 다시 시작하고, 다른 PC 브라우저에서 로그인 → 목표 지정 한 번 → 감사 기록 actor가 로그인 이름인지 본다.
  4. 개발 현장(D-473 개발 연결 모드)은 개발 세션이 이름 있는 운영자라 바뀌는 것이 없다.
  - 릴리스 노트와 `docs/plans/2026-10-09-fleet-console-v2.md` (a) 브랜치에 이 순서를 같이 싣는다.

#### 10. 범위 밖(감사에서 찾았지만 이 ADR에서 하지 않는 것)

- 관제 canvas 지도와 현장 지도 SVG를 한 그리기 엔진으로 합치기(B3). 이 ADR은 로봇 층을 현장 지도에 더하고 범례·색 토큰만 맞춘다.
- 카메라 영상 네 곳 중 위에서 본 그림(D-515)과 썸네일 원본의 정리(D-515 미결 그대로).
- 로봇 전면 영상 실시간 보기, 수동 조종, 녹화, SSH 키, payload 설치·롤백을 Fleet에 넣는 것(D-399: 로봇·Pilot 몫).
- D-438 해결기 기본 켬, D-492 모델 단계, D-511 M1/M2 교정, D-536 G2 이후 자동 동작.

- 로봇 대시보드의 "운용자" 어휘, 설치 순서를 설치 문서 단계 탭으로 옮기기.

### Alternatives

| 대안 | 판단 |
|---|---|
| 운행 칸을 현장 지도에 두고 관제 카드는 링크만 | 운행 중에 탭을 넘겨야 하고, 그 문서 지도에는 막힘·블록이 없다. 사용자 결정 ①로 기각 |

### Consequences

- 운영자는 한 로봇에 대해 카드 하나, 결정에 대해 큐 항목 하나만 배운다. 현장 지도는 편집 문서가 되고 운행 버튼이 없다.
- 이름 없는 공유 토큰 화면은 보기와 멈춤만 한다. `site-users.yaml` 로그인 줄이 없는 현장은 배포 전에 9항 이행을 해야 한다.
- D-517 10항 4번째 줄은 이 ADR이 대체한다(D-517에 개정 줄을 단다). 이 ADR이 수락되기 전에는 D-517 10항 그대로다.
- CORE 쪽 trip 소유(다른 화면의 수동 조종이 trip 로봇을 가져가는 문제)는 이 ADR로 풀리지 않는다. [D-541](D-541-core-fleet-trip-lease.md)이 정한다. 그 전까지 카드의 `운행 취소`는 Fleet trip만 끝낸다.

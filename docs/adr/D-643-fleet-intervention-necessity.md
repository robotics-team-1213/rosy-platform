## D-643 Fleet 판단 2단계 개입 비개입과 판단 보류 기준

**Status:** Proposed (2026-10-11, 사용자 요구: Fleet 중앙 판단 규약을 D-640보다 먼저 단계별로 다듬고 비개입과 외부 사람 처리를 포함). 문서만이며 구현·배포·모델 호출·외부 발송·장치 수용은 미실행.

### Context
개입이 필요하지 않은 정상 상태와 이미 해결된 상황도 판단 대상이다. 열린 문제만 모으면 불필요한 개입과 놓친 문제를 평가할 수 없다. 아무 답도 보내지 않은 상태는 비개입 판정의 근거가 아니다.

### 책임·배포 선행 관문
[D-647 공통 판단 책임·배포 0단계](../adr/D-647-shared-judgment-ownership-and-deployment.md)을 먼저 따른다. 이 ADR의 Fleet은 현재 소비자·서비스 문맥이다. 공통 상황평가 holder와 초기 배포는 아직 미결정이며 권고와 작업/자원 승인·원장 소유를 구별한다. 기존 Fleet transaction과 CORE/OMX 권한은 유지한다.

### Decision
1. 공통 상황평가는 개입 필요, 개입 불필요, 근거 부족으로 판단 보류를 권고하고 현재 Fleet 소비자가 이를 기존 owner 정책으로 처리한다. 이는 제안된 판단 의미이며 기존 로봇 명령 enum을 늘리지 않는다. 개입 여부, 사유/규칙 revision, 참조 근거, 유효 범위·재판단 조건을 기록한다.
2. 비개입은 신선한 상태에서 정상 진척, 기존 owner/교통 정책의 유효한 안전 대기, 독립 근거로 사건 해소, 다른 책임자가 이미 처리 중인 경우에 판정한다. 활성 owner가 정상 진척 중이면 새 명령·새 사건·외부 알림을 만들지 않는다. 담당자 처리 중은 방치와 구분하며 기한/실패 시 재판단한다. 사건 해소는 과거 `closed_at`만으로 현재 정상이라 추론하지 않는다.
3. 비개입은 모델 기권, 통신 실패, stale, 위치 불명, 증거 상충, 무시와 다르다. 근거 부족은 보류와 필요한 관측/사람 검토를 기록하며 기존 장치-local 안전과 허가를 유지한다. unknown을 이유로 Fleet이 임의 재개하거나 모든 정상 로봇에 blanket stop을 보내지 않는다.
4. 개입은 새 위험 근거, 목표 진척 실패, 제한 시간 초과, 복구 예산 소진, 자원 교착 지속 등 현재 계약의 조건으로 연다. 최초 후보와 지속 확정은 구별한다. 조건별 debounce/hysteresis/기한을 정하고 평가 시작 전에 고정한다. 신선한 새 근거·위험도 상승·기한 초과·owner 상실은 비개입을 만료시킨다.
5. 판단의 대상은 정상 관측 구간과 미지/실패 구간을 포함한다. observation 샘플 정책과 전이 기록을 제한 용량으로 남기되 매 poll마다 새 사건을 만들지 않는다. 정상 구간의 샘플링 편향과 분모를 보고한다. 이동/암의 근거는 도메인별이고 공통 판단 의미만 공유한다.

### 완료 관문
신선 정상 진척, 일시 정체, 정상 신호/자원 대기, 닫힌 사건, 처리 중, 진짜 막힘/교착, stale·상충·연결 단절·암 대상 실패를 구별하는 사람이 검수한 시나리오 표를 만든다. 비개입은 transport의 명령 전송 zero-call, 판정 보류는 기권 사유, 재판단은 새 revision으로 단언한다. 관측 읽기는 허용한다. 불필요 개입/개입 누락을 둘 다 측정하고 허용 기준이 미정이면 다음 단계 HOLD다.

### 기존 계약과 범위

D-427의 소유 분류, D-429의 후보/실행 분리, D-430의 safety gate와 CORE/OMX 최종 writer를 유지한다. D-608/D-619의 사건·상황 및 D-632의 inbox 의미를 재사용한다. 새 공개 API는 producer/consumer와 API Reference를 함께 변경할 때 확정한다.

단계 순서·수용 시나리오·파일별 작업은 [중앙 판단 선행 계획](../plans/2026-10-11-fleet-central-judgment-stages.md)을 따른다.

## D-829 업무 목표·제약과 공통 자원 배정·물리 점유를 분리한다

**Status:** Proposed (2026-10-21). 배정 책임과 후속 검증의 제안이다. 범용 스케줄러 구현·병렬 운행·자동 충전·새 실행 프로필을 허가하지 않는다.

### Context

업무 앱이 장치 ID와 대기·충전 순서를 모두 고정하면 도메인마다 가용성·충돌·복구 로직이 복제된다. 반대로 플랫폼이 업무 우선순위·출고 전략까지 결정하면 도메인 중립성이 사라진다. 공통 배정은 계획상 예약과 실제 장치·공간 점유를 구분해야 한다.

기존 Fleet에는 운송·action claim·교통 예약·charging admission의 서로 다른 소유 경로가 있다. `rosy.execution.site.charge_policy`는 에너지 예산을 평가하는 순수 계산이며 스스로 dispatch하지 않는다. 이를 한 DB나 새로운 중앙 서비스로 합칠 필요가 확인된 것은 아니다.

### Decision

1. 업무 앱은 대상·목적·업무 우선순위·선후관계와 허용 장치/능력·목적지·기한 등의 제약을 제공한다. 플랫폼은 승인된 정책과 가용 자원 안에서 실행 대상을 정하고 경합·admission을 집행한다. 앱은 후보 장치나 고정 작업대 제약을 줄 수 있지만 플랫폼의 권한·상태 검사를 우회할 수 없다.
2. 모든 작업을 단일 전역 최적화 문제로 만들지 않는다. 첫 구현은 기존 운송·작업·충전의 소유 경로를 재사용하고 선택 범위를 명시한다. 업무 전략을 바꾸는 최적화는 앱 또는 선택 가능한 공정 정책이 담당한다.
3. 장치 identity, 설치 역할, 현재 작업 역할을 구분한다. 설치 위치·도달 가능 영역 같은 제약은 프로필에 두고, 작업에 따라 바뀌는 운송·대기·충전 역할을 장치 번호에 하드코딩하지 않는다.
4. 예약·실제 사용·해제 근거·차단/불명을 구분한다. 물리 점유는 관측 또는 승인된 작업 결과로 확인한다. TTL 만료·클라이언트 종료·재시작만으로 공간이나 화물이 비었다고 간주하지 않는다. 미확인 사용 자원은 새 작업에 중복 배정하지 않는다.
5. 여러 자원의 동시 확보·부분 실패 정리는 해당 실행 경로의 기존 transaction·claim과 연결한다. 앱의 업무 예약과 플랫폼 실행 claim, 장치 lease는 서로 대체하지 않는다. 동일 자원의 독립 정본을 앱마다 만들지 않는다.
6. 충전 자리는 설치된 수용량을 가진 자원이다. 대기 위치와 충전 위치를 구분하고, 도착·접안·충전 시작·충전 종료·이탈 가능을 각각 확인한다. 배터리 예산에는 검증된 작업·복귀·접안·예비 비용이 필요하며, 없는 계측을 SOC 추정만으로 채우지 않는다.
7. 자동 충전 경로가 준비되지 않은 설치에서는 수동 교대·정비 차단을 표현할 수 있어야 한다. 적재·보유 불명 차량을 임의로 충전소로 보내거나, 충전소가 있다는 이유로 자동 운영을 활성화하지 않는다.
8. 기존 보수적 직렬 실행·동시 운행 제한은 유지한다. 자원별 병렬성을 열 때는 경로·영역·장치 owner의 조건과 실물 증거를 별도 변경에서 검토한다. 전체 잠금을 제거하는 것만으로 병렬 기능을 구현하지 않는다.

### 기존 결정과의 관계

| 결정 | 관계 |
|---|---|
| D-427·D-429 | Fleet의 원장·배정·admission과 World 관측 책임을 유지. 폴더와 자원 이름은 권한이 아님 |
| D-430 | 장치별 최종 실행·정지·안전 검증과 기존 병렬성 제한을 유지 |
| D-772·D-776 | 기존 충전 source·시간·replay fence·검증된 작업 예산 경계를 재사용 |
| D-773·D-797 | Proposed 장치 포트·실물 dispatch를 이번 설계로 개방하지 않음 |
| D-827·D-828 | 앱의 업무 제약과 플랫폼 배정을 나누고 실제 자원 해제를 근거에 결속 |

### Alternatives

- 앱이 모든 장치를 직접 배정: 특수 작업에 후보·제약을 주는 것은 허용하되 공통 가용성·경합 처리를 앱마다 복제하지 않는다.
- 플랫폼이 업무 전략까지 결정: 도메인 정책을 공통 원장에 결합시키므로 채택하지 않는다.
- 별도 범용 자원 서버·분산 잠금 서비스 도입: 기존 Fleet·장치 경로에서 해결할 수 없는 사례가 확인되기 전에는 도입하지 않는다.

### Consequences

첫 설계 산출물은 자원별 소유자·관측 생산자·예약 저장소·확보/해제 조건·미확인 복구·호출자의 표다. 실제로 같은 불변식을 가진 범위만 공통화한다. 충전·교통·팔 작업의 서로 다른 물리 조건을 하나의 만료 규칙으로 덮지 않는다.

### 검증 기준

- 업무 정책 또는 장치 후보 변경이 플랫폼 코드 변경 없이 가능하고, 플랫폼이 불가용·허용되지 않은 장치를 거절한다.
- 동시 배정·순서 역전·부분 실패·프로세스 재시작에서도 동일 자원 사용이 겹치지 않고 미확인 자원을 자동 해제하지 않는다.
- 충전 자리가 가득 찼거나 계측이 오래됐거나 도착 후 충전이 시작되지 않으면 작업 가능한 상태로 오인하지 않는다.
- 기존 직렬 실행·정지·권한 시험이 유지된다.

구현 단위와 관련 시험은 [실행계획](../plans/2026-10-21-domain-neutral-application-phases.md)에 둔다.

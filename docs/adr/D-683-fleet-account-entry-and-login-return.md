## D-683 Fleet 계정 진입점과 전용 로그인·업무 복귀

**Status:** Accepted (2026-10-12, 사용자 요청: 익숙한 우측 로그인/계정 규칙으로 재정리. 구현·회귀·설치·실물 수용 별도)

### Context

D-658의 접속 상세에 사람 로그인·계정·테마가 섞여 첫 사용자가 계정을 찾기 어렵다. 사용자 요청과 [후속 설계](../plans/2026-10-12-platform-ux-conventions-design.md)에 따라 인증 백엔드를 바꾸지 않고 계정 발견성과 업무 복귀를 정리한다.

### Decision

1. 네 Fleet 문서는 우측 유틸리티 영역에 로그인 링크 또는 계정 메뉴를 제공한다. 계정은 독립 안전 그룹 앞에 있고 비상 정지 위치·규격·권한을 바꾸지 않는다. 로그인/계정은 보이는 문구를 사용한다. D-641의 아이콘 단독 기본에 대한 이 두 조작의 한정 예외다.
2. 사람 로그인은 `/console/login` 문서에서 기존 D-519 API와 HttpOnly 쿠키로 수행한다. D-519 §6의 내장 로그인 폼과 D-658 §7의 계정 상세 위치는 이 결정으로 대체한다. D-658의 네 영역·안전·토큰/테마 펼침은 유지한다. 계정 메뉴는 테마/고급 토큰을 소유하지 않는다.
3. 로그인 성공 뒤 서버 세션의 cookie principal/role을 확인하고 허용된 네 Fleet 문서로 복귀한다. 복귀 주소는 same-origin allowlist이며 외부 주소·인증 반복·다른 제품 경로를 거절한다. 저장한 쓰기 요청을 자동 재실행하지 않는다.
4. 작업 화면을 강제 인증 리다이렉트로 떠나게 하지 않는다. 미저장 편집 중 로그인은 새 탭으로 제공하고 원래 작업과 재확인 방법을 설명한다. 재접속은 로컬 초안을 유지하고 기존 서버 revision으로 다시 검토한다. 자료를 덮어쓰거나 자동 저장하지 않는다.
5. 로그인 오류는 아이디를 보존하고 비밀번호를 지운다. 중복 제출과 계정 열거를 막는다. 쿠키·CSRF·Bearer 우선·속도 제한·감사는 D-519대로다. 로그인 미설정/개발 모드는 사람 로그인 성공처럼 표시하지 않는다.
6. 계정 메뉴는 현재 principal/role을 표시한다. 쿠키 로그아웃은 서버 종료와 세션 부재를 확인한 뒤 완료로 표시한다. 실패하면 현재 인증 표시를 유지하며 확인 불가와 재확인을 제공한다. 실패 응답만으로 자격이 폐기됐다고 주장하지 않는다. Bearer 접속 해제는 브라우저 자격만 제거하며 서버 토큰 폐기를 주장하지 않는다.
7. Robot/Pilot/Cam/Learning/Game/LCD는 후속 설계의 적용 표를 따른다. Fleet 쿠키를 다른 CORE 권한으로 확장하거나 없는 계정/SSO를 만들지 않는다.

### Existing contracts

| 계약 | 관계 |
|---|---|
| D-519 | 기존 인증 API/보안/기계 자격 보존; 사람 폼 진입과 계정 위치만 대체 |
| D-641, D-658 | 영역 소유권과 탐색 보존; 계정 문구 예외·계정 위치 대체 |
| D-427, D-429 | 기존 operations/ui/console과 Fleet 서빙/배포 closure 재사용; 새 최상위 폴더 없음 |
| D-430 | 명령·CORE·정지 의미/권한을 변경하지 않음. 독립 검토와 안전 접근 회귀 유지 |

### Consequences

전용 페이지·자산은 정적 allowlist/패키징에 포함한다. 네 문서의 계정 위치, 로그인→세션 조회→복귀, 입력 보존, 만료·로그아웃 실패, 320px 안전 접근을 원격 검증한다. CI/설치본/실물 증거는 별도다. 이 문서는 구현 완료를 뜻하지 않는다.

> 2026-10-13 [D-741](D-741-unified-app-shell-seats.md) Fleet 앱 바 조각: 2항의 "계정 메뉴는 테마와 토큰을 갖지 않는다"가 바뀌었다. 계정·화면 표시·토큰 접속이 계정 단추 아래 한 칸에 같이 있다. 1항의 로그인 링크 또는 계정, 전용 로그인 문서와 복귀는 그대로다.

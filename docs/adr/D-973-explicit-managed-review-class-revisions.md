# D-973: 검수 작업공간의 명시적 관리자 클래스 개정

**Status:** Accepted (2026-11-03, 사용자 요청). 실제 작업공간의 클래스 변경과 재검수 승인은 별도다.

## 배경

D-485의 최초 클래스 바인딩은 이미 기록된 번호와 정본 이름을 다른 뜻으로 해석하지 못하게 한다. 사용자는 검수 화면에서 현재 프로젝트의 클래스 표시를 고치거나 새 클래스를 추가할 수 있어야 한다. 기존 바인딩 함수를 느슨하게 만들면 자료 등록만으로 승인 의미가 바뀔 수 있다.

## 결정

일반 바인딩 함수의 최초 바인딩 제한을 유지한다. 별도 관리자 개정 경로 `GET /api/classes?kind=object|pixel`, `POST /api/classes/revisions`를 둔다. 로그인 작업공간은 현재 프로젝트의 `manage` 권한을 검사하고 기존 CSRF·Origin 검사를 적용한다. 요청은 서버가 이미 결합한 작업공간만 대상으로 하며 프로젝트·서버 경로 입력을 받지 않는다.

개정은 작업공간 전체 클래스셋에 적용된다. 자료 폴더 선택은 검수 대상을 좁히며 클래스셋을 분리하지 않는다. 화면은 전체 작업공간 범위와 재검수 대상 수를 표시하고 명시적 확인을 요구한다. 현재 전체 바인딩 문서의 SHA와 예상 무효화 건수가 달라지면 409로 거절한다.

기존 클래스의 번호·정본 이름·픽셀 역할·의미는 수정·삭제·재배열하지 않는다. 표시 이름과 색상은 수정할 수 있다. 새 클래스는 기존 번호를 유지하며 0..254의 미사용 번호에 추가한다. 객체 번호는 연속이어야 하고 픽셀 255는 계속 ignore다. 픽셀 배경은 정확히 하나이며 기존 클래스 검증기를 재사용한다.

D-485의 표시 정보 계약을 유지한다. 객체 표시 이름·색상과 픽셀 표시 이름만 바꾸면 기존 승인과 식별자는 유지한다. 픽셀 표시 이름은 기존 동결 매니페스트의 표시 오버라이드로 보관한다. 객체 클래스 추가 또는 픽셀 번호·역할·색상 구성이 확장되면 새로운 명시적 개정으로 기록하고 해당 종류의 승인만 버전을 올려 검수 대기로 돌린다. 제외 상태와 다른 종류의 검수는 유지한다.

개정 기록은 이전·새 바인딩, 작업자, 시각, 영향 건수를 추가 전용으로 저장한다. 식별자 또는 픽셀 색상 구성이 바뀌면 해당 종류의 모든 사진 버전을 올려 기존 탭의 저장·승인·재검수 요청을 거절한다. 미등록 픽셀 검수의 암묵적 v0도 새 버전으로 기록한다. 대기·제외 상태는 유지하고 승인 상태만 대기로 돌린다. 박스 좌표와 픽셀 마스크 파일·해시를 유지하고 모든 이전 상태·픽셀 바인딩과 승인 이력·미리보기를 보존한다. 픽셀 식별자가 바뀌는 개정은 상태 폴더 안에 내용 해시 이름의 YAML을 동결한다. 이전 AI 초안은 삭제하지 않고 격리·철회하며 진행 중 작업은 기존 바인딩 스냅샷 비교로 낡은 결과를 게시하지 못한다. 새 바인딩·버전·권한 검사를 통과한 새 추론만 같은 결과 해시의 초안을 최신 출처로 재게시할 수 있다. 오래된 가져오기와 낡은 작업은 격리를 해제하지 않는다.

## 검증

`test_review_classes.py`는 권한·CSRF, 낡은 SHA/영향 건수, 식별자 변경 거절, 승인 버전 증가, 제외 상태, 라벨 바이트·다른 종류 보존, 불변 이력과 초안 격리를 확인한다. 브라우저 시험은 추가·확인·반영 흐름을 확인한다. 호스트 시험과 실제 데이터의 운영 변경·수용은 구분한다.

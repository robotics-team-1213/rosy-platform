## D-475 고정 평가 세트에 사람이 검수한 정답 버전을 두고, MCAP 프레임의 출처를 증명해 검수 앱으로 받는다

**Status:** Proposed (2026-10-06, 사용자 "ADR 초안부터" 선택; 구현·실제 검수·평가 게이트 전환 별도).

### Context

D-379 결정 3은 고정 평가 세트도 자동 라벨(LiDAR 벽·주행 궤적)로 만들었고, 대안 절에서 "사람 교정 라벨은 필요해지면 평가 세트에만 도입을 다시 논의한다"고 남겼다. 이 ADR이 그 재논의다.

2026-10-06 모델 PC의 rosy_26 학습 기록에서 다음을 확인했다.

- 평가 세트 `rosy26-heldout-wall-role-20261006`(99장, 세션 `20261005T134540Z_rosy_26` 하나)에서 drivable IoU가 후보 모델마다 0.45~0.56에 머문다. 같은 기록의 오류 분석은 99장 중 39장이 LiDAR만으로 라벨을 만들어 drivable 정답 화소가 0이라고 적는다. 그 39장을 빼도 장당 평균 drivable IoU는 0.464로 거의 같다.
- 자동 drivable 정답은 "로봇이 실제로 지나간 폭 0.10 m의 띠"다(D-379 2026-09-30 부록 5). 모델이 차선 사이 바닥을 더 넓게 예측하면 정답과 어긋난다. 이 차이는 모델 오류가 아니라 정답 정의에서 생긴다.
- 그래서 같은 평가 세트로는 drivable 개선을 측정할 수 없다. 실제로 후보 `lane-seg-20261006-62db9403`은 이 세트에서 mIoU가 올랐지만 다른 평가와 실제 화면 확인에서 보류(`hold_shadow_promotion`)됐다.

사람이 정답을 고치려 해도 기존 도구가 받지 못한다. D-462 픽셀 검수 앱의 입력(`review_ingest.import_frames`)과 D-464 출처 증명은 원본 영상 SHA와 영상 프레임 번호를 요구하는데, 평가 프레임은 MCAP 녹화에서 뽑았다. 값을 지어내 넣는 것은 출처 위조라 허용하지 않는다. 기존 도구는 또 평가 세트를 학습 라벨에서 일부러 제외하도록 만들어져 있어 "평가 정답을 사람이 검수한다"는 경로가 없다.

### Decision

1. **범위는 평가 정답만이다.** 이 결정은 D-379의 "학습은 자동 라벨" 원칙과 D-464의 학습용 사람 라벨 경로를 바꾸지 않는다. 사람이 검수한 평가 마스크는 학습 데이터셋에 들어가지 않는다. 검수 대상 세션은 D-379 2026-10-03 부록과 D-464 §4의 평가 분리 inventory에 그대로 포함되어 학습 입력에서 제외된다.
2. **새 버전을 만들고 기존 버전은 지우지 않는다.** 사람 검수 정답은 같은 `rosy.perception.dataset/1` 스키마의 새 평가 세트 버전으로 `<store>/evalsets/<이름>/<내용 해시>/`에 쓴다. 매니페스트에 `annotation_origin: human_reviewed_eval`과 프레임별 검수 revision·승인 digest를 남긴다. 자동 라벨 평가 세트는 그대로 둔다. 두 버전의 점수는 서로 비교하지 않으며, 챔피언 비교는 같은 평가 버전 안에서만 한다.
3. **MCAP 프레임의 출처 증명.** 영상 필드를 흉내 내지 않고 출처 종류를 따로 둔다. `source_kind: mcap` 행은 `source_session`, `capture_group`, bag 파일 목록과 각 SHA-256, 이미지 토픽, 메시지 `log_ns`와 header stamp, 원본 이미지 SHA를 갖는다. 검증은 D-464 §3과 같은 원칙을 따른다. 같은 immutable snapshot의 bag bytes에서 그 메시지를 다시 decode해 저장된 원본 이미지와 화소가 같은지 확인한다. bag SHA 불일치, 메시지 누락, 증명되지 않은 재인코딩은 거절한다. `source_kind: video` 행의 기존 계약은 바뀌지 않는다.
4. **검수는 기존 픽셀 앱이 맡는다.** 새 앱을 만들지 않는다. D-462 앱의 입력 계약에 3항의 `mcap` 출처를 추가하는 것이 유일한 앱 변경이다. 승인 규칙은 D-464 §2와 같다. 전체·배경 확인을 명시하고, 값 255가 남은 마스크는 승인하지 않는다. 정답 확정 권한은 사람에게만 있다.
5. **평가 초안에 평가 대상 모델의 예측을 쓰지 않는다.** 검수자가 평가받는 모델의 출력을 정답으로 따라 그리는 편향을 막기 위해서다. 초안은 D-379 기하 라벨(LiDAR 벽, 궤적)만 쓴다. 근거가 없는 화소는 255로 비워 사람이 채운다. SAM 등 D-465의 범용 분할 초안은 경계 보완 용도로만 허용하고, 사용 여부를 매니페스트에 기록한다.
6. **drivable 정의는 검수 시작 전에 확정한다.** 지금의 자동 정의(지나간 폭 0.10 m)와 사람이 그을 정의가 다르면 같은 클래스 이름으로 다른 것을 재게 된다. 평가 담당자가 "로봇이 차선 규칙 안에서 주행해도 되는 바닥 전체"인지 다른 정의인지를 classes 문서에 먼저 적는다. 정의가 바뀌면 클래스 의미 변경이므로 학습 라벨과의 관계도 같은 변경에서 기록한다. 이 ADR은 정의를 정하지 않는다(미결 1).
7. **게이트 전환은 별도 기록이다.** intake `gate.yaml`의 `eval_set`을 사람 검수 버전으로 바꾸는 것은 이 ADR이 아니라 별도 변경에서 한다. 전환 전까지 intake는 두 평가 버전의 결과를 함께 보고할 수 있다. 사람 검수 버전의 최소 장수와 세션 수는 평가 담당자가 실행 전에 숫자로 정한다(미결 2). 현재 세트는 세션 하나뿐이라 다른 날과 다른 로봇에서의 일반화를 보증하지 않는다.

### 관계

| ADR | 관계 |
|---|---|
| D-379 | 결정 3의 "평가 라벨도 자동"을 평가 세트에 한해 확장한다. 학습 자동 라벨 원칙은 유지한다 |
| D-462 | 같은 앱과 같은 승인 권위를 쓴다. 입력 계약에 `mcap` 출처만 추가한다 |
| D-464 | 출처 증명 원칙(§3)과 승인 규칙(§2)을 평가 정답에 그대로 적용한다. 학습용 경로는 바꾸지 않는다 |
| D-465 | 초안 생성 도구를 재사용하되, 평가 정답 초안에는 평가 대상 모델 출력을 쓰지 않는다(5항) |
| D-427·D-429·D-430 | 새 폴더나 소유 경계를 만들지 않는다. 코드는 `learning/training/perception/` 안에 둔다. 안전 경로를 바꾸지 않는다 |

### Alternatives

- 자동 평가 세트에서 drivable만 빼고 mIoU를 계산: 당장 점수는 안정되지만 drivable 개선을 아예 잴 수 없다. 사람 검수 버전이 생길 때까지의 보조 보고로만 둔다.
- 영상이 있는 녹화에서만 평가 세트를 새로 뽑아 기존 앱을 그대로 사용: 앱 변경은 없다. 다만 기존 평가 inventory와 MCAP 세션을 버리게 되고, 영상이 없는 녹화는 영영 평가에 쓸 수 없다. 3항이 구현되기 전의 임시 경로로는 허용한다.
- 영상 필드에 MCAP 값을 넣어 기존 계약을 통과: 출처 위조이므로 채택하지 않는다.

### Consequences and verification

구현 순서는 (1) `mcap` 출처 행 생성과 bag 재decode 증명, (2) 앱 입력 계약 확장과 회귀 시험, (3) drivable 정의 기록, (4) 평가 담당자의 실제 검수, (5) 새 평가 세트 버전 빌드, (6) 별도 변경의 게이트 전환이다. 각 단계는 서로 다른 증거다. 시험은 synthetic MCAP fixture로 bag SHA 불일치, 메시지 누락, 화소 불일치, 255 잔존 승인, 학습 입력 누출을 거절하는지 확인한다. 문서 lint 통과는 실제 검수·평가 품질·모델 승격의 증거가 아니다. 이 결정은 현재 shadow 모델과 보류된 후보의 상태를 바꾸지 않는다.

**미결:** (1) 사람 검수용 drivable 정의, (2) 사람 검수 평가 버전의 최소 장수·세션 수, (3) 평가 검수 담당자.

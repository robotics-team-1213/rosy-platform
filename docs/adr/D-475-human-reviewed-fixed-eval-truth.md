## D-475 고정 평가 세트에 사람이 검수한 정답 버전을 두고, MCAP 프레임의 출처를 증명해 검수 앱으로 받는다

**Status:** Proposed (2026-10-06, 사용자 "ADR 초안부터" 선택; 구현·실제 검수·평가 게이트 전환 별도).

### Context

D-379 결정 3은 고정 평가 세트의 라벨도 자동으로, 가장 믿을 출처(지도 투영·궤적)로 만든다고 정했다. 2026-10-03 부록은 지도 투영이 아직 없어 LiDAR 벽과 궤적을 믿을 출처(`TRUSTED_SOURCES`)로 썼다. D-379의 대안 절은 "사람 교정 라벨은 필요해지면 평가 세트에만 도입을 다시 논의한다"고 남겼다. 이 ADR이 그 재논의다.

2026-10-06 모델 PC의 rosy_26 학습 기록에서 다음을 확인했다. 수치는 모델 PC의 파일에서 읽은 것이다.

- 평가 세트 `rosy26-heldout-wall-role-20261006`은 99장이고 세션 `20261005T134540Z_rosy_26` 하나에서 나왔다. intake가 보고하는 drivable IoU(평가 세트 전체 화소를 합쳐 계산)는 후보 모델마다 0.45~0.56이다.
- 같은 기록의 오류 분석에 따르면 99장 중 39장은 LiDAR만으로 라벨을 만들어 drivable 정답 화소가 0이다. 궤적이 있는 나머지 60장만 보면 모델 `lane-seg-20261006-28e8454d`의 drivable IoU 장당 평균은 0.464다. 화소 합산 값 0.449와 거의 같다.
- 자동 drivable 정답은 "로봇이 실제로 지나간 폭 0.10 m의 띠"다(D-379 2026-09-30 부록 5). 모델이 차선 사이 바닥을 더 넓게 예측하면 정답과 어긋난다. 이 차이는 모델 오류가 아니라 정답의 정의에서 생긴다.
- 그래서 지금 평가 세트로는 drivable 개선을 잴 수 없다. 후보 `lane-seg-20261006-62db9403`은 이 세트에서 mIoU가 올랐지만, 다른 평가와 실제 화면 확인 결과로 보류(`hold_shadow_promotion`)됐다.

사람이 정답을 고치려 해도 지금 도구는 이 프레임을 받지 못한다.

- D-462 픽셀 검수 앱의 입력(`review_ingest.import_frames`)은 원본 영상 SHA와 영상 프레임 번호를 요구한다. 프레임 정체성(`review_evidence.identity`)과 기존 행 연결도 영상과 프레임 번호를 기준으로 한다. 평가 프레임은 MCAP 녹화에서 뽑았다. 영상 값을 지어 넣는 것은 출처 위조라 허용하지 않는다.
- 평가 세트 빌더(`build.py --eval-set`)는 `lidar`·`trajectory` 출처만 받는다. 평가 세트 보조 검증(`training/review_eval_companion.py`)은 출처마다 영상과 sidecar를 요구한다. D-464 §4는 학습 빌드마다 store의 모든 평가 버전을 이 방식으로 다시 확인하고, 확인하지 못하면 UNKNOWN/HOLD로 멈춘다.
- D-464 §4는 사람 검수 라벨 경로가 "새 eval 정답을 만들지 않는다"고 적었다. 사람이 평가 정답을 검수하는 경로는 아직 없다.

### Decision

1. **범위는 평가 정답만이다.** D-379의 "학습은 자동 라벨" 원칙과 D-464의 학습용 사람 라벨 경로는 바꾸지 않는다. 사람이 검수한 평가 마스크는 학습 데이터셋에 들어가지 않는다.
2. **검수를 시작하기 전에 세션을 평가용으로 예약한다.** 평가 세트 빌드가 끝날 때까지 기다리면, 그 사이 같은 세션이 학습 빌드에 들어갈 수 있다. 그래서 검수 대상 세션과 capture group을 import 전에 store의 예약 목록에 적는다. D-464 §4와 D-379 2026-10-03 부록의 평가 분리 확인은 이 예약 목록도 읽어 학습 입력에서 제외한다. 예약을 해제하는 것은 기록을 남기는 별도 변경이다.
3. **검수는 평가 전용 workspace에서 한다.** 같은 앱 코드를 쓰되 state 폴더를 따로 둔다. 학습용 검수 workspace와 classes 파일이 다를 수 있고(6항), 앱은 기존 workspace의 classes가 바뀌는 것을 거절한다. 평가 workspace의 승인 결과는 학습용 export 경로로 내보내지 않는다.
4. **새 이름의 평가 세트를 만들고 기존 세트는 지우지 않는다.** 사람 검수 정답은 같은 `rosy.perception.dataset/1` 스키마로 `<store>/evalsets/<기존 이름>-human/<내용 해시>/`에 쓴다. 매니페스트에는 `frames[].sources`에 `human_reviewed_eval`을 적고, 프레임별 검수 revision과 승인 digest를 남긴다. 자동 라벨 평가 세트는 그대로 둔다. 챔피언 비교는 같은 평가 버전 안에서만 한다(D-379 2026-10-03 부록, `intake.py`의 content_sha 대조).
5. **MCAP 프레임의 출처 증명.** 영상 필드를 흉내 내지 않고 `source_kind: mcap`을 따로 둔다. 기준은 D-464 §3과 같다.
   - 행에는 `source_session`, `capture_group`, rosbag2 `metadata.yaml`과 bag 파일들의 SHA-256, 이미지 토픽과 채널, 메시지 `log_ns`, header stamp, 원본 이미지 SHA를 적는다.
   - 프레임 정체성 키는 (bag SHA 목록, 토픽, `log_ns`)다. 같은 `log_ns`가 둘이면 채널 ID와 메시지 순서로 구분한다. bag 순서는 `metadata.yaml`의 순서를 따른다(`extract.py`와 같은 규칙).
   - 검증은 bag bytes를 읽는 같은 읽기에서 해시를 계산하고 그 bytes에서 메시지를 decode해, 저장된 원본 이미지와 화소가 같은지 확인한다. 경로를 두 번 읽어 해시와 내용이 달라지는 경우(ABA)를 막는다.
   - 압축 이미지(`CompressedImage`)는 bag에 저장된 압축 bytes를 원본으로 본다. decoder 이름과 버전을 고정하고 기록한다. JPEG decoder마다 화소가 조금씩 다르기 때문이다.
   - 용량을 줄이려고 다시 쓴 bag(`shrink_session`의 `.compact` 등)은 재인코딩본이다. 원본 bag과 화소 동등성이 증명되지 않으면 출처로 인정하지 않는다.
   - bag SHA 불일치, 메시지 누락, 화소 불일치, 증명되지 않은 재인코딩은 거절한다. `source_kind: video` 행의 기존 계약은 바뀌지 않는다.
6. **바꿔야 하는 코드를 명시한다.** 새 앱을 만들지 않는다. 다음은 모두 `mcap` 출처를 받기 위한 확장이다.
   - 픽셀 앱 입력(`review_ingest`): `mcap` 행 검증. 기존 영상 행 연결(legacy linking)은 `mcap` 행에 적용하지 않는다.
   - 프레임 정체성(`review_evidence`)과 검수 행: 5항의 키.
   - 평가 세트 빌더(`build.py --eval-set`): `human_reviewed_eval` 출처를 받는 경로. 승인 규칙은 D-464 §2와 같다. 전체·배경 확인을 명시하고, 값 255가 남은 마스크는 쓰지 않는다.
   - 평가 보조 검증(`review_eval_companion`): `mcap` 출처 계보. 이것이 없으면 4항의 새 평가 버전 때문에 모든 학습 빌드가 HOLD가 된다.
   - 정답 확정 권한은 사람에게만 있다.
7. **평가 초안에는 학습된 모델의 출력을 쓰지 않는다.** 검수자가 모델 출력을 정답으로 따라 그리는 편향을 막기 위해서다. 이것은 평가 정답에 한해 D-465 §2(차선 초안은 기존 모델로 만든다)와 §3(외부 모델 보조)을 좁힌다. 학습 라벨 초안에는 D-465가 그대로 적용된다.
   - 초안에는 LiDAR 벽 같은 기하 라벨만 쓴다. 근거 없는 화소는 255로 비워 사람이 채운다.
   - 지나간 폭의 궤적 띠는 바꾸려는 정의 그 자체라, drivable 초안으로 넣지 않는다. 화면에 참고 표시로만 보여 준다.
   - SAM 등 범용 분할 모델은 사람이 찍은 점·영역을 따라 경계를 맞추는 용도로만 허용하고, 사용 여부를 매니페스트에 적는다.
8. **drivable 정의는 검수 시작 전에 확정한다.** 지금의 자동 정의(지나간 폭 0.10 m)와 사람이 그을 정의가 다르면, 같은 클래스 이름으로 다른 것을 재게 된다. 평가 담당자는 정의를 평가 workspace의 classes 문서에 먼저 적는다. 예를 들어 "로봇이 차선 규칙 안에서 주행해도 되는 바닥 전체"가 될 수 있다. 정의가 학습 라벨과 달라지면 그 관계를 같은 변경에서 기록한다. 이 ADR은 정의를 정하지 않는다(미결 1).
9. **평가 세트를 특정 후보에 맞추지 않는다.** 승인 뒤 정답을 고칠 때는 고친 이유를 검수 기록에 남긴다. 어떤 후보의 실패를 보고 정답을 고쳤다면 그 사실도 적는다. 이유 없는 수정은 새 평가 버전에 넣지 않는다.
10. **게이트 전환은 별도 변경이다.** intake `gate.yaml`의 `eval_set`을 새 버전으로 바꾸는 일은 이 ADR에 포함하지 않는다. 바꾸기 전에 현재 shadow 모델을 새 버전으로 intake해서 그 버전의 챔피언 기준을 먼저 만든다. intake는 한 번에 평가 세트 하나만 받으므로, 두 버전의 결과는 intake를 버전마다 따로 실행해서 얻는다. 새 버전의 최소 장수와 세션 수는 평가 담당자가 실행 전에 숫자로 정한다(미결 2). 지금 세트는 세션 하나뿐이라, 다른 날이나 다른 로봇에서의 일반화를 보증하지 않는다.

### 관계

| ADR | 관계 |
|---|---|
| D-379 | 결정 3의 "평가 라벨도 자동"을 평가 세트에 한해 확장한다. 학습의 자동 라벨 원칙은 유지한다 |
| D-462 | 같은 앱 코드와 같은 승인 권위를 쓴다. 평가용 workspace를 따로 둔다 |
| D-464 | 출처 증명(§3)과 승인 규칙(§2)을 평가 정답에도 적용한다. §4의 평가 분리 확인에 예약 목록과 `mcap` 계보를 더한다. 학습용 경로는 바꾸지 않는다 |
| D-465 | §8의 "사람이 확인한 독립 평가 마스크"를 실제로 만드는 경로다. 평가 초안에 한해 §2·§3을 좁힌다(7항) |
| D-427·D-429·D-430 | 새 폴더나 소유 경계를 만들지 않는다. 코드는 `learning/training/perception/` 안에 둔다. 안전 경로를 바꾸지 않는다 |

### Alternatives

- 자동 평가 세트에서 drivable만 빼고 mIoU를 계산: 당장 점수는 안정되지만 drivable 개선을 아예 잴 수 없다. 사람 검수 버전이 생길 때까지의 보조 보고로만 둔다.
- 영상이 있는 녹화에서만 평가 세트를 새로 뽑아 기존 앱을 그대로 쓰기: 앱의 출처 계약은 그대로다. 다만 기존 MCAP 평가 세션을 버리게 되고, 영상 없는 녹화는 평가에 쓸 수 없다. 5항이 구현되기 전의 임시 경로로 허용한다. 이때도 2·3·4·7·9항은 적용한다.
- 영상 필드에 MCAP 값을 넣어 기존 계약을 통과: 출처 위조이므로 채택하지 않는다.

### Consequences and verification

구현 순서는 다음과 같다. 각 단계의 결과는 서로 다른 증거다.

1. 평가 세션 예약 목록과, 학습 빌드의 예약 확인.
2. `mcap` 출처 행 생성과 bag 재decode 증명.
3. 앱 입력·정체성·평가 빌더·평가 보조 검증의 확장과 회귀 시험.
4. drivable 정의 기록.
5. 평가 workspace에서 사람의 실제 검수.
6. 새 평가 세트 버전 빌드.
7. 현재 shadow 모델의 새 버전 intake.
8. 별도 변경의 게이트 전환.

시험은 synthetic MCAP fixture로 다음을 거절하는지 확인한다: bag·metadata SHA 불일치, 메시지 누락, 같은 `log_ns` 처리, 화소 불일치, 증명 안 된 재인코딩, 255가 남은 승인, 예약 세션의 학습 입력 누출, `mcap` 계보 없는 평가 버전 때문에 생기는 학습 HOLD. 문서 lint 통과는 실제 검수·평가 품질·모델 승격의 증거가 아니다. 이 결정은 현재 shadow 모델과 보류된 후보의 상태를 바꾸지 않는다.

**미결:** (1) 사람 검수용 drivable 정의, (2) 새 평가 버전의 최소 장수·세션 수, (3) 평가 검수 담당자.

**Related:** D-356, D-373, D-379, D-434, D-462, D-464, D-465.

## D-647 공통 판단 0단계 World·Work Orchestration·Fleet 책임과 배포 경계

**Status:** Proposed (2026-10-11). 검토용 책임·배포 대안이며 서비스 분리, 소스 이동, 판단 구현, 설치·현장 수용을 수행한 결정이 아니다.

### Context
Fleet도 가용성·배차·교통·공유 자원을 판단하지만, 문 장애·암 작업 실패·정상 비개입을 평가하는 공통 능력을 전부 Fleet 소유로 고정하면 단일 셀과 로봇에서도 관제에 종속된다. 반대로 이를 World model이라고 묶으면 관측 상태, 미래 예측, 판단, 실행 승인이 혼동된다. D-642~D-646의 Fleet은 현재 소비자·배포 문맥이며 공통 판단의 영구 소유자를 확정하지 않는다.

현재 Accepted D-429는 `operations/decision`을 deliberative 후보 생성으로 한정한다. Proposed D-435는 Work Orchestration의 Mission 원장·수용·진척과 Fleet coordination의 구별을 제안하며 아직 수용되지 않았다. Accepted D-630의 World는 관측과 현재 상태 projection이며 행동 조건부 미래 예측은 구현돼 있지 않다. 현재 Fleet 배포가 `rosy.decision`을 함께 설치하고 판단 경로에 Fleet 저장소 의존이 남아 있는 것은 물리 배치 사실이며 공통 의미의 소유권 근거가 아니다.

### 제안하는 논리 책임

| 책임 | 입력과 출력 | 실행 권한 |
|---|---|---|
| World 현재 상태 | 출처·시각·revision을 가진 관측과 현재 상태 snapshot | 없음; 모델 가설을 관측 사실로 승격하지 않음 |
| 미래 World 예측(후속) | 상태·행동 후보에서 예상 상태/불확실성 산출 | 없음; 현재 구현으로 주장하지 않음 |
| 공통 상황평가 | 상태·목표·제약·근거에서 정상/이상과 개입 필요성·비개입·보류 권고 | 없음; 새 논리 holder와 실제 위치는 0단계에서 결정 |
| Deliberative Decision | 문제·예측·제약에서 대안/계획 후보, 모델 라우팅·제한 토론 또는 기권 | 없음; D-429의 deliberative 범위 유지 |
| Work Orchestration | 작업 수용·소유·진척·취소·복구·결과와 실행 승인 중재 | 해당 Mission의 기존 단일 owner/transaction 경로 |
| Fleet coordination | 로봇 가용성·배정·교통·공유 자원의 승인과 조정 | 기존 Fleet coordination 계약 안에서만 |
| 장치 owner와 독립 검증 | 허용 요청을 재검사·실행하고 실제 결과/목표 근거 회수 | CORE/OMX 등 기존 최종 writer; 판단·토론이 대체하지 않음 |

Console은 관측·판단·담당·조치·결과를 표시하고 인증된 사람 처리를 받는 진입점이다. 알림 채널도 같은 사건을 가리키며 공통 추론 소유자나 별도 장치 writer가 되지 않는다. 학습은 결과 교정과 독립 평가 후 승인된 버전을 소비하게 하며 자체 승격하지 않는다.

### 배포 대안과 잠정 추천

| 대안 | 이점 | 비용과 선택 조건 |
|---|---|---|
| A. 공통 판단도 Fleet 내부 책임으로 고정 | 현재 연결 비용이 작음 | 셀/단일 로봇의 재사용·시험이 Fleet 원장/서비스에 종속될 수 있음 |
| B. 공통 논리·입출력 경계를 먼저 정하고 초기에는 기존 서비스에 함께 배치 | 기존 transaction을 유지하며 셀/로봇 재사용과 이후 분리를 검토할 수 있음 | 실제 의존을 조사하고 권고와 승인 사이 port를 확정해야 함 |
| C. 공통 판단/예측을 즉시 독립 서비스로 배치 | 별도 소비자·자원·장애 격리 가능 | 지연·snapshot 일관성·stale/timeout·재시작·늦은 결과·인증 계약이 추가됨 |

**잠정 추천은 B다.** 새 범용 서비스나 디렉터리는 지금 만들지 않는다. 서비스 수와 공통 상황평가 holder는 아직 미결정이며, 실제 소비자와 의존·장애 격리 필요를 비교한 뒤 0단계에서 명시적으로 확정한다. 모델 실행기가 Fleet PC에서 동작한다는 배치 선택도 공통 판단 전체를 Fleet coordination 소유로 만들지 않는다.

### 0단계 완료 관문

1. 단일 암 셀, 단일 로봇, 다중 로봇의 동일한 정상/막힘/근거 부족 사례를 비교한다. 활성 Mission이 없는 관측 이상과 정상 비개입도 포함한다. 각 사례의 관측·상황평가·후보·작업/사건 owner·자원 승인·장치 writer·결과 검증을 이름 붙인다. Fleet coordination이 필요 없는 사례에도 억지로 Fleet 승인을 추가하지 않는다.
2. 공통 평가 입력은 불변 snapshot·목표·제약·근거 참조·버전, 출력은 필요성 권고·사유·불확실성·적용 전제·유효기간/재평가 조건으로 경계를 정한다. 평가 모듈이 Fleet DB/장치 transport를 직접 변경하지 않는 의존 표와 시험 seam을 검토한다. 공개 필드·wire는 이 ADR에서 신설하지 않는다.
3. 필요성 권고와 현재 owner의 승인·비개입 유지·사람 인수를 구별한다. 상충/보류/늦은 결과는 기존 local 안전을 유지하며 임의 재개하지 않는다. 작업/자원 transaction의 단일 소유와 중복·세대 fence를 보존한다.
4. 기존 `fleet.stuck`, Situation, World, `rosy.decision`, Mission/claim 원장의 실제 호출·설치 의존 표, 공통 로직의 holder/port, 초기 배포 위치와 선택 이유를 기록한다. 독립 서비스로 바꿀 조건은 실제 별도 소비자·자원 경합·장애 격리 요구 및 지연 예산으로 정하고 변경 시 실패/재시작/일관성 계약을 먼저 검증한다.
5. 위 결정과 단일 셀/로봇/다중 로봇의 검수 결과가 준비되어야 D-642~D-646의 공통 로직 구현 위치를 확정한다. 비개입 zero-command, 보류·상충·늦은 결과, 기존 원장/장치 권한 보존을 수용 기준에 포함한다. 그 이후 D-640의 모델 라우팅·토론과 독립 개선 평가를 진행한다.

### 기존 계약과 범위
Accepted D-429/D-630과 기존 권한 계약을 변경하지 않으며 Proposed D-435를 수용된 계약으로 취급하지 않는다. 공통 상황평가를 `operations/decision`에 넣으려면 deliberative 한정 계약을 별도 검토해야 한다. 이번 문서는 D-642~D-646과 D-640의 선행 판단 관문을 추가하는 Proposed 보완이며 실제 분리 완료를 뜻하지 않는다.

단계·파일별 작업은 [중앙 판단 선행 계획](../plans/2026-10-11-fleet-central-judgment-stages.md)을 따른다.

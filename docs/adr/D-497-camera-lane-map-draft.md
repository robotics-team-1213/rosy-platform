## D-497 현장 카메라의 관측 차선으로 Fleet 지도 초안을 만든다

**Status:** Proposed (2026-10-07; 사용자 구현 요청, SOURCE/LOCAL 검증 대상)

### Context

사용자가 CAD 가져오기뿐 아니라 현장 카메라 차선에서 지도를 자동 생성하도록 요청했다.
D-488의 자동 지도 생성 범위 제외를 이 초안 생성 기능에 한해 넓힌다. 지도 저장·활성화와
최종 명령 소유는 그대로다. D-375의 기존 CAD 맞춤은 새 차선 생성 자체가 아니다.

### Decision

1. Vision의 `rosy-lane-map` 명령이 저장한 원본 영상 또는 신선한 직접 Vision 프레임을 읽는다.
   CAD 파일은 필요 없다. 입력은 같은 영상 크기의 확인된 `image_to_map` 보정과 측정 차로 폭이다.
   선택 `bounds_m`은 작업 영역을 제한한다. 보정·축척을 영상만 보고 추측하지 않는다.
2. 기존 흰 페인트 검출기를 재사용한다. 작은 반사·줄무늬를 제거하고 서로 마주 보는 경계 사이를
   세선화한다. 짧은 잡가지는 제거하고 관측된 짧은 교차 링크만 묶는다. 원형 차로는 세 장소로 나눈다.
   가린 부분을 연결하지 않는다. 0.05 m 이내의 별도 끝점이 모호하면 생성 자체를 거절한다.
   넓은 흰색 테두리도 경계로 관측하며 보정 JSON의 `white_value_min`은 80–255 정수(기본 180)다.
   출력 영역 밖도 차로 폭만큼 관측하므로 작업 영역 끝을 카메라 가림으로 취급하지 않는다.
   흰색 무늬만으로 도로 의미를 확정하지 않는다. 선택 `road_seed_m: [x, y]`는 관측된 도로 위
   기준점이며, 그 점이 속한 연결된 도로 영역만 추출한다. 가림을 건너 연결하지 않는다.
3. 출력은 D-488 `rosy.site_map/1` 초안 JSON과 별도 근거 JSON이다. 프레임 SHA256, 보정, 해상도,
   차로 폭과 생성기 버전을 남긴다. 기본 양방·`lane`·0.03 m/s는 검토용 기본값이다. 통행 방향,
   차로 의미, 장애물, 교차 연결은 운영자가 확인한다. 흰 선과 단일 차로 폭만 지원한다.
4. Fleet 현장 지도 화면에서 파일을 선택해 기존 `PUT /api/fleet/site-map/draft`로 가져온다.
   기존 서버의 크기·스키마·이름 있는 운영자·revision 검사를 그대로 쓴다. 기존 초안 교체는 확인한다.
   활성 지도는 별도 기존 활성화 조작 전까지 바뀌지 않는다. 새 API나 영상 중계는 만들지 않는다.
5. 직접 읽기는 HTTPS·기존 사이트 CA·환경 변수의 source-scoped preview lease를 쓴다.
   redirect, 3 s 초과/나이 불명, 보정된 미리보기는 거절한다. 토큰과 URL을 근거에 기록하지 않는다.
   기존 파일도 덮어쓰지 않는다. 무보정 영상은 초안을 만들 수 없다.
6. 모델 PC는 D-446의 `exec camera_lane_map.py`로 같은 생성기를 실행한다. 서명 묶음에는
   Vision의 `__init__.py`, `lane_map.py`, `map_register.py`만 추가한다. 작업 잠금·환경 지문·
   고정 source 영수증은 기존 실행기가 소유한다. 관제는 초안 저장·검토·활성화를 맡는다.
   모델 PC의 고정 controller는 후보 밖에서 별도로 갱신하며, 이전 후보 복귀를 유지한다.
   GPU 환경과 모델 승격은 바꾸지 않는다. 모델 PC 설치·실행 수용은 별도로 확인한다.

### Consequences

카메라의 관측으로 차선 중심선 지도를 생성하고 Fleet에서 검토할 수 있다. 카메라 이동·렌즈 변경 후
재보정이 필요하다. 반사, 노란 표시, 가림, 넓이가 다른 길, 도로 밖 흰 무늬는 첫 생성기의 한계다.
초안 검토는 필수이며 자동 활성화·자동 주행·Nav2 점유지도 생성은 없다. SOURCE/LOCAL 합성과
실제 영상의 추출 결과는 장치 배포, 현장 지도 정확도 수용 또는 G4/G5를 대신하지 않는다.

## D-372 브랜치·worktree 이름은 처음부터 내용대로 짓고, 공유 main 체크아웃의 남의 작업은 지우지 않고 보존만 한다

**Status:** Accepted (2026-09-30, 저장소 작업 규칙만). 기존 ADR의 의미·게이트·CI를 바꾸지 않는다. D-346 규칙 5(공유 트리에서는 짧은 커밋 창, 긴 작업은 `.worktrees/`)를 넓힌다.

### Context

한 저장소를 여러 세션이 같은 main 체크아웃에서 돈다(D-346). 2026-09-30 한 회차에서 다음이 일어났다.

- 머지할 브랜치가 main 체크아웃의 미커밋 파일 세 개(`docs/logs.md`, ADR Log, 대시보드 `index.html`)와 경로가 겹쳤다. 실행 중인 세션 여섯 곳에 물었고 모두 "내 것이 아니다"라고 답했다.
- 이 세션은 그 미커밋 작업 38파일을 임시 인덱스로 `wip/orphaned-main-checkout-20260930` 브랜치 한 커밋에 보존(해시 검증)한 뒤 main 체크아웃에서 그 경로를 되돌리고 머지했다.
- 이름이 내용을 말하지 않았고, 서로 다른 주제 다섯 개(D-362 ADR, Fleet `app.py` 라우터 분리, 센싱 캘리브레이션 추출, 대시보드 분할, ER2 조사 문서)가 한 커밋에 섞였다. 사용자가 이름과 폴더 구조를 처음부터 정확히 잡으라고 지적했다.
- 한 시간 뒤 같은 경로들이 다시 1~7분 전 수정 시각으로 나타났다. 주인은 살아 있었고 ListAgents에 보이지 않는 곳(다른 도구나 미등록 세션)에서 작업 중이었다. "아무도 소유를 주장하지 않음"은 "버려짐"이 아니었다. 되돌리기가 그 작업을 방해했다.

### Decision

1. **이름은 처음부터 내용대로.** 브랜치는 저장소 접두어(`feat/`, `fix/`, `refactor/`, `docs/`, `uiux/`)에 주제와, 있으면 ADR·계획 항목 번호를 붙인다. 예: `refactor/d362-p0-1-fleet-app-routes`, `docs/d362-file-size-budget`. 한 브랜치에는 한 주제만 둔다. 앞선 결정에 의존하는 브랜치는 그 ADR 브랜치 위에 쌓는다. `wip/`, `tmp/`, `orphaned-*`, 날짜만 있는 이름은 쓰지 않는다.
2. **worktree 폴더는 `.worktrees/<짧은-주제>`.** `git worktree add --relative-paths`로 만들고, main에 머지되고 깨끗해진 worktree는 지우고 브랜치는 `git branch -d`로 정리한다. Windows에서 Android 빌드 경로가 길어 남는 폴더는 `\\?\` 경로로 지운다.
3. **공유 main 체크아웃의 남의 미커밋 작업은 소유 주장이 없어도 지우지 않는다.** 보이는 세션이 모두 부정해도 주인은 다른 도구나 미등록 세션일 수 있다.
   - 먼저 파일 수정 시각을 본다. 가장 최근 수정이 24시간 이내면 살아 있는 작업으로 본다.
   - 보존은 작업 트리를 건드리지 않는 방법으로만 한다: 임시 `GIT_INDEX_FILE`로 `read-tree` → `add` → `write-tree` → `commit-tree` → 주제별 이름의 브랜치로 `update-ref`. Windows에서는 바이트 그대로 다루도록 subprocess를 바이너리로 쓴다(텍스트 모드는 LF를 CRLF로 바꾼다). 보존 후 모든 파일의 blob 해시를 작업 트리와 대조한다.
   - main 체크아웃에서 그 경로를 되돌리는 일은 사용자가 명시적으로 승인하고, 모든 경로의 마지막 수정이 24시간 넘게 지났을 때만 한다. 그 전에는 머지를 미루거나, 겹치지 않는 범위로 나눈다.
   - 되돌렸다면 보존 브랜치 이름과 복구 방법을 알려진 모든 세션에 즉시 알린다.
4. **보존한 남의 작업은 주인 확인 없이 머지하지 않는다.** 리뷰도 시험도 거치지 않은 작업이고, 주인이 같은 작업을 이어서 하고 있을 수 있다.

### Alternatives

- **`git stash push -u`로 옮기기** — 스택이 모든 worktree·세션과 공유되고, 작업 트리를 즉시 비워 살아 있는 주인을 방해한다. 임시 인덱스 방식은 작업 트리를 그대로 둔다.
- **주인 없는 작업을 main에 그대로 커밋** — 리뷰 안 된 미완성 코드가 main에 들어가고, 주인의 커밋과 충돌한다.
- **모든 병행 세션이 main 체크아웃을 쓰지 않도록 강제** — 짧은 문서 커밋의 효율을 잃고 도구 밖 세션에는 강제할 수 없다. D-346 규칙 5의 짧은 커밋 창을 유지한다.

### Consequences

- 이름만 보고 브랜치 내용을 알 수 있고, 머지 단위가 주제별로 작아진다.
- 공유 체크아웃의 머지는 겹치는 남의 파일이 있으면 늦어질 수 있다. 이 비용을 남의 작업 손실보다 낫다고 본다.
- 2026-09-30 보존 브랜치는 이름을 고쳐 주제별 다섯 개로 나눴다: `docs/d362-file-size-budget`, `refactor/d362-p0-1-fleet-app-routes`, `refactor/d362-p0-2-sensing-calibration-sequence`, `refactor/d362-p1-dashboard-split`, `docs/er2-gemini-api-limits`. 주인이 main에서 같은 작업을 이어가고 있어 머지하지 않고 백업으로 둔다.

### Validation

- 2026-09-30: 보존 38파일 blob 해시가 작업 트리와 전부 일치, 주제별 다섯 브랜치로 나눈 뒤 37파일 바이트 일치·로그 항목 5개 전부 배정 확인 후 원래 브랜치 삭제.
- 이 ADR은 작업 규칙이다. 자동 검사는 두지 않는다. 위반은 리뷰와 세션 기록에서 찾는다.

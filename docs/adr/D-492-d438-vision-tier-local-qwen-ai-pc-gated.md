## D-492 D-438 비전 모델 단계는 ai PC 의 로컬 Qwen3-VL 로 채우고, 재생 평가와 그림자를 거쳐 켠다

**Status:** Proposed (2026-10-07, 사용자 결정: 로컬 Qwen3-VL 기본, 실행 호스트 ai PC, 켜기 전 재생 평가·그림자 둘 다). D-438 §3 을 고친다. 문서만이다. 코드, 모델 설치, ai PC 사용(소유자 동의 전), Tailscale 정책 변경, 실기 활성화를 승인하지 않는다.

### Context

- **D-438(Accepted)이 막힘 판단의 자리를 이미 정했다.** Fleet 판단기가 규칙 → 비전 모델 → 사람 순으로 답하고, 판단기는 CORE 에 `stuck_resolver` 역할로 답한다. 비전 모델은 막힘마다 미리보기 한 장을 받아 `{decision, reason, confidence}` 를 낸다. 답은 `WAIT`·`BACK_AND_RETRY`·`RESUME`·`ABORT`·`ESCALATE` 이고 `MANUAL` 은 사람만 고른다. `lane_lost` 에서 `RESUME` 은 고를 수 없다. 기본 시간은 8 s, 최소 신뢰도는 0.7 이다. 공급자는 OpenRouter 이고 기본 꺼짐이다.
- **2단계는 아직 없다.** D-438 구현 메모(2026-10-03)대로 규칙(R1–R3)과 사람 단계만 구현됐고, 규칙이 못 풀면 `no_rule` 로 사람에게 간다.
- **D-438 은 모델을 켜기 전의 평가 관문을 두지 않는다.** 사이트 설정 하나로 켜진다. 이 모델의 막힘 판단 정확도는 측정된 적이 없다.
- **로컬 VLM 이 준비됐다.** 2026-10-06 모델 PC 에 Ollama 0.35.1 과 `qwen3-vl:8b-instruct` 를 설치했다. 320×240 프레임 한 장 판단에 1.5–3 s 걸렸다(3× 확대, 출력 상한 600 토큰). 모델 PC 의 차선·바닥 점 찍기에서는 선 점이 자주 틀렸고 바닥 점은 대체로 맞았다(D-465 추가 조항 2026-10-07). 막힘 판단 정확도는 아직 모른다.
- **업계의 자율 시스템도 같은 방식이다.** 빠른 층(드론 비행 컨트롤러의 자세 제어, 차량·로봇의 실시간 정책)이 구동하고, 느린 층(VLM)은 초 단위로 판단을 낸다. 느린 층이 조용하면 빠른 층의 기본 동작(failsafe)이 이어진다. Rosy 에서는 CORE 차선 추종·정지가 빠른 층이고, D-438 판단기가 느린 층이며, 느린 층이 없으면 D-407 동작이 이어진다(D-438 §7).
- **관제 PC 에는 쓸 만한 GPU 가 없다.** D-434 상 관제 PC 는 사이트 스택 전용이고, 모델 PC 는 학습·평가 전용이다. ai PC(Tailscale `ai`, `tag:modelpc`, RTX 5080 Laptop 16 GB, RAM 15 GB)는 팀이 쓰는 GPU 노트북이다. 2026-10-07 에 다른 사용자의 SAM 작업이 돌고 있었다.

### Decision

1. **D-438 §3 의 공급자를 고친다.** 2단계 비전 모델의 기본 공급자는 **사이트 로컬 VLM** 이다.
   - 시작 모델은 `qwen3-vl:8b-instruct`(Ollama)다. 평가와 운영은 모델 digest 와 프롬프트 id 를 고정해 쓴다. 바꾸면 V0 부터 다시 한다.
   - 프레임은 사이트 밖으로 나가지 않는다. D-438 §3 의 외부 전송 조건(운영자 동의, 제공자 고정, 보관 거부)은 OpenRouter 를 고를 때만 적용된다. OpenRouter 는 선택지로 남는다.
   - 입력·출력·답 제한·시간·신뢰도·예산·CORE 응답 처리·안전 불변식은 D-438 §3–§7 그대로다. 이 결정은 그것들을 넓히지 않는다.
2. **실행 호스트는 ai PC 다(소유자 동의 조건).**
   - ai PC 의 소유자가 GPU 시간과 상주 메모리를 허락한 뒤에만 쓴다. 허락 전에는 V0(모델 PC 오프라인)만 한다.
   - 모델은 상주시킨다(`keep_alive` 무기한). 첫 적재가 8 s 시간 예산보다 길기 때문이다. 상주 VRAM(약 6–7 GB)과 같은 GPU 의 다른 작업이 겹치면 판단이 늦어질 수 있으므로, V1 동안 지연 분포를 기록한다.
   - ai PC 는 모델 PC(OMEN, D-434)와 다른 기계다(Tailscale `ai`, 100.108.76.123). 둘 다 `tag:modelpc` 이므로 태그로 열면 모델 PC 도 열린다. 그래서 Tailscale 정책에 ai PC 한 대만 가리키는 `hosts` 이름을 두고, 판단기(관제 PC, `tag:site`)에서 그 이름의 Ollama 포트 하나로 가는 grant 를 더한다. 다른 출발지와 포트는 열지 않는다.
   - Ollama 는 ai PC 의 Tailscale 주소에만 묶는다. 0.0.0.0 이나 LAN 전체에 열지 않는다.
   - Fleet 판단기는 Ollama 연결 실패·시간 초과를 D-438 §3 대로 `ESCALATE` 로 본다. ai PC 가 꺼져 있어도 규칙 단계와 사람 단계는 그대로 돈다.
   - D-434 의 역할 표에 ai PC 를 「사이트 로컬 VLM 추론(D-438 2단계)」으로 더하는 것은 소유자 동의 뒤 D-434 추가 조항으로 한다.
3. **코드 자리는 D-438 판단기다.** 2단계는 `operations/fleet/fleet/server/stuck_resolver*` 의 판단 단계로 둔다. 공급자별 HTTP 클라이언트는 그 옆의 작은 adapter 로 두고, 공급자를 설정으로 고른다. 이 출력은 D-429 의 숙고형 「Mission·Task 후보」가 아니라 D-438 의 막힘 답이므로 `operations/decision` 으로 옮기지 않는다.
4. **판단 시점과 프레임을 기록한다.**
   - 판단기는 판단할 때 로봇 viewer API 에서 미리보기 한 장을 받는다(D-438 §3). 그 응답의 촬영 시각(`X-Rosy-Camera-Captured-At`, CORE 시계)을 막힘이 열린 CORE 시각과 비교한다. 촬영 시각이 없거나 막힘이 열리기 전이면 판단하지 않고 `ESCALATE` 로 본다. 카메라가 멈춘 채 막힌 경우(옛 장면)를 모델이 판단하지 않게 하기 위해서다. 미리보기 순서번호는 CORE 재시작 때 0 으로 돌아가고 비어 있을 수 있으며 주기가 일정하지 않으므로 시간 판정에 쓰지 않고 기록만 한다.
   - 모델의 `reason` 은 신뢰하지 않는 글이다. 200자로 자르고, 사람에게 올릴 때 「모델 근거」로 따로 표시한다. 장면 안의 글자(표지·라벨)가 모델 판단을 바꿀 수 있으므로, 판단 근거로 프롬프트 밖의 지시를 따르지 않는다고 프롬프트에 적고 V0 에 그런 프레임을 넣는다.
   - 콘솔이 그 프레임을 사람에게 보이는 것은 D-59 를 고치는 일이라 이 결정 밖이다. 사람 단계는 지금처럼 순서번호·여유값·모델 근거를 본다.
5. **켜기 전 관문: V0 재생 평가.**
   - **평가 세트:** 기록된 막힘 사건(D-407 §6 의 표시 구간, D-379 녹화)에서 막힘 순간 프레임과 사건 입력(원인·여유값·마지막 차선 관측)을 모은다. 정답은 사람이 D-438 의 답 집합(`ESCALATE` 포함)으로 붙인다. 모델 출력은 정답이 아니다(D-475 §7 의 원칙). 세트는 세션 단위로 나누고, 평가에 쓴 세션은 프롬프트 조정에 쓰지 않는다.
   - **최소 크기:** 원인별(`obstacle_ahead`, `lane_lost`)로 30개 이상, 정답에 나온 답마다 10개 이상. 모자라면 V0 판정을 하지 않는다.
   - **합격 시작값**(실행 전에 평가 담당자가 바꿀 수 있고, 바꾸면 이유와 함께 기록한다):
     - 위험 오답 상한: 정답이 `WAIT`·`ABORT`·`ESCALATE` 인데 모델이 `RESUME` 을 낸 비율 0, `BACK_AND_RETRY` 를 낸 비율 ≤ 5 %.
     - 모델이 `ESCALATE` 가 아닌 답을 낸 프레임 중 정답 일치율 ≥ 80 %.
     - 모델 답 중 `ESCALATE` 비율 ≤ 50 %(이보다 높으면 쓸모가 적다).
     - 지연 p95 ≤ 6 s. 정확도는 같은 모델 digest 로 어느 GPU 에서나 잴 수 있지만(모델 PC, D-434), 지연은 실행 호스트인 ai PC 에서 같은 세트로 잰다. ai PC 소유자 동의 전에는 지연 항목을 판정하지 않고 V1 로 넘어가지 않는다.
   - 결과는 모델 digest, 프롬프트 id, 세트 hash 와 함께 learning 평가 산출물로 남긴다.
   - 사람이 찍힌 프레임은 세트에 넣기 전에 사람이 확인하고, 필요 없으면 뺀다. 세트와 프레임은 git 에 넣지 않고 로컬 store 에 둔다.
6. **켜기 전 관문: V1 그림자.**
   - 판단기는 막힘마다 규칙 단계와 나란히 모델을 한 번 부르고 기다리지 않는다. 모델 답은 CORE 에 보내지 않는다. 실제 처리는 지금처럼 규칙 → 사람이다.
   - 그림자 답은 Fleet 판단기의 **별도 그림자 기록**(내부 DB 표)에 남긴다. `fleet_line_stuck_answers` 와 `board.answers()` 에는 넣지 않으므로 콘솔의 `GET /api/fleet/line-stuck` 응답은 바뀌지 않는다. 바뀌는 것은 내부 표 하나, 판단기 설정 항목(공급자, 주소, 모델 digest, 프롬프트 id, 그림자 켜기), Tailscale grant 하나다. 그림자 행에는 `accepted` 가 없다(보내지 않았으므로).
   - **비교 정답:** 사람이 그 막힘에 실제로 답했으면 그 답이다. 사람 답 없이 닫힌 막힘(규칙 답, 로컬 후진, `cleared`)은 V0 와 같은 방법으로 검토자가 녹화(D-379)에서 정답을 사후에 붙인다. 정답이 붙지 않은 막힘은 세지 않는다.
   - **V1 → 켜기 기준:** 정답이 있는 막힘이 2개 이상 세션에서 30건 이상. 위험 오답(정답 `WAIT`·`ABORT`·`MANUAL`·`ESCALATE` 인데 모델 `RESUME`) 0건, 일치율이 V0 합격값 이상, 지연 p95 ≤ 6 s, 시간 초과 ≤ 5 %.
   - 켜는 것은 사이트 설정이고, 단계마다 사용자 승인이 필요하다.
7. **기록.** 켠 뒤의 모델 답은 D-438 §8 의 감사에 더해 공급자(`local`·`openrouter`), 모델 digest, 프롬프트 id, 프레임 촬영 시각, 미리보기 순서번호, 지연을 남긴다. 이 열들은 감사 표의 null 가능 열로 더한다(D-438 구현 메모와 같은 방식). 그림자 기록도 같은 항목을 갖는다. Fleet 은 프레임 자체를 저장하지 않는다(D-438 §3).

### Alternatives

- **D-438 그대로(OpenRouter, 관문 없이 설정으로 켬).** 측정 없이 모델이 막힌 로봇에 답하게 된다. 프레임이 사이트 밖으로 나간다.
- **VLM 을 빠른 층에 넣는다(조향·속도).** 1.5–3 s 지연으로 차선 추종 주기를 맞출 수 없고, D-231 §4·D-442 와 어긋난다.
- **모델 PC 에서 실시간 추론.** D-434 의 학습 전용 역할과 GPU 동시 사용 제한에 걸린다. 사용자는 ai PC 를 골랐다.
- **관제 PC 에 GPU 를 산다.** 구조상 가장 맞지만 비용·시간이 든다. ai PC 를 쓸 수 없게 되면 다시 본다.
- **세계 모델 기반 계획(V-JEPA 2 류).** 행동 결과를 예측해 고르는 방식은 빠른 층 계획기 후보다. 이 결정의 막힘 판단보다 넓어 따로 조사한다.

### Consequences

- D-438 의 빈 2단계가 외부 전송 없이 채워질 길이 생긴다. 켜지기 전까지 로봇 동작은 바뀌지 않는다.
- 막힘마다 사람 답·모델 그림자 답·촬영 시각이 쌓인다. 평가 프레임은 Fleet 이 아니라 로봇 녹화(D-379)에서 그 시각으로 찾아 세트에 넣는다.
- 새로 필요한 것: ai PC 소유자 동의, Ollama 설치와 Tailscale 주소 바인딩, ai PC 한 대를 가리키는 Tailscale grant, 판단기 2단계·adapter·그림자 기록 표·설정, 감사 표 열, V0 평가 도구와 세트. 각각 별도 변경이다.

### Verification

- 이 ADR 은 문서다. `python tools/harness/rosy_harness.py lint` 통과는 구조 기록의 증거이며 모델 판단 품질의 증거가 아니다.
- 2단계 구현은 D-438 §3·§5·§7 의 호스트 시험(답 제한, 시간 초과 → `ESCALATE`, 예산, CORE 거부 처리)과 이 결정의 촬영 시각 거부(없음·막힘 전)·그림자 기록이 콘솔 답 목록에 섞이지 않음 시험을 갖춘다.
- 켜기는 V0 결과 파일과 V1 기록으로만 판정한다.

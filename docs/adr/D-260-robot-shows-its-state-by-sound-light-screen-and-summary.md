## D-260 로봇은 부팅음·LED·LCD·운용 화면 요약줄 네 곳에서 같은 상태를 같은 말로 보여준다

**Date:** 2026-09-26

**Status:** Proposed

**Context:** 2026-09-25~26 `rosy_18`을 켜고 다룬 사람은 로봇이 지금 어떤 상태인지 알 길이 거의
없었다.

1. **소리.** 부저는 BCM 22로 추정돼 꺼져 있었다(D-190). 사람이 소리를 듣고 이분 탐색해서 BCM 4로
   확정했다. 지금은 준비 완료에 한 번, 실패에 세 번 울리는 것이 전부다.
2. **빛.** WS2812 램프(8개, GPIO19)는 D-169에서 벤치 전용이었다. 드라이버 다섯 문제를 고친 뒤
   (`docs/solutions/runtime-errors/ws2812-lamp-dark-on-ubuntu-pi5-rp1-ws281x-2026-09-26.md`) 켜진다.
   그래도 어떤 상태도 표시하지 않는다.
3. **LCD.** 부팅 단계, 이름, IPv4, 로그인 코드, 배터리를 보여준다(D-190). 다만 준비가 끝난 뒤
   "움직일 수 있는가", "무엇이 문제인가"는 없다. ADC가 멈췄을 때도 배터리 칸이 `--`일 뿐, 해결 방법이
   없었다.
4. **대시보드.** operator로 로그인해도 왜 못 움직이는지 몰랐다(D-247 결정 7이 운용 뷰 문장으로
   고쳤다). 장치 요약, 배터리·온도, 할 일은 점검 뷰 깊숙이 있거나 아예 없다.

네 표면이 따로 말하면, 사람은 같은 로봇을 네 번 해석해야 한다.

**Decision:**

1. **상태의 원천은 하나다.** 부팅 단계(`boot-status.json`, D-174), 장치 관측(`hardware.json`,
   D-247), CORE의 운전 가능 판정(`motion_reason`, D-247 결정 7)을 합쳐 **로봇 상태** 하나를
   정한다. 상태 어휘는 다섯 개로 고정하고, 네 표면은 이 어휘만 쓴다.

   | 상태 | 뜻 | 우선순위 |
   |---|---|---|
   | `부팅 중` | CORE_READY 전 | — |
   | `실패` | 부팅 단계 FAILED | 1 (가장 높음) |
   | `주의` | 배터리 경고 이하, 또는 제품 장치(D-169)가 `응답 없음` | 2 |
   | `준비됨 — 못 움직임` | CORE_READY이지만 `motion_reason`이 비어 있지 않음 | 3 |
   | `준비됨` | CORE_READY이고 움직일 수 있음 | 4 |

   여러 조건이 겹치면 우선순위가 높은 것 하나만 표시한다. 나머지는 요약줄의 할 일 목록에 남는다.
2. **부팅음 (부저, BCM 4, 수동형).** 소리는 짧고 드물게 낸다. 상태가 바뀔 때만 울리고, 같은 상태에서
   반복하지 않는다.

   | 상태로 바뀔 때 | 소리 |
   |---|---|
   | `준비됨` / `준비됨 — 못 움직임` | 짧게 한 번 (현재와 같음) |
   | `실패` | 짧게 세 번 (현재와 같음) |
   | `주의` | 낮은음 두 번 |

   - 기본값은 켜짐이다. BCM 4는 사람이 2026-09-26에 확인했다(D-190 확인 절차 충족).
   - 카드에서 `ROSY_BUZZER_ENABLED=false`로 끌 수 있다.
3. **LED 램프 (8개).** 부팅 표시등으로만 제품에 들인다. D-169의 "벤치 전용"은 램프를 **조작하는**
   기능(`lamp_control`의 색 지정 서비스)에 대해서는 그대로 유지된다.

   | 상태 | 램프 |
   |---|---|
   | `부팅 중` | 파랑, 천천히 숨쉬기 (2 s 주기, 최대 밝기의 25 %) |
   | `준비됨` / `준비됨 — 못 움직임` | 초록 3초 뒤 끔 |
   | `실패` | 빨강 1 Hz 깜빡임, 해결될 때까지 |
   | `주의` | 주황 0.5 Hz 깜빡임, 해결될 때까지 |

   - 드라이버가 없거나 초기화에 실패하면 표시등은 조용히 빠진다(fail-open). 부팅을 막지 않는다.
   - 실패 사실은 D-247 장치 카드가 `드라이버 없음`으로 보인다.
   - 운용 중에 램프를 다른 용도로 쓰는 일은 이 ADR 범위 밖이다.
4. **LCD.** 기존 카드(D-190)에 두 줄을 더한다. 둘 다 결정 1의 어휘를 쓴다.
   - **상태 줄:** 예 `준비됨 — 못 움직임: CORE 전용 모드`.
   - **할 일 줄:** 가장 급한 할 일 하나. 예 `전원을 완전히 껐다 켜세요 (ADC)`, `카메라 케이블 확인`.
5. **운용 화면 상단 요약줄.** 운용 뷰 맨 위에 한 줄을 둔다. D-201 적합 계약을 지키고, 문서를
   스크롤시키지 않는다.
   - (a) 로봇 상태 칩(결정 1)과 운전 가능 여부 이유
   - (b) 장치 요약 `정상 12/14 · 카메라 응답 없음` (누르면 점검 뷰 장치 카드로)
   - (c) 배터리 %·V와 온도
   - (d) 할 일 개수 (누르면 목록)

   네트워크, 이번 부팅 이력, 세션 역할과 만료는 점검 뷰에 둔다.
6. **할 일 목록은 규칙에서 나온다.** 사람이 적는 목록이 아니다. D-247 장치 행과 부팅 단계에서
   정해진 규칙으로 만든다. 예:
   - ADC가 `응답 없음` → "전원을 완전히 껐다 켜세요"
   - 카메라가 `응답 없음` → "카메라 케이블 확인"
   - 부저·램프가 `사람 확인 필요` → "시험 동작으로 확인"
   - CORE 전용 모드 → "관리자가 모터 모드로 승격"

   같은 규칙표를 LCD와 요약줄이 함께 쓴다.
7. **어디서 계산하나.**
   - 로봇 쪽(부저·램프·LCD)은 root 쪽 `rosy-boot-display`가 파일만 읽어 계산한다. 그래서 CORE가
     죽어도 동작한다.
   - 대시보드 쪽은 CORE가 같은 규칙을 적용해 `GET /api/v1/host/status-summary`(viewer)로 낸다.
   - 규칙표는 파이썬 모듈 하나로 두고 두 곳이 같이 쓴다. 표 불일치를 막는 시험을 둔다.

**Alternatives:**

- **표면마다 따로 설계한다.** 지금 상태가 그렇다. 네 표면이 서로 다른 말을 한다.
- **램프를 운용 상태등(주행 중·경고)으로 바로 쓴다.** 모터·안전과 묶이므로 D-58/D-169 경계를 먼저
  다시 열어야 한다. 이 ADR은 부팅과 준비 상태까지만 다룬다.
- **"시작" 전용 화면을 둔다.** 로그인 직후 체크리스트 화면이다. 범위가 크고, 운용 화면과 답이 둘로
  갈린다(D-77과 같은 문제). 요약줄과 점검 뷰로 충분하다.

**Consequences:**

- **바뀌는 것.**
  - D-169: 램프가 부팅 표시등으로만 제품에 들어온다(부분 대체).
  - D-190: 부저 기본값이 켜짐, BCM 4가 된다.
  - D-247 결정 7의 문장은 요약줄의 (a)로 흡수된다.
- **이미지.** D-247 2차에서 넣는 램프 드라이버(모듈, 오버레이, `pwm_channel=3`, udev)가 전제다.
  `rosy-boot-display`에 램프 권한(`/dev/ws281x_pwm`)을 더한다.
- **시험.**
  - 규칙표 단위 시험
  - 부저·램프 패턴 시험(가짜 출력)
  - LCD 렌더 시험
  - 요약줄 브라우저 시험(D-201 적합)
  - 실기 확인: 사람이 소리와 빛을 확인한다

**Validation / Transition:**
- **2026-09-26 발견 (결정 2 전제).** D-247 부저 시험 동작(`rosy-hw-test`)은 `rosy-boot-display`가 부저 선을 쥐고 있으면(`ROSY_BUZZER_ENABLED=true`) 충돌 방지로 `busy`를 내고 울리지 않는다. 부저 기본값을 켜기 전에 시험 요청을 부팅 화면 프로그램이 대신 울리도록 넘기거나, 시험 동안 부팅 화면 프로그램이 선을 놓게 해야 한다. 그 전까지는 부저 시험 때 부팅 부저를 잠시 끈다.

- **1차.** 규칙표와 로봇 상태 계산, `status-summary` API, 운용 화면 요약줄.
- **2차.** `rosy-boot-display`의 램프 패턴·부저 패턴·LCD 두 줄.
- **DEVICE.** `rosy_18`에서 사람이 확인한다: 부팅 중 파랑, 준비 완료 초록 3초와 한 번 울림, ADC를
  멈춘 상태에서 주황과 LCD 할 일 줄.

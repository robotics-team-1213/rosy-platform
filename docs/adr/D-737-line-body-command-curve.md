## D-737 일반 카메라 차선추종의 검사 곡률과 최종 명령을 일치시킨다

**Status:** Accepted (2026-10-13, SOURCE 계약). 구현·원격 회귀·Gazebo 완주·실물 수용은 별도 증거다.

## 배경

Leg10 원본 지도 실행은 36.6cm 뒤 `obstacle_ahead`로 멈췄다. 실제 HOLD 관측과 신선한 LiDAR 스캔을 기존 CORE 계산으로 재생하면 의도한 호의 몸 여유는 25.3mm, 정지 거리는 21.4mm다. 선속도만 줄이는 기존 호 집합은 9.4mm를 선택하여 실제 HOLD 값과 일치한다. 이 값은 재개 거리 51.4mm보다 작으므로 재개나 완주의 증거는 아니다. 이전 SDK raw scan 거절도 별도로 남는다.

D-735의 교통 감속과 최종 LINE 안전 제한은 두 축을 같은 비율로 줄인다. 그러나 그 앞의 정적 LINE clip과 몸 검사의 clip은 독립 축 제한이고, 몸 검사는 여전히 선속도만 줄이는 호 집합을 검사한다. 일반 추종의 검사와 발행 기하를 같은 계약으로 맞춘다.

## 결정

1. `CommandManager.clip_line_candidate`는 기존 공통 `limit_velocity`의 곡률 보존 경로를 사용한다. 유한 값 검증, zero, 정적 cap, 최종 명령 권한과 epoch 검사는 유지한다. 일반 NAVIGATION·MANUAL·DOCKING의 독립 축 제한은 바꾸지 않는다.
2. CORE가 곡률 보존 발행 경로를 명시적으로 연결한 경우에만, 신선하고 출처가 맞는 일반 CAMERA 관측의 몸 검사를 같은 비율의 정적 제한으로 계산한다. cue·IR 조향 보정·arc·bridge·return·recovery·junction 후보와 외부 일반 clearance 호출은 기존 검사다. 기본 연결은 기존 의미를 유지한다.
3. 이 좁은 범위에서만 선속도만 줄이는 추가 호 집합을 생략한다. 검사 뒤 최종 nonzero 후보가 다른 기하나 다른 소유 경로로 바뀌면 기존 호 집합으로 재검사하거나 기존 정지 경로로 내린다. 모드 이름만으로 이 범위를 인정하지 않는다.
4. 실제 의도 호 충돌, LiDAR·근접 기억·초음파 융합, 센서 신선도, 몸 윤곽, 정지 거리와 재개 hysteresis, SDK raw 거절을 유지한다. 잡음·거리·시간 기준, 외부 모드·API·설정 옵션을 추가하거나 완화하지 않는다.
5. D-735 결정 4의 정적 LINE 독립 clip과 결정 5의 무조건적인 legacy 호 집합 유지만 위 범위로 대체한다. D-422와 D-735의 나머지 계약 및 기본·비소유 경로의 호 집합은 유지한다.
6. CORE 명시 연결의 일반 추종 이외 경로에서는 기존 독립 clip·legacy 호 집합에 실제 공통 정적 clip의 호도 추가하여 최소 여유를 선택한다. 같은 cap snapshot과 기존 정지·재개 기준을 쓰고 현재 LiDAR·기억·초음파 및 역방향 쓸기에 적용한다. generic 호출도 더 보수적으로 거절될 수 있지만 기존 허가를 넓히지 않는다. 명시 연결 없는 기본 동작은 그대로다. 추가 호의 속도 zero는 새로운 pivot 권한이 아니다.

## 검증

먼저 정적 LINE cap에 따른 곡률 변형의 실패를 원격에서 재현한다. 후속 몸 검사 회귀는 실제 Leg10 입력, 실제 의도 호 충돌, 비소유 호출, 관측·모드 epoch, cap 변경, 명령 교체, stale·기억·초음파와 raw SDK 거절을 포함한다. 독립 안전 검토와 원격 회귀 뒤 새 전체 빌드·사전 검증·제한된 원본 지도 주행을 수행한다. 성공 판정은 원본 지도 완주와 반복 실행 증거로 한다.

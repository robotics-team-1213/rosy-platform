## D-314 지면 G4는 실측으로 간소화하고 수동 운전의 반복 확인을 없앤다

**Status:** Accepted (2026-09-28, 소스 결정). 장치 배포와 실물 G4/G5는 미검증.

**Context:** D-312는 바퀴 들기를 필수 조건에서 제거했지만, G4 승인에는 여전히
방향·정지 원인 조합 8회, 두 작업자, 별도 검토자가 필요했다. 대시보드도
인증·MANUAL·실시간 상태를 확인한 뒤 다시 현장 조건 체크박스를 눌러야 했다.
이 반복 확인은 정지 기능을 추가하지 않으면서 현장 진행을 지연시켰다.

**Decision:**

1. 대시보드의 반복 확인 체크박스를 두 화면에서 제거한다. 조작 권한, 유효한
   실행 모드와 capability, MANUAL, 비상정지 해제, 최신 pose/velocity, 버튼을
   누르는 동안에만 명령 전송, 포커스·연결 상실 시 0 명령과 서버의 500 ms
   watchdog을 그대로 사용한다. 화면 요청은 선속도 0.03 m/s, 각속도
   0.10 rad/s, 한 번에 최대 2초다.
2. G4 번들 schema v2는 한 명의 기록 작업자와 모터 사전 점검, 5개의 원시
   odom 시험을 요구한다. 전진·후진·좌회전·우회전의 버튼 해제 정지 4개와
   전진 명령 소실 정지 1개다. 각 시험의 속도·방향·누적 이동 10 cm·정지
   지연 0.65초·지속 0 속도·SHA-256을 도구가 검증한다. 중복·누락 시험은
   승인하지 않는다. 별도 안전 담당자와 검토자 필드는 v2에 없다.
3. 승인 도구는 검증한 번들과 원시 파일을 봉인하고 작업자·릴리스·해시가
   일치하는 기록을 만든다. `rosy-navigation.service`는 기동할 때마다 다시
   검증한다. 기존 schema v1의 8회 시험과 독립 검토 기록은 계속 읽는다.
4. 실제 이동 전의 구역 정리와 물리 정지 접근성은 현장 운용에 남긴다.
   소프트웨어의 사실 검증 필드나 반복 체크박스로 가장하지 않는다.

**Alternatives:** 단순히 승인 마커를 만들거나 내비게이션 가드를 없애는 방식은
시험 증거 없이 하드웨어 모드를 열기 때문에 채택하지 않았다. 8회 시험을
그대로 두고 체크박스만 제거하는 방식은 주요 병목을 해결하지 못한다.

**Verification:** schema v1/v2 계약 시험, 버튼 해제·명령 소실 누락과
원시 해시·작업자 변조 거부, 두 대시보드의 버튼 해제 0 명령과 그룹 전환
정지, JS 구문 검사. 장치 전원이 꺼져 있으므로 이번 변경의 실물 정지 지연,
SLAM/Nav2, 지도 결과는 아직 확인하지 못했다.

**Rollout / Recovery:** 새 이미지 소속 승인 도구와 대시보드를 같은 서명
릴리스로 설치하고 장치에서 소스·파일 해시를 읽어야 한다. 릴리스 019에는
이 변경이 없다. 실패하면 이전 서명 릴리스로 돌아가고, 승인 기록을
인위적으로 만들지 않는다.

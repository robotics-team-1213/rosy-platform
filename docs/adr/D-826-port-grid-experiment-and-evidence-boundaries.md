## D-826 3×3×3 혼합 화물 야드는 실행 기준선·입출고 계획·장애 복구를 분리해 실험한다

**Status:** Proposed (2026-10-21). 실험 목적·비교·증거 경계의 제안이다. 구현 완료, 실제 Isaac 실행, 새 API·capability, 장치 동작·DEVICE/FIELD 수용을 뜻하지 않는다.

## Context

사용자는 OMX-F가 공급 구역의 서로 다른 크기 화물을 가져와 3×3 바닥·3층 야드에 적층하는 Isaac 실험을 요청했다. 고정 배치만 실행하면 실행 가능성과 실패 원인을 확인할 수 있지만, 적재 전략의 우수성이나 항만 반출 효율·양팔 필요성은 확인할 수 없다. 공간·화물·정보·버퍼를 같게 하고 시스템의 배치·회수·복구 결정을 비교해야 한다.

현재 main의 mixed recipe/3 planner는 연속 좌표의 혼합 적재·지지·하중·접근·팔 배정을 제공한다. 고정 27칸 격자, 반출·재배치, 온라인 도착과 Isaac 물리 조작 연결은 없다. Isaac OMX import와 기존 계산/보조 부착 증거를 종단 물리 파지 성공으로 표현해서는 안 된다.

## Proposed decision

1. 실험의 질문을 **물리 실행 가능성**, **점유율과 반출 재취급의 관계**, **한 팔 대비 양팔/Leader의 복구 가능 상태 확대**로 나눈다. 고정 배치는 첫 질문의 기준선에만 사용한다.
2. 논리 공간은 칸막이 없는 3×3×3, 화물은 높이 1칸의 1×1·2×1·3×1 직육면체, 허용 yaw는 0/90°다. pitch·gap·height·질량·그리퍼·환경·source pose를 fixture revision으로 고정한다. 논리 27칸 점유와 물리 체적 충전율을 구분한다.
3. 출고 구역과 단층 외부 재배치 버퍼(0/3/9칸)를 명시한다. 야드 안 합법적 빈칸 재배치도 허용하고 원장·재취급 회계에 포함한다. 공급 트레이·기타 야드 밖을 숨은 버퍼로 쓰지 않는다. 버퍼 형상/접근 가능성과 부족을 판정하며 탐색 실패를 불가능 증명으로 간주하지 않는다. 부하 단계는 SKU 조성도 달라지므로 단계 사이 차이를 점유율만의 인과 효과로 발표하지 않는다.
4. E0는 정해진 배치의 단일 OMX 물리 실행, E1은 동일 조건의 first-fit/격자 혼합 greedy/반출 고려 방식 비교다. 적재 전략 비교에서는 반출 실행기를 공통으로 유지한다. E2 온라인과 E3 장애·양팔/Leader는 후속 상세 계획 및 기존 선행 계약을 충족한 뒤 연다.
5. 오프라인에는 모든 정보를 동일하게 공개하고, 온라인에는 같은 제한 입고 큐/현재 요청만 공개한다. 개발 seed와 봉인 평가를 분리하며 입력·계산/시도 예산·정책·verifier를 실행 전에 고정한다. 효과가 없거나 악화된 결과도 보존한다.
6. 접촉 기반 물리 파지·실제 안착·인접 화물 변화를 독립 관측으로 확인한다. `LOGICAL_ONLY`, `SIM_AID`, `PHYSICS_GRASP` 증거를 구분한다. 명령 성공·관절 도달·부착 aid·Pinky 주행을 OMX 적층 성공으로 대체하지 않는다.
7. 첫 착수 범위는 환경/자산 확인→한 물체 연결 smoke→크기별·1층·3층 실행 기준선이다. 현재 없는 장면·controller·파지·판정 연결을 후속 구현한다. 반출·온라인·양팔을 동시에 구현해 첫 물리 실패 원인을 섞지 않는다.
8. 상세 조건·표본·성공 판정·중단/확대 관문은 [실험 계획](../plans/2026-10-21-port-grid-experiment-design.md)을 따른다. 새 실험은 모두 NOT RUN이다. 실제 로봇·Pinky 이동·배포는 범위 밖이다.

## Alternatives

| 대안 | 판단 |
|---|---|
| 미리 정한 18개 적층 영상으로 계획기 효과 선언 | 실행 기준선으로만 사용. 전략 비교의 근거로 불충분 |
| 기존 mixed planner를 변경 없이 격자/반출 실행기로 간주 | 연속 좌표·오프라인·palletize 의미와 충돌하므로 채택하지 않음 |
| 논리 계획·물리 replay·장애 복구를 분리하고 같은 입력으로 비교 | 채택할 제안. 재사용 범위와 추가 개발·실패 원인이 명확함 |
| 처음부터 온라인·양팔·Leader·Pinky 전체 연계 | 별도 계약/기능 공백이 많아 첫 실행 기준선 이후로 미룸 |

## Consequences

실행 성공·계획 우위·협응 필요성을 각기 다른 증거로 설명할 수 있다. 대신 공통 입력·버퍼 회계·독립 verifier·전체 실패 기록이 필요하며, 논리 계획 성공만으로 물리 성공을 선언할 수 없다. 작은 active grid에서 양팔이 직렬화되거나 한 팔+받침이 충분한 결과도 유효하다.

## Validation

ADR 본문·색인·계획 링크와 기존 계약의 충돌을 문서 검사·독립 검토한다. 시뮬레이션은 계획의 G0 이후 별도 run/revision·환경·trace·영상·hash에 결속한다. 이 ADR의 Proposed 등록이나 문서 검사 통과는 실험 완료 증거가 아니다.

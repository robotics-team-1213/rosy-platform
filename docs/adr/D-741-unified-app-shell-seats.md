# D-741 모든 앱이 같은 자리를 쓰는 통합 셸

**Status:** Accepted (2026-10-13, 사용자 요청: 여러 앱을 한 틀로 묶고 계획대로 모두 고친다. 구현은 조각마다 따로 착지하며 CI·화면 검증·설치·실물 수용은 별도다)

### Context

Rosy Fleet, Rosy Robot, Rosy Pilot, 학습 검수, 경기 보드, Rosy Cam은 같은 일을 서로 다른 자리에서 한다.

- 화면 이동이 Fleet은 왼쪽 아이콘 레일, Robot은 머리 안 알약, 학습 검수는 머리 안 탭이다.
- 화면 안 이동이 Fleet 안에서만 세 가지다(작업 선택 레일, 가로 앵커 줄, 옆 칸 탭).
- 머리가 두 줄로 접히는 폭이 Fleet은 48rem(D-658), Robot·Pilot은 64rem(D-466)이다.
- 공용 `ui-shell`은 `grammar` 이름표만 갖고 탐색·오른쪽 칸 자리가 없어 표면마다 배치를 새로 짠다.
- 사건 기록, AI 상황 사실, 원인 분류, 검토 저장이 Fleet 관제의 오른쪽 칸 탭 하나에 눌려 있다.

사용자는 2026-10-13에 여러 앱을 한 틀로 묶고, 작업 종류가 늘어도 버티는 위계와, AI 판단·기록·원인·조치가 들어갈 자리를 요청했다. 규칙은 하려는 일을 위해 있어야 한다는 것도 같이 요청했다.

### Decision

**1. 배치는 여섯 가지 일을 위해 있다.** 화면에서 아래 정한 것이 그 일에 방해가 되면 화면을 따르고 `shared/web/surfaces.yaml`에 이유를 적는다.

| 하려는 일 | 그래서 정한 것 |
|---|---|
| 급할 때 바로 멈춘다 | 그 화면의 정지는 어느 앱에서나 앱 바 오른쪽 끝에 있다 |
| 지금 무슨 일인지 한눈에 본다 | 본문이 가장 크고 틀은 얇다. 정상은 조용하다 |
| 일을 쉽게 시킨다 | 로봇에게 시키는 일은 `작업` 한 영역에 모은다 |
| 왜 그랬는지 남기고 다음에 쓴다 | 기록은 가운데, 우리의 판단과 조치는 오른쪽에 적는다 |
| 어디 있는지 잃지 않는다 | 같은 종류의 것은 어느 앱에서나 같은 자리에 있다 |
| 늘어나도 버틴다 | 대상은 위에서, 기능은 왼쪽에서 고른다 |

**2. 단계마다 자리는 하나다.**

| 단계 | 자리 | 넓은 폭 치수 | Fleet 예 |
|---|---|---|---|
| 1 앱과 대상 | 앱 바 왼쪽 | 높이 64px | R 심볼, Fleet, 현장 이름 |
| 2 영역 | 탐색 레일. 아이콘 아래에 이름 | 폭 72px | 관제, 작업, 기록, 지도, 설치 |
| 3 화면 | 하위 탐색 | 폭 232px | 작업: 전체 작업, 승인 대기, 끝난 작업, 새 작업 |
| 4 본문 | 가운데 | 남는 폭 | 현장 지도, 작업 목록, 사건의 흐름 |
| 5 고른 것 | 오른쪽 칸. 위는 지금 상태, 아래는 입력·조작·근거 | 폭 360px | 현재 개입, 작업 한 건, 원인과 조치 |

- 본문 위 경로 줄(56px)이 `영역 / 화면`을 말한다. 더 깊은 단계는 칸을 늘리지 않고 경로 줄과 본문 머리의 탭으로 표현한다.
- 고른 것이 없는 화면(로봇 등록, 로그인)은 오른쪽 칸을 빼고 결과를 폼 아래에 둔다.
- Fleet `/console`의 지도와 오른쪽 칸은 D-629의 2:1을 유지한다.
- 치수는 `shared/web/tokens.css`의 토큰이다. 자리의 배치는 새 공용 시트 `shared/web/app-shell.css`가 갖고, 표면 시트는 자리 안의 내용만 배치한다.

**3. 앱 바.** 왼쪽은 맥락, 오른쪽은 연결·알림·나·정지 순서다.

| 정보 | 평소 | 달라질 때 |
|---|---|---|
| 앱 | D-654 R 심볼과 앱 이름 한 단어. 누르면 다른 앱으로 간다 | — |
| 대상 | 이름만 | 고를 것이 둘 이상이면 선택 단추 |
| 연결 | `실시간`과 로컬 시각 | 지연은 주의색. 끊기면 앱 바 아래 띠와 지도 위 글 |
| 알림 | 종 아이콘 | 읽지 않은 수. D-632 알림 창은 오른쪽 칸 위에 덮인다 |
| 나 | 역할 이름이 붙은 계정 단추 | 로그인 전 `로그인`(D-683), 개발 연결 표지(D-473) |
| 정지 | 위험 채움 | 명령하지 않는 화면에는 없다 |

- 로봇 연결 수는 앱 바가 아니라 관제 화면 줄의 내용이다.
- 화면 표시(테마), 접속 토큰, 진단, 버전은 계정 단추 아래 메뉴에 둔다.
- 아래 줄(푸터)은 두지 않는다. 시계는 앱 바로, 값의 신선도는 값 옆으로 간다.

**4. 정지 자리의 이름은 그 명령이 하는 일을 말한다.**

| 화면 | 이름 | 명령 |
|---|---|---|
| Fleet | 비상 정지 | `POST /api/fleet/estop`, 현장 전체, 래치(D-421). 대상을 좁혀 보고 있어도 현장 전체다 |
| Robot, Pilot 웹 | 비상 정지 | CORE `safety/stop`, 그 로봇 |
| 경기 보드 | 두 로봇 정지 | 호스트 `/stop`. 스페이스 키 유지(D-224) |
| Pilot Android 2대 조종 | 두 로봇 정지 | 0 속도와 `IDLE`. 비상 정지가 아니므로 이름과 채움을 바꾸지 않는다 |

**5. 접히는 폭은 둘이고 칸 질의로 정한다.** 공용 시트는 `@media`가 아니라 `@container`를 쓴다(D-359 §6.3). 셸 폭 64rem 아래에서 레일과 하위 탐색이 각각 가로 한 줄이 된다. 48rem 아래에서 본문이 한 줄로 쌓이고 지금 상태가 본문보다 먼저 온다. 앱 바는 한 줄을 유지한다. 48rem은 `web-common`의 `container_breakpoints`에 이유와 함께 올린다.

**6. 화면 이동과 화면 안 이동.**

- 화면이 둘 이상인 앱의 화면 이동은 탐색 레일이다. Robot의 `운용·작업 준비·설치·정비`와 학습 검수의 네 화면이 머리에서 레일로 간다. 현재 위치 표식은 D-277 장미색을 유지한다.
- 서로 독립된 작업을 하나씩 하는 영역은 작업 목록을 하위 탐색 자리에 둔다. D-439 `createTaskChooser()`가 그 자리의 구현이다. 현장 지도와 Cell의 가로 앵커 줄은 없앤다.
- 같은 대상을 다르게 보는 것은 본문 머리나 오른쪽 칸의 탭이다.

**7. 작업 영역.** Fleet의 로봇에게 시키는 일은 `작업` 영역 하나다.

- 하위 탐색은 `전체 작업`, `승인 대기`, `끝난 작업`, `새 작업`이다. 앞의 셋은 지금의 `GET /api/fleet/work` 결과를 화면에서 상태로 거른 것이다. API는 바꾸지 않는다.
- `/console/cell`의 주소와 문서는 그대로 둔다(API reference에 실린 주소다). 레일에서는 `작업`이 현재 위치가 되고 하위 탐색의 `새 작업` 아래에 놓인다.
- 승인 화면은 서버가 이미 지키는 규칙을 그대로 보여 준다: 이름 있는 운영자만 승인하고, Cell 작업은 제안한 사람이 승인할 수 없다(`mission_routes.py`). 막힌 단추에 그 이유를 적는다.
- 새 작업 종류(예: 물체 가져오기)의 API·필드·실행 owner는 SRS와 별도 ADR이 정한다. 이 결정은 그 종류가 들어갈 자리만 정한다.

**8. 기록 영역.** Fleet 레일에 `기록`을 둔다.

- 하위 탐색은 사건(검토할 사건, 열린 사건, 닫힌 사건), AI 판단(AI 상황 사실), 관제 기록이다.
- 사건 한 건은 가운데에 일어난 일을 시간 순서로 둔다: 감지, AI 판단, Fleet 검증, 사람 결정, 실행, 결과. 이 줄기는 고칠 수 없다.
- 오른쪽 칸에 우리의 판단을 적는다: 원인, 확실한 정도, 판단 근거, 조치. 지금의 사건 검토 저장과 JSON 내보내기를 그대로 쓴다.
- AI가 낸 것에는 늘 제안, 본 것, Fleet 검증 결과를 같이 적는다. 승인한 사람과 결과는 다른 줄에 적는다.
- 관제의 현재 개입 카드에는 요약만 두고 전체는 `기록`으로 넘긴다.

**9. 상태 표현은 공용이다.** 값의 신선도 네 가지(D-398), 명령의 보냄·접수·완료·거절, 권한 없음, 빈 목록, 불러오는 중과 실패, 되돌릴 수 없는 일의 확인(D-371)을 화면마다 따로 그리지 않는다. 점선은 "할 수 없음"과 "정보 없음"에만 쓴다.

**10. 조작의 테두리.** 단추와 입력 필드의 테두리는 새 역할 `--control-line`(잉크 40%)을 쓴다. `--border-default`(잉크 14%)는 면을 가르는 선으로 남긴다. 어둡게 테마에서 조작 경계의 대비가 3:1을 넘는다. 밝게 테마에서는 잉크 40%가 2.4:1이라, 조작에 적용하는 조각에서 밝게 값을 따로 정한다.

### 이 결정이 바꾸는 기존 결정

아래 항은 그 화면을 고치는 조각이 착지할 때 바뀐다. 그 전까지 해당 표면은 기존 결정대로 동작한다.

| 기존 | 바뀌는 항 |
|---|---|
| D-658 | 2항의 "시각·진단은 푸터", 3항의 접속·테마 펼침 영역, 7항의 계정 위치 |
| D-668 | 1항의 머리 줄 테마 단추, 2항의 수·읽지 않음·개발 표지를 한 단추에 모으는 것, 7항의 전화 폭 두 줄 |
| D-683 | 2항의 "계정 메뉴는 테마와 토큰을 갖지 않는다" |
| D-466 | 화면 전환을 머리 cluster에 두는 것. 2항의 64rem 두 줄 머리 |
| D-359 | 2026-10-04 부기의 "머리 접힘은 64rem, 새 예외 없음". 공용 셸은 칸 질의 48rem을 쓴다 |
| D-641 | 1항의 다섯 영역 가운데 푸터. 4항의 전역 탐색 아이콘 단독(아이콘 아래에 이름을 적는다) |
| D-201 | 경기 보드 정지의 아래 붙박이 줄. 앱 바 오른쪽 끝으로 간다 |
| D-540 | Cell을 전역 문서 탭으로 두는 탐색 구성 |

D-277, D-220, D-371, D-421, D-629, D-632, D-439, D-473은 그대로 따른다.

### 이 결정이 하지 않는 것

- Pilot Android의 자기 줄을 없애지 않는다. 그 줄의 `로봇 목록`, `두 번째 로봇`, `기기·연결`은 액티비티 메서드를 부르고, 2대 조종에는 웹 화면이 없다. 웹과 네이티브 사이 통로를 정한 뒤 다시 본다.
- 경기 보드에 앱 이름을 주지 않는다. D-377의 이름 결정이다.
- 밝게 테마의 `--status-warn`을 바꾸지 않는다. 주의 글자가 놓이는 면을 바탕색으로 맞춘다.
- Robot 입구(`/dashboard`)의 로그인 전 비활성 비상 정지는 그대로 둔다. 로그인하면 같은 자리에서 살아나므로 자리가 움직이지 않는다.

### Consequences

- 공용 시트 하나와 토큰 몇 개가 늘고, 표면 시트의 머리·탐색 배치 규칙이 줄어든다.
- 머리·탐색·푸터 마크업을 고정한 시험이 단계마다 같이 바뀐다. 목록은 계획 문서에 있다.
- 브라우저 시험은 원격 시험 PC에서 돌지 않으므로 CI가 증거다.
- `DESIGN.md`는 공용 시트가 들어가는 커밋에서 고친다.
- 지금 근거는 설계 캔버스의 소스 검토 두 차례와 코드 조사다. 브라우저 렌더 확인, G1·G2·G3, 구현, 설치, 실물 수용은 없다.

### 2026-10-13 부기: 10항의 값

10항의 "잉크 40%, 밝게 값을 따로 정한다"는 구현에서 "잉크 50%, 두 테마 같은 값"이 됐다. 파생 토큰은 테마마다 따로 정할 수 없다(D-359 §1). 잉크 50%는 다섯 바탕 위에서 어둡게 4.20–4.76:1, 밝게 3.11–3.31:1이다.

이 비율은 계산한 값이고 화면에서 잰 값이 아니다. 눌린 조각의 바탕(`--ground-card-2`)은 밝게에서 3.00:1로 여유가 없고, 영상 위와 반투명 면 위의 조작은 확인하지 않았다. Rosy Cam의 외곽선은 잉크 14%로 남아 있다.

> 2026-10-13 부기(Fleet 앱 바 조각의 검토 반영): "이 결정이 바꾸는 기존 결정"에 두 가지를 더한다. D-632 1항 — 셸 폭 30rem 아래에서 로그인 전에는 공통 머리의 알림 단추를 숨긴다(로그인하면 같은 자리에 다시 선다). D-658 6항 — 좁은 화면 상태 그룹의 두 줄 높이는 한 줄 앱 바로 바뀐다. D-632의 나머지 항은 그대로 따른다. 48rem 아래에서 `연결 대기`·`지연`·`연결 끊김` 글은 잘리지 않게 앱 바 아래 자기 줄에 서고, 30rem 아래에서 계정 단추의 역할 이름은 접근 이름에만 남는다.

> 2026-10-14 부기(Cam 앱 바 조각의 검토 반영): Android 벡터 `operations/site_ui/cam/app/src/main/res/drawable/ic_rosy_mark.xml`은 SVG를 쓸 수 없는 네이티브 앱을 위한 `shared/web/brand/mark.svg`의 허용된 옮김이다(D-654 2항의 예외). `LauncherIconParityTest`가 경로와 뷰포트를 정본과 대조한다. 색은 D-654 3항대로 `--brand-rose`다. 이 밖의 복사본은 만들지 않는다.

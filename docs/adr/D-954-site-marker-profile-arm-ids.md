## D-954 현장 마커 번호는 프로필 한 장에 배정하고, 팔 마커는 50번부터 쓴다 (D-933 8항 대체)

**Status:** Accepted (2026-11-01, 사용자 결정 "현장에 맞는 프로필로, 서로 겹치지 않게"). 배정표·검사·팔 번호 이동은 이 변경으로 들어갔다. 천장 팔 마커(3항)의 Vision·Fleet 소비, 인쇄·부착, 실물 수용은 별도다.

### Context

ArUco 번호를 쓰는 곳이 여럿이고 각자 정했다.

- 천장 Vision: `DICT_4X4_50`. 로봇 40~49(D-562), 도크 7, 경기장 모서리 30~33, 장소 마커 34~38(D-564).
- 공급암 셀: `DICT_4X4_100`. ChArUco 0~34, 팔 슬롯 n은 `35 + 15 (n - 1)`부터 15개(D-933 8항).

`DICT_4X4_100`의 0~49번은 `DICT_4X4_50`과 같은 그림이다. 그래서 팔 슬롯 1(35~49)은 장소 마커 35~38, 로봇 40~49와 같은 그림을 쓴다.

- 팔 위 카메라는 셀에 들어온 Pinky의 천장 스티커(현장 40·41번)를 본다. 이 스티커가 슬롯 1의 면 마커(38~41)로 읽히면 면 자세가 틀어진다.
- 슬롯 1의 핑키 트레이 면 마커(46~49)는 천장 카메라가 로봇 46~49로 읽을 수 있다.

2026-11-01 현장 확인 결과는 다음과 같다. 관제 PC에는 `cameras.top` 보정 기록이 없다(`cell_frame learn` 미실행). 그래서 번호를 옮겨도 학습된 보정은 깨지지 않는다. `site-cameras.yaml`에는 `identity` 블록이 없어 D-596 자동 LED 확인이 기본값(켜짐)으로 돈다. 정합은 `field_boundary`이고 코너 마커는 없다.

### Decision

1. **배정표 한 장**: 현장 프로필 `rosy.marker-profile.v1` JSON이 소유자별 번호 범위를 적는다.
   - 예시: `deploy/site/marker-profile.json.example`. 현장 사본: `/etc/rosy/site/marker-profile.json`.
   - 검사: `deploy/site/marker_profile.py check PROFILE [--site-cameras YAML]`.
   - 같은 계열(`4X4` 등) 안에서 번호가 겹치면 거절한다. 사전 크기가 달라도 같은 계열의 같은 번호는 같은 그림이기 때문이다.
   - `use: calibration`(보정할 때만 드는 판, 지금은 ChArUco)과의 겹침은 경고로만 낸다.
   - `site-cameras.yaml`의 `corner_marker_ids`·`place_markers`·`robot_markers`가 각 소유자의 범위 밖 번호를 쓰면 거절한다.
   - `arms`는 팔 슬롯과 실제 팔 이름(S, A, B)을 짝짓는다. 슬롯 블록이 없는 팔은 거절한다.
2. **팔 슬롯은 50번부터 쓴다**: 슬롯 n(1~3)은 `50 + 15 (n - 1)`부터 15개다(그리퍼 1, 받침대 2, 면 3×4). 이 15개 구성은 D-933과 같다.
   - 50~94번은 회전을 포함해 `DICT_4X4_50`의 모든 번호와 최소 3비트 다르다. 천장 Vision은 4×4 사전에서 비트를 고치지 않으므로 팔 마커를 로봇이나 장소로 읽지 않는다. 이 성질은 시험으로 고정했다.
   - 슬롯은 3개다(지금 팔 3대). 4번째 팔을 넣으려면 새 ADR로 면 수를 줄이거나 더 큰 사전으로 옮긴다.
   - 정본은 `cell_print_sheets.arm_ids`이고, `cell_frame.slot_ids`와 Cell 화면 번호 목록이 같은 표를 따른다. 시험이 이 둘을 예시 프로필과 맞춰 본다.
3. **천장용 팔 마커 20~22**(`arm_ceiling`, `DICT_4X4_50`, 슬롯 1~3 순서): 팔 받침대 옆에 천장 카메라가 읽을 크기로 하나씩 붙여, 팔을 Fleet 지도에 올리는 데 쓴다. 이 변경은 번호만 예약한다. Vision 검출, Fleet 표시, 크기 결정(천장 해상도 실측), 팔 셀 좌표와 지도 좌표의 연결은 후속이다.
4. **겹침 검사의 정본은 이 프로필 하나다.** 코드의 번호 상수(Vision `ROBOT_MARKER_IDS`, 팔 슬롯 표)는 시험이 예시 프로필과 맞는지 확인한다. 새 마커 소유자는 프로필에 먼저 행을 더한다.

### 관계

| ADR | 관계 |
|---|---|
| D-562, D-564 | 천장 번호(로봇·도크·모서리·장소)는 그대로이고, 프로필에 행으로 옮겨 적는다. |
| D-933 | 8항(35부터의 번호표)을 이 ADR 2항이 대체한다. 나머지(카메라 모델, 마커 묶음, 인쇄물)는 그대로다. |
| D-596 | LED 신원 확인은 바꾸지 않는다. 3항의 천장 팔 마커가 팔의 같은 역할을 하는 첫 단계다. |

### Consequences

- 현장마다 프로필 사본 하나로 "몇 번이 누구 것인가"를 확인하고, 설치 전에 겹침을 거절한다.
- 이미 35~49번으로 인쇄했다면 버리고 새로 인쇄한다. Cell 화면 「보정 인쇄물」은 이제 50번부터 낸다.
- 사람이 할 일: 팔 마커 다시 인쇄·부착, 천장 팔 마커 크기 실측 뒤 부착, 현장 프로필 사본의 `arms` 대응 확인.
- 남은 위험: 천장 해상도로 20~22번 마커가 읽히는지는 실측하지 않았다. 프로필 검사는 `site_preflight`에 아직 들어가지 않았다.

## D-617 앞쪽 조기 회전 여유와 출구 기억 재검증

Status: Accepted (2026-10-10, 사용자 요청; DEVICE와 FIELD 검증 별도)

### 근거

동시 CAMERA_LINE 600초 녹화에서 9dfk는 `exit_behind_line: true` 뒤 `exit_from_memory: true`와 `drivable_pivot_left`를 함께 보고했다. 차선 너머 출구를 거부한 뒤 같은 방향을 기억으로 복원하는 순서 오류다. 측면 벽도 새 출구만 거부하고 기억·회전 latch는 거부하지 않았다. 기존 앞 벽 거리 0.08m 차감과 pivot 0.14m 기준은 약 0.22m 앞 물체부터 카메라가 보는 길을 닫힌 것으로 만들었다. CORE의 실제 속도 기반 정지 여유와 별개다.

### 결정

1. LiDAR만으로 카메라 전방 길이를 닫는 조건은 기존 RobotBody의 앞끝 + 0.02m 이내다. 기준 원점은 base_link이며 2cm는 몸 바깥 여유다. 더 먼 물체는 debug에 남기되 CORE의 기존 속도 기반 제동·몸 윤곽 정지에 맡긴다. 카메라 자체의 닫힌 길과 곡선 판단은 유지한다.
2. 측면 벽으로 거부된 기억·방향 latch를 지운다. 관측한 차선 경계를 넘는 출구를 거부하면 같은 출구의 `seen_exit`, 기억과 회전 latch도 지워 다시 선택되지 않게 한다.
3. CORE 단일 최종 명령, E-Stop, hold lease, IR, 후진 근거·시도 횟수, 센서 freshness는 유지한다. 횡단보도는 연속 5초 비움과 최소 40 scan을 확인해야 통과한다. 시간 초과만으로 통과시키지 않는다.
4. 5초 `no_motion` 감지는 이미 설치되어 있다. 8kcn `local_disabled`, 9dfk `crosswalk_unknown` 등 실제 복구 거부 근거를 제거 없이 기록한다. 비제로 회전·제자리 방향 왕복은 기존 5초 zero-command 감지와 다르며 D-607 과제다.
5. 속도 2배 요청은 0.04→0.08m/s다. 8kcn의 명령/odom 회전 방향 불일치와 추론 지연을 먼저 확인하고 적용 증거를 별도로 기록한다. 이 ADR의 조향 변경 자체는 cruise나 제동 한도를 올리지 않는다.

### 검증

원격 시험 PC에서 가까운/먼 앞 벽, 기억한 출구의 새 측면 벽, 관측 경계 너머 출구 재등장, 정상 곡선·횡단보도·회전 각도 예산을 검증한다. 두 장치의 signed release와 실제 keeper debug로 DEVICE/FIELD를 별도로 확인한다. 아래쪽이라는 영상 위치만으로 로봇 ID나 원인을 확정하지 않는다.

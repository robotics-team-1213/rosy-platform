## D-659 도로면·현재 도로 구역의 인지 적합성과 주행 수용을 분리한다

**Status:** Accepted (2026-10-11, 사용자 합의와 ADR 기록 요청). 수용 범위는 의미 분리, 독립 인지 평가와 후속 주행 단계의 경계 및 구현 전 선행 조건이다. 모델 출력/라벨 마이그레이션 구현, 평가 정답 검수, 모델 적합성 승인, 배포·주행 활성화·실물 수용은 별도다.

### Context

사용자는 도로·물체·세그멘테이션 학습 결과를 시뮬레이션과 실물에서 검증하는 구조를 논의한 뒤, 인지 적합성을 먼저 확인하고 주행은 후속 단계로 처리하기로 합의했다. 도로 전체와 로봇이 현재 속한 도로 구역을 구분해야 문제를 구현 전에 해결할 수 있다는 취지로 ADR 기록을 요청했다.

기존 계약에서도 의미 차이가 드러난다. D-475 §8의 사람 평가 정답은 보이는 도로 바닥 전체이며 D-576의 조향용 direct는 로봇이 있는 도로 구역이다. D-379의 궤적 띠는 실제 지나간 폭이라 도로 전체 정답과 같지 않다. 이 셋을 같은 `drivable` 점수로 비교하면 모델 오류와 정답 정의의 차이를 구분하지 못한다. D-475는 Proposed이며 그 문서의 존재만으로 실제 검수나 구현 완료를 주장할 수 없다.

자동 라벨러를 최종 평가의 유일한 정답으로 쓰거나 같은 세션의 인접 프레임을 학습과 시험으로 나누면 오류와 데이터 누설이 점수를 부풀릴 수 있다. 시뮬레이터의 정답 위치·물체 ID를 주행 모델 입력으로 쓰면 실물에서도 같은 인지를 할 수 있는지 증명하지 못한다. 불확실한 영역을 과도하게 제외해도 평균 점수만 높아질 수 있다.

### Decision

#### 1. 인지 의미 세 가지의 책임을 구분한다

아래 이름은 의미 계약이며 새 API 필드·모델 role·클래스 ID를 등록하는 결정이 아니다.

| 개념 | 의미 | 책임/범위 |
|---|---|---|
| 도로면 | 영상에 보이는 도로 바닥 전체. 목적지와 선택한 진행 방향에 따라 바꾸지 않는다 | 이번 인지 평가 |
| 현재 도로 구역 | 로봇이 현재 속한 차선 또는 도로 구획의 가시 영역. 도로면 전체와 별도로 판정한다 | 이번 인지 평가; 경계·로봇 위치와 필요 시 검증된 지도 근거 |
| 따라갈 경로 | 목적지와 통행 규칙에 따라 선택한 진행 경로 | 후속 경로·주행 판단 |

갈림길의 양쪽 가지는 모두 도로다. 경계로 구획되지 않은 연결부에서는 현재 도로 구역이 두 가지와 연결될 수 있다. 목적지로 한 가지를 골라 인지 정답을 만들지 않는다. 근거로 현재 구역을 확정할 수 없으면 불확실로 남긴다. 선택하지 않은 구역도 도로라는 의미는 유지한다.

도로 바닥, 도로 밖 바닥, 차선·정지선·횡단보도 칠, 물체 및 가림/불확실은 검수 기준에서 구분한다. 물체에 가려진 바닥을 확정 정답으로 복원하지 않는다. 물체의 존재, 도로의 의미 및 지금 진입해도 되는지는 별개다. 신호·공유 구간·통행 허용은 후속 판단이 맡는다.

#### 2. 기존 `drivable`의 의미를 조용히 바꾸지 않는다

기존 데이터셋, 모델, 평가 정답과 소비자는 각자의 의미·버전을 보존한다. D-576의 현재 조향 계약과 D-475의 전체 도로 평가 정답을 이 ADR로 같은 출력이라고 재해석하지 않는다. 기존 운용 경로의 연결도 변경하지 않는다.

라벨/출력 구현 전에 클래스·role·구역 표현, 검수 기준, manifest/preprocess, 모델 출력, 학습 빌더, intake·재생 평가와 각 소비자의 대응표를 확정해야 한다. 새 표현과 구형 모델의 혼용·변환 가능 여부, 거절 조건 및 원래 버전으로의 복귀를 상세 계약에 적고 시험한다. 외부 API/프로토콜 변경이 필요하면 기존 SRS/API reference 및 스키마 절차를 따른다.

현재 도로 구역은 기존 인지 결과·경계·위치에서 산출하는 기준선부터 평가할 수 있다. 모델이 직접 구역을 예측하는 방식은 같은 독립 정답과 입력 조건에서 비교한다. 두 모델, 다중 head 또는 새 서비스를 미리 강제하지 않는다.

#### 3. 학습·개발 검증·최종 시험과 정답의 계보를 고정한다

실물은 원본 세션/capture group 단위로, 시뮬레이션은 원본 장면 구성과 생성 조건 단위로 분리한다. MCAP·변환 영상·추출 프레임과 동일 장면의 단순 변환본은 같은 출처로 취급한다. 평가 대상은 검수 전에 예약해 학습 입력에서 제외한다.

학습용 자동 라벨은 출처와 오차를 기록한다. 최종 실물 평가 정답은 독립적으로 검수하며 평가할 모델의 예측을 그대로 정답으로 채택하지 않는다. 원본 해시, 프레임 정체성·촬영 시각, 카메라 보정, 지도·라벨 의미·split·검수 버전을 추적한다. 기존 평가 세트 수정은 새 버전과 이유로 기록하고 같은 평가 버전의 후보끼리 비교한다.

최종 시험 실패를 보고 모델·학습 데이터·설정을 고치면 그 시험은 개발 근거가 된다. 이후 최종 수용에는 새로 보류한 시험 장면이 필요하다. 실패에 맞춰 합격 임계값이나 정답을 변경해 통과시키지 않는다.

#### 4. 시뮬레이션과 실물은 인지 증거로 따로 판정한다

이번 시뮬레이션은 영상과 독립 정답 및 조건별 인지 시험을 제공한다. 기존 Isaac/Gazebo 경로를 활용하며 필요한 카메라/정답 지원부터 확인한다. 세 시뮬레이터 동시 구축이나 MuJoCo 추가는 요구하지 않는다.

같은 의미 정의·전처리·고정 모델·지표로 시뮬레이션과 실물을 평가한다. 정답용 위치·물체 ID가 실물에서 얻을 수 없는 모델 입력으로 유입되지 않도록 분리한다. 지도·위치를 사용하는 구역 추정은 실물에서도 가능한 입력과 그 보정·오차·나이·유효 조건을 명시하고, 이를 만족하지 못하면 구역 판정을 보류한다.

`260919 MAP FILE.STL` 기반 `map_v2_fleet` 출처를 유지하고 곡률 등을 바꾼 학습용 맵은 별도 버전으로 표시한다. 합성 영상 점수와 실물 점수는 출처별·조건별로 보고한다. 시뮬레이션의 높은 점수가 실물 실패를 상쇄하지 않는다. 시뮬레이션 완주·강화학습 보상·모델 설치는 인지 정확도의 증거를 대신하지 않는다.

#### 5. 불확실과 평가 불능을 통과로 처리하지 않는다

도로면의 IoU·도로 밖 오인·도로 누락·경계 오차와 현재 구역의 IoU·다른 구역 포함·자기 구역 제외를 별도로 평가한다. 물체는 확정한 클래스의 정밀도·재현율 및 작은/가려진 물체 조건을 평가한다. 거리 출력이 있다면 거리 오차를 추가하며 픽셀 오차를 미터로 바꿀 때는 검증된 보정을 쓴다.

전체 평균과 조건별 결과, 지표 분모, 유효 정답 수, 불확실/제외/보류 비율과 사유를 함께 기록한다. 전부 보류하거나 어려운 영역을 제외한 모델이 합격하지 않도록 최소 유효 판정 범위와 장면 수를 정한다. 장치에서는 고정 모델·전처리의 readback, 촬영부터 결과까지 지연 분포와 프레임 손실을 확인한다.

출처·해시·시각 정렬 불일치, split 중복, 정답 없음, 라벨 의미 불명, 필요한 보정/위치 무효는 평가 불능/HOLD다. 유효한 평가에서 기준 미달은 후보 실패다. 의미별 기준 모델을 측정한 뒤 클래스별 임계값, 적용 환경·장면·표본 범위와 지연 조건을 최종 시험 전에 고정한다. 수치나 증거가 미정이면 인지 승인은 HOLD다.

#### 6. 인지 승인과 주행 승인은 별도 관문이다

순서는 수집·정답 준비 → 학습 → 고정 후보 → 독립 시뮬레이션/실물 인지 평가 → 장치 관측 전용 추론 → 적용 환경을 명시한 인지 승인이다. 기존 사람 운전 기록은 이동 장면 평가에 사용할 수 있다. 새 실물 주행, E-Stop 해제나 운영 소비자 활성화는 이 ADR의 문서화 작업에 포함하지 않는다.

인지 승인에는 모델·전처리·입력 보정·의미/정답 버전·평가 증거·적용 환경과 한계를 묶는다. 후속 주행 단계는 이 결과를 소비하며 경로 선택, 통행 규칙, 조향·속도, CORE/Fleet 검사와 실제 이동 결과를 별도로 평가한다. CORE의 최종 `/cmd_vel`과 Fleet의 미션·공유 구간 권한은 유지한다.

### 구현 전에 닫아야 할 문제

| 문제 | 닫힘 증거 | 미해결 시 |
|---|---|---|
| 도로 전체/현재 구역/궤적 띠의 혼용 | 라벨·manifest·모델·검수·평가·소비자 의미 대응표, 버전 전환·구형 호환/거절 시험 | 출력·라벨 전환 HOLD |
| 교차로·가림에서 임의 구역 확정 | 목적지 없이 검수 가능한 구역 기준, 근거 부족 시 불확실 및 검수 일치성 확인 | 해당 구역 확정 HOLD |
| 학습·시험 중복과 자동 정답 편향 | 출처/예약/split 검증, 독립 검수 정답과 보류 시험 기록 | 인지 승인 HOLD |
| 시뮬레이터 정답 입력 누설과 실물 차이 | 입력과 평가 정답 분리, 보정/위치 유효성, 출처별 조건별 평가 | 인지 승인 HOLD |
| 평균 점수·불확실 제외로 실패 은폐 | 지표 분모·최소 유효 범위·표본·임계값 사전 고정, 조건별 실패 보고 | 인지 승인 HOLD |
| 장치 지연·전처리/버전 불일치 | 장치 관측 전용 readback·지연·프레임 손실 결과 | 장치 인지 승인 HOLD |
| 인지 통과를 주행 활성화로 해석 | 승인 전달물과 후속 주행 관문을 분리한 소비 계약 | 주행 활성화 HOLD |

이는 선행 조건의 계약이며 실제 문제가 이미 해결됐다는 판정이 아니다. 진행 상태는 이행 기록에 의미/전환 계약, 정답, 평가, 장치 추론 및 인지 승인별로 남긴다.

### Alternatives and consequences

하나의 `drivable`로 도로면·현재 구역·선택 경로를 모두 나타내면 출력은 작지만 정답과 소비자의 의미가 충돌한다. 영상부터 행동까지 직접 학습하면 행동 목적과 인지 오류를 이번 단계에서 분리하기 어렵다. 의미별 인지 평가를 먼저 고정하고 기존 출력에서 구역 산출 기준선을 비교하는 방식을 채택한다.

독립 정답과 별도 평가 비용이 생기지만 모델 오류, 정답 정의 오류, 보정 문제와 제어 문제를 나눌 수 있다. 새 데이터 의미를 도입할 때는 기존 모델·데이터의 버전 보존과 소비자 전환 검증이 필요하다.

### 기존 ADR과 이행

| 근거 | 관계 |
|---|---|
| D-475 (Proposed)/D-576 (Accepted) | 전체 도로 정답과 조향용 현재 구역의 기존 의미를 보존하고 이번 인지 분리를 명시. D-475 전체의 구현/수용을 소급 주장하지 않음 |
| D-379/D-356 | 출처·고정 평가·세션 분리 및 모델 전달과 주행 선택 경계 재사용 |
| D-427/D-637 | 기존 curation/training/evaluation/registry 소유 경로 재사용; 새 최상위 폴더나 서비스 없음 |
| D-638 | 경로 추종 학습과 완주 진단의 증거를 인지 정확도로 재해석하지 않음 |
| D-656 | 인지 증거, 후속 판단/작업 실행, 독립 평가와 최종 writer의 책임 분리 유지 |

세부 구조와 후속 작업은 [인지 적합성 설계](../plans/2026-10-11-perception-fitness-design.md)를 따른다. 이행 영향 범위는 `learning/curation/perception`의 라벨·검수·빌더, `learning/training/perception`의 학습/출력, `learning/registry/perception`의 manifest/intake/전달, `learning/evaluation/perception`의 재생·지표와 `middleware/perception/vision/perception/learned`의 로더·현재 소비자 및 관련 시험이다. 실제 표현을 바꾸기 전에 모든 생산자·소비자·fixture·설정의 범위를 확인한다.

### Verification

ADR 본문과 Log 행의 ID·제목·Status 일치, 기존 설계와의 링크, 의미 분리 및 선행 조건을 문서 검사로 확인한다. 문서 generate/lint와 커밋 HEAD의 원격 계약 시험은 문서 정합성 증거다. 독립 정답 검수, 실제 인지 평가, 장치 추론과 후속 주행 수용은 각각 별도의 실행 결과가 있어야 통과로 기록한다.

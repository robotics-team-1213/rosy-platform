## D-439 웹 앱은 공용 디자인과 작업 중심 정보 위계로 순차 개선한다

**Status:** Accepted (2026-10-03, 사용자 지시 — 전체 웹 앱을 목표로 기록하고 화면별 개선·검증·커밋·로컬 병합). 개선 원칙과 실행 범위의 승인이다. 모든 화면 수정 완료나 장치·FIELD 수용을 뜻하지 않는다.

### Context

Pilot은 D-432에서 실제 태블릿의 발견·연결·영상과 웹/네이티브 공용 디자인을 정리했다.
사용자는 남은 웹 앱도 직접 살펴보고, 이유 없는 UI 나열·레이아웃·일관성 문제를 목표로
관리하며 하나씩 개선하도록 요청했다. 기존 기능과 권한은 화면 배치만으로 바뀌지 않는다.

첫 로컬 브라우저 점검에서 작업 준비는 모바일 2788px, 설치·정비는 3317px의 페이지로
이어졌다. 가로 넘침이 없다는 사실만으로 다음 작업을 찾기 쉽다고 판정할 수 없다.
여러 독립 작업을 같은 무게로 펼치는 구조는 작업 선택과 현재 진행을 구별하기 어렵다.
이 수치는 로컬 대역의 초기 관측이며 사람 평가나 실제 설치 환경의 판정은 아니다.

### Decision

1. 표면 registry와 실제 라우트·패널을 함께 목록화한다. 로봇 로그인/운용/작업 준비/
   설치·정비, Fleet 관제/기기 설치, 게임 보드, 공용 부품을 제품 경로로 점검한다.
   PARKED 진단·시뮬 뷰어도 구조와 화면을 살피되 기능을 활성화하지 않는다.
2. 화면은 사용자 목적, 현재 근거, 다음 행동, 완료·오류, 복귀의 순서로 읽힌다.
   독립 작업을 선택할 수 있게 하고 세부 설정과 원시 readback은 필요할 때 연다.
   운용의 지도·영상·정지처럼 함께 봐야 하는 정보는 동시에 유지한다.
3. 색·글자·여백·터치 크기·버튼·비활성 사유·초점·동작 아이콘은 D-359와 D-432의
   공용 토큰/컴포넌트가 소유한다. 표면은 자기 작업의 배치와 실제 기능을 소유한다.
   단순히 모든 화면을 같은 격자로 만들기 위해 각 표면의 문법을 없애지 않는다.
4. 새로운 공용 역할은 반복되는 실제 필요를 확인한 뒤 추가한다. 제목, 안내, 상태,
   입력, 동작의 반복 구조를 공용화하며 제품과 무관한 장식이나 기능을 넣지 않는다.
5. 웹 권한, 서버 거절, 정지의 즉시성, 기존 `beforeHide`/unmount, polling scope,
   신선도 판정, CORE 최종 writer는 유지한다. 화면을 닫거나 전환하면 입력 소유권을
   반환하고 이전 화면의 늦은 응답이 새 화면을 덮지 않아야 한다.
6. 각 화면은 수정 전 관측·수정 이유·접속/빈 화면/오류·키보드·반응형 검증을 기록한다.
   코드 검사와 브라우저 대역, 실제 앱/장치, 사람 G3·현장 수용은 서로 구별한다.
7. `impeccable` Operate·distill과 `frontend-ui-engineering`으로 기존 제품 철학을
   적용한다. 구현 계획에 따라 한 묶음씩 수정하고 독립된 요구사항/품질 검토를 거쳐
   커밋한다. 마지막 최신 main 통합·검증 뒤 로컬 main에 병합한다.
8. 기본 `/dashboard`는 인증과 허용된 역할 목적지를 우선한다. 기존 종합 운용은
   명시적 `#compatibility`에서 유지한다. 이 선택은 `view=compatibility` query로
   정규화하여 기존 본문 건너뛰기 anchor와 새로고침이 운용 화면을 유지하게 한다.
   홈 `/dashboard`로 이동하면 기본 진입으로 돌아간다. 기본 진입에는 운용 socket·영상·polling을
   켜지 않는다. 비상 정지는 첫 화면에 두되 인증 전에는 로그인 사유와 함께 비활성이다.
   whoami 확인 후 기존 viewer 이상 정지 권한을 그대로 사용하며, 누른 경우에만 즉시
   정지 요청과 상태 확인을 한다. CORE 응답과 실제 물리 정지를 구별한다.
   인증 helper의 선택적 AbortSignal은 기본 진입의 코드 로그인·로그아웃 대기 시간을
   제한한다. 자격의 저장·만료·회수와 프로토콜은 기존 client가 소유하며, 취소된 늦은
   페어링 응답은 자격을 저장하지 않는다. 기존 운용 호출자는 기본 인자로 동작을 유지한다.
9. 교통 정책은 서버 판정, 수정 중인 입력, 저장된 검토본, 적용 요청 결과를 구별한다.
   입력을 바꾸면 다시 검토본을 저장해야 적용할 수 있다. 요청 중에는 polling이 입력과
   잠금을 덮지 않고, 완료·실패 결과는 다음 작업 전까지 남는다. 정보 없는 거리는 0으로
   바꾸지 않는다. 모드 값은 실제 API의 `DISABLED`/`MONITOR_ONLY`/`ENFORCED`를 사용하며
   알려진 값은 한국어로 읽고 미지의 원시 값은 숨기지 않는다. 정지 확인과 권한은 서버가
   계속 판정한다.

### Consequences

현재 역할 메뉴의 장미색 위치 표식은 D-277과 DESIGN의 허용 범위를 유지한다.
새 작업 선택은 기존 중립 segment 표현을 사용한다. 역할 위치와 작업 선택은 서로 다른
정보이므로 같은 강조색을 강제하지 않는다. 정지 색과 공용 팔레트 게이트는 유지한다.

작업 선택과 진행의 위치가 분명해지고, 반복 UI를 한 곳에서 고칠 수 있다. 공용 변경은
여러 소비 표면의 상태·키보드·정지 접근을 함께 검증해야 한다. 모든 기능을 없애거나
원시 정보를 은폐하여 단순하게 보이게 만드는 변경은 허용하지 않는다.

실행 순서와 화면별 판정은 [계획](../plans/2026-10-03-web-app-design-unification.md)과
[검증 기록](../validation/web-app-design-2026-10-03/README.md)에 남긴다.

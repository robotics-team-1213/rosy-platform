## D-454 중앙 Fleet 착수 — 시드 위 성장과 PRT-004 활성화 순서

**Status:** Accepted (2026-10-04, 사용자 지시 "착수해"). 이 ADR은 착수 사실과 성장 경로·단계 순서를 정한다. 어떤 구현 완료도 같이 주장하지 않는다. D-445가 "착수 여부를 별도 ADR로 올린다"고 예약한 자리다. D-445의 착수 전제 3개 중 관측된 것은 ③(서명 사이트 후보, 2026-10-04 5건)이고 ①(fleet ROS-SIM·ARTIFACT·DEVICE GO)과 ②(dashboard·pilot ARTIFACT GO)는 아직 열려 있다 — 사용자 결정으로 전제 완료를 기다리지 않고 시드 위 성장 경로로 지금 착수하며, ①②는 사다리(D-444·D-445)를 따라 병행된다.

## 배경

- 중앙 Fleet 카탈로그(API Ref §10.1–10.5 — robots/pairing, 명령 추적, 미션/대형, 지도/백업, 사건/감사)는 "중앙 Fleet 서버가 착수할 때 구현된다"로만 존재해 왔다.
- 사이트 시드(`operations/fleet`)는 이미 페어링(D-341)·등록(D-361)·작업·미션 원장(D-12·D-330)·사건·감사·발견을 가지고 있고, D-437 파이프라인(빌드→출처 증명→자동 서명)이 매일 후보를 만들고 있다.
- PRT-004 명령 상관/ACK는 "중앙 Fleet 착수까지 유보"(D-170, 설계는 D-177, 활성화 계약은 D-297)였다 — 착수가 이 유보를 연다.
- 2026-10-04 현재 번호 D-448–D-453은 여섯 갈래 작업이 썼다(모델PC 갱신 보호, 학습 아티팩트, 셀·발견, 차선 만남 판정, peer 조립). 이 ADR은 D-454다.

## 결정

1. **성장 경로 — 시드 위에 자란다.** 중앙 Fleet은 새 저장소·새 서비스 트리가 아니라 `operations/fleet` 의 같은 코드베이스에 단계적으로 구현되고, 배포 단위가 다를 뿐이다(사이트 프로파일 :8090, 중앙 프로파일의 포트·구성은 1단계 설계에서 확정). FLEET SRS의 DASH·CTR·MSN·OBS 요구는 이 코드베이스가 흡수한다(D-429·D-435 — 원장 소유는 Fleet 하나).
2. **단계 순서.** (1) §10.1 robots/pairing 중앙 레지스트리 뷰 → (2) §10.2 명령 추적과 **PRT-004 상관/ACK 활성화(D-170·D-297 유보 해제)** → (3) §10.3 미션/대형 REST → (4) §10.4 지도·웨이포인트·백업 → (5) §10.5 사건·감사 집계. 각 단계는 설계·실행 문서 쌍(design + plan)을 먼저 남긴다(저장소 관행).
3. **게이트 관계.** 이 착수는 DEVICE/FIELD 승격을 주장하지 않는다. (2)단계는 실명령 경로를 다루므로 착공 전 fleet ROS-SIM(D-426) 통과가 선행 조건이다. 사다리의 P1.2(기기 GET 200)·P2(페달 측정)·P3(사이트 DEVICE)는 이 착수와 무관하게 병행한다.
4. **범위 밖.** 자연어 Console(D-290), ER2 정책 디스패치 밸브(D-268) 변경, 로봇 쪽 계약의 단독 변경(필요하면 D-18 API 주기로), 중앙-사이트 이중 원장(원장은 하나다).

## 결과

- "중앙 Fleet은 미구현"이라는 문장(API Ref §10 서문)이 단계적으로 실현으로 바뀐다. 각 단계 완료 시 API Ref 해당 절의 상태 표기를 갱신한다(D-18: 문서와 schema 함께).
- PRT-004 유보가 해제된다 — 명령 상관·ACK의 로봇 쪽 활성화는 (2)단계 설계가 소유한다.
- 시드와 중앙이 같은 코드이므로 사이트 기능 개선이 중앙에 즉시 흐른다.

## 검증

- 이 ADR: ADR Log 행 + harness lint.
- (1)단계: 설계 문서 쌍 + fleet 시험(ROS 없음) + API Ref §10.1 상태 갱신이 한 변경에.
- (2)단계: D-426 ROS-SIM 통과 기록 + PRT-004 스키마/시험(D-18) + CORE 게이트 회귀.

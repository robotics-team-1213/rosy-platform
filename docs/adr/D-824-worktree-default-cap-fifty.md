## D-824 워크트리 기본 상한을 50개로 낮추고 기존 작업과 명시적 예외를 보존한다

**Status:** Accepted (2026-10-20, 사용자 지정 기본 상한). 기존 워크트리 삭제·착지·푸시 또는 다른 운영 결정을 승인하지 않는다.

## Context

새 Proposed ADR 작업을 만들 때 기존 상한 60개에 도달했고 손실 없이 정리할 수 있는 워크트리가 없었다. 사용자는 그 작업에 대한 상한 예외를 승인하면서 기본 상한을 50개로 낮추라고 지정했다. 현재 개수를 강제로 50개까지 줄이라는 요청은 아니다.

## Decision

1. `tools/worktrees.py`의 공유 기본값 `CAP`을 50으로 둔다. `.worktrees/` 아래 계산 대상이 49개이면 하나를 더 만들 수 있고, 50개 이상이면 일반 `new`를 거절한다. orphan 포함 여부와 점으로 시작하는 항목·일반 파일 제외 등 기존 계산 규칙은 유지한다.
2. 상한을 낮추어도 기존 작업공간·브랜치·캐시·미커밋 내용을 삭제하거나 변경하지 않는다. 현재 개수가 50보다 많으면 일반 생성이 계속 거절될 수 있다.
3. 명시적 `--force-over-cap "<reason>"` 예외와 이유·owner 감사 기록을 유지한다. 이번 Leader ADR 작업에 대한 사용자 승인은 다른 작업의 상시 예외 허가가 아니다. 기본 상한을 바꾸는 것도 정리 권한을 확대하지 않는다.
4. 현재 사용하는 `AGENTS.md`, `tools/AGENTS.md`, shared-checkout·git-workflow 안내와 테스트의 상한을 50으로 맞춘다. 과거 ADR의 당시 60개 관측·결정문은 보존한다. 이 결정은 D-761 결정 8과 D-790의 ‘상한 60 유지’에서 숫자만 대체한다. 청소·소유자·idle·stale-history 규칙은 바꾸지 않는다.

## Consequences

상한 부근에서는 새 작업을 시작하기 전에 기존 작업의 착지·손실 없는 정리나 명시적 예외가 더 자주 필요하다. 상한 변경이 61개 등의 현재 상태를 자동 정리하지 않는다. 생성 거절·상태·lint·도움말은 공유 `CAP`을 사용해 같은 값을 표시한다.

이번 변경은 개발 협업 도구와 그 안내만 대상으로 한다. D-427·D-429의 제품 폴더/호스트/권한과 D-430의 safety 체인을 바꾸지 않는다.

## Validation

기존 작은 상한 경계·빈 예외 이유 거절·예외 감사 기록 시험을 유지한다. 기본값 50에서 빈 orphan 49개를 포함해 50번째 생성 성공, 다음 일반 생성 거절, 사유 있는 예외 생성, 기존 orphan 보존을 회귀 검증한다. 시험 결과는 커밋에 결속된 원격 로그로 별도 확인한다. 이 결정의 Accepted 상태가 시험 통과를 대신하지 않는다.

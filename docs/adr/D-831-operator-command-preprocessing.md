# D-831 관제 자연어 전처리·명령 후보 검증·토큰 예산

**Status:** Accepted (2026-10-21; 전처리·후보 검증 설계)

사용자가 설계 후 즉시 구현을 요청했다. 첫 구현은 공통 전처리·기존 인자 계약 검증·실제 사용량 계측까지다. 새로운 자연어 확인 계약과 운영 활성화·자동 실행은 별도 수용 대상이다.

## Context

운영자는 통합관제와 Discord에서 한국어·영어로 질문하거나 작업을 요청한다. LLM은 여러 표현을 해석할 수 있지만 등록된 대상, 부정 범위, 누락된 인자와 실행 권한을 모델 답변만으로 확정할 수 없다. STT의 오인식도 같은 검증 경계를 지나야 한다.

현재 D-810/D-821 Console은 원문 2,000자·최근 이력 최대 4턴·사실 최대 64개, 선택 로봇 필터, 5초 관측 신선도를 검사한다. broker는 한 번의 호출·context 8192·생성 최대 1024와 닫힌 분류 응답을 사용한다. 전용 정규화·형태소 분석·별칭 해소·자연어 인자 추출·입력 토큰 사전 계산은 없다. CONTROL 분류와 별도 명시적 좌표 접수는 이미 분리되어 있다.

문자 수와 바이트 수는 모델 토큰 수가 아니다. 형태소 분석과 모델 토큰 분할도 서로 달라 형태소로 나누는 것만으로 토큰 절감이나 의미 보존이 보장되지 않는다. 조사를 지우면 `A 말고 B 상태`의 대상이나 `보내지 마`의 부정이 사라질 수 있다.

## Decision

### 1. 의미 해석과 실행 접수를 분리한다

| 용어 | 정의·권한 |
|---|---|
| 원문 | 사용자가 실제 전송한 텍스트. STT 결과를 수정했다면 수정 후 전송문이 요청 원문이다. 음성 원본·수정 전 전사는 별도 동의 없이 수집하지 않는다 |
| 정규화 문장 | 원문과 함께 보존되는 해석용 사본. 신원·권한이나 실행 의도를 새로 만들지 않는다 |
| 명령 후보 | 질문/행동 종류와 등록 대상·인자·부족한 정보를 표현한 비실행 제안. 모델 출력·confidence는 허가가 아니다 |
| 실행 접수 | 현재 권한·기명 확인·최신 카탈로그/관측·입력 계약을 Fleet가 검증해 기존 Task owner에 전달한 상태. 실제 성공·완료와 구분한다 |

처리 흐름은 `인증된 입력 → 원문 보존 → 제한된 정규화 → 대상/인자 해석 → 후보 검증 → 필요 정보 재질문 → 기명 확인 → 현재 조건 재검사 → 기존 실행 접수`다. 조회는 현재 사실과 권한 검증 뒤 답하며 실행 확인을 요구하지 않는다. 거절/재질문은 실행 접수로 이어지지 않는다.

명령 후보의 개념 항목은 질문/동작 종류, 로봇·장소의 canonical ID, 수치와 단위, 원문상 근거, 미해결 대상/인자다. 원문 근거는 모델이 제안하더라도 원문과의 일치를 검증한다. 이는 새 공개 JSON 필드나 API의 정의가 아니다. 실제 구조화 계약은 구현 전에 기존 `core_common.intent.interpret`의 지원 동작·인자와 대조하고 필요한 ADR/API·schema 변경을 별도로 예약한다. 임의 동작 문자열·도구 호출·셸 코드는 받지 않는다.

### 2. 원문을 보존하고 뜻을 바꾸는 정리를 금지한다

- 원문을 덮어쓰지 않는다. 원문 요청 ID·본문·locale의 멱등성을 유지하고 정규화 문장·정규화 버전·해석 profile·카탈로그 버전을 해석 증거에 결속한다. 서로 다른 원문을 정규화 결과가 같다는 이유로 같은 요청으로 합치지 않는다.
- 첫 구현은 NFC와 의미를 바꾸지 않는 제한된 공백 처리만 허용한다. 식별자·인용 내용·부정 어미·조사·숫자 부호·소수점·단위를 보존한다. 대소문자 접기·NFKC·불용어 삭제·공격적인 오타 교정을 전체 원문에 적용하지 않는다.
- 로봇·장소의 이름/별칭은 Fleet가 제공하는 현재 등록 카탈로그에서 canonical ID로 해소한다. 같은 별칭의 중복, 미등록 대상, `그것/거기`의 불명확한 참조는 재질문한다. 근사 일치는 사용자에게 보여줄 제안이며 자동 대상 선택 근거가 아니다.
- 형태소 분석기는 기본 의존성으로 추가하지 않는다. 실제 한국어 실패 사례에서 이름/조사 경계 추정에 도움이 입증될 때 Decision 내부의 교체 가능한 보조 처리로 검토한다. 형태소·키워드 목록만으로 실행 여부나 부정 범위를 판정하지 않는다.

### 3. 검증 가능한 단일 후보부터 지원한다

- 부정·인용·가정·설명 요청의 범위를 보존한다. `A 말고 B 상태`는 B를 묻는 조회이고, `A를 보내지 마`는 A의 이동 접수를 만들지 않는다. 이 두 문장을 단순한 부정 키워드 규칙 하나로 같은 것으로 처리하지 않는다.
- 여러 명령·조건문·중간 자기 수정이 있는 문장은 첫 단계에서 단일 작업으로 재확인한다. 앞부분만 실행하거나 뒤의 부정/조건을 버리지 않는다. `A를 보내고 B는 보내지 마`를 일괄 실행으로 확장하지 않는다.
- 동작별 필수 인자·타입·유한 수치·단위·지도 좌표계와 등록 대상 일치를 검사한다. 단위 변환은 정의된 변환만 결정적으로 수행하고 원 값·변환 값의 대응을 보존한다. 알 수 없는 단위·범위는 추정하지 않는다.
- 해석 결과가 명확하지 않으면 필요한 대상/인자만 질문한다. 되묻는 대화도 같은 principal·채널 범위에 속한 새 요청으로 접수하며, 새 발화만으로 이전 작업이 승인되거나 UNKNOWN이 자동 재실행되지는 않는다.
- 실행 확인은 단순히 `네`라는 텍스트를 얻는 일이 아니다. 사용자가 보는 동작·대상·인자와 그 버전/hash에 기명 확인을 결속하고 만료시킨다. 확인 후 권한·카탈로그·관측·승인이 바뀌면 재해석/재확인하며 기존 후보를 다른 대상으로 바꾸지 않는다. 이 확인 계약은 후속 구현 대상이다.
- 그 전까지 D-821의 별도 명시적 좌표 API·30초 유효성·기본 실행 OFF를 그대로 사용한다. 자연어 명령 후보를 기존 좌표 확인의 대체물로 연결하지 않는다. 비상정지는 기존 독립 경로를 유지한다.

### 4. 문맥을 줄이고 토큰·지연을 측정한다

- 정형 버튼과 기존 구조화 API는 LLM 없이 처리한다. 자유 문장을 정규식에 맞춰 곧바로 실행하는 별도 경로는 만들지 않는다.
- 선택 대상과 질문에 필요한 사실, 관련 있는 최근 이력만 포함한다. 권한·부정·사실 출처/시각·최신 작업 결과를 버리는 요약은 하지 않는다. 카탈로그/문맥이 예산을 넘으면 필요한 대상을 재질문하거나 보류하며 조용히 잘라 명령을 실행하지 않는다.
- profile별 전체 context 예산은 고정 정책·schema·카탈로그·사실·이력·현재 질문·응답 예약량을 모두 포함한다. 기존 8192/1024는 현재 profile 설정이며 추가 호출 허가가 아니다. 입력 사전 계산은 고정 모델과 일치하는 토크나이저 또는 검증된 보수적 상한이 있을 때만 도입하며, 구현 전에는 정확한 사전 토큰 제한이 있다고 주장하지 않는다.
- 실제 `prompt_eval_count`, `eval_count`, 지연을 동일 ko/en 사례의 전/후로 비교한다. 현재 broker는 응답의 사용량 값을 검사하지만 운영 계측으로 저장/표시하지는 않는다. 후속 계측은 원문·민감 정보 없이 request ID의 제한된 연결값, profile/source, 입력 hash와 사용량·지연을 기록한다.
- 현재 JSON과 `LATEST USER MESSAGE`에 중복된 원문은 실제 ko/en 분류 문제를 해결한 경로다. 중복 제거·프롬프트 축약은 동일 독립 suite에서 분류/거절 품질과 토큰·지연을 비교한 뒤 채택한다. 목표 절감률을 미리 성공으로 표시하지 않는다.
- 고정 정책·카탈로그는 버전/hash로 관리한다. 캐시를 도입해도 principal 격리·요청별 권한·현재 관측·실행 결과를 공유 캐시로 대체하지 않는다. 이번 ADR은 새 캐시 구현을 요구하지 않는다.
- 명령 전처리 때문에 자동 모델 호출 반복·자동 재시도·자동 하위 작업을 추가하지 않는다. 기존 호출 예산·타임아웃·멱등성·UNKNOWN 처리를 유지한다.

### 5. 소유자를 늘리지 않는다

| 책임 | 소유 위치 |
|---|---|
| 채널 인증·원문 요청·멱등성·재질문/확인 수명 | 기존 Fleet `server/assistant`·`server/channel`의 각 원장/접수 경로 |
| 정규화·의미 해석·공통 후보 검증 규칙 | 기존 `operations/decision/src/rosy/decision/conversation/` |
| 등록 로봇/장소·현재 권한·확인 후 최종 검증·Task 원장 | 기존 Fleet owner. World의 현재 자세·출처를 사용하며 모델 설명으로 덮어쓰지 않음 |
| 고정 모델·토큰 예산·추론 수치 | 기존 AI PC broker와 고정 profile |
| 독립 ko/en 비교·승격 증거 | 모델 PC |
| 입력 편집·대상/후보 표시·기명 확인 | Console은 `applications/fleet/web/assistant/`, Discord는 기존 채널 응답 경로 |
| 실제 장치 명령·안전·완료 관측 | 기존 실행 owner와 CORE. 새 장치 worker·직접 ROS 발행 없음 |

공통 의미 규칙은 Decision에 두고 Console·Discord에 같은 규칙을 복제하지 않는다. 채널별 신원·원장·허용된 실행 종류는 유지한다. 의미 해석 공유가 Discord 신원 대용이나 Console 실행 범위 확대를 뜻하지 않는다.

|---|---|

| D-429 | Decision 후보·World 현재 사실·Fleet 거래/원장 책임 유지 |

## 첫 구현 경계 (2026-10-21)

Decision의 `conversation/preprocessing.py`를 Console 새 profile과 Discord `d728-semantic-v3-d831`에 연결한다. 등록 이름의 원형과 NFD 등가 표기를 보존하고 공백 정리로 생기는 이름 충돌은 재질문한다. 후보는 기존 `core_common.intent.interpret`의 닫힌 동작·인자 계약으로 검증한다. 사용량은 broker의 실제 추론 응답으로만 만들고 Fleet가 전처리 digest를 검사한다. 입력 7168/생성 1024의 응답 후 검사는 정확한 호출 전 토큰 계산이 아니다.

새 Discord profile에는 자동 실행 worker를 설치하지 않는다. Console의 기존 별도 명시적 좌표 접수는 유지한다. 새 공개 확인 API·후보 확인 수명은 아직 구현하지 않았다. 원문 근거 span이나 범용 형태소 분석기도 추가하지 않았다. 질문 중복 제거/과도한 프롬프트 축약은 실제 의미 회귀가 있어 채택하지 않았으며, 불필요한 인증 식별자·전처리 해시만 모델 문맥에서 제외한다. [운영 안내](../../operations/fleet/docs/operator-assistant.md)와 [실측 기록](../validation/operator-preprocessing-2026-10-21/result.md)을 따른다.

## Alternatives

- **원문을 모두 LLM에 넘기고 자유 형식 답을 명령으로 사용:** 표현 수용은 쉽지만 등록 대상·부정 범위·필수 인자·확인 일치를 코드에서 보장하기 어렵다. 닫힌 후보와 서버 검증을 선택한다.
- **형태소 분석·키워드 규칙을 필수 관문으로 사용:** 비용은 예측하기 쉽지만 인용·조건·부정 범위와 ko/en 혼합 문장을 다루는 규칙이 커진다. 보수적 정규화와 LLM 해석, 명시적 재질문을 선택한다.
- **문맥을 먼저 요약하거나 토큰 수만 줄임:** 근거·부정·수치가 유실될 수 있다. 대상별 문맥 선택과 측정 후 절감을 선택한다.

## Consequences and acceptance

원문·해석 후보·확인·실행 결과가 연결되어 오인식과 모델 오류를 조사할 수 있다. 대신 후보/확인 수명과 ko/en 독립 평가가 필요하며, 애매한 입력은 빠른 실행보다 재질문이 늘어난다. 새 모델·형태소 분석기·서버 STT/TTS 설치는 이 결정에 포함하지 않는다.

구현 수용은 원문 불변/멱등성, 정규화 재현성, 별칭 충돌, 동작별 인자/단위, 누락/위조 인자, 권한 철회·카탈로그 변경·확인 만료, 채널 격리·재시작·UNKNOWN을 검증한다. `보내`, `보내지 마`, `보내지 말라는 뜻이야`, `A 말고 B 상태`, 복합 명령, 인용·가정·혼합 언어·잘못 인식한 ID·음수 좌표를 같은 ko/en 비교군에 넣는다. 위조되거나 바뀐 대상/인자로 실행이 접수되는 사례는 0이어야 한다.

동일 고정 모델·source/profile·카탈로그·입력으로 전/후 후보, 재질문/거절, 실제 토큰·p50/p95 지연을 비교한다. 의미/거절 회귀가 있는 절감은 채택하지 않는다. 텍스트 의미 시험과 [실제 음성·Discord·장치 수용](../plans/2026-10-21-operator-ai-field-acceptance.md)은 별도로 남긴다. 구현 시 모델 입력/정규화 규칙 변경을 새 profile과 독립 평가 증거에 결속하며 이전 SHA의 수용을 재사용하지 않는다.

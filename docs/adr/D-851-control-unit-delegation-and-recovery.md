## D-851 독립·상하위 관제의 상태 소유권과 위임·복구 계약

**Status:** Proposed (2026-10-23). D-850의 Accepted 구조 목표를 구체화하는 세부 계약 설계다. 사용자는 설계 작성·정식 기록·검증·로컬 병합을 지시했다. 문서 병합이 새 wire 계약·production dispatch·장치 수용을 승인하지 않는다.

### Context

관제 단위를 독립·상하위·중첩 구성으로 운영하려면 업무 결과와 실행 상태의 소유자, 중복 요청, 권한과 단절 중 허용 범위가 필요하다. 기존 기능을 범용 위임으로 과장하지 않고 [상세 설계](../plans/2026-10-23-composable-control-design.md)에 기본안과 수용 순서를 모았다. 이 ADR은 선택 이유와 경계를 기록하며 세부 규칙을 복제하지 않는다.

### Decision proposal

각 관제가 자기 원장과 직접 소유 자원을 가진 상하위 트리를 기본안으로 한다. 첫 범위는 같은 현장 LAN의 독립 관제, 루트 아래 A·B, R → A → A1의 3수준 중첩이다. 상위가 하위 자원을 집계하는 것은 직접 실행 소유권이 아니다.

업무 앱은 도메인 장부와 업무 완료, 각 관제는 자기 위임 이력, 하위 Fleet은 자기 실행 원장·admission·점유, CORE·OMX owner는 최종 장치 실행을 소유한다. World는 관측을 제공하고 실행 사실을 덮지 않는다.

논리 위임 식별은 관계 세대·재시작·재전송으로 바뀌지 않는다. 영속 중복 방지·작업 결합·기존 claim과 admission으로 반복 전달의 중복 실행을 막는다. 응답 유실·시간 초과·불명 점유에서 다른 하위에 자동 재배정하거나 자원을 해제하지 않는다.

첫 버전에서 상위는 후보·위임 접수까지만 요청한다. 사람 확인이 필요한 작업은 하위 인증 named operator가 기존 경로로 승인한다. 상위 사용자 이름이나 AI 응답은 승인 증거가 아니다. 상위 연결 단절 중에는 현재 admission된 유한 Action의 기존 정책만 유지하고 다음 Action·위임은 막는다.

독립 구성을 상하위 단절의 자동 권한 승격으로 해석하지 않는다. 재연결은 소유자 상태·시도·revision·완료 근거를 대조하며, 링크 복구만으로 재시작·래치 해제·점유 해제를 하지 않는다. PC 수와 논리 계층 수는 별도다.

### Alternatives and consequences

중앙 DB 하나로 모든 원장을 합치면 독립 운영이 중앙 장애에 결합된다. 동등 관제 간 자유로운 교차 실행은 소유·권한 회수의 경합 범위를 넓힌다. 트리 방식은 첫 범위의 권한·상태 소유를 제한하지만, 관제 간 동시 예약·전역 최적화·다중 현장 WAN·자동 이중화는 후속 설계가 필요하다.

공개 위임 API·서비스 인증·승인 결속·영속 transaction의 구체 계약을 확정한 뒤 구현한다. 상세 설계 P0–P5의 구성 검증, 접수, 권한·복구, 화면·배치, 장치 수용을 각각 증거로 닫는다. 설계 검토에서 찾은 세대별 중복 실행 위험·단절 중 다음 Action 실행·상위 승인 신뢰·Proposed 계약 오인은 수정·재검토했다. 이는 코드·전체 API·장치 시험을 대신하지 않는다.

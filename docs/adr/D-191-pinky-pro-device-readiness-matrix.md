## D-191 이미지는 실기 평가표가 모두 PASS(또는 사람 대기)일 때만 배포한다 — 격차는 스토리 하나씩 저장소→이미지→카드로 닫는다

**Status:** Proposed (2026-09-24). D-173(병합 커밋으로 첫 카드), D-189(서명 전 실행 검증),
D-190(공식 동등성)을 묶어 배포 기준을 정한다.

**Context:** 2026-09-24 실기 평가(`docs/validation/pinky-pro-evaluation-2026-09-24.md`)에서 부팅·Wi-Fi·SSH·
CORE 기동은 됐지만, 공식 Pinky Pro가 하는 일 대부분이 우리 이미지에서 동작하지 않았다. 원인은 모두
"이전 Docker 설치 경로에는 있었지만 서명 이미지 경로로 옮겨지지 않은 것"이거나 "공식 이미지에 미리 깔려
있어 저장소에 선언되지 않은 것"이었다.

- 모터 UART overlay
- `dynamixel_sdk`
- `sllidar_ros2`
- `pinkylib`(Rosy에서는 `rosylib`)
- 하드웨어 런타임 unit
- API 초기 토큰
- LCD 라이브러리

호스트 테스트와 이미지 빌드는 이 격차를 하나도 잡지 못했다. 실기에서만 보였다.

**Decision:**

1. **평가표가 배포 기준이다.** 모든 행이 PASS이거나, 사람의 입회를 기다리는 BLOCKED이고 그 다음 행동이
   적혀 있을 때만 새 이미지를 "배포 가능"으로 표시한다. 평가표는 이미지마다 다시 채운다.
2. **격차는 스토리 하나씩 닫는다.** 순서는 평가표 "우선순위"를 따른다(US-002 → US-009 → US-004/005 → US-003
   → US-006 → US-007 → US-008). 스토리마다 브랜치 하나, PR 하나, 독립 리뷰, 실기 증거를 둔다.
3. **공식 이미지에 미리 깔린 것은 이름과 버전을 고정해 이미지에 넣는다.**
   - `dynamixel_sdk`는 해시 고정 wheel로 넣는다.
   - `sllidar_ros2`는 고정 커밋의 소스를 빌드한다(Docker 경로에 있던 커밋).
   - UART overlay는 `config.txt`에 넣는다.
   - `pinkylib`는 공개 소스가 없어 재배포할 수 없다. 필요한 기능(배터리)은 공개된 장치 프로토콜
     (`sensor_adc`와 같은 ADC 읽기)로 Rosy가 직접 구현한다.
4. **서명 전 검사를 넓힌다(D-189 B의 연장).** 이미지 빌드가 다음을 확인하지 못하면 실패한다.
   - 하드웨어 런타임 import: `bringup`, `dynamixel_sdk`, `rosylib`
   - `sllidar_ros2` 설치 여부
   - `config.txt`의 UART overlay
   - 필요한 unit의 설치와 enable
5. **실기에서만 알 수 있는 것은 실기로 확인한다.** 장치 노드 생성, 모터 ping(토크 없이), 라이다 스캔,
   배터리 토픽, LCD 화면이 여기에 해당한다. 바퀴를 움직이는 시험은 런북 G4대로 사람이 있을 때만 한다.
6. **장치 즉석 수정 금지(D-190 결정 6)를 이 계획 전체에 적용한다.**

**Alternatives:**

- 공식 이미지 위에 Rosy를 얹기: 공식 이미지는 공통 비밀번호, root 서비스, 서명 없는 갱신을 쓴다.
  D-33·D-161·D-164와 충돌한다.
- `pinkylib`를 공식 이미지에서 복사하기: 라이선스를 알 수 없어 재배포할 수 없다.
- 평가표 없이 결함을 만날 때마다 고치기: 이번처럼 카드 한 장마다 새 결함이 나오고, 언제 끝나는지
  알 수 없다.

**Consequences:**

- 다음 배포 이미지(007)는 평가표를 모두 채운 뒤에 나온다.
- 이미지가 `sllidar_ros2` 빌드와 wheel 몇 개만큼 커지고, 빌드가 길어진다.
- `rosylib`는 Rosy 소유 코드가 되고, 공식 동작과의 동등성은 평가표로 추적한다.

**실행 계획:** 평가표의 스토리 표와 ralph PRD(스토리 US-001~US-009).

## D-772 스테이션 위치 버전과 배터리 기반 자동 충전 운영

**Status:** Accepted (2026-10-16, 사용자 설계·계획 실행 승인). 구현은 단계별이며 실기·현장 수용과 운영 활성화는 별도다.

### Context

도크 포즈는 로봇별 저장소에 있고 현장 카메라 sighting은 자동 접안용 제어 근거가 아니다. 저배터리 복귀와 충전 중 확인은 있지만 스테이션 이동 시 좌표 합의, 배터리 건강도 기반 스케줄, 정상 충전 종단 이후 자동 재투입은 연결돼 있지 않다. 충전 확인 해제로 peak_v가 초기화되므로 기존 만충 이벤트만으로 출발할 수 없다.

### Decision

Fleet이 검증된 스테이션 설치 포즈와 위치 버전을 발행한다. 스테이션 ID, 지도 ID/revision, 위치 버전, 교정 revision, 충전 session, 로봇 boot/odom 세대는 다른 식별자다. 카메라와 로봇은 관측 후보를 제공하며 위치 버전의 권위자가 아니다. 스테이션 카메라의 상대 포즈만으로 지도상 새 위치를 확정하지 않는다.

CORE는 검증된 상대 관측으로 최종 접안을 수행하고 실제 정지·물리 착좌를 확인한다. 이전 위치 버전을 무효화하면 진행 중 목표의 종료를 확인한 뒤 새 목표를 제출한다. Fleet은 경로와 에너지 비용을 다시 계산하며 지도/진입 연결·배터리 여유가 부족하면 HOLD다.

충전 중 확인, 물리 정상 종단, 정책 목표 충전량, 출발 가능은 별도 사실이다. 정상 종단은 충전기/BMS의 근거와 최신 팩 관측을 요구한다. 단순 무전류나 높은 전압만으로 완료·출발하지 않는다. Fleet은 robot/station claim과 durable 충전 세션을 기존 admission에 연결한다. 이안 완료와 접점 이탈 전 일반 작업을 배정하지 않는다. 수동·E-stop·로컬 저배터리 보호가 우선한다.

배터리 SOH·유효 에너지·남은 운행 시간이 미측정이면 unknown을 유지한다. 초기에는 검증된 보수적 운행 프로필을 사용할 수 있지만 이를 건강도 계측으로 표시하지 않는다. 측정된 용량·부하별 비용에 따라 작업+귀환+접안+예비 에너지 예산을 재평가한다.

공유 계약은 `core_common.protocol.station_charging`이며 canonical export는 `schemas`에 둔다. 수치·식별자·시간 범위는 typed schema로 검증하고 source 인증·기대 대상·신선도·권한은 입력 경계에서 검증한다. DTO 생성 자체는 제어 허가가 아니다. 실제 endpoint 추가는 producer/consumer와 API reference를 함께 변경하는 후속 단계다.

### Consequences

기존 제어기·작업 원장·trip·저배터리 보호를 재사용한다. 위치 변경·재시작·중복 이벤트·이안 결과 불명을 정상적인 복구 상태로 처리한다. 실물 정상 종단 신호나 건강도 계측이 없는 구성은 전체 자동 운영 수용을 완료할 수 없다. 1대/1스테이션 연속 사이클과 이동 후 복귀를 먼저 검증한다.

| 기존 결정 | 관계 |
|---|---|
| D-427 | contracts/operations/middleware의 기존 책임을 사용한다 |
| D-429 | 카메라 관측·현장 장치·로컬 실행의 권위를 분리한다 |
| D-430 | 모터/접점/저전압 보호를 스케줄러가 우회하지 못하며 safety 변경은 독립 검토한다 |
| D-350·D-369·D-763 | 충전 단계, 정지 근거, 기존 실행 owner와 claim을 유지·확장한다 |
| D-758 | Proposed 공통 지도 기준을 이미 존재하는 기능으로 가정하지 않는다 |

검증·세부 범위는 [설계](../plans/2026-10-16-station-charge-lifecycle-design.md)와 [구현 계획](../plans/2026-10-16-station-charge-lifecycle.md)을 따른다.

### 구현 부기: 관측과 설치 기록의 source holder

Fleet 크기 검사가 17800→18081 증가를 거절했다. 기존 sightings·tracking/교정과 신규 station 설치 원장을 `server/site_observation` holder로 묶어 독립 크기 단위로 측정한다. 기존 `fleet.server.*` import와 실행 권한은 유지한다. 관측·교정·설치 기록이라는 같은 책임으로 묶으며 표시용 tracking을 자동 접안 근거로 승격하지 않는다. 새 최상위 패키지나 writer를 만들지 않는다(D-427·D-429·D-430).

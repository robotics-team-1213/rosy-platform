## D-346 병행 세션 충돌은 커밋 시점 검사로 막는다 — ADR 번호는 행 추가 즉시 선점한다

**Status:** Accepted (2026-09-29, 저장소 도구·작업 규칙만). 기존 ADR의 의미, 게이트 정의(ROS-SIM…FIELD), CI 구성을 바꾸지 않는다. 훅 설치는 클론별 옵트인이며 강제 이행 수단이 아니다.

### Context

한 저장소를 여러 병행 세션이 같은 작업 트리(main 체크아웃)에서 돌며, 커밋 author가 전부 동일하다(`pl3`, 2026-09-29 하루 136커밋). 이 환경에서 같은 날 네 번의 번호 충돌과 여러 적신 착지가 기록되어 있다:

- **번호 충돌 4건**: D-223(2026-09-25, D-224로 회피), D-324(같은 날 충돌로 D-325 재부여, `adr_gaps` 노트), D-337(2026-09-29, 병행 커밋 흡수로 표에 동일 번호 2행 — 이 회차에 D-338로 재부여), 그리고 조사에서 발견된 **D-218·D-219·D-220 잠복 중복 행**(같은 결정의 두 문구 변형이 나란히 커밋됨).
- **적신 착지**: 2026-09-29 하루 6건(ADR 본문 부재, io 이미지 클로저, 프로토콜 버전 핀 2건, 크기 예산 2건) — 전부 1~2분짜리 계약·구조 시험으로 잡히는 것들이었으나 커밋 뒤에야 발견됐다. 풀 게이트는 52분이라 상시 실행이 현실적이지 않다.
- **인코딩 손상**: D-336 표행이 PowerShell 리다이렉트 코드페이지로 한글이 `?`로 바뀐 채 커밋됐다(같은 회차에 복구).
- git hook은 전혀 없다(`.git/hooks` 샘플뿐).

근본 원인은 두 가지다: (a) 중복 ADR 번호가 `parse_adr_log`의 dict 축소로 **조용히 묻혔다** — 본문 중복만 잡고 표 행 중복은 못 봤다. (b) 위반을 잡는 검사가 이미 존재하지만 **실행 시점이 착지 뒤**라서 늦다.

### Decision

1. **표 행 중복은 즉시 에러다.** `parse_adr_log`가 인덱스 행 중복을 `duplicate index row`로 보고한다(기존 `duplicate body section`과 함께). dict 축소로 묻히는 경로를 없앤다.
2. **깨진 인코딩도 lint가 잡는다.** governed 파일(ADR Log, 모듈 progress/logs)에서 `??` 연속(코드페이지가 한글을 먹은 흔적)을 발견하면 에러로 보고한다.
3. **푸시 시점 패스트 게이트를 둔다.** `tools/hooks/`의 pre-push 훅이 harness lint + 계약·구조·protocol·io 클로저 시험(약 2분)을 돌린다. 설치는 `tools/hooks/install.sh`. 훅은 git 버전 관리 밖이므로 문서로 안내한다.
4. **번호는 선점이다.** ADR 번호는 표에 행을 넣는 즉시 그 커밋으로 선점한다(본문·저널은 뒤따라도 좋다). 분기로 번호를 미리 쓸 때는 `adr_gaps`에 사유를 남긴다(기존 관행을 규칙으로 승격).
5. **공유 트리에서는 짧은 커밋 창.** main 체크아웃에서 문서·구조 파일을 고치는 세션은 그 즉시 커밋한다(작업 흡수·저널 소실 방지). 긴 작업은 `.worktrees/` 격리가 원칙이다.
6. **게이트는 2티어로 문서화한다.** 커밋 직전 최소 게이트(≈2분, 3번 목록)와 풀 게이트(52분, 릴리스·현장 전)를 AGENTS에 구분해 적는다.

### Alternatives

- **세션별 git author 구분으로 attribution 방어:** author가 하나라 불가능하고, 규약 위반이지 기술 방어가 아니다. 기각.
- **CI(origin push)에만 의존:** 피드백이 수 시간 늦고 실패는 이미 공유 main에 착지한 뒤다. 기각.
- **풀 게이트를 매 커밋에:** 52분이라 위반을 양산한다. 2티어가 답이다. 채택.
- **아무 것도 안 함:** 충돌 사례가 4건으로 누적됐다. 기각.

### Transition / validation

- 이 ADR과 같은 변경에서: 표 행 중복 검사·`??` lint 추가와 단위 시험, D-218/219/220 잠복 중복 정리(본문문서 제목과 일치하는 행을 남긴다), pre-push 훅·설치 스크립트, 솔루션 문서 2건(스윕, 인코딩)을 함께 반영한다.
- 새 검사는 변이 증명으로 믿는다: 중복 행·`??`를 삽입해 적신을 확인하고 복구한다(test/AGENTS 규약).
- sd_writer 부하 민감 시험(단독 통과·풀스위트 실패)은 별도 결함으로 기록하고 이 ADR 범위 밖에서 정비한다.

**Consequences:** 병행 세션의 번호 충돌과 깨진 인코딩은 푸시 시점에 적신으로 드러난다. 중복 행을 남겨둔 채로는 lint가 녹색이 되지 않으므로 레거시 정리가 선행 의무가 된다. 훅 미설치 클론은 방어망 밖이며, 그 경우 기존 게이트 규율이 그대로 적용된다.

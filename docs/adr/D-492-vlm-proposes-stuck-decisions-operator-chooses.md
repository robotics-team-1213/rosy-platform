## D-492 막힘 판단은 영상 언어 모델이 제안하고 운영자가 고른다 — 느린 판단 층의 첫 자리

**Status:** Proposed (2026-10-07, 사용자 요청 "이미지를 보고 판단을 맡길 수 있는지, autopilot·드론 비행처럼 더 고민"). 자리·경계·도입 순서 결정만이다. 코드, 모델 설치, Fleet 콘솔 화면, 새 공개 API, 모델 자동 응답, 실기 활성화를 승인하지 않는다.

### Context

- **로봇은 대부분 막혀서 멈춘다.** D-407 배경대로 2026-10-01 실주행에서 차선 추종 시간의 대부분이 `obstacle_ahead` HOLD 또는 `LOST` 였다. D-407 은 막힘 사건을 열고 관제 운영자에게 다섯 답(`WAIT`, `RESUME`, `BACK_AND_RETRY`, `MANUAL`, `ABORT`)을 묻는다. 운영자는 여러 대를 보고 있어 늦게 답하거나 답하지 못하고, 15 s 뒤 로컬 복구로 넘어간다.
- **사람이 하는 그 판단은 카메라 한 장으로 하는 판단이다.** 앞이 비었는지, 차선이 보이는지, 물러날 자리가 있는지를 미리보기와 여유 값으로 본다. 영상 언어 모델(VLM)은 이런 질문에 자연어 근거와 함께 답할 수 있다.
- **VLM 은 느리다.** 2026-10-06 모델 PC 실측에서 `qwen3-vl:8b-instruct`(Ollama, RTX 5080 Laptop 16 GB)는 320×240 프레임 하나에 1.5–3 s 걸렸다. 로봇 ↔ 사이트 왕복 지연이 더해진다. 차선 추종(10–30 Hz)과 정지(LiDAR·IR, 그보다 빠름) 루프에는 들어갈 수 없다.
- **업계의 자율 시스템은 빠른 층과 느린 층을 나눈다.**
  - **드론**(PX4, ArduPilot)은 자세 제어를 비행 컨트롤러에서 수백 Hz 로 돌린다. 임무·의미 판단은 companion computer 에서 초 단위로 돈다. companion 이 끊기면 비행 컨트롤러의 failsafe(정지 비행·귀환)가 받는다.
  - **자율주행 연구 DriveVLM-Dual** 은 VLM 이 장면을 해석하고, 고전 계획기가 실시간 궤적을 만든다.
  - **로봇 Figure Helix, NVIDIA GR00T N1** 은 System 2(느린 VLM)와 System 1(빠른 정책)로 나눈다.
  - 공통점은 셋이다. 느린 층은 빠른 층에 목표·판단을 주고 직접 구동하지 않는다. 느린 층이 조용해지면 빠른 층의 기본 동작이 이어진다. 안전은 모델 밖에 있다.
- **Rosy 는 이 자리를 이미 정했다.** D-399·D-427·D-429 는 VLM 을 「숙고형」으로 두고 `operations/decision` 에 둔다. 숙고형은 Mission·Task·replan 후보만 내고 실행권이 없다(D-326 §2). 모델 tool 은 요청 메시지이고 구동·정지 도구는 없다(D-392 §2, §4). 숙고형은 Motion Intent 를 만들지 않는다(D-442). 원격 AI 는 로봇 명령 경로에 들어가지 않는다(D-231 §4). 이 결정은 그 자리 안에서 첫 쓰임새를 정한다.

### Decision

1. **첫 쓰임새는 D-407 막힘 판단의 제안이다.**
   - 막힘 사건이 열리면 사이트의 판단 제안기가 사건의 카메라 미리보기와 여유 값(앞·뒤·회전반경, 원인, 마지막 차선 관측)을 받는다.
   - 제안기는 다섯 답 가운데 하나와 짧은 근거, 판단에 쓴 프레임 identity 를 낸다.
   - 제안은 Fleet 콘솔의 판단 요청 옆에 「모델 제안」으로 보인다. 운영자가 그 답을 고르거나 다른 답을 고른다. CORE 로 가는 답은 지금처럼 운영자 권한의 `POST /api/v1/line-follow/stuck/decision` 하나다(D-407 구현 메모).
   - 차선 추종·정지·후진 같은 빠른 층은 바뀌지 않는다.
2. **제안기는 숙고형 규칙을 그대로 따른다.**
   - 코드는 `operations/decision`, 모델 공급자 adapter 는 `integrations/models/<provider>` 에 둔다(D-429).
   - 제안은 D-392 의 실행권 없는 proposal 결과다. 막힘 사건 id 와 묶이고, 다른 사건에 쓰이지 않는다.
   - 제안기는 CORE·ROS·Device Action·정지 API 를 부르지 않는다. 모델 credential 은 Fleet 밖으로 나가지 않는다.
3. **느린 층이 조용해도 안전하다.**
   - 제안은 D-407 의 `recovery_ask_s`(기본 15 s) 안에 운영자 화면에 도착해야 쓸모가 있다. 제안기 시간 예산은 그보다 짧게 둔다(시작값 8 s). 넘으면 제안 없음으로 기록한다.
   - 제안이 없거나 늦거나 형식이 틀려도 D-407 §3 의 흐름(운영자 대기 → 로컬 복구 → HOLD)은 그대로다. 제안기가 로봇 동작을 바꾸는 경로는 없다.
   - 모델 출력은 다섯 답의 닫힌 목록으로만 받는다. 목록 밖 값은 제안 없음이다.
4. **모델은 사이트 안에서 돈다.**
   - 기본 공급자는 사이트 GPU 의 로컬 VLM(현재 후보 `qwen3-vl:8b-instruct`, Ollama, loopback 또는 사이트 내부 주소)이다. 프레임이 사이트 밖으로 나가지 않는다.
   - 외부 API 공급자는 D-392 §7 의 자료 반출 승인을 따로 받은 뒤에만 쓴다.
   - 어느 호스트에 둘지(관제 PC GPU 확인 필요, 모델 PC 는 D-434 상 학습 전용, ai PC 는 소유자 협의 필요)는 도입 1단계 전에 정한다.
5. **도입은 D-378 의 재생 → 그림자 → 사람 확인 순서다.**
   - **V0 재생 평가.** 기록된 막힘 사건(D-407 §6 의 전후 프레임, D-379 녹화)에서 사람이 정답 답을 붙인 평가 세트를 만든다. 제안기의 답 정확도, 답별 혼동, 지연을 잰다. 합격 수치는 실행 전에 정해 적는다. 이 단계는 모델 PC(D-434)에서 오프라인으로 한다.
   - **V1 그림자.** 실주행에서 제안을 기록만 하고 운영자 화면에 보이지 않는다. 운영자 답과 제안의 차이를 세션마다 남긴다.
   - **V2 운영자 보조.** 제안을 운영자 화면에 보인다. 운영자가 고른다.
   - 단계마다 사용자 승인이 필요하다.
6. **모델이 사람 없이 답하는 것은 이 결정 밖이다.** D-326 §3 의 재판단 밸브와 같은 성격이라 별도 ADR 이 필요하다. 그 ADR 은 최소한 V2 운영 기록의 일치율, 자동 답을 허용할 답의 부분집합(예: 동작이 없는 `WAIT`), 운영자 부재 판정, 사고 시 기록 규칙을 정해야 한다.
7. **기록한다.** 제안마다 사건 id, 프레임 identity 와 hash, 공급자·모델·프롬프트 id, 지연, 답, 근거, 운영자가 고른 답을 사건 카탈로그에 남긴다. V0 평가 세트와 결과는 learning 의 평가 산출물로 남긴다(D-475 의 평가 정답 규칙: 모델 출력은 정답이 아니다).

### Alternatives

- **VLM 이 직접 조향·속도를 낸다(end-to-end, VLA 를 빠른 층으로).** 1.5–3 s 지연으로 차선 추종 주기를 맞출 수 없고, D-231 §4·D-442 와 어긋난다. 반응형 정책은 D-399 후속 1의 엔벌로프 스킬로 별도 결정한다.
- **VLM 이 막힘 답을 바로 CORE 에 보낸다.** 운영자 권한 규칙(D-407 §2)과 D-326 §2·D-392 §4 를 우회한다. 평가 근거 없이 판단을 맡기게 된다.
- **제안 없이 운영자만 판단한다(현 상태).** 운영자가 없거나 늦으면 15 s 를 잃고 로컬 복구로만 간다. 막힘 자료를 판단 학습에 쓰지 못한다.
- **세계 모델 기반 계획(V-JEPA 2 류).** 「이렇게 움직이면 어떻게 되나」를 예측해 행동을 고르는 방식이다. 빠른 층의 계획기 후보가 될 수 있지만 학습 자료·연산·검증 부담이 크고 지금의 막힘 판단 문제보다 넓다. 따로 조사한다.

### Consequences

- 막힘 판단 요청이 「사진 + 다섯 답」에서 「사진 + 다섯 답 + 모델 제안과 근거」로 바뀐다(V2 에서). 운영자가 여러 대를 볼 때 판단 시간이 줄 수 있다. 줄어드는지는 V1·V2 기록으로 잰다.
- 막힘 사건마다 사람 답이 쌓여 판단 평가 세트가 자란다. 나중의 자동 응답 ADR 근거가 된다.
- 새로 필요한 것: 사이트 GPU 호스트 결정, 제안기 서비스, 콘솔 표시, 평가 세트 도구. 각각 별도 변경이다.

### Verification

- 이 ADR 은 문서다. `python tools/harness/rosy_harness.py lint` 통과는 구조 기록의 증거이며 모델 판단 품질의 증거가 아니다.
- V0 의 합격은 사람 정답 평가 세트의 수치로만 선언한다.

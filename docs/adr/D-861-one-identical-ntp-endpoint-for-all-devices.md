# D-861 — 모든 기기는 동일한 현장 NTP 서버 하나를 사용한다

**Status:** Accepted (2026-10-24, 사용자 명시 결정)

## Context

사용자는 전체 기기에 같은 NTP 서버를 적용할 것을 재확인했다. D-859는 현장 계층을 정했지만 Linux 클라이언트의 복수 source를 허용해 설치마다 다른 서버 집합을 만들 수 있었다. 단순히 각 OS의 NTP를 켜는 것으로는 요구를 충족하지 않는다.

## Decision

1. 관제 PC의 NTP 서비스를 **모든 기기의 단일 공통 endpoint**로 정한다. 운영자의 비공개 설치 기록에 정한 동일한 DNS 이름을 Linux PC·Pinky·OMX 제어 호스트·Windows에 그대로 사용한다. 실제 이름·주소는 공개 저장소에 넣지 않는다. 여러 네트워크에서 같은 이름으로 도달할 경로와 이름 해석을 먼저 확인한다.
2. Linux 클라이언트는 `server` 하나만 허용한다. 자체 공용 pool·DHCP source·개별 fallback·다른 현장 서버를 추가하지 않는다. Windows의 manual peer도 같은 서버 하나다. 컨테이너는 그 호스트 시계를 공유한다. 설정 파일의 동일성과 실제 선택한 NTP 서버를 함께 검사한다.
3. 외부 시간원 여러 곳을 사용하는 주체는 관제 PC 하나뿐이다. 관제 PC 중단·연결 단절·미동기는 정상 완료로 숨기지 않는다. D-859의 오차·표본 나이·유지보수·권한 경계와 별도 장치 수용을 유지한다. 공통 서버 교체는 전체 기기를 같은 새 endpoint로 전환하는 운영 변경이며 개별 fallback으로 해결하지 않는다.
4. 모바일·MCU도 동일한 endpoint를 설정해야 한다. OS/MDM/펌웨어에서 설정할 수 없거나 연결되지 않은 기기는 **적용 미완료**로 남긴다. 서버 수신 시각을 붙이는 일은 해당 기기 시계 동기화의 대체 증거가 아니다. 실제 설정·선택 서버·갱신 시각·오차를 장치별로 확인하기 전에는 전체 완료를 보고하지 않는다.
5. 이미 운영 중인 관제 PC의 승인된 NTS upstream은 인증을 유지한다. 이 경우 D-859의 전체 설정 교체 대신 기존 `confdir`에 클라이언트 ACL만 추가할 수 있다. 구문을 검사하고 같은 ACL을 실행 중 chrony에 적용한다. 재시작·강제 step 없이 서버를 열어도 전체 시각 정확도 수용은 별도로 확인한다. 클라이언트는 여전히 같은 단일 endpoint만 사용한다.

## Consequences

전체 장치가 같은 기준을 따르는 대신 관제 NTP가 단일 장애점이 된다. 외부망에 NTP를 공개하지 않고 승인된 클라이언트만 허용한다. 비밀번호 sudo, 오프라인 장치, OS 설정 제한은 적용 장애로 명시하고 권한 우회·임의 인증 변경으로 처리하지 않는다.

이 결정은 D-859의 복수 클라이언트 source 허용 부분을 대체한다. [구현·절차](../../deploy/hosts/README.md#공통-시간-동기화-d-859) 및 `test/test_time_sync.py`의 복수 source 거부 시험으로 연결한다.

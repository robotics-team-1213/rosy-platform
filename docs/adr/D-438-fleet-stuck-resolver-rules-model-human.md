## D-438 막힌 로봇의 판단은 Fleet 판단기가 규칙 → 비전 모델 → 사람 순으로 내리고, Fleet 은 미리 주의점을 알린다

**Status:** Proposed (2026-10-03, 사용자 지시 "콘솔에서 사람이 답하지 말고 알고리즘에 따라 처리하고, 안 되면 사람에게 확인하거나 OpenRouter 비전 모델로 처리", "로봇이 문제가 생기면 fleet 을 호출하고, fleet 이 보고 있다가 미리 주의점을 전달"). D-407 §2 의 "관제 운영자 권한 이상이 답한다"를 고친다. 로봇 쪽 막힘 상태기계, 다섯 답, CORE 의 답 재검사(D-407 §2·§4·§5)는 그대로다. 경로·필드·오류코드는 D-18 에 따라 구현 변경에서 API Reference·typed schema 와 함께 확정한다. 문서만, 코드 변경 없음.

## 배경

- **실주행에서 멈춘 채 끝난다.** 2026-10-03 8kcn·9dfk CAMERA_LINE 실주행(payload 031)에서 세 번 모두 멈춤으로 끝났다. `obstacle_ahead` 50 s(옆 로봇이 몸 모서리 4 cm 앞), `LOST camera_reselection_required`(9dfk 가 흰 벽을 선으로 따라감, 8kcn 이 횡단보도에서 선 상실), `camera_observation_stale`(로봇 CPU 과부하). 막힘 질문(D-407)은 열렸지만 아무도 답하지 않아 `WAITING_CONSOLE` 에 머물렀다.
- **Fleet 은 막힘을 브라우저가 열려 있을 때만 본다.** `LineStuckBoard.observe` 는 `GET /api/fleet/state` 안에서만 돈다(`src/site/fleet/fleet/server/console_routes.py`). 콘솔을 아무도 열지 않으면 Fleet 은 막힘을 모른다.
- **답은 사람만 한다.** D-407 §2 는 운영자 권한 이상을 요구하고, `WAITING_CONSOLE` 에는 기한이 없다. 운영자는 대부분 그 자리에 없다(D-407 배경).
- **Fleet 이 아는 것을 로봇이 모른다.** Fleet 은 여러 로봇의 위치, 사이트 차선(`site_lanes`), 횡단보도·정지선 같은 장면 요소를 알지만, 로봇에 미리 알려줄 통로가 없다. 로봇은 횡단보도에서 선이 끊기는 것을 놀라서 멈춘다.

## 결정

1. **Fleet 판단기(resolver)를 둔다.** Fleet 서버 안 상시 작업이다. 브라우저 없이 동작한다.
   - **로봇이 Fleet 을 부른다.** 판단기는 FleetAgent 사건 `nav.line_stuck_opened`·`nav.line_stuck_asked` 를 받는 즉시 그 막힘을 맡는다. 사건이 빠졌을 때를 위해 로봇 상태(`line_follow.stuck`)도 짧은 주기로 다시 읽는다. 둘 중 먼저 본 쪽이 맡고, 같은 `stuck_id` 는 한 번만 맡는다.
   - **답은 기존 경로로 낸다.** `POST /api/fleet/robots/{robot_id}/line-stuck/decision` 이 쓰는 Fleet→CORE REST 중계를 그대로 쓴다. 새 하향 통로를 만들지 않는다.
   - **판단기는 자기 주체로 답한다.** 사람 운영자 토큰을 빌리지 않는다. 판단기 주체(예: `fleet-resolver`)는 막힘 답에만 쓰이고, 비상정지 해제·모드 변경·보정 lease·제한값 변경 권한이 없다. CORE 는 이 주체의 답을 운영자 답과 같은 검사로 받는다.
2. **1단계 — 규칙.** 같은 입력이면 같은 답을 낸다. 규칙마다 id 가 있고, 답에 그 id 를 싣는다. 처음 규칙:
   - `R1 peer_ahead`: 원인 `obstacle_ahead` 이고 Fleet 이 아는 다른 로봇의 몸이 막힌 로봇의 앞 경로 띠 안 `resolver_peer_reach_m` 이내면 `WAIT`. 그 로봇이 띠 밖으로 나가면 `RESUME`.
   - `R2 static_back_off`: 원인 `obstacle_ahead`, 앞 물체가 Fleet 로봇이 아니고, 로봇이 보고한 뒤 여유(`rear_state`)가 `clear` 면 `BACK_AND_RETRY`.
   - `R3 lane_lost_back_off`: 원인 `lane_lost` 이고 뒤 여유가 `clear` 면 `BACK_AND_RETRY` 한 번.
   - 같은 막힘(`restuck_of` 로 이어진 막힘 포함)에 규칙이 낼 수 있는 답은 `resolver_rule_budget`(기본 2) 개다. 넘거나 맞는 규칙이 없으면 2단계로 간다.
   - CORE 가 답을 거부(409)하면 그 규칙은 그 막힘에서 다시 쓰지 않는다.
3. **2단계 — 비전 모델(OpenRouter).** 사이트 설정으로 켤 때만 쓴다(기본 꺼짐).
   - 입력: 로봇 카메라 미리보기 한 장(판단할 때 로봇에서 한 번 받는다. D-59 의 영상 중계 금지는 그대로이고, 저장하지 않는다), 막힘 원인과 여유값(앞·뒤·회전, `rear_state`), 마지막 차선 관측, 같은 막힘에서 지금까지의 답과 CORE 응답, 근처 Fleet 로봇 위치.
   - 출력: 고정 JSON `{decision, reason, confidence}`. `decision` 은 `WAIT`·`BACK_AND_RETRY`·`RESUME`·`ABORT`·`ESCALATE` 중 하나다. `MANUAL` 은 사람만 고른다. 형식이 틀리거나, `confidence` 가 `resolver_model_min_confidence` 미만이거나, `resolver_model_timeout_s` 안에 답이 없으면 `ESCALATE` 로 본다.
   - `RESUME` 도 고를 수 있다. CORE 는 경로 띠 안 물체가 정지 거리 안이거나 scan 이 오래되었으면 거부한다(D-407 §2). 모델 판단이 이 검사를 넘지 못한다.
   - 같은 막힘에 모델 답은 `resolver_model_budget`(기본 2) 개다. 넘으면 3단계로 간다.
   - 모델 이름·키는 관제 PC 설정에만 둔다. 저장소·로봇·사건에는 키를 두지 않는다. 카메라 영상이 외부 서비스로 나가므로 켤 때 사이트 운영자의 명시적 동의가 필요하다(설정 항목 하나, 기본 꺼짐).
4. **3단계 — 사람.** 판단기가 `ESCALATE` 하면 지금의 콘솔 판단 요청(D-407 Fleet 쪽)에 단계·사유·시도 기록과 함께 올리고 알림을 보낸다. 사람의 답은 언제나 판단기보다 우선한다. 사람이 답하면 판단기는 그 막힘에서 손을 뗀다.
5. **기한.** `WAITING_CONSOLE` 에 로봇 쪽 기한은 두지 않는다(로봇은 HOLD 가 안전한 기본값). 대신 판단기가 막힘을 맡은 뒤 `resolver_escalate_after_s`(기본 60 s) 안에 풀리지 않으면 단계와 관계없이 사람에게 올린다.
6. **Fleet 의 사전 주의점(advisory).** Fleet 은 로봇이 막히기 전에 주의점을 보낼 수 있다.
   - 종류(처음): `slow_zone`(구간 안 선속도 상한), `lane_gap_ahead`(횡단보도·교차로처럼 차선이 끊기는 구간과 길이), `peer_approaching`(다가오는 로봇과 예상 만남 지점).
   - **조이는 주의점은 바로 반영한다.** 속도 상한을 낮추는 것은 로봇이 그대로 따른다.
   - **푸는 주의점은 로봇 설정 안에서만.** `lane_gap_ahead` 는 그 구간에서 차선 상실 판정(`lost_after_s`)을 늦추고 마지막 방향을 유지하게 할 수 있지만, 거리·시간은 로봇 설정의 최대치(`lane_gap_bridge_max_m`, 기본 0 = 꺼짐)를 넘지 못한다. CORE 의 장애물 판정(D-422·D-424)은 그 구간에서도 그대로다.
   - 주의점은 유효 기간과 위치를 가진다. 기한이 지나거나 로봇이 구간을 벗어나면 로봇이 버린다. Fleet 연결이 끊기면 받은 주의점 중 푸는 것만 즉시 버린다.
   - 주의점은 판단(명령)이 아니라 힌트다. CORE 가 유일한 `cmd_vel` 발행자라는 원칙(D-2)과 Safety Guard 앞 배치(D-399, D-430)는 바뀌지 않는다.
7. **안전 불변식.**
   - 어느 단계의 답이든 CORE 의 재검사가 최종이다. CORE 의 거부는 그대로 기록되고 판단기는 거부를 우회하지 않는다.
   - 비상정지는 판단기·모델·주의점이 풀 수 없다. 비상정지는 막힘을 닫는다(D-407).
   - Fleet 연결이 끊기면 로봇은 D-407 동작(관제 연결 없음 → 로컬 복구 설정을 따름 → HOLD)으로 돌아간다. 판단기가 없다고 로봇이 스스로 더 풀어주지 않는다.
   - 모델 출력은 안전 기능이 아니다(D-430). 모델 SDK·HTTP 클라이언트는 Fleet 판단기 안에만 있고 로봇 런타임에 들어가지 않는다.
8. **기록.** 판단기의 모든 답은 단계(`rule`·`model`·`human`), 규칙 id 또는 모델 이름, 입력 요약(미리보기 순서번호, 여유값), CORE 응답(수락·거부 code), 걸린 시간을 Fleet 감사에 남긴다. 모델 판단과 그 결과(풀림·재막힘·사람 개입)는 나중에 규칙을 늘리거나 학습 자료로 쓸 수 있게 남긴다. 카메라 영상 자체는 남기지 않는다(D-379 녹화가 따로 있다).

## 결과

- 막힌 로봇은 사람이 콘솔을 보지 않아도 규칙이나 모델의 답을 받는다. 사람은 규칙·모델이 못 푼 막힘만 본다.
- Fleet 판단기, 주체, 사건 구독, 미리보기 한 장 받기, OpenRouter 호출, 감사 기록, 콘솔의 단계 표시가 Fleet 쪽 변경이다.
- 로봇 쪽은 주의점 수신·만료와 `lane_gap_ahead` 연결(CORE 차선 추종), 판단기 주체 수용이 변경이다. 막힘 상태기계와 다섯 답은 그대로다.
- `R1` 과 주의점은 Fleet 이 차선 로봇의 위치를 알아야 쓸 수 있다. 위치는 D-395(Fleet 보조 위치추정)·D-257(천장 카메라 자세)에서 오고, 없으면 그 규칙·주의점은 쓰지 않는다(다음 단계로 넘어간다).
- OpenRouter 사용에 비용과 지연이 생긴다. 예산(`resolver_model_budget`)과 기한으로 묶는다.

## 검증

- 호스트: 단계 전이(규칙 → 모델 → 사람), 예산·기한, `stuck_id` 중복 맡기 금지, CORE 409 뒤 규칙 재사용 금지, 사람 답 우선, 모델 출력 형식 오류·저신뢰·시간초과 → `ESCALATE`, 주체 권한 범위, 주의점 만료·연결 끊김 시 푸는 주의점 폐기, `lane_gap_bridge_max_m` 상한.
- Gazebo: 두 로봇이 마주 본 `obstacle_ahead`(R1), 벽 앞 막힘(R2), 횡단보도 선 상실(`lane_gap_ahead` 있음·없음)을 재현한다. 모델 단계는 고정 응답 대역(stub)으로 시험한다.
- 실기: 사용자 승인 뒤 한 대씩. 모델 단계는 사이트 운영자 동의와 키 설정 뒤.

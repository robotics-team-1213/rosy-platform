## D-835 도메인 독립 지도 따라 그리기와 검토 가능한 선·영역 추출

**Status:** Accepted (2026-10-21)

### Context

D-825는 STL 참조와 평면 지도 편집을 정의했다. 사용자는 특정 지역·지도·업무에 종속되지 않는 기반을 우선하고, 지도 자료를 보면서 직접 그리거나 선을 추출하며 AI도 활용하도록 요청했다. STL 투영만으로는 이미지 도면을 편집하기 어렵고, 이미지의 경계가 곧 주행 도로라는 보장은 없다.

이번 결정은 입력·추출과 운영 지도의 경계를 확장한다. D-825의 저장·좌표계 결속·검토·활성화와 CORE 최종 실행 권한을 유지한다. Accepted는 설계 수락이며 새 추출 기능의 구현·배포·정확도 검증 완료를 뜻하지 않는다.

### Decision

1. **공통 도형을 먼저 만든다.** 공통 편집은 유한 2D 점·연속선·다각형, 좌표 변환과 편집 이력만 다룬다. 입력 형식·AI 모델·현장명·도로 정책·로봇 배치를 공통 기하에 넣지 않는다. Fleet는 확정한 도형에 목적지·도로·구역의 의미와 운영 제약을 부여한다.
2. **입력 어댑터와 추출기를 분리한다.** STL은 기존 투영 어댑터를 유지한다. 다음 입력은 PNG/JPEG 평면 도면이며, 벡터 자료는 실제 파일과 지원 범위를 검증한 뒤 원래 선을 보존하는 가져오기를 우선한다. 벡터가 있는 자료를 AI가 다시 그리게 하지 않는다. PDF·DXF·DWG 등 직접 지원을 이 결정만으로 약속하지 않는다.
3. **직접 그리기는 추출 없이도 동작한다.** 배경 위에서 클릭으로 연속선을 그리고 끝점 붙이기, 선 분할·연결, 꼭짓점 수정·삭제, 취소·다시 실행을 제공한다. 붙이기는 화면 배율에 맞는 명시적 허용 거리 안의 선택된 대상에만 적용하고, 단순 교차나 가까움으로 운영 그래프를 자동 연결하지 않는다. 같은 도구로 수동 도형과 추출 도형을 수정한다.
4. **추출 결과는 후보 초안이다.** 선택 범위의 선·윤곽선 추출과 AI의 점·영역 지시 기반 분할은 같은 후보 검토 흐름으로 연결한다. 마스크는 별도 윤곽 변환·단순화·검증을 거쳐 편집 가능한 도형이 된다. 후보를 원본 위에 미리 보여 주고 사용자가 일부를 선택·수정·확정한다. 확정 전에는 운영 지도를 바꾸지 않는다. 후보 확정도 초안 편집이며 활성화·이동 승인이 아니다.
5. **좌표와 출처를 추적한다.** 원본 내용 해시, 선택 범위, 원본 픽셀 좌표와 변환, 추출기/모델 및 설정 버전, 후보 결과, 사용자 수정·확정을 보존한다. 축척·원점·방향은 실측 기준으로 등록하고 픽셀과 미터를 구분한다. 사진의 원근·왜곡은 평면 도면과 같은 정확도로 취급하지 않으며 지원하는 교정과 검증 전에는 미교정 자료로 남긴다. 원본·좌표 기준 변경은 D-825의 새 map_id·검토 해제·현장 앵커 비계승 규칙을 따른다.
6. **AI는 교체 가능한 추출 구현이다.** 선명한 직선 도면은 일반 영상 처리를 기준선으로 평가하고, 복잡한 이미지의 영역 선택에는 AI 분할을 비교한다. 특정 모델·클라우드·GPU를 필수 기반으로 고정하지 않는다. 모델 점수가 있더라도 기하 정확도·통행 가능성·사용자 승인으로 해석하지 않는다. 모델 미설치·추론 실패 시 직접 편집을 계속 사용할 수 있다. 외부 추론 전송은 기본으로 켜지 않으며, 별도 전송·보존 정책과 명시적 선택 없이 원본을 외부로 보내지 않는다.
7. **비동기 결과가 편집을 덮어쓰지 않는다.** 추출 요청은 원본·좌표 등록·초안 revision에 결속한다. 입력 교체·재요청·취소·초안 변경 후 늦게 도착한 결과는 자동 반영하지 않는다. 후보 채택은 기존 편집 이력으로 되돌릴 수 있고, 저장·활성화는 기존 인증·named operator·CSRF·감사·CAS·busy 차단을 따른다.
8. **자료와 연산을 제한한다.** 파일 크기뿐 아니라 디코딩 후 픽셀·메모리·도형 수·실행 시간·동시 작업·보관량을 제한하고 취소·실패 시 임시 자원을 정리한다. 일부 도형을 몰래 버리거나 잘못된 파일을 빈 성공으로 반환하지 않는다. 구체적인 한도·DTO·API는 구현 계획에서 확정하고 공개 계약 변경 시 API reference와 schema를 함께 갱신한다. 이번 ADR은 새 API나 프로토콜 필드를 정의하지 않는다.

### Alternatives

| 선택지 | 판단 |
|---|---|
| 직접 편집만 확장 | 정확한 보정 수단으로 필요하지만 반복적인 선 입력을 줄이지 못한다. |
| AI가 운영 지도를 한 번에 생성 | 출처·좌표 오차·잘못된 연결을 검토하기 어려워 채택하지 않는다. |
| 직접 편집 + 일반 추출 + 선택적 AI 후보 | 공통 도형과 사람의 검토를 공유하고, 자료에 맞는 추출기를 비교할 수 있어 채택한다. |

### Consequences

구현 순서는 이미지 배경과 실측 좌표 등록·따라 그리기, 일반 선·윤곽 추출과 후보 검토, AI 영역 선택과 윤곽 변환 순이다. 기존 Console 지도 편집과 Fleet 지도 보관 경계에서 시작하며 새 최상위 part·독립 서비스·공통 플러그인 프레임워크를 선행 구축하지 않는다. AI 모델·실행 위치는 실제 자료의 정확도·지연·자원 측정으로 고른다.

수용 검증은 서로 다른 평면 도면에서 같은 편집 경로가 동작하는지, 알려진 길이·좌표의 오차와 선 누락·과검출·잘못된 연결을 함께 평가한다. 입력/원본 변경 중 늦은 결과, 취소, 후보 일부 선택·거절·undo/redo, 위조·과대 파일, 자원 제한, 기존 지도 저장·활성화 회귀와 모델 없는 환경을 검사한다. 합격 오차는 자료와 용도에 맞게 구현 계획에서 명시하고 실제 파일로 확인한다.

실측 오차·로봇 좌표 교정·실물 navigation·군집 주행·현장 인수는 별도 검증이다. AI 후보, 화면에서의 후보 확정, 브라우저 시험 통과를 그 증거로 대체하지 않는다.

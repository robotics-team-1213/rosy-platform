## D-166 과속 반응은 기록 전용이며, 자동 감속은 로봇 계약 확인과 판정 검증 후에만 상향한다

**Status:** Accepted (2026-09-22). 속도 평면의 과속 반응(D-C) 결정.

**Context:** 신호등 속도 평면의 루프는 "측정(Pi) → 판정(Fleet) → ① 표시 ② 로봇 감속"
이다. ① 은 구현된 scatter 로 되지만 ② 의 **로봇 감속 메커니즘은 로봇 계약(API Ref)에
아직 없다** — 저장소 규칙은 임의 REST 경로를 금지한다. 게다가 판정 자체가 검증 전이다
(AC-25 오차 ±10% 미실측). 이 상태에서 즉시 자동 감속을 연결하면 근거 없는 제동이 구동에
결합된다. 반면 이 제품의 컨셉(단속 카메라)은 사실상 "확인하고 기록하는 것"이라, v1
반응이 기록 전용인 것과 결이 같다. 관측은 이미 읽기 전용 평면으로 고정돼 있고(D-163),
Pi 배치·F1/F2 피드백 등급은 여전히 미결정이다.

**Decision:**

- 과속 확정(2-소스 충족)의 **1차 반응은 기록 전용**이다 — 이벤트·로그·콘솔 표시로 남긴다.
  기록은 낭비가 아니라 증거다: 과속 빈도·구간 통계가 이후 감속 루프 설계의 입력이 된다.
- **자동 감속(로봇 감속 명령)은 두 확인을 모두 통과한 뒤에만** 상향한다: (1) 로봇 계약
  API Ref 에 공식 속도 상한/감속 경로가 있는지 확인(D-18 — `schemas` 도 함께), (2) 판정이
  AC-25(오차 ±10%) 를 통과. 어느 쪽이든 미충족이면 반응은 기록 + 표시 + 운영자 개입까지다.
- 상향 전까지 로봇 계약에 없는 경로를 Fleet 이 만들지 않는다. 신호등 표시(all_red scatter)
  는 구현된 표시 장치의 몫으로 그대로 쓴다.
- 속도의 **2-소스 원칙**(오도메트리 1차 + 카메라 검증)은 상향 여부와 무관하게 유지된다 —
  단일 출처 속도로는 감속을 걸지 않는다.

**Alternatives:**

- 즉시 Fleet → 로봇 감속 명령(임의 REST) — 계약 없는 경로를 만드는 것 자체가 규칙 위반이고,
  미검증 판정이 곧바로 구동에 결합한다.
- 로봇 오도메트리 단독으로 로컬 감속 — 2-소스 원칙을 깨고, 바퀴 미끄럼(오도메트리 오차)
  상황에서 근거 없는 감속을 만든다.
- 반응을 아예 설계에서 빼기 — 기록조차 남지 않아 상향 판단의 증거(실제 과속 빈도·구간)를
  모을 수 없다.

**Consequences:** 과속해도 로봇은 스스로 줄지 않는다 — v1 안전은 "표시 + 운영자" 계층의
몫이며 운영자에게 이 범위를 알려야 한다. 반응이 기록 전용이므로 로봇 구동 코드는 속도
평면과 느슨히 결합된 채로 남고, 상향은 계약·AC 증거를 모은 뒤 새 결정으로 닫는다.

**Validation / Transition:** 기록 전용 반응은 과속 확정 시 로그·콘솔에 이벤트가 남는지로
확인한다. 상향은 AC-25 합격 + API Ref 경로 확인 기록을 근거로 재결정한다(그때 이 ADR 을
개정). 반응 자체의 성능 소유는 수용 계획 AC-25 다.

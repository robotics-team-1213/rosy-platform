## D-259 지도 키보드 조작 — 클릭 목표의 키보드 길을 놓는다

**Status:** Accepted (2026-09-26). 십자선 + 키 핸들러 + 시험 + 변이 증명 + G2 셀로 착지.

잇는 결정: [D-224](표면의 키보드 어휘) · D-92 제5항 · D-130.2 · concept 16 Law 4.

**Context (실측):**

대시보드 지도의 클릭 동작(초기 자세 찍기·목표 찍기, `map.js` 클릭 모드)은
포인터 전용이다. 같은 동작의 키보드 길은 없다. 웨이포인트·도크 목록의
이동 버튼은 진짜 `<ui-button>`이라 키보드가 닿지만, 임의 좌표 지정은
지도가 유일하다. 키보드만 쓰는 운용자(장갑·접근성)는 AMCL 초기 자세와
임의 목표를 지정할 수 없다.

같은 비판 pass에서 무혐의로 닫은 2건도 기록한다. (a) triage 문구 잘림:
`styles.css:370-381`이 의도로 못박았고(고정 프레임 D-201, 전문은 화면
낭독기가 읽음) — 결함이 아니다. (b) 역할 거울: 서버 강제
(`safety/stop`=viewer·`release`=admin·조작계=operator, `api/v1/*.py` 전수)와
UI disabled+사유 병기가 일치한다 — 어긋남 없음.

**Decision (초안):**

1. **지도에 키보드 십자선을 둔다.** canvas를 `tabindex="0"`으로 포커스
   가능하게 하고, 화살표로 셀 이동·Enter로 확정·Escape로 취소한다. 확정은
   현 클릭 모드(초기 자세/목표)와 같은 confirm·같은 API를 탄다. 새 입력
   칸(좌표 숫자 입력)은 만들지 않는다 — 십자선이 지도 문법을 지킨다.
2. **시각 언어는 그대로.** 십자선은 paper 색에 십자+원 모양으로 그린다.
   당초 `--pin`을 쓰려 했으나 공용 토큰에 없어서 열지 않고, 모양으로
   구분한다(로봇 삼각 vs 십자+원) — Law 1. 새 토큰 없음.
3. **파일럿 커밋 범위.** `map.js` 십자선 + 키 핸들러 + 포커스 링(전역 규약).
   전송·자격·confirm 불변이라 PINNED·적합 게이트에 손대지 않는다.
4. **D-224를 개정한다.** 약속 표에 "대시보드 지도: 화살표 이동·Enter 확정·
   Escape 취소" 1행을 더한다.

**Alternatives:** 좌표 숫자 입력칸안 — 새 입력 + 검증 + 문법 오염으로 파일럿
초과. 현상 유지안 — 키보드 운용자가 임의 목표를 못 찍는다. 웨이포인트로
우회안 — 저장된 점만 가리켜 임의 지정이 안 된다.

**Consequences (Accepted되고 파일럿이 끝나면):** 지도 3동작(보기·찍기·키보드)
이 닫힌다. 진단 지도는 PARKED라 범위 밖이다.

**Validation / Transition:** (1) `hmi/dashboard` + 브라우저 지도 경로 녹색,
(2) 키보드 전용 G2 셀 1개(십자선 이동→확정), (3) 변이 증명(핸들러 제거 →
키보드 무응답 적색). `ROSY ADR Log.md`에 `D-259 | 지도 키보드 조작 |
Proposed` 1행 추가가 이 초안의 착지다.

**References:** D-92, D-130, D-201, D-218, D-224, D-233, concept 16 §7.1.

## D-777 사람과 에이전트를 위한 간결한 문서와 단일 기준

**Status:** Accepted (2026-10-17, 사용자 요청. 공유·협업 문서부터 적용)

## 배경

README의 상세 설계가 시작 안내보다 앞에 있고, 협업 규칙과 GitHub 설정이 여러 문서에 반복된다. 독자는 작업 위치를 고르기 전에 많은 배경을 읽어야 하며, 규칙을 바꿀 때 수정할 곳도 늘어난다.

## 결정

### 읽는 순서

첫 화면에는 문서의 목적, 독자가 할 일, 다음 문서 링크를 둔다. 절차는 입력과 작업 위치, 행동, 완료 조건을 적고 실패했을 때 돌아갈 단계도 보여 준다. 배경과 상세 설계는 해당 주제를 맡은 문서로 연결한다.

사람과 에이전트는 같은 기준을 읽는다. 개인 클론과 실험실 공유 체크아웃은 명령을 보기 전에 구분한다. 커밋 식별자(SHA), 시험 결과, 미실행 검사는 기록에 명시한다.

### 그림과 문장

- 관계·분기·순서는 Mermaid로 설명한다. 그림 하나는 질문 하나를 다루고, 필요한 조건과 실패 경로를 표시한다. 단일 사실이나 명령은 짧은 문장·표·코드 블록으로 적는다.
- 그림의 노드와 화살표에는 역할과 행동을 쓴다. 현재 구현과 제안·목표를 구분하고, 그림 앞뒤에 핵심을 한 문장으로 적어 렌더링 없이도 뜻을 읽을 수 있게 한다.
- 한 문단은 한 가지 판단이나 행동을 설명한다. 반복된 소개·강조·맺음말을 덜어낸다. 줄 수를 맞추려고 필요한 조건이나 예외를 없애지 않는다.
- 내용과 구조를 먼저 확인하고 Humanizer·`ce-noslop`으로 문장을 다듬는다. 명령·경로·식별자·수치·안전 조건과 확실성은 유지한다.

### 기준 문서

| 문서 | 맡는 내용 |
|---|---|
| 루트 `README.md` | 제품 요약, 작업별 시작점, 핵심 계약과 상세 문서 링크 |
| `.github/CONTRIBUTING.md` | GitHub 기여자가 고를 시작 경로 |
| `docs/reference/team-guide.md` | 개인 클론 설정, 시험 PC 접속 불가 시 훅 예외, 작업 분담과 인수인계 |
| 루트 `AGENTS.md` | 실험실 공유 체크아웃의 명령·조건·예외 전문 |
| `docs/reference/shared-checkout.md` | 실험실 착수 순서와 주요 중단 조건, 전문으로 가는 링크 |
| `docs/reference/pr-pipeline.md` | 작성·독립 검토·게시·CI·병합 절차와 확인일을 붙인 GitHub 설정 |
| 모듈 `AGENTS.md` | 그 경로의 추가 계약과 작업 조건 |
| SRS·API reference·ADR | 제품 요구사항, 인터페이스, 결정의 이유 |

같은 규칙을 다른 문서에서 다시 정의하지 않는다. 요약은 기준 문서를 연결하고, 상세 내용을 옮기면 기존 링크·앵커를 보존하거나 소비자를 함께 고친다. 반복되는 파일 목록은 기존 소유 영역 표나 생성 색인을 연결한다.

생성 문서는 입력 자료와 생성기를 고친다. 기존 ADR, 날짜별 검증 기록, 이어 쓰는 Log는 당시의 결정을 보존하며 문체 정리 대상으로 삼지 않는다. 요구사항·API·안전 계약의 우선순위는 유지한다.

## 적용과 확인

```mermaid
flowchart LR
    facts["내용·구현 상태 확인"] --> home["기준 문서와 링크 정리"]
    home --> edit["필요한 그림·짧은 문장"]
    edit --> check["링크·계약 검사·독립 검토"]
    check -->|누락·충돌| home
```

개인 클론에서 시험 PC에 닿지 않는 기여자, 공유 체크아웃의 에이전트, 교대받은 게시 담당자가 각자 다음 행동과 완료 조건을 찾을 수 있어야 한다. 바꾼 링크와 앵커, 기존 문서 계약 시험, 생성 기록을 확인하고 최종 SHA를 독립 검토한다.

| 기존 결정 | 관계 |
|---|---|
| D-17·D-45 | 문서 책임과 기존 경로를 유지하고 안내 순서를 정리한다 |
| D-61 | 상태·작업 Log·생성 색인의 역할을 유지한다 |
| D-510 | 새 ADR 번호는 쓰기 직전에 선점한다 |
| D-761·D-762 | 워크트리 관문과 게시 권한·검토·시험 조건을 유지한다 |

## 결과

규칙 변경은 기준 문서에서 처리하고 진입 문서는 링크를 유지한다. 이번 적용은 공유·협업 문서부터 진행한다. 문서 정리로 기능 구현이나 장치 수용 상태를 바꾸지 않는다.

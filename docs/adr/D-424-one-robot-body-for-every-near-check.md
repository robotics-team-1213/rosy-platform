## D-424 몸 하나, 센서 여럿 — 모든 근접·정지 판정은 같은 URDF 몸과 같은 간격 규칙으로 한다

**Status:** Proposed (2026-10-02, 동작·설정 결정; 사용자 지시 2026-10-02 "교정 중에도, 평소에도 센서와 교정 절차가 가깝지 않은데 가깝다고 판단한다 — 10 cm 이상 여유가 있는데 전혀 움직이지 못한다. 막아라. 반경에서 시작해 로봇 자신의 논리로 따져라"). D-422(CORE 차선 추종 몸 기준 정지)의 몸·간격 규칙을 공유 모듈로 올려 CORE, sensing 게이트, PC 교정 도구가 같이 쓴다. D-400 정책 그림자는 여전히 강제하지 않는다 — 이 ADR 의 sensing 게이트 수정이 장치에서 확인되기 전에는 강제하지 않는다.

## 배경

판정마다 몸을 따로, 손으로 정한 숫자로 그렸다. 그래서 한쪽은 너무 엄격해 로봇이 얼고, 다른 쪽은 너무 느슨했다(local main af26a19d6 감사, 2026-10-02).

- **지금 실제로 얼게 하는 것(LIVE).**
  - (L) `tools/calibration/run_calibration.py`: 제자리 회전은 360° 어디든 0.20 m 안 반사가 하나라도 있으면 중단, 직진은 진행 방향 ±25° 에 0.20 m 안이면 중단. 반면 0.08 m 안 반사는 "자기 몸"으로 버렸다 — 너무 엄격하면서 위험하다(벽에 붙은 로봇은 회전을 허락받는다).
  - (M) `core_features/localization/mission.py`: 회전은 0.20 m 안 반사가 하나라도 있으면 거부, 조금 전진(nudge)은 앞 0.25 m 이상 + 보이지 않는 빔 30% 이하가 필요했다. 값은 dataclass 리터럴이고 설정 경로가 없었다.
- **잠복(LATENT, sensing 게이트).** D-400 worker(기본 꺼짐)와 옛 `robot.launch.py` 에서만 돈다.
  - (A) `lidar_guard.lidar_limits` 앞 정지 하한 = 외접원 0.076 + LiDAR 0.017 + 0.018 = 0.111 을 정면에 썼다. 실제 몸 앞끝은 base 에서 0.042 다. 기본 정지/해제 0.12/0.14.
  - (B)(C) 반사 없는 빔(inf/0/NaN)과 반사 없는 부채꼴 = 막힘. 해제는 느린 필터로.
  - (D) `lidar_can_rotate` 는 6 부채꼴이 모두 유한해야 했고, footprint_guard 가 꺼진 worker 기본에서 회전 반경은 0.076(URDF 회전 반경 0.0826 보다 작다 — 이것은 너무 느슨했다).
  - (E) footprint_guard 상자 반폭 0.077(+0.010) vs URDF 0.05655 → 옆 벽 3 cm 에 앞뒤 모두 얼었다.
  - (F) `command_gate`: 호 명령에서 v 만 잘리면 회전도 못 하고 완전 정지(`trajectory_changed`).
  - (G) 학습한 회전 envelope 가 만료되면 다시 교정할 때까지 `can_rotate` False 로 걸렸다(latch).
  - (I) 교정 순서의 `front_stop_m` 0.070, 상자 0.077 등 리터럴.
  - (J/K) 카메라 무효·없음·늦음·워밍업 → 모든 움직임 정지. 카메라 중앙 아래 비바닥 45% 판정은 카펫·테이프·그림자에 걸린다.
- **사용자 규칙.** 모든 기하 기본값은 URDF 공칭에서, 로봇별 교정이 다듬고, 운영자 overlay 가 이긴다. 손 숫자 금지(D-397).

## 결정

1. **몸은 하나다.** `core_common.robot_body.RobotBody`(stdlib, contracts foundation): 몸 앞끝 F, 뒤끝 R, 반폭 W, 제자리 회전 반경 ρ, 센서 위치(LiDAR x/y/정면각, 초음파 x)와 간격 정책(여유·지연·감속·히스테리시스·쓸기 여유). `from_geometry(geometry.yaml)` < 승인된 교정 기록(`resolve_body`: 지금은 `lidar_mount` 의 정면각) < 운영자 overlay. `PINKY_PRO` 는 geometry.yaml 부분집합이고 drift 시험이 묶는다.
   - CORE(D-422 `clearance._inside_body`, `_masked`, `LineFollowConfig.derived_stop_gap_m`)는 이 모듈의 `inside_body`·`masked`·`stop_gap_m` 를 쓴다(복제하지 않는다). sensing `sensing/body.py` 는 `PINKY_PRO` 에 위임한다. D-155 모듈 경계는 sensing 이 `core_common.robot_body` 를 가져오는 것을 허용 목록에 더한다(계약 기반이지 CORE 런타임이 아니다).
   - **우선순위가 실제로 걸리는 곳(리뷰 L1).** `resolve_body` 가 URDF 공칭 < 승인 기록 < overlay 를 한 곳에서 묶지만, 지금 각 소비자는 이렇게 받는다: 몸 기하는 URDF 공칭(`PINKY_PRO`; CORE 는 로봇 패키지 `core.yaml` `line_follow.body_*`, 운영자 overlay 가 이긴다). LiDAR 정면각 교정 기록은 각 소비자의 기존 경로가 적용한다(sensing TF·`calibrated_values`, `run_calibration` 의 `lidar_yaw_for`, CORE `lidar_mount`). 몸 윤곽 교정 종류는 아직 없어 sensing·교정 도구에 몸 overlay 경로는 미래 일이다.
2. **모든 센서는 base_footprint 점이 된다.** 몸 윤곽 안 반사는 자기 몸이다. `range_min` 보다 가까운 유한 반사도 장애물이다(가까운 반사는 간격을 줄이기만 한다). 반사 없는 빔은 inf(=비었음)도, 막힘도 아니다 — `range_min` 까지의 **UNKNOWN 띠**다.
   - UNKNOWN 은 그 띠 안으로의 **평행 이동**을 막는다. 앞쪽은 신선한 초음파가 **실제 메아리**(띠보다 먼 유한 거리)를 주고 그 띠가 원뿔(±15°) 안일 때만 풀린다. 메아리 없음(HC-SR04 시간 초과)은 아무것도 증명하지 못한다(비스듬한 면·흡수면) — 풀지 않는다. 원뿔 밖 모서리는 UNKNOWN 으로 남는다(리뷰 M6).
   - **회전(리뷰 M1/M2).** 보이는 점이 모두 ρ + 여유 밖이어야 하고, base 둘레 8 구간(45°) 각각에 반사가 하나 이상 있어야 한다(45° 넘게 비어 있으면 빈 공간이 아니라 못 본 것; 빈 스캔·유한 빔 하나는 회전 불가). UNKNOWN 띠가 몸 밖으로 나가 쓸기 고리를 지나면: 뒤쪽은 센서가 없어 결코 풀리지 않고, 앞쪽은 위 초음파 규칙으로만 풀린다. 교정 도구·위치 미션은 초음파가 없어 앞쪽 UNKNOWN 도 회전을 막는다. 호 명령 → (0, w) 도 이 판정이 통과할 때만이다.
3. **간격 규칙은 D-422 와 같다.** `g(v) = 0.02 + 0.15·v + v²/(2·0.5)`, 재출발 `+0.03`. 직진 띠 반폭은 W + 0.010, 띠 밖 옆 점은 세지 않는다. 회전은 base 기준 ρ + 0.010(sensing 게이트), 교정·위치 미션의 회전은 ρ + 0.02(D-422 몸 여유). 회전 반경은 ρ 아래로 내려가지 않는다(worker 기본 반경 0.076 → 0.0826; 이것은 **더 보수적**이 된다). "6 부채꼴 모두 유한" 조건은 뺀다.
4. **교정 도구(L).** 회전: 모든 base 점 > ρ + 0.02. 직진: 사전 점검에서 여유 ≥ 거리 + g(v)(LiDAR 환산 앞뒤 약 0.085 m). 모자라면 중단하지 않고 그 직진을 줄인다. 줄일 거리조차 없으면 잠시 기다렸다 다시 재고, 그래도 없으면 그 직진만 건너뛴다. 움직이는 중에 간격에 닿으면 그 단계만 끝낸다. 0.08 m 자기 반사 무시는 몸 윤곽 + self-mask 로 바꾼다. 늦거나 없는 스캔이면 여전히 중단한다.
5. **위치 미션(M).** 회전 시작은 base 기준 ρ + 0.03(약 0.113 m), 도는 동안 매 tick ρ + 0.01(약 0.093 m)로 다시 판정해 들어오면 `obstacle` 로 끝낸다(리뷰 H1; 장치 증거가 나올 때까지의 값). 몸 기하가 없는 로봇은 옛 0.20 규칙(도는 동안에도). nudge 정지는 g(v)(LiDAR 환산 약 0.085), 사전 점검은 정지 간격 + 최소 nudge 이동, 여유가 요청 거리보다 작으면 거리를 줄인다. 값은 `localization_mission:` 설정 절로 옮기고 옛 설정(절 없음)도 그대로 읽힌다.
6. **sensing 게이트.** (A) 정지 간격은 실제 `safety_max_linear` 로 유도한다(리뷰 M3). 늦은 앞뒤 거리는 inf 가 아니라 NaN(막힘)이다 — inf 는 이제 '띠가 비었다'(리뷰 M4). (F) 장애물·뒤 막힘으로 v 가 잘리고 회전이 결정 2 의 회전 판정을 통과하면 (0, w) 를 보낸다(낭떠러지·기울어짐은 여전히 정지). (G) 만료된 envelope 는 max(ρ, 마지막 정상 envelope 반경)으로 돌아가고 걸리지 않는다(리뷰 M8; 살아 있는 교정이 envelope 를 요구하는데 없을 때만 거부). D-424 이전 반경(0.076·0.083)으로 기록된 프로필은 1 mm 허용·ρ 로 들어 올려 그대로 쓴다(리뷰 M7). (J/K) 카메라: `camera_observation_unavailable`(무효·없음·늦음·워밍업)은 앞 속도 제한(×0.5)만, `camera_obstacle_unranged` 는 **앞으로 가는 것만** 멈춘다(스캔 평면 아래 낮은 물체; 리뷰 H2). 카메라는 회전·후진을 결코 막지 않는다. (A/D/E/I) 는 `RobotBody` 를 쓴다. `core_common` 이 없으면 control 은 import 에서 분명한 오류로 멈춘다(리터럴 대체 없음; 리뷰 L4).
7. **보수적으로 남는 것.** 늦거나 없는 스캔 → 정지. 회전은 ρ 아래로 판정하지 않는다. UNKNOWN 띠는 실제 초음파 메아리 없이 평행 이동으로 들어가지 않는다. 감속도 0.5 m/s² 는 실측 전까지 그대로. D-400 은 강제하지 않는다.
8. **교정 도구 보고(리뷰 M5).** `--self-mask name=FROM:TO:REACH[/...]`(로봇의 `line_follow.lidar_self_mask` 형식). 건너뛴·줄인·일찍 끝난 단계는 결과(`adjusted_steps`)와 반복 판정에 남고, 움직이는 단계를 모두 건너뛴 실행은 성공이 아니다.

## Pinky Pro 숫자 (URDF 공칭)

- F 0.04205, R −0.076, W 0.05655, ρ 0.08257, LiDAR x −0.017 → LiDAR 에서 앞 0.05905, 뒤 0.059.
- sensing 게이트 0.014 m/s: 정지 g = 0.0223 → LiDAR 환산 앞 약 0.081(옛 0.12), 해제 약 0.111(옛 0.14). 뒤도 약 0.081.
- footprint 띠 반폭 W + 0.010 = 0.0666(옛 0.087). 회전 base 기준 ρ + 0.010 = 0.0926.
- 교정 0.03 m/s: g = 0.0254 → LiDAR 환산 약 0.085. 교정 회전 ρ + 0.02 = 0.1026, 미션 회전 시작 ρ + 0.03 = 0.1126 / 도는 중 정지 ρ + 0.01 = 0.0926(옛: 0.20 m 안 반사 하나면 중단).
- 게이트 최고 속도가 0.1 m/s 면 g = 0.045 → LiDAR 환산 약 0.104.
- 예: 옆 벽이 LiDAR 에서 0.13 m(base 약 0.131)면 회전 가능. 정면 0.07 m 반사는 base 0.053 — 회전 거부(옛 도구는 무시했다). 앞 0.30 m 에서 0.24 m 직진은 0.2155 m 로 줄여 수행.

## 결과

- 10 cm 이상 실제 여유가 있으면 어떤 근접 판정도 로봇을 얼리지 않는다. 회전 반경 판정만은 이전보다 엄격해진다.
- 판정이 같은 숫자를 말한다. 몸 기하·센서 위치를 바꿀 곳은 geometry.yaml(URDF 생성) 하나다.
- 남는 일: Gazebo·실물에서 UNKNOWN 띠(실제 C1 `range_min`, 반사 없는 빔 빈도), 카메라 제한 계수, 0.5 m/s² 감속, (N) `space_speed.py` 죽은 코드와 (O) `road_behaviour` 미연결은 이 ADR 범위 밖으로 둔다.

## 검증

- 호스트 시험: 결정마다 옛 코드에서 실패하는 시험(보고서 참조).
- **장치에서 잴 것.** C1 드라이버가 0.15 m(`range_min`)보다 가까운 반사를 유한값으로 내는지 inf 로 내는지. inf 로 낸다면 반사 없는 빔이 잦고, 결정 2 의 UNKNOWN 규칙 때문에 뒤로 가기·회전이 자주 막힐 수 있다 — 그 빈도와 초음파가 앞 띠를 얼마나 덮는지 Gazebo·실물에서 확인한다. 미션 회전 여유(0.03/0.01)와 카메라 제한 계수(0.5)도 장치 증거로 다시 정한다.

## D-932 공급암 S 현장은 로컬 main에 착지한 리비전 하나로만 실행한다

**Status:** Accepted (2026-10-30). 현장 세션 코드의 main 통합(`feat/omx-field-session-sync`)과 현장 재배치는 진행 중이다.

### Context

2026-10-30에 main 코드로 감독 시험을 시작하려 했다. D-911 게이트가 두 번 `state_unavailable`로 막았다. 원인은 현장의 팔 세션이 main에 없는 리비전(`44bdc20883`, 10-26~28 커밋 25개, 약 1,277줄)으로 돌고 있었기 때문이다. 그 세션은 `operating_context`를 보내지 않는다.

main 코드로 세션을 띄우자 모터 설정(`caps.json`)의 `p` 키를 거부했다. 현장에서만 쓰던 기능이 main에는 없었다.

- 서보 프로파일
- 상태 패킷 재확인
- 터치 높이 측정

같은 시기 현장 복사본에는 파일을 손으로 덮어쓴 흔적이 있었고, CRLF 때문에 패치가 거부되기도 했다. 이 상태에서는 다른 PC나 다른 팔에서 같은 결과를 낼 수 없다.

### Decision

1. 현장에서 쓰는 코드는 로컬 main에 착지한 커밋 하나에서 `git archive`로 만든다. 디렉터리 이름과 `REVISION` 파일에 SHA를 남긴다(`omx-tools-<sha>`). 현장 복사본의 파일을 손으로 고치지 않는다.
2. 세션, 판정, 운반 스크립트는 모두 같은 리비전을 쓴다. 세션 시작 스크립트도 그 리비전의 `record_session.py`를 가리킨다.
3. 현장에서 시험한 변경은 main으로 착지한 뒤에만 다음 시험에 쓴다. 착지하지 않은 브랜치를 현장에 둘 때는 실험이라고 표시하고, 끝나면 착지하거나 버린다.
4. 현장 설정(카메라 장치, 사이트, 운영 조건, 장치별 프로파일)은 코드와 따로 현장 디렉터리에 둔다. 공개 저장소에는 넣지 않는다.

### Consequences

- 다른 PC에서도 같은 SHA를 배치하면 같은 판정과 같은 세션이 나온다. 바뀌는 것은 현장 설정뿐이다.
- 현장에서 급히 고치는 일이 느려진다. 대신 고친 것이 사라지지 않는다.
- 이미 현장에만 있는 커밋은 한 번 통합해야 한다(진행 중). 통합 전까지 main으로는 감독 시험 세션을 띄울 수 없다.
- 관련: D-868(로컬 main 먼저 착지), D-911(작업 범위 게이트).

## D-471 같은 네트워크 무인증 연결 요청은 기각하고, 같은 망 무코드 접속은 개발 연결 모드로만 제공한다

**Status:** Accepted (2026-10-06, 사용자 요청 기록 + 방향 결정. 구현 변경 없음)

**번호:** 없음 — 신규.

잇는 결정: [D-193](D-193-login-code-and-credential-lifecycle.md)(로그인 코드·자격 수명) · [D-341](D-341-overhead-console-approved-pairing.md)(콘솔 승인 페어링) · [D-432](D-432-common-discovery-and-development-link-mode.md)(공통 발견·개발 연결 모드) · [D-456](D-456-lan-receiver-approval-and-persistent-pairing.md)(LAN 수신 승인·지속 페어링).

### Context

2026-10-06 사용자 요청: "같은 네트워크에선 인증이 필요없도록 해." 이날 하루 현장 태블릿에서 페어링·승인·세션 절차가 여러 번 걸렸다(피어 승인 대기, 인증서 지문 확인, 세션 상한 소진 잠김 — 모두 그날 수리 또는 완화됨: D-471 작성 시점 기준 세션 재사용·상한 8회·운영자 코드 보여주기 착지).

요청의 실질적 목표는 "같은 LAN 안에서 코드 입력 없이 바로 조종 화면에 들어가는 것"이다.

### Decision

1. **전면 무인증(LAN 안 모든 요청 면제)은 만들지 않는다.** 같은 Wi-Fi에 붙은 누구나 로봇을 조종·관리할 수 있는 상태가 되며, 이는 D-193이 제거한 "공용 개발 토큰이 LAN에서 그대로 통하는" 상태로의 회귀다. CORE SRS·API Ref·ADR의 보안 계약과 충돌한다.
2. **같은 망 무코드 접속의 정답은 D-432의 개발 연결 모드다.** 로봇이 `network.connection_mode: development` 와 `ROSY_DEPLOYMENT=development` 를 함께 명시한 경우에만 `/api/v1/auth/development-session` 이 코드 없는 1시간 운영자 세션을 발급하고, Pilot 앱은 이미 이 경로를 지원한다("개발 즉시 접속"). 이는 배포 담당자의 명시적 선택이고, 발견 실패·인증 실패가 자동으로 개발 모드로 강등하지 않는다(D-432 4항).
3. **현장(bench) 로봇은 `paired`를 유지한다.** 2026-10-06 확인: rosy_60(rosy-pinky-8kcn)의 `GET /api/v1/auth/connection` → `{"mode":"paired"}`. 무코드를 원하는 자리에서는 그 로봇을 개발 배포로 명시적으로 전환한다(전환은 별도 작업·검증).
4. 이 결정은 요청 기록과 방향 확정이며, 코드·계약 변경을 수반하지 않는다.

### Alternatives

- **평문 LAN이므로 무인증도 감수.** 기각 — D-193 §10의 위협 모델(같은 WPA2-PSK를 아는 사람은 모든 트래픽을 볼 수 있음)이 그대로 적용되고, 무인증은 여기에 "조종 권한 즉시 획득"까지 더한다.
- **페어링 1회 후 영구 신뢰.** 부분 채택 — 피어 승인의 "승인 유지"(persistent) 경로가 이미 이 역할을 하며, 승인 회수·만료는 CORE가 계속 소유한다.

### Consequences

- 같은 망 무코드 접속이 필요한 벤치·개발 자리는 개발 연결 모드로 명시 전환한다(운영 프로필은 자동 상속하지 않는다, D-432).
- 현장 로봇의 무인증 요청은 이 ADR을 인용해 거절한다.
- 태블릿 경험 부담은 2026-10-06의 세션 재사용(자연 만료까지 재발급 없음)·승인 유지·운영자 코드 보여주기로 이미 낮췄다.

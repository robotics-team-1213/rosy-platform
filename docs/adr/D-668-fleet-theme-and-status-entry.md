# D-668 Fleet 단일 테마 버튼과 접속·알림 진입점

**Status:** Accepted (2026-10-12).

**Context:** D-658의 공용 헤더에서 접속 설정과 알림은 서로 다른 버튼이고 화면 테마는 접힌 영역의 세 버튼이었다. 사용자에게 반복 조작을 찾게 하고 같은 헤더의 정보를 흩어 놓았다.

**Decision:**

1. 우측 actions 영역에 테마 버튼 하나를 둔다. 기존 `RosyTheme.choices/get/set`을 사용해 어둡게 → 밝게 → 시스템 순환한다. 현재 선호의 아이콘을 표시하고 접근성 이름·공용 툴팁에 현재 값과 다음 클릭 결과를 설명한다. 표시 선호는 권한과 무관하며 로그아웃·보기 전용에서도 사용 가능하다.
2. status 영역은 **하나의 상태 센터 버튼**이다. 내부에 `connect` 아이콘과 연결 비율, `notification` 아이콘과 미확인 메시지 수, 활성 개발 모드의 짧은 `개발` 경고를 넣는다. 이 셋은 “지금 이 관제를 어떤 조건에서 사용할 수 있는가”라는 한 질문에 답하고 같은 상세 영역으로 이어지므로 한 누름 영역으로 묶는다. 연결됨은 실행 가능, 미확인 메시지는 미해결 사건을 의미하지 않는다. 다른 문서는 메시지 수를 추정하지 않고 `—`로 조회 전임을 표현한다. 권한·로그인·메시지 이동은 상세에 둔다.
3. 공용 `fleet-header.js`만 클릭으로 접힘을 전환한다. Console connection view는 인증 안내의 자동 열기·닫기와 로그인 입력 포커스만 소유한다. Escape로 닫으면 진입점으로 포커스를 되돌린다.
4. 요약을 여는 것은 읽음이나 개입 해소가 아니다. 기존 `rosy:inbox` 이벤트로 실제 메시지 창을 선택했을 때 기존 읽음 처리가 적용된다. 다른 문서의 `/console?inbox=1` 이동을 보존한다. 서버 API·명령·인증·CORE/OMX의 실행 권한은 변경하지 않는다.
5. 아이콘은 카탈로그의 의미 그대로 사용한다. `connect`는 연결, `notification`은 메시지, 달·해·모니터는 테마 선호, 팔각형은 정지다. 개발 모드에는 연결고리 아이콘을 재사용하지 않는다. 연결 수·알림 수·개발 경고·서버 없음과 비상 정지 동사는 보이고 반복 조작의 명칭·상세 이유는 접근성 이름과 공용 툴팁으로 설명한다.
6. 상태 센터 안의 값은 공용 `ui-tag variant="inline"`으로 표현한다. 이 변형은 배지 외곽선·채움을 제거하고 숫자·상태 의미를 유지한다. 위험은 읽을 수 있는 중립 글자와 위험색 점으로, 주의는 기존 주의 글자로 표현한다. 새 색·크기 토큰이나 화면별 덧칠을 만들지 않고 `/styleguide`에 같은 견본을 제공한다.
7. 네 문서는 같은 마크업·공용 버튼·아이콘·토큰을 사용한다. desktop은 `제품·현장 | 상태 센터 | 테마 | 비상 정지`, mobile은 `제품·현장 | 비상 정지`와 `상태 센터 | 테마` 두 줄이다. 센터 내부 간격은 작고 그룹 사이 간격은 넓다. 비상 정지와 조작의 48px 규격·권한을 유지한다. 이는 D-658의 상태와 조작 분리를 상태 요약을 여는 단일 조작으로 갱신하며, D-658 §3의 접속 상세 자동 펼침은 유지한다.

**Validation:** 정적 동일성 및 권한 선택자 시험, 테마 전체 순환·저장·재접속, 한 클릭에 한 번 열기·닫기, Escape 포커스, 요약 열기와 메시지 읽음의 구분, 네 문서의 모바일/데스크톱 Chromium 측정으로 확인한다. 실제 장치 명령 시험은 이 표시 변경의 검증에 포함하지 않는다.

**Consequences:** 상태를 개별 배지·조작처럼 나란히 늘어놓지 않는다. 테마는 관제 상태를 바꾸지 않는 개인 표시 선호라 별도이고, 비상 정지는 즉시 위험 조작이라 별도다. 개발 연결 경고와 안전 조작의 접근 단계는 늘어나지 않는다. 기존 인증·알림·설정 경로를 재사용하며 새로운 서비스나 테마 설정 원장을 만들지 않는다. 크기 검사 통과로 실제 UX 수용을 대신하지 않는다.

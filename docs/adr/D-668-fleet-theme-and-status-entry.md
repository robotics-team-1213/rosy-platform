# D-668 Fleet 단일 테마 버튼과 접속·알림 진입점

**Status:** Accepted (2026-10-12).

**Context:** D-658의 공용 헤더에서 접속 설정과 알림은 서로 다른 버튼이고 화면 테마는 접힌 영역의 세 버튼이었다. 사용자에게 반복 조작을 찾게 하고 같은 헤더의 정보를 흩어 놓았다.

**Decision:**

1. 우측 actions 영역에 테마 버튼 하나를 둔다. 기존 `RosyTheme.choices/get/set`을 사용해 어둡게 → 밝게 → 시스템 순환한다. 현재 선호의 아이콘을 표시하고 접근성 이름·공용 툴팁에 현재 값과 다음 클릭 결과를 설명한다. 표시 선호는 권한과 무관하며 로그아웃·보기 전용에서도 사용 가능하다.
2. status 영역의 접속·알림 버튼 하나가 접속 요약 영역을 연다. 연결 수와 개발 모드 경고는 접힘 밖에 남고, 상세 권한·로그인·메시지 이동은 접힘 안에 모은다. Console만 가진 미확인 메시지 수는 이 진입점에도 표시한다. 다른 문서는 읽지 않은 메시지 수를 추정하지 않는다.
3. 공용 `fleet-header.js`만 클릭으로 접힘을 전환한다. Console connection view는 인증 안내의 자동 열기·닫기와 로그인 입력 포커스만 소유한다. Escape로 닫으면 진입점으로 포커스를 되돌린다.
4. 요약을 여는 것은 읽음이나 개입 해소가 아니다. 기존 `rosy:inbox` 이벤트로 실제 메시지 창을 선택했을 때 기존 읽음 처리가 적용된다. 다른 문서의 `/console?inbox=1` 이동을 보존한다. 서버 API·명령·인증·CORE/OMX의 실행 권한은 변경하지 않는다.
5. 네 문서는 같은 마크업·공용 버튼·아이콘·토큰을 사용한다. identity/status/actions/safety 영역과 비상 정지의 48px 규격·권한 규칙을 유지한다. 320px에서도 테마·접속·비상 정지와 로그인 입력에 접근할 수 있어야 한다.

**Validation:** 정적 동일성 및 권한 선택자 시험, 테마 전체 순환·저장·재접속, 한 클릭에 한 번 열기·닫기, Escape 포커스, 요약 열기와 메시지 읽음의 구분, 네 문서의 모바일/데스크톱 Chromium 측정으로 확인한다. 실제 장치 명령 시험은 이 표시 변경의 검증에 포함하지 않는다.

**Consequences:** 헤더에는 테마 한 버튼과 접속·알림 한 진입점이 남는다. 개발 연결 경고와 안전 조작은 접근 단계가 늘어나지 않는다. 기존 인증·알림·설정 경로를 재사용하며 새로운 서비스나 테마 설정 원장을 만들지 않는다.

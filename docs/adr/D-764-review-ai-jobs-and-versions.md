## D-764 사람·AI 검수 실행과 저장 버전 조회

**Status:** Accepted (2026-10-14)

### Context

D-755 공동 검수 화면은 저장된 초안과 의견을 읽지만 모델 재실행과 전체 이력 조회를
연결해야 한다. AI 요청자와 사람 승인자를 구분하고, 실행 중 수정된 입력에 과거 결과를
적용하지 않아야 한다. 이 결정은 구현 계약이며 운영 모델 실행·학습 품질 수용의 증거가 아니다.

### Decision

모델 PC 검수 앱에 기존 Qwen 객체 초안, Qwen/SAM 미검수 픽셀 보완, VLM 마스크 확인을
단일 사진 작업으로 연결한다. 별도 범용 작업 스케줄러나 외부 inference provider를 만들지 않는다.
관리자의 private 설정은 workspace ID, 절대 Python 경로, 고정 모델 digest와 선택적 SAM
체크포인트·SHA256만 지정한다. 모델 이름·loopback 주소·worker 코드는 기존 adapter를 따른다.
브라우저는 명령·서버 경로·모델 주소를 지정할 수 없다. 미설정·의미 체계 불일치는 이유와 함께 차단한다.

작업은 queued/running/succeeded/failed/cancelled/stale 상태와 요청자, 시각, 입력 revision,
이미지·마스크·클래스 해시, 모델 식별자를 SQLite에 보존한다. 작업공간당 worker 하나만 허용한다.
재시작된 미완료 작업은 실패로 남기며 자동 재실행하지 않는다. 취소는 소유 subprocess와
결과 등록을 중단하지만 이미 Ollama가 받은 연산의 즉시 종료를 보장하지 않는다.

협업 모드의 읽기는 view, 생성·취소는 edit 권한을 검사한다. 타인의 작업 취소는 manage도 요구한다.
결과 등록 직전 요청자의 edit 권한과 입력 revision·해시·상태를 재검사한다. 권한 취소,
입력 변경, 실패·취소에서는 후보를 등록하지 않는다. 비협업 모드의 요청자는
local-unidentified로 기록하며 인증된 사람 이름으로 표시하지 않는다.

결과는 미적용 후보 또는 advisory 의견이다. 사람 라벨·승인·학습 admission을 변경하지 않는다.
보완할 픽셀이 0이면 완료 상태를 표시하되 새 후보가 생겼다고 표현하지 않는다.
재시도는 현재 저장 revision을 기준으로 새 작업을 만들며 이전 실패 기록을 보존한다.
화면은 실행 상태·요청자·모델과 결과 조회를 제공한다. 완료 알림 때문에 미저장 편집을 버리거나
새 후보를 자동 적용하지 않는다. 기존 기능 검색(Ctrl+K)과 키보드 접근을 재사용한다.

객체·픽셀 이력을 version 내림차순으로 페이지 조회하고, 선택한 저장 버전을 읽기 전용으로
표시한다. 현재 편집본과 과거 승인본을 구분한다. 마스크는 보존된 불변 파일의 해시·경로·크기·
클래스를 검사한다. 과거 스냅샷이나 작업자 기록이 없으면 미보존·미기록으로 표시하며 추정하지 않는다.

경로와 요청 필드는 API reference의 D-764 부록을 따른다. CORE `/api/v1` 및
`core_common.protocol.schemas`, ROS, CORE/OMX 실행 권한은 바뀌지 않는다.
D-427/D-429 책임 경계, D-430/D-516 모델 PC 역할, D-663 픽셀 의미 체계를 유지한다.

### Validation

worker adapter 통합 시험, 입력 변경·취소·재시작·권한 취소·위조 요청 차단, 후보/의견
영속 readback, 전체 이력 페이지·스냅샷 검증을 원격 pytest로 확인한다. 복사 자료의 실제
브라우저에서 요청·상태·후보 조회·이전 버전·키보드와 빈 상태를 확인한다.
모의 모델 응답의 연결 시험과 실제 GPU 모델 결과, 배포, 사람 정답 기반 품질은 별도로 보고한다.

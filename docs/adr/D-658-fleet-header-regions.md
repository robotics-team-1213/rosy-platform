# D-658 Fleet 공용 헤더는 네 역할 영역과 접속 상세를 분리한다

**Status:** Accepted (2026-10-11)

### Context

사용자는 공용 헤더부터 영역을 나누어 구조화하도록 요청했다. D-641의 화면 위계와 D-654의 브랜드를 유지하면서 네 Fleet 문서의 공통 헤더를 정리한다.

### Decision

1. 왼쪽 제품·현장 정체성, 연결·권한 상태, 알림·접속 조작, 오른쪽 비상정지의 네 접근성 그룹을 사용한다. 상태를 버튼처럼 표현하지 않고 조작과 분리한다.
2. 넓은 화면은 `identity | status | actions | safety`, 좁은 화면은 `identity | safety`와 `status | actions` 두 줄이다. 문서 이동은 헤더 아래 기존 탐색 영역, 관측·개입은 본문과 오른쪽 문맥 패널, 시각·진단은 푸터가 담당한다.
3. 접속·테마 상세는 네 영역 아래 펼침 영역이다. 화면 폭에 관계없이 설정 아이콘으로 연다. 이는 D-359의 90rem 이상 자동 노출 규칙을 대체한다. 접속이 필요하면 기존 컨트롤러가 자동으로 펼치는 동작은 유지한다.
4. 알림·설정은 아이콘과 툴팁·접근성 이름으로 표현한다. 제품 이름, 연결·권한 상태와 비상정지 동사는 보인다. 비상정지는 기존 48px 높이·14px 글자·12px 좌우 여백을 유지한다. 모든 간격·크기·색은 기존 공용 토큰을 사용한다.
5. 네 문서의 정적 마크업과 공용 CSS·컨트롤러를 사용한다. 비상정지를 동적 로딩 뒤로 옮기지 않는다. API, 명령 권한, CORE의 안전 판단은 바꾸지 않는다.
6. 좁은 화면의 상태 그룹은 두 줄 높이를 확보한다. 권한과 개발 배지는 같은 상태 그룹 안에서 줄바꿈할 수 있으며 개발 배지의 등장·소멸이 헤더를 흔들지 않는다. 로그인·재접속 시험도 접속 상세를 명시적으로 열어 사용한다.
7. 로그인한 계정 이름·로그아웃은 접속 상세에 둔다. D-519의 쿠키 세션과 로그아웃 기능은 유지하고 헤더의 상태 그룹에 조작 버튼을 넣지 않는다. 접힌 상태에서도 권한 배지의 title에 계정과 권한이 남는다.

### Verification

네 문서의 동일 마크업, 그룹 소속, 320–1920px 실제 Chromium 배치, 겹침·가로 넘침·정지 위치, 접속 거부와 상세 펼침을 원격 시험한다. 소스 회귀, CI, 설치본과 실물 수용은 별도 증거다.

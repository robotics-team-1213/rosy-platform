## D-521 Rosy Cam은 원격 G4/G5 입회 시야를 제공하고 현장 물리 차단 담당자를 대체하지 않는다

**Status:** Proposed (2026-10-08). 문서 계약이며 장치 G4/G5 수용이나 주행 허가가 아니다.

### Context

2026-10-08 현장 조회에서 `rosy_26`과 `rosy_60`은 모두 `motor` 모드이고,
`rosy-navigation`은 꺼져 있으며 G4 승인 기록과 장치 지도가 없다. 사이트
`ceiling_north` Rosy Cam 프레임은 수신된다. 사용자는 이 영상을 입회에 활용해
두 로봇을 ROSY Web에서 제어할 수 있도록 관련 결정을 조정해 달라고 요청했다.
현재 현장 물리 차단 담당자는 없다. 따라서 이번 회차의 G4/G5는 HOLD다.
D-314는 G4 schema v2의 기록 작업자 한 명만 요구하지만 물리 전원 차단의
접근성은 현장 운용 조건으로 남겼다. D-512의 카메라 사전 점검은 일반 장치
시험의 원격 관찰을 허용하며 G4 승인과 G5 지도 수용을 대신하지 않는다.

### Decision

1. G4/G5의 명령·관찰 담당자는 원격에 있을 수 있다. Rosy Cam의 실제 최신
   프레임과 CORE 상태·오도메트리·시험 원시 파일을 같은 장치·릴리스·세션으로
   대조한다. 로봇 ID가 영상에서 확정되지 않거나 로봇·바퀴·시험 구역·장애물·
   케이블·물리 차단 담당자의 위치가 보이지 않으면 시작하지 않는다. 카메라
   영상은 물리 정지 거리와 시간을 재는 계측값이 아니다.
2. 움직이는 동안 현장에는 독립 전원 차단 수단을 즉시 조작할 수 있는 담당자가
   로봇 곁에 있어야 한다. 원격 관찰자와 현장 담당자는 시작·중단 신호를
   확인한다. Rosy Cam, Fleet 정지, 원격 E-Stop, 소프트웨어 watchdog은
   이 역할을 대체하지 않는다. 담당자가 없거나 연결이 끊기면 G4/G5는 HOLD다.
3. 매 시험 전과 시험 중에 source, 프레임 순서, 수신 시각·나이를 확인한다.
   프레임이 멈추거나 오래되거나 가려지거나 잘못된 로봇을 보여 주면 새 명령을
   내리지 않고 시험을 중단한다. 원격 정지는 최선으로 요청하고 현장 담당자가
   물리 차단과 실제 정지를 확인한다. 정지 결과가 불명확하면 재개하지 않는다.
4. 기존 G4 schema v2의 다섯 원시 odom 시험·0.65초 정지·10 cm 이동 한도,
   `mapping_approval.py` 봉인과 `rosy-navigation.service` 기동 검사는 유지한다.
   원격 시야는 증거를 보강할 뿐 승인 마커를 생성하거나 `motor`를 `hardware`로
   바꾸는 근거가 되지 않는다. G5는 별도 실물 SLAM/MCAP·지도 YAML/PGM·최종
   정지 증거가 필요하다. 현장 영상·담당자·원시 계측의 출처와 시각은 비공개
   현장 증거에 남기고 공개 저장소에는 장치 주소나 영상을 넣지 않는다.

### Consequences and verification

`pinky-pro-first-device-runbook.md`, `pinky-pro-attended-session-runbook.md`,
`pinky-native-mapping-recovery.md`에 원격 관찰과 현장 차단의 역할을 분명히 한다.
Rosy Cam 수신만으로 G4/G5를 GO로 바꾸지 않는다. 첫 DEVICE 세션에서 두 로봇
각각 신원·연속 영상·원시 계측·현장 차단·복구를 확인한다. 실패하거나 현장
담당자가 없으면 현재 `motor` 상태와 목적지 주행 비활성을 유지한다.

## D-521 Rosy Cam 원격 입회로 G4/G5를 진행하고 별도 현장 담당자를 필수로 두지 않는다

**Status:** Accepted (2026-10-08, 사용자 결정). 절차 결정이며 장치 G4/G5 수용이나 주행 완료를 뜻하지 않는다.

### Context

2026-10-08 현장 조회에서 `rosy_26`과 `rosy_60`은 모두 `motor` 모드이고,
`rosy-navigation`은 꺼져 있으며 G4 승인 기록과 장치 지도가 없다. 사이트
`ceiling_north` Rosy Cam 프레임은 수신된다. 사용자는 이 영상을 입회에 활용해
두 로봇을 ROSY Web에서 제어할 수 있도록 관련 결정을 조정해 달라고 요청했다.
사용자는 현장 담당자 없이 Rosy Cam으로 입회하고 기존 정지 장치를 사용해
지금 진행하도록 명시했다. D-314의 G4 schema v2는 기록 작업자 한 명만
요구하며 별도 안전 담당자 필드를 제거했다. 첫 장치 런북의 두 사람 문구와
D-314의 현장 물리 차단 접근성은 원격 단독 운용과 충돌한다. D-512는 이미
카메라 사전 점검과 CORE의 정지 경로를 사용하는 에이전트 실기 시험을 정했다.

### Decision

1. G4 schema v2의 한 명의 기록 작업자가 원격에서 명령·관찰한다. 별도 현장
   담당자나 물리 전원 차단 접근성을 필수 사전 조건으로 두지 않는다. 이는
   D-314 결정 4의 접근성 조건을 원격 schema v2 세션에 한해 바꾼다. 현장
   사람이 있으면 물리 차단을 추가 수단으로 사용하지만, 없다는 이유만으로
   승인 입력을 거절하지 않는다. schema v1의 두 작업자·차단 조건은 유지한다.
2. 시작 전 같은 `robot_id`·호스트명·릴리스·boot ID를 묶고, Rosy Cam의 실제
   최신 프레임과 로봇 전면 영상·LiDAR·CORE 상태를 대조한다. 대상 로봇의
   신원이나 계획한 방향의 몸체 여유·케이블·시험 구역이 불확실하면 움직이지
   않는다. ROSY Web/Fleet의 정지 요청, CORE E-Stop, 300 ms 원격조종 감시,
   버튼 해제 0 명령과 읽기 응답을 사전 점검한다. 한 경로의 응답만으로 다른
   정지 경로가 동작한다고 추정하지 않는다.
3. 매 시험 전과 시험 중에 source, 프레임 순서, 수신 시각·나이를 확인한다.
   프레임이 멈추거나 오래되거나 가려지거나 잘못된 로봇을 보여 주면 새 명령을
   내리지 않고 정지 요청 후 CORE 속도·상태와 다음 영상을 다시 읽는다. 정지
   결과가 불명확하면 재개하지 않는다. 영상은 물리 정지 거리·시간 계측값이 아니다.
4. 기존 G4 schema v2의 다섯 원시 odom 시험·0.65초 정지·10 cm 이동 한도,
   `mapping_approval.py` 봉인과 `rosy-navigation.service` 기동 검사는 유지한다.
   원격 시야는 증거를 보강할 뿐 승인 마커를 생성하거나 `motor`를 `hardware`로
   바꾸는 근거가 되지 않는다. G5는 별도 실물 SLAM/MCAP·지도 YAML/PGM·최종
   정지 증거가 필요하다. 현장 영상·담당자·원시 계측의 출처와 시각은 비공개
   현장 증거에 남기고 공개 저장소에는 장치 주소나 영상을 넣지 않는다.

### Consequences and verification

`pinky-pro-first-device-runbook.md`, `pinky-pro-attended-session-runbook.md`,
`pinky-native-mapping-recovery.md`에 원격 단독 입회와 중단 조건을 일치시킨다.
Rosy Cam 수신만으로 G4/G5를 GO로 바꾸지 않는다. 첫 DEVICE 세션에서 두 로봇
각각 신원·연속 영상·원시 계측·원격 정지·복구를 확인한다. 실패하면 현재
`motor` 상태와 목적지 주행 비활성을 유지한다.

## D-850 독립 운영과 하위 구성을 지원하는 관제 단위

**Status:** Accepted (2026-10-23, 사용자 결정). 관제 구성의 목표와 책임 경계다. 계층 간 위임 구현·자동 독립 전환·배포·장치 수용은 완료되지 않았다.

### Context

관제 PC와 통합관제 PC부터 나누면 통합관제를 화면 단말로 고정하거나 중앙–현장의 두 단계만 허용하기 쉽다. 사용자는 통합관제의 독립 운영과 각각의 서브 관제를 포함하는 구성을 요구했다. 논리 책임과 결합 관계를 먼저 정하고 PC 배치는 별도로 정한다.

### Decision

1. **관제 단위는 독립 운영할 수 있다.** 상위 통합관제의 존재를 모든 배치의 필수 조건으로 강제하지 않는다. 배치 목표이며 운영 중 링크 단절 시 자동 독립 전환을 허용하는 결정은 아니다.
2. **통합관제는 하위 관제 단위를 포함할 수 있다.** 각 하위 단위는 자기 범위의 조정 책임을 갖는다. 자체 하위 관제를 묶으면서 상위에는 하나의 서브 관제로 참여할 수 있는 구성을 목표로 한다. 지원 깊이·단일 부모 여부·순환 방지 계약은 후속 설계에서 정한다.
3. **다음 세 역할을 구분한다.** 역할마다 PC 한 대나 프로세스 하나를 요구하지 않는다.

| 역할 | 책임 |
|---|---|
| 통합관제 | 관할 업무의 목표·우선순위·진행 상황을 관리하고 하위 관제에 업무를 맡긴다. |
| 현장·서브 관제 | 자기 범위의 장비·공간·실행 조건을 확인하고 담당 실행자 사이의 작업을 조정한다. 하위 관제들을 조정할 때는 그 범위의 통합관제 역할을 수행한다. |
| 장치 실행자 | 개별 장치의 상태·명령 권한·안전 조건을 확인하고 실제 동작을 수행한다. |

4. **상위 구성에 참여해도 장치 실행 권한은 이동하지 않는다.** 요청은 담당자의 공개 경로와 검증을 거친다. CORE의 최종 이동 명령 발행 권한과 OMX의 관절·Action owner, 기존 안전 경계를 유지한다. 하위 단위 등록만으로 구동 권한이 생기지 않는다.
5. **관제 서비스와 관제 화면은 별개다.** 통합관제 PC라는 이름으로 브라우저 단말 또는 업무 서버를 확정하지 않는다. 통합관제를 Fleet coordination 하나와 동일시하지 않으며 현재 Fleet의 계층 간 위임 지원을 주장하지 않는다.

구성 예시는 독립 관제 A, 통합관제 아래 관제 A·B, 자체 하위 관제를 가진 A가 상위 통합관제에 참여하는 중첩 구성이다. 실제 설치 구성이나 새 API를 확정하지 않는다.

### 기존 결정과의 관계

| 결정 | 관계 |
|---|---|
| D-427 | 논리 구성이다. middleware / operations / learning 파트나 새 최상위 폴더를 정하지 않는다. |
| D-429 | 판단·제어·사이트 장치 소유권을 유지한다. 상위 관제가 실행자를 대체하지 않는다. |
| D-430 | 안전은 담당 장치와 기존 안전 경로에 남는다. 상위 관제가 안전 기능의 필수 네트워크 의존점이 되지 않는다. |
| D-434 | 기존 호스트 역할을 폐기하지 않는다. 추가 통합관제의 실제 호스트 배치는 별도 결정한다. |
| D-435 | 작업 오케스트레이션·Fleet coordination·장치 실행의 역할과 권한 구분을 유지한다. |
| D-516 | 모델 PC·AI PC·현장 PC의 권한 구분을 유지한다. 계층 추가가 추론 모델에 실행 권한을 주지 않는다. |

### Alternatives

- 화면 단말로 고정: 독립 운영과 하위 관제 조정 요구를 담지 못하므로 채택하지 않는다.
- 중앙과 현장을 두 단계로 고정: 중첩 구성을 표현하지 못하므로 채택하지 않는다.
- 독립 운영과 조합을 지원하는 관제 단위: 사용자 요구에 따라 구조 목표로 채택한다. 위임·장애 계약은 별도 설계가 필요하다.

### Consequences

단일 현장과 다중 현장을 같은 구성 원칙으로 논의할 수 있다. 물리 PC 수와 관제 계층 수는 별도 문제다. 계층 간 실행을 열기 전에 관제 식별·등록·관할 범위·포함 관계 제약, 상위 업무와 하위 작업의 대응, 상태의 정본 소유자·완료 증거를 정해야 한다.

위임·접수·거절·취소·재시도·중복 방지·권한 경합, 상하위 인증·사람 확인·정지 전파, 연결 단절 시 작업 계속·중단·신규 작업 허용 범위와 재연결 정합성도 미결이다. 첫 적용 범위가 현장 내 공정·셀인지 다중 현장인지와 실제 PC 배치는 후속 설계에서 정한다.

기존 링크 단절·정지 정책은 계속 유효하다. 자동 재시작·래치 정지 해제·운영 중 자동 승격을 도입하지 않는다.

### Validation

이번 결정은 구조 목표의 기록이며 기능 시험·배포·실물 수용 증거가 아니다. 후속 구현에서는 독립·상하위 구성의 업무 흐름, 무권한 요청·중복 요청·취소·링크 단절·복구를 각 상태 소유자의 증거로 검증한다.

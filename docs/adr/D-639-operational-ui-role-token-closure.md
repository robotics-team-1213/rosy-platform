# D-639 운영 UI의 역할 토큰·공용 조작·표면 검사 폐쇄성

**Status:** Accepted (2026-10-11)

### Context

D-624는 색의 단일 원본과 역할 사용을, D-629는 관제 위계와 동일한 조작 규격을 정했다. 그러나 실제 소비 화면에는 입력 덧칠, 펼침 행 자체 규격, 캔버스 숫자 글자 크기, native의 독립 글자·버튼 치수가 남아 있다. 기존 재귀 색·간격 검사는 이를 일부 지키지만, 토큰 참조 검사와 몇몇 시각 검사는 Robot 최상위 CSS만 읽는다. 표면 레지스트리의 중복 YAML 키도 조용히 이전 설명을 덮는다.

2026-10-11 사용자는 목적을 세워 운영 UI의 시각 하드코딩을 제거하고 각 역할에 맞게 통일하도록 요청했다. 이 결정은 기존 기능·명령 소유자를 보존하며 구현과 검증의 범위를 정한다. Accepted는 모든 화면 구현·CI·설치본·실물 수용 완료를 뜻하지 않는다.

### Decision

1. 운영 표면 목록·매체·역할·문법·테마·계약의 원본은 `shared/web/surfaces.yaml`이다. 중복 키를 거절하고, 실제 화면 소유 역할과 레지스트리를 일치시킨다. PARKED 진단·SIM 개발 표면의 색 정리 또는 목록 기록으로 운용을 활성화하지 않는다.
2. 시각 값은 원본 토큰 → 파생·역할 → 공용 컴포넌트 → 화면 배치 순서로 소비한다. 표면은 공용 부품의 면·색·글자·내부 여백을 덮지 않는다. 색·서체·글자 계단·조작 크기·여백·표준 포커스의 수동 사본과 임의 척도를 없애며, 이미 닫힌 규칙을 다시 구현하지 않는다.
3. 일반 조작과 비상정지는 최소 48px·라벨 14px·좌우 12px를 따른다. 위험은 채움·아이콘·동사로 구분한다. 읽는 행을 여는 조작은 공용 disclosure 행으로, 같은 최소 누름면·내부 여백·키보드·펼침 상태를 사용한다. 행의 로봇 이름은 본문 역할 16px로 표현할 수 있으나 조작 문구·보조 정보와 구분한다.
4. Pilot의 조이스틱·페달처럼 입력 기하 자체가 사용 목적이면 일반 버튼 덧칠로 크기를 숨기지 않는다. 필요한 공간은 명시된 입력 역할·기하·수용 시험으로 정한다. 일반 메뉴·접속·정지 조작은 해당 예외를 물려받지 않는다. LCD는 물리 해상도·프로필과 글자 맞춤을 유지하며 웹 버튼을 복제하지 않는다.
5. `canvasFont`는 공용 글자 역할을 읽고 표시 배율만 적용한다. 숫자 첫 인자로 별도 글자 크기를 만드는 호출을 거절한다. 지도 좌표·영상 비율·브러시 반경·annotation 분류 색과 같은 도메인 자료는 UI 시각 토큰과 구분한다. 아이콘·native의 생성 산출물은 원본 토큰과 일치하는 기존 생성·검증 경로를 사용한다.
6. Native의 공용 버튼·서체·여백·모서리도 기존 생성/리소스 export에서 공용 척도를 소비하고 매체 단위로 제공한다. 색상만 같다는 이유로 typography·dimension까지 통일됐다고 판단하지 않는다. 새로운 런타임 프레임워크나 수동 팔레트 사본을 도입하지 않는다.
7. 검사 범위는 등록 표면과 하위 실제 자산을 따라간다. 선언되지 않은 토큰, 공용 부품 덧칠, 캔버스 역할 우회, 중복 레지스트리 키, native 척도 불일치를 실패로 만든다. 기존 raw 값 예외는 대상·이유·계약 상태를 명시하며, 운영 표면의 실패를 숨기려고 예외를 늘리지 않는다.
8. 각 화면은 목적·현재 상태·주 동작·복귀 경로를 먼저 정한다. Fleet 관제는 D-629의 지도와 상태 레일을 유지한다. Install은 단계·전제·결과, Site-map은 활성 지도와 초안, Cell은 준비·컴파일·제안·승인·진행을 구분한다. Robot·Pilot·검토·경기 화면은 각 기존 소유 역할을 지킨다.
9. 문의·AI 판단·Fleet 전달·CORE 수신·실행 완료는 서로 다른 증거다. 읽음은 완료를 뜻하지 않고, 이전 영상은 현재 관측을 뜻하지 않는다. 기존 조회·명령 API와 credential·CORE 최종 실행 권한은 변경하지 않는다. 브라우저 로컬 메시지는 서버 영속 메시지함으로 표현하지 않는다.
10. 구현 완료는 계획·ADR로 선언하지 않는다. 호출자·route·설치 자산·fixture를 함께 고치고, 목표 범위의 UI 실패를 원격 시험과 실제 소비 화면으로 확인한다. source·원격 시험·CI·서명 artifact·설치 readback·장치·현장 증거를 구분한다. G2/G3가 없는 전체 제품의 현장 수용을 선언하지 않는다.

### Consequences

`pilot-shell`은 parent Pilot의 native 구현이다. 발견·연결 외에 이미 존재하는 `GroupDrive`가 두 CORE에 독립 요청한다는 역할을 레지스트리에 기록하되, `manual-drive`·`estop` 소유권은 parent Pilot에 유지한다. 웹 조종 캡처는 native 함께 조종의 장치 수용을 대신하지 않는다.

워드마크는 운용 글자 계단과 별도의 정체성 그림이다. 기존 칸 맞춤 기하를 `tokens.css`의 `--brand-wordmark-size`에 보존하고 공용 `ui-brand`만 소비한다. 이 값으로 상태·조작 글자의 크기를 대체하지 않는다.

일반 웹 규칙은 이미 토큰을 사용하는 부분을 유지하고 실제 누락만 닫는다. 공용 원본의 변경이 모든 소비자에 미치므로 대표 견본만으로 끝내지 않고 실제 Install·Pilot·native 등의 소비 규격을 검사한다. 시각 계단, 입력 기하, 도메인 데이터와 고정 매체의 구분이 명시되어 값 치환으로 지도가 깨지는 일을 피한다. 요청된 기술 구현·회귀 완료와 실물 주행 수용은 별도로 보고한다.

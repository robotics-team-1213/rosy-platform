## D-406 관제 콘솔 카메라 구역은 운용 무대(영상)와 설치·보정 묶음(접힘)으로 나뉘고, 목표 받기는 토글 위계를 가진다

**Status:** Accepted (2026-10-02, 사용자 지시 — 화면 위계 산만함 해소·역할별 컴포넌트화). D-201·D-359 §5·D-405를 좁힌다.

이는 결정: [D-201](D-201-fixed-grammar-surfaces-fit-contract.md) · [D-280](D-280-calm-intelligence-product-design-philosophy.md) · [D-359](D-359-theme-ready-tokens-shared-controls-and-responsive-tiers.md) · [D-405](D-405-icon-first-controls-and-measured-size-discipline.md).

### Context

2026-10-02 관제 회차 감상: "화면이 허접하다, 아이콘·버튼 크기가 산만하고 뭐를 말하는지 모르겠다, 역할별로 컴포넌트화해라." 관제 카메라 구역이 영상 프리뷰 + 제안 도구 버튼 7개 + 상태 힌트 4문단 + 설정 `details` 2개(경기장 크기·레이어, 왜곡·사각 보정)를 한곳에 펼쳐 놓아, 운용 일(영상 보기)과 설치 일(보정·맞춤)이 뒤섞여 있었다. 로봇 카드의 목표 받기 버튼이 `quiet`라 "지금 어느 로봇이 목표를 받는지"가 색으로 보이지 않았다.

### Decision

1. **카메라 구역은 둘로 나뉜다.** 운용 무대 — 카메라 선택·새로고침·최신 프레임·소개 문장. `카메라 설치·보정 도구` 묶음(`details#camera-install-tools`) — 경기장 제안 도구, 맵 맞춤 도구, 제안 상태 문장, 결과 그림 2개, 경기장 크기·레이어, 왜곡·사각 보정. 묶음은 기본 접힘.
2. **D-201 "예외 문법은 한 화면에 다 보인다"를 좁힌다.** 제안 도구(경기장 찾기·맵 맞춤)는 설치 흐름이므로 접힌 묶음 안에서 산다. 제안이 대기 중이면 `field-proposal-state` 문장이 묶음 안에서 말하고 설치자가 연다. 예외 문법의 "다 보임"은 운용 예외(주의·개입 큐, 연결 끊김)에 그대로 적용된다.
3. **목표 받기는 토글 위계다.** `ui-button[data-goal-robot-id]`는 `kind="toggle"` + `aria-pressed` — 눌림 = 계열 파랑 채움 = "지도를 찍으면 이 로봇이 움직인다". 기존 `.arming` 클래스 표시를 대체한다(색은 공용 표현만 쓴다, D-359 §5).
4. **측정 라벨 아이콘은 라벨 척도(`--text-label`)다.** 값과 같은 크기(1.125rem)면 무겁다 — D-405 세부 적용.

### Alternatives

- **별도 설치 뷰(라우트 분리):** 다음 단계 후보. 이번 회차는 접기로 v1 — 묶음이 나중에 설치 표면으로 옮겨갈 뿌리가 된다.
- **펼침 유지(D-201 원문 그대로):** 운용 밀도 문제가 그대로 남는다. 거절.

### Consequences

운용 화면의 카메라 구역이 영상 중심으로 좁아지고 설치 흐름은 요약줄 한 줄로 접힌다(폰 문서 높이도 줄어든다). `vision-adjustments` 등 아이디는 그대로라 기존 시험·JS가 그대로 붙는다.

### Validation

- 계약 시험: fleet 전체(브라우저 회귀 포함), `test_task_contract_docs.py`의 `vision-adjustments` 아이디 보존.
- 브라우저: 재캡처에서 묶음 접힘·토글 눌림(계열 파랑) 확인, 페이지 오류 0.

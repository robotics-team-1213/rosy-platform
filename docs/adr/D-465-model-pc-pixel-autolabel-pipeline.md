## D-465 모델 PC에서 픽셀 자동 라벨 초안을 만들고 검수·학습 자격을 분리한다

**Status:** Accepted (2026-10-05, 사용자 차선·바닥·벽 픽셀 우선 및 ADR 기록 요청). 파이프라인 방향의 결정이며 구현·설치·외부 API 호출·착지·push·배포·모델 활성화 승인이 아니다.

### Context

사용자는 모델 PC에서 OpenRouter 또는 다른 모델을 이용한 자동 라벨링을 요청했고, 객체 박스보다 차선·바닥·벽의 픽셀 마스크를 우선으로 골랐다. GPU는 RTX 5080으로 답했으며 메모리 용량은 대화 중 18 GB/12 GB를 확인했다. 이번 설계 기준은 16 GB다. D-434에 모델 PC의 RTX 5080 Laptop GPU와 16 GB가 기록되어 있지만 이번 세션에서 실제 장비의 GPU·VRAM·드라이버를 조회하지 않았다. NVIDIA의 데스크톱 RTX 5080 사양도 16 GB지만 그것으로 대상 장비 신원을 확정하지 않는다.

D-379의 `dataset/autolabel.py`는 LiDAR 벽과 주행 궤적 바닥을, `dataset/prelabel.py`는 기존 차선 모델의 마스크 초안과 불확실성 순위를 제공한다. D-462는 픽셀 검수·원본 정체성·독립 revision·최신 결정 확인을, D-464는 승인 indexed PNG의 immutable 데이터셋 구성을 정한다. 외부 모델 호출과 로컬 분할 모델 실행을 이 앞단에 연결하는 계약은 별도로 필요하다. 여기서 말하는 자동화는 정답 확정까지의 무인 처리가 아닌 초안 생성이다.

### Decision

1. **배치와 소유.** D-434에 따라 모델 PC가 프레임 선택·자동 초안·데이터셋·학습·평가를 맡는다. 소스는 D-427의 기존 `learning/training/perception/` 아래에 둔다. 추론 실행과 초안 산출물은 learning 도구가 소유하고, 검수 UI·저장·승인 권위는 D-462의 기존 앱이 소유한다. 관제 PC의 Fleet/Vision과 로봇 CORE에 라벨 생성 책임을 추가하지 않는다. D-429의 판단·제어·통신 구분 및 D-430의 안전 경계와 연결하며 cmd_vel·E-stop·운용 모델 writer를 바꾸지 않는다.
2. **로컬 추론을 기본으로 한다.** 기존 기하 라벨과 차선 모델 초안을 먼저 활용한다. 벽·바닥은 동기화와 카메라/LiDAR 보정이 확인된 관측 범위에서만 기하 후보를 만든다. 주행 궤적은 주행하지 않은 모든 영역의 정답을 보장하지 않는다. 차선은 기존 모델로 후보를 만들고 반사·희미한 선·교차·가림을 검수한다. SAM 2 계열은 점·영역 프롬프트에 따른 경계 보완 후보로 시험한다. SAM 자체가 차선·바닥·벽의 의미 클래스를 보장한다고 가정하지 않으며, 얇은 차선 품질과 기존 초안 대비 이득을 실영상으로 검증한 뒤 채택한다. 초기 처리 단위는 한 프레임 또는 짧은 영상 구간으로 제한한다.
3. **외부 모델은 선택 가능한 보조 판단이다.** OpenRouter 또는 직접 제공자 API는 클래스·장면 해석 및 애매한 영역의 검수 우선순위에 활용할 수 있다. 외부 모델이 반환한 좌표·폴리곤도 미승인 후보다. JSON Schema 지원은 형식 제약이지 픽셀 정확도나 calibrated confidence의 증거가 아니다. 실제 모델 ID·제공자·이미지 입력/구조화 출력 지원을 확인하고 고정하며 모델 자동 선택으로 평가 재현성을 잃지 않는다. 로컬 경로는 외부 API 없이도 진행할 수 있어야 한다. 외부 전송 전 자료 범위·제공자의 보관 정책·비용 상한을 확인하고 키·장비 주소는 공개 저장소에 넣지 않는다. 이번 ADR 기록으로 API 호출을 시작하지 않는다.
4. **파이프라인.** 원본 녹화·센서 기록 수집 → 원본 hash·촬영 세션·시각 보존 → 프레임 선택/중복 제거 → 기하/학습 모델/선택 외부 모델 초안 → 클래스·원본 크기·좌표 변환 검사 → 출처별 불일치와 미라벨 표시 → 기존 픽셀 앱에서 수정·전체/배경 확인·승인/제외 → D-462의 최신 결정 export → D-464의 학습 자격 검증·데이터셋 구성 → D-356/D-373의 학습·독립 평가·intake 순서다. 객체 승인을 픽셀 승인으로 재사용하지 않는다. 학습 결과의 로봇 운용 승격은 기존 별도 절차다.
5. **마스크와 정답 경계.** 클래스 ID/role은 기존 classes 계약을 사용하고 임의로 추가하지 않는다. 원본 크기 8bit indexed PNG와 `ignore_index=255`를 유지한다. 미관측·불일치 영역은 255로 남기고 UI에서 명시한다. 이는 초안에는 허용되지만 D-464의 전체 승인 학습 입력에는 255가 남으면 거절된다. 리사이즈·crop·투영을 했다면 원본 좌표로의 변환과 검증을 기록한다. CAD 참고와 검증되지 않은 지도 투영으로 정답을 생성하지 않는다. 모델 출력과 자기 보고 confidence만으로 자동 승인·고정 평가 정답을 만들지 않는다. D-379의 기존 신뢰 출처와 D-464의 명시 승인 경로를 보존한다.
6. **작업 실행과 재현.** 원본 image/video hash·frame identity·source_session/capture_group·클래스 계약 hash·source commit·모델 checkpoint/제공자 ID·프롬프트/파라미터 버전·기하 보정 출처·변환·실패·출력 hash를 작업 receipt에 남긴다. 기존 계약과 도구를 재사용하며 새 공용 schema나 API 경로는 여기서 확정하지 않는다. 진행률·제한된 재시도·중단 후 재개·예산 초과 정지를 제공하고 오류를 빈 background 정답으로 바꾸지 않는다. 동일 작업 완료 산출물은 불변으로 보존하며 재생성은 새 초안 revision이다. 승인 자료를 덮어쓰거나 자동 재승인하지 않는다.
7. **GPU와 환경.** 실제 모델 PC에서 GPU 모델·VRAM·드라이버·CUDA/PyTorch 호환성을 확인한 뒤 설치한다. 16 GB는 설계 예산이며 모델 크기·해상도·영상 길이에 따른 실제 peak VRAM/처리시간은 미측정이다. 작은 모델·batch 1부터 측정하고 OOM은 작업 실패/재개 가능 상태로 남긴다. D-434의 Isaac/학습 환경 분리와 GPU 동시 사용 제한을 자동 라벨 작업에도 적용한다. D-446의 고정 source·작업 lock을 재사용하며 진행 중 작업의 코드/환경을 갱신하지 않는다. Windows 개발 검증의 스크래치·로그·overlay는 `X:/DevTemp/`에, 실제 데이터셋·모델은 기존 store에 둔다.
8. **평가와 도입 순서.** 대표 촬영 세션에서 100~200장으로 첫 비교를 한다. 선택 프레임 수와 별개로 train/eval은 source_session 및 capture component 단위로 분리하고 D-464의 전체 고정 eval version 제외를 적용한다. baseline(기하+기존 모델), 로컬 분할 보완, 선택 외부 보조를 비교한다. 사람이 확인한 독립 평가 마스크로 클래스별 IoU·차선 경계/누락 오류를 측정하고 장당 수정 시간·처리시간·peak VRAM·실패율·외부 호출 비용을 함께 보고한다. 수치 합격 기준은 실행 전에 평가 담당자가 정해 기록한다. 현재 정확도·속도·자동화 절감 효과는 UNKNOWN이며 샘플 수만으로 품질 PASS를 선언하지 않는다.

### Alternatives

- 외부 비전 모델만으로 모든 픽셀 정답을 생성: 클래스 의미 판단은 가능해도 원본 좌표의 경계 정확도·누락·비용을 검증해야 하므로 기본 경로로 채택하지 않는다.
- 로컬 기하/기존 차선 모델만 사용: 초기 baseline과 API 없는 경로로 유지한다. 반사·교차·센서 미관측의 교정 부담이 남는다.
- 로컬 초안과 선택 외부 보조를 기존 검수에 연결: 채택한다. 검수 시간과 클래스별 품질 개선을 비교해서 실제 모델 조합을 확정한다.

### Consequences and verification

기존 라벨·검수·builder·store를 재사용하고 부족한 자동 초안 실행 연결만 후속 구현한다. 사람은 처음부터 전부 그리는 대신 후보와 충돌을 확인하지만 실제 시간 절감은 측정 전이다. 모델 선택/설치, 실행 UI/worker 연결, 오류·중단 복구·원본 좌표 roundtrip 검증, 모델 PC GPU 파일럿, 독립 마스크 평가를 각각 후속 작업으로 둔다. 로컬 문서 lint/계약 테스트는 구조 기록의 증거이며 GPU 실행·라벨 품질·학습·DEVICE/FIELD 수용의 증거가 아니다. 기존 모델 운용 HOLD나 승격 권한을 변경하지 않는다.

### Addendum 2026-10-07 — SAM 3와 VLM 점으로 drivable 초안

**맥락.** 모델 PC 파일럿(세션 `20261006T091340Z_rosy_26`, 642프레임)에서 VLM(Qwen3-VL 8B) 점 → SAM 분할을 시험했다. VLM 차선 점은 가장자리 환각이 많아 SAM 3 텍스트 프롬프트 차선보다 나빴다. VLM 도로 점 + SAM은 「카펫」을 분할할 뿐 도로와 도로 밖을 구분하지 못했다.

**결정.** §2의 SAM 2 계열에 SAM 3.0(텍스트·점 프롬프트, tracker 전파)을 더한다. lane_line·wall 초안은 SAM 3 텍스트 프롬프트로 만든다. drivable 초안은 로봇 바로 앞 카펫(발판) seed와 밝기·차선 gate를 통과한 VLM 점으로 tracker를 K프레임마다 다시 시작하고, 흰 선을 넘지 않고 발판과 연결된 카펫 성분만 drivable로 둔다. 선 너머 카펫은 기존 base 값을 유지하며 사람이 판단한다. VLM 점은 학습 초안에만 쓰고 고정 평가 정답(D-475 §7)에는 쓰지 않는다. 초안은 receipt에 영상·점·base·체크포인트 hash와 source commit을 남기고, 승인 없이 `review_ingest`로만 들어간다. 도구: `dataset/road_draft.py`, `qwen_points.py`, `sam3_road_draft.py`.

**검증 상태.** 파일럿 수치(연속 프레임 IoU 중앙값 0.998, 0.5 미만 전환 5/641, 0.43 s/frame, peak 7.5 GB)는 초안 안정성 증거이며 라벨 정확도 증거가 아니다. 정확도는 사람 검수 수정량과 독립 평가 마스크(§8)로 잰다.

## D-567 Fleet 경로를 주행 기준으로 유지하고 동기화된 지도 자세·바닥 경계로 제한 보정한다

**Status:** Proposed (2026-10-09). 사용자 요청: 계획과 알고리즘 검토, SIM 비교, 두 대의 실물 확인. 이 ADR은 보정 권한·검증 순서를 정하는 제안이며 배포나 장치 주행 수용이 아니다.

잇는 결정: [D-557](D-557-ring-next-is-model-pc-lap.md)(현행 D-520 모델 PC 한 바퀴 먼저) · [D-520](D-520-map-guided-ring-arc-following.md)(Fleet 호와 CORE 최종 명령) · [D-531](D-531-route-context-to-lane-keeper.md)(경로 문맥은 거부 전용) · [D-476](D-476-lane-loss-expected-road-bridge.md)(직선 소실의 별도 짧은 다리) · [D-494](D-494-fleet-trip-execution-m2-contracts.md)(Fleet 지도 자세) · [D-546](D-546-recovery-manoeuvre-signals-and-fleet-pose-request.md)(정지 뒤 위치 요청) · [D-379](D-379-learning-data-pipeline-auto-labels-local-store.md)(원본·라벨 출처) · D-422(차체 sweep) · D-430(안전 검토).

### Context

- D-520 단계 1은 odom에 놓은 지도 원을 따라가며 `arc_blind_max_m: 1.0`까지 카메라 맞춤 없이 진행한다. [NE 원시 로그 재계산](../validation/lane-pivot-pose-audit-2026-10-09/result.md)은 첫 호의 지도 접선 대비 방향 오차 +15.497…+16.273°(4회)를 보였다. [blind 교차점](../validation/lane-arc-blind-envelope-2026-10-09/result.md)은 오차 25 mm가 odom 0.1104–0.1281 m에서 처음 기록됐음을 보였다. 이 값은 SIM 평가 결과이지 실물 허용 거리나 차체 충돌 측정이 아니다.
- D-520 `lane_arc_fit.py`는 카메라 바깥선의 원 맞춤 후보를 계산하지만 바닥/벽·spoke 정체, 투영 계통오차와 시간 정합의 상한은 제공하지 않는다. Fleet `MapPose`에는 `odom_stamp`·`map_id`가 있지만 측방·방향 오차 상한은 없고, trip의 `pose_view`에는 그 두 식별자가 빠진다. `LOCALIZED`나 점 수·RMS를 보정 허가로 읽지 않는다.
- D-557은 새 조향 연결보다 먼저 현행 설정 그대로 모델 PC 한 바퀴를 재현하도록 정했다. 이 순서를 유지하면서 보정 후보 계산과 기록은 독립적으로 진행할 수 있다.

### Decision

**주행 목표.** Fleet이 지정한 차로를 한 바퀴 끝까지 따라가되, 매 시점 로봇의 예측 차체 sweep과 측정된 정지 후 추가 이동이 승인된 차로 경계 안에 들어야 한다. 도색 선의 일부를 밟는지는 경계 침범 판정과 분리한다. 통과하려는 다음 구간의 차체 여유나 증거 상한을 계산할 수 없으면 그 지점 전에 HOLD한다. 우선순위는 안전 경계·정지 가능성, 경로 완주, 중심선 오차·승차감 순이다. 조향 보정 자체, 특정 진입 각도, GT로 맞춘 반지름은 목표가 아니다.

1. **한 명령 경로.** Fleet은 활성 지도, 차로·호 중심과 다음 장소를 정한다. CORE의 D-520 추종기는 기존 원호·IR·D-422·통행권 검사를 계속 소유하고 최종 `cmd_vel`은 CORE Command Manager만 낸다. 지도 자세 추정기와 바닥선 맞춤은 후보 증거를 병렬 계산하되 별도 주행 publisher, Fleet 직접 조향 명령, 자동 재출발은 만들지 않는다. 첫 구현은 기록·SIM 평가만 한다.
2. **시간과 출처.** 후보는 같은 로봇·활성 `map_id`·캘리브레이션·odom/TF epoch를 검증한다. Fleet 자세의 `odom_stamp`, Rosy Cam `captured_at`, CORE 원본 ROS 시각은 각각의 시계·단위·수신 구간을 기록하고 보간 가능할 때만 짝짓는다. HTTP 조회 시각이 같다는 이유로 동일 센서 시각으로 간주하지 않는다. Fleet 자세가 Rosy Cam과 odom에서 유도됐다면 두 값을 독립 관측처럼 가중 결합하지 않는다. 승인된 바닥 경계 ID가 없으면 벽·spoke·한쪽 테이프 후보를 조향 근거로 쓰지 않는다.
3. **제한 보정 후보.** 지도 호의 현재 접선·중심선에서 지도 자세의 횡방향·방향 오차를 계산한다. 별도로 보이는 바닥선이 있을 때만 D-520 고정 반지름 맞춤으로 같은 두 오차를 계산한다. 각 후보는 잔차뿐 아니라 측정한 위치·방향·지연·투영의 **계통오차 상한**을 가진다. 같은 부호·허용 오차 안에서 일치한 후보만 기존 D-520 보정 항의 입력 후보가 된다. 한쪽 선 소실은 확인된 반대쪽 경계와 지도 차로 폭으로만 범위를 제한한다. 보이지 않는 선이나 drivable 화소를 생성하지 않는다. 고정 −13° 회전값, GT 자세, 시험 후 보정값을 제품 입력으로 사용하지 않는다.
4. **전진 가능 범위.** 지도의 차로 반폭에서 차체 반폭, 경계 위치 상한, yaw·곡률·odom 성장 오차, 제어·통신 지연 중 이동, 측정한 정지 중 추가 이동을 뺀 여유가 양수인 거리까지만 후보를 허용한다. 필요한 상한이 없으면 보정 권한도 전진 거리도 만들지 않는다. 영상 없음·시간 역전·지도 불일치·벽/바닥 불명·후보 충돌은 해당 기존 HOLD로 간다. 직선 한쪽 선 소실은 D-476의 별도 상한을 유지한다. IR·차체 sweep·E-Stop은 후보가 있어도 매 틱 유지한다.
5. **승격 순서.** (a) D-557 현행 설정의 모델 PC 한 바퀴를 재현해 baseline을 고정한다. (b) SW·NE·lap 원시 기록에 후보를 shadow 계산하고 양쪽/한쪽/가림/벽·spoke·지연/중복을 나눈다. 사람이 승인한 물리 경계만 정답으로 쓴다. (c) 같은 시작·속도·지도·시드의 폐루프 Gazebo에서 baseline, 지도 자세만, 승인 바닥선까지 더한 후보를 비교한다. 독립 GT로 차체 sweep의 경계 침범 0, 필요한 때 경계 전에 STOP, 허용된 구간의 완주를 판정한다. 최대 `|Δr|`, 진입 방향, 연속 miss, HOLD 사유는 진단값으로 기록한다. 이전의 `|Δr| ≤ 0.05 m`와 보정 후보 `≤ 0.03 m`는 차로 폭·차체 폭·정지 거리 없이 안전 통과를 보장하지 못하므로 단독 합격 기준으로 사용하지 않는다. (d) 두 로봇을 각기 식별해 카펫 yaw, 바닥·외부 보정, 지도 자세 오차, 지연, 차체 여유·정지 거리를 독립 측정한다. 사람 감독의 짧은 장치 시험에서 먼저 shadow readback을 확인하고 그 다음 별도 활성화 결정을 한다. 한 로봇 결과를 다른 로봇에 복사하지 않는다.

실물 승격 판정은 로봇별로 분리한다. `rosy_26`/9dfk와 `rosy_60`/8kcn의 측정 바퀴 기하·카메라 자세는 이미 다르지만, 과거 측정값이 현재 accepted record와 실행 override라는 증거는 없다. 각 로봇의 calibration digest·실행 파라미터·릴리스·독립 위치 오차·실측 차체 sweep·정지 후 이동을 같은 실행에서 결속한다. 바퀴 반지름 차이를 물리 차체 반경 차이로 간주하지 않으며, SIM 외접 원과 한 로봇의 합격 결과를 다른 로봇에 복사하지 않는다.

### 검토한 대안

| 방식 | 판단 |
|---|---|
| `turn_deg`에 NE SIM의 −13°를 더한다 | GT를 보고 고른 값이고 다른 입구·로봇에 이식할 근거가 없다. 기각. |
| Fleet 지도 자세만 믿고 호를 계속 간다 | 현재 측방·방향 상한이 없고 `LOCALIZED`만으로 차체 여유를 증명하지 못한다. shadow 비교에만 사용. |
| 한쪽 카메라 선만으로 조향한다 | 벽·spoke와 바닥선의 출처 및 투영 계통오차가 미검증이다. 승인 경계가 있을 때만 제한 후보. |
| **Fleet 중심선 + 동기화된 근거의 제한 보정** | 경로 의도를 유지하며 오차를 실제로 관측할 수 있다. 상한이 확인될 때만 제어 승격. |

### 소유권과 수용 경계

| 기존 결정 | 유지할 경계 |
|---|---|
| D-427·D-429 | Fleet은 경로와 지도, perception은 센서 증거, CORE는 주행 권한을 소유한다. 배치·패키지 이전 없음. |
| D-430 | 안전 경로 변경 전 독립 Safety-Review와 SIM·DEVICE 증거가 필요하다. Proposed ADR만으로 활성화하지 않는다. |

현재 완료 판정은 **설계·후보 검토**까지만 가능하다. 모델 PC 연결, 동기화된 실물 자세, 두 로봇의 운영자·정지 수단 또는 사람 검수 경계가 빠지면 그 단계는 HOLD로 명시한다.

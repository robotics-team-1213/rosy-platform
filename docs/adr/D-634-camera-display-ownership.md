## D-634 카메라 촬영·교정·관측·좌표 표시의 역할 분담과 표시 안정성

**Status:** Proposed

### Context

2026-10-11 사용자는 기존 역할에 따라 Rosy Cam과 다른 구성 요소의 중복 책임을 정리하도록 요청했다. 증상을 확인한 뒤 «하단 좌표가 나타났다 사라지는 문제»라고 명시했다. 이를 렌즈 자동 전환이나 실제 카메라 교체로 단정하지 않는다.

현재 `tracking-view.js`는 유효 관측 행이 없으면 좌표 표 전체를 숨긴다. `displayLeaseMs`는 최대 1초에서 source 관측 나이와 HTTP 소요 시간을 빼고, 만료 시 `show(null)`을 호출한다. 따라서 새 관측 대기 중 표 높이가 사라졌다 돌아오는 경로가 있다. 좌표 수명을 늘리거나 지난 수치를 현재 위치로 남기는 방법으로 해결하면 안 된다.

별도로 `shared/vision-view.js`는 source 목록 갱신 때 선택한 source가 사라지면 다른 첫 source로 바꾼다. 이것은 이번 하단 좌표 증상의 원인으로 입증되지 않았지만, 운용자가 선택한 영상의 안정성을 깨는 별도 경로다.

### Decision

기존 D-377, D-457, D-544, D-589, D-595, D-631의 역할을 유지한다. D-633의 측정 교정은 Proposed 설계이며 구현 완료로 취급하지 않는다.

| 구성 요소 | 책임 | 넘겨받거나 중복하지 않는 책임 |
|---|---|---|
| Rosy Cam | 카메라 바인딩·명시적 렌즈 선택·원본 JPEG와 촬영 메타데이터·최신 프레임 전송. `CameraController`의 촬영 제어기가 CameraX 적용과 확인을 담당 | 지도 생성·좌표 추적·교정 승인·로봇 명령을 하지 않음 |
| Vision | source별 영상 수신, 교정 적용·교정 제안, 마커/배경 인식과 지도 좌표 관측 생성. D-589 노출 요청을 Cam에 제안 | 렌즈·source를 임의 선택하거나 지도를 활성화하지 않음. 제안을 승인 교정으로 자동 대체하지 않음 |
| Fleet | 활성 지도·승인 교정 보관, source/map/revision/신선도 검증과 로봇 식별, 관측 수명 제공 | 영상 바이트 중계·카메라 촬영 제어·브라우저 교정값에 의한 운영 좌표 생성 없음 |
| Console | 운영자가 고른 source·표시 모드 유지, 좌표·원본·교정 결과·유효성 표시 | 관측이나 승인 교정을 새로 만들지 않음. 관측 없음에서 다른 카메라나 좌표를 몰래 대입하지 않음 |

Cam의 D-544 로컬 노출 보조와 Vision의 D-589 인식 노출은 동일 CameraX writer에 경쟁해서 쓰지 않는다. 현재 `CameraController.evaluateExposure`는 유효 Vision 요청이 있을 때 로컬 보조를 비활성화하고 `writer.drive` 한 경로로 적용한다. 이 우선순위와 만료 시 로컬 복귀, 열 정지를 유지한다. `StreamService`의 명시적 렌즈 변경 후 새 hello와 재연결도 유지한다. logical multi-camera의 물리 렌즈 변화 여부는 실장치 측정 없이는 확정하지 않는다.

Console은 관측 소스가 확인되면 좌표 표를 계속 표시한다. 유효 좌표가 없을 때는 `관측 대기 / — / — / 현재 유효한 좌표 없음`으로 바꾼다. 만료한 지도 점·좌표 수치는 즉시 제거한다. 인증 해제·뷰 초기화·라우트 없음은 표를 숨긴다. 검출 신뢰도·수명 기준은 변경하지 않는다.

카메라 목록의 순서 변경·일시 소실·빈 목록은 현재 선택을 바꾸지 않는다. 선택 source가 없으면 연결 끊김을 표시하고 영상·교정 미리보기를 지운다. 다시 연결되면 같은 source를 사용하며 다른 source는 운영자가 직접 선택한다. 최초 선택과 인증 초기화 후 선택은 첫 사용 가능 source다. source 전환에서는 진행 중 영상 요청과 관련 lease를 무효화하며 다른 source의 렌즈·제안을 사용하지 않는다.

브라우저의 표시용 교정(D-318), 승인 지도 평면 변환(D-560), 원본 warp fallback(D-515)은 각각 다른 입력·목적과 호환성 조건이 있다. 이를 촬영 제어와 합치거나 근거 없이 삭제하지 않는다. 비선형 측정 교정과 단일 remap의 통합은 D-633의 별도 구현·계약·실물 오차 검증 단계로 남긴다.

### Verification

- 좌표 표 만료 때 숨겨지는 기존 동작과 source 소실 때 다른 카메라로 바뀌는 기존 동작을 Node 시험으로 먼저 재현했다.
- 수정 후 Node 284 passed. 새 시험은 표 유지와 만료 숫자 제거, 지도 점 제거, 초기화 때 표 숨김, source 소실·빈 목록·순서 변경·재연결·명시적 전환을 검증한다.
- `b1b8214c5`: AI PC 원격 관련 pytest 151 passed, known_failures NEW 0. `26181c12d`: 실제 Chromium 시나리오 1 passed; 좌표 수신 → 만료 → 다시 수신에서 표 표시와 지도 영역 위치 유지, 만료 숫자 제거를 확인했다. harness lint 오류 0, 기존 모듈 증거 경고 25개.
- 사용자 보고의 실제 현장 발생 시각·영상·관측 시퀀스는 아직 대조하지 않았다. 소스 경로 재현은 배포나 장치 재현 증거가 아니다.

### Consequences

하단 좌표 표시가 없어도 표의 배치가 흔들리지 않는다. «위치 없음»을 명확히 표시하면서 관측 신선도를 보존한다. 촬영 설정·인식 설정·지도 승인·표시 설정을 서로 다른 권한으로 유지한다. Cam APK나 Vision 알고리즘을 이 변경에서 수정하거나 배포하지 않는다.

# D-697 독립 운영 성과 비교와 증거 생산 책임

**Status:** Accepted (2026-10-12, 설계 계약; 구현·운영 수용은 별도)

## Context

D-681의 목표는 교체 가능한 모델들이 사건 판단, 제한된 처리, 결과 확인과 개선을 맡고 사람이 최종 미해결 문제를 검토하는 것이다. 확률 JSON, 모델 간 합의, 오프라인 calibration만으로 실제 해결이나 무개입 안전성을 입증할 수 없다. D-694의 비용 근거와 D-695의 실패 분류도 독립 정답이나 운영 승격 증거가 아니다.

## Decision

운영 비교의 독립 소비자는 `learning/evaluation/decision`에 둔다. 실제 소스가 생길 때 holder와 `platform_parts.yaml` 소유자를 등록한다. Fleet은 원래 사건의 불변 export를 생산하고 평가기는 JSON 산출물만 소비한다. 루트 도구가 실행을 연결하며 learning에서 Fleet·Decision 운영 코드를 import하지 않는다. 기존 단일 프로파일 calibration API와 형식을 유지한다.

| 기존 계약 | 관계 |
|---|---|
| D-427 | operations는 사건 원장, learning은 독립 평가를 소유한다. 산출물로 연결하고 역방향 import를 금지한다. |
| D-429 | 실제 구현 holder만 등록한다. 새 최상위 폴더·비어 있는 package·크기 기준 상향으로 검사를 우회하지 않는다. |
| D-430 | 평가기는 장치 명령 권한이 없다. 운영 승격 후에도 Fleet admission과 CORE 최종 안전 검사를 유지한다. |

비교 대상은 규칙만, 기본 모델, 기본 모델+조건부 재평가의 세 전략이다. 각 전략은 정책·전략 revision과 전체 역할 프로파일 hash를 고정한다. 전략은 승인된 설정으로 식별하며 호출 횟수로 추정하지 않는다. 조건부 재평가 전략도 기본 모델 한 번만 호출할 수 있다. 단일 모델 calibration hash와 역할 쌍 hash를 혼용하지 않는다.

같은 검수 사건 집합·입력·문제 유형·관측 창·평가 한계에서 비교한다. 학습·보정·최종 평가의 recording/session ID와 원본 hash 중복, 다른 사건, 변조, 중복·누락 case, 미승인 검수 자료를 거절한다. 모델의 자체 정답이나 작성자 문자열은 독립 정답 인증이 아니다.

## 증거 생산과 의미

| 생산 책임 | 필요한 근거 | 해석 한계 |
|---|---|---|
| Fleet 원장 | 전략, 사건 scope, 판단·시도·종결, 정상 상태 미개입 | 사건 해제와 새 정상 관측은 모델의 인과적 기여를 입증하지 않는다. |
| Fleet 인수·알림 | queue, outbox, claim의 같은 snapshot export | queued, 제공자 전송 수용, 이름 있는 claim을 구분한다. 팀 수신·인증된 사람 인수는 별도다. |
| Fleet·CORE 실행 소유자 | 고정 관측 창의 제출·수용·효과 기록과 cursor/재시작/누락 범위 | 정상 상태 명령 0건은 완전한 기록 범위가 있어야 계산한다. |
| Fleet 관측 소유자 | 종결 이후 고정 추적 창과 후속 사건 연결 | 추적 창이 불완전하면 재발 없음으로 계산하지 않는다. |
| 호출·청구 근거 소유자 | 알려진 한계 비용, UNKNOWN 예약 책임, 실제 청구 근거 | 요금제 한계 비용 0과 실제 청구 미확인을 구분한다. |
| Model PC 독립 평가 | 검수 수용 manifest, 분리된 데이터, 고정 한계와 비교 보고 | 합성 시험과 관측 비교는 현장 성공·인과적 개선을 대신하지 않는다. |

해제 비율, 사건 결과 불명 비율, 재발, 정상 불필요 명령, 인수, 지연·비용을 별도 분모로 보고한다. 시도별 비용 불명과 사건별 결과 불명을 섞지 않는다. 자료·추적 범위·분모가 없으면 null과 누락 사유를 남기고 HOLD한다. 누락을 0이나 통과로 바꾸지 않는다.

## 실행 순서와 수용

1. D-696 인수 근거 생산을 기존 export의 선택적 버전으로 연결하고 같은 snapshot·scope 검증·기존 호환을 시험한다.
2. 규칙·기본 모델·조건부 검토의 실제 생산 경로와 정상 명령·재발 추적 범위를 구현한다. 쌍 프로파일 export를 복제해 규칙 기준으로 가장하지 않는다.
3. 독립 소비자와 CLI를 구현해 동일 cohort 비교, 자료 부족 HOLD, 누락·변조·데이터 누출 거절을 원격 시험한다.
4. 별도의 결정 모델 후보 계약으로 승격·복귀를 기록한다. 기존 ACT 전용 registry 계약을 범용 판정 모델로 가장하지 않는다. 메타데이터 승격, 운영 설정 readback, 새 사건의 실제 활성 revision을 각각 확인한다.

사람은 최종 미해결 사건과 평가 정답·한계의 최종 검수를 맡는다. 승인된 범위의 모델 판단·재관측·해결 단계마다 사람 확인을 요구하지 않는다. 위험 누락·관측 부족에서의 조치·다른 사건 조치·정상 불필요 명령은 수용 집합에서 0건을 요구한다. 나머지 정확도·지연 한계는 팀 검수 후 고정한다. 진행 중 사건의 프로파일·예산을 유지하고 UNKNOWN 재제출·안전 정지 해제로 증거를 만들지 않는다.

소스·원격 시험·실제 제공자·독립 품질·설치·활성화·현장 수용을 각각 기록한다. 현재 부족한 운영 증거가 채워지기 전에는 promotion과 FIELD를 HOLD한다. 전체 실행 순서는 [통합 목표 계획](../plans/2026-10-12-model-led-incident-closure.md)에 연결한다.

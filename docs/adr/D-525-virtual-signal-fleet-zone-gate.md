## D-525 가상 신호등 — 실물 신호기 없이 Fleet이 구역 입구를 신호 단계로 열고 닫고, 로봇은 D-517 통행권만 따른다

**Status:** Proposed (2026-10-08, 사용자 요청: "신호등 … 위치가 있고 … fleet 에서 보면 이를 우리가 신호등 체계로 해서 이를 화면에서 보여주고 그걸 보고 rosy pinky 가 이를 통해서 접근하고 처리", "초록색으로 나오면 그떄관제에서 받아서 로봇이 진행하면 되는거아니야?"). 문서만. 구현·SIM·DEVICE는 9항 단계로 따로 한다. CORE 계약은 바꾸지 않는다.

잇는 결정: [D-517](D-517-multi-robot-lane-traffic.md)(고정 블록·구역·CORE 통행권, 통행권은 줄지 않음, 만료하면 선다) · [D-474](D-474-caution-point-zone-grant.md)(구역 허가) · [D-443](D-443-site-device-contract.md) §1.4(실물 신호의 진입 허가 다섯 술어) · [D-337](D-337-robot-signal-source-measured-light.md)(로봇은 신호기 주장을 읽지 않는다) · [D-163](D-163-signal-observation-readonly-plane.md)(관측은 읽기 전용) · [D-12](D-12-mission-fleet.md) 신호 순서 소유자는 Fleet · [D-493](D-493-fleet-console-map-first-layout.md)(지도 먼저 화면) · [D-18](D-18-rosy-core.md)(CORE만 최종 `cmd_vel`).

### Context

2026-10-08 코드와 ADR을 다시 읽은 결과는 다음과 같다.

- **신호 체계가 둘이고 서로 잇지 않는다.**
  - Fleet `SignalConsole`(`fleet/server/signals.py`)은 ESP32 신호기(ROSY-SIGNAL-001)를 감독하고 운영자가 녹색·적색·점멸·전체 적색·자동을 누른다. 신호기는 펌웨어만 있고 굽거나 단 적이 없다. 하드웨어 없는 신호기는 시험 가짜(`test/fake_signals.py`)뿐이다.
  - CORE `traffic_policy`는 정지선 앞에서 적색이면 기다리고 녹색이면 간다. 입력은 로봇 카메라(위쪽 ROI HSV 픽셀 수)와 관측 서비스(D-337)뿐이고 기본은 `mode: DISABLED`다. 실제 정지선 인식은 흰 벽을 정지선으로 읽는다(D-474).
- **Fleet → 로봇 신호 경로는 없고, 신호기 주장을 로봇이 믿는 경로는 금지다**(D-337 1항, D-443 §1.4).
- **신호등에 위치가 없다.** Fleet 신호 설정은 `signal_id`·`base_url`·`token`·관측 주소만 가진다. 현장 지도(`map_v2_fleet`)와 Fleet 사이트 지도에 신호·정지선이 없다. 콘솔에는 옆 카드 목록으로만 보인다.
- **Rosy Cam은 신호등을 보지 않는다.** 로봇 자세만 Fleet에 보낸다. 실물 불빛이 없으면 볼 것도 없다.
- **Fleet → 로봇 "여기까지만 가라" 통로는 이미 있다.** D-517 블록 표는 구역(교차로, 수용 대수)을 가진다(`fleet/traffic/blocks.py`, 설정 `fleet.traffic.zones`). 허가하지 않은 블록 앞에서 CORE가 통행권 끝으로 선다(M2, `POST /api/v1/line-follow/authority`).

### Decision

**원칙.** 가상 신호등은 장치가 아니라 **Fleet 교통 규칙**이다. 신호 단계는 Fleet이 정하고, 그 단계가 구역 입구의 블록 허가를 막거나 연다. 로봇은 신호 색을 받지 않는다. 로봇이 받는 것은 지금처럼 D-517 통행권뿐이다. 그래서 녹색이면 Fleet이 통행권 끝을 구역 너머로 늘려 로봇이 가고, 적색이면 통행권 끝이 정지선에서 멈춰 로봇이 선다.

1. **정지선 = 구역 입구.** 신호등 하나는 D-517 구역 하나에 붙는다. 그 구역으로 들어오는 차로(접근로)마다 구역 첫 블록 경계가 정지선이다. 정지선 좌표를 따로 적지 않는다. 지도 그래프와 구역 정의에서 계산한다. CORE는 통행권 끝에서 정지 거리 d_stop(v)를 빼고 서므로(D-517 4항) 로봇 앞 끝은 정지선 앞에서 선다.

2. **설정.** 사이트 설정 `fleet.traffic.signals`에 둔다. 지도 파일과 신호기 설정(`signals.yaml`)에는 넣지 않는다.

   ```yaml
   fleet:
     traffic:
       zones:
         ring_n: [[ring_n_a, ring_n_b], 1]
       signals:
         sig_ring_n:
           zone: ring_n
           phases:                       # 순서대로 돈다
             - {approaches: [east],    green_s: 8}
             - {approaches: [ring_s_in], green_s: 8}
           yellow_s: 2
           all_red_s: 1
   ```

   - `approaches`는 구역으로 들어오는 차로 id다. 구역에 들어오는 모든 차로가 정확히 한 단계에 들어 있어야 한다. 아니면 설정 검사에서 거절한다(신호 없는 입구를 남기지 않는다).
   - 시간은 Fleet 단조 시계로 잰다.

3. **단계와 허가.**
   - 녹색인 접근로의 로봇만 그 구역의 새 허가를 받는다. 허가 순서·수용 대수·합류 최대 대기는 D-517 3항 그대로다.
   - 황색·적색·전체 적색에서는 어떤 접근로에도 그 구역의 **새** 허가를 주지 않는다.
   - **이미 받은 허가는 줄지 않는다**(D-517 4항). 녹색에 구역 허가를 받은 로봇은 황색·적색이 되어도 구역을 건너간다.
   - **다음 단계의 녹색은 구역이 비었을 때만 켠다.** 전체 적색이 끝나도 앞 단계 로봇이 구역을 점유하거나 점유가 UNKNOWN이면 전체 적색을 늘린다. 점유는 D-517 3항의 사실 판정을 쓴다. 시간만으로 비었다고 보지 않는다.
   - 전체 적색이 30 s 넘게 늘어나면 예외 큐에 올린다(D-517 5항 사람 단계).

4. **운영자 명령.** 지금 신호 카드의 동사를 가상 신호에도 쓴다(D-443 §1.3).
   - `cycle`: 2항 단계를 돈다. 기본이다.
   - `hold`: 지금 단계에 머문다.
   - `all_red`: 모든 접근로 적색. E-stop은 지금처럼 모든 신호(가상 포함)를 `all_red`로 만든다.
   - `set_aspect`(수동 녹색): 운영자가 있는 동안만 유지하고, 없어지면 `all_red`로 간다(D-443 수동 점등 유지와 같은 이유).
   - 수동 녹색도 3항의 "구역이 비었을 때만"을 지킨다. 반대편 녹색과 동시에 켤 수 없다.

5. **실패하면 적색.**
   - Fleet이 멈추거나 링크가 끊기면 통행권이 만료돼 로봇이 선다(D-517 4항). 가상 신호가 따로 할 일은 없다.
   - Fleet이 재시작하면 가상 신호는 `all_red`로 시작한다. 마지막 단계를 다시 켜지 않는다. 운영자가 `cycle`을 다시 누른다.
   - 설정 검사가 실패하면 그 구역은 늘 적색이다(입구 허가 없음).

6. **로봇 쪽.**
   - CORE는 바뀌지 않는다. `traffic_policy`(카메라 신호 판정)는 이 기능에 쓰지 않고 지금처럼 기본 꺼짐이다.
   - D-517 통행권을 받지 않는 로봇(`line_follow_authority` 없음, `hold_back`)은 M1 교차로 보류로만 선다. 이 구역에 그런 로봇이 있으면 출발을 거절한다(`TRIP_SIGNAL_NEEDS_AUTHORITY`). 보류만으로는 적색에서 멈춘다는 보장이 없다.

7. **실물 신호기와의 관계.** 나중에 실물 신호기를 같은 구역에 붙이면 Fleet 단계는 그 신호기 명령이 된다. 그때 녹색 허가는 2–3항 조건과 D-443 §1.4 다섯 술어(측정 녹색, `measured == agree`, `link ok`, 신선함, `stale_seq` 없음)가 **모두** 참일 때만이다. 이 ADR은 실물 신호기 없이 다섯 술어를 건너뛰는 근거가 되지 않는다. 가상 신호는 사람이나 로봇이 볼 불빛이 없으므로 "주장과 실제 점등이 다르다"(D-337)는 위험이 생기지 않는다. 화면의 신호 표시는 Fleet 판단을 보여 주는 것이지 측정이 아니다.

8. **화면(D-493, D-517 10항 틀 안).**
   - **관제 지도 교통 층.** 각 접근로 정지선에 짧은 가로 막대를 그리고 색을 단계로 칠한다(녹·황·적). 구역 윤곽 옆에 "가상 신호 · 녹 5 s"처럼 남은 시간을 붙인다. 색은 상태 토큰만 쓴다([D-359](D-359-theme-ready-tokens-shared-controls-and-responsive-tiers.md)). 색만으로 구별하지 않게 막대 옆에 글자(녹·황·적)를 둔다.
   - **신호 카드.** 지금 카드 목록에 가상 신호를 함께 두고 "가상" 표시를 단다. 링크·관측 칸은 "해당 없음"이다.
   - **로봇 카드 한 줄.** "신호 대기 · sig_ring_n 적색".
   - **예외 큐.** 3항 30 s 넘는 전체 적색, 5항 설정 검사 실패만 올린다. 신호 대기 자체는 정상이라 올리지 않는다.

9. **단계와 수용.**
   1. **S0 순수 계산:** `fleet/traffic/` 안에 단계 기계와 허가 막음을 둔다. 무작위 시험으로 반대 접근로 두 대가 같은 시각 구역 허가를 쥐는 순간 0, 적색 접근로에 새 허가 0, 비지 않은 구역에 다음 녹색 0을 확인한다.
   2. **S1 Fleet:** 설정 검사, 블록 표 연결, 운영자 명령, 재시작 `all_red`, 화면 8항. 가짜 로봇 2대.
   3. **S2 SIM:** 모델 PC나 관제 PC Gazebo(이 노트북 금지)에서 `map_v2_fleet` 2대, 서로 다른 접근로에서 30분. 구역 동시 점유 0, 적색에서 정지선 넘음 0.
   4. **S3 DEVICE/FIELD:** 실물 2대, 사람이 옆에서 E-stop을 쥔 채.
   - S1 이후는 D-517 M2 통행권 Safety-Review 재확인과 `fleet.traffic.authority: true`가 먼저다.

### Alternatives

| 대안 | 판단 |
|---|---|
| Fleet이 신호 색을 로봇에 보내고 CORE `traffic_policy`가 판단 | 신호기 주장을 로봇이 믿는 경로가 된다(D-337 1항). 정지선 인식도 믿을 수 없다. 기각 |
| Rosy Cam이 신호등을 보고 판단 | 실물 불빛이 없으면 볼 것이 없다. 실물 신호기를 달 때 관측(D-163) 입력으로 다시 본다 |
| 가짜 ESP32 HTTP 장치를 띄워 기존 신호 감독에 붙임 | 장치 계약(D-443)을 흉내 내지만 측정이 없어 다섯 술어를 못 넘는다. 허가에 쓸 수 없고 화면만 생긴다. 기각 |
| 신호 없이 D-517 구역 수용 1만 씀 | 지금도 충돌은 막는다. 사람이 보는 순서·시간과 운영자 명령이 없다. 신호 체계를 원하는 요청에 맞지 않는다 |

### Consequences

- 실물 신호기 없이 화면의 신호등 순서대로 로봇이 서고 간다. 로봇 쪽 계약과 코드는 바뀌지 않는다.
- 가상 신호는 D-517 M2 통행권이 켜진 현장에서만 쓸 수 있다.
- 나중에 실물 신호기를 같은 구역에 붙여도 설정 이름과 화면은 그대로이고, 허가 조건에 D-443 다섯 술어가 더해진다.
- 구역이 비지 않으면 다음 녹색이 늦어진다. 처리량보다 안전을 먼저 둔 결과다.

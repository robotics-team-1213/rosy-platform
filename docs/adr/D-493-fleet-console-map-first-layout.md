## D-493 Rosy Fleet 관제 화면은 지도가 주인공이다 — 지도 3 : 오른쪽 열 2, 예외 규칙 하나, 카메라 썸네일, 다른 문서는 머리 링크 하나

**Status:** Accepted (2026-10-07, 사용자 결정). Rosy Fleet `/console` 운용 문서의 배치와 예외 큐의 판정 규칙만 정한다. 와이어, API, 웹 경로, 저장소 키, 설치·Cell·현장 지도 문서의 내부 배치는 바꾸지 않는다.

**부분 대체:**
- D-201(예외 문법의 적합)의 "두 열은 같은 폭" 배치 시험과 "큐는 왼쪽 열 첫 행" 고정을 대체한다. 1920×1080에서 문서가 스크롤되지 않는다는 적합 계약은 그대로다.
- [D-487](D-487-site-console-displays-as-rosy-fleet-birdseye.md) 3항의 카메라 배치(지도 칸 안의 카메라 칸, 지도가 없으면 카메라가 지도 칸 전체 폭)를 대체한다. "원본은 한 번만 보인다"는 그대로다.
- D-359 US-009의 한 열 순서(예외 → 로봇 → 지도 → 카메라 → 대형)는 그대로다. 발행 띠가 로봇 목록 머리로 들어갈 뿐이다.

잇는 결정: D-153 · D-159 · D-201 · D-359 · D-410 · D-415 · D-421 · [D-487](D-487-site-console-displays-as-rosy-fleet-birdseye.md).

### Context

2026-10-07 impeccable critique(dual-agent, 20/40)가 main `646fe2969`의 관제 화면을 평가했다. 사용자는 "중복된 정보, 위계 없는 정보, 탭 같은 레이아웃부터" 잡으라고 했고, 범위를 1920 구성까지(1+2단계), 카메라는 보는 용도의 썸네일로 골랐다.

평가가 찾은 것:
- **P0** 예외 큐와 로봇 카드가 다른 규칙을 썼다. 큐(`roster.js` `fillQueues`)는 오프라인·상태 없음·판단 요청·위치·HITL·성능 저하만 보았고, 카드의 "주의" 보기(`needsAttention`)는 비상 정지, 목표 실패, 교통 대기, 양보, 릴레이 증거까지 보았다. 그래서 카드에 빨간 "릴레이 끊김"이 붙은 로봇이 있어도 큐는 숨었다.
- **P1** 1920에서 지도가 약 440px(화면의 11%)였고 같은 크기의 카메라가 옆에 섰다. 그 아래와 신호등·기록 칸이 비었다.
- **P1** 화면 위 두 줄이 조작이 아니었다. 처음 한 번 하는 설치 순서(1 관제 접속 … 4 시작점 설정)가 운용 화면 맨 위에 있었고, 대기열이 없는 Fleet에서는 "발행 제어 미설정" 띠가 늘 섰다. 전체 주행 취소가 비상 정지 다음으로 가장 밝은 버튼이었다.
- 다른 문서로 가는 길이 넷이었다(설치 순서 2단계, "…은 설치·보정 화면에서 합니다" 문장 셋). Cell 링크는 DOM 노드 둘이었다.

### Decision

#### 1. 예외 규칙은 하나다

`roster.js`의 `attentionItems(robot)`이 로봇마다 `{severity, text}` 목록을 낸다. 예외 큐는 그 목록을 그대로 행으로 쓰고, 카드의 "주의" 보기는 `attentionItems(robot).length > 0`(또는 Fleet 상태 확인 불가)이다. 두 곳이 다른 규칙을 다시 갖지 않는다.

| 근거 | 큐 |
|---|---|
| 오프라인, 상태 없음 | 주의 (이 둘이면 다른 행 없음) |
| 차선 추종 판단 요청, 위치 확인 필요, HITL 개입 요청 | 최우선 |
| 성능 저하 | 주의 |
| 릴레이 증거 crit(끊김) / warn(지연·증거 없음) | 최우선 / 주의 |
| 비상 정지 걸림, 정지 상태 미확인, 목표 실패, 교통 대기, 양보 | 주의 |

빈 큐는 지금처럼 숨는다(D-159, D-82). 한 로봇이 여러 행을 가져도 큐 머리의 이름은 한 번이다.

#### 2. 배치 (64rem 이상)

- `main`은 `minmax(0, 3fr) minmax(0, 2fr)`이다. 왼쪽 열은 현장 지도 하나이고, 지도는 첫 화면 높이를 채운다(`max(20rem, 100dvh − 17rem)`, 접속 안내 띠가 보이면 그만큼 줄인다).
- 오른쪽 열 순서: 예외 큐 → 등록 로봇(머리 줄에 발행 띠·전체 주행 취소) → 관제 카메라(썸네일) → 대형·신호·기록.
- 지도 칸 아래는 두 줄을 넘지 않는다: 범례와 배경 다시 학습 한 줄, 접힌 시작점 설정·관제 범위 안내 한 줄.
- 110rem 이상에서 대형·신호·기록은 대형 왼쪽, 신호등·진단·기록 오른쪽이다. 기록은 3–8줄이고 지우기는 기록 머리 줄에 선다.
- 큐 제목 "주의 및 개입 요망"은 화면 읽기용으로만 남는다. 두 분류 머리(주의 요망 n, 최우선 개입 요망 n)가 같은 말을 한다.
- 64rem 미만은 D-359 US-009 순서 그대로다.

#### 3. 천장 카메라는 한 번에 한 곳에만 보인다

- 평소에는 오른쪽 열 썸네일(높이 11rem)이다.
- 지도가 없을 때(접속 전·지도 없음·대기)는 지도 칸이 같은 프레임(`#map-birdseye`)을 보이고 썸네일 영상은 접힌다. 빈 지도 안내는 영상 위 한 줄이다.
- 지도가 있을 때 "크게 보기"(`#birdseye-toggle`, `aria-pressed`)를 누르면 지도 칸이 영상으로 바뀐다. 다시 누르면 지도로 돌아온다. 영상이 없으면 버튼은 "영상 대기" 사유와 함께 잠긴다.
- 보정 맞춤이 있으면 지도 캔버스가 프레임을 바닥에 그린다(그대로).

#### 4. 위 두 줄과 다른 문서로 가는 길

- 설치 순서 막대(`#console-workflow`)는 운용 문서에서 빠진다. 접속은 접속 안내 띠가, 보정·시작점은 각 자리(설치·보정 문서, 지도 칸의 접힌 시작점 설정)가 맡는다. 설치 순서를 설치 문서의 단계 탭으로 옮기는 것은 이 ADR 범위 밖이다.
- 발행 띠는 로봇 목록 머리로 간다. 발행 제어가 없거나 확인 중이면 글 없이 전체 주행 취소 버튼만 선다. 알릴 상태(허용·재시작 대기·래치 차단·확인 실패)가 있으면 머리 아래 한 줄을 쓴다(`data-state`).
- 전체 주행 취소는 `kind="quiet"`이다. 가장 큰 빨간 동작은 비상 정지 하나다.
- 다른 문서(설치·보정, 현장 지도 편집, Cell 작업)로 가는 링크는 머리의 접힘 칸 안에 하나씩이다. 본문의 "…에서 합니다" 문장과 기기 연결 안내 칸은 없앤다.

### Consequences

- 교통 대기·양보도 주의 큐에 오른다. 예외가 많은 현장에서 큐가 길어지면 큐 안에서 스크롤한다(높이 상한 그대로).
- 1366×768 노트북에서는 오른쪽 열이 한 화면보다 길다. 선언 뷰포트는 1920×1080 관제 PC와 390/320 모바일이다(PRODUCT.md).
- 비평의 나머지(문서 공용 탭, 설치 순서 탭, Cell 셸 통일, 운용자/운영자 어휘, 로그인 뒤 토큰 칸, 대형 릴레이 행과 카드의 엇갈림, 시작점의 설치 이동)는 다음 단계다.

## D-1090 영역별 파일 수 상한과 저장소 밖 증거 (D-226 4항 개정)

**Status:** Accepted (2026-11-28, 사용자 승인 "좋아": 네 입장 병렬 토론 결론 1단계와 작업마다 문서를 쓰는 규칙 축소). 구현은 이 ADR과 같은 PR이다.

| 결정 | 관계 |
|---|---|
| [D-226](D-226-document-placement-and-publication-criteria.md) | 4항을 개정한다. 날짜 증거의 기본 위치가 `docs/validation/`에서 `$ROSY_SCRATCH`와 PR 본문으로 바뀐다. |
| [D-766](D-766-size-limits-split-on-exceed.md) 줄 수 상한 | 지킨다. 줄 수 상한은 그대로 두고, 그 상한이 만든 파일 수 증가를 이 ADR이 막는다. |
| D-427·D-429·D-430 | 지킨다. 폴더 배치와 안전 경로는 바꾸지 않는다. 시험 하나와 문서 규칙만 더한다. |

### Context

2026-11-28 측정(origin/main cd65c8970b): 추적 파일 13,542개. 최근 30일에 3,270개가 추가되고 230개가 삭제되어 약 3,040개(22%)가 순증했다. 줄 수 ratchet(D-766)은 비었다. 그러나 600줄 상한이 파일을 쪼개게 만들었고, 전체 개수에는 예산이 없다. 같은 30일 신규 문서는 `docs/solutions` 165개, `docs/adr` 139개, `docs/validation` 101개다. 작업마다 날짜 증거와 교훈을 새 파일로 쓰는 규칙이 가장 큰 원천이다. 네 입장(삭제·경계·절차·점진) 병렬 토론은 "유입부터 막는다"를 1단계로 정했다.

### Decision

1. **파일 수 상한.** `test/architecture/test_file_count_budget.py`의 `CAPS`가 추적 파일 50개 이상인 영역(최상위 폴더, `docs`는 하위 폴더)마다 상한을 둔다. 상한은 측정값에 여유를 더한 값이다. 코드 영역은 쪼개기용으로 20, `docs/adr`·`docs/solutions`는 진행 중 PR용으로 10, `docs/validation`·`docs/plans`는 0이다. 상한을 넘으면 실패한다. 같은 영역에서 지우거나 합치거나, 같은 PR에서 상한을 올리고 본문에 `Budget-Raise: <영역> +N (이유)`를 적는다. 여유가 40을 넘으면 상한을 내리라고 경고한다.
2. **증거는 저장소 밖.** 날짜 증거(로그·캡처·실행 결과)는 `$ROSY_SCRATCH/<topic>/`과 PR 본문에 둔다. README·STATUS·모듈 문서가 수용 근거로 링크해야 하는 기록만 `docs/validation/`에 둔다. 이때도 같은 주제의 기존 기록을 먼저 갱신한다.
3. **교훈은 갱신이 기본.** `docs/solutions`에는 같은 원인의 교훈이 없을 때만 새 파일을 만든다. 상한에 닿으면 기존 교훈을 합친다.

### Consequences

- 새 날짜 증거를 `docs/validation`에 더하는 진행 중 PR은 이 PR 뒤 큐에서 실패한다. 증거를 PR 본문으로 옮기거나 기존 기록을 갱신한다.
- 상한을 올리는 일은 막지 않는다. 다만 diff와 PR 본문에 드러난다.
- 하지 않은 것: 기존 문서 은퇴, AGENTS.md 반복 틀 정리, land 도구 정리, fleet 경계 재정렬. 토론 결론의 2·3단계로 따로 낸다.

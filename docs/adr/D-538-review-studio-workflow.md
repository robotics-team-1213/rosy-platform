## D-538 객체·픽셀 검수 스튜디오는 같은 작업 순서와 단축키를 보여주되 독립 결정을 유지한다

**Status:** Accepted (2026-10-09, 사용자 검수 스튜디오 흐름·ADR 지시; SOURCE/브라우저 검증과 모델 PC 적용은 별도 증거).

### Context

같은 사진의 객체 박스와 픽셀 마스크를 검수하지만, 화면마다 다음 행동을 찾는 위치가 다르다. 객체 모델 초안은 접힌 영역에 숨어 있었고, 픽셀의 큰 안내문은 사진을 밀어냈다. 초안·저장·승인 상태가 서로 다른데 같은 버튼으로 오인하면 미검수 자료가 정답처럼 보인다. D-461의 작업 우선 화면, D-462의 독립 revision, D-514의 작업별 클래스 의미를 실제 연속 검수에 맞춰 연결한다.

### Decision

1. **공통 작업 순서:** 두 화면 상단에 `사진 선택 → 초안 비교 → 수정·저장 → 전체 확인·결정`을 짧은 한 줄로 표시한다. 현재 단계와 다음 행동은 실제 저장·확인 상태에서 파생한다. 사진과 도구를 가리지 않도록 한 줄은 줄바꿈할 수 있지만 큰 리본이나 별도 마법사로 만들지 않는다. 원본·초안·저장된 결과를 구별하고, 미적용 초안 미리보기는 서버 결정을 바꾸지 않는다.
2. **저장 방식은 작업별로 명시:** 객체 박스 이동·그리기·클래스 변경은 기존 version CAS로 자동 저장한다. 픽셀 점·영역·브러시는 미리보기/로컬 획을 적용한 뒤 `초안 저장`을 명시적으로 누른다. 저장 실패·다른 탭 충돌 때에는 다음 단계나 승인을 완료로 표시하지 않는다. 다른 사진으로 이동하기 전에 픽셀 미저장 획을 처리한다.
3. **결정은 각각 독립:** 객체 승인에는 모든 박스의 클래스와 사진 전체 확인이 필요하다. 픽셀 승인에는 저장된 마스크, 사진 전체·기본 배경 확인, 작업 공간의 255 규칙 충족이 필요하다. 한쪽 승인으로 다른 쪽을 승인하지 않는다. 새 초안을 적용하거나 라벨을 수정하면 이전 승인은 해제된다. 불확실한 영역/사진은 대기, 검수 범위에서 뺄 것은 해당 작업의 제외로 남긴다. 빈 객체 초안도 사람의 사진 전체 확인 없이 승인하지 않는다.
4. **연속 검수:** 사진 목록/썸네일에서 선택하거나 이전·다음으로 이동한다. 결정 뒤에는 `다음 검수 대기`를 이용한다. 자동 다음 이동은 서버 결정 성공과 최신 상태 확인 뒤에만 허용하며, 실패·충돌·미저장 초안에서는 현재 사진에 머문다. 대량 자료를 일괄 승인하지 않는다.
5. **키보드 계약:** 두 화면에서 `←/→` 사진 이동, `N` 다음 대기, `V` 명암 보기, `1–9` 현재 작업 클래스, `C` 전체 확인, `A` 승인, `X` 대기 중 제외, `?` 단축키 안내를 같은 뜻으로 쓴다. 픽셀 전용 `B` 배경 확인, `T` 점/브러시, `P` 영역, `Enter` 선택 적용, `[`/`]` 반지름을 안내한다. 객체의 `Delete`는 선택 박스만 삭제한다. `A`는 확인 체크를 대신하지 않고, 비활성 버튼을 우회하지 않는다. 입력·선택 중, IME 조합 중, Ctrl/Alt/Meta 조합 중에는 단축키를 실행하지 않는다. 안내는 버튼과 키보드로 열 수 있다.
6. **클래스와 학습 경계:** 객체 클래스셋과 픽셀 클래스셋은 별도이며 화면은 각 작업의 현재 셋만 보여준다(D-485, D-514). 255는 픽셀 미검수 값이지 클래스가 아니다. AI/모델 제안은 출처가 있는 검수 초안이며 승인·학습 데이터·`v13-drivable` 모델이라고 표시하지 않는다. 승인 자료 준비, 최신 결정 대조, 학습 수용, 모델 접수·섀도·주행 사용은 각기 별도 단계다(D-464, D-532).

### 검증 시나리오

| 경우 | 기대 결과 |
|---|---|
| 객체 초안이 없는 사진 / 미적용 모델 초안 사진 | 빈 상태 또는 점선 제안을 보며 박스를 추가·적용·수정하고 저장 출처를 확인한다 |
| 픽셀 미저장 획 / 255 잔존 | 초안 저장과 전체 확인을 구별하며 승인 불가 이유가 보인다 |
| 같은 사진의 객체 승인 / 픽셀 대기 | 객체만 승인으로 표시되고 픽셀은 그대로 대기다 |
| 다른 탭 수정 / 서버 거절 | 현재 사진에 머물며 충돌·실패가 표시되고 승인은 발생하지 않는다 |
| 1600×1000 및 좁은 화면, 연속 키보드 검수 | 사진과 현재 단계가 함께 보이고 입력 칸·IME에서는 키가 오작동하지 않는다 |

SOURCE/호스트 테스트, 실제 브라우저 저장·승인 시험(별도 test state), 모델 PC 배치·readback, 사람의 정답 판단, 학습 실행·수용을 각각 증거로 기록한다. 운영 자료의 미검수 초안을 검증 목적으로 승인하지 않는다.

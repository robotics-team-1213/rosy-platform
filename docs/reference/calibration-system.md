# 보정 체계 — 코드 · 화면 · 절차 · 이력

English: [calibration-system.en.md](calibration-system.en.md)

상태: 기준일 11-20 · 코드 모듈 22개 · 보정 작업 27건 · 화면은 샘플 데이터

## 1. 요약

핵심 결론: 보정 앱·엔진·현장 자동화를 한 경로로 묶었다.
보정 앱과 Fleet 화면이 요청·답·승인을 다룬다. 엔진이 측정·판정·기록을 파일로 남긴다.
10-19부터 11-18까지 보정 작업 27건을 했다. 천장 카메라·셀 높이·관절 게인·TCP 값을 새로 잰다.
천장 자동 트랙 보정이 2분 간격으로 돈다. 사람은 판정과 승인만 맡는다.
남은 일은 top 렌즈 K 정본·arm_a 팔레트 재보정·단 높이별 실물 검증이다.

## 2. 흐름

![그림 1 [화면] 보정 흐름: 사람·엔진·화면·타이머](../assets/calibration/flow-calibration.png)

그림은 보정 흐름의 사람·엔진·화면·타이머 역할과 순서를 보여 준다. 사람 승인 항목은 화면 요청으로 열린다.

1. (사람) 준비를 한다. 인쇄 마커 부착과 ChArUco 판 들기를 한다.
2. (엔진) 측정을 한다. cell_depth.py·cell_frame.py·cell_calibrate.py가 실측을 한다.
3. (엔진) 팔 동작은 감독 시험으로만 한다. 사람이 동작마다 스위치를 확인한다.
4. (엔진) 결과 파일을 쓴다. calibration_path JSON·bias.json·카메라 모델 JSON이다.
5. (엔진) 판정을 한다. cell_calibrate.py check가 남은 할 일 목록을 낸다.
6. (엔진) 사람 확인 항목을 요청으로 연다. cell_requests.py가 후보마다 예측값을 적는다.
7. (화면) 요청 목록과 그림을 보여 준다. 보기에는 site 로그인 세션이 필요하다.
8. (사람) 로그인해 답을 입력한다. 답에는 calibration.operate 권한이 필요하다.
9. (화면) cell_requests.answer만 부른다. by는 세션 이름이다. 파일을 직접 쓰지 않는다.
10. (엔진) 반영은 해당 단계의 재실행으로 한다. 사람이 숫자를 손으로 고치지 않는다.
11. (타이머) 천장 자동 트랙 보정을 2분마다 돌린다. Fleet에 갱신을 요청한다.

## 3. 안전 경계

경고: 팔이 움직이는 단계는 D-911 감독 시험이다. 동작마다 사람이 스위치 옆에 있는지 확인한다. person_at_switch가 없으면 서버가 422로 거절한다.

경고: 가드 한계를 넓히는 일반 설정을 만들지 않는다. 계획 바닥 낮춤은 사람이 승인한 low_zones 사각형에만 허용한다.

주의: 숫자를 손으로 고치지 않는다. 다시 재야 하면 해당 단계를 다시 돌린다.

주의: 화면 쓰기 경로는 같은 출처와 calibration.operate 권한을 요구한다. by는 세션 이름이 온다.

주의: Fleet 보정 화면의 값은 표시 전용이다. sighting·CameraMap·주행에 넘기지 않는다.

주의: 자동 트랙 보정은 보정·지도 기록만 바꾼다. 이동 명령은 없다.

## 6. 보정 종류별 절차와 수용 기준

### 6.1 셀 6단계(장치·높이·카메라 모델·면·관절 게인·점검)

- 입력: 셀 설정 JSON. D435 Z16 프레임과 컬러 프레임. 세션 caps.json. FK 점의 집게 마커 사진.
- 출력: 테이블 면·깊이↔색 정렬·면 높이·팔 판 FK 영점. 카메라 자세와 마커 위치. 하중 관절 I 게인. check 결과 JSON.
- 수용 기준(숫자): 장치 문제 0개. 계층 검사 rms 1.5 px 이하. 최대 2.5 px 이하. 높이 오차 1.5 mm 이내. 관절 I 게인 50. 게인 없을 때 TCP 오차 12.3 mm, 있을 때 3.3 mm. check 남은 할 일 0개.
- 담당 파일: `cell_depth.py` `cell_frame.py` `cell_calibration.py` `cell_calibrate.py` `SKILL.md`

### 6.2 ChArUco 렌즈

- 입력: 인쇄 판 7×10칸·칸 20 mm·마커 15 mm·DICT_4X4_50. 실측 50 mm 막대 길이. RGB 프레임.
- 출력: K·왜곡·해상도 JSON. 원본 프레임 폴더와 출처 영수증.
- 수용 기준(숫자): 프레임 30장 요청. 유효 영상 25장 이상. 재투영 RMS 0.5 px 이하. 미달 시 accepted false와 종료 코드 1.
- 담당 파일: `cell_checkerboard.py` `applications/calibration/README.md`

### 6.3 천장 카메라 지도 맞춤·자동 트랙 보정

- 입력: 차선 페인트 호모그래피 제안. 코너 4점 시계열. Fleet 현재 보정. 인증 토큰.
- 출력: 승인 판정 JSON. Fleet 보정·지도 갱신 요청. 상태 파일.
- 수용 기준(숫자): 코너 이동 0.015 m 초과 시 보정 갱신. 장소 오차 0.012 m 초과 시 지도 갱신. 표본 5개. 퍼짐 0.025 m 이하. 승인 간격 600 s 이상.
- 담당 파일: `deploy/site/rosy-auto-track-calibration` `host-state/rosy-auto-track-calibration.timer` `map-fit-view.js` `field-view.js` `field-layers.js`

### 6.4 측정 보정 기록(measured calibration)

- 입력: 렌즈·바닥 후보. 학습 영상 해시 8개 이상과 검증 해시 2개 이상. 측량 해시. 촬영 서명과 회전.
- 출력: rosy.measured-calibration/1 번들과 sha256 digest. D-47 저장소 기록·이벤트.
- 수용 기준(숫자): 후보는 미적용 상태. revision이 내용 해시와 일치. 번들 digest가 전체 내용과 일치. 크기 200000자 이하. 바닥 inlier 4~10000개. 수용은 사람이 한다.
- 담당 파일: `measured_calibration.py` `calibration_store.py` `measured-calibration-view.js`

### 6.5 팔 리스 보정 작업(D-1035)

- 입력: cells.json(tools·python·work·arms). POST 본문 arm·step·targets·person_at_switch.
- 출력: 202 응답과 jobs 기록 JSON·로그. assessments.jsonl. incident 해제.
- 수용 기준(숫자): step은 4종만 허용. 이동 단계는 person_at_switch true 필수. 리스 만료 1800 s. 해제는 600 s 안의 clear 판정 필요. 근거는 frame·joints 해시 일치.
- 담당 파일: `calibration_jobs.py` `calibration_web.py` `cell_calibrate.py` `cell_arm_lease.py`

### 6.6 현장 절차(사람/도구 구분)

셀 팔(OMX) 보정. 순서는 D-951이 정한다. 각 단계의 결과는 파일로 남는다.

경고: 팔을 움직이는 단계는 사람이 스위치 옆에서 매 동작을 확인한다(D-911).

1. (사람) D-933 인쇄물을 100% 무광으로 인쇄한다.
2. (사람) 50 mm 막대로 인쇄 크기를 확인한다.
3. (사람) 집게·베이스에 마커를 붙인다.
4. (사람) 벨트·팔레트에 면 마커를 넷씩 붙인다.
5. (도구) 장치와 카메라를 점검한다(omx_devices scan, omx_cameras).
6. (도구) 테이블 평면을 구한다(cell_depth).
7. (도구) 깊이와 색 영상을 정렬한다.
8. (도구) 각 팔의 판 높이와 면별 surface_z를 낸다.
9. (도구) 마커로 카메라 모델을 만든다(cell_frame learn/check).
10. (사람) 바닥을 낮출 사각형과 값을 승인한다(low_zones).
11. (세션) 손목·팔꿈치에 I 게인 50을 쓴다. 끝나면 되돌린다.
12. (도구) 지도를 한 점 빼기로 확인한다(cell_calibrate check).
13. (도구) LOO 15 mm를 넘으면 저장을 거부한다.
14. (사람) 줄자·눈으로 판정 대상 값을 잰다. 도구는 후보별 예측값을 미리 적는다.
15. 판정 기준은 평균 3 mm 이하다.

영점 절차. 11-18 패널 판정이다. 11-19 기준 구현은 브랜치 단계다.

1. (사람) base 마커 2개를 90 mm 이상 벌려 붙인다.
2. (사람) 마커의 팔 좌표를 자로 잰다(오차 0.3 mm 이하).
3. (도구) 카메라 이름마다 자세를 촬영한다.
4. (도구) base 마커 PnP로 시드를 잡는다.
5. (도구) 영점 5개와 카메라 6자유도를 푼다.
6. (도구) 예측 σ를 0.25° 관문에 대조한다.

천장 카메라 보정.

1. (사람) 트랙 전체가 보이게 카메라를 놓는다.
2. (도구) Fleet 추적 API로 camera null을 확인한다.
3. (도구) 승인 보정을 영상에 겹쳐 어긋남을 본다.
4. (도구) 콘솔 맵 자동 맞춤을 시도한다. 옛 도면이라 도구가 0.50으로 거절한다.
5. (도구) 현재 프레임을 world_261026 도면에 정합한다(`rosy_vision.map_register`).
6. (도구) 주차 구역(y 0.20 m 초과)을 도면에서 뺀다.

# Rosy World Parallel Training & Real Fleet Closed-Loop Contracts

## Symptoms & Root Causes Verified Under Real Execution

1. **`world_train_parallel.py` passing `--concurrent` to sequential MuJoCo teacher tasks (`KeyError: 'zones'`)**
   - `omx_two_arm_teacher.py run <task> --concurrent` routes through `omx_two_arm_teacher_stages.run_concurrent_steps()`, which accesses `s["zones"]`. Default tasks (`stack`, `rehandle`, `outbound-stand`) do not carry `zones` unless generated by the zone planner (`plan` / `omx_two_arm_chain.py`).
   - **Fix**: Removed unconditional `--concurrent` from `tools/sim/world_train_parallel.py` and exposed opt-in `--mujoco-concurrent`.

2. **ACT GPU lease lock (`GpuBusy`) during multi-node parallel runs**
   - `learning/training/omx/experiment_train.py` enforces an exclusive `fcntl.flock` on `~/.cache/rosy-learning/gpu.lock` plus `nvidia-smi` compute PID check before running with `device="cuda"`. A host whose CUDA compute context has not started yet can still hold `gpu.lock` for an active Isaac/learning session.
   - **Fix / Rule**: Respect `gpu.lock` (never override or unlink it); select `device="cpu"` on busy-lease hosts when validating telemetry streaming alongside MuJoCo physics.

3. **Real Fleet <-> Virtual CORE HTTP/TLS Contract**
   - **`navigation` type contract**: CORE `/api/v1/robot/state["navigation"]` must be a string enum (`IDLE`, `NAVIGATING`, `ARRIVED`, `CANCELED`, `FAILED`), whereas `GET /api/v1/navigation/state` returns the detailed object. Returning a dict from `/api/v1/robot/state` breaks Fleet ingestion.
   - **Startup dispatch interlock**: `FleetTaskService` initializes `dispatch_enabled = 0` (`close_dispatch_for_startup`). Goals queue as `QUEUED` until `GET /api/fleet/dispatch-control` + `POST /api/fleet/dispatch/rearm` with `{"expected_generation": N}`.
   - **Traffic keep-out margin (`YIELD_KEEP_OUT_M = 0.45 m`)**: Fleet checks route clearance against all 6 registered entities including stationary OMX arms (`arm_s/a/b`). Goals whose path passes within 0.45 m of arms trigger `_make_room` -> `501 NOT_SUPPORTED`; south-lane goals (`y = -0.207`, `x = -0.1914`) stay >= 0.818 m clear and dispatch cleanly.
   - **E-Stop cache TTL**: `SharedGather` caches `/api/fleet/state` for 1.0 s. Automated checks after `POST /api/fleet/estop` must poll past 1.2 s before asserting propagated state.

4. **Legacy Docker Builder & `fleet.cli console` Startup Flags**
   - Without BuildKit (`docker buildx`), `docker build -f deploy/site/Dockerfile.fleet` uses repo root `.dockerignore` (which excludes `operations/fleet/`) instead of `deploy/site/Dockerfile.fleet.dockerignore`. Legacy CI/local builds without BuildKit need `Dockerfile.fleet.dockerignore` active as `.dockerignore` in the build context.
   - `applications/world/Dockerfile` sets `WORKDIR /world` without baking bundle files into the image; containers require mounting the bundle to `/world` (or copying in a derived Dockerfile).
   - Passing `--sightings-config` to `fleet.cli console` enforces at least one camera source (`validate_sighting_config`), whereas virtual closed-loop stacks without cameras omit `--sightings-config` and `--sightings-db` as in `deploy/site/compose.virtual-closed-loop.yaml`.

5. **2-Row Pinky Cargo Tray & 9x3x3 Ship CAD Physical Envelopes**
   - Extending Pinky's rear tray to 2 horizontal 90x30x32.4 mm rows (`pinky-tray-j-v4-2row`, 8.0 mm inter-container jaw gap) adds +18.8 mm rear overhang behind `J-v3` (`x_min: -134.0 -> -152.8 mm`, rotation radius `160.77 mm`). Sideways printing stays support-free (`support_free_violations == 0`) by using a 45-deg self-supporting upper retaining wedge (`+x_dock`) rather than square cantilevered walls. Existing station v3.4 stop walls and outbound stand v6 require matching setback.
   - `compact-ship-r08` (`config="three_hold"`, 414 mm, 27 containers) puts Holds 1-2 (18 slots) inside conservative 230 mm radial OMX reach while Hold 3 (9 slots, 231..268 mm) requires berth longitudinal slide or mobile shuttle transfer.

6. **Live Site Host Rollout (`rosy-fleet-r`) Overlay & Firewall Contracts (`deploy/site/compose.world.yaml`)**
   - **`registry_token` 401 vs viewer token**: `site-update-registry` `registry_token` is rejected (401) by Fleet `/api/fleet/state`. Co-located `world-real-bridge` uses dedicated read-only secret `world_fleet_viewer_token` (`0440 root:rosy-fleet`, copied from `site-update-viewer.token`).
   - **`rosy-world-advertise.service` boot failure on tmpfs**: `/run/rosy-site` is tmpfs, so `world-public.env` may not exist before stack startup. Setting `Environment=ROSY_WORLD_PORT=8140` + `EnvironmentFile=-/run/rosy-site/world-public.env` lets `_rosy-world._tcp` start reliably across reboots.
   - **`site_backend` `internal: true` blocks host port `8140`**: Attaching `world` only to `site_backend` keeps port `8140` unbound on the host. `world` must join `[site_backend, site_edge]`.
   - **`ROSY-SITE-INGRESS` drops container hairpin & named-volume root ownership**: `mangle PREROUTING` `--dport 8443` runs `-m addrtype --dst-type LOCAL -j DROP` before `-i br+ -j RETURN`, so a co-located container fails dialing `rosy-fleet-r.local:8443` (`Errno 101`/drop). Co-located `world-real-bridge` dials `https://fleet:${ROSY_FLEET_PORT:-8080}` over `site_backend` (verified via `site_ca`), while off-host `applications/world/compose.yaml` keeps `--fleet-mdns-host`. Because `applications/world/Dockerfile` omits `/var/lib/rosy-world/worlds`, a named Docker volume mounts `root:root` (`PermissionError`); mounting it as `tmpfs` (`uid=10001,gid=10001`) works portably without root chown.

# OMX 서보 모델 실험: Dynamixel PID로 실물 에피소드 재생 (2026-11-09)

[첫 맞춤 기록](../omx-sysid-2026-11-09/result.md)의 후속. 지금 후보들은 MuJoCo 위치 서보(PD)에 이상 중력 보상을 얹어 I 이득을 흉내 낸다. 여기서는 몸통 관절을 실물 서보 그대로 굴렸다: PWM = P/128·e + I/65536·Σe + D/16·Δe(틱, 1 kHz), PWM_Limit에서 자름, 토크 = PWM/885 × 정지 토크 − 역기전력(정지 토크/무부하 속도 × ω), XL330은 Current_Limit에서 자름. 이득·한계는 arm_b 세션 caps(`caps-arm-b-wrist400-20261103.json`), 수동 감쇠·마찰은 `servo-friction-20261109`. 스크립트 `evidence/dxl_replay.py`(AI PC, 11-03~07 에피소드 27개, 보류 11개).

| 모델 | 보류 평균 (°) | 관절별 |
|---|---|---|
| servo-friction-20261109 (PD + 모든 관절 중력 보상) | 0.410 | 0.317 / 0.37 / 0.527 / 0.525 / 0.313 |
| Dynamixel, 레지스터 그대로 | 0.447 | 0.317 / 0.582 / 0.511 / 0.489 / 0.334 |
| Dynamixel, XL430 공통 ×1.5 (맞춤 세트 최적) | 0.424 | 0.345 / 0.440 / 0.514 / 0.489 / 0.334 |
| Dynamixel, joint2만 P ×2 | 0.411 | 0.317 / 0.404 / 0.512 / 0.489 / 0.334 |

- 가짜 중력 보상 없이 I 이득 관절(joint3·joint4)은 더 잘 맞는다(0.527→0.511, 0.525→0.489). XL330 데이터시트 값은 그대로가 가장 좋다(×0.5~2 중 ×1).
- joint2만 실물이 레지스터 계산보다 2~4배 단단하다(평균 편향 +0.35°가 ×4에서 0). joint1은 ×1이 가장 좋으므로 XL430 공통 환산 오류가 아니다. 남은 후보: 모델의 팔 질량(URDF)이 실제보다 커서 joint2 중력이 과대, 또는 실제 joint2 P 레지스터가 caps와 다름. 레지스터를 팔에서 읽거나 joint2 램프(`cell_step.py`)로 가른다.
- D 이득은 ×0.25~×4로 바꿔도 거의 같다(에피소드로 정해지지 않음). 실제 값은 arm_b 레지스터 기록(11-08 probe)에서 XL430 P 640·I 0·D 3600, XL330 P 400·D 0이다(가정 4000을 3600으로 고쳤고 `registers-20261109`의 kv가 0.50→0.47). 세션 중에는 caps가 joint2 P 1600, joint3·joint4 I 50을 얹는다. 그러므로 joint2가 더 단단한 원인으로 '레지스터가 caps와 다름'은 세션 중 값을 읽어야만 배제된다.
- 결론: 물리적으로 더 맞는 구조지만 점수는 기존 최선과 같다(0.411 대 0.410). 월드에 넣으면 매 단계 파이썬 서보 계산이 들어가 두 팔 학습 월드가 느려지므로 지금은 월드를 바꾸지 않았다. joint2 원인이 정해지면 다시 본다.

에피소드 재생이며 실물 수용이 아니다. 11-08 전 에피소드는 어느 팔인지 적혀 있지 않다.

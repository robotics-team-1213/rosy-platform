# 10/6·10/7 주행영역 후보의 로봇 몸체 경로 대조

**판정: 정면 근접 수치는 주행 불가 정답이 아니다. 주행 허용 HOLD.** [앞선 후보 대조](../drivable-lidar-candidate-2026-10-08/result.md)는 영상의 넓은 `drivable` 후보와 정면 LiDAR의 0.30 m 미만 반환이 동시에 나온 프레임을 찾았다. 벽이 로봇 옆에 있을 수 있으므로, 이번에는 같은 스캔을 제품의 `body_path_gap`에 넣어 **가정한 직진 경로**에서 몸체가 처음 닿을 때까지의 거리를 계산했다. 벽/바닥의 픽셀 정답이나 실제 CORE 주행 판정으로 사용하지 않는다.

## 입력과 재현

- 원본은 10/6·10/7의 네 MCAP에서 추출한 비디오 sidecar 및 LiDAR `.scan.npz`다. 원본은 X:에 유지하고, 이전 분석의 [해시와 프레임 수](../drivable-lidar-candidate-2026-10-08/evidence/summary.json)를 [분석 코드](evidence/analyze.py)가 다시 확인한다. 모델의 `per_frame.jsonl` 두 파일도 이전 해시와 대조한다. 입력 내용과 추출 대응은 이전 증명에 따른다.
- 코드 기준은 로컬 `b23055884`의 `front_sector`, `scan_points`, `body_path_gap`, `stop_gap_m`이다. Pinky Pro 설정의 LiDAR 전방 180°, LiDAR x = −0.017 m, 몸체 전방 x = 0.04205 m, 후방 x = −0.076 m, 반폭 0.05655 m, 회전 반경 0.08257 m를 썼다. 실제 장치 mount 보정의 현장 측정치는 아니다.
- 이전과 동일하게 영상 시각 대비 스캔 나이가 0~0.15초이고 전방 ±20° 빔의 70% 이상이 유효할 때만 계산했다. 영상 3,336프레임 중 2,621프레임이 이 필터를 통과했다. 나머지는 자유 공간이 아니라 **미평가**다.
- 반례 확인용으로 직진 0.08 m/s, 각속도 0, 경로 길이 0.40 m를 가정했다. 기본 설정의 margin 0.02 m, 지연 0.15초, 감속 0.5 m/s²를 `stop_gap_m`에 넣은 정지거리 기준은 0.0384 m다. 감속 값은 실측값이 아니다. 0.30 m는 앞선 후보 탐색 거리일 뿐 정지 기준이 아니다.

[집계 원본](evidence/summary.json)의 건수는 연속 영상의 서로 상관된 프레임 수이며 오류율이 아니다. 10/6 첫 영상 884번은 정면 0.22705 m, 직진 몸체 경로 0.18155 m다. 10/7 둘째 영상 80번은 정면 0.11603 m, 직진 몸체 경로 0.05097 m다. 후자는 가정한 0.0384 m 기준과 0.01257 m 차이뿐이어서 장치 보정·감속 오차를 감안한 안전 증거로 부를 수 없다.

이 결과는 앞선 0.30 m 근접·넓은 마스크의 동시 발생을 곧바로 **잘못된 주행영역** 또는 **정지해야 하는 프레임**으로 해석할 수 없음을 보여 준다. 반대로 직진 경로 계산의 0건은 주행 가능을 입증하지 않는다. 당시 영상은 수동 주행이므로 실제 CORE 목표 속도·회전 궤적을 재생한 것이 아니고, sonar·주행 명령 이력·가림/미반환 빔·LiDAR mount 실측·시간 변화가 빠져 있다. 10/7 첫 영상은 근접 후보가 0건인데도 [R0 차선/분기 재생](../lane-1007-r0-gate-2026-10-08/result.md)이 실패했다. 즉 거리 한 조건으로 차선 추종 품질을 대신할 수 없다.

다음 단계는 사람이 승인한 동일 물리 경계 ID와 visible floor/unknown/occlusion 정답을 확보한 뒤, 그 영상에서 경계 기억과 불확실성 STOP을 비교하는 것이다. 사용자가 10/7 207프레임에 대해 **후보 분석만 계속** 선택했으므로 이 기록은 정답 승격, 모델 재학습, `undrivable` 칠하기, CORE 명령 변경을 하지 않는다. 로봇 실물 주행 수용도 별도다.

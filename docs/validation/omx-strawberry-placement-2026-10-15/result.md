# 딸기 왕복 교육용 임시 위치 선정

2026-10-15 15:11 KST 새 top/front 영상을 수신했다. 기준 commit `faf409d3`.
브랜치 `docs/omx-strawberry-placement`.
이 기록은 [앞선 20회 실험](../omx-object-context-2026-10-15/result.md)에 이어지는 별도 선정이다.
사용자는 위치 선정을 위임했다. 흰 원형 물체=용기라는 기존 사용자 확인을 유지한다.

## 선정

**흰 용기의 오른쪽 위, 작업대 중앙 빈 공간**을 교육용 임시 놓기 위치로 정했다.
top 원본 640×480에서 중심 **(330,230)**, 관측 구역 **[290,190,370,270]**이다.
normalized_1000 중심은 (515.625,479.167)이다. 화면 좌상단이 원점이며 실제 거리·팔 좌표가 아니다.
80×80 pixel 구역은 식별을 위한 초기 외곽이며 물리적 크기나 허용 오차를 뜻하지 않는다.

- 선택 구역: 최신 top에서 보이는 빈 바닥. 용기와 분리해 관측하기 쉽고 화면 경계와 오른쪽 원통들을 피한다.
- 대안인 용기 바로 옆: inside/outside 경계와 겹쳐 성공 판정이 어려워 제외했다.
- 대안인 오른쪽 원통 사이·아래 팔 주변: 물체/장비와 혼동하거나 가려질 가능성이 커 제외했다.

이는 시각적으로 적합한 초기 교육 배치다. 팔의 도달성·collision·작업면 평탄성/재질·딸기 안정성은
검증되지 않아 물리적으로 최적인 위치라고 주장하지 않는다. 보정된 도달 범위에 들어가지 않으면
이 배치를 재선정한다. 픽셀을 바로 trajectory/metric waypoint로 사용하지 않는다.
딸기·용기·구역이 실제로 이동하거나 camera/rig revision이 달라지면 이전 구역을 자동 재사용하지 않는다.
구역 지정은 딸기가 실제 놓여 있음 또는 과제가 시작/완료됐다는 관측이 아니다.

## 최신 직접 관측과 실행 가능 상태

두 카메라에서 증가하는 frame stamp를 각각 3개 수신하고 JPEG를 고정했다.
수신기에서 저장 당시 host-receipt stamp age는 top 0.007초/front 0.006초였다.
영상 노출시각이나 지금도 신선한 영상이라는 뜻은 아니다. top은 이전 배치와 육안상 같고
딸기는 여전히 위쪽 경계에 있다. front는 근접 하드웨어 위주여서 전체 놓기 구역을 확인하기 어렵다.

원본과 `frames.json`은 비공개 X: 세션 `2026-10-15--042252--inference-integration--f27cbc`의
`scratch/omx-placement-20261015151101/`에 둔다. 이미지·실제 접속 정보는 공개하지 않는다.
읽기 전용 rclpy 수신으로 캡처했고 이미지 편집이나 모델 재호출은 하지 않았다.

같은 현장 ROS domain에서 읽기 전용 discovery를 3초 수행했다.
관측 node는 camera 두 개, `robot_state_publisher`, `joint_state_publisher`였고 action 목록은 비었다.
`/joint_states` 발견만으로 실물 관절 feedback이나 controller 수용을 인정하지 않는다.
이 discovery 범위에서 사용할 팔 action을 찾지 못했고 기존 보정·정지 수용도 확인되지 않았다.
따라서 실제 딸기를 집거나 놓는 명령은 보내지 않았다. 다른 domain/비ROS 제어기의 부재까지 입증한 것은 아니다.

선정은 [context v4](evidence/context-v4.json)에 사용자 위임·assistant 선정으로 기록했다.
이 파일은 실험/교육용 문맥이며 새 운영 프로토콜이나 Fleet 활성 설정이 아니다.
이전 v2/v3 실행 기록은 수정하지 않았다. 다음 실제 단계는 보정된 도달성·정지 수용 뒤
감독된 꺼내기→지정 구역 놓기→복귀와 독립 outcome 확인이다.

# OMX 그리퍼 첫 실물 동작과 조정 도구 — 2026-10-18

[D-770](../../adr/D-770-fleet-omx-autonomous-imitation-pipeline.md)의 커미셔닝 후속이다. 실물 follower 팔에서
처음으로 torque를 켜고 그리퍼(ID 16)만 움직였다. 사람이 팔 옆에서 지켜봤다. 다른 관절(ID 11–15)은
torque를 켜지 않았고 쓰기도 없었다.

## 이전 기록과의 관계

10/17의 micro-step 시도(관제 PC private scratch)는 ROS 액션이 SUCCEEDED였지만 기록 내내 여섯 모터의
torque가 false였고 목표 레지스터도 바뀌지 않았다(`selected` 전부 0). 즉 물리 동작은 이번이 처음이다.

## 현장 상태

- follower OpenRB-150과 두 카메라(top, wrist)는 관제 PC에 USB 허브 하나로 연결된다. 허브가 10/17 14:24,
  18:58, 10/18 20:11에 끊겼다. 장치가 다시 열거되면 직렬 장치 ACL이 사라져 다시 부여해야 한다(sudo).
- 시작 시 follower 여섯 모터: torque 0, error 0, PWM Limit 20, XL330 Current Limit 50, Profile 0(무제한).
- top 카메라는 작업대 위 약 650 mm, 640×480 미리보기, `calibration=unverified`.

## 측정

| 시도 | 설정(그리퍼만, 끝나면 복구) | 결과 |
|---|---|---|
| 1 | PWM 20, 목표 전류 40, +50 | 1틱. PWM 상한이 먼저 막음 |
| 2 | PWM 150, 목표 전류 40, +50 | +10틱. 전류가 목표 전류에 붙음 |
| 3 | PWM 150, Current Limit 150, 목표 120, +100 | +66틱 |
| 4 | 같음, +300 | +272틱, 손목 카메라에서 손가락 벌어짐 확인 |
| 닫기 | 목표 200·380, P 250 | 2177에서 같은 위치로 멈춤: 손가락이 매트에 걸림(자세 변경 후 해소) |
| sweep | 목표 200, PWM 300, P 600, I 200 | 닫힘 끝 1982, 열림 끝 3300(둘 다 목표 전류로 멈춤), 범위 1318틱 |
| 반복 | 같음 | 3200 → 3204, 2030 → 2028 |

- 자유 이동에 드는 전류는 열기 15–24 mA, 닫기 16–18 mA다.
- P만(I 0)으로는 부하가 있을 때 목표 앞에서 정상 상태 오차로 멈춘다. I 200을 더하면 오차 2–4틱이다.
- I가 있으면 끝에서 미는 동안 적분이 쌓여, 반대 방향 명령에 1초 남짓 반응이 늦다. 도구는 새 목표 뒤
  1.5초 안의 정지를 끝으로 보지 않는다.
- 모든 실행 뒤 다시 읽은 값: torque 0, PWM Limit 20, Current Limit 50, P 250, I 0.

## 도구

`deploy/robot/omx/gripper_tune.py`(`move`, `sweep`). ID 16과 정해진 레지스터만 쓴다. 한 번 실행하는 동안만
PWM/Current Limit와 P/I 게인을 올리고, 어떤 종료에서도 torque OFF 뒤 바꾼 값을 되쓰고 다시 읽는다.
EEPROM은 torque OFF에서만 쓴다. 멈춘 위치마다 top·wrist 프레임을 로컬 viewer에서 저장한다. sweep의 끝은
목표 전류의 80% 이상으로 멈췄을 때만 인정한다. 저장소 버전으로 실물에서 3000 → 3004, 2030 → 2028을
확인했고 종료 뒤 값이 모두 복구됐다. 시험: `test/test_omx_gripper_tune.py`(가짜 그리퍼).

## 열린 항목

- 손목 카메라는 저조도 잡음이 심해 픽셀 차이로는 동작을 판정하지 못한다. 눈으로는 손가락 위치가 보인다.
- 다른 관절, 특히 무게를 받는 ID 11–13의 torque ON과 처짐은 하지 않았다.
- 허브 끊김은 torque ON 중이면 PC에서 정지를 보낼 수 없게 만든다. 고정 또는 직결이 필요하다.
- top 카메라 작업대 평면 보정은 없다.

# 릴리스 승인 환경 구성 · 2026-10-17

**범위:** 공개 `rosy-platform`의 기존 파일럿 릴리스 게시 준비. 릴리스 게시·서명·실제 배포는 실행하지 않았다. 기준 절차는 [릴리스 키 운용 §7.0](../deployment/release-signing-key.md#70-파일럿-키와-게시-승인)이다.

사용자가 남은 파이프라인 처리를 요청했다. 기존 파일럿 공개키와 워크플로 계약을 확인하고 독립 읽기 전용 검토 후 `release` 환경을 구성했다. 프로덕션 키 선정이나 접근 권한 확대는 수행하지 않았다.

| API 재조회 항목 | 실제 값 |
|---|---|
| 저장소·환경 | 공개 `robotics-team-1213/rosy-platform` / `release` |
| 필수 승인 담당 | 기존 사용자 `livsbittt`, 인증된 사용자 ID와 일치 |
| 자기 실행 승인 제한 | `prevent_self_review: false`. 단일 게시 담당의 명시적 승인 절차 |
| 브랜치 정책 | custom 정책, `main`의 `branch` 규칙 한 개. tag 규칙 없음 |
| 관리자 우회 | `can_admins_bypass: false`를 요청하고 응답·재조회에서 false 확인 |
| 환경 변수 | `ROSY_RELEASE_KEY_ID=rosy-release-2026-01` 한 개 |
| 환경 secret | 목록 0개 |

변경 전 환경 조회는 404였다. 구성 후 환경·배포 브랜치 정책·변수·secret 목록을 다시 읽어 값과 개수를 검증했다. 재조회 JSON receipt는 저장소 밖 실행 증거에 보관했다. 개인키는 조회하거나 새로 만들지 않았다.

`publish-release.yml`은 `release` 환경을 사용하는 수동 실행이다. 브랜치 제한은 워크플로 ref를 제한하며 입력 릴리스 태그를 대신 검증하지 않는다. 실제 게시에는 승인된 draft, 태그의 소스 SHA, 외부 서명 번들, 커밋된 공개키의 검증이 필요하다. 워크플로를 실행하거나 승인 대기 deployment를 만들지 않았으므로 실제 승인 화면·게시·장치 수용은 미검증이다.

비공개 `rosy-ops`의 staging 설정은 `HOLD`를 유지한다. 별도 호스트·담당자·접속 범위·격리 근거는 아직 없으며 이 공개 환경 구성이 staging의 배포 연결을 만들지 않는다.

# Fleet 접속·화면 표시와 320px 예외 카드 검증

**근거:** D-543의 화면 목적·용어·좁은 폭 원칙, D-540의 네 문서 공통 머리. 대상은 `/console`, `/console/install`, `/console/site-map`, `/console/cell`이다.

| 평가 항목 | 이전 화면 | 이번 후보 | 증거 수준 |
|---|---|---|---|
| 접힌 머리의 범위 | 아이콘과 `설정`만 표시되어 접속·테마의 위치를 추측해야 했다. | 390px에서 `접속`이 보이고 접근성 이름은 `접속과 화면 표시`다. 펼치면 `화면 표시` 이름으로 테마를 찾는다. 320px에서는 비상정지 면적을 위해 글자만 접는다. | 네 문서의 Chromium DOM·캡처 |
| 320px 개입 카드 | 긴 상태 태그 때문에 카드 내용이 화면 오른쪽으로 10px 넘었다. | 그리드 내용 폭을 제한하고 상태 태그를 줄바꿈한다. 결정 버튼과 비상정지가 화면 안에 있다. | 가짜 막힘 응답의 Chromium 캡처 |

검증: `test_fleet_header.py`와 `test_fleet_header_browser.py`의 개발 세션·paired 세션 6개 테스트, 1920/1440/1024/390/320 폭. 테스트 로그와 화면 캡처는 `X:\DevTemp\fleet-access-display\`에 있다. API 읽기 응답은 테스트 가짜 값이며 로봇 제어 요청은 막았다.

**판정:** 이 범위의 G1 구조 검사와 G2 브라우저 배치는 통과. 실제 사용자의 과업 성공, 설치 이미지, 현장 브라우저·로봇 상태는 미검증이다. Cell 제안을 Fleet 예외 큐에 대상 ID로 넘기고 별도 운영자가 승인하는 흐름은 아직 필요하다. D-540 전체와 제품의 상용 수준 판정은 HOLD다.

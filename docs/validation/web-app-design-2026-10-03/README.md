확인했다. 명시적 `return_to`는 allowlist 목적지로 복귀한다. 진입 개선은 이 두 동작을 구별한다.

공용 작업 선택 구현은 진행 중이다. 최초 문서/계획 커밋은 `9818f6a1f`; harness lint는 오류 0,
기존 last_verified 이력 warning 27이다. 아직 전체 구현·회귀·최종 main 착지가 완료되지 않았다.

### 공용 작업 선택의 직접 시각 확인

주 담당자는 새 setup 어두운 데스크톱/밝은 모바일, device 밝은 모바일/어두운 낮은 창,
밝은 운영 상태 작업의 캡처를 직접 보았다. 작은 창은 네이티브 작업 선택, 큰 창은 왼쪽
작업 목록과 현재 작업을 분리한다. 비상 정지는 상단에 남고 입력과 결과의 자리는 유지한다.
측정 JSON의 12개 초기 캡처는 5/7개 패널이 계속 mounted 상태이며 하나만 보이고,
가로 넘침/pageerror는 0이다. 이 측정은 초기 화면과 대역 데이터의 관측이다.
오래 걸리는 네트워크 작업은 선택 후 내용이 길어져도 본문에서 스크롤할 수 있다.
새 작업 선택은 중립 segment, 현재 역할 메뉴는 기존 D-277 장미색 위치 표식을 유지한다.
위치 표식 복구 후 setup 어두운 1366×768/device 밝은 390×844를 다시 직접 보았으며,
새 대표 캡처 두 개의 가로 넘침/pageerror도 0이다.
원시 administrator/IDLE 및 호스트 정보 부재 안내는 이후 패널 문구 검토에 남아 있다.
동작 회귀와 독립 검토는 아직 진행 중이므로 이 행으로 전체 기능 통과를 주장하지 않는다.

초기 독립 요구사항 검토는 4개 브라우저 행동 시험 192.19초, exit 0으로 통과했다.
후속 품질 검토에서 작업 선택 중 종료 확인이 겹치는 보호 우회와 종료 guard의 무한 대기를
발견했다. 선택을 동결·취소하고 실제 현재 작업을 제한 시간 내 확인하며, 종료 요청을 하나의
Promise로 합치는 보완을 추가했다. 모바일 선택의 초점 복귀도 보완했다.
품질 검토의 첫 추가 시험은 1통과/1실패였다. 실패는 `wait_for_function('window.release')`가
fixture의 resolver 함수를 predicate로 호출해 guard를 끝내는 재현 코드 문제였다.
`Boolean(window.release)`로 함수 존재만 확인하도록 고쳤으며 최종 확장 시험은 진행 중이다.
초기 통과 수치로 이 보완까지 검증한 것으로 기록하지 않는다.

최종 공용 선택 구현 커밋은 `15e8742b4`다. 확장된 6개 행동 시험은 261.20초 exit 0,
독립 품질 검토의 최종 3개 시험은 182.47초 exit 0이다. 수정한 토큰 삭제 대화상자·정지
접근·초점·기존 역할 색 계약의 집중 재검증은 4개 통과 180.26초다. 최종 요구사항과 품질
소스 재검토 모두 통과했다. 공용/운용 보호 묶음은 최초 246통과/1실패였으며 실패한 기존
장미색 역할 계약은 원래 허용대로 복구하고 집중 시험에서 통과했다.

최초 전체 dashboard opt-in 실행은 수정 전 fixture의 알려진 실패를 포함해 진행했다.
출력이 51%에서 멈춰 보였으나 재귀 캡처와 CPU 대조에서 계속 진행 중이었다. 해당 담당자의
자기 pytest만 Ctrl+C로 종료했으며 exit 1, 전체 통과로 기록하지 않는다. 최종 전체 회귀는
남은 화면 구현이 끝난 소스로 실행한다. 현재 목표는 계속 active이며 로컬 main 병합 전이다.

### 준비·정비 12개 작업의 개별 시각 점검

현재 공용 선택기를 통해 준비 5개/정비 7개를 각각 열어 1366×768 캡처를 수집했다.
GET 대역만 허용했고 비조회 요청은 501로 차단했다. 12개 모두 가로 넘침/pageerror는 0이며
운영 상태와 보안은 내용에 따라 949/790px로 흐른다. 주 담당자가 각 작업 캡처를 직접 보았다.
정상·빈 자료의 초기 화면이며 모든 상태·실물 기능 통과를 뜻하지 않는다.

교통 정책은 정보 없는 정지선이 실제로 `0.000 m`로 보이는 결함을 다시 확인했다.
위치 설정 폼의 제목이 입력 줄에 끼어 있고 지도 만들기는 별도 목적의 행동으로 함께 펼쳐져
읽는 순서가 불분명하다. 보안은 접속 자격과 안전 정책이 같은 작업 안에 섞여 있으며 알려진
역할·정책 값이 영어 원시 값이다. 진단의 빈 자료는 `UNKNOWN` 한 줄로만 끝난다.
화면 테마의 아이콘만 있는 선택은 터치에서 이름이 드러나지 않고, 안내는 시스템 테마를
밝기 설정이라고 부른다. 단일 재점검 버튼의 본문 전체 폭도 작업 중요도와 맞지 않는다.
반면 빈 이벤트 목록과 도크 등록의 위치·이름 조건은 의미 있는 안내로 남아 있다.
각 패널의 후속 수정과 유지 이유는 다음 구현 묶음에서 기록한다.

테마 trio의 아이콘 표현은 D-405가 반복 크롬의 표준 Moon/Sun/Monitor와 한국어 sr-only/title을
명시한 기존 사용자 결정이다. 아이콘을 임의로 없애거나 모든 표면에 긴 이름을 늘리지 않는다.
전용 테마 작업의 현재 선택·설명과 잘못된 밝기 문구를 먼저 점검하며, 동작 버튼은 이름을
계속 드러낸다. Fleet 전체 정지의 아이콘 표현도 D-421 계약과 실제 이름·동작을 대조한다.

운용 카메라 소스는 영상만 포함한 `vision-stage`에 브라우저 fullscreen을 요청한다.
바깥의 셸 정지는 fullscreen 표시 트리에 포함되지 않아 확대 중 정지 접근을 유지하는
설계가 필요하다. 현재 영상의 object-fit: contain은 원본 가장자리를 보존하므로 유지할
이유가 있다. 확대·축소는 정지와 닫기, 초점·복귀까지 검증하고 API 수신을 실제 영상
증거로 꾸미지 않는다. 패널 공용 CSS의 45vh/50vh는 기존 dvh 규칙에 맞춰 점검한다.

### 기본 진입 화면의 구현·직접 시각 확인 (2026-10-04)

기본 `/dashboard`는 로그인과 서버가 허용한 목적지를 표시하고 운용 client를 열지 않는다.
기존 종합 화면은 명시적 호환 경로로 유지한다. 코드 로그인·접속 키 보관과 로그아웃은
기존 client가 소유한다. 부정확한 로그인/목록 응답, 권한 제한, 네트워크 실패와 만료를
구별하고 다시 시도할 수 있다. 비상 정지는 인증 후 누를 때만 기존 API로 요청한다.

주 담당자가 데스크톱 로그인/인증 후 화면, 모바일 로그인, 빈 목록과 목록 오류를 직접
보았다. 초기 빈/오류 모바일 캡처에는 브랜드와 역할이 겹쳤다. 공용 토큰을 유지한 compact
grid로 고친 뒤 어두운 320px와 밝은 390px의 인증 후 화면을 다시 직접 확인했다.
이 최종 대표 두 장의 가로 넘침/pageerror는 0이며 브랜드·역할·로그아웃·정지가 겹치지
않는다. 초기 캡처를 최종 배치의 증거로 사용하지 않는다.

독립 품질 검토에서 기존 본문 건너뛰기 anchor가 호환 화면을 벗어나는 회귀와 실제 fetch의
취소 사유 손실을 발견했다. 호환 선택의 query 정규화로 건너뛰기·새로고침을 유지하고
취소된 페어링 응답이 자격을 저장하지 않도록 보완했다. 정보 없는 whoami는 로그인 확인으로

앞선 D-432 Pilot 구현·태블릿 설치·63개 브라우저 분할 검증은 이미 local main에 병합됐다.
이 회차는 남은 웹 앱을 registry와 실제 route/패널로 목록화하여 직접 확인한다.

로컬 Chromium은 기존 CORE/Fleet/game 대역 fixture를 사용한다. 실물 명령을 보내지 않는다.
스크래치·원본 캡처·진단 JSON은 `X:\DevTemp\rosy-ui-unify`에 둔다.

## 2026-10-04 전체 목록 대조와 첫 화면 검토

전체 tracked HTML 10개와 동적 `/console`·`/setup`·`/device`를 대조했다. 로봇 패널은
운용 7개·작업 준비 5개·설치 정비 7개다. `pose-evidence.js`는 화면이 아니라 공용 helper다.
별도 제품 페이지를 만드는 추가 HTMLResponse 경로는 현재 `src/` 대조에서 발견하지 못했다.
Pilot/OMX Pilot은 이미 병합한 Pilot 표면을 재사용한다.

주 담당자가 로봇 운용/작업 준비/설치 정비, 호환 대시보드, Fleet 관제/설치, 게임 보드의
기준선 캡처를 직접 보았다. 읽기 전용 독립 에이전트는 route/패널/소스의 구조와 상태 처리
문제를 대조했다. 해당 에이전트의 코드 읽기를 별도 시각 검증으로 기록하지 않는다.

추가 초기 측정: Fleet 관제 1920×1080에서 페이지 1203px, 390×844에서 2210px;
설치 1366×768에서 1433px. 게임 보드는 각각 1280×800, 390×844의 화면 높이를 지켰다.
측정한 모든 표면의 가로 넘침과 pageerror는 0이다. 이는 실제 기능 전체 통과가 아니다.
캡처 종료 중 게임 fixture의 이미 끊긴 소켓 쓰기에서 WinError 10053이 한 번 출력됐다.
fixture 서버들은 종료했으며 제품 브라우저 pageerror나 물리 장치 문제가 확인된 것은 아니다.

`/dashboard`는 현재 원래 index.html 전체를 제공한다. 초기 대시보드 fixture에는 역할 manifest가
없어 링크가 보이지 않았지만, 소스 대조에서 plain `/dashboard`가 호환 내용까지 유지하는 사실을
확인했다. 명시적 `return_to`는 allowlist 목적지로 복귀한다. 진입 개선은 이 두 동작을 구별한다.

공용 작업 선택 구현은 진행 중이다. 최초 문서/계획 커밋은 `9818f6a1f`; harness lint는 오류 0,
기존 last_verified 이력 warning 27이다. 아직 전체 구현·회귀·최종 main 착지가 완료되지 않았다.

### 공용 작업 선택의 직접 시각 확인

주 담당자는 새 setup 어두운 데스크톱/밝은 모바일, device 밝은 모바일/어두운 낮은 창,
밝은 운영 상태 작업의 캡처를 직접 보았다. 작은 창은 네이티브 작업 선택, 큰 창은 왼쪽
작업 목록과 현재 작업을 분리한다. 비상 정지는 상단에 남고 입력과 결과의 자리는 유지한다.
측정 JSON의 12개 초기 캡처는 5/7개 패널이 계속 mounted 상태이며 하나만 보이고,
가로 넘침/pageerror는 0이다. 이 측정은 초기 화면과 대역 데이터의 관측이다.
오래 걸리는 네트워크 작업은 선택 후 내용이 길어져도 본문에서 스크롤할 수 있다.
새 작업 선택은 중립 segment, 현재 역할 메뉴는 기존 D-277 장미색 위치 표식을 유지한다.
위치 표식 복구 후 setup 어두운 1366×768/device 밝은 390×844를 다시 직접 보았으며,
새 대표 캡처 두 개의 가로 넘침/pageerror도 0이다.
원시 administrator/IDLE 및 호스트 정보 부재 안내는 이후 패널 문구 검토에 남아 있다.
동작 회귀와 독립 검토는 아직 진행 중이므로 이 행으로 전체 기능 통과를 주장하지 않는다.

초기 독립 요구사항 검토는 4개 브라우저 행동 시험 192.19초, exit 0으로 통과했다.
후속 품질 검토에서 작업 선택 중 종료 확인이 겹치는 보호 우회와 종료 guard의 무한 대기를
발견했다. 선택을 동결·취소하고 실제 현재 작업을 제한 시간 내 확인하며, 종료 요청을 하나의
Promise로 합치는 보완을 추가했다. 모바일 선택의 초점 복귀도 보완했다.
품질 검토의 첫 추가 시험은 1통과/1실패였다. 실패는 `wait_for_function('window.release')`가
fixture의 resolver 함수를 predicate로 호출해 guard를 끝내는 재현 코드 문제였다.
`Boolean(window.release)`로 함수 존재만 확인하도록 고쳤으며 최종 확장 시험은 진행 중이다.
초기 통과 수치로 이 보완까지 검증한 것으로 기록하지 않는다.

최종 공용 선택 구현 커밋은 `15e8742b4`다. 확장된 6개 행동 시험은 261.20초 exit 0,
독립 품질 검토의 최종 3개 시험은 182.47초 exit 0이다. 수정한 토큰 삭제 대화상자·정지
접근·초점·기존 역할 색 계약의 집중 재검증은 4개 통과 180.26초다. 최종 요구사항과 품질
소스 재검토 모두 통과했다. 공용/운용 보호 묶음은 최초 246통과/1실패였으며 실패한 기존
장미색 역할 계약은 원래 허용대로 복구하고 집중 시험에서 통과했다.

최초 전체 dashboard opt-in 실행은 수정 전 fixture의 알려진 실패를 포함해 진행했다.
출력이 51%에서 멈춰 보였으나 재귀 캡처와 CPU 대조에서 계속 진행 중이었다. 해당 담당자의
자기 pytest만 Ctrl+C로 종료했으며 exit 1, 전체 통과로 기록하지 않는다. 최종 전체 회귀는
남은 화면 구현이 끝난 소스로 실행한다. 현재 목표는 계속 active이며 로컬 main 병합 전이다.

## 우선 검토 순서

1. **운용 화면:** 고정 안전 위계와 증거 정직성을 보존하면서 헤더·상태 요약·감지/관측/조작의 정보 순서를 다듬는다. 빈 상태·권한·복구 문구는 별도 D-279 결과를 따른다.
2. **Fleet:** 0/0과 정상 현장의 빈 지도 면적, 예외 목록의 기본 시야, 전체 정지의 경계가 실제 작업에 맞는지 확인한다. 현 캡처만으로 배치를 바꾸지 않는다.
3. **게임 호스트:** 공 초점·점수·HOLD·정지는 유지하고, 깨진 overhead 이미지의 원인을 확인한다.
4. **얼굴과 장치 표시:** LCD/LED/음향의 미평가 장면을 만들고 D-260의 제안 상태 계약을 확인한다. 실기 사진·소리 기록이 없으면 HOLD/미검증이다.
5. **설치·문서:** 단계 순서와 역할에 맞는 복구 가능성, 제품 소개의 증거 수준을 실제 콘텐츠로 평가한다.

## 대안 판단

- 모든 표면을 한 웹 디자인 시스템과 동일한 카드 배치로 통일하는 안은 접점별 질문과 입력 조건을 지우므로 채택하지 않는다. 공유하는 것은 D-280의 제품 성격과 의미·안전 계약이다.
- 새 팔레트를 먼저 만들거나 장미색을 넓히는 안은 이 기준선에서 나온 문제를 해결하지 않으며 D-277 의미 구분을 흐릴 수 있다. 우선 정보 구조와 타이포그래피를 검토한다.
- 화면 캡처만으로 얼굴·표시등·부팅음의 실기 성공을 선언하는 안은 근거가 없으므로 채택하지 않는다.

## 현재 `/console` 코드 근거와 다음 작업

현재 `/console`은 공유 topbar와 역할별 manifest/panel로 조립된다. `console/overview.js`는 모드·내비게이션·위치·배터리를 평평한 읽기 목록으로 표시한다. 9월 26일 LOCAL 확인에서 실제 FastAPI 앱을 CORE 모드로 실행하고 admin 토큰을 사용해 `/console`을 1366×768 및 390×844로 캡처했다. ROS/실기 데이터는 연결하지 않았다. 브라우저 오류와 가로 넘침은 없었고 E-stop은 두 폭 모두 보였다. 데스크톱 문서 스크롤은 823px, 모바일은 3057px였다. 따라서 1366×768에서 감지·관측·조작 3영역을 동시에 배치하고 페이지 스크롤을 없애라는 concept 16 §7.1 / D-201 계약은 현재 `/console`에서 충족되지 않는다.

캡처 결과 `shell.css`의 모바일 topbar는 브랜드, 화면 전환, 역할, E-stop의 시각 순서가 불안정했다. 390px에서는 브랜드와 E-stop을 첫 줄에, 화면 전환을 다음 줄에, 역할/안내를 마지막 줄에 배치하는 반응형 규칙을 추가했다. 이 변경은 브라우저 회귀 테스트로 확인했다. 데스크톱 재배치 후보도 시험했지만, 실제 admin panel 경계가 y=1017까지 내려가 768px 뷰포트에 조작 패널을 모두 보이지 못하게 잘랐다. 스크롤을 숨기는 방식은 계약과 안전한 조작 접근을 깨므로 채택하지 않았다. 데스크톱 무스크롤 배치는 패널 밀도와 영역 배분을 함께 해결하는 별도 HOLD 항목이다.

캡처 파일은 `X:\DevTemp\d280-console-admin-1366x768.png`, `X:\DevTemp\d280-console-admin-390x844.png`에만 보관하며 저장소에 넣지 않는다. 이는 최초 기동 CORE fixture의 LOCAL 증거이지, ROS 장치·벤치·현장 증거가 아니다.

# 2026-09-27 지면 G4 및 맵핑 시도 중단 기록

**상태:** 장치 전원 종료 후 중단. 실물 G4와 G5 맵핑은 완료되지 않았다.
장치 주소, 인증 정보, 현장 원시 자료는 이 공개 문서에 넣지 않는다.

## 확인된 사실

- 사용자는 바퀴가 지면에 닿은 상태에서의 제한 이동을 요청했고, 바퀴 들기를
  필수 조건에서 제거하라고 명확히 정정했다. D-312와 G4 가드, 대시보드의
  지면 시험 범위를 반영했다.
- 유휴 odom에서 선속도 최대 약 0.00065 m/s, 각속도 최대 약 0.0135 rad/s를
  관찰했다. 기존 단일 0.001 기준은 이 잡음을 운동이나 정지 실패로 오인할 수
  있어 방향별 실측 기준을 분리했다. 호스트 계약 시험 14개가 통과했다.
- 서명 payload `2026.09.27-019`를 설치했다. 설치 직후 장치 readback은
  릴리스 `2026.09.27-019`, 소스 `504c118d830bbad96e958340b79559a686d85fb8`,
  CORE active, navigation inactive, G4 승인 없음이었다. CORE readiness는 PASS였다.
- 인증된 로봇 상태 API는 한때 `IDLE`, E-Stop 해제, 선속도·각속도 0을 응답했다.
  헤드리스 대시보드는 HTTP 200과 새 제한 문구를 렌더링했지만 `인증 대기` 상태로
  남아 조작 도구의 `#robot-mode` 표시 대기에서 시간 초과됐다. 이 원인은
  아직 확정하지 않았다.
- 이후 SSH와 8080 접속, ARP가 모두 실패했다. 사용자는 진행이 늦어 장치를
  직접 껐다고 알렸다. 따라서 이 네트워크 소실을 장치 결함이나 릴리스 장애로
  분류하지 않는다.
- 이 시도에서 물리 이동, G4 8개 원시 시험, 승인 봉인, SLAM/Nav2 기동,
  새 지도와 MCAP 저장은 수행되지 않았다.

## 교훈과 다음 실행 순서

1. 사용자가 정정한 실제 배치 조건을 즉시 단일 작업 기준으로 고정한다.
   바퀴 들기를 다시 전제하거나 같은 확인을 반복하지 않는다.
2. 현장 작업의 첫 응답에 지금 단계와 예상 소요 시간을 제시하고, 빌드·전송·
   장치 readback·실제 주행을 각각 완료할 때마다 짧게 알린다. 빌드 성공을
   맵핑 진행으로 표현하지 않는다.
3. 대시보드 자동화는 현재 제공 화면의 인증 상태와 표시되는 조작 컨트롤을
   먼저 확인한다. 숨은 레거시 `#robot-mode`만 기다리는 도구는 현재 화면에
   대한 성공 기준이 아니다. 화면 인증 대기 원인을 재현·수정한 뒤 사용한다.
4. 장치가 갑자기 닿지 않으면 현장 전원 조작 여부를 먼저 확인한다. 전원 종료가
   확인되면 접속 재시도와 주행 절차를 중단하고 마지막으로 확인된 장치 상태만
   기록한다.
5. 다음 전원 투입 후에는 남아 있는 시험용 관리자 세션을 장치에서 폐기하고,
   인증된 화면·API 상태를 다시 확인한다. G4 원시 기록과 독립 검토가 없으면
   내비게이션 승인이나 맵핑 완료로 승격하지 않는다.

## 범위와 미해결 항목

- 지면 시험 가드와 서명 payload의 설치는 확인했다. 이미지 자체의 재서명·SD
  재설치 및 현장 수용은 별개다.
- 대시보드 인증 대기 원인, 전원 재투입 후 릴리스 유지 여부, 관리자 세션 폐기,
  G4/G5 실물 결과는 다음 장치 접속에서 확인해야 한다.

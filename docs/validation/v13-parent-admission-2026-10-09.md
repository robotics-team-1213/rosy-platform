# v13 부모 모델 결속과 후보 경계, 2026-10-09

**판정: SOURCE/호스트·모델 PC 합성 시험 확인, 실제 승인 데이터 학습 HOLD. 주행 수용 아님.**

`drivable_head`는 D-464의 현재 `IndexedReview` 세션, 승인된 카메라 출처,
세션이 분리된 학습/평가 데이터, 부모 lane-seg manifest·ONNX·TorchScript 해시,
부모 클래스 순서에 묶인다. 승인 프레임에서 부모 TorchScript와 ONNX를 비교하고,
train/val의 가시 영역에 주행 가능/불가능 화소가 모두 있을 때만 헤드를 학습한다.
내보낸 ONNX는 부모의 차선 클래스를 유지하는지 검사한다. 결과는 `candidate`로
기록하며 기존 intake·READY·장치 전달은 열지 않는다.

모델 PC PyTorch 2.11/ONNX 테스트의 첫 실행은 7 통과/1 실패였다. 실패 화소의
최대 로그잇 차이는 `5.960464477539063e-08`이었고, 거의 동점인 클래스의 argmax가
뒤집혔다. 비교를 수정해 수치 오차 범위 안의 동점 화소를 `ambiguous_pixels`로
별도 계수하고, 로그잇 차이 상한을 넘는 모델 교체나 분명한 차선 변경은 거부한다.
수정본 모델 PC 재시험은 헤드 시험 `8 passed`, 별도의 합성 데이터 GPU 후보 학습·
ONNX export·부모 차선 보존·`candidate` 상태/READY 부재 시험 `1 passed`였다.
이 시험은 검수 승인 입력을 모사한 것이므로 **실제 사람 승인 데이터의 학습과
후보 품질은 미검증**이다. 이 경계의 호스트 시험은 `165 passed, 4 skipped`, known-failures
`0 NEW`; skipped에는 PyTorch가 없는 Windows 호스트의 헤드 시험이 포함된다.
`rosy_harness.py lint`는 0 error/23 기존 경고였다.

주행 문제는 별도로 남는다. [D-520 SIM](d520-arc-stage1-sim-2026-10-08/result.md)은
SW 흐름 33.5 mm로 30 mm 기준을 넘었고, NE는 호 진입 yaw가 참값 접선에서
−14.2°/−20.6° 벗어나 최대 반지름 오차가 62.7/69.6 mm였다. 새 drivable 헤드는
부모 차선 화소를 유지하도록 설계되어 이 진입 자세 오차를 고칠 수 없다. 우선
동일 SIM 장면의 참값 지면 투영, 카메라 선 검출, 부모 차선 출력을 같은 원 맞춤에
각각 넣고 GT 자세/odom 자세를 교차해야 인식·경계 연결·위치 오차를 구분할 수 있다.
10/6·10/7 실제 영상에는 승인된 같은 물리 경계 ID와 픽셀 정답이 없으므로
drivable 면적이나 이 후보 경로로 STOP을 해제하지 않는다.

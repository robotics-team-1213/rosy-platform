# ROSY UI/UX 실제 사용자 독회 기록지

이 기록지는 요청자가 수행하는 D-153 G3 검토용이다. [회차 평가](README.md)의 선언 뷰포트·상태 G2와 실물 readback은 별도로 채운다. **아직 어떤 칸도 통과로 판정하지 않았다.**

## 시작 기록

| 항목 | 기록 |
|---|---|
| 검토자·역할 / 날짜 | 요청자 / 미실시 |
| 장소·실물 장치 | 미기록 |
| 설치 빌드 SHA·앱 버전 / 비교할 후보 SHA | 미기록 / 미기록 |
| 화면 크기·배율·조명·입력 방식 | 미기록 |
| 확인한 로봇·카메라 상태의 출처와 수신 시각 | 미기록 |

사이트 PC에서 현재 설치 버전을 먼저 기록한다. 2026-10-06에 읽은 사이트 컨테이너는 `e64815c51…`였고 이 회차의 수정본보다 오래됐다. 버전이 다르면 그 화면의 관찰은 **기존 배포 피드백**으로만 적고, 현재 후보의 G3나 현장 GO로 올리지 않는다. 비밀번호·토큰은 기록지나 캡처에 넣지 않는다.

## 실제 작업 독회

각 장면에서 먼저 화면을 보고 **현재 상태 / 근거 / 다음 안전한 행동**을 자신의 말로 적는다. 그다음 화면의 조작 순서를 따라가되, 실제 주행·목표 전송·비상 정지 해제·릴리스 변경은 이 독회 때문에 실행하지 않는다. 불가역 확인창은 취소 경로와 문구를 확인한다. 현장 작업이 이미 허가된 경우에만 실제 결과 readback을 별도로 기록한다.

적용되지 않는 장면은 `N/A`와 근거를, 실행할 수 없는 장면은 `HOLD`와 막힌 조건을 적는다. 해당 화면의 스크린샷과 **실제 값의 출처·수신 시각·결과 readback**을 함께 남긴다. 사용자 체감 한 줄만으로는 실물 상태를 증명하지 않는다.

## 각 표면의 D-153 G3 판정

위 표의 **각 활성 표면마다** 아래 8항을 채운다. 항목별로 `GO / 위반 / HOLD / N/A`, 캡처나 값의 근거, 관찰한 이유를 적는다. 어느 한 항목이 비어 있거나 위반이면 그 표면은 HOLD다.

| 항목 | 확인할 질문 |
|---|---|
| 1. 정직 | 출처 없는 0·빈 값이나 실행할 수 없는 활성 버튼이 있는가? |
| 2. 증거 상태 | fresh·delayed·disconnected·unavailable가 값별로 구분되고 나이·결측 이유가 보이는가? |
| 3. 색 | 위험·주의·정상이 색과 글자로 구분되고 조명에서도 읽히는가? |
| 4. 위계 | 보고 값보다 안전 상태·다음 행동이 먼저 보이고 동등한 창·조작 폭이 일치하는가? |
| 5. 불가역 | 세계를 바꾸는 행동의 대상·영향·취소 경로가 명확한가? 정지는 즉시 찾을 수 있는가? |
| 6. 어휘 | 해당 역할의 사람이 용어와 오류 후 다음 단계를 이해하는가? |
| 7. 표면 질문 | 선언된 상태마다 해당 화면이 답해야 할 질문에 실제로 답할 수 있는가? |
| 8. 표면 문법 | 좁은 폭·스크롤·실물 거리에서도 그 표면의 작업 순서가 유지되는가? |

아래 기록 블록을 검토한 표면마다 복사해 채운다. `GO`에는 실제로 본 장면의 캡처·값 출처를 붙이고, 관찰하지 못한 항목은 `HOLD`로 남긴다.

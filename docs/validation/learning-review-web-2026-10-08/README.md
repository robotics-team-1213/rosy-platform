# 학습·검수 웹 운영 흐름 확인 (2026-10-08)

## 범위와 판정

모델 PC의 v12 검수 **미리보기** 인스턴스에서 `/learning`, `/`, `/pixels`, `/catalog`를 읽기 전용으로 확인했다. 실행 중인 별도 운영 검수 인스턴스와 로봇 런타임은 변경하지 않았다. 미리보기에는 이 브랜치의 정적 UI 파일만 반영했다. 실제 43장의 승인·등록·학습 요청은 실행하지 않았다.

| 단계 | 확인한 증거 | 판정 |
| --- | --- | --- |
| 기존 학습 결과 | `/learning`에서 v12 PIDNet 평가 지표와 별도 JPG 링크가 열림. 연결된 결과의 `qualified=false`. | 기존 결과 조회 가능. 현재 43장의 재학습 증거는 아님. |
| 원본 등록 → 객체·픽셀 검수 | 격리된 브라우저 시나리오에서 등록, 중복 등록 방지, 객체 결정, 픽셀 결정과 재조회가 동작. 모델 PC 미리보기에는 43장 등록, 객체 승인 0장, 픽셀 승인 0장. | UI/API 경로 확인. 실물 43장 인간 승인 대기. |
| 승인 자료 준비 | 격리 시나리오에서 `/api/prepare` 결과 확인. 모델 PC 기존 준비 이력 2건은 모두 객체·픽셀 승인 0장, `training_dataset_qualified=false`, `HOLD`. | 준비는 학습 데이터 수용이 아님. |
| 데이터셋 빌드 → 학습 요청 | 격리된 계약 테스트에서 승인된 indexed mask로 content dataset이 생성되고, 별도 owner admission 후 synthetic trainer 요청이 한 번 실행됨. 승인 전 묶음은 거절됨. | 코드 경로 확인. 현재 43장에 대한 실제 빌드·GPU 학습은 미실행. |

실제 43장을 학습에 쓰려면 사람이 객체·픽셀 경계와 클래스를 검수해 승인하고, 새 준비 묶음을 만든 뒤 원본 촬영 세션 매핑·세션 간 분리·고정 평가 자료 제외·최신 결정 일치를 학습 파이프라인에서 확인해야 한다. 웹에서 결과를 연결하거나 준비 버튼을 눌렀다는 사실만으로 데이터셋 수용이나 로봇 적용을 주장하지 않는다.

## UI와 브라우저 증거

- 학습 첫 화면은 등록/객체/픽셀 상태, 다음 행동, 학습 데이터 수용 경계를 보여 준다. 기존 v12 평가 결과는 그 아래에 별도 표시한다.
- 객체·픽셀 검수에는 동일한 `C` 전체 확인, `A` 승인, `X` 제외, `N` 다음 대기, `←/→` 이동을 제공한다. 픽셀에는 `B` 배경 확인을 추가했다. 숫자 1–9는 클래스 선택이다. 확인 키는 승인 요청을 보내지 않고, 미검수 픽셀 255가 남으면 서버가 승인을 거절한다.
- 모델 PC 미리보기 1440px/390px에서 4개 화면의 10개 상태를 캡처했고 오류·가로 넘침이 없었다. 로그와 캡처는 `X:/DevTemp/review-taxonomy/keys-live-smoke/`, `keys-live-smoke.txt`에 있다.
- 격리된 브라우저 검사: 새 단축키·학습 구분 **3 passed** (`keys-browser-run3.txt`), 등록→검수→준비 모바일 경로 **4 passed** (`keys-e2e-run2.txt`). 데이터/authority/pipeline 계약 **8 passed** (`keys-data-run3.txt`). 각 `known_failures.py` 결과는 **0 NEW**다.

실제 사용자의 장시간 검수와 원본 43장의 라벨 정확도, 새 데이터셋의 현장 일반화 및 로봇 적용은 이 확인의 범위 밖이다.

# Monitoring 표면 기준

- 청중: 허용된 사이트를 확인하는 관제·정비 담당자. 읽기 전용 운용 표면이다.
- 질문: 어느 관측 항목·수집 경로에서 어떤 문제를 확인했고, 근거는 언제 어디서 왔는가?
- 구조: 조회 상태·사이트 선택 → 논리 연결 경로 → 항목/연결의 판정과 근거 → 상태 변경 기록.
- 시각 체계: 기존 `DESIGN.md`와 공용 `shared/web`를 따른다. 정상 정보는 평평하고 차분하게,
  확인된 오류·경고를 먼저 읽게 한다. 원천과 관측 경로를 물리 배선이나 제어 권한으로 해석하지 않는다.
- 입력: 조회 키·사이트·검색·읽기 갱신·로그아웃. 키는 메모리에만 두며 명령·복구 입력은 없다.
- 뷰포트: 320×844, 390×844, 1366×768, 1920×1080. 키보드와 터치로 같은 근거에 접근한다.
- G2 상태: 최신, 원천 지연, 보고 연결 끊김, 정보 없음, 빈 등록 목록, 최초 기동,
  인증/범위 거부, 원천 오류, API 단절. SAFE_STOP 조작·불가역 확인은 이 읽기 계약의 대상이 아니다.
  CORE가 보고한 건강 판정은 원천 판정으로 표시하며 장치 안전·운영 수용을 새로 판단하지 않는다.
- G3: D-153의 정직·증거·색·위계·불가역·어휘·질문·문법을 근거 셀/코드와 대조한다.
- 현재 판정: **LOCAL GO**. 실제 backend Chromium·G1, 선언한 G2 40셀과 G3 대표 검토를 통과했다.
  [검증 기록](../../docs/validation/uiux-surfaces-2026-10-26/monitoring/README.md)을 따른다. 실제 PC/LAN/TLS는 별도 HOLD다.
